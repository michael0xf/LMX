<a id="call-frames"></a>
## Входы и namespace

> 1. args и data в (fn sub catch) объединяются в одну структуру data которая описывает входящие данные, каждый вызов создаёт новый кадр data.

> 2. При трансляции Си-сигнатуры собираются из реальных вызовов, а не из полного описания аргументов функции, при этом сигнатура без тела code описывает именно такой вот вызов, а не какую-то конкретную полную fn-sub.

> 3. ничего не публикуется, механизм load-dirty из кода совсем убираем.

> 4. В графе ничего не автозаполняется. Полный кадр code просто добавляется к namespace и тоже не публикуется.

> 5. Локальные объявления через ресиверы в коде, которым нет соответствия в data, инициализируются вместе с code каждый вызов (не как в Python при объявлении callable). Инициализацию namespace делаем как сейчас, только корневого уровня data в namespace текущего вызова, таким образом позиционные объвления при вызове просто мэпятся.

> data\ и code\ остаются путями в исходный граф через которые можно записать что угодно. Кадр делается code -- в случае интерпретатора желательно чтобы он при инициализации положил себе копию этого графа.

> Обход ответвлений лексического дерева data не делаем, code при инициализации обходим таким же способом -- только корень.

> Новые объявления видны на своем уровне и вложенных -- это просто транслируется в Си, а повторное объявление просто не транслируется в native.

> 8. Задачу кеширования, таким образом, тоже полностью убираем

## Повторное объявление, свёртывание и вычисление

> 1) Убирается только повторное объявление переменной. В `int: x bump()` вызов bump() и присвоение существующей x остаются. Всё по прежним правилам, просто новую переменную в Си объявлять не нужно.

> Инициализацию в графе делаем не каждый раз при вызове, а при построении чистого графа, но без вызовов внутри инициализации. Используем тот самый код который схлопывает "int: i 5" в ссылку на зачение int.

> При выполнении кода с переменными namespace сохраняем это поведение:
> ```yaml
> mark()
> int: y makeValue() # тут y никто не вызывал раньше -- он и не вызвался
> ```

> Как будто ты обращаешься к структуре root\y. Наружу из ветви новое имя не выходит.

## Удаление лишнего и общий код сборщика

> 1. Удалять ненужные проверки вместе с обслуживающими их таблицами, переносами и ветками генератора.
> 2. Реализовывать построение и проверку чистого графа в сборщике, с оптимизацией под реальные задачи.
> 3. Когда появится конкретная потребность runtime — переносить туда нужные части уже работающего сборщика и использовать общий код.
> 4. Не создавать заранее отдельную инфраструктуру runtime, универсальные обёртки и дополнительные состояния «на будущее».
