# Объявление-аргумент имени, которого у вызываемого нет: что с позициями следующих аргументов

Дата: 2026-11-18. Задаёт исполнитель (сессия fable_pc); противоречие нашла вспомогательная сессия opus при
подготовке среза об аргументах вызова. Статус: **открыт**. Работу не останавливает: шаги о встроенном присваивании
от ответа не зависят.

## Что записано

Два ответа автора одного дня встречаются на одной записи.

Первый — о записи `g(int: b 2; 5)` при `fn: g (int: a; int: b)`, [журнал](../../2026-11-18.md#assignment-signs-are-heads):

~~~text
Так как ты написал будет отказ потому что 5 не понятно уже к чему относится, а вот g(int: b 2) не было бы отказом так как "a" не required.
~~~

Второй — об объявлении как аргументе, [журнал](../../2026-11-18.md#declaration-in-expression):

~~~text
Исчисление позиций такое же ленивое -- если попал на позицию тёзки то как позиционный, если не попал но тезка все же есть или вообще такой переменной не было заявлено то счетчик позиций с него отключается. Зачем нужно -- для подстановки data и code. Из него возникает эффект для ресивера: "for( int: i 5; i++; i < 10)" перестает быть специальным случаем который вы как-то там по своему разбираете -- можно будет юзать общий код.
~~~

Книга, [ветвления и циклы](../../../docs/LMX_semantics.ru.md#branches): основной `for` содержит инициализацию,
условие, шаг и тело.

## Где они встречаются

У `for` формала с именем `i` нет. По второму ответу объявление `int: i 5` заводит `i` в кадре `for`, а счётчик
позиций с него отключается. По первому ответу позиционный аргумент после отключённого счётчика — отказ. Тогда
`i++` и `i < 10` в записи `for( int: i 5; i++; i < 10)` отказывают, а тот же второй ответ называет эту запись
общим кодом.

## Программы

Обе — в коде метода; `seen` — наблюдаемое поле.

```lmx
for(int: i 0; i < 3; i := i + 1)
    seen := seen + i
```

```lmx
fn: g (int: a; int: b) int
    return: a * 10 + b
seen := g(int: c 2; 5)
```

## Два чтения

1. Правило как записано. Объявление имени, которого у вызываемого нет, отключает счётчик так же, как объявление
   тёзки вне его позиции. Первая программа отказывает; вторая отказывает. Общий `for` тогда пишет условие и шаг
   по именам.
2. Объявление имени, которого у вызываемого нет вовсе, позиции не занимает и счётчик не отключает; отключает его
   только объявление тёзки вне своей позиции. Первая программа даёт 3; во второй `c` заводится в кадре `g`,
   `a` получает 5, ответ 50. Запись `g(int: b 2; 5)` остаётся отказом.

## Что ещё зависит от ответа

- Сегодняшняя запись тестов `for: (n := 0; n < 3; n := n + 1)`. В ней `n := 0` стоит на собственной позиции
  аргумента, то есть это именованная подача формалу `n`, а такого формала у `for` нет. По книге неизвестное имя
  — ошибка. Если запись должна остаться, нужно сказать, чем здесь `n := 0` отличается от именованной подачи.
- Порядок частей. В примере второго ответа шаг стоит перед условием (`i++; i < 10`), в книге — условие перед
  шагом.

## Масштаб

В `tests/graph` пять записей `for` в четырёх файлах, все одной группой после двоеточия; в исходниках L2 записей
`for` нет. Запись `for(...)` с тремя аргументами сегодня отказывает.
