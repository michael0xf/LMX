## Факт

Ответ Q38 (автор, чат fable_pc, 2026-09-27): k.4 «outside the copied operand subtree is a shared reference» —
чепуха, потому что merge «does not copy unused»: за пределами копируемого ничего не видно, общей ссылке туда
нет ни адресата, ни смысла. Прочтение — `LMX_blog/q/q38.md`, «Как прочитано».

Код ядра сегодня — `dev/l2src_sandbox/lmx_graph_copy_owned.h.lm1` :18 и :25–:30 (дословно):

```
# Pointer cells (@: T): the cell is copied; the pointee is SHARED (-186 k3).
…
# k.4: any Structure whose parent lies outside the copied operand subtree is a shared
# reference (Q22 = II, generalized -- not only a method occurrence): kept by address, not
# copied, parent not rewritten. A Structure whose parent is inside the operand is copied
# as an ordinary Structure. There is no separate METHOD/CALLABLE domain any more; the
# question is answered structurally (child\parent inside the copied set, or not), never by
# a domain classification.
```

Книга (`provenance/semantics-book.md` :1562): «Shared method references are terminals under their contracts.
When `merge` encounters an eternal branch qualified `independent: const: immutable`, it MUST not copy it and
MUST place the original physical value reference directly into the result. … Other used mutable state receives
distinct storage, and the algorithm leaves no references into another mutable arena.» `next_core_tasks.md` :646:
merge «copies mutable used state, preserves shared method references under their contracts, … does not copy
unused state merely because it exists in an enclosing activation or lexical ancestor».

## Вопросы

1. Объём правки k.4. Так ли читается: общая ссылка по адресу (Q22 = II) — только вхождение метода / вечная
   ветвь `independent: const: immutable` по контракту; всякая иная Structure, до которой доходит используемый
   граф операнда, копируется как изменяемое состояние, где бы ни лежал её родитель (внутри или вне операнда);
   до которой не доходит — в копии отсутствует; ссылок из копии наружу нет («leaves no references into another
   mutable arena»). Правило «родитель вне операнда → ссылка» снимается целиком, не уточняется? То же ли чтение
   для ячейки-указателя `@: T` (:18 — сегодня pointee общий): pointee, до которого доходит используемый граф,
   копируется, иначе отсутствует?

2. Гранулярность «используемого» (Opus). Хозяин объявляет `loc` своего типа `Model` и возвращает модель,
   читающую `loc\value` (случай B в q38). Копируется ли вся `loc` как Structure своего типа — раскладка типа
   цела, модель адресует поля индексами типа (как в q39) — или только читаемые поля `loc`, и тогда раскладка
   копии не раскладка `Model`, а индексная адресация модели — тот же вопрос, что q39 (переразложение)?
   Иначе: единица «используемого» — Structure со всеми своими полями или отдельное поле?

## Рекомендация (fable_pc, Opus; до ответа копировщик не правится)

Единица — Structure своего типа: копия целой Structure, до которой доходит используемый граф (её раскладка —
раскладка типа, индексные пути модели находят поля без переразложения); Structure, до которых граф не доходит,
в копии отсутствуют. k.4 снимается: копирование по достижимости из используемого графа, общие ссылки — только
методы и вечные ветви по контракту.
