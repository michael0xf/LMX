## Границы работы

- Начать реализацию проверяемой основы сейчас: **MIR → WASM linear → RISC-V**. Это Path A: существующий L1 → C99 → внешний инструмент. Новый printer L1/L3 не писать.
- Команда интерпретатора и команда `myxa_manager` уже работают, по сообщению автора. Не менять их файлы, задачи, исходники ядра, трансляторы и стабильные `l1src/`, `l2src/`. Нужные исправления основного проекта передавать владельцу с минимальным воспроизведением.
- Grok Bot владеет новым `dev/vm_porting/`: скрипты, небольшие L1-примеры, манифест зависимостей, README и отчёт состояния. Codex ведёт этот файл и сводный план; Bot сообщает результаты через канал, чтобы не редактировать их одновременно.
- Загрузки, распаковки, сторонние checkout, сгенерированный C, бинарники и логи размещать в `dev/vm_porting/build/` (уже исключён из Git). Собственные скрипты, тесты, версии/хэши и краткий отчёт сохранять в Git. Ничего не скачивать поверх существующих каталогов и не коммитить сторонние SDK целиком.
- Использовать официальные источники, фиксировать точную версию/commit, URL, SHA-256, host/target и лицензию. Проверять опубликованные upstream хэши/подписи, если они есть; собственный вычисленный хэш не выдавать за независимое подтверждение.
- Разрешена локальная подготовка нужных переносимых инструментов. Не устанавливать новую ОС/WSL, не менять глобальный PATH, системные настройки, службы или права. Если нужны такие изменения либо платные ресурсы — сообщить, что именно отсутствует, и запросить решение.
- Пункты 4–7 (JVM, WASM GC, Lua 5.4, CIL) остаются очередью после L3 и отдельного согласования интерфейса. Старый план содержит исторические ссылки и представления ядра; они не отменяют актуальное вступление LMX и решения автора. LLVM runtime и BEAM не добавлять.

## Последовательность и критерии

| ID | Задание | Проверяемый результат |
| --- | --- | --- |
| VM-00 | Инвентаризация и native baseline | Найдены реальные версии инструментов/ABI и доступность WSL; один L1 smoke переведён существующим транслятором в C99, собран нативно и выполнен; зафиксированы команды, exit code, stdout и хэши |
| VM-01 | MIR / c2m | Закреплён upstream commit, собраны инструменты, пройден upstream smoke; **тот же сгенерированный C** запускается через MIR с результатом, совпадающим с native baseline; затем проверяются ABI и own/указатели |
| VM-02 | WASM linear | Подготовлены закреплённые wasi-sdk и Wasmtime, тот же корпус C собран для `wasm32-wasip1` и выполнен; проверены файловый preopen в отдельный тестовый каталог, memcpy и данные в linear memory |
| VM-03 | RISC-V | Согласованы compiler target, libc/sysroot и runner; те же C-примеры собраны и выполнены под подходящим эмулятором, результаты сопоставлены с baseline |

Переходить к следующему пункту после отчёта о предыдущем: pass либо конкретный воспроизводимый blocker. Blocked не означает pass; документированный внешний blocker не должен удерживать независимую подготовку следующего пункта. Не начинать сразу несколько новых backend-разработок.

### VM-00: что уже известно, что ещё проверить

Codex выполнил только первичную инвентаризацию Windows, не сборку VM:

- В PATH найдены GCC (`C:/Qt/Tools/mingw1310_64/bin/gcc.exe`), CMake и Ninja. `clang`, `make`, `wasmtime`, `riscv64-linux-gnu-gcc` в этом PATH не найдены; это не доказывает их отсутствие во всех каталогах или в Linux.
- `wsl --list --quiet` возвращает `Ubuntu`. Запуск дистрибутива, Linux-инструменты и их версии в этой проверке ещё не подтверждены.
- Рабочий seed Translator-L1: `C:/Nyasha_Planet/L1/bin/l1trans.exe`. Использование с двумя позиционными путями подтверждено [build_parser_dev.py](../tools/build_parser_dev.py); не копировать исторический пример с `-o` без проверки CLI.
- Dev P0 уже проверен нативно: [инструкция](../dev/l1src_sandbox/README.md), 13 текущих и 131 прежняя проверка. Это не результат на VM. L1 `predef` встраивает зависимости в C: стабильный драйвер незаметно вернёт стабильный parser; для нового поведения использовать именно dev-драйвер.

Подготовить небольшой L1 smoke с детерминированным результатом; затем пример `fopen`/`fread`/`fclose` и `memcpy`, затем операции own/указателей. Брать существующие пригодные fixtures только после проверки их реальных путей и контрактов; [libc_abi.lm1](../l1src/libc_abi.lm1) — материал для изучения, не обещание готового самостоятельного теста. Ручной hello.c допустим для проверки установки инструмента, но не доказывает переносимость L1.

После базовых случаев постепенно включить P0/own и тестовый корпус. Переход к self-tests L2 — только на согласованном завершённом снимке команды ядра, не на меняющихся файлах её dev-песочницы. Не исправлять golden ради зелёного результата.

### VM-01: MIR

[Официальный MIR](https://github.com/vnmakarov/mir) описывает поддерживаемые проверенные платформы Linux/macOS; Windows не считать автоматически поддержанным. Сначала проверить уже имеющийся Ubuntu WSL и выбрать реально подходящий путь по `INSTALL.md`/`MIR.md` закреплённой ревизии. Не превращать задание в порт самого MIR на Win32.

Раздельно отчитаться: сборка MIR; запуск его штатного примера; компиляция сгенерированного L1 C; исполнение и совпадение результата. Зафиксировать используемый режим исполнения. Если остаётся ошибка C/libc, сохранить минимальный исходник и диагностику; не переписывать транслятор самостоятельно и не удалять семантически значимый код из C.

### VM-02: WASM linear

Использовать [wasi-sdk](https://github.com/WebAssembly/wasi-sdk) и [Wasmtime](https://github.com/bytecodealliance/wasmtime/releases), подходящие фактической ОС/архитектуре. Это linear memory/WASI, **не WASM GC и не готовое браузерное приложение**. Давать гостю доступ только к специально подготовленному тестовому каталогу, не ко всему репозиторию или домашнему каталогу. Зафиксировать фактический CLI, а не без проверки повторять команды старого плана.

### VM-03: RISC-V

Для первого дешёвого эксперимента предпочесть Linux ABI в существующем Linux-окружении: `riscv64-linux-gnu` и `qemu-riscv64`, с совместимым sysroot либо статической линковкой. [QEMU user-mode](https://www.qemu.org/docs/master/user/main.html) выполняет гостевые пользовательские программы с системными вызовами поддерживаемой ОС. Не брать `riscv64-unknown-elf`/newlib и затем без runtime запускать результат как Linux executable. Bare-metal/Spike/proxy kernel — отдельный маршрут, не незаметная замена выбранного ABI.
