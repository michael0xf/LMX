# LMX `dev/` — разработка, не стабильный корень

Историческое разделение «стабильный корень / dev» описывает старые снимки. Текущий runtime берётся из явного
[списка canonical inputs](../tools/l2/inputs/README.md), а не копированием всего sandbox или старой стадии.

| путь | роль |
| --- | --- |
| `l1src/` в корне LMX | стабильная версия (после миграции и зеркала песочницы L1) |
| `l2src/` в корне LMX | копия `dev/l2src_sandbox/` на старом месте: ничего не собирается и не тестируется (автор, 2026-09-26; прежний двойник — тег `l2src-twin-20260926`) |
| `dev/l2src_sandbox/` | поддерживаемые 35 runtime-модулей L2, P0/compiler helpers и полный driver L2; временные handwritten frontend/libc ABI и старые фикстуры |
| `dev/l1src_sandbox/` | dev-копия P0 и её printTree; сохраняет пустой вертикальный аргумент, [сборка и тесты](l1src_sandbox/README.md) |
| `dev/graph_interp/` | исторический макет интерпретатора того же графа; раскладка слотов там не является текущей нормой |
| `build/` под `dev/` | артефакты, в git не входят |

Не править корневые `l1src/` / `l2src/` «чтобы попробовать» и не зеркалировать туда новый runtime из dev.
Обычная подготовка использует существующие языковые `manifest` и `stage-copy`: пять списков выбирают 73 файла
(47 runtime/compiler/support, 1 libc ABI, пустой driver.list, 8 tools, 17 short-test files) в новую пустую стадию.
Существующий `bootstrap quick` пишет L3-declarations и переводит P0/compiler/kernel/driver L2 до C-потребителей.
Предыдущие generated outputs не подаются входами; ошибка генерации не разрешает взять старую LM1/C-копию.
Это не source-closed S8.6: handwritten frontend/libc ABI, внешний backend, BASE и часть tooling ещё остаются.

`tools/build_l2src.ps1`, `tools/l2_harness.ps1` и sandbox runners сохраняют отдельные legacy gates и их assertions,
но обычный language-owned bootstrap их не вызывает и при отказе к ним не переходит. Их полный перенос — долг S8.5;
короткий набор не объявлен заменой прежних проверок. Датированные команды и результаты ниже — история этого долга,
не инструкция запускать старый путь как запасной.

## Исторические проверки заголовков и бюджет имён

Закреплённый `l1trans` держит имена типов всего замыкания `predef` одной транслируемой единицы в таблице на **64 имени** (и 4096 байт) и 65-е отвергает словами `too many header type names` — причём в том заголовке, который прочитан последним, а не в том, что добавил тип. На checkpoint сентября 2026 единицы L3 с Thread занимали 62 из 64; актуальное значение надо измерять заново.

`tools/build_l2src.ps1` каталог `dev/l3_interp` **не собирает**, поэтому зелёный гейт L2 об этом классе поломок не говорит ничего: `4ab2877` добавил два типа в заголовок ядра, гейт был зелёным, а все наборы L3 с Thread перестали транслироваться.

Проверки типов, импортов и полного L3-набора сохраняются для переноса без потери assertions. По текущему приоритету
[READ.ME](../READ.ME) до рубежа L3+L2 выполняется необходимый короткий сквозной bootstrap; новая широкая кампания
не является разрешительным gate каждого среза. Исторические команды ниже сохраняются как конкретный gate своего среза:

- `python tools/run_l3_selftest.py` — наборы по умолчанию и проверка бюджета имён;
- `python tools/run_l3_selftest.py --test tests/l3_n9_walk_selftest.lm1` и то же для `tests/l3_n10_walk_selftest.lm1` — они не входят в набор по умолчанию;
- отдельно бюджет: `python tools/l3_type_budget.py` — число имён меряется самим закреплённым транслятором. Зафиксированное в проверке ожидание нужно сопоставлять с текущей зависимой сборкой, а не принимать исторические 62 за норму языка.

Если бюджет изменился по делу, число в `EXPECT` меняют вместе с объяснением причины; подгонять его под результат нельзя. Подробности — в [l3_interp/README.md](l3_interp/README.md#бюджет-имён-типов).
