# Поле-ссылка тела Structure с кандидатом-Structure: связывается при построении или при выполнении тела

Статус: ОТКРЫТ, 2026-10-11. Вопрос задаёт `fable_pc` при срезе R6-2 (4) тикета
[critical_general_receiver_routes_bug](../../../steps/tickets/critical_general_receiver_routes_bug.md)
([перепись](../../../steps/receiver-routes-census-20261010.md), раздел «Slice R6-2 (4)»); передан автору через
Codex почтальоном `lmx_uds` (STATUS FABLE-STATUS-20261011-27).

## Контекст

Книга ([L2 §12](../../../docs/L2_spec_ru.md)): для отсутствующего `b` записи `b: A` и `@: b A` равнозначны —
явное присваивание ссылки; преобразование и `implements` относительно потребителя предшествуют записи.
Общее правило инициализации ([семантика, #dynamic](../../../docs/LMX_semantics.ru.md#dynamic)): вычисляемая
инициализация — два обычных соседних оператора, присваивание выполняется, когда управление доходит до строки;
фазы построения нет.

Транслятор сегодня (замер на `2a711a13`, native и walkroot) делает две формы по-разному:

- связывание `p: Model` в теле юнитовой Structure `Holder` — строка связывания (`l2_ns_bind_item`,
  `l2_emit_ns_refs`): после `h: merge: Holder` ячейка `h\p` сразу указывает на Model;
- типизированная форма `@: Model p Model` в том же теле — оператор тела: после `h: merge: Holder` ячейка `h\p`
  пуста, после голого оператора `h` (Structure выполнена) указывает на Model и `h\p\v` читает 11; `@: Model p q`
  (q — поле-ссылка выше) связывается так же, через q; `@: Model p Other` без поля v — отказ «implements is false
  in assignment»; `@: Model p 5` — «assignment value has incompatible type».

Пять зафиксированных фикстур (`unit_local_reference_model_copy_deep` и родственные, срез COPIER-FULL-COPY
2026-10-10) закрепляют вторую семантику для локальных Structure метода с вложенным референтом: `@: Inner ref Inner`
после выполнения копии указывает на СОБСТВЕННЫЙ Inner копии (самоотносительно), до выполнения — пусто.
Связывание при построении (на вход юнита) такой самоотносительной ссылки выразить не может.

## Вопрос

Какое время связывания — языковое для поля-ссылки тела Structure, чей кандидат — слово-Structure?

1. Построение (тогда типизированная форма тоже связывается при построении; ожидания пяти локальных фикстур
   меняются; что именует `@: Inner ref Inner` при вложенном референте — собственный член?).
2. Выполнение тела (тогда `p: Model` перестаёт связываться при построении — строка связывания становится
   оператором тела).
3. Иное разграничение (например, обе формы — графовые связывания при построении только для слова-Structure, а
   вычисляемый кандидат — оператор).

## Что зависит от ответа

Срез R6-2 (5) (операторы тела результата merge: какие объявления тела — данные, какие — код); срез ядра по
дефекту [MERGE-REFERENCE-TO-OPERAND](../../../steps/defects.md#merge-reference-to-operand) (какие ссылки на
со-операнд видны статически); свидетели `unit_ns_ref_statement`, `unit_ns_ref_var`, `unit_ns_ref_zero`,
закрепляющие текущее поведение. До ответа транслятор остаётся как есть: связывание — при построении,
типизированная форма — при выполнении.
