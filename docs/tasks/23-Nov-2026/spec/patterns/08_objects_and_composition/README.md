# Объекты, зависимости и композиция

[Руководство RU](LMX_Design_Patterns.ru.md) · [Guide EN](LMX_Design_Patterns.en.md)

Все десять исходных паттернов сохранены и проверены на пользу операндов и отдельной библиотеки. Fluent Interface теперь показывает реальную цепочку через OPERANDS_TEMPLATE; остальные примеры сохраняют прямые именованные операции там, где новая оболочка лишь увеличила бы механизм. Примеры работают у одного последовательного владельца; shared mutable состояние в LMX принадлежит Message.

## Повторный просмотр с общими ресиверами — 22 ноября 2026

Каждый пример ниже проверен на применение нового прямого API `fun`. Сохранены действующие клиенты: у предложенных замен либо меняется указанный протокол, либо полный клиент с необходимыми объявлениями исходов и адаптерами на одном текущем ядре не становится короче. Это решение относится к данным небольшим сценариям, а не запрет использовать библиотеку в более крупных программах.

| № | Рассмотрены | Причина сохранения |
| --- | --- | --- |
| 072 | `apply, partial` | Два execute с явно переданным read уже выражают dependency injection; apply добавляет контейнер и разыменование результата, partial создаёт две фабрики с throws вместо двух готовых named actuals. Сам умножающий callback остаётся в клиенте. |
| 073 | `overload, partial` | Locator разрешает один ключ и возвращает fallback для любого другого, после чего клиент вызывает полученный метод. overload добавляет предикаты и исходы отсутствия/неоднозначности, а partial не заменяет сам выбор fallback. |
| 074 | `identity, guard` | Silent.write — процедура, принимающая значение и не возвращающая результат. identity возвращает аргумент, guard проверяет условие; ни один не является более короткой заменой этого no-op с тем же контрактом. |
| 075 | `bracket, once` | Pool.take выдаёт текущий ресурс либо@0, give возвращает его в пул; demo проверяет идентичность после возврата и нулевой второй take. bracket требует отдельный action и release-адаптер и не сокращает серверную выдачу/возврат. once запретил бы повторную выдачу после give. |
| 076 | `derive, overload` | Два исходных объекта выбираются по kind=0 либоfallback, затем копируются. derive добавляет пустое наложение к готовому copy; overload требует дополнительные предикаты и обработку fallback. Проверяемая независимость новых экземпляров не допускает возврата общего исходного объекта. |
| 077 | `memoize` | Реестр уже имеет два постоянных экземпляра и возвращает второй для любого ненулевого ключа. memoize потребовал бы фабрику, сравнение векторов ключей и сохранение кеширующего callable; он не устраняет существующие экземпляры или правило fallback. |
| 078 | `predicate` | Пригодность непосредственно проверяется satisfies(item;Marker). predicate — фабрика callable с дополнительной сигнатурой/ошибками; он длиннее явного отображения результата проверки в0/1 и не заменяет само требование Marker. |
| 079 | `bindFields, derive, patch` | withCount/withPrice изменяют тот же объект и возвращают его для fluent-цепочки. bindFields возвращает метод с копией DATA, derive/patch создают новый контейнер; они меняют идентичность и наблюдаемые записи Options. Для сохранения mutation те же setters остаются. |
| 080 | `project, apply` | Оба объекта разделяют одну изменяемую TypeData, и второе чтение должно увидеть damage3 после изменения общего объекта. project делает копию, apply добавляет вызов/запись результата к единственному чтению item.kind.damage. |
| 081 | `derive, bindFields` | Extension устанавливается в существующий Host и возвращается query с той же идентичностью. derive копирует, bindFields предназначен для DATA callable; они не заменяют эту установку и запрос без изменения владельца и API. |
