## Изменение

Удалены root_declares/root_declare/space_reach и code_apart. Поля данных видны прежнему
registry целиком; исполнение именованной записи больше не пропускает корневое объявление.
Живая разрешённая голова вызывает метод или запускает обычную Structure прежним механизмом.
Native emitter тоже выбирает живую цель, включая обычную Structure из поданных данных,
которая затеняет лексический метод. Искусственных методов и новой таблицы нет.
Экспорт graph_run сокращён с 53 до 50; graph API остаётся 68.

Standalone written groups остаются значениями по Р17. Block и emitter их пропускают;
scanner нормализует поля только явно выбранного CodeBody в свою прежнюю очередь. Аргументы
if/while/until/for, поля else/finally и statement-позиции for-header читаются как код,
condition — как выражение. Вложенное самостоятельное значение не становится кодом.
Own collector не добавляет его объявления. Созданные FN values, включая описание без code,
пропускаются всеми этими читателями. Требуемые/возможные entry snapshots среза 370 сохранены;
LHS и адресование не превращаются в чтения. frame.own и проход собственных данных не расширены.

## Независимые наблюдения

- self_record_dispatch: self x становится 3; Step из D увеличивает n до 1; глобальный
  лексический Step не вызывается, global_calls остаётся 0.
- anonymous_code_value: quiet не получает phantom и имеет ноль own fields. Написанные
  группы не вызывают tick и не требуют missing_a/b/c. После явно выбранного Body calls=0,
  x=3; prefix operator AST +(tick()+1) вызывает tick один раз. Numeric consumer math
  даёт 5 и вызывает tick второй раз. after_ast=1, after_math=2, arithmetic=14, body_x=3.
- struct_root_declares: один S с двумя actual отказывает с 5 после reached=1,
  до reached=2. Это проверка обычного запуска, без неоднозначных двух S.
- root_closed_names: анонимное значение closed сохраняет написанные A:B и B:A;
  seen=1, полный дамп не скрывает замкнутые имена.
- index_cycle_dump: настоящий созданный цикл виден под graph; A:(B A), B:(A B), seen=1.

Принятый graph 371 на тех же окончательных исходниках отвечает соответственно 5, 3 и 0
вместо новых 0, 0 и 5 для первых трёх программ. Квитанции baseline371-final-* сохраняют
полные BEFORE/AFTER; struct_root_declares на старом маршруте доходит до reached=2.
Golden новых состояний задаёт числа и полные сохраняемые структуры, а не только exit.
Старый мутант удалённого root declaration skip не объявляется повторно убитым.
