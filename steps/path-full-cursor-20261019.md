# Полный курсор пути — частный срез, не приёмка N4-U

Снимок Codex 2026-10-19. Единственный writer/build — Codex. Main сохраняет
формальный WIP `a8163df3…`, проверяемый отдельным full07. Изменения ниже
находятся только в `build/codex_mixed_path_fold_*`; они **не перенесены в dev**.
Норма, kernel runtime и положительные ожидания исходного корпуса не менялись.

## Реализация

Прекурсор01 исправляет общую запись: тип каждого INDEX, модель следующего
NAME, compiler-only `model_step` — происхождение текущего контракта, а не
родитель кандидата. `l2_place_step` читает индексный span из полной
последовательности; index-leaf сохраняет свой тип. Проверка этого прекурсора
дала12298 compiler checks/0 ошибок,4097 чередующихся индексов. Это не
исполнение глубокого графа и не результат следующего варианта04.

В03 native `l2_emit_path_resolved` передаёт работу одному
`l2_emit_path_cursor`, который проходит **все** подготовленные шаги.
Отдельный старый цикл native Array-place удалён. Адрес выбранной ячейки
стабилизируется до эффектного индекса/RHS. `lmx_array_cell_in` использует
существующий типизированный пул; новый механизм адресации не введён.

Обходчик также читает все шаги. Шесть прежних routines получили явный
контекст подготовленного `L2Path`; их старые сигнатуры лишь передают
аргументы в те же тела. Отдельная старая Array-цепь удалена. Сериализация
для существующих потребителей хранит весь `n`, а не `names`; INDEX-метка17
существует только в compiler adapter и **не является новым runtime opcode**.
Graph по-прежнему использует существующие ELEM/OF/PUT_OF/ADDRESS и обычные
карты. Второго разбора текста новые emitters не выполняют.

Это ещё не доказательство миграции всех старых потребителей/корней/readonly,
composed/capture-контрактов и всех COUNT/EMIT-вариантов. При переносе нужно
проследить оставшиеся адаптеры, а не объявлять их готовыми по этим тестам.

## Причинная проверка модели после вложенной Structure

`codex_mixed_path_effectful_origin_02.lm2` использует путь
`roots[pickA(...)]\Nested\link\samples[pickB(...)]`. В03 native проходит,
а фактический обход даёт108 вместо7: `pickA` вызван8 раз вместо4. Данные,
запись67 и71 через адрес уже верны; ошибка именно в повторном вычислении
префикса при выборе модели. Обе комбинации корня сохраняют это расхождение.

В04 common producer сохраняет принимающую модель через структурного
ребёнка уже допущенного holder. Native читает модель **следующего шага из
записи**, а не выбирает её повторно по виду поля. Обходчик использует ту же
непрерывную цепь требований. Новый кэш индексов, guard-stack, opcode,
runtime-поле или второй граф не добавлены. Тот же неизменённый позитив
проходит во всех четырёх режимах, `pickA/pickB` вызываются ровно4 раза.
