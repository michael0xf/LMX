# Именованные фактические обычного вызова (книга §10, :1060)

Строка плана — `next_core_tasks.md`, «Именованные фактические обычного вызова». Норма — книга :1060: «Positional actual
arguments precede named ones. After the first named argument, subsequent arguments must also be named. An unknown name,
duplicate assignment to one argument, missing required argument or ordering violation is an error. A named argument's
body is supplied as a structural value when that is the receiving expression's specified mode; it does not become an
arbitrary sequence of immediate calls.»

## 1. Замер (Opus, 2026-09-28, на `d4196be`)

- **Как читается вызов.** Обычный вызов привязывает фактические по позиции: проверка (`l2_check_call`), подготовка и
  эмиссия (`l2_prep`, `l2_emit_call`), обход (`l2_rw_call`) и скан свободных имён (`l2_scan_node`) — все идут по полям
  тела вызова и делят их на фактические через `l2_expr_span`. Именованное фактическое понимается только в виде
  `Name: ()` (D-23, `l2_named_empty_actual` — семь мест). Любое другое `f(a: 8; b: 1)` отказывает: «unknown method»,
  frame=a. Кадр `a: 8` читается как вызов `a`.
- **Как это выглядит в P0** (printTree). `f(a: 8; b: 1)` — кадр `f`, тело `[кадр a (8), кадр b (1)]`. `g(x)` и `g: x` —
  одно дерево: кадр `g` с телом `[x]`. `f(x + 1, -1)` — плоско: `[x, +, 1, -1]`, где `-1` — один атом. А `f(x, - 1)` —
  `[x, -, 1]`, одно фактическое `x - 1`.
- **Общие ворота привязки уже есть.** Это `l2_bind_actuals`, которым привязывает свои фактические ресивер `table`
  (`steps/table-receiver.md` §5). Слова отказов — книги: аргумент дважды, имя не формала, позиционное после
  именованного, больше позиционных, чем формалов, формал без фактического.
- **Как читается вызываемый.** `l2_call_head_method` (D-106): сначала callable-формал вызывающего метода (контракт —
  его формалы), затем метод по имени или по пути (`A\M` — метод поля-ссылки).

## 2. Механизм

Один проход до всех остальных — `l2_bind_calls`, первым шагом `l2_parse_unit` и `l2_parse_library`. Он читает тело
каждого метода (E и процедуры именованных Structure включительно) и `return`-trailer, а тела вложенных методов — как
их собственные. У каждого кадра, чей заголовок `l2_call_head_method` читает как вызываемого, фактические привязываются
`l2_bind_actuals` к формалам вызываемого. Порядок формалов:

- все фактические позиционные и по порядку — вызов остаётся как написан (дерево не трогается);
- есть именованное — тело вызова переписывается в порядке формалов: у позиционного — его поля как написаны, у
  именованного — тело его кадра;
- `name: ()` — P0 сплющивает единственную `()`, у кадра нет полей — даёт пустую Structure (узел Structure без полей).

**Тело именованного аргумента — одно значение** (книга). Переписанный вызов читается назад по `l2_expr_span`, и каждое
фактическое обязано быть одним фактическим своих полей. Тело, которое при позиционном чтении стало бы несколькими
(`p: 1 2`) или склеилось бы с соседом (`b: - 1` после `a: x` даёт `x - 1`), хранится целым — одной Structure.

Так все проходы видят позиционный вызов. Отдельной ветки для именованных у проверки, эмиссии, обхода и скана нет.

**Следствия.**
- *Заголовок-формал.* Кадр среди фактических, заголовок которого называет формал вызываемого, — аргумент этого формала,
  что бы ещё ни называло это имя: P0 не различает `g(2)` и `g: 2` (свидетель `unit_named_actual_formal_name`).
- *Слова арности.* Число фактических у вызова метода проверяют ворота. Прежние «incompatible entry signature» за
  лишние или недостающие фактические становятся словами книги («more arguments than f has formals», «f has no
  argument b»).
- *D-23 обобщён.* `l2_named_empty_actual` (кадр `x:` без полей среди фактических) стал `l2_empty_actual` — пустая
  Structure позиционно для формала Structure-типа. Особой формы именованного больше нет: `take(x: ())` после привязки —
  та же пустая Structure на месте `x`.

## 3. Итог (Opus, 2026-09-28)

**Строки харнесса** (новые; все — в обоих режимах, кроме строки callable-формала — он вне обходимого подмножества,
как `unit_callable_anon`):
- `unit_named_actuals` и обходимый двойник: `f(a: 8; b: 1)`, `f(b: 1; a: 8)`, `f(8; b: 1)`, `f(a: x; b: 0 + 1)`,
  тот же вызов из метода и вызов, привязанный внутри аргумента, `f(b: 1; a: f(b: 1; a: 9))` — все 7;
- пять отказов ворот словами книги: аргумент дважды, `c` — не аргумент, позиционное после именованного, `f has no
  argument b`, «given by position and again by name»;
- `unit_named_actual_formal` — `op(x: value)` по формалу контракта;
- `unit_named_actual_path` — `A\M(v: 4U)`;

  formals»;
- `unit_call_args_refuse_nested`, `unit_call_args_refuse_named` — «add has no argument b».

  В `add( arg: 1 2 )` имя `arg` не формал `add`: это позиционное фактическое, и `b` остаётся без своего.

## 4. Исправление по REVIEW 394f6a9 (Opus, 2026-09-28)

**Предел в 16 формалов снят** (обязательное исправление; проба P62 a fable_pc). `l2_bind_call` держал слоты привязки в
массивах на 16 и отказывал вызову метода с 17 формалами словами «internal: a callee with more formals than a binding
holds». Это регресс на законной программе: предела у языка нет. Теперь слоты заводятся по числу формалов вызываемого
(`l2_m_arity`): `l2_bind_call` выделяет их и освобождает, привязка идёт в `l2_bind_call_in` — прежнее тело без изменений,
кроме того, откуда берутся массивы.

**Строки** (каждая — и обходимым двойником):
- `unit_named_actual_many` — 17 формалов позиционно (25) и с именованными за шестнадцатым в обратном порядке
  (`a17: 20; a16: 16` — 28). Под копией с прежними 16 слотами — отказ «internal …», красная.
- `unit_named_actual_trailer` — именованный вызов в хвосте `return:` метода (P0 вешает хвост на кадр метода, вне тела;
  M54 и P62 c fable_pc). Под M54 (хвост не привязывается) — «unknown method», красная.
- `unit_named_actual_sub` — именованный вызов sub в форме оператора (P62 d). Без прохода привязки — «unknown method»,
  красная.

## 5. Тело вызова остаётся как написано (fable, 2026-10-04)

Механизм §2 изменён в одном: привязка больше не переписывает тело вызова. Решение Codex
FABLE-CODEX-20261004-03 и полный отчёт — [§41](fable-continuation-20261003.md#written-body-mechanism)
и [§43 журнала](fable-continuation-20261003.md#written-body-kept).

- **Тело.** Первое и последнее поле, счётчик, связи полей и именующие кадры остаются такими, какими
  их дал P0.
- **Проекция.** Список фактических в порядке формалов — тело именованного на месте своего формала,
  целое тело одной Structure — лежит в записи привязки (`l2_bnd_first`, `l2_bnd_count`) рядом с
  рангом записи и именующим кадром каждого формала.
- **Выбор вида.** Читатель берёт фактические вызова через `l2_call_actuals(body)` там, где входит в
  тело: у привязанного тела это проекция, у любого другого — его собственные поля. Сама привязка
  читает написанное тело и проходит именующий кадр насквозь, к его телу. Итератор только шагает.
- **Что читает проекцию.** Проверка вызова, нативный вызов, вызов в графе; скан свободных имён; все
  обходчики, которые придают смысл встреченному кадру: скан merge, скан канала throw, сканы
  использования ссылки, локалы метода, receive, место под собственные строки, упоминания и return
  у callable merge, скан захватов, uses у `implements`, узел свободного имени для диагностики.
  `l2_declaration` привязанный вызов не читает вовсе: он ничего не объявляет.
- **Память привязки** освобождается в конце трансляции (`l2_bound_free`), пока исходное дерево живо.

Строка §2 «Так все проходы видят позиционный вызов» теперь читается так: все проходы видят
позиционный список через один аксессор; дерево P0 при этом не тронуто.

**Мутант `norewrite` из §3 больше не существует**: переписи нет. Его место занимают контроли —
копии транслятора, где один читатель снова входит в написанное тело:

| Контроль: читатель снова входит в написанное тело | Что отличается |
|---|---|
| проверка вызова; нативный вызов (фактическое по формалу); вызов в графе — операнд и оператор | вывод: все строки с именованными |
| скан свободных имён: вызов метода; вызов callable-формала или по пути; вызов-оператор | вывод: 17, 6 и 4 строки гейта |
| скан merge; скан канала throw по полям тела | вывод у `unit_named_actual_structure_name` (у библиотечной строки — отказ «unsupported library ABI»); в гейте — только число аллокаций |
| скан использования ссылки | вывод у `unit_named_actual_reference_whole` (строка-проба) |
| обход привязки принимает именующий кадр за оператор вызывающего | `unit_named_actual_method_names`: «more arguments than h has formals» |
| `l2_declaration`, место под собственные строки, внутренние поля в скане throw | только число аллокаций |
| нативный вызов (счёт фактических), вызов в графе по неразрешённому пути, упоминания и сегменты у скана ссылки, локалы метода, receive, узел свободного имени, uses у `implements`, упоминания и return у callable merge, скан захватов | ничего: именующий кадр для них прозрачен; переведены ради одного правила |
| память привязки не освобождается | `live` больше нуля в журнале аллокаций |
| память привязки освобождается сразу после прохода привязки | вывод: все строки с именованными |

**Новые строки** — в [§43 журнала](fable-continuation-20261003.md#written-body-kept): имя формала
совпадает с именем из области вызывающего (поле юнита, локал, скрытый вход, метод, Structure,
типизированная ссылка, имя из хозяина вложенного определения), и факт, который ищет анализ, стоит
только внутри именованного фактического.

**Открыто** (воспроизводится на прежнем трансляторе, к переписи не относится): именованное
фактическое в индексе заголовка записи (`unit_named_actual_head_index`) и у удерживаемого callable
(`unit_named_actual_held`) — привязка туда не доходит, «unknown method».
