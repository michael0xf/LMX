# `sort` и `unique`: общие операции ядра

Источник реализации — [corePerlExamples.lmx](src/corePerlExamples.lmx). Дополнение
общего реестра — [CORE_PERL_ADDITIONS_20261123.json](CORE_PERL_ADDITIONS_20261123.json).
Это прямые ресиверы ядра; прикладной код не импортирует сравнительные библиотеки.
Имена `sort` и `unique` используются также в наборах сравнения с Julia.

## Общий договор

`items: @` обозначает любой допустимый Array, в том числе плотный `[]T` и обычную
структуру, которая уже является массивом `@`. Тип элемента не зашит в алгоритм.
Оба ресивера создают новый внешний массив с тем же полным `arrayType`, сохраняют
значения примитивных элементов и идентичность ссылочных элементов. Глубокой копии
вложенных графов нет. Пустой и одноэлементный вход допустимы; callback для них не
вызывается. Служебные переменные находятся в `private`; публичная сигнатура
содержит только явно перечисленные аргументы.

Callbacks выполняются последовательно в одном Message. Они не должны менять
слоты/длину входного массива или ключи сравнения во время обхода. При отказе
callback исходный массив не изменён; частичный результат не возвращается.
Побочные эффекты, которые сам callback сделал вне массива, не откатываются.
Обычные именованные выходы callback проходят через существующий `FxApply` и
сохраняются в `FxCallFailure`. Ошибки ядра, типов, индексов и размеров объявлены
конечными `throws` прямо в коде.

## `sort(items; compare)`

`compare(first; second)` принимает два значения элементов целиком, включая
структуры, и возвращает инициализированный `int`: отрицательный — первый раньше,
ноль — эквивалентные ключи, положительный — второй раньше. Callback должен задавать
согласованный порядок; алгоритм не проверяет транзитивность перебором троек.
Значения элементов могут иметь любые типы: `int` относится только к результату
сравнения. Неподходящий результат callback даёт `SequenceElement`.

Реализована стабильная сортировка слиянием снизу вверх. При равенстве выбирается
элемент левой половины. Число сравнений — `O(n log n)`, дополнительное хранение —
`O(n)`. Ширина серии и концы интервалов вычисляются с проверкой до сложения;
фиксированной длины слова, максимального числа элементов или рекурсивного стека
в алгоритме нет. Оригинал не меняется, даже если сравнение прервало сортировку.

Сравнение Perl использует настоящий `sort { ... } @items`, а отдельная пара
реализаций содержит собственный общий алгоритм слияния. Стабильность и договор
знака компаратора заданы в [документации Perl](https://perldoc.perl.org/5.40.1/functions/sort).

## `unique(items; same=0)`

`unique(items)` использует общее обычное равенство скаляров и рекурсивное сравнение Array через `FxValueSame` / `FxEqualFields`. Проверка `AnyArray` идёт по существующему AR01, без таблицы известных типов; пара Array/не-Array различна. Для ссылок сохраняется обычное равенство языка, не изобретается обход графа.

Необязательный `same(first; second)` получает два значения элементов и возвращает обычный
инициализированный `int`: ноль — различны, ненулевое значение — одинаковы.
Другой тип результата даёт `FxPredicate`. При каждом новом элементе проверяются
уже сохранённые представители по порядку. Первый экземпляр сохраняется,
последующие эквивалентные отбрасываются. Предполагается согласованное отношение
эквивалентности; алгоритм не изобретает общий хеш для произвольных значений.
Худшее число проверок — `O(n²)`, дополнительное хранение — `O(n)`.

У `List::Util::uniq` в Perl нет callback: он использует собственное сравнение
строковых представлений с отдельной обработкой `undef`. Поэтому прикладной
пример ограничен каноническими целыми числами, для которых результаты совпадают.
Для общего договора с пользовательским `same` рядом приведена полная отдельная
реализация Perl, но клиент её не импортирует. См.
[List::Util 1.63](https://perldoc.perl.org/5.40.1/List::Util#uniq).

## Message и проверка

Эти алгоритмы синхронные: их временные массивы и callbacks принадлежат текущему
Message. Если нужно исполнить всю операцию асинхронно, уже существующий `post`
на метод владельца обеспечивает доставку и возврат результата. Отдельный поток
сортировки, общий изменяемый массив между аренами или второй API futures здесь
не вводятся.

Исходники LMX проверяются по текущей спецификации; доступного исполнителя LMX в
этой поставке нет. Поэтому статус исполнения остаётся `NOT_RUN`. Отдельные Perl
реализации и реальные клиентские примеры проверяются исполняемыми тестами;
успех их тестов не считается запуском LMX.

Обычная и операндная формы `unique` и `sort` публикуются под теми же именами и используют те же тела. Полные правила равенства, включая uninit, numeric cases и callbacks, находятся в [общем договоре](../../GENERIC_EQUALITY.md); контекст захвата whole-value и роли — в [PUBLICATION_CONTRACT.md](PUBLICATION_CONTRACT.md).
