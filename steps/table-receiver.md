# Ресивер `table` над обыкновенными Structure — замер и предложение (Opus, 2026-09-28)

Записка — замер и предложение для ревью; кода нет. Строка плана — §GATE «Все настройки — в декоративных таблицах»
(Q36, Q41, Q43). Нормы дословно — `LMX_blog/2026-09-27.md` «Q36», «Q41», «Q43»; вопросы — `LMX_blog/q/q36.md`,
`q41.md`, `q43.md`.

## 1. Нормы

- **Q36:** «Вообще все настройки должны лежать в "декоративных таблицах" как впредыдущем проекте lingvamyxa_prev»;
  на L1 «_ничего не будет написано_».
- **Q41:** это реализация таблицы в старом коде; «ресивер table должен потреблять обыкновенные структуры аргументами
  (ничего не парсить специально для table row и так далее!!!!)».
- **Q43:** `rows:` — не строки, а цепочка аргументов, которую режет число столбцов из `columns:`; «Каждый аргумент может
  быть и атомом и структурой и даже массивом — все совершенно через общие ворота должно идти!!!»; отказ ячейке-не-атому
  — баг.
- **Книга lingvamyxa_prev** (`Lingvamyxa_spec.txt`, строки проверены): :10510 — «In an L2 or L3 table profile, `table:`
  and `join:` are ordinary receiver Frames whose bodies are valid LMX Structures. `table:` explicitly materializes one
  table representation as an Lmx graph … A named result is attached as an ordinary child occurrence to the Structure
  selected by the source operation; it is not inserted into a runtime namespace»; :18189 — ранний загрузчик узнаёт
  корневые `table:`/`join:` «because the ordinary receiver bindings do not yet exist … This is a bootstrap limitation,
  not a second table model»; там же: первый столбец — ключ строки; `source` первым атомом тела просит проекцию на
  время трансляции/модуля; строки плотные — число ячеек кратно числу столбцов, физические строки источника ничего не
  значат; в `columns:` голый атом — имя столбца, анонимная Structure — имя и метаданные.

## 2. Замер

### 2.1 lingvamyxa_prev

- `lm2/table.lm2` — не ресивер, а отдельный переформатировщик (выравнивает таблицы в исходнике).
- **Загрузчик реестра** (`lm2/registry_source_loader_unit_payload.lm2`): только корневые `table:`/`join:`; `source`
  первым и один раз (:677, «table source marker must be the first present table body field and appear exactly
  once»); ячейка `i` — столбцу `i % column_count`, строка — когда заполнен последний (:590–:605); остаток — отказ
  «rows have %zu fields, not divisible by %zu columns» (:608–:612); **ключевой столбец — только атом** (:596–:599,
  «table rows currently expect atom cells in the key column») — по Q43 такой отказ был бы багом.
- **Путь транслятора** (`lm2/trans_l1_statement.lm2`, `trans_l1_registry.lm2` — по карте, строки не перепроверены):
  `columns:` читает обычный разборщик формалов (`lm_trans_formal_param_list_from_structure`): `(T: n)` — столбец `n`
  типа `T`, `(@: char kind)` — глубина адреса 1; ячейка декодируется по типу столбца, столбец типа `node` держит сам
  узел; результат — дескриптор (`LmTableDescriptor`: имя, столбцы, строки) в реестре по имени `name:`; доступ —
  `<таблица>.<столбец>` по ключу первого столбца.
- **Вывод:** и там это особый разбор дерева P0, не привязка аргументов ресивера; книга прямо называет это временным.

### 2.2 LMX сегодня

- **Потребитель один** — преобразования (S7): `convert.lm2` рядом с источником, одна таблица `primitive.convert`.
- **Чтение — особый обход P0** (`dev/l2src_sandbox/l2trans.lm1`): `l2_convert_load` (:6485) разбирает файл,
  `l2_convert_walk` (:6420) ищет кадры `columns:` и `rows:` на ЛЮБОЙ глубине дерева; `table:`, `name:`, `source` не
  читаются — две таблицы в одном файле не различаются.
- **Столбцы** — `l2_convert_columns` (:6357): имя столбца — последний атом кадра, тип столбца не читается; шесть имён
  (`from`, `to`, `forbidden`, `kind`, `receiver`, `impl`) — **закрытый список** `l2_convert_canon` (:6339); столбец с
  другим именем хранится в строке и не читается.
- **Строки** — по Q43 уже цепочка аргументов: ячейка — одно фактическое (`l2_expr_span`), хранится узлом
  (`l2_convert_keep`, :6303, `l2_cv_arg`); место ячейки — по имени столбца.
- **Запрос** — `l2_convert_hit(from, to)` (:6594): линейный поиск по двум столбцам; ячейка-не-имя, которая нужна
  строке, — located-отказ (вычисление аргумента таблицы не портировано).
- **Второй закрытый список** — `l2_prim_kind` (:11047): имена примитивов зашиты в транслятор (комментарий: «Hosted
  primitive.description rows from lingvamyxa_prev/lm2/primitive.lm2»), два признака — `cell` и `forbidden` —
  выведены из таблицы вручную (q36).

## 3. Предложение

**Ресивер.** `table:` — вызов ресивера `table`, тело — его фактические, привязанные общими воротами аргументов (как у
любого вызова: именованное фактическое `name:` — формалу `name`, и т. д.), без поиска кадров по дереву:
- `source` — голый атом-флаг (первым): таблица — данные трансляции (проекция на время трансляции), не значение
  программы;
- `name:` — имя таблицы (атом; обратные кавычки — часть имени-атома);
- `columns:` — Structure формалов: `(T: n)` разбирает тот же разборщик, что формалы метода; `T` — тип столбца
  (дескриптор), `n` — имя;
- `rows:` — цепочка фактических, режется числом столбцов; каждая ячейка — фактическое через общие ворота (атом,
  Structure, массив) и привязывается к своему формалу-столбцу обычным механизмом.

Резка `rows:` числом столбцов — **единственное место, где `table` отличается от обычного вызова**: число фактических в
`rows:` кратно числу формалов-столбцов, а не равно ему (N строк по N фактических). Это норма автора, не
подразумевание (Q43, дословно: «rows: потребляет не строки а просто цепочку атомов которые вы сами разюиваете на
строки так как знаете число солонок из columns:»; REVIEW 7dad13b, замечание 1).

**Результат** — значение-таблица: строки как Structure с полями по именам столбцов, под именем `name:`. Потребитель
транслятора (преобразования) запрашивает её по имени таблицы и по именам столбцов, а не по закрытому списку.

**Срезы:**
1. Ресивер `table` в трансляторе: разбор `table:` как вызова (привязка `source`/`name:`/`columns:`/`rows:` общими
   воротами), таблица по имени; `convert.lm2` читается через него, `l2_convert_walk`/`l2_convert_canon` уходят;
   поведение преобразований не меняется (корпус), свидетели B2 (`unit_s7_conv_*`) остаются требованиями.
2. `primitive.description` — таблица рядом с источником по образцу `lingvamyxa_prev/lm2/primitive.lm2`; `l2_prim_kind`
   читает её (признаки `cell`, `forbidden` — столбцы), закрытый список уходит.
3. Инвентарь остальных закрытых списков и настроек транслятора и ядра — по одному в таблицу (строка §GATE).

## 4. Вопросы к ревью

1. `source` — таблица времени трансляции (данные транслятора); `table:` без `source` — значение программы (Table в
   графе, книга :10510). Срез 1 — только `source`-таблицы (транслятору нужны свои данные); таблица-значение — позже,
   вместе с исполнением ресивера в программе. Так?
2. Ключ: книга — первый столбец ключ; у `primitive.convert` поиск по паре (`from`, `to`). Запрос по нескольким столбцам
   — общий (по именам столбцов), без особого ключа — или первый столбец обязан быть уникальным ключом?
3. Где объявлен ресивер `table` для транслятора — встроен (как сегодня `sizeof`, `length`), или L2-объявление в
   библиотеке рядом (`fn: table (...)`)? Для среза 1 предлагаю встроенный, с формалами, объявленными один раз в
   трансляторе, и привязкой общими воротами.

## 5. Срез 1 — ресивер `table`, `convert.lm2` через него (Opus, 2026-09-28)

По ответам и замечаниям REVIEW 7dad13b. Код — `dev/l2src_sandbox/l2trans.lm1` (и двойник `l2src/`).

- **Заголовок ресивера — данные.** `l2_table_header`: `fn: table (@: Lmx source; @: Lmx name; @: Lmx columns; @: Lmx
  rows) Lmx`; P0 разбирает строку, формалы читает `l2_typed_formal` — тот же разборщик, что у формалов метода
  (`l2_table_formals`, один раз). Каждый формал — обыкновенная Structure (Q41).
- **Привязка — общими воротами.** `l2_bind_actuals` — правило книги §10 («Positional actual arguments precede named
  ones»): фактическое режет `l2_expr_span`; позиционное — следующему формалу; именованное — кадр, чья голова — имя
  формала (квотированное написание — то же имя), — этому формалу, его тело — значение. Located-отказы словами книги:
  аргумент дважды, после именованного — имя не формала или позиционное, позиционных больше, чем формалов, формал без
  фактического. **Обычный вызов (`l2_check_call`) по-прежнему привязывает по позиции** (кроме `Name: ()`, D-23):
  именованные фактические обычного вызова через те же ворота — строка плана §3.
- **Таблицы источника.** `l2_table_source`: `table:` в корне входа трансляции, чьё тело начинается атомом `source`
  (книга prev :663, :684), строятся по порядку. Иное — не таблица трансляции: `table:` без `source` — место построения
  во время выполнения, особого отказа нет (ответ 1); ниже корня транслятор не смотрит (обход `l2_convert_walk` искал
  `columns:`/`rows:` на любой глубине).
- **Таблица** (`l2_table_call`). Имя — один атом `name:`; одно имя — одна таблица источника. Столбцы — формалы
  `columns:`: имя — как у формала (последний атом кадра формала; голый атом — имя), тип — как записан. Строки — цепочка
  `rows:`, ячейка — одно фактическое любого вида (Q43), хранится узлом; режется числом столбцов (§3).
- **Запрос.** Преобразование спрашивает таблицу `primitive.convert` по имени (`l2_table_find`) и свои столбцы — `from`,
  `to`, `forbidden`, `receiver`, `impl` — по имени (`l2_table_col`, `l2_convert_colname`); таблица хранит и любые другие.
  `kind` преобразование не читает и больше не требует. Закрытый список `l2_convert_canon`, обход `l2_convert_walk`,
  `l2_convert_columns`/`l2_convert_keep` и шестислотовая раскладка строки удалены.
- **Имена в кавычках** (замечание 3). Обратные кавычки — квотированное написание того же имени, как везде в трансляторе
  (`l2_payload_eq`; книга — «quoted identifier spelling»): `l2_payload_same`. Имя с точкой пишется только в кавычках:
  P0 читает голое `primitive.convert` тремя атомами `primitive`, `.`, `convert` (замер printTree), и такое `name:` —
  не имя одной таблицы. Свидетель — `unit_s7_tbl_quoted` (имена столбцов в кавычках).
- **Типы столбцов и ячейка-не-имя** (замечание 2). `(class: from)` через `l2_typed_formal` — «unknown type»: `class` и
  `categoryFlag` определяют таблицы (`class` и `primitive.description` в `lingvamyxa_prev/lm2/primitive.lm2`), которых
  у транслятора ещё нет — срез 2. До него тип столбца хранится как записан. Ячейка-Structure в столбце, который
  преобразование не читает, принимается (`unit_s7_conv_cellstruct`, Structure в `kind`); ячейка, которая нужна

## 7. Срез 2 — `primitive.description` вместо `l2_prim_kind`; таблицы транслятора читаются в начале (Opus, 2026-09-28)

(открыт), до ответа — рядом с источником.

- **Замер** (транслятор с пробой в `l2_prim_kind` и `l2_colon_types_compatible`, 873 источника песочницы, нативно):

## 8. Срез 3 — таблица в любом месте программы (Q46) (Opus, 2026-09-28; план, кода нет)

**Норма.** Автор, Q46 и общее правило того же дня (`LMX_blog/2026-09-27.md`):
- «таблица это тупо ресивер table. ГДЕ ХОЧЕТ ТАМ И ЛЕЖИТ -- В ЛЮБОМ МЕСТЕ ПРОГРАММЫ»;
- «никаких специальных операторов и специальных конструкций и специальных файлов».

Книга (`provenance/semantics-book.md` :1642): связывание модуля «neither scans arbitrary directories»; провайдеры
«are selected by an explicit reference, configuration or supplied Table»; «There is no separate semantic import
operation: only `merge` performs graph composition».

**Замер (`99511ff`).**

*Транслятор.*
- Таблицы транслятора читает `l2_input_tables` из файлов с фиксированными именами рядом с источником: `convert.lm2`
  и `primitive.lm2` (`l2_convert_beside`).
- Из этих файлов берутся только вызовы `table: source …` в корне (`l2_table_source`: «nothing below the root is
  looked into»).
- Собственные вызовы `table:` переводимого источника таблицами не читаются вовсе: `l2_table_source` вызывает только
  `l2_input_tables`.
- Файл-реализация, который называет ячейка `impl` строки `primitive.convert`, ищется рядом с источником
  (`l2_convert_beside`).
- Вопросы: `l2_convert_load` и `l2_prim_load` — в начале трансляции и ещё раз у места вопроса.

*Harness.*
- Копирует `convert.lm2`, `primitive.lm2` и `convert_impl.lm2` песочницы в `src` под этими именами.
- Строки со свойствами `Table`, `Primitive`, `Impl` (26, 9 и 3) копируют свой файл в свой каталог **под фиксированным
  именем** — переименованием. Поэтому их отказы говорят `convert.lm2:…` / `primitive.lm2:…`, какой бы файл ни был
  взят: 23 Needle называют эти имена, 5 — фразы про «table file of the translator».
- Другие инструменты l2trans на программах не запускают: `build_l2src`, `gate_p0_header`, `l2_provenance_probe`,
  `own_lookup_audit`, `peak_mem` собирают или разбирают исходник транслятора.

**Предложение.**
- *Программа* — переводимый источник и её прочие файлы, названные явно при вызове:
  `l2trans [--walk-methods] [--library] main.lm2 [part.lm2 …] out.lm1`. Имён файлов транслятор не знает, каталогов не
  просматривает — книга :1642, явная ссылка или конфигурация. Каждый файл программы — обычный источник L2.
- *Таблицы источника* — каждый вызов `table:` с `source` первым, где бы он ни стоял, в любом файле программы, на
  любой глубине (корень, тело метода, тело Structure, блок). Строятся в начале трансляции, в порядке файлов и
  источника. Одно имя дважды — прежний отказ «two source tables have this name».
- *Вопросы транслятора* (`primitive.convert`, `primitive.description`) ищут таблицу по имени среди таблиц программы.
  Нет таблицы — отказ у первого вопроса, которому она нужна: «the program has no source table `…`», с местом вопроса.
  Программа, которая ничего не спрашивает, таблиц не требует.
- *Файл-реализация строки* — рядом с файлом, где стоит таблица: ссылка — данные таблицы, не свойство источника.
- *Уходят:* `l2_input_tables`, фиксированные имена, правило «ниже корня не смотрим», переименование файлов в harness и
  фразы «table file of the translator».
- *Harness* передаёт файлы программы явно. По умолчанию — `convert.lm2` и `primitive.lm2` песочницы. `Table` и
  `Primitive` называют свой файл или `absent`, без переименования; Needle называют файл его собственным именем.
- *Свидетели:*
  - таблица в самом переводимом источнике — в корне и вложенная (`unit_s7_tbl_nested` переворачивается в исполнение);
  - таблица во втором файле программы;
  - программа без `primitive.description`: ничего не спрашивает — переводится; спрашивает — отказ у вопроса;
  - два файла с одним именем таблицы;
  - файл-реализация рядом с файлом таблицы, а не рядом с источником.
  Мутанты — на каждый пункт.
- *Учёт ревью среза 2* (fable_pc): `l2_prim_kind` ставит «сказано» (`l2_cv_said`, gap 3) прямо, не сдвигом счётчика.

**Вопросы к ревью.**
1. *«Программа» — источник плюс явно названные файлы вызова.* Альтернатива — «только сам источник, каждая программа
   несёт свои таблицы текстом» — отпадает. 279 из 873 источников спрашивают примитив, и `primitive.description`
   пришлось бы повторить в каждом. Композиция единиц из разных файлов через `merge` в L2 пока не построена. Явный
   список файлов — «явная ссылка/конфигурация» книги. Если читается иначе — до кода.
2. *Где искать файл-реализацию строки:* рядом с файлом таблицы (предложение) или рядом с источником (сегодня).

## 9. Срез 3 — сделан (Opus, 2026-09-28)

**Что сделано** (план §8; REVIEW 311902d и ответы fable_pc на его вопросы).

*Программа* — переводимый источник и файлы, названные после него при вызове:
`l2trans [--walk-methods] [--library] main.lm2 [part.lm2 …] out.lm1`. Это «configuration» книги :1642. Имён файлов
транслятор не знает, каталогов не просматривает. Части читаются в начале (`l2_parts_read`); P0-диагностика части —
в её файле.

*Таблицы источника* — каждый `table:` с `source` первым, где бы ни стоял, в любом файле программы, на любой глубине:
корень, тело метода, тело Structure, блок (`l2_tables_in`). Строятся до трансляции в порядке файлов и источника.
Построенный вызов становится неактивным узлом (`LM_P0_NODE_INACTIVE`) — это проекция на время трансляции (prev
:18194), и ни одно тело не читает его как оператор. Две таблицы одного имени — отказ у второй с местом первой
(«two source tables have this name (the other at …)»).

*Приёмник преобразования* — метод программы, найденный по имени ячейки `receiver` (`l2_convert_method`), как любой
вызов. Файл реализаций (`convert_impl.lm2`) — просто часть программы, названная при вызове. Файлов по пути из ячейки
транслятор не открывает; столбец `impl` — данные, которые он не читает. Повторная трансляция Q33 («внести приёмник
по требованию и перевести заново», `l2_cv_need`) снята: приёмники — методы с самого начала, трансляция одна. Нет
метода — отказ у ребра: «the program has no method `…`, the receiver of this conversion».

*Вопросы транслятора* спрашивают таблицу по имени, когда приходят:
- нет `primitive.convert` — отказ у ребра («the program has no source table `primitive.convert`»);
- нет `primitive.description` — отказ там, где читалась программа (`l2_q_at`: оператор проверки или элемент
  единицы — место вопроса).

Программа, которая ничего не спрашивает, таблиц не требует: строки `unit_s7_prim_table_absent` и `_conv_table_absent`
теперь исполняются.

*Одно «сказано»* (учёт REVIEW 2a48dc7): `l2_table_said` говорит строку у причины и ставит флаги, по которым спросившее
место ничего не добавляет. Сдвиг счётчика в `l2_convert_hit` снят.

*`table:` без `source`* строит таблицу во время выполнения. Этого тела ресивера ещё нет, и отказ — своими словами:
«a table built at run time is not supported yet». Раньше — словами присваивания.

**Часть — ступенью** (ответ fable_pc на пункт 3).

Часть даёт программе то, что программа у неё спрашивает: таблицы источника на любой глубине и методы (по имени).
Прочее в корне части — поле, оператор, именованная Structure, квалифицированная ветвь, директива — отказ словами
недостающего механизма и только его: «… in a program part is not supported yet (the part's root is not built as a
Structure of its own yet)» (`l2_part_refused`).

Метод части читает свои формалы, свои поля и методы программы. Поля источника не в его области (`l2_own_unit_seen`).
По месту из него не видно ничего из объявленного источником: места двух файлов не сравниваются (`l2_vis_ok`,
режим 2). Имя, которого метод части не объявляет, — свободное имя: его связывает вызывающий (книга :1178), а без
связывателя — «unresolved name» у чтения, в файле части.

*Механизм следующего шага* — корень части строится как своя Structure:
- её поля с инициализаторами (книга :928, как у неисполняемой именованной Structure);
- её операторы — тело процедуры над ней, проверяется и не вызывается (§12 записки named-struct-exec);
- лексический родитель её методов — она: метод части читает поля своей части.

Этим уйдёт отказ «… in a program part is not supported yet».

**Найдено по пути (общие правки).**
- Свободное имя, стоящее в trailer `return:` метода (P0 вешает его на заголовок, вне тела), теперь ищется и там
  (`l2_free_name_at`). Отказ говорится в файле метода (`l2_method_src`).
- `l2_unit_declares` читал любой `X: name` в корне как объявление поля `name`. Поэтому `else: Counter` (голое
  исполнение в теле else корня) делал `Counter` «полем единицы», и именованная Structure `Counter` переставала ею
  быть: «unsupported trailer» у её объявления. Голова управляющего ресивера (`if`, `else`, `while`, `for`,
  `return`) или метода — не тип. Это случай P59 из REVIEW 99511ff; свидетель — `unit_named_struct_exec_else`.

**Корпус** (`99511ff` → срез). Каждый `tests/*.lm2` и `*.lm2` песочницы, оба режима. Старый транслятор читает свои таблицы

## 10. Корень части — своя Structure (Opus, 2026-09-28; план, кода нет)

Следующая ступень §9: механизм, которого ждёт отказ «… in a program part is not supported yet (the part's root is not
built as a Structure of its own yet)». Норма — ответ fable_pc на пункт 3 §8: часть — обычная единица; её корень —
Structure, которую никто не исполняет (вход — корень первого файла).

**Замер (`70f869c`).**
- *`node` метода* — его «фиксированное лексическое пространство»: родитель вхождения. Вхождение каждого метода
  строится `lmx_struct_new_owned(l2_entry_unit, …)`, так что для всякого метода, в том числе метода части, это
  единица программы.
- *Код метода* достаёт через `node` и то и другое:
  - поля единицы — `lmx_arena_ref_cell(node, …)`, через `l2_unit_ref` = "node";
  - вхождения других методов и узлы именованных Structure — `lmx_arena_ref_struct(node, l2_unit_base + mi)`,
    `l2_ns_base + rank` (`l2_own_ctr`).
- *Именованная Structure уровня единицы* — дочерний единицы; её поля строятся с инициализаторами (книга :928).
  Операторы её тела — процедура над ней (§12 записки named-struct-exec): проверяется, а исполняется только
  исполнением S.
- *Реестр `l2_ns_*`* ищет по имени. Имя читают пять мест, и все сравнивают его с текстом.

**Предложение.**
1. *Корень части — безымянная Structure уровня программы.* Запись `l2_ns_*` без имени (по имени её не найти),
   дочерний единицы. Её поля — объявления полей корня части, с инициализаторами при построении, как у именованной
   Structure.
2. *Операторы корня части* — тело её процедуры (§12). Проверяются общим путём; не исполняются, потому что
   исполнения корня части нет.
3. *Лексический родитель метода части* — эта Structure:
   - вхождение метода части строится её ребёнком (`lmx_struct_new_owned(<корень части>, …)`), так что `node` в теле
     метода части — корень части;
   - поле корня части метод читает и пишет через `node` по слоту поля — путём, как `P\k`, по таблице полей этой
     Structure;
   - единицу программы — вхождения методов и именованные Structure — код метода части достаёт через
     `l2_program_unit`, не через `node` (`l2_unit_ref` для метода части).
4. *Именованная Structure в корне части* остаётся в этой ступени отказом тех же слов. Её видимость — только в
   части или в программе, как методы, — отдельный вопрос; отдельная строка.
5. *Уходят* отказы полю и оператору в корне части.
6. *Свободное имя метода части* по-прежнему связывает вызывающий (книга :1178). Поле своей части — лексическое, как
   поле единицы у метода источника.

**Свидетели** (одна часть с полем `k 5`, оператором и методом `peek`):
- `peek` читает `k` своей части — 5, в обоих режимах; и пишет его — источник видит новое значение через вызов метода
  части.
- Оператор корня части не исполняется: поле, которое он пишет, остаётся со своим инициализатором.
- Поле корня части не видно из метода источника: там это свободное имя.
- Две части с полем одного имени — у каждой своё.

**Мутанты:**
- вхождение метода части — ребёнок единицы (`node` — единица): поле части не находится;
- единица через `node` в методе части: вызов другого метода промахивается;
- инициализатор поля части не строится: 0 вместо 5;
- оператор корня части исполняется.

**Вопрос к ревью.** Безымянная запись `l2_ns_*` — или отдельный реестр корней частей? Предлагаю запись: у корня
части нет ничего, чего нет у именованной Structure (поля, процедура, построение), кроме имени.

## 11. Корень части — своя Structure — сделано (Opus, 2026-09-28)

**Что сделано** (план §10; REVIEW a582309 и три условия fable_pc к нему).

*Корень части — Structure программы без имени.* Поля и операторы корня части (все его элементы, кроме методов и
таблиц источника) собираются в тело, и это тело берётся так же, как тело именованной Structure, только без имени
(`l2_part_root` → `l2_take_ns_body(0, …)`). Кадр, на котором оно висит, — транслятора, с местом корня. Запись
`l2_ns_*` — дочерний единицы; её поля строятся с инициализаторами, как у именованной Structure (книга :928). Часть,
в корне которой нет ни полей, ни операторов, записи не получает: программы из методов и таблиц не меняются.

*Операторы корня — тело его процедуры* (§12 записки named-struct-exec). Процедура регистрируется всегда
(`l2_ns_procs`): её собственные поля и есть поля корня, которые метод части читает по имени. Тело проверяется общим
путём, в файле части (`l2_m_file`, `l2_method_src`), и никогда не исполняется.

*Корень — лексический родитель методов части.* Вхождение метода строится ребёнком единицы, а когда корень построен,
становится его ребёнком (`\parent`). `node` метода — родитель его вхождения: `lmx_call_node` у трамплина, `l2_c\parent`
у прямого вызова, `lmx_fresh` копирует родителя кода. Поэтому в теле метода части `node` — корень части:
- поле корня метод читает и пишет через `node`, по слоту поля (`l2_own_ctr`); обходимый код называет его держателем,
  корнем (`l2_nsp[…]`, `l2_rw_cell`), и обход его достаёт (`l2_rw_seen`);
- `node\k` — поле корня части (`l2_e_own_seg`). У корня единицы — E и процедуры корня части — `node` нет;
- единицу программы — вхождения методов, именованные Structure — метод части достаёт через `l2_program_unit`
  (`l2_unit_ref`). Это касается и модели вызываемого merge: `l2_mad_emit_into` и `l2_t7_write` называли единицу
  буквально `node`;
- построение вызываемого поля (`fn: m`) сверяет родителя вхождения с его лексическим родителем (`l2_m_lexparent`), а
  не с единицей. Иначе программа с таким полем на метод части отказывала бы при старте.

*Видимость.*
- Поле корня видно методу своей части, если объявлено в её файле выше метода — правило единицы (`l2_own_unit_seen`).
- Коду части — методу части и процедуре её корня — не видно ничего из источника: ни полей, ни по месту (`l2_vis_on`
  2 по `l2_m_file`).
- Коду источника не видно полей части.
- Поле корня, названное как метод, — отказ «method collides with a unit field», как у поля единицы: методы программы
  видны из методов части. Именованные Structure источника из части не видны, коллизии с ними нет.

*Часть читается как источник* — каждый её элемент против её собственного корня (`l2_cur_unit` на время прохода части):
метод, названный там, поле, объявленное там, определение, к которому привязывается объявление метода. Раньше часть
читалась против корня источника, и объявление метода части не находило своего определения: «duplicate definition».

*Библиотека операторов не исполняет* — ни в источнике, ни в корне части: «a library unit executes no statements», в
файле части. У этого отказа не было ни одной строки; теперь две (новое свойство строки харнесса `Library`).

*Ступень дальше.* Именованная Structure, квалифицированная ветвь, блок os и директива в корне части — отказ словами

## 12. Типы столбцов — ячейка читается по типу своего столбца (Opus, 2026-09-28; план, кода нет)

  `(class: class) (class: kind)`. У каждой строки есть вид: `class`, `primitive`, `relation`, `literal` или другой
  класс (`categoryFlag  uint8` — `core.lm2`:32; `serial  decimal` — :31).
- *Таблица `class` объявлена в двенадцати модулях* (`core.lm2`, `primitive.lm2`, `libc_abi.lm2`, `own.lm2`,
  `own_abi.lm2`, `parser_registry.lm2`, `rest_lmx_http_client.lm2`, `rest_lmx_http_server.lm2`, `trans_registry.lm2`
  и три модели `mix/`). Каждый модуль добавляет свои классы.
- *Одноимённые таблицы разных модулей объединяются.* Строки всех источников одного имени, чья схема совместима,
  дописываются в одну таблицу (`lm_registry_view_append_materialized_rows_mode`, `table_descriptor.lm2`:1008–1073).
  Совместима — та же схема или обе таблицы из двух столбцов (`lm_table_descriptor_join_schema_compatible`, :501). Дубликат
  в одном модуле — ошибка: «duplicate table in one registry source module»
  (`registry_source_loader_unit_payload.lm2`:815, :1021).
- *Ячейка читается кодеком класса своего столбца.* Кодек — из таблицы `serialization.codec`
  (`(class: class) (@: char codec)`, `trans_registry.lm2`:393–420):
  - `lmx.decimal-atom` — числовые классы (`int`, `size_t`, `unsigned`, `categoryFlag`, `uint8`, `u32`, `Boolean`, …);
  - `lmx.char` — `char`;
  - `lmx.opaque-handle` — `FILE`.

  Перед таблицей prev держит и закрытый список: `lm_trans_registry_descriptor_payload_is_numeric` в
  `trans_l1_registry.lm2`:1853–1864 перечисляет `int`, `size_t`, `int8`, `uint8`, `categoryFlag`, `decimal`,
  `serial`.
- *Смысл особых значений — тоже таблицы:* `None.value`, `OK.value`, `false.value`, `true.value`
  (`trans_registry.lm2`:454, :471, :485, :494).

**Замер LMX (`dcc5fd3`).**
- Столбец записывается только именем — последним атомом кадра `(T: n)`. Тип `T` не читается нигде (`l2_table_call`).
- Потребители сравнивают текст ячейки:
  - `l2_prim_kind`: `cell` — «равно "1"», `convert` — «равно "forbidden"»;
  - `l2_convert_hit`: `forbidden` — «равно "1"», `receiver` — «равно "None"», `from` и `to` — строкой с именем типа.

  Следствия: `01` или `1U` в столбце `categoryFlag` — не 1. Одноэлементная Structure `(1)` — «not a name (evaluating
  a table argument is not ported yet)», хотя по прозрачности (prev §4.0.1) это та же единица. Смысл `None` —
  написание в коде транслятора, а не данные.
- Две таблицы одного имени в двух файлах программы — отказ «two source tables have this name (the other at …)»
  (срез 3, `l2_table_twice`), тогда как prev их объединяет.

**Предложение (срез 4).**
1. *Таблицы типов — данные.* В `primitive.lm2` переходят из prev:
   - `class` — строки, которые называют типы столбцов таблиц LMX и слова транслятора (замер точного списка в
     срезе);
   - `serialization.codec` — кодеки этих классов.
2. *Тип столбца читается и разрешается.* Голова кадра `(T: n)` вместе с глубиной адреса `@:` разрешается по строкам
   `class` программы. Неизвестный тип — отказ у столбца. (prev держит имена классов в виде, `view\class_names`,
   `table_descriptor.lm2`:516; проверяет ли он ими типы столбцов — не нашёл; замер — первым шагом среза.)
3. *Ячейка декодируется кодеком класса своего столбца* — строкой `serialization.codec` этого класса, как в prev
   (`lm_trans_registry_descriptor_column_serialization_codec`: у prev своя строка есть у каждого числового класса,
   `categoryFlag` включительно; цепочки видов prev не проходит). У класса без строки кодека ячейка читается как имя —
   тоже как в prev:
   - десятичный атом — число;
   - столбец класса `class` — имя, которое должно быть строкой `class`;
   - `@: char` — текст атома.

   Потребители спрашивают у таблицы значение ячейки по имени столбца — число, имя или текст — и не сравнивают тексты.
   Смысл `None` в ячейке `receiver` — строка таблицы `None.value`, как в prev.
4. *Ячейка-не-атом.* Одноэлементная Structure прозрачна: `(1)` — та же ячейка, что `1`. Выражение (`1 + 0`) —
   вычисление по типу столбца при трансляции, а это свёртка констант, которой у транслятора нет. На этой ступени —
   отказ у ячейки словами недостающего механизма: «… is not evaluated at translation yet (a constant expression of
   the column's type)».
5. *Одноимённые таблицы* — вопрос ниже.

**Ответ автора на вопрос ниже (Q47, 2026-09-28, `LMX_blog/2026-09-27.md` «Q47»):** две таблицы одного имени — два
одноимённых объявления, и реакция на них — общее правило, как у второй полной функции `fn:` того же имени: отказ.
Объединение было бы особым случаем общего правила — костылём. Значит, п.5 решён прочтением 1: правило среза 3 («two
source tables have this name (the other at …)») остаётся, реестры программы (`class`, `serialization.codec`) — каждый
одним вызовом `table:` в одном файле, свидетели и мутант объединения (ниже) не нужны. Остаётся проверить одно: отказ на
два одноимённых объявления — одно правило, и слова у него должны быть одни — у второго метода «duplicate definition
(the other at …)», у второй таблицы «two source tables have this name (the other at …)»; привести к одним словам — в
срезе 4.

**Вопрос к ревью (и, если нужно, к автору).** Две таблицы одного имени в двух файлах программы:
- (A) отказ, как сейчас (срез 3, одобрено REVIEW 70f869c);
- (B) объединение, как в prev: строки дописываются, если схемы совместимы; дубликат в одном файле — отказ.

От ответа зависит код. Таблица `class` в prev лежит в двенадцати файлах, и при (A) все классы программы должны
лежать в одном. Предлагаю (B): это правило prev, а норма автора для настроек — «как в предыдущем проекте». При
(B) «two source tables have this name» остаётся только для одного файла, а у несовместимых схем свои слова.

**Свидетели** (строки харнесса; `Primitive` — своя `primitive.lm2`, где нужно):
- `cell` из `01`, из `1U`, из `(1)` — ячейка есть (сегодня: нет);
- столбец неизвестного типа — отказ у столбца;
- ячейка класса `class`, не названная в `class`, — отказ у ячейки;
- выражение в `categoryFlag` — отказ словами ступени;
- `None` из строки `None.value`: без строки — «no row» у ячейки; с другим написанием в таблице — то же поведение;
- при (B): `class` из двух файлов объединён; две таблицы одного имени в одном файле — отказ; несовместимые схемы —
  отказ со словами схемы.

**Мутанты:**
- кодек снят, текст сравнивается, как сейчас: `01`/`1U`/`(1)` красные;
- тип столбца не разрешается: строка неизвестного типа принята;
- `None` по написанию: строка `None.value` с иным написанием красна;
- при (B): объединение без проверки схемы — строка несовместимых схем принята.

**Корпус:** каждый файл обоих режимов тождествен, кроме строк, где сегодняшнее сравнение текстов даёт иной ответ, —
их перечислить.
