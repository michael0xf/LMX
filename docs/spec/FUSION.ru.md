# fuse: один обход выбранных конечных элементов результата

`fuse(expression)` — стандартный ресивер с **одним RAW-выражением** общего
механизма Expression. Он сохраняет живое выражение и запрашивает пригодное
вычисление за один обход результата. Обычная eager-функция с входом
`@: expression` этот договор сама по себе не реализует.

Внутри выражения действует [общее правило depth](OPERATOR_DEPTH.ru.md):
обычная операция имеет глубину 0, `.op` — 1, `.(EXPR)op` передаёт один полученный
неотрицательный int. Ресивер использует базовое имя и именованный вход `depth`,
например `` `*`(a; b; depth := 2) ``. Обратные кавычки сохраняют идентификатор,
а не декодируют точечное имя. `.=` сравнивает; `.:` присваивает как форма базового
`:=` с глубиной 1.

## 1. Пригодные вычисления

```lmx
return: fuse(a .* b .+ e)
```

Для согласованных **одномерных** Array каждая координата выполняет скалярное
умножение, затем сложение. Промежуточный Array `a .* b` не создаётся; выделяется
только результат. Исходный скалярный аргумент распространяется по допустимым
уровням, но получается один раз до обхода.

```lmx
return: fuse(values .* scale() .+ bias())
```

`scale()` и `bias()` выполняются по одному разу в установленном порядке, в том
числе для пустого результата. Чисто скалярное подвыражение также получается
один раз. Два написанных вхождения остаются двумя вычислениями; кэша по имени
функции или тексту нет. Выражение глубины получает обычный механизм востребования
Expression: отдельный разбор числового литерала или повторный вызов на каждом
элементе не вводится.

Для плоских Array ранга 2 скалярные ячейки выбирает следующая форма:

```lmx
return: fuse(a .(2)* b .(2)+ bias)
```

Depth потребляет сохранённые логические оси того же плоского хранилища.
На глубине 1 вход ранга 2 предоставляет логические строки, и базовый `*` над
двумя строками — векторная свёртка. На глубине 2 он предоставляет скалярные
ячейки. Доступ к строке использует временный дескриптор адреса/формы, а не
выделенный Array строки или узел графа. Запрошенные оси должны существовать
по допускаемому описанию. Достигнутый внутри Array скаляр не подставляет
отсутствующую ось другого Array. Пока lifting требует следующей оси,
распространяется именно исходный scalar-аргумент. При оставшемся depth=0
потребление выбирает базовый метод, включая его профиль Array/scalar.
Полностью скалярным исходным аргументам фиктивные оси не создаются.

| Выбранная операция | Пригодность |
| --- | --- |
| Чистая арифметика, побитовая операция или сравнение совместимых конечных элементов | Да |
| Допустимый обычный профиль Array/scalar с работой по элементам | Да |
| Обычное `a * b`, выбирающее векторную/матричную свёртку | Нет |
| `a .* b` для матриц ранга 2 | Нет: каждая пара логических строк выбирает векторную свёртку |
| `a .(2)* b` для матриц ранга 2 | Да: базовый метод получает скалярные ячейки |
| I/O, мутация, yield или неизвестные эффекты в конечном kernel | Нет |
| Скалярные получения вне kernel | Один раз на востребованное написанное вхождение |
| Полностью скалярное выражение | Одно обычное вычисление без Array и обещания ускорения |

Проверяется действительный выбранный договор. Неизвестная или непригодная
форма диагностируется и не запускает запасное eager-вычисление. Матричное
`a * b + e` и покоординатное `a .(2)* b .(2)+ e` остаются разными операциями.
Для одномерных входов скалярная форма по-прежнему `a .* b .+ e`.

## 2. Условие, диагностика и обычные ошибки

```lmx
return: fuse(enabled ? a .* b : e .+ bias())
```

В этом коротком примере входы одномерные. Для скалярной арифметики входов
ранга 2 указывается depth=2; по числу знаков глубина не переопределяется.

Получается и подготавливается только выбранная ветвь. В неактивной ветви нет
вызовов и вычисления её выражений глубины. Условие скалярное: Array предикатов
не превращается неявно в маску истины. Значения и ссылки передаются по обычному
договору тернарного выражения.

Неверные значение/тип глубины, отсутствие запрошенной логической оси,
несогласованные выбранные формы и непригодность `fuse` — **диагностика транслятора,
если это известно при подготовке, иначе диагностика интерпретатора при достижении
операции**. Это не перехватываемые исключения LMX; новые формы не получают для
них исходов `FxDepth`, `FxShape` или `FxKernelFailure`. Класс диагностического
исключения host-модели не является новым языковым исключением. Если само
пользовательское выражение глубины или выбранная числовая/обратная операция
порождает обычную ошибку, сохраняется её прежний договор ошибок.

После получения инвариантов и проверки конечные элементы обходятся структурно;
внутри каждого фактического Array последняя координата меняется быстрее.
Для элемента сохраняется порядок дерева скалярного выражения. Не вводятся
переассоциация, FMA, изменение точности или скрытая замена decimal/real на double.
Чистая скалярная операция всё ещё может отказать. Явный fuse выбирает первый
такой отказ по порядку элементов, затем по дереву выражения. Eager-операции над
целыми массивами могут встретить другую первую ошибку; компилятор не вправе
незаметно заменить один порядок другим.

## 3. Присваивание, глубина и алиасы

```lmx
values .: fuse(values .* scale .+ bias)
```

Для назначения ранга 2 выбирается и глубина его скалярных ячеек:

```lmx
values .(2): fuse(values .(2)* scale .(2)+ bias)
```

Назначение содержит настоящие места. Форма, нужные уровни и допустимость
перекрытия проверяются до первой записи. Полный скалярный результат получается
и допускается непосредственно перед записью его места. Поэтому поздний обычный
скалярный отказ или отказ допуска может оставить записанный префикс. Этот
потоковый договор запрошен явно через `fuse`; он не заменяет обычный снимок RHS.

Разрешены раздельное хранилище и одна и та же карта чтения/записи конечных мест.
Чтение другой будущей цели, в том числе в соседнем регионе или общем поле Structure, в этом профиле
диагностируется до записей. Повторные реальные места назначения также не образуют
безопасную fused-карту. Явный снимок значений может дать другой допустимый
источник. Проверка не исполняет всю арифметику заранее и не откатывает прежние
эффекты получения аргументов.

Обычное `.:` или `.(n):` сначала удерживает **все выбранные значения RHS во всех
ветвях**, затем допускает каждую настоящую цель и лишь после этого пишет в
выбранном порядке. Это сохраняет обмен перекрывающихся логических строк и
общих полей Structure. При достигнутом depth=0 настоящее binding PLACE
принимает целое новое значение по своему типу; прежнее значение не ограничивает
перепривязку. У региона строки нет независимого reference-slot: присваивание
целому региону допускает совместимый блок и пишет его существующие ячейки.
Поэтому гарантированное скалярное заполнение ранга r выбирает depth=r, если
сам базовый договор целого блока не допускает скаляр.

```lmx
(a b c) .: (b c a)
```

Из `1,2,3` получается `2,3,1`. Единственный возвращённый Array читает на
непосредственные значения сам потребитель присваивания на выбранном уровне.
Несколько соседних структурных значений остаются несколькими значениями.
Группировщик не добавляет раскрытия после вызова. Срез в VALUE создаёт свежую
выборку; срез в PLACE выбирает реальные ячейки для этой операции, без постоянного
нового типа view.

## 4. Один живой граф и хранение результата

Операция удерживает ссылки на фактические вхождения Expression, полученные
скаляры/depth, полные требования, описания формы и допустимые карты адресов.
Это временные сведения операции, а не копия namespace, переписанный исходный
граф или вторая исполняемая программа. Шаблон скалярного выражения общий для
выходных элементов; он не клонируется на каждый элемент. Скалярный результат,
который повторно использует допустимый базовый профиль, можно удержать в одном
регистре текущей структурной позиции.

Результат использует каноническую TypeRef полного объявленного/вычисленного
требования. Сохраняемые выходные размеры входят в это требование; нельзя уточнять
общий тип по строкам инициализатора, резерву или полученным данным. Временный план
Expression может передать размеры следующей операции, но не становится скрытым
дескриптором каждого Array. `FxSeqAllocate(arrayType; count)` — прежний helper
линейного типа без фиксированной длины. Результат с заданными размерами
конструируется общим механизмом сразу под полным вычисленным TYPE, с допустимыми
count и заполненным backing до публикации. Пустой фиксированный массив с
последующим resize и скрытая смена типа готового `[]T` этого не заменяют;
старому исходнику требуется соответствующая миграция. При capacity=length второго дескриптора
нет. Реальный резерв использует необязательную запись capacity и сам по себе
не меняет TypeRef. Заголовок `Lmx` не расширяется. Публикация следует
[каноническим типам Array](ARRAY_STORAGE.ru.md#array-profiles); недостаток размеров,
действительно нужных fuse, даёт диагностику.

Плоское прямоугольное хранилище входа и результата
остаётся плоским при обходе осей. Если договор результата действительно
возвращает Structure в полях, это обычные необходимые значения результата,
не отдельная сущность «массив массивов» и не временные объекты строк.

Самостоятельное `[items]` — конструктор Array общего P0, не узел группировки.
`[arr2]` сохраняет одну целую ссылку arr2. Пригодный fuse может один раз получить
этот конструктор; явно написанное исходное значение отличается от промежуточного
результата арифметического оператора. Убрать его выделение можно лишь доказанной
оптимизацией, сохраняющей identity, время жизни и порядок ошибок. Единичная ось
не распространяется автоматически, а цепочка не переассоциируется.
См. [Array непосредственно в выражении](ARRAY_EXPRESSIONS.ru.md#inline).

Обходчик может использовать общий потребитель конечного элемента, а native-
транслятор — сгенерировать тот же обход. MLIR, новый рабочий граф и неявная
компиляция не нужны. Границы явной компиляции и `endturn` сохраняются.

## 5. Общие LMX-тела и граница интеграции

Исходник: [array_expression_ops.lmx](patterns/LMX_Fn_Receivers/src/array_expression_ops.lmx).

| Общее тело | Выполняемая работа |
| --- | --- |
| `FxArrayExpressionFill` | Один выходной цикл с выбранным writer либо обход void |
| `FxArrayInputsAt` | Один сбор аргументов с выбранным плоским или логически-осевым reader |
| `FxArrayDepthBase` / `FxArrayDepthCell` / `FxArrayDepth` | Целый базовый вызов и один линеаризованный обход выбранных depth логических элементов |
| `FxArrayElementCell` / `FxArrayElementwise` | Прямой скалярный покомпонентный профиль |
| `FxArrayContractionCell` / `FxArrayProduct` | Упорядоченная свёртка multiply/add; нуль провайдера нужен только для пустой свёртки |
| `FxArraySnapshot` / `FxArrayAssignPrepared` | Общие полный снимок RHS, допуск всех целей и запись |
| `FxArrayDepthCollect` / `FxArrayDepthAssignPrepared` | Выбор глубоких реальных PLACE и вызов того же присваивания |
| `FxArrayResultTree` | Выделение только описанных контейнеров результата |
| `FxFuseFill` / `FxFusePrepared` / `FxFuseIntoPrepared` | Один общий конечный цикл для нового результата или готовой цели |

`FxArrayDepth\apply(context; depth; inputs)` получает готовое число depth,
а не переписанный плоский набор аргументов. Контекст предоставляет:

| Поле контекста | Требуемый договор |
| --- | --- |
| `base`, `hasResult` | Настоящий source callable и точный R/void |
| `level(context; depth; inputs)` | Проверенные оси, происхождение исходных скаляров и полный R/void; frame `{hasArray,count,inputs,read,layout,write}` |
| `read(map; index)` в frame | Один выбранный скаляр, обычная Structure или дескриптор логического среза того же хранилища; без выделения строки |
| `write(output; index; value)` в frame | Допуск/запись одного базового результата в подготовленный скалярный/блочный регион результата |
| `publish(context; layout; result)` | Сохранение полного типа и описания rank/extents фактического результата |

Полный выбранный договор глубины/форм готовится до вызовов исходного метода.
`count` — число базовых применений после выбранных осей, не обязательно число
скалярных ячеек. Линеаризация выполняет то же упорядоченное рекурсивное правило
осей, не выделяя контейнеров на промежуточных осях. Тело добавляет
`frame.root = context`. Для результата `FxArrayResultTree` выделяет/публикует
только полный подготовленный layout; общий цикл получает входы через `read`,
один раз вызывает базовый метод и пишет через `write`. Для прямых плоских
операций по умолчанию остаётся прежний reader.

При depth=0 и при полностью исходных scalar-аргументах быстрый базовый путь
сохраняет точный R/void и один раз вызывает source без создания Array.
Void использует тот же
цикл без результата и без `Array<void>`; wrapper сохраняет отсутствие публичного
результата. RAW, PLACE, TYPE и другие специальные ресиверы выбирают собственную
политику depth и не попадают в VALUE-lifting случайно.

Глубокое присваивание получает доступ к реальным местам через `open`/`child` и
представление выбранных entries через `linearize`. Затем `FxArrayAssignPrepared`
один раз выполняет указанные `admit(context; index; value)` и
`write(context; index; ready)`. Это настоящие места/карты, не копии переменных
вызывающего. Логический регион строки/плоскости — адресуемый блок, не выдуманный
pointer-slot. У fuse `bindOutput` предоставляет проверенные
`target/count/cell/write/direct`: плотный результат можно адресовать напрямую,
прочие реальные места — через компактную карту. Список PLACE-handle на каждый плотный элемент
не обязателен. Эти callbacks — явные границы общего механизма типов/Expression/
PLACE, а не новые публичные функции с пустыми телами или объявленная готовой
интеграция runtime.

## 6. Проверка и смысл ускорения

[Исполняемая модель](tools/array_expression_reference.py) использует
[общий транспорт depth](tools/operand_depth_reference.py), а не второй парсер.
[Проверки](tools/test_array_expression_reference.py) охватывают базовое/глубокое
произведение flat rank2 на глубинах 0/1/2, оси ранга 3, востребование динамического
depth, перепривязку реальных мест, снимки блоков, inline-конструкторы и порядок
обычных цепочек, диагностику форм/уровней, общие числовые контексты,
void, алиасы, ленивые ветви, обычные ошибки и число проходов/выделений.
Production parser, translator и LMX runtime: **NOT_RUN**. Фактический результат
host-проверок [записан отдельно](tools/array_expression_reference_results.json).

```sh
python docs/spec/tools/test_array_expression_reference.py \
  --json docs/spec/tools/array_expression_reference_results.json
```

Для одномерного `fuse(a .* b .+ e)` модель фиксирует один проход и один Array
результата вместо двух проходов и двух результатов eager-композиции.
`fuse(a .(2)* b .(2)+ e)` для ранга 2 также выделяет один плоский результат с
сохранённой формой; обход логических строк не выделяет их хранилища.
Обычные Structure, требуемые договором результата, создаются один раз.
При совместимой записи на месте промежуточного результирующего Array нет.
Это счётчики алгоритма, а не native-benchmark и не универсальное обещание
меньшего времени на любом размере и числовом профиле.
