## 4. Кто чем занят

### sonnet — жетон конвейера, срез исполнения выражений

Норма среза: книга, [выражения](docs/LMX_semantics.ru.md#assignment-inside-expression); грамматика,
[операции](docs/LMX_grammar.ru.md#operators) и [структурный результат](docs/LMX_grammar.ru.md#normal-form);
[ТЗ автора](docs/new_parts/to_fable_operands_arguments_priorities.md), редакция 3; ответы исполнителя Р94, Р96,
Р97, Р99 в [журнале ответов](LMX_blog/q/fable-self-answers-20261110.md).

Каталог подготовки: `receipts/sonnet/one-graph/expression-step/` — `INVENTORY.txt`, `PLAN.txt`, `QUESTIONS.txt`,
`fixtures/` (100 программ, `pins.tsv`), `a1/`, `a2/`, `a3/`, `e3/`.

Шаг a1 — общий анализ цепочки выражения по одной таблице приоритетов, которым пользуются и интерпретатор, и
эмиттер нативного образа; значение узла — запись «тип и значение»; построитель графа не меняется. Состояние по
сообщению sonnet (мной не перепроверено): кандидат с метками `x102`, 212 строк в трёх режимах — 173 базовые без
изменений и 39 новых зелёные; нативные образы базовых строк побайтно равны прежним; идут 24 мутанта. Дифф в
рабочем дереве я прочитал: особых случаев по имени ресивера и битовых флагов нет. Замечания к сдаче, не
требующие пересборки: комментарии шириной около 190 знаков переносить со следующего шага; запись значения
копируется через `memcpy` — спросить, нет ли готовой функции.

Вместе со сдачей a1 sonnet вносит в дерево восемь пар перезакреплённых фикстур opus из `receipts/haiku/repin/`
(раздел 6, Р101). Ожидание на его кандидате: семь из восьми зелёные во всех трёх режимах, `declsel_b10` красная
только в нативном режиме.

Следующие шаги у него подготовлены скриптами вне дерева:

- **a2.** Построитель перестаёт вкладывать по приоритету; выражение остаётся одним элементом; граница элемента
  определяется лексикой операторного токена. Свидетели: 94 закреплённых дампа переводятся скриптом из старого
  текста; `expr_g02`, `expr_g03`; целый графовый список.
- **б.** Явная группа читается как одно выражение: `(1 + 2 3 4)`, `(+ 2 - 3 4)`. Свидетели: `expr_s01`–`s07`,
  `n03`–`n05`, `p17`.
- **e1a.** Уровни сдвигов и побитовых операций и унарный `~`. Свидетели: строки `c`-ряда.
- **e2.** Значение присваивания по требованию, однократность, короткое замыкание. Свидетели: `p05`, `p06`, `p11`,

## 6. Открытое и долги

- **Вопрос автору.** Что отвечает целочисленная операция, когда результат не помещается в тип или не определён.
  До ответа взято чтение, которое не меняет сегодняшних ответов: не помещается — значение по модулю разрядности;
  не определено (деление на нуль, сдвиг вне разрядности, отрицательная степень) — отказ; `0 ** 0` равно 1.
  Строки-свидетели, зависящие от ответа, не закреплены.
- **Девять красных строк среза выбора объявления.** Четыре (`declsel_b02`, `g01`, `g02`, `g03`) ждут шага C:
  формал без записанной модели `@: a` пока не принимает Structure. Пять были закреплены моим неверным чтением и
  перезакрепляются: `call(C)` при `C(foo())` в данных метода по общим правилам ничего внешнего не вызывает —
  решение автора от 2026-11-11, журнал `LMX_blog/2026-11-11.md`, якорь `self-launch-no-own-rules`.
- **Нативный образ** отдаёт выбранный вызов выбору интерпретатора — временно, до таблиц вызова.
- **Скан снят, но** удержание свободного имени после первого чтения не имеет ни кода, ни свидетеля; скрытое под
  `private` имя отличимо от необъявленного (`marks_ref_code_private` красная намеренно).
- **Место отказа вызова** различается: у вызываемого в корне — при исполнении, у объявленного в коде метода —
  при построении графа. Так же было на базе.
- **Таблица преобразований** попадёт в ядро проекцией `convert.lm2` через frontend. Конечная форма — Structure
  чистого графа — сейчас недостижима: построитель графа запись `table:` не строит.
- **Сирота в тестах:** `selfbuild/tests/graph/precedence_twice.expected` снимается на шаге a2.

## 7. Как принимать сдачу помощника

Порядок, которым приняты оба среза этого дня. Все команды — из каталога `S`; префикс запуска — `0 entry 0 --`.

1. Проверить, что сборочных процессов нет (`lmxtool-tool`, `l2trans`, `gcc`, `cc1`, `graph_trans-prod`), и что
   `HEAD` равен `origin/main`.
2. Дифф дерева сравнить со сданным по SHA-256: `git diff -- <файлы>` и файл диффа из квитанции. Список новых
   файлов сравнить со сданным списком.
3. Манифест: `T ... manifest R/selfbuild/inputs.list R/selfbuild OUT.sha256`, затем
   `T ... verify OUT.sha256 R/selfbuild` и `T ... verify OUT.sha256 S`. Число файлов и SHA сверить со сданными.
4. Хэши tool, frontend, runtime, Graph. Runtime, собранный итоговым frontend, сравнить с кандидатом через `cmp`;
   Graph — после обнуления в PE полей TimeDateStamp и CheckSum.
5. Прочитать дифф: нет ли веток по имени ресивера, битовых флагов вместо нового кода типа, фиксированных
   пределов; закрыватель `---` только при спуске на два уровня; новых `end:` нет.
6. Свой прогон строк на итоговой цепочке — hosted frontend из итоговых исходников, runtime и Graph, собранные
   им: `sh rows_run_d1.sh МЕТКА FE RT GRAPH ИМЕНА ЗАКРЕПЛЕНИЯ`. Гнать порциями по 35 строк на переднем плане,
   порция идёт около 50 секунд. Старые строки обязаны совпасть с базой, новые — с закреплением.
7. Свои пробы интерпретатором: `GRAPH 0 entry 0 -- run ФАЙЛ 1`. Программа — с ведущей группой `Observed` и
   строкой `@: shared data[0]`; Structure-аргументы объявляются в данных метода как `Имя(поля)`.
8. Мутанты помощника: последняя строка по каждому должна быть KILLED. Строке SURVIVED не верить и не отмахиваться
   от неё: запустить Graph мутанта напрямую на строках-кандидатах. Правило, у которого мутант неотличим от
   кандидата, получает свидетеля или снимается.
9. Свидетельство в `steps/witnesses/<имя>/` и правки READ.ME, плана, чек-листа, `steps/current.md`, журнала
   ответов — скриптом, сначала на копиях. Пересоздать `selfbuild/inputs.sha256`.
10. `git add` по точному списку, проверка документов, и только при её успехе коммит и пуш одной цепочкой через
    `&&`. Перед коммитом вывести `git diff --cached --name-status` и сверить число файлов.

Проверка документов: создать каталог `O/docs-indexN`, перейти в него и выполнить
`T2 0 entry 0 -- docs check R R/provenance/semantics-sources/l1.txt R/provenance/semantics-sources/older.txt
C:/Git/cmd/git.exe O/docs-indexN`. Подпись коммита: `git -c user.name=fable commit`, заголовок с `[fable]`.

Мои скрипты приёмки лежат копиями в `O/scratch-backup-20261118/`: `rows_run_d1.sh`, `accept_d1.py`,
`accept_s2.py`, генераторы проб `gen_prq33.py` — `gen_prq35.py`, правки документов `edit_r97.py` —

## 9. Ошибки этого дня, которых не повторять

- Я ответил opus, что блок вызовов под `call(C)` вызывает внешние функции, не поискав решение автора; оно было
  принято 2026-11-11. Пять строк закрепили неверно, в свидетельство попали два несуществующих дефекта (Р101).
- Я ответил sonnet, что `S: a + b` в данных — три поля, не прочитав нормативную запись структурного результата в
  грамматике. Выражение — один элемент разбора; ответ снят в тот же час (Р99).
- Я написал автору и в журнал ответов, что `k(5)` при `fn: k (u8: x)` сегодня принимается. Проба показала отказ
  при любом формале-примитиве, кроме `int` (Р100, поправка).
- Скрипты с обратными слешами через heredoc портятся: оболочка схлопывает двойной слеш, и путь Windows
  превращается в управляющие символы. Такой текст писать файлом, а в самом скрипте брать слеш как `chr(92)`.
- Фоновый ожидатель при нехватке памяти убивает сама среда. Ждать сообщения помощника о сдаче, а не цикла опроса.
