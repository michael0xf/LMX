# Исполнение именованной Structure голым атомом: замер и предложение (Opus, 2026-09-27)

Пункты плана: §3 «Исполнение именованной Structure» :245 (а) «голое `f` исполняет обычную именованную
Structure (не только метод)» и §4 :401 «интерпретация callable-Structure — эмиссия тела именованной Structure».
В аудите `steps/checkpoint-2-6-20260927.md` — «OPEN, средний, не блокирует». Записка — замер и предложение
срезов для ревью; кода нет.

## Норма (автор)

- 2026-09-23 (`LMX_blog/2026-09-23.md`, книга §10/§12/§13): всякая именованная Structure исполняется голым
  атомом имени; объявление/построение её не исполняет.
- Q19.1 (2026-09-24): `return`-trailer закрывает любую callable-Structure, в том числе обычную именованную;
  у не-`fn` — только голый `return`, и в теле, и как trailer.
- **Q19.2 = 2** (2026-09-24, `LMX_blog/2026-09-24.md`): исполнение именованной Structure выполняет **всё тело,
  как тело метода** — объявление поля есть оператор на своём месте; последнее состояние тела **публикуется
  в граф** (как у метода: dirty load, checkpoint) и читается путём; путь `Counter\n` — чтение поля, он
  **не** исполняет `Counter`, даже если `Counter` — метод. Пример автора: `Counter: / size_t: n 0U /
  n: n + 1U / return` — после `Counter` `Counter` путь `Counter\n` читает 1 (объявление исполняется заново).

## Замер (транслятор `e1c4fd1`, только трансляция)

| Программа | Результат |
|---|---|
| `Counter:` с полем и оператором `n: n + 1U`, закрыта `end: Counter` | отказ «a Structure reference field needs a name» (1:1) — тело именованной Structure принимает только объявления полей |
| то же, закрыто голым `return` (форма автора) | отказ «unknown method» на первом поле (2:5) — с `return`-trailer тело проверяется как тело метода, а объявление поля читается как вызов |
| только поля + голый `return` | тот же отказ «unknown method» (2:5) |
| `Counter:` с одним полем, затем голое `Counter` | отказ «executing a named Structure is not supported yet» (строка `unit_bare_struct_refused`) |

Ядро готово: `lmx_call_prim(arena, code, data, …)` при `code\native` = 0 обходит `code` над `data`
(`steps/code-data-split-189.md` §4); у именованной Structure `native` = 0 всегда; корень и так обходится.

## Предложение

Исполняемая именованная Structure — **метод без формалов и без результата над собственным вхождением**:
её поля — own-поля этого «метода», тело — его тело, голое `S` — вызов, `S\x` — правило `M\x` (чтение
опубликованной ячейки без исполнения). Это ровно «как тело метода» Q19.2, и оно сводит пункт к механизму,
который уже есть: own-поля, опубликование состояния, обход тела (`--walk-methods`), `M\x`.

Срезы:
1. Тело именованной Structure принимает операторы (разбор и проверка как тела метода, не как списка полей);
   голый `return` — trailer и в теле. Свидетели: форма автора транслируется; `return: v` у не-`fn` —
   отказ.
2. Голое `S` в корне — CALL вхождения `S` над ним самим (обход); `S\x` — чтение без исполнения.
   Свидетель — пример автора: `Counter` `Counter` → `Counter\n` = 1; мутант «объявление не исполняется
   заново» → 2.
3. То же в теле метода (нативно и под knob).

## Вопросы до кода

- **Тип и экземпляр.** Именованная Structure сегодня — и значение (дочерний узел единицы), и тип
  (`Model: left` — новая Structure типа `Model`). Если её тело содержит операторы, что получает
  `Model: left` — копию полей с исполнением тела, без исполнения, или такая Structure типом быть не может?
  Это вопрос автору, если ответа нет в книге §10/§12.
- **Что считается «исполняемой».** Норма «всякая именованная Structure исполняется»: Structure только из
  полей тоже исполняется (её объявления исполняются заново — значения полей возвращаются к начальным)?
  По Q19.2 — да; строка-свидетель это покажет.
- Раскладка: у метода шаги лежат после own-полей (`l2_m_kids`); у именованной Structure место под шаги в
  узле единицы нужно добавить — это сдвиг номеров слотов у всех ns-строк только если шаги кладутся внутрь
  узла; альтернатива — шаги в отдельном узле кода (как `code` при `data` = узел Structure).
