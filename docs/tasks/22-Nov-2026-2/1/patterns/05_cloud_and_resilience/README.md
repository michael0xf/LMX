# Облако, HTTP и отказоустойчивость

[Руководство RU](LMX_Design_Patterns.ru.md) · [Guide EN](LMX_Design_Patterns.en.md)

Сохранены все 12 исходных паттернов группы и добавленный Backpressure. Retry и Ambassador используют общую прикладную RetryLibrary; её полный алгоритм показан отдельным примером реализации. LMX использует Message и уже определённый HTTP-профиль. HTTP admission, исполнение операции и семантический успех различаются. Общая обвязка перечислена отдельно и не считается бесплатной.

## Повторный просмотр с общими ресиверами — 22 ноября 2026

Каждый пример ниже проверен на применение нового прямого API `fun`. Сохранены действующие клиенты: у предложенных замен либо меняется указанный протокол, либо полный клиент с необходимыми объявлениями исходов и адаптерами на одном текущем ядре не становится короче. Это решение относится к данным небольшим сценариям, а не запрет использовать библиотеку в более крупных программах.

| № | Рассмотрены | Причина сохранения |
| --- | --- | --- |
| 038 | `retryCall, guard` | При открытом breaker запрос вообще не вызывается до now>=until; два последовательных отказа открывают окно, успех сбрасывает счётчик. retryCall немедленно повторяет объявленные отказы и не заменяет это сохраняемое состояние/часы. guard дал бы ошибку вместо -1. |
| 039 | `retryCall` | Текущий протокол повторяет HTTP-статус503, принимает delay и сохраняет интервалы1,2,...; общий retryCall работает с объявленными исключениями и не содержит callback задержки. Статус503 является нормальным числовым результатом, поэтому замена без адаптера вообще не повторит его. |
| 097 | `retryCall` | Реализация RetryLibrary включает распознавание503, ограничение числа попыток, необязательный delay и экспоненциальную паузу. Для retryCall понадобились бы преобразование статуса в объявленный отказ, обратное преобразование и отдельный backoff. Эти алгоритмы не исчезают, и заменой одного имени полный код не сокращается. |
| 040 | `bracket, once` | Сервер предоставляет раздельные acquire/release и возвращает0 при занятом единственном слоте. bracket управляет лексическим временем уже полученного ресурса, но не реализует эту admission-политику и не заменяет два серверных состояния. |
| 042 | `overload, apply` | Две ветви выбирают разные HTTP URL/paths и возвращают404 для остальных route. overload потребует два предиката, два callable, список candidates и ошибки выбора вместо прямых условий; apply добавит контейнер фактических аргументов и чтение записи результата к уже прямым вызовам http.post. |
| 043 | `compose, pipe` | MobileBff возвращает один backend.price, WebBff складывает два независимых запроса. pipe передаёт результат первой стадии второй и меняет интерфейс shipping; compose не выражает сумму двух чтений. Нужные прикладные тела всё равно остаются, а фабрика/импорт добавляются. |
| 044 | `trace, apply` | Sidecar — отдельный Message, append отправляется через post/ask и возвращаемого значения нет. trace — локальная обёртка вызова со своими событиями входа/выхода; она не заменяет почтовый адрес, доставку и sink.write. |
| 045 | `retryCall` | Ambassador повторяет нормальный HTTP503 через RetryLibrary, сохраняя URL/path. retryCall видит успешный числовой возврат и не повторяет его; необходимый HTTP/error адаптер длиннее существующего `read retry 2`. |
| 049 | `lazy, memoize` | После store.write кеш обязательно инвалидируется. lazy без сброса хранит первый успех навсегда; корректный вариант обязан заменять thunk при put и хранить его в node. Даже ограниченный нульарным read кандидат длиннее текущего клиента; обычный read() дополнительно допускает DATA/autofill, которые generic lazy не скрывает. |
| 052 | `memoize, once` | Счётчик обнуляется при любом изменении now/10, в том числе при возврате к прежнему окну. memoize по номеру окна сохранял бы прежнее значение/кеш вместо нового окна, once не сбрасывает счётчик. Часы и admission-проверки остаются отдельным алгоритмом. |
| 053 | `map, repeat` | accept только ставит работу в очередь, tick забирает не более одной текущей работы. map/repeat обрабатывают уже переданный набор/число вызовов и не заменяют разделённые во времени enqueue/tick и проверку текущего размера очереди. |
| 054 | `repeat, runUntil` | Worker должен дождаться semantic answer take, вызвать process и отправить следующий запрос. Локальный цикл runUntil/repeat изменил бы ожидание ответа и turn. Возврат-1 как конец очереди также не является исключением retryCall. |
| 056 | `predicate, guard` | readiness возвращает200 только для probe()=1 и503 иначе; predicate нормализует любое ненулевое значение, а guard сообщает отказ. Нужное точное сравнение и отображение в HTTP-код всё равно остаются. |
| 087 | `guard, contract` | Кредит изменяется у Message-владельца до post, offer без кредита возвращает0 без отправки. guard/contract вводят FxPredicate вместо0 и не убирают учёт кредитов или почтовую операцию. |
