## В2. Раскрытие единственной Structure: ресиверы и определения (п. 1; шаг M6.1)

```text
return: (a + b)
if: (count > 0)
const: (@: source char)
merge: (P Q)
P: (x: int: 1; y: int: 2)
```

Сейчас ([грамматика §18](../../../docs/LMX_grammar.ru.md#empty-colon)) P0 заменяет единственную анонимную Structure
хвоста её полями у любой головы. В исходниках около 13,5 тыс. строк, где весь хвост — одни скобки: `return:` — 10 934,
`if:` — 500, `const:` — 358, `while:` — 58, остальные — присваивания вида `base: (…)`. По п. 1 раскрытие переходит к
разбору аргументов callable.

1. Ресиверы: раскрытие делается только у callable (функции и вызываемой Structure), а ресивер получает написанное,
   или ресиверы тоже принимают единственную Structure как весь свой список аргументов? В первом случае
   `return: (a + b)` и `if: (count > 0)` вычисляют выражение в скобках и смысл сохраняют, но `merge: (P Q)` получает
   один операнд, а `const: (@: source char)` — одну Structure с объявлением внутри.
2. Определения: `P: (x: int: 1; y: int: 2)` для нового `P` даёт Structure с одним полем — анонимной Structure с `x` и
   `y`; определение с двумя полями в одну строку пишется компактной формой `P(x: int: 1; y: int: 2)` или вертикально.
   Верно?

Предлагаю: (1) только callable; скобки с одним выражением ресивер вычисляет как выражение, а места вида
`merge: (P Q)` и `const: (…)` переписываются (вторые — заодно с п. 10); (2) да.

## В3. Многострочное тело в `myFn: fn: return args` (пп. 4, 6; шаг M6.3)

```text
myFn: fn: int (int: a)
. int: b a + 1
. return: b
```

По [грамматике §15](../../../docs/LMX_grammar.ru.md#levels) после переноса уровень возвращается к уровню физической
строки, и более глубокие строки принадлежат первой голове строки — `myFn`, а не `fn` из её хвоста. У `myFn` получаются
два поля: Frame `fn: int (int: a)` без тела и строки тела; ресивер `fn` тело не получает. В нынешней записи
`fn: myFn (int: a) int` головой строки был сам `fn`. Как должно быть:

- (а) изменить общее правило уровней: более глубокие строки продолжают последнюю голову, открытую на предыдущей строке
  (`fn`); тогда в любой записи `x: y: z` с более глубокими строками они уходят в `y`;
- (б) правило уровней не трогать, тело писать внутри Frame `fn` явно — в скобках `myFn: fn: int (int: a) (` … `)` либо
  `fn:` отдельной строкой под `myFn:`;
- (в) правило уровней не трогать, а связывание `myFn:` передаёт следующие свои поля ресиверу `fn` — исключение по имени
  ресивера, которого я делать не хочу.

Предлагаю: (б) — без изменения правил уровней; если нужна запись тела без скобок, то это (а), и перепись покажет,
сколько существующих строк при этом меняют смысл.

## В9. Как я понял остальное (поправьте, если неверно)

- `A:` и `A()` дают `A` без полей, `A: ()` — одно поле, пустую Structure. Для функции `f` записи `f:`, `f()` и
  `f: ()` — вызов без аргументов: в третьей единственную пустую Structure раскрывает разбор аргументов вызова.
- Имя функции: `f := g` — ошибка. Указатель: `p: @: f` объявляет, `p := g` переписывает, `p(args)` вызывает.
- `():` без полей в скобках остаётся нынешней головой `()` ([грамматика §14](../../../docs/LMX_grammar.ru.md#bounded));
  голова-Structure содержит хотя бы одно поле.
- `{}` остаётся Mix.
- Формы `fn` по числу полей: `return args` — описание интерфейса, `return args body`, `return args var body`; у `sub`
  и `catch` то же без `return`.
- Анонимная функция как значение (`fn: …` без внешней головы) не вводится.
