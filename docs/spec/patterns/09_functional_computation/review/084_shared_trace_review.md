# Проверка варианта 084 с общими eval и code внутри Trace

Дата: 22 ноября 2026 года. [Полный исправленный исходник](084_shared_trace.lm3). Это разбор присланного дополнительного варианта, а не замена сохранённого исходного листинга 084.

## DATA и имена

У `Trace\eval` и `Trace\code` DATA — их настоящий родитель `Trace`. Вызов из `Acquire\open` или `Action\use` этого не меняет. Поэтому корневые `mode` и `events` являются собственными местами этих вызовов с готовыми начальными значениями. Без явного actual эти значения имеют приоритет перед autofill. См. [структурный вызов и правила привязки](../../../LMX_semantics.en.md).

В присланном `if: mode = mode` обе стороны читают одно место. При неизменённом исходном поле это `0 = 0`. В отдельном statement `mode := mode` внутри `Example\run` обе стороны также относятся к одному собственному месту `Example`; поле `Trace\mode` не меняется.

В исправлении `code(mode)` явно передаёт значение `Acquire\mode` или `Action\mode` в первый вход `Trace\code`. Затем `Trace\mode = mode` сравнивает поле графа с переданным значением. Режим сценария устанавливается через `Trace\mode := mode` в `Example\run`.

Голое `events` в `eval` — собственное место его активации. Запись в него не обновляет постоянный журнал `Trace\events`. Поэтому изменение, сброс и чтение общего журнала используют явный путь `Trace\events`.

С `x` такого конфликта нет: у `Trace` отсутствует собственное корневое объявление `x`. Оно остаётся свободным именем. Правило цепочки вызовов позволяет прочитать 1 из Acquire, 2 из Action и 3 из Release, даже если промежуточный `code` сам `x` не использует. Дополнительный параметр или фиктивное объявление `x` не нужны.

## Объявленные выходы и структура записи

`Acquire\open` и `Action\use` должны объявить `throws: ResourceFailure`, поскольку вызывают `code` и пропускают его объявленный выход наружу. `Around\use` уже его объявляет; `Example\run` ловит. Само наличие списка в `code` не добавляет его другим методам. См. [Declared failures and diagnostics](../../../LMX_semantics.en.md).

`return: resource\value` на уровне `use:` допустим: terminal return дописывает возврат в тело и закрывает этот Frame. В исправлении `return: Resource` использует тот же приём для `open`. Это прямо разрешено [§17 грамматики](../../../LMX_grammar.en.md).

Пустые строки внутри вертикального `Trace` удалены: по текущей грамматике такая строка закрывает открытые вертикальные формы до корня. Для переходов от вложенных тел к следующей структуре добавлены `end: code` и `end: close`. `throw` сам по себе не является структурным tail cutter.

## Ожидаемое поведение

| Вызов | Ожидаемый результат | Порядок событий |
| --- | ---: | --- |
| `Trace\Example\run(0)` | 42123 | acquire, action, release |
| `Trace\Example\run(1)` | −123 | ошибка action, затем release |
| `Trace\Example\run(2)` | −1 | ошибка acquire; release не регистрируется |

Это вывод по правилам документации, не результат запуска. LMX runtime здесь не исполнялся. Дополнительный вариант сохраняет все три передаваемых callback, значение ресурса и наблюдаемые ошибки; основной сравнительный листинг 084 остаётся прежним.

Полный дополнительный исходник занимает **739 непробельных символов / 57 непустых строк**. Текущий основной вариант 084 занимает 719 символов. Проверяемая здесь факторизация не даёт сокращения относительно него; это отдельный разбор, исключённый из текущих основных таблиц.
