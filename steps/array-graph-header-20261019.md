# K07: общий заголовок графового Array — доказательства WIP

Статус: **WIP, полный L2-корпус завершён RED**. Это физическая основа
[K07](tickets/array-as-lmx-20261015.md), не закрытие всего тикета или
общего алгоритма путей. База — `1cab144d`; код пока не опубликован.
Норму языка эта запись не меняет.

## Изменение

`Lmx` начинается с `parent/native`, затем содержит фиксированную `array`.
`LmxArray` — алиас этого полного заголовка; физический пул арены определяет
вид и тип элементов. Сырой `VoidArray {size,data}` остаётся C/List-хранилищем,
не графовым объектом. Нового opcode, имени, тега модели или wrapper для
каждого элемента не добавлено.

Общие `lmx_graph_node_in/cell_in/value_in` подтверждают адрес и физический
пул до чтения. GC, copier, квалификация, implements и walker используют
этот общий контракт. Copier заранее отображает все физические ячейки;
поглощение корней merge затем проходит ту же карту один раз. Родители,
ссылочный backing и самостоятельные pointer-ячейки перенаправляются вместе,
через точные accessors настоящих C-объектов. `reparent` сохраняет точные
read/write операции в scratch-транзакции, не в графовых полях.

Native backing Array<@T>, доступный как T**, теперь действительно создаётся
как T* ячейки. Генератор выпускает один набор C-accessors на закрытый тип
элемента; пул переносит этот контракт при копировании. Это не семейство
новых языковых Array-типов. Ссылочный backing графа остаётся `void *`;
для него нельзя подставлять `LmxArray **` только приведением адреса.
Отдельные скалярные pointer-поля пока сохраняют прежний canonical ABI:
все адресные случаи произвольных T** этим срезом не объявляются решёнными.

уже подтвердил регрессию двух прежних OK: `unit_array_empty` и
`unit_array_field` компилируются с четырьмя guards, но завершаются exit1

reference is not admitted». Общая квалификация теперь видит Array как
графовый узел, а source producer по-прежнему оставляет его parent=0.
Таким образом, физическая миграция ещё не зависимо полна; публиковать
её как принятый срез нельзя. Требуется общий producer места объявления,
а не возврат Array-bypass или ослабление квалификации.
Причину изолирует отдельный `nonconforming_parent_control`: подстановка
непосредственного E вместо parent=0 даёт оба exit0 (19 проверок,1 root).
Это только причинный контроль: E не является требуемым местом переменной;
ни в исходники, ни в постоянные ожидания такой parent не переносится.

Конструкторы обычных Array-деклараций пока передают parent=0: устойчивое
графовое место объявления `arr` ещё не реализовано. Минимальный
`arr: []: (int: first 11; int: second 29)` пока отвергается как неполная
старая Array-декларация (`build/codex_k07_source_place_01.log`). Общий
результат декларации/выходной Frame должен исправить это без подстановки
целой var/body, голого void** или особого имени `arr`.

Открыты также обычный L1 `[]` против явного `c.array`, полный Array-root
merge/use/toLmx, все случаи пригодности native после мутаций и смешанные
пути с implements-картой после индекса. Kernel-свидетель реального
permuted map в обоих движках не означает, что L2 frontend уже передаёт
каждый такой контекст. Два прежних положительных field-after-index
свидетеля остаются неизменными. Самосборка L3+L2 и T01–T26 не завершены.

## Общая проекция принимающих адресов — частные снимки03/04

На этапе03/04 это **исследовательские исходники под `build/`, не перенесённые в dev**.
Ни результат отдельной проверки, ни физический кандидат ниже не объявляют
ABI принятым, source producer готовым или все пути унифицированными.

Снимок03 сохраняет единую карту исходных адресов в копию и отдельно
композирует проекцию адресов копии в реальные ячейки принимающей Structure.
Она применяется один раз к точным указательным объектам по контрактам их
пулов; числа и native-слово адресами не считаются. Fresh merge, merge-into
и прежний absorb используют этот механизм. До исправления поглощения
владельца новый свидетель давал33 проверки/3 отказа: parent уже изменён,
но сохранённый адрес и backing места ещё адресовали промежуточную копию.
В `codex_k07_field_view_03/obj08`: merge33/0, merge-into24/0,
однократная проекция36/0, переставленное размещение22/0 и прежний
merge-into34/0. Чтение, перепривязка через сохранённый адрес и запись
проверены после освобождения источника. Это размещение задаёт явная карта
merge, не автоматически построенный frontend `implements`.

Тот же снимок03 выявил следующий положительный RED: разделяемое
двухпольное представление после перестановки не имеет сплошного backing.
`field_view_wide` в obj08 даёт17 проверок/1 отказ. Отказ не принят как

В снимке04 исследуется физический backing адресов полей. Он содержит
адреса **существующих канонических ячеек**, не дубликаты значений, имена,
пользовательский тип модели или второй граф программы. Обычный сплошной
backing остаётся прямым. `lmx_graph_cell_in` возвращает реальную ячейку
через один общий алгоритм; запись использует тот же результат. Входы

ячейки отвергаются, повторная проекция отсутствует.

Общий allocator копии сверяет физическое тождество ячеек, а не частный
однопольный prefix/slice, и выделяет только ещё не скопированные ячейки.
Проверены оба порядка входа копирования: владелец первым и представление
первым. Смешанное представление с общими и собственными ячейками проходит
полную квалификацию, копирование и mark/sweep без потерянного backing.

прежние walked merge102/0, merge-model6/0 и exec-projection0 отказов.

для builder; после исправления setup obj07 обнаружил реальный отказ AT
(31 проверка/1 отказ). Общий resolver координат исправляет его в obj08.

Kernel-native/walker-свидетель использует **действительное завершённое

## Source producer места и различение отсутствия/неверного значения

Следующий WIP переносит создание Array из source на настоящее место поля.
`lmx_field_place_new` создаёт обычный однопольный вид `Lmx` над **той же**
канонической ячейкой `S`; его `parent` — фактический владелец поля. Он не
создаёт второе значение, не оборачивает примитивные элементы и не ищет
имя/Model. Уже существующее написанное место результата используется
повторно. Через этот producer проходят primitive/ref/closed-pointer Array,
namespace, method parts и остальные вызовы общего allocator в frontend.
Профиль места берётся из фактической ячейки, не подменяет её родителя.

Целое поле-массив оказалось ещё не доступно как обычное значение выражения.
Теперь его тип — ссылка на фактический дескриптор — проецируется из уже
разрешённой записи пути одним `l2_path_rec_leaf_ft`. Native-проверка и
типизация записей обходчика читают этот результат; чтение не разбирает имя
повторно и не принимает typed backing элементов за само значение Array.
Отрицательный контроль подтверждает: такое значение не становится `int`.
