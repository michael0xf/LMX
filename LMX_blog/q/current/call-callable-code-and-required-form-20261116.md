# Открытые вопросы автору после решений 2026-11-16

Вопросы возникли при записи [решений автора 2026-11-16](../../2026-11-16.md) в книгу.
Реализацию среза410 они не останавливают, кроме самих описанных случаев.

## Q1. Что наблюдается при `call(D s)`, когда `s` объявлена через `sub`

```text
Counter:
    int: steps 0

D:
    int: x 10

sub: s (int: x 5) (Counter\steps := Counter\steps + x)

call(D s)
```

Решено: ресивер запуска не выбирает часть внутри поданной Structure, `call(D s)` исполняет саму `s`,
а тело над другими данными пишется `call(D s\code)`. Из этого не следует значение `Counter\steps`
после `call(D s)`. Наблюдаемые варианты:

- `10`: тело видит `x` из `D`;
- `5`: запись `int: x 5` части `s` исполняется как код и присваивает локальному `x` значение5;
- отказ: записи самой `s` в роли code не дают определённого запуска;
- другое значение.

В книге число для этой программы не записано.

## Q2. Где пишется ресивер `required`

Слова автора: «добавь ресивер required который будет проверять что данное поле инициализировано
на первой строке code». Исполнитель записал в книгу чтение А
([ответы исполнителя](../fable-self-answers-20261110.md), Р29).

Чтение А — `required` помечает объявление поля в data, как `private:`; проверка выполняется,
когда начинается code:

```text
fn: f (required: (int: a)) int
    return: a
end: f

f(7)
f()
```

`f(7)` возвращает7, `f()` отказывает на первой строке code.

Чтение Б — `required` пишется оператором на первой строке code:

```text
fn: f (int: a) int
    required: a
    return: a
end: f
```

Результаты `f(7)` и `f()` те же; различается запись и то, можно ли поставить проверку
не на первую строку.
