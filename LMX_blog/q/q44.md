# Q44. Вхождение метода при `merge`: вечная ветвь или свой признак

Состояние: 2026-09-27, открыт (Opus, с поправкой fable_pc; следствие Q42 и замера `steps/copier-q42.md`); отвечен автором
в чате fable_pc 2026-09-28 ~00:05 UTC, закрыт и перенесён в `LMX_blog/q/`.

## Факт

Книга (`provenance/semantics-book.md`, `merge`), дословно:

```text
Ссылки на общие методы являются терминалами своих контрактов. Когда `merge` встречает [вечную ветвь](#eternal) `independent: const: immutable`, он обязан **не копировать** её, а поместить в результат исходную физическую ссылку.
```

```text
Файл сам является Structure, поэтому метод, объявленный на уровне файла, объявлен внутри неё, и её поля — его лексический родитель; поле другой Structure, ссылающееся на такой метод (`A: fn: M`), остаётся при `merge` общей ссылкой на то же вхождение: оно не копируется, а `node` метода не меняется.
```

Ваш ответ Q42 п. 1: ссылкой, без копии, остаются только ветви `independent: const: immutable`; всё остальное, что
вызывается, копируется.

L2 §3 (`docs/L2_spec_ru.md`), дословно:

```text
Слот родителя держит сам `M`: путь `M\x` снаружи читает поля последней активации над собственным графом; экземпляры повторного входа через слот не видны, результат через слот не читается; одна Structure, переданная двум активациям, делится ими.
```

Сегодня ядро отличает общий метод одним признаком — «родитель вне копируемого» (правило k.4, которое вы в Q38 назвали
чепухой). Замер (мутант «k.4 снят», `steps/copier-q42.md` §3): кроме пина самого правила, на нём держатся только пять
случаев общего метода (`A: fn: M`). Другого признака метода у ядра нет: метки в узле нет, номер домена CALLABLE никто
не читает.

## Вопрос

Вхождение метода, объявленного на уровне файла, при `merge`:

1. **Само вечная ветвь `independent: const: immutable`** — код неизменяем, корень независим, — и тогда признак уже есть:
   копировщик оставляет ссылкой только вечное, а вхождение метода вечно по построению. (Против: по L2 §3 сам `M` держит
   поля своей последней активации, то есть его данные изменяемы.)
2. **Не вечная ветвь, но общий терминал своего контракта** (первое предложение книги), и ядро узнаёт его своим
   признаком — диапазоном: вхождения методов лежат в своём массиве арены (вид Structure, свой тип), как ядро узнаёт любой
   тип (lmx.h: тип ребёнка — диапазон, в который попадает его значение).
3. **Копируется**, как всё прочее вызываемое (тогда `A: fn: M` после `merge` — копия `M`, и книга здесь меняется).
4. Иначе.

## Предложение Opus

2 — если вхождение метода не вечное по построению (L2 §3 говорит, что его поля пишет активация): признак физический,
по диапазону, без метки в узле. Если 1 — признак уже есть, и нового массива не нужно.

## Ответ автора (2026-09-28)

Дословно — `LMX_blog/2026-09-27.md` (раздел Q44). Как прочитано (fable_pc; при расхождении действует цитата):

1. Фраза книги про `A: fn: M` («остаётся при `merge` общей ссылкой на то же вхождение… `node` метода не меняется») отвергнута — «фигня написана»; автор напоминает, что уже говорил это. Имелась в виду общая ссылка на **нативную реализацию** метода: нативная реализация получает узел графа (при вызове), поэтому ссылку на неё сохранить можно. К Structure это отношения не имеет.
2. Следствие для вопроса: варианты 1 (вхождение метода — вечная ветвь) и 2 (общий терминал со своим признаком) сняты — среди Structure общего по адресу нет; вхождение метода как Structure подчиняется общему правилу Q42 (всё достигнутое копируется), а общей остаётся ссылка на реализацию — значение в скопированном вхождении, указывающее на тот же нативный вход. Для интерпретируемого метода «реализация» — его тело как кадры кода (общие по контракту, как сегодня) — это чтение fable_pc для замера ведущего, не цитата.
3. Следствие для кода и свидетелей (ведущий): k.4 снимается целиком, без нового признака метода; пин `lmx_merge_selftest` «shared by address», `lmx_shared_method_selftest` «shared M kept by address» и четыре «merge result check 77» (то же вхождение по адресу) воплощают отвергнутое чтение — пересмотреть под ссылку на реализацию. Документы поправлены здесь (`provenance/semantics-book.md` RU/EN, порождённые `docs/LMX_semantics.*`); `steps/copier-q42.md` §1 — у ведущего.
4. Дополнения автора (~00:14 UTC, дословно в блоге): «объясни причем здесь уровень файла?» и «Уровень файла ничемне отличается от других уровней». Прочтение: уровень файла выделяла сама постановка q44 (и отвергнутая фраза книги, и k.4 с его «родитель вне операнда» — у метода уровня файла родитель — единица); выделения нет — правило одно для метода любого уровня: вхождение копируется по общему правилу, общей остаётся ссылка на нативную реализацию. Книга поправлена так же (уровень объявления ничем не отличается); фраза «метод, объявленный в теле операнда, копируется вместе с операндом» заменена общей.
