# Load/cache/dirty: решение автора и границы

Этот документ — короткая запись решения 2026-09-28 и его последующих уточнений, не отдельная спецификация исполнения. Норма находится в [L3 §12](../LMX_semantics.ru.md#dynamic), [L3 §14](../LMX_semantics.ru.md#exits) и [L2 §18](../L2_spec_ru.md#lowlevel-address). Старые планы и журналы могут ссылаться на разделы 1–2 ниже; их исторические формулировки не заменяют действующие правила.

## 1. Решение автора: вернуть load/cache/dirty

Автор: «…удалить "there are no caches, dirty marks, working copies or checkpoints" и вернуть нормальное load и dirty как кеширование». Предыдущее предложение писать каждое присваивание немедленно в граф отозвано.

При входе в активацию используемое собственное поле загружается из графа в рабочее значение. Чтение и загрузка не делают его `dirty`. Успешное присваивание меняет рабочее значение и помечает поле `dirty`; отказ допуска не записывает новый кандидат и не стирает прежнее успешное изменение. На установленной контрольной точке публикуются только изменённые собственные поля, в их существующие места объявления. Чистое кэшированное поле обратно не пишется.

Явные и скрытые аргументы остаются локальными значениями активации: их присваивание не создаёт графового поля и не пишет в источник вызывающего. Явный путь через ссылочную переменную (`b\value` при `b: A`) берёт текущее рабочее значение ссылки `b`, затем обращается к референту в графе. Путь от непосредственно построенной Structure (`A\value` при `A: (...)`) начинается с её физического графового поля; он не подменяется рабочим значением. Запись через путь не присваивает и не помечает `dirty` чистое рабочее значение самого адресованного поля. После вложенного вызова внешняя активация автоматически не перечитывает свой кэш. Адрес `@x` относится к действительной ячейке значения, не временному кэшу или ABI-буферу; для Structure/Array это ячейка хранимой ссылки, а не дескриптор.

Публикация выполняется перед передачей управления вызываемому после вычисления фактических аргументов, на определённых выходах и при `yield`. `return`, `throw`, диагностика и `finally` следуют порядку [L3 §14](../LMX_semantics.ru.md#exits); передача управления `retry` и обычный шаг цикла сами по себе не новые контрольные точки. `dirty` — семантическая информация, не обязательный флаг внутри каждого `Lmx`: нативный транслятор может доказать необходимые записи статически, обходчик — хранить битовую карту.

## 2. Проверка вызываемого: решение Q49

Старое равенство целых сигнатур `sig(aVar.p) = sig(bVar.p) = ExpectedSig(Consumer,p)` и сравнение только обязательных формалов не описывают направленный допуск. По [решению Q49](https://github.com/michael0xf/LMX/blob/0a764078/LMX_blog/q/q49.md), для каждого видимого вызова Consumer кандидат должен принимать **фактически поданные** аргументы, включая явно поданные необязательные. Отсутствующие входы формируются из разрешённых умолчаний и динамических/лексических источников; полученный вызов должен подходить действительному описанию реализации. Результат и выходы проверяются относительно ожиданий Consumer. Аналитическая стадия не исполняет тело, преобразователи или тесты; явно заданные тесты Consumer исполняются следующим этапом. Соответствие, установленное однажды, не перепроверяется после каждой мутации значения.

## 3. Три разные публикации

- Публикация рабочего поля: `dirty`-значение активации → существующая ячейка графа.
- Публикация построения: готовый результат становится доступен принимающему месту.
- Публикация Message: подготовленные исходящие письма переходят в состояние доставки по правилам успешного такта.

Диагностический выход может выполнить публикацию рабочих полей и очистку, но не делает неуспешный такт успешным и не публикует его ожидающие исходящие письма. Эти значения слова «публикация» нельзя заменять друг другом.

## 4. Что не является текущим правилом

Отозваны прежние описания «нет кэша/dirty», обязательной прямой записи каждого own-присваивания, sticky-адреса временного аргумента и скрытой копии графа при рекурсии. Также не действует старый выбор последнего одноимённого вхождения: повторное объявление на одном уровне теперь адресует существующее поле по общему правилу присваивания. Этот документ не вводит отдельный граф данных, глобальный сервис когерентности, автоматическое перечитывание после каждого вызова или скрытый откат внешних эффектов.
