# Доменная модель и хранение данных

[Руководство RU](LMX_Design_Patterns.ru.md) · [Guide EN](LMX_Design_Patterns.en.md)

19 исходных паттернов 16–34 сохранены отдельно. Листинги показывают одинаковую ограниченную задачу. Внешние БД и коллекции с методами, не заданными языком, перечислены как порты: их цена не считается нулевой. Транзакция БД отличается от последовательного turn Message. HTTP-профиль LMX существует; он доставляет запрос к прикладной границе и не создаёт автоматических гарантий хранения. Все листинги авторские; источники использованы для определения паттерна. LMX-фикстура заранее помещает зависимости и начальное состояние в фактический DATA владельца; входы с потенциальной неоднозначностью позиции передаются явно по имени. Например, account\debit(amount := 30). Листинги контролей рассчитаны на Python 3.10+, C# 12, Java 17 и Go 1.18+ там, где соответствующий язык присутствует.

## Запуск R0 и вызов сценария

Программа всегда начинает выполнение с **R0**, обычного L3 Thread под родительской заглушкой, без DATA и пользовательских actuals. Отсутствие DATA пропускает только обработку входов; локальные переменные, обычные вызовы, диспетчеризация и выходы сохраняются. Именованный сценарий вызывается из уже запущенного корня или обработчика обычным механизмом и не заменяет точку старта.

Для фрагмента указываются его принимающий контекст и обычный вызов сценария. Описание DATA получает эту роль только по существующему договору принимающей операции; оно не превращает CODE корня в DATA и не вводит отдельный профиль загрузки или выбор Main. Родительская заглушка может передать свои значения обычным сообщением корню; внутренние параметры запуска Thread не становятся пользовательскими actuals. См. [запуск корня](../../LMX_semantics.en.md#root-entry).
