## Следующая зависимость M2

Методный случай `unit_named_struct_call_method_rebound_hidden.lm2`: корень перепривязывает `A` к `B`, затем вызывает `run`, внутри которого `call: A`. Сгенерированный `run` читает фактический адрес B, но `l2_check_struct_call` для `mi != l2_e` оставляет статический ABI A. В B есть скрытый `status`, поэтому `lmx_call_prim` вызывается с нулём входов, а B требует один; walker падает на `ARG_ENTRY`. **Не чинить это добавлением аргумента по имени или fallback на тип A.**

Нужна общая межпроцедурная передача кандидатов из корневого потока в точные входы вызываемых методов, включая вызовы внутри выражений, с объединением состояний у всех мест вызова. Делать её до `l2_check_body`/`l2_dyn_close`/подсчёта кадров, чтобы рёбра вызовов, скрытые входы, `throws`, размеры, walker и native видели одно фактическое тело. Единственный доказанный B должен дать сертификат B на внутреннем `call: A`; несколько или неизвестные кандидаты не дают права использовать объявленную A — нужен общий адресный диспетчер либо честный отказ до его реализации. До этого методный положительный тест остаётся красным. Нынешний `l2_m2_root_current` работает только для `mi == l2_e`; статический fallback в других методах опасен.

Затем продолжить общий M2 для полного операнда `call` (`Outer\Inner`, удержанная ссылка, результат `merge`, копия, косвенная запись) и выбранных по фактическому телу скрытых входов/`throws`. Не делать отдельный парсер для пути и не выбирать ABI по модели поля. Открытые свидетели и зависимость раннего D-105 описаны в [M2 плана](next_core_tasks_v3.md) и [steps/current.md](steps/current.md). Для принятого среза нужны native, принудительный walker, отрицательный мутант и полный необходимый gate; только затем точный отчёт, коммит и push. Codex больше не выполняет конкурентный build.
