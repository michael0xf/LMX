## Что из ответа следует

Это решение Codex по ответу автора (FABLE-CODEX-20261004-12), не слова автора.

- Таблица имён во время исполнения запрещена при любых условиях, в том числе
  при формировании входов вызова. Имена служат трансляции и `toLmx`.
- Исходные имена и соответствия разрешаются при трансляции. Исполнение идёт по
  физическим ссылкам, выбранным местам объявления и обычным позициям входов.
- Замена таблицы реестром хешей имён, записью METHOD, полем Lmx, метаданными
  атома или постоянным вспомогательным графом не допускается.
- Адреса существующих объектов не двигаются: ни дескрипторы перемещения, ни
  вторая система идентичности не нужны. Явное копирование графа создаёт другие
  объекты и перенастраивает их обычные ссылки.
- Семантика вызова не меняется: формируются входы фактически выбранного
  вхождения, а не список образца. Совпадение номера входа и машинного типа не
  делает разные имена одним входом.
- Специализация при трансляции допустима там, где она доказана. Полное
  перечисление будущих фактических не становится требованием языка, а
  неизвестное происхождение не считается несовместимостью.
- Если сохранённый граф или ABI потеряли нужные ссылки, чинится эта потеря.

## Уже установленные правила

- Вызов использует фактически выбранную Structure; её реальный `native`
  выбирает нативное исполнение, иначе исполняется её граф.
- Скрытые входы берутся из текущих значений вызывающего, затем из входов и
  лексического окружения фактического callable. Одинаковый машинный тип не
  делает разные имена одним входом.
- Имена не хранятся внутри Lmx или атомов. Уже существует отдельная таблица
  адресов и исходных имён. Новые вспомогательные графы запрещены.
- При вызове проверяются полный интерфейс и доступность динамических входов
  ([семантика: допуск вызова](../../docs/LMX_semantics.ru.md#admission-case-7),
  [перенесённый callable](../../docs/LMX_semantics.ru.md#admission-case-8)).

## Минимальное различие

Два обычных именованных тела A и B требуют соответственно свободные `x` и
`y`, оба `int`. У вызывающего есть `x=11`, `y=29`. Вхождение p сначала
ссылается на A, затем заменяется на B. При вызове текущего p второе тело
должно получить 29, а не 11. Номер ABI-входа 0 и тип `int` у обоих одинаковы.
Третье тело требует `z`, которого нет ни у вызывающего, ни в его фактическом
лексическом окружении: такой вызов должен получить отказ до выполнения тела.
Это проект диагностического свидетеля, не утверждение о выполненном тесте.

## Конкретное расхождение текстов и реализации

В [§4 семантики](../../docs/LMX_semantics.en.md#fields) внешняя таблица
объявлена только средством восстановления исходника: construction/copy/calls
не используют её для разрешения значений или выбора кода. Аналогичный запрет
есть в §1 и `dev/l2src_sandbox/lmx_source_names.h.lm1:3`.

В проверенном translator7ADBFE22 полные имена/порядок скрытых входов есть только
в временных массивах транслятора. `l2_emit_parts` не сохраняет аргументную
часть обычной именованной Structure, `l2_rw_arg` сохраняет номер, fallback и
тип, а `l2_emit_ns_exec_at`/`l2_rw_ns_hidden` готовят входы по исходному
прототипу. Реальный native word уже диспетчеризуется правильно. Теряются
сведения о том, какой скрытый вход нужен текущему заменённому телу.

Вопрос не предлагает новых полей Lmx, METHOD/sig-record, native registry,
перманентного вспомогательного графа или атомных метаданных. Запрет пока не
отменён; до ответа не менять спецификацию и не выдавать одну из альтернатив
за утверждённую норму. Другие проверяемые срезы critical_graph_bug продолжаются.

## Измеренный свидетель — 2026-10-04

Измерение сделано до ответа автора и механизма не выбирает. То же различие
для callable-формала измерено на трансляторе коммита `69d3d9a5`
(`dev/l2src_sandbox/l2trans.lm1`), нативно. Удерживаемый callable в нём не
участвует.

```text
int: base 5
int: other 9
fn: f0 () int
    return: base
end: f0
fn: g1 () int
    return: other + 1
end: g1
fn: run (f0: q) int
    return: q()
end: run
int: r run(g1)
```

| Программа | По установленным правилам | Измерено |
| --- | --- | --- |
| как написано | 10: у `run` нет `other`, лексический источник даёт 9 | 6: `g1` получил значение `base` на месте `other` |
| `int: other 40` внутри `run` | 41: привязка вызывающего | 6 |
| `run(f0)` с `int: base 40` внутри `run` | 40 | 40 |
| фактический читает `other` и `third`, образец — один `base` | 29 | программа принята; останов при исполнении: `lmx: invariant: a trampoline was called outside its method's signature` |
| фактический без свободных имён, образец с одним | 3 | принята; тот же останов |
| образец без свободных имён, фактический с одним | 10 | принята; тот же останов |

С обходом методов каждая из этих программ отвергается: `a callable result or
a callable formal is outside the walkable subset`.

Где это в трансляторе, строки на `69d3d9a5`. Допуск фактического —
`l2_method_sig_compatible` (:27645): арность, результат, throws и типы
объявленных формалов. Вызов через формал — `l2_emit_call` (:27958):
`nhid: l2_m_dyn[idx]` (:28015), где `idx` — метод, которым объявлен формал
(`l2_cf_get`, :27634); источник каждого скрытого входа выбирает
`l2_hidden_from` (:26333) для этого метода, и входы передаются вхождению
позиционно. Сгенерированный `run` принимает `base` своим скрытым входом и
вызывает вхождение с одной ячейкой.

Строки стенда: красные обязательные позитивы
`unit_callable_formal_free_names_other`, `_override`, `_extra`, `_none`,
`_forward`; зелёный контроль точного совпадения
`unit_callable_formal_free_names_self`.

Третий случай исходного проекта — вход, которого нет ни у вызывающего, ни в
лексическом окружении фактического, — здесь не измерялся.
