# Интеграция выражений, типов и массивов

## Обязательная норма: пустая строка завершает блоки

**Пустая физическая строка закрывает все открытые блоки первого уровня
и выше, сбрасывает текущий логический уровень в 0; следующий код
разбирается от нулевого уровня.** Она не продолжает прежний вложенный блок.
Пустой является строка без символов либо только с пробелами/табуляциями.
Строка с комментарием `#`, точками уровня или иным текстом не является пустой.

Это правило применяется в обычном структурном лексическом контексте.
Защищённое содержимое допустимых литералов, точных идентификаторов,
блокового текста и сырых комментариев сохраняет свои правила. Вложенный
ограниченный документ Mix имеет свой корень. Пустая строка не подставляет
отсутствующую закрывающую скобку и не исправляет незавершённый литерал.
Нормативные подробности: [грамматика RU](spec/LMX_grammar.ru.md#levels)
и [EN](spec/LMX_grammar.en.md#levels).

Корректный пример без `---` и `end`:

```lmx
First:
    Nested:
        int: value 1

Second:
    int: value 2
```

Здесь `First` и `Second` — два соседних корневых узла; `Second` не является
продолжением `First` или `Nested`. Между фрагментами достаточно **одной**
пустой строки.

Поэтому `---` на нулевом уровне, за которым идёт пустая строка и новый
код, удалён из примеров как избыточный. Значимые закрытия, без которых
обычный переход между уровнями недопустим, сохранены. Генераторы
используют [нормализатор](tools/NORMALIZE_LMX_CLOSERS.md), а не слепое
удаление всех строк с `---` или `end`.

## Проверка общей границы P0

Если P0 требует закрытия у примера с корректной структурной пустой строкой,
нужно локализовать ошибку и внести исправление общего P0 в [план](../next_core_tasks_v3.md#types-arrays-20261126).
Для диагностики сверяют начало незакрытого региона и проверяют, входит ли пустая строка
в защищённый литерал, скобочную группу или другой ограниченный контекст.

Минимальная проверка исправления:

1. Два корневых фрагмента с ровно одной пустой строкой между ними
   разбираются без дополнительного закрытия.
2. Пустая строка после нескольких вложенных уровней закрывает их все.
3. Строка из пробелов/табуляций создаёт ту же границу; строка только
   с комментарием сама по себе её не создаёт.
4. Удаление корневого `---` непосредственно перед пустой строкой
   не меняет полученный граф.
5. Без пустой строки необходимое многоуровневое закрытие остаётся
   обязательным; защищённое содержимое и границы Mix не повреждаются.
6. Разбор, сериализация и повторный разбор сохраняют дерево.

## Новые договоры, которые нужно подключать вместе

| Форма | Договор |
| --- | --- |
| `a * b + e` | При наличии Array выбирается допустимый матричный/массивный профиль; форма и реальные типы берутся из описания |
| `.*`, `.+` и другие точечные формы | Глубина 1; общий обход одного логического измерения по сохранённой форме |
| `.(expression)op` | Явная глубина; выражение в скобках разбирает общий P0 и вычисляет один раз при достижении операции |
| `.=` | Поэлементное сравнение на равенство, без записи |
| `.:` | Поэлементное присваивание; обычная форма сохраняет RHS и проверяет допуск до записей |
| `(a b c) .: (b c a)` | Та же операция над группой реальных мест; Structure является Array свободных элементов |
| `fuse(expression)` | RAW-выражение с общим обходом результата; явная форма `target .: fuse(expression)` имеет описанный потоковый договор записи |
| `a ? b : c` | Условие вычисляется один раз; только выбранная RAW-ветвь |
| `array[start:stop:step]` | Пропуски границ, знаковые границы, ненулевой шаг; стоп исключён |
| `array[::-1]` | Обратная выборка последовательности |
| `a + b + [1 2 3] + d` | Inline Array — целое значение внутри обычной цепочки Expression |
| `[arr2]` | Обычный Array из одного целого значения arr2, без раскрытия содержимого |
| `[][][]int: arr` | Трёхмерное описание одного плоского Array; доступные оси в описании фактического типа; при capacity=length второго дескриптора нет |

Прямая отрицательная индексация Array не приобретает смысл отсчёта
с конца. Отрицательное относительное смещение выполняется **через
указатель**. Интерпретируемый L2 проверяет границу Array; нативный
L2 не вставляет автоматическую проверку, но это не делает недопустимый
доступ корректным. Отрицательные границы среза — отдельный допустимый
договор.

Нормативные главы: [массивы](spec/ARRAY_EXPRESSIONS.ru.md),
[глубина операций](spec/OPERATOR_DEPTH.ru.md),
[хранение и мерность](spec/ARRAY_STORAGE.ru.md),
[fuse](spec/FUSION.ru.md), [условие и срезы](spec/TERNARY_AND_SLICES.ru.md).
Готовые LMX-циклы, псевдокод интеграции, эталонные модели и демонстрации
находятся по ссылкам в этих главах. Обе формы операции используют
общий алгоритм; RAW и PLACE нельзя заранее вычислять как обычные VALUE.

### Окончательный договор depth

Шаблон операнда принимает **left, depth, right**, затем сохраняет две
обязательные константы PASS_ARGS_AS_IS и PRIORITY. Без точки передаётся 0,
одна точка означает 1, все прочие глубины записываются `.(выражение)`.
Повторные точки не являются формой глубины. Сочетание `.(` всегда
начинает модификатор оператора или функции: числовой сканер не поглощает
его точку как десятичную. `1.(3)+2.(2)+3` разбирается с теми же границами,
что `1 .(3)+ 2 .(2)+ 3`; обычное выражение внутри скобок разбирает общий P0. Число не добавляется в right;
отсутствующий left остаётся отсутствующим. RAW/TYPE/DATA/PLACE сохраняют
свои роли. Вычисление глубины не выполняется при обнаружении имени,
чтении приоритета или в пропущенной ветви.

В структурной форме используется базовое имя в обратных кавычках и
именованный аргумент depth: `` `*`(a; b; depth := 2) ``. Отдельных стандартных
вызываемых имён с точкой нет. Для присваивания каноническое имя — `:=`:
`:=` передаёт 0, `.:` — 1, `.(выражение):` — указанную глубину. `.=` остаётся
сравнением. Ссылки на throws тоже используют базовое имя.

**Depth работает по логическим измерениям плоского массива.** У rank-2
массивов `a * b` получает целые матрицы; `a .* b` применяет базовое
произведение к парам логических строк; `a .(2)* b` умножает скалярные
координаты. Строки адресуются срезами того же хранилища без выделения
отдельных LMX-структур. Это заменяет ошибочное промежуточное ограничение
«любой плоский Array имеет лишь один уровень depth».

Недопустимая глубина, несовместимость требуемых измерений/форм и
непригодность выражения для fuse — **диагностика транслятора, если нарушение
определимо при подготовке, иначе интерпретатора при достижении операции**.
Для этих нарушений не вводятся новые пользовательские исключения и
добавочные throws. Реальные отказы вызываемых функций сохраняют свои
обычные каналы.

### Единое хранение и доступ

Последующее дополнение уточнило эту часть: мерность и явно заданные размеры
входят в каноническое описание типа, TYPE непосредственно ссылается на него.
Capacity экземпляра хранится отдельно только при реальном резерве; при
capacity=length второго дескриптора нет. **Заголовок Lmx
`parent/length/storage` и пользовательские поля Structure не расширяются.** Плоские
одномерные операции и операции с учётом мерности доступны над одним
хранилищем согласно их обычным договорам. Обновление формы не должно
оставлять размеры осей, несовместимые с фактической длиной.

Structure остаётся общим `[]@`. Отдельной сущности «массив массивов» нет.
Для соответствующих индексов полей действуют формы общего доступа:

| Путь по именам | Путь по индексам |
| --- | --- |
| `struct\struct2\field` | `struct[i]\[j]` |
| `struct\struct2\field[k]` | `struct[i]\[j]\[k]` |

Не путать этот путь с соседними индексами `arr[i][j][k]`, которые используют
сохранённую мерность плоского массива. Inline `[items]` создаёт целое Array-
значение; группировщик не снимает с него границу как с группировки выражения.
Оптимизация цепочки с таким значением сохраняет приоритеты, порядок
вычислений, типы, наблюдаемую идентичность и порядок отказов.

### Две формы строк массива

В объявлении многомерного массива точка с запятой завершает текущую
строку и начинает следующую. Прежняя форма с отдельными квадратными
группами строк сохраняется. Вложенные вызовы, строки и прочие защищённые
формы сохраняют свои внутренние разделители; вне инициализатора `;`
по-прежнему завершает короткую форму.

Обе записи ниже корректны и полностью равнозначны: в каждой три строки
по три элемента. Идентификаторы a, b, c, d, e предполагаются уже
объявленными int-значениями. В групповой форме строки разделены пробелами.

```lmx
[][]int: [a b c; a b d; a b c]
[][]int: [[a b c] [a b d] [a b c]]
```

Размеры обоих массивов — `(3,3)`, значения также совпадают. Ещё одна
равнозначная пара с готовыми числами:

```lmx
[][]int: [1 2; 3 4; 5 6]
[][]int: [[1 2] [3 4] [5 6]]
```

Следующие записи **ошибочны**; в первых двух длины строк равны 3, 4 и 5:

```lmx
[][]int: [a b c; a b c d; a b c d e]
[][]int: [[a b c] [a b c d] [a b c d e]]
[][]int: [[a b c] [a b d] [a b c d]]
```

В последней записи длины равны 3, 3 и 4; она тоже ошибочна.
Неравные длины не создают новый вид массива. Это диагностика формы
транслятора/интерпретатора. Допустимый конструктор формирует одно плоское
хранилище, сохраняет доступные rank/extents в описании фактического типа и не добавляет поля
в Lmx. Прямоугольность остаётся обязательной для этого объявления.

У обычной DATA-структуры требования прямоугольности нет. Эти две
альтернативные записи корректны и равнозначны:

```lmx
Struct: [a b c] [a b d] [a b c d]
Struct: (a b c) (a b d) (a b c d)
```

В обоих случаях внутри Struct находятся три обычные безымянные структуры
длиной 3, 3 и 4. Это общий Array/Structure, без отдельного вида контейнера.
Принимающая роль определяет смысл групп в чистом графе; группировщик не
смотрит на символы исходных скобок и не получает признаков их начертания.

### Динамическая мерность и глубина указателя

В спецификацию добавлены динамические формы уже имеющихся префиксных
конструкторов типа:

| Форма | Значение |
| --- | --- |
| `[](N)int` | N измерений одного массива; эквивалент N последовательным `[]` |
| `@(N)int` | N уровней указателя; эквивалент N последовательным `@` |

```lmx
[](1)int: [1 2 3 4]
@(2)int: ptr_to_ptr
```

Первая строка соответствует `[]int: [1 2 3 4]`, вторая —
`@@int: ptr_to_ptr`. N задаёт число измерений либо уровней указателя,
а не длину, capacity или размеры отдельных осей. Выражение N получается
один раз при потреблении требования типа через общий механизм выражений;
построение типа само по себе не выделяет массив или цепочку указателей.
Повторные формы `[][][]int` и `@@@int` сохраняются.

По отдельному указанию автора это **дополнение спецификации и описания
патча**. Production-реализация динамических префиксов не добавлялась;
существующие host-проверки массивов не выдаются за проверку этих форм
реальным P0, транслятором или runtime. Норма включена в
[контракт объявлений](spec/TYPE_DECLARATION_FORMS.md), грамматики и
[описание хранения](spec/ARRAY_STORAGE.ru.md).

## Проверки и статистика

Статистика пересчитывается по полным актуальным исходникам. Процедурный
и функциональный LMX считаются отдельно, со всеми написанными
объявлениями и `throws`; колонки «без сложного throws» нет. В PDF/XLSX
зелёным выделяется фактический минимум строки среди сопоставимых
полных листингов, включая равные минимумы.

Проверки моделей и статические проверки источников не подменяют
production parser, компилятор или runtime. Их конкретные результаты
и ограничения перечислены в [отчёте редакции](spec/REVISION_2026-11-26.md).
Новые примеры не получают фиктивный статус parser PASS.

Не запускайте полный `core_catalog/tools/rebuild_core.py` в этой
поставке без исходного `selfbuild/`: отсутствующий внешний исходник
нельзя превращать в пустой исторический индекс. Для текущей редакции
использован [точечный синхронизатор](tools/SYNC_LMX_METADATA.md).

Проект будущего генератора описан в [записке об интерпретаторе и SLJIT](LMX_INTERPRETER_JIT.md).
