# Тесты парсера

Перенос выполнен последовательно: `lingvamyxa_old_worked_version` → `lingvamyxa` → `L1`. Старые проекты не изменены. Все рекурсивно найденные `tests/**/*.lmx` из этих трёх деревьев сохранены; совпадающие путь и SHA-256 используют одну копию, различающиеся версии — разные файлы. Происхождение каждого файла, размер и SHA-256 указаны в [манифесте](../../provenance/parser-tests.json).

В составе переноса: 184 версии входов P0 `.lmx`; 301 файл замороженных эталонов `printTree.lm0`; 78 файлов контракта дерева/метаданных; 43 входа проверок выражений и C-поверхности; 7 исторических управляющих файлов; 1 вспомогательный файл и 1 исходник, используемый как вход проверки парсера. Наличие `trans_` в имени некоторых `.lmx` не означает проверку семантики: в корпусе P0 это только вход разбора.

Дополнительно проверены все 119 входов `.lmx` в `lingvamyxa_prev`: все уже представлены побайтово совпадающими копиями. Их происхождение добавлено к тем же записям манифеста.

Текущая переносимая обвязка — `tools/run_parser.py`. Ей передаётся готовый `printTree` извне; реализации парсера в новом проекте пока нет. Исторические скрипты сохранены для переноса дополнительных проверок и содержат пути/зависимости своих прежних проектов; это архив обвязки, а не обещание их автономного запуска в LMX.

Из корня LMX:

```text
python tools/check_docs.py
python tools/run_parser.py --parser PATH_TO_PRINTTREE --profile historical --output build/historical
python tools/run_parser.py --parser PATH_TO_PRINTTREE --profile previous-l1 --output build/previous-l1
python tools/run_parser.py --parser PATH_TO_PRINTTREE --profile current --output build/current
```

`historical` проверяет 131 случай старого манифеста: код выхода и точные байты дерева либо код/строку/колонку ошибки. `previous-l1` проверяет тот же набор с зафиксированными старыми изменениями допуска L1. Эти профили — историческая регрессия, не утверждение новой нормы. `current` проверяет новые уточнения автора; он должен выявлять несовпадения старой реализации, а не скрывать их. Отказ, аварийный выход и таймаут не считаются успешным отрицательным тестом.

Проверено 2026-09-19:

- Исторический `printTree.lm0.exe`: 131/131 старых ожиданий совпали.
- `L1/build/l1trans/gen2/printTree.exe`: 131/131 прежних ожиданий L1 совпали.
- Новое `receiver:` / `---`: текущий L1 отвергает с `P0 parse error 32 at 1:1`; исторический парсер принимает, но теряет пустую структуру-аргумент. Оба результата не соответствуют уточнению автора.
- Контрольное `receiver: ()`: оба парсера сохраняют одно поле с пустой структурой.

Точные хэши исполняемых файлов и результаты находятся в [отчёте проверки переноса](../../provenance/parser-verification.json). Новое правило уже закреплено положительным тестом; парсер для него ещё предстоит перенести/исправить. Остальные перенесённые сценарии и metadata/выражения сохранены, но этот прогон не объявляется их полным исполнением.

Нельзя перегенерировать исторические эталоны для получения зелёного результата. Тест нового языка и старый снимок должны оставаться различимыми. Особенно важно проверять наличие пустой структуры, а не только успешный код выхода.
