# Q52. Присваивание свободному имени в методе не объявляет поле и не пишет вызывающему

Состояние: закрыт двумя ответами автора 2026-09-28; документальное решение не означает, что код и гейты уже исправлены.

Правило (a) — рабочее состояние (`docs/new_parts/dirty.md`, книга §12): own-поля, используемые голым именем, загружаются при входе в активацию в рабочие значения; присваивание помечает dirty; публикация — на границах; после возврата ничего не перечитывается: «приостановленная внешняя активация не перечитывается и сохраняет свои рабочие значения» (книга §12, RU), «After the inner return, the outer activation's bare `x` reads 2, its own working value» (EN). Свободное имя в вызываемом получает текущее значение из контекста вызывающего (скрытый вход, книга §12); присваивание аргументу — явному или скрытому — меняет значение активации и не пишет обратно (`assignment_is_not_declaration`, bafca4c).

Правило (b) — Q9 (автор, `LMX_blog/2026-09-22.md`:363): «любое присвоение проецируется в поле структуры». Так работает транслятор: голое `y: y + 3` в методе пишет поле единицы `y` в графе, и ~20 строк гейта читают его в ROOT после вызова. Сегодня же: видимость вперёд и вниз — `y`, объявленное в ROOT до `s`, видно в `s` как то же место объявления.

Наименьший пример (строка гейта `unit_sub_return_trailer`):

```text
int: y 0
sub: s ()
    y: y + 3
    return
s
exit(y)
```

Сегодня (гейт): 6. Если ROOT кэширует свои поля как любая активация, `exit(y)` читает своё рабочее `y` — 0: по (a) граф остаётся 0 (`y` в `s` — скрытый вход без записи назад), по (b) граф становится 3, но ROOT его не перечитывает и явного пути к своему полю не имеет (`node` в ROOT — 0, имени у ROOT нет), а следующая dirty-запись ROOT затирает 3. Тот же класс: `unit_bare_fn_stmt`, `unit_named_actual_sub`, `unit_field_write_from_method` (свидетель Q9), `unit_s1_catch_publish`, записи `node\shared` из метода с проверкой в ROOT — всего ~20 строк.

## Вопрос

`y: y + 3` в `s` пишет место объявления `y` единицы (Q9), и голое `y` в ROOT после вызова читает это место — 6, то есть тело единицы работает прямо над местами объявления, без рабочих копий активации; или ROOT — такая же активация с загрузкой при входе, и `exit(y)` даёт 0?

## Ответ автора

Автор: «Q52 -- нет видимого поля "y" у структуры "s", граф для интерпретатора сохраняется а поля такого нет (потому что объявление не там)».

На уточнение «что читает ROOT после вызова?» автор выбрал: «0 — меняется лишь скрытый вход s».

Следовательно, `y: y + 3` в `s` не объявляет поле `s\y`; оператор остаётся в полном графе `s` для интерпретатора. Присваивание меняет полученный скрытый вход активации `s`, не объявленное в ROOT место `y` и не ячейку вызывающего. В минимальном примере `exit(y)` читает **0**. Прежнее чтение 6 и Q9 в этом применении отменены ответом автора, а не компенсируются особым случаем ROOT.

Гейт `unit_sub_return_trailer` и другие зависимые строки требуют поимённого пересмотра в срезе Opus; до измерения не считать их зелёными.
