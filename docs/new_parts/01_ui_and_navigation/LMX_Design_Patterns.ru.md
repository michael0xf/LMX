# LMX: Интерфейс и навигация

TypeScript показывает типичный браузерный стиль с функциями и объектами; C# — явные контракты и стандартные уведомления .NET. Оба языка допускают UI без привязки сравнения к конкретному toolkit.

Семь исходных позиций сохранены: MVC, MVP, MVVM и Redux различаются направлением обновления состояния; Front/Page/Application Controller различаются областью ответственности. HTTP-примеры используют существующий транспортный профиль LMX и сравнивают принимающее ядро, а не полный web-host.

## Каталог

### 001. [MVC (Model-View-Controller)](001_mvc_comparision.md)

Модель хранит состояние; контроллер обрабатывает действие; представление читает модель.

**Сценарий:** Увеличить счётчик с 5 до 6 и получить значение через отдельное представление.

**Наблюдение:** 6; контроллер не записывает поле отображения.

Во всех трёх вариантах сохранены три роли. У LMX ссылки на модель находятся в DATA, у контрольных языков — в полях экземпляров.

### 002. [MVP (Model-View-Presenter)](002_mvp_comparision.md)

Пассивное представление получает готовое значение от презентера.

**Сценарий:** К модели 5 прибавить 2; презентер явно обновляет пассивный экран.

**Наблюдение:** Модель 7, экран 7, demo возвращает 77.

Ключевое отличие от MVC-примера — экран не читает модель. Интерфейс IView/структурный контракт можно подменить записывающим тестовым представлением.

### 003. [MVVM (Model-View-ViewModel)](003_mvvm_comparision.md)

ViewModel предоставляет состояние представления и уведомляет binding об изменениях.

**Сценарий:** Ввести значение 6; отображаемое производное значение равно удвоенному вводу и обновляется через подписку.

**Наблюдение:** 12; обновление доходит до экрана через зарегистрированную связь.

LMX и TypeScript показывают одну связь уведомления; C# использует стандартный INotifyPropertyChanged. Полный binding engine ни одному языку не приписывается бесплатно.

### 004. [Flux / Redux](004_flux_redux_comparision.md)

Действия проходят через единый store и чистый reducer.

**Сценарий:** Из состояния 0 обработать действия +2 и +3; сохранить старое значение после первого шага.

**Наблюдение:** Сохранённое значение 2, текущее 5, demo = 25.

TypeScript использует объект action, C# — value record, LMX — структурный вызов с именованным delta. Это однонаправленный поток без обязательной библиотеки Redux.

### 035. [Front Controller](035_front_controller_comparision.md)

Один вход применяет общую политику и направляет запрос к обработчику.

**Сценарий:** Маршрут 1 возвращает 200 только при admission=1; иначе 403. Неизвестный маршрут даёт 404.

**Наблюдение:** demo = 200; дополнительные проверки: (0,1) → 403, (1,9) → 404.

Общая политика применяется до выбора endpoint. Все листинги измеряют одинаковый dispatch-core, исключая HTTP host, декодирование и реальную аутентификацию.

### 036. [Page Controller](036_page_controller_comparision.md)

Отдельный обработчик принадлежит конкретной странице или действию.

**Сценарий:** Обработчик страницы заказа принимает quantity=3 и строит значение subtotal=30.

**Наблюдение:** 30; другая страница не участвует в вычислении.

Page Controller отличается от Front Controller принадлежностью одному экрану/действию. Общий web-router может существовать перед ним; эти паттерны совместимы.

### 037. [Application Controller](037_application_controller_comparision.md)

Единое место принимает решения о переходах между экранами.

**Сценарий:** На экране 1 успешная проверка переводит на экран 2; отказ оставляет экран 1.

**Наблюдение:** 2 после успешного перехода; (screen=1, valid=0) возвращает 1.

Смысл паттерна — концентрация правил перехода. Автоматический переход от изменения любого поля модели во всех трёх вариантах отсутствует.

## Границы сравнения

Размеры вычислены из трёх листингов каждого паттерна. Они не измеряют скрытый код поставленных библиотек, runtime, HTTP-хоста или БД. Для полного понимания нужны ограничения каждого отдельного примера. Номер совпадает с исходным списком; номера 86–90 — явно добавленные темы.
