# `sys\toLmx` и ресиверы объявлений в данных: что восстанавливается из чистого графа и как

Запись исполнителя (fable_pc), 2026-11-17, по вопросу автора: сможет ли `toLmx` восстановить ресиверы `int`,
`merge` в роли данных и остальные из чистого графа и как он будет это делать. Факты — одиночные прогоны
графового инструмента среза418+419 и чтение кода (sonnet; таблица по 42 записям и круговые прогоны лежат вне
репозитория: `build2/codex_fix250generationchain01/runs/fable-m10-call-forms-20261116-01/receipts/sonnet/tolmx/REPORT.txt`).
Самого `sys\toLmx` в чистом графе ещё нет: есть диагностический дамп (`lmx_graph_dump`), и всё измеренное
относится к нему. Норма — [книга](../docs/LMX_semantics.ru.md#memory) и
[спецификация ядра, §8](../docs/kernel-implementation.ru.md).

## Коротко

1. Объявления мест (`int: a 1`, `int: a`, `@: p T`, `@: p`, `@: p 0`) восстанавливаются полностью: записи ресивера
   в графе нет, место само и есть объявление, а ресивер выводится из типа ячейки.
2. Записи всех остальных ресиверов лежат в чистом графе как написаны и выводятся с головы: вычисляемые
   объявления, `fn`, `sub`, `catch`, Structure, вызовы, `if`, `for`, `:=`, квалификаторы, `@: R merge(A; B)`.
3. `merge` в данных (`S: merge: A B`) восстановим всегда: запись остаётся в графе, явный путь её не исполняет,
   а композицию вызов готовит в своём namespace и в граф не пишет. Подготовленный шаг ядра, заменявший запись
   составленной Structure при построении графа, отозван.
4. Нынешний дамп кодеком ещё не является: целиком обратно в построитель он не читается ни разу из56 проб, и в
   нескольких местах печатает другую конструкцию. Список — в последнем разделе.

## Правило, от которого всё идёт

Автор, 2026-11-11 ([журнал](../LMX_blog/2026-11-11.md#single-structure-index-path)): «ресиверы объявления
примитивов не помещаются в граф непосредственно. Остальные ресиверы -- непосредственно помещаются в чистый граф».
Там же об атоме известной Structure: «никуда физически не раскрывается и при построении чистого графа тоже …
На knownModel он начинает ссылаться только при интерпретации-трансляции».

Книга о выводе: «`sys\toLmx` выводит LMX-текст текущего графа с каноническими именами и сохранёнными
комментариями. Явно перезаписанная конструкция выводится в текущем виде; исходник из истории или native не
восстанавливается … Сохраняются порядок и пустые позиции, общие ссылки, циклы, имена и типизированные значения:
это восстанавливаемый текущий граф, не только печать похожего исходника».

Имён в ячейках нет: имя места, Structure и Frame — строка таблицы «адрес → имя»; у Frame эта строка — его голова,
то есть слово ресивера.

## Как `toLmx` выводит каждую запись

Вывод идёт по полям выбранной Structure в их порядке; что печатать, решает то, что лежит в слоте.

| Запись в данных | Что лежит в графе | Как выводится |
|---|---|---|
| `int: a 1` | ячейка числа; имя — строка «адрес → имя» | ресивер — по типу ячейки, имя — из таблицы, значение — текущее: после записи7 выводится `int: a 7` |
| `int: a` | ячейка «`int` без значения» | `int: a`; после записи значения место должно выводиться со значением (дамп сегодня его не печатает) |
| `int: a f()` | Frame `int` с именем и записанным вызовом | записью, как написано; после явной записи в поле — местом со значением |
| `u8: a 1`, `double`, `char`, `string` | сегодня Frame: местом чистый граф делает только `int` | записью; когда место получит запись «код типа и значение» (M15) — как `int`, ресивер по коду типа |
| `@: p T`, `@: p`, `@: p 0`, `@: p int` | ссылочные ячейки четырёх видов | `@:`, имя, затем цель, `0`, ничего или `int` — по виду ячейки и её цели |
| `@: p int @x`, `@: p f()`, `@: R merge(A; B)` | Frame `@` с записанным кандидатом | записью |
| `fn`, `sub`, `catch` | Frame ресивера с частями: имя, входы, `return`, `data`, `code` | заголовком и частями |
| Structure — `A()`, `A: B`, `A(int: x 1)`, блок | Lmx с именем `A` и полями | одной нормальной формой: скобки, двоеточие и блок в графе не различаются |
| атом, называющий Structure, место или ничего | слово | словом; на что оно ссылается, решается при чтении |
| `private: (int: x 10)` | место `x` с признаком; обёртки в графе нет | обёрткой `private:` по признаку (дамп сегодня её не печатает) |
| `const:`, `immutable:`, `independent:`, `required:` | Frame-обёртка | записью |
| `x := e`, `if:`, `for:`, вызов `f(x)` в данных | Frame с головой | записью |
| `S: merge: A B` | сегодня Frame `S` с одним полем — Frame `merge` со словами `A`, `B` | записью |

Итог по вопросу: `int` восстанавливается из типа места, остальные ресиверы — из собственных записей. Для
`toLmx` не нужно ни второй таблицы, ни признаков: достаточно типа ячейки, таблицы имён и самих Frame.

## `merge` в данных

Поправка того же дня. После этого разбора автор решил: явный путь ничего не исполняет
([журнал](../LMX_blog/2026-11-17.md#path-reads-no-execution), [книга](../docs/LMX_semantics.ru.md#path-reads-no-execution)).
Прежнее чтение исполнителя — «первая явная запись в `S` заменяет запись составленной Structure» (Р44) — снято.
Для записи `S: merge: A B` решение значит:

- запись лежит в графе как написана (правило 2026-11-11) и не меняется ни построением, ни чтением;
- путь `data\S` даёт запись; `data\S\x` — не поле, к операнду ведёт `data\S\merge\A\x`;
- композицию готовит вызов, для которого `S` — корневое объявление его данных, когда обращается к `S` по
  голому имени; это локал вызова, и записи в него в граф не попадают: «Локальное исполнение не публикует кадр и
  не заменяет инициализатор в исходной data»;
- `toLmx` всегда выводит `S: merge: A B`.

Так же устроено вычисляемое место: `int: field f()` по пути — запись объявления, а `f()` исполняет вызов, когда
читает свой локал `field`.

Для пути это совпадает с измеренным сегодня: `S\x` отвечает3, `S\merge\A\x` читает1. Не хватает
другого: вызов ещё не готовит композицию для локала `S`. Заготовка шага ядра, заменявшая запись композицией
при построении графа, отозвана.

## Чего не хватает нынешнему дампу, чтобы стать `toLmx`

Измерено на56 дампах проб и на42 записях по отдельности.

- Весь дамп обратно в построитель не читается ни разу: принтер печатает присваивание как `:=: a 5`, а это не
  запись языка (первая диагностика везде — на строке `:=:`). По отдельности 34 записи из42 дают тот же второй
  дамп.
- Вызов без аргументов `f()` печатается как `(f)`. При обратном чтении это группа со словом, а не вызов:
  `int: a f()` читается как3 (вызов исполнен), напечатанное `int: a (f)` — ответ1. Печать совпала, граф — нет.
- Скобки растут при каждом проходе: `@x` печатается `(@ x)`, затем `((@ x))`; так же `x + own` в `return` и
  объявления внутри `const:` и `independent:`.
- Место, объявленное без значения, после записи значения печатается по-прежнему `int: a`: значение в графе
  есть, в выводе его нет.
- Признак `private:` в графе есть, в выводе его нет.
- Пустые позиции не печатаются, хотя книга требует их сохранять; спецификация ядра называет ещё безымянные
  циклы.
- Комментарии теряются раньше графа: дерево разбора их не содержит, а книга требует выводить текст «с
  сохранёнными комментариями».
- Примитивы, кроме `int`, местами чистого графа ещё не являются (задача M15).

Эти пункты внесены в чек-лист плана как работа над кодеком `toLmx`.
