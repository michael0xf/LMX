# Координация состояния: Message и общая память

[Руководство RU](LMX_Design_Patterns.ru.md) · [Guide EN](LMX_Design_Patterns.en.md)

Все шесть исходных паттернов сохранены отдельно. LMX-альтернатива через Message обеспечивает выбранные наблюдения, но не притворяется shared-memory RW lock, DCL fast path или OS-thread-local storage. Различия параллелизма, affinity и latency указаны по каждому примеру.

## Повторный просмотр с общими ресиверами — 22 ноября 2026

Каждый пример ниже проверен на применение нового прямого API `fun`. Сохранены действующие клиенты: у предложенных замен либо меняется указанный протокол, либо полный клиент с необходимыми объявлениями исходов и адаптерами на одном текущем ядре не становится короче. Это решение относится к данным небольшим сценариям, а не запрет использовать библиотеку в более крупных программах.

| № | Рассмотрены | Причина сохранения |
| --- | --- | --- |
| 065 | `guard, apply` | Последовательные read/write уже обеспечены владельцем ValueMessage. Локальный guard не реализует отдельную блокировку или очередь читателей; apply добавляет упаковку к прямому доступу и не сокращает код. |
| 066 | `lazy, once` | Нужно один раз вызвать build и сохранять значение между Message-turn. Generic lazy требует сохранённый thunk и его начальную установку, а не вычисляемый default, который мог бы создаваться при каждом get. Полный кандидат с этими условиями и throws длиннее; ограничение build нульарной сигнатурой тоже не подразумевается одним вызовом build(). |
| 067 | `lazy, guard` | awaitValue регистрирует requestId до publish и отправляет отложенные ответы после публикации. lazy не ставит запросы в очередь, guard сигнализирует отказ вместо ожидания; прежний цикл waiters и replies.send обязателен. |
| 068 | `once, guard` | start возвращает0 при busy, finish вновь открывает доступ. once не сбрасывается после finish, guard меняет нулевой отказ на исключение. Два перехода состояния уже короче соответствующих адаптеров. |
| 069 | `memoize, once` | Смысл — отдельный count каждого владельца Message и его увеличение при каждом next. memoize/once подавляли бы повторное действие; общий статический счётчик нарушил бы изоляцию. Никакого повторяемого функционального алгоритма здесь нет. |
| 070 | `guard, contract` | withdraw должен возвращать0 без изменения баланса для отрицательной суммы и недостатка средств. guard/contract дадут объявленный отказ и потребуют его преобразовать обратно в0; проверка balance и запись остаются у того же владельца. |
