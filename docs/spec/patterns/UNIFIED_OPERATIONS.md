# Общие операции в примерах и сравнениях

Все приведённые ниже формы используют действующую систему имён, принимающих ролей и контекстов. Парсер уже передаёт ресиверы в Expression; их выполнение и нативная трансляция сохраняют семантику существующего обработчика. Точный идентификатор не разбирается повторно.

Нормативные основания: [равенство и unique](../GENERIC_EQUALITY.md), [общие библиотечные операции](../GENERIC_OPERATIONS.md), [монадические контейнеры](../MONADIC_OPERATIONS.md), [две формы операции](../OPERATION_FORMS.md).

## Короткие клиенты

В сравнительных сценариях сохраняется конкретный предметный профиль контрольного языка. Общая реализация LMX при этом не сужается до типа этого сценария.

| Сценарий | Каноническая запись | Что находится в общей реализации |
| --- | --- | --- |
| Уникальные значения | `unique(items)` или `(unique items)` | Типизированный обход, обычное равенство либо явный comparator, первый представитель и профиль Array |
| Maybe / Result / Array | `some(x) bind half bind half` и `bind(container; next)` | Однократный захват значения, выбор объявленного семейства, связывание без второго алгоритма |
| Построение функции | `compose(outer := second; inner := first)` | Точный вход/выход, общая передача контекста и ошибок |
| Применение стадий | `value pipe first second` | Передача фактической записи между стадиями; тип может меняться |
| Предикаты | `allOf(predicates := (first; second))` | Общая сигнатура, короткое замыкание, сохранение мест и defaults |
| Поиск записи | `findFirst(items; accepts)` | Один проход; местный предикат задаёт только предметное условие |
| Предметное равенство | `equals(a; b; projection := fields)` | Проекция каждого значения один раз и единое отношение равенства |
| Повторение попытки | `retry(operation; retryOn; limit; delay := wait)` | Общий цикл, фактический результат и явная политика; HTTP 503 — отдельный профиль |
| Последовательность Pattern | `literal(prefix) then literal(suffix)` | Один движок над текстовым либо общим последовательностным источником |
| Фактический тип | `type(value)` или `value type` | Существующий запрос фактического кода типа; не восстановление произвольной предметной модели |
| Сигнатура | `` `->`(A; B) `` или `A -> B` | Полные TYPE-токены; последним передаётся результат |

`allOf` получает целую группу через именованный actual `predicates`: её поля не превращаются в дополнительные позиционные аргументы. Группировщик Expression определяет дерево и поток текущего уровня, отдельная подготовка применения формирует один `left` и массив ссылок `right`. Повторного раскрытия готового вектора нет. Обычный выбор W/E остаётся правилом допуска callable; настоящий PLACE, RAW и исходный контекст сохраняются. [Общая архитектура](../EXPRESSION_GROUPING.md).

## Произвольные Arrays

[Полный исходник двух примеров](examples/lmx/unified_operations.lmx) не содержит локальных копий поиска, сравнения или Pattern-движка:

```lmx
GenericUnique:
    []: items
    return: @
    run:
        throws: copy(FxThrows\predicate) SequenceElement SequenceSize
        return: unique(items)

SequencePattern:
    []: items
    []: prefix
    []: suffix
    return: @
    run:
        throws: copy(FxThrows\pattern)
        return: wholeMatch(arrayView(items); literal(prefix) then literal(suffix))
```

В `GenericUnique` обычное скалярное равенство сохраняет свой профиль, а конечные ациклические вложенные последовательности сравниваются через общий диапазонный проход. Имена полей и лексический родитель Structure не входят в физическое упорядоченное равенство. Для другой предметной эквивалентности передаётся `same`.

В `SequencePattern` каждый элемент входного Array остаётся целой типизированной единицей. `literal(prefix)` и `literal(suffix)` задают блоки единиц. Текстовый источник задаётся отдельно через `utf8Text` или `byteText`; он сохраняет декодирование и отображение координат в исходные байты. Конструктор `element(x)` соответствует одному целому элементу, включая вложенный Array.

Пустая последовательность, отсутствие Maybe и успешное совпадение нулевой длины различаются. Один общий движок сохраняет порядок ветвей и кандидатов, captures, защиту повторения без продвижения и прозрачность исходных callback-ошибок.

## Имена и символические формы

`print` и `` `print` `` имеют одну идентичность. Существующий `@` остаётся ресивером; `` `@name` `` означает одно непрозрачное имя. Флаг кавычек не выбирает иной алгоритм.

| Применение | Ресиверная форма | Результат |
| --- | --- | --- |
| `++x` | `` `++var`(x) `` | Новое сохранённое значение |
| `x++` | `` `var++`(x) `` | Прежнее значение |
| `--x` | `` `--var`(x) `` | Новое сохранённое значение |
| `x--` | `` `var--`(x) `` | Прежнее значение |

`var` — одна позиция аргумента в имени шаблона. Имя реальной переменной не создаёт отдельную операцию. Сложная цель вроде `items[next()]` определяется один раз. Для программно созданного графа исходные текстовые spans не обязательны.

## Проверка и подсчёт

Обновлённые исходники, публикационные копии и JSON должны совпадать. Иностранные исходники сохраняют свои публичные имена, например Scala `flatMap` и Haskell `intercalate`; миграция имён LMX к ним не применяется.

Список `throws` остаётся полным. По мнению автора, конечные списки и `throws: copy(Throws)` — преимущество: у узла явно видны возможные ошибки. Для сравнений Haskell/Scala/Julia/SBCL/Perl публикуются процедурная и функциональная LMX-записи одного договора. Обе считаются по полному тексту, включая все объявления и весь Throws. Нормализующей колонки нет. В PDF/XLSX зелёный фон и подчёркивание числа получают все равные минимумы сопоставимых полных записей. Если низкоуровневый договор требует одинаковой минимальной формы, она хранится и публикуется один раз, а оба стилевых столбца имеют равный размер.

При переносе меняется исходный код и нормативный договор. Сохранённые подтверждения прежних parser-проверок относятся к прежним байтам. Изменённым примерам новый parser/runtime pass не приписывается. [Подготовленные сценарии](validation/unified_operations_cases.json) имеют статус **NOT_RUN**.

## Типизированные ссылки и массивы

Тип и его постфикс находятся слева от двоеточия: `Model@: p`, `int@: left`, `FxMaybe@: input`, `int[]: items`. Записи с префиксом `@Type` или `[]Type`, а также прежние объявления `@: name int`/`@: int name` не используются. Обычная ссылка `@: value expression` остаётся допустимым объявлением generic-reference; это не старая запись типизированного указателя.
