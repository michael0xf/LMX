# Редакция: размеры Array и прямые ссылки на типы

Исторический отчёт от 26 ноября. Исходный список ниже фиксирует написания и проверки той редакции. В действующем языке размеры стоят перед типом (`[N]T`), `[](E)T` принимает число осей или вектор размеров, а совместимость структурного инициализатора проверяется по доступной форме. При `capacity = length` отсутствует запись о резерве; View может иметь собственный контекст в parent. [Формы TYPE](TYPE_DECLARATION_FORMS.md#extent-vector-prefix) · [Инициализатор](ARRAY_STORAGE.ru.md#shape-inference) · [Хранение](ARRAY_STORAGE.ru.md#parent-context).

## Изменения в выпущенной редакции

- В TYPE добавлены размеры осей `T[N]`, смешанные `T[][N]` и полные
  `T[2][5]`, с общим P0-разбором выражений внутри каждого суффикса.
- В `{type value}` type является прямой TypeRef на каноническую системную
  Structure любого типа. Числовой счётчик и lookup по int-коду отменены.
- Канонизация зависит только от полного нормализованного конструирующего
  требования. `int[][]` и `int[](2)` — один тип; `int[2][3]` и `int[3][2]`
  различны. Инициализатор, length и reserve тип не уточняют.
- Строки инициализатора проверяют прямоугольность и уплощаются; неизвестные
  размеры не сохраняются в скрытой записи. Само хранение `int[][]` с
  неопределёнными осями допустимо. Диагностика возникает у нуждающегося в них
  потребителя.
- При capacity=length второго дескриптора Array нет. Реальный резерв хранится
  необязательной ассоциацией экземпляра, не меняя TypeRef.
- `sys\descriptor(typeof(obj))` возвращает само системное описание типа.
  Для канонического TYPE эта ветвь имеет приоритет; обычный Array/Structure
  сохраняет три живых адреса полей Lmx.
- Нормы sizeof, выравнивания, uninit, dense backing, времени жизни, attach,
  сериализации и native ABI согласованы с адресным префиксом.
- Результат с фиксированными осями конструируется сразу под полным типом;
  прежний empty+resize helper не заменяет эту подготовку.

Подробное пояснение: [Представление TypeRef](TYPE_REFERENCES.md#type-reference).
Порядок применения, точные формы автора, ошибки, миграция исходников и
проверки общего P0: [Миграция типов и потребителей ABI](../../projects/kernel-runtime.md#type-layout).

## Область изменения

Исправлены обе языковые редакции L1, L2, grammar, semantics, semantic guide,
kernel implementation и общих типов, а также главы Array, операций и
библиотечных интерфейсов. Нужные главы полного исходного архива включены,
даже если они не входили в предыдущий патч.

Изолированные LMX/C-прототипы прежнего ABI сохранены и явно помечены как
требующие миграции. Это позволяет отличить новую норму от существования её
производственной реализации. Прежние фикстуры, ожидавшие конкретные оси от
одного `int[][]`, также отмечены в соответствующих README.

Изменены только два Python-генератора документации: сохранение редактируемого
предисловия Array-expression README и отметка прежних assignment fixtures.
Эталонные семантические алгоритмы и сравниваемые исходники не менялись.
