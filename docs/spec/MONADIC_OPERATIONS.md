# Монадические операции и адаптивные конструкторы значений

Нормативная пользовательская запись — `return: some(x) bind half bind half`. Упаковка полной записи значения и связывание принадлежат общей библиотеке LMX; типы, контракты и конечные `throws` принадлежат настоящим узлам.

Инфиксные операторы через `OPERANDS_TEMPLATE`, гомоиконность, адаптивная типизация и доступный контекст преобразований актора — существующие средства языка. Конкретное подключение новых библиотечных входов проверяется отдельно; исполнение LMX в этом пакете — **NOT_RUN**.

Обе формы монадической операции называются `bind`. Pattern-композиция называется `then` и описана в [общих операциях](GENERIC_OPERATIONS.md). Правила ролей, канонических имён и трансляции заданы в [формах операций](OPERATION_FORMS.md).

## 1. Пользовательский результат

Основная запись скрывает служебную упаковку внутри конструктора и использует операндное связывание:

```lmx
return: some(x) bind half bind half
```

`bind` связывает результат предыдущего шага со следующим методом; `some(x)` сохраняет фактический тип `x`. Пользователь не обязан писать `record`, служебную сигнатуру, фабрику типизированного адаптера или промежуточные контейнеры. Явные `throws`, требования входа и описание результата остаются у соответствующих узлов.

Обобщённость относится к библиотеке: полезным значением может быть число любого допустимого типа, строка, массив, Structure, ссылка, вызываемая операция или другое значение, допускаемое обычными контрактами LMX. Индексы, флаги присутствия и результаты предикатов по-прежнему могут иметь тип `int`.

| Pattern-операнд `then` | [regex/operands.lmx](patterns/LMX_Fn_Receivers/src/regex/operands.lmx) | Сохранить его значение; обобщение источников — в разделе общих операций. |

| Контекст преобразований | [контекст Message](LMX_semantics.en.md#conversion-context) | Подключить адаптивный вход публичных конструкторов к доступному контексту актора. |

Это библиотечный механизм. Новое ключевое слово, специальный парсер монад или отдельная машина исполнения не нужны. Исходный граф, динамическое связывание, `copy`/`merge`, обычное принятие аргументов и текущий Message остаются действующими механизмами.

Историческая основа — исходные редакции 22-Nov-2026 и 23-Nov-2026 до унификации. В обеих были обычные `bind` и прежний отдельный Result-вход; старый альтернативный пример 091 содержал инфиксный `MaybeOps\bind` над `MaybeValue` с полезным значением `int`. В текущем ядре обе формы и все семейства имеют каноническое имя `bind`, а полезное значение сохраняет свой фактический тип. `then` остаётся операцией Pattern.

## 3. Один адаптер значения для всех конструкторов

### 3.1. Контракт

Адаптер строит обычную функцию с точным входом `T`. При исполнении она получает уже принятое значение, сохраняет его полную запись и при необходимости передаёт эту запись выбранному конструктору.

Режимы:

| Построение | Полученный callable |
| --- | --- |
| `FxRecordAdapter\make(T)` | Принимает одно значение `T`, возвращает ссылку на его типизированную запись. |
| `FxRecordAdapter\make(T; FxSome\some)` | Принимает одно значение `T`, возвращает Some с этим значением. |
| `FxRecordAdapter\make(T; FxOk\ok)` | Принимает одно значение `T`, возвращает успешный Result. |
| `FxRecordAdapter\make(T; FxErr\err)` | Принимает одну причину типа `T`, возвращает ошибочный Result. |

`T` включает полное фактическое требование: квалификации, форму массива и ссылки. Он не заменяется на `int` или общий физический код Structure. Захват исполняется ровно один раз, включая `T = @`: `some(null)` означает присутствующее ссылочное значение, а не отсутствие Maybe.

### 3.2. Полный код общего построителя

Общий адаптер находится рядом с `FxCaptureOne` в [generic_functions.lmx](patterns/LMX_Fn_Receivers/src/generic_functions.lmx). У конструктора ровно одна позиция для готовой записи. Адаптер вызывает её позиционно, поэтому настоящее имя `value` у `FxSome\some` или `reason` у `FxErr\err` не меняет передачу значения и не требует псевдонима.

```lmx
FxRecordConstructor :: (@: value; return: @)

FxRecordAdapterState:
    @: record 0
    FxRecordConstructor@: constructor

FxRecordAdapter:
    private:
        @: typeToken
        FxRecordConstructor@: constructor 0
    required: typeToken
    return: @
    make:
        throws: copy(FxThrows\selection)
        private: @: inputType FxKernel\normalizeType(typeToken)
        private: @: noResult FxKernel\normalizeType(void)
        private: @: inputs FxKernel\signatureData(
            FxOne\make(inputType);
            noResult;
            FxLabels\labels(1)
        )
        private: @: state (copy(FxRecordAdapterState))
        state\record := FxRecordOperands\record
        private: @: resultType FxKernel\normalizeType(FxTypeTokens\reference[0])
        private: @: failures FxCaptureFailures\names()
        private: char[]: body "return: (p0 node\\private\\state\\record)\n"
        if: constructor != 0
            state\constructor := constructor
            private: @: shape FxKernel\signature(constructor)
            resultType := shape\resultType
            failures := FxFailures\union(failures; shape\throws)
            body := "return: node\\private\\state\\constructor((p0 node\\private\\state\\record))\n"
        private: @: outputs FxKernel\signatureData((); resultType; ())
        Captured :: (
            private: copy(inputs)
            required: p0
            copy(outputs)
        )
        return: FxBuild\make(Captured; body; state; failures)

FxCaptureOne:
    private:
        @: requirement
        @: sourceRecord
    return: @
    capture:
        throws: copy(FxThrows\selection) FxRecordArity
        private: @: receiver FxRecordAdapter\make(requirement)
        return: receiver(p0 := \sourceRecord)
```

Это замена построения внутри `FxCaptureOne`, а не второе тело того же алгоритма. В новой версии нужно оставить одну реализацию каждого определения.

Используемые помощники — существующие `FxOne`, `FxLabels`, `FxCaptureFailures`, `FxFailures` и `FxBuild`. Строка тела разбирается существующим `sys\fromLmx` внутри `FxBuild`; строится обычный граф функции. Повторного вычисления пользовательского выражения, скрытой компиляции или заимствования адреса завершившегося native-кадра здесь нет. Правила хранения и времени жизни записи остаются правилами [типизированных значений](L2_spec_en.md#value-record) и [prepared operand storage](LMX_semantics.en.md#operand-storage).

`required: p0` находится в настоящем DATA полученной функции. Поэтому отсутствие аргумента отвергается; переданные `0`, пустая строка, пустая Structure и нулевая ссылка остаются полноценными переданными значениями. Служебное `state` принадлежит построенному владельцу и не становится вторым пользовательским параметром.

При подключённом конструкторе выход берётся из его действительного `shape\resultType`. Поэтому адаптер `some` сохраняет `FxMaybe@`, а адаптеры `ok`/`err` — `FxResult@`; они не стираются до общего `@`. Только режим отдельного захвата возвращает обычную ссылку на запись.

### 3.3. Подключение к публичным `some`, `ok`, `err`

В явно доступном контексте актора задать соответствие:

| Публичный конструктор значения | Цель адаптера |
| --- | --- |
| `some` | `FxSome\some` |
| `ok` | `FxOk\ok` |
| `err` | `FxErr\err` |
| `done` | `FxDone\done` |

Для публичного вызова контекст получает один логический аргумент, выбирает его полный фактический `T` и обычный конструктор `FxRecordAdapter\make(T; target)`. Подготовленное значение передаётся в полученный узел как `p0 := readyValue`. Это именованное внутреннее связывание не открывает контейнер повторно.

**Подключение этой таблицы к существующему адаптивному входу актора — обязательная часть реализации.** Одна фабрика без подключения не обеспечивает написание `some(x)`. Пользователь не должен выбирать `T`, вызывать фабрику или отдельно импортировать конструктор для каждой разновидности значения. Конкретный путь до контекста следует взять из текущей реализации; в доступной редакции его устройство описано семантически, без единого фиксированного имени поля. Новое глобальное хранилище конвертеров не вводится.

Публичный вход конструктора потребляет одно значение целиком: строку, массив, анонимную Structure с одним или многими полями, либо результат функции. Он не пытается отдельно подобрать ещё один конструктор по раскрытым полям. Это контракт данного конструктора, не изменение общих правил W/E для всех вызовов языка. Исходное выражение вычисляется один раз обычным путём; чтение типа и выбор маршрута не исполняют его повторно.

Преобразование включается для роли аргумента конструктора значения. Нельзя объявить общее правило «каждый `@` автоматически упаковать» или угадать готовую запись по адресу. Иначе будут потеряны различия между значением-ссылкой, ссылкой на запись значения и прямой передачей уже подготовленной записи.

### 3.4. Совместимость внутренних вызовов

Существующие внутренние операции `FxSome\some(value := recordRef)`, `FxOk\ok(value := recordRef)` и `FxErr\err(reason := recordRef)` сохраняют контракт приёма готовой записи. Их тела не получают повторный `record`.

Публичные примеры с прежней ручной упаковкой мигрируют явно: `some(value := (x record))` становится `some(x)`. Если код действительно передаёт уже готовую запись по внутреннему протоколу, он использует соответствующий внутренний конструктор. Автоматически различать эти два намерения по содержимому указателя нельзя.

## 4. Единое имя `bind`: вызов и операнд

### 4.1. Существующие алгоритмы и точные результаты

Обычные варианты — `FxBind\bind` для Maybe и `FxBindResult\bind` для Result. Они сохраняют свои единственные алгоритмы и точные требования результата:

| Определения в `containers.lmx` | Требование результата |
| --- | --- |
| `FxSome`, `FxNone`, `FxBind` | `return: FxMaybe@` |
| `FxOk`, `FxErr`, `FxBindResult` | `return: FxResult@` |

При приёме типизированной записи результата `FxApply` в этих двух bind-телах использовать соответственно `private: FxMaybe@: result \record` и `private: FxResult@: result \record`. Это одна обычная загрузка настоящего результата `R`: для ссылочного `R` получается ссылочное значение, для структурного `R` — целая Structure, принимаемая по её дескриптору. Ни рекурсивного раскрытия, ни нового `unwrap` не требуется. Такой же приём применён в существующем [FxWrap](patterns/LMX_Fn_Receivers/src/generic_runtime.lmx), формирующем `return: \fx_answer` для точного результата.

### 4.2. Полный код операторных форм

Ниже один общий проход по продолжениям и типизированные объявления с одинаковым именем `bind`. Они переиспользуют прежние тела связывания.

```lmx
FxMaybeActive:
    private: FxMaybe@: input
    required: input
    return: int
    active:
        return: input\present

FxResultActive:
    private: FxResult@: input
    required: input
    return: int
    active:
        return: input\ok

FxBindChain:
    private:
        @: current
        @[]: steps
        @: step
        @: active
    required: current steps step active
    return: @
    run:
        throws: copy(FxThrows\call) FxArity
        if: length(steps) = 0
            throw: FxArity()
        private: int: i 0
        while: i < length(steps)
            if: active(input := current) = 0
                return: current
            current := step(input := current; next := \steps[i])
            i += 1
        return: current

FxBindOperandTail:
    private: @[]: right
    required: right
    const: int: PASS_ARGS_AS_IS 0
    const: int: PRIORITY sys\priority("+")

FxMaybeBindOperand:
    private: FxMaybe@@: left
    copy: FxBindOperandTail
    required: left
    return: FxMaybe@
    bind:
        throws: copy(FxThrows\call) FxArity
        return: FxBindChain\run(\left; right; FxBind\bind; FxMaybeActive\active)

FxResultBindOperand:
    private: FxResult@@: left
    copy: FxBindOperandTail
    required: left
    return: FxResult@
    bind:
        throws: copy(FxThrows\call) FxArity
        return: FxBindChain\run(\left; right; FxBindResult\bind; FxResultActive\active)

MonadBindings:
    import: FxBind FxBindResult FxMaybeBindOperand FxResultBindOperand
```

Каждый итоговый DATA соответствует существующему `OPERANDS_TEMPLATE`. Общий хвост хранит `right`, режим и приоритет один раз. Не следует поверх полного `copy: FxPreparedOperands` добавлять второй `left` другого типа: повторное объявление поля не является заменой первого.

Публичный одиночный alias `bind` заменить публикацией семейства настоящих объявлений. `import` сохраняет настоящие DATA и `parent` методов. Два одинаковых универсальных `const: @: bind …` не являются реализацией такого семейства. Старое `bindResult` удаляется из кода; в Result и Maybe используется `bind`.

### 4.3. Различение форм по аргументам

| Форма | Вход выбранного объявления |
| --- | --- |
| `bind(m; f)` для Maybe | `FxMaybe@: input`, обычный `next`. |
| `m bind f` для Maybe | `FxMaybe@@: left`, подготовленный вектор `right`. |
| `bind(r; f)` для Result | `FxResult@: input`, обычный `next`. |
| `r bind f` для Result | `FxResult@@: left`, подготовленный вектор `right`. |

`@@` здесь относится к настоящему ссылочному значению: ссылка на подготовленную запись значения `FxMaybe@` имеет уровень `FxMaybe@@`; одна загрузка `\left` возвращает исходную ссылку. Это не новая обязательная упаковка произвольной Structure. Настоящий Array/Structure-valued результат сохраняет собственный дескриптор и не получает выдуманный дополнительный уровень. Основание — [хранение операндов](LMX_semantics.en.md#operand-storage) и [варианты записи значения](L2_spec_en.md#value-record).

Сохранение истинного `R` обязательно проверить на интерпретируемом и native-путях. Нельзя одновременно стирать ссылочный результат до дескриптора и рассчитывать на различение перегрузок по глубине ссылки.

У конструктора и промежуточного `bind` сохраняется модельное требование результата. Это необходимо для цепочки `some(x) bind f bind g`. Если значение допускает несколько конкурирующих моделей, действует обычная ошибка неоднозначности [выбора объявления](LMX_semantics.en.md#declaration-selection), без пробного вызова и без ручного диспетчера по `sys\typeof`.

При добавлении общего Array-семейства этих различий уже недостаточно: Maybe является Structure, а Structure допускается как Array. Поэтому общий публичный `bind` должен подключить контракт двух представлений и семантических семейств из раздела 3 раздела общих операций. Код `import` выше сохраняет объявления, но сам по себе не доказывает однозначность всех их объединений. Требуется явное подключение контекста; скрытого предпочтения «обычный вызов раньше операнда» или «самая узкая Structure» нет.

Приведённые объявления поддерживают `m bind f`, цепочку `m bind f bind g` и хвост `m bind f g`. Их левый вход обязателен. Они не объявляют автоматически ещё и `(bind m f)` с отсутствующим `left`: обычная префиксная форма уже есть — `bind(m; f)`. Если нужен также левопустой операндный вариант, он получает отдельное однозначное описание входов в рамках общего механизма; оно не считается реализованным этим кодом.

### 4.4. Остановка и порядок эффектов

После None/Err общий проход возвращает тот же терминальный контейнер до чтения следующего продолжения из `steps`. Сохраняются причина ошибки, фактические типы и идентичность ссылок. Some(0), Some(null) и Some(пустой массив) остаются присутствующими значениями.

Голое имя `half` — ссылка, а не вызов. Тело продолжения запускает существующий `bind`. Написанная справа фабрика `makeHalf()` остаётся вычисляемым аргументом prepared-режима 0: её подготовка и пропуск вызова уже полученного продолжения — разные события. Режим raw для обычной монадической цепочки не вводится.

`FxBindChain` вызывает выбранный `step` напрямую. Он не оборачивает сам `bind` ещё одним `FxApply`, поэтому не добавляет лишний уровень `FxCallFailure`. Семейство Maybe/Result задаётся выбранным типизированным объявлением, а результат каждого шага проходит его обычный контракт.

### 4.5. Array: то же имя, прежний алгоритм

Последовательностный вход — `FxListBind\bind` с внутренним общим алгоритмом `FxSeqBind\bind`. Его обход и соединение не дублируются.

Обычный Array-вход возвращает фактический `@[]` существующего алгоритма. Это целая последовательность значений; вложенные Arrays не раскрываются глубже одного уровня связывания.

```lmx
FxListBind:
    private:
        []: input
        @: next
    required: input next
    return: @[]
    bind:
        throws: copy(FxThrows\traversal)
        private: @: result FxSeqBind\bind(items := input; next := next)
        return: \result

ArrayBinding:
    const: @: bind FxAsOperand\asOperand(FxListBind\bind; sys\priority("+"))
```

`FxSeqBind\bind` получает `items` и `next`; делегирование явно сохраняет это позиционное соответствие. `FxListBind` предоставляет один публичный последовательностный контракт и использует единственный алгоритм обхода.

`ArrayBinding` показывает отдельное операндное представление с настоящим владельцем и точным результатом. После подключения общей публикации доступны `bind(xs; f)` и `xs bind f` в выбранном последовательностном контракте. Квалифицированное `xs ArrayBinding\bind f` пригодно для проверки конкретного представления; оно не заменяет требование завершить общий публичный вход.

Нельзя при пустом Array возвращать исходный плотный контейнер вместо установленного нового `@[]` результата. Остановка None/Err и пустая последовательность имеют разные договоры, поэтому Array не пропускается через `FxMaybeActive`.

## 6. Исключения и контракты узлов

У построителя адаптера и созданного callable разные исходы. Построитель объявляет `FxThrows\selection`. Созданное тело объявляет `FxRecordArity` и реальные `throws` выбранного конструктора; `FxKernel\signature` должен читать фактическую операцию. `FxBuild` формирует эти объявления в обычном узле, сохраняя их в графе.

Если контекст актора строит адаптер при первом динамическом использовании, ошибки построения остаются частью этой достигнутой операции. При предварительном построении они относятся к подготовке, а выполнение готового callable имеет собственный список. Этот выбор должен быть явно отражён в опубликованном контракте; ошибки нельзя скрывать за короткой записью конструктора.

Монадический `bind` сохраняет существующий контракт `bind`: ошибка пользовательского callback идёт через `FxCallFailure` с исходным именем и payload. Этот путь виден в `throws`; он не преобразуется в `none()` или `err(...)`. Явный `attempt` остаётся отдельной библиотечной операцией.

Если проект требует прозрачного проброса исходных имён для специализированного построенного узла, его конечное множество `throws` формируется из реальных сигнатур и используется существующий `attempt/raise` путь. Нельзя просто написать неограниченный «любой throw», удалить декларацию ради краткости или вручную сравнивать имя исключения посимвольно.

Гомоиконность позволяет построить правильный обычный узел с его DATA, CODE и `throws`. Она не отменяет правила допуска типов и не означает, что код можно исполнить во время выбора подходящей сигнатуры.

<a id="7-полный-пользовательский-пример"></a>
## 7. Полный пользовательский пример

В этом примере адаптер `some` для фактического входного типа уже подготовлен контекстом актора. Ошибки построения `FxThrows\selection` относятся к этой подготовке; готовый конструктор объявляет `FxRecordArity`. Если реализация строит адаптер при первом вызове, его ошибки построения нужно также включить в контракт достигнутого вызова, как указано в разделе 6.

```lmx
Example:
    int: x
    return: FxMaybe@
    half:
        throws: FxRecordArity
        if: x % 2 = 0
            return: some(x / 2)
        return: none()
    run:
        throws:
            FxRecordArity
            FxCallFailure
            FxKernelFailure
            FxTypeToken
            FxArity
        return: some(x) bind half bind half
```

В этом конкретном примере чётность — задача над целыми числами, поэтому его `x` имеет тип `int`. Ограничение не переносится на конструкторы, контейнеры, `bind`. Например, `some(text)` и `ok(rows)` используют тот же адаптивный вход и сохраняют типы строки и массива.

Для входов `8`, `6`, `3`, `0` ожидаются соответственно Some(2), None, None, Some(0). В случае `3` ни одно продолжение после получения None не вызывается; при `6` выполняется два шага, и второй возвращает None. Счётчики вызовов должны проверять именно эти наблюдения.

Полный `throws` в примере намеренно сохранён. Считаю явное перечисление возможных отказов преимуществом языка. Повторяемые списки можно объединять через `Throws` и `throws: copy(Throws)`, не скрывая их состав.

## 8. Интеграция и приёмка

1. Выделить общий `FxRecordAdapter`, заменить построение внутри `FxCaptureOne` делегированием и подключить публичные конструкторы к существующему контексту актора.
2. Убедиться, что `some(x)`, `ok(x)` и `err(x)` действительно работают без подготовки со стороны пользователя. Код одной фабрики без этого входа не считать завершённой реализацией.
3. Опубликовать обычные и операндные объявления `bind` под одним именем, включая Array, с общей проверкой неоднозначности. Удалить прежние callable-имена `bindResult` и `flatMap` и обновить все ссылки. Pattern-операцию `then` обобщить отдельно по разделу общих операций.
4. Удалить ручную упаковку из основных примеров, включая [082_monad.lm3](patterns/09_functional_computation/examples/lmx/082_monad.lm3), и обновить документацию. Вспомогательную обвязку учитывать в реализации библиотеки, а не дублировать в клиентах.
5. Выполнить проверки ниже во всех предусмотренных сочетаниях I→I, I→N, N→I, N→N. До исполнения сохранять статус **NOT_RUN**.

| Группа | Обязательные наблюдения |
| --- | --- |
| Типы | Целые разных типов, дробные значения, строки, плотные и ссылочные массивы, Structure, ссылка на метод; фактический тип полезного значения сохранён. |
| Присутствие | Some(0), Some(null), Some(пустая строка), Some(пустой массив) отличаются от None; `some()` отвергается. |
| Один аргумент | Одно- и многопольная Structure сохраняется целиком; результат функции не раскрывается; аргумент с эффектом вычисляется один раз. |
| Ссылки | Сохраняется цель ссылочного значения; нет двойной упаковки готовой записи во внутреннем API и нет висячей ссылки на native-кадр. |
| Цепочка | Левый порядок, правильное число вызовов, остановка на None/Err, сохранение первого терминального контейнера. |
| Контракты | Продолжение получает фактический payload; несовместимый аргумент или результат другого семейства отвергается обычным принятием. |
| Динамическое связывание | Свободные имена продолжения доступны через действующую цепочку вызовов; библиотечные `private`-поля не захватывают пользовательские имена. |
| Ошибки | Callback-ошибка не становится None/Err; исходное имя и payload не теряются; декларации адаптера и построенного узла соответствуют действительным путям. |
| Операнд | Одинаковый результат для цепочки и допустимых форм общего `left/right`; свойства режима и приоритета готовы до вычисления аргументов. |
| Перегрузки | Обе формы `bind` выбирают одно объявление в явном семантическом семействе; реальные пересечения Maybe/Result/Array дают обычную неоднозначность. Старые callable-имена отсутствуют. `then` не получает монадической ветви. |
| Стандартные законы | На допустимых чистых продолжениях проверены левая и правая единица и ассоциативность по наблюдаемому содержимому контейнера. Упаковка исключений рассматривается отдельно по объявленному контракту. |

Реализацию не считать завершённой по одному успешному сравнению длины исходников. Требуются исполнение короткого пользовательского примера, отрицательные проверки контрактов и проверка исходного графа созданных узлов. Клиентские публикации используют эти же канонические входы и полный контракт.
