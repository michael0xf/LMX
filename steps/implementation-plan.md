# Общий план Codex и Grok

Актуальное поручение автора от 2026-09-20. Этот файл — единый план дальнейшей работы; отчёты о выполненных исследованиях остаются отдельными.

## Принятое устройство

Единственный механизм допуска кандидатов: аналитический `implements` по используемым именованным путям дерева принимающего выражения, затем выполнение его юнит-тестов интерпретатором графа. Иного самостоятельного механизма семантической валидации не вводить. Позиционный `lmx_runtime_implements` признан автором невалидным и подлежит полной замене. Классификация адресов по таблице арены — инфраструктура типов, которую эта замена должна сохранить.

Нормативное описание: [допуск L3](../docs/LMX_semantics.ru.md#admission). Исследование старого кода и мест использования: [отчёт Codex](l3-semantics.md). Перенос исходников и L1/L2: [отчёт Grok](l1-l2-migration.md).

Уточнение автора об индексах: L2 получает адрес настоящего элемента графового массива и работает с ним по машинному контракту C. `@array[i]` корректно; брать адрес рабочей копии нельзя. В L2 не должно быть проверок индекса или дескриптора при таком доступе. Проверяемый доступ — только L3. Чтение `desc.data` для получения backing не является проверкой дескриптора. Это заменяет прежнюю норму о проверяемом Array в обоих уровнях.

## Этапы и критерии завершения

Последовательность реализации: аналитический `implements` по дереву → **интерпретатор уже построенного графа** → валидация юнит-тестами через этот интерпретатор. Интерпретация исходного текста не является промежуточным этапом. Парсер строит граф; интерпретатор исполняет его структуры и связи.

## Координация

- Codex редактирует норму L3, согласует параграфы допуска в L1/L2 и фиксирует решения автора. Grok ведёт реализацию после принятия назначения, собственные тесты и состояние переноса.
- Обновлять статус этапа только по фактическому результату. Перед редактированием одних файлов согласовать владение через существующие каналы из [work_chat](../work_chat/README.md).
- Не перезаписывать чужой индекс Git или незакоммиченные изменения. Коммитить свои точные пути; после проверки документации делать push.
- По поручению автора включён периодический контроль сохранения документов и исходников: каждые 30 минут в текущей задаче (автоматизация `lmx-git`). Готовые партии проверять, коммитить точными путями и отправлять обычным push в существующий upstream; незавершённые параллельные правки сначала согласовывать с владельцем. Секреты, локальные истории, сборки, блокировки и резервные файлы не публиковать. Конфликты и провалы проверок докладывать, не обходить force-push или изменением чужого кода. При неизменном состоянии повторных сообщений не делать.
- При противоречии модели и кода фиксировать факт и задавать автору конкретный вопрос. Ограничения исторической реализации не превращать в требования языка.
- По новому поручению автора обо всех исправлениях докладывать существующему Grok CLI. Для каждой партии фиксировать здесь норму, затронутые файлы, необходимость реализации, код сообщения и фактическое подтверждение. Запись в плане сама по себе не считается доставкой.
- Grok уже работает в [dev](../dev/README.md), по сообщению автора. Разработку вести там; корневые `l1src/` и `l2src/` сохраняют роль стабильного снимка. Codex не редактирует параллельно код Grok и не переносит его незавершённые изменения в корень.

### Проверки этапа 9

- Положительные L2-примеры: переменный индекс; чтение и запись элемента; типизированный адрес `@array[i]`; изменение через этот адрес видно через обычный доступ к тому же элементу; адрес не относится к временной копии.
- В результирующем понижении нет вставленной проверки bounds/дескриптора. Допустимость синтаксиса и типов индекса не равна проверке его границ.
- Старые отрицательные тесты нельзя механически перевести в положительные: например, `address_array_element.lm2` возвращает указатель из функции с результатом `int`; новый положительный пример должен иметь корректный тип результата.
- L3: проверка индекса/дескриптора остаётся в высокоуровневой операции. Пока эта операция не реализована, не объявлять перенос завершённым только по удалению проверки из L2.
- Проверки выделения памяти, размеров выделения и внутренних служебных таблиц не удалять вслепую под видом исправления индексирования пользовательского массива; отличать их от проверок доступа к элементу.
