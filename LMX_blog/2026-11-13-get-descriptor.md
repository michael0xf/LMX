<a id="header-receivers"></a>
## Ресиверы чтения заголовка и имена length/storage

Техническая выдержка из предложения автора:

```text
1) делаем ресиверы а не псевдо-поля потому что ресивер выполняется только в code и тогда объявление в data такого же поля будет обрабатываться по общим правилам для всяких ресиверов которые не объявления (data\for допустим при одном for)

В двух вариантах: с одним аргументом и без аругмента:

parent

length (переименуйте в length поле size в Lmx)

container (придумай как назвать и тоже перименуй из data в Lmx потому что data занято парой data-code)

2. Вот эти поля остаются полями при выполнении потому что это аргументы-структуры call:

data

code

3. Вопрос что делать c node. Можем ли мы дешево вычислить node(любой структуры) или эта информация доступна только изнутри во время выполнения?
```

Исполнитель предложил имя `storage` и сохранение действующего контракта `node`.
На вопрос о выборе `data` либо `code` для ресиверов без аргумента автор ответил:

```text
С текущей data
```

Окончательное уточнение автора, техническая выдержка:

```text
Без аргумента — от текущей data. storage подходит, node оставляем как есть.
```

Следствия, сформулированные исполнителем: заголовок теперь `parent/native/length/storage`;
`parent()`, `length()`, `storage()` равнозначны явному аргументу текущей `data`.
Ресиверы читают значения, а согласованный ранее `getDescriptor` даёт адреса полей для записи.
Переименование относится также к полям его результата. `node(S)` не вводится.
Прежние цитаты с `size` и `data` выше сохранены дословно как история решения.

<a id="native-receiver"></a>
## Включение native в ту же группу

Следующее техническое уточнение автора:

```text
к группе `parent`, `length`, `storage`  давай ещё добавим native ресивер
```

Следствие общего правила, сформулированное исполнителем: группа состоит из parent/native/length/storage.
`native(S)` читает значение S.native, `native()` — то же, что `native(data)` от текущих данных запуска.
Это значение нативного входа (либо 0), без его вызова; адрес ячейки по-прежнему даёт getDescriptor.

<a id="receiver-names"></a>
## Имена ресиверов без get

Техническая выдержка из сообщения автора:

```text
давай переименуем все ресиверы get\<Name> во что-то более подходящее для ресиверов. "getName" обычно используется в коде. Найди какие-нибудь аналоги в других языках.
```

Исполнитель выбрал имя `descriptor` вместо `getDescriptor` по общему стилю parent/native/length/storage.
Это выбор названия в рамках поручения, не новая дословная формулировка автора. Типы возвращаемых адресов
и способ записи не меняются. `getType` уже ранее переименован в `typeof`; getPixel/getValue/getTypedValue
в текущих документах — имена прикладных функций в примерах, не встроенные ресиверы.
Сопоставление с именами Rust, Julia и Python и ссылки на их документацию приведены в ТЗ.
Прежние цитаты и обсуждение getDescriptor выше сохранены дословно как история.

<a id="descriptor-current-data"></a>
## descriptor с аргументом и без

Техническая выдержка из следующего сообщения автора:

```text
descriptor тоже давай в двух вариантах: с аргументом и без, без аргумента — от текущей data.
```

Следствие: `descriptor()` равнозначен `descriptor(data)` от текущих данных запуска;
явный аргумент выбирает другую Structure. Оба варианта возвращают адреса настоящих полей.
