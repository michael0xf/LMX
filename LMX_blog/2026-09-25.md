Источник: вопрос автора в чате fable 2026-09-25 (merge методов и сигнатур как частичное применение), дословно:

```text
По поводу исполнения именованных структур и одобренного плана широкого мержа в том числе методов и сигнатур:
haskell:
 add :: Int -> Int -> Int
 add x y = x + y
 add5 = add 5

возможно ли на LMX сделать так:

fn: add (int: x; int y)
 . return: x + y fn:
fn: add5 (int: x) int merge(y: 5; add) #сигнатура add пропадёт

И обратное:

 fn: add5 (int: x)
 . return: x + 5
 add: merge(add5, fn: add (int: y) int (return: x + y)) 

?
```

Ответ координатора (чтение по принятым правилам Q21 = А + «merge методов = интерпретируемый результат»): прямое — да: `fn: add5 (int: x) int merge(add; y: 5)` — модель `add` (первый операнд), `y: 5` переопределяет слот формала `y` значением (формал становится связанным полем), объявленная снаружи сигнатура `(int: x) int` — заголовок результата (сигнатура `add` пропадает), `x` тела `add` разрешается транслятором в формал `x` результата; результат интерпретируется (дескриптор без нативного адреса). Порядок операндов существенен: модель — первая, `merge(y: 5; add)` сделало бы моделью `(y: 5)` и переопределило бы поле `y` несвязанным формалом `add`. Обратное — нет в предложенной форме: тела — op-деревья, дописываемые по порядку; `return: x + 5` модели `add5` исполняется первым, и приписанное тело `return: x + y` не достигается — получится `add5` с лишним формалом `y`. Переопределения тела merge не делает (переопределяются поля, операции дописываются).
