# Q20. Исполнение именованной Structure: где живёт её тело и нужен ли child 0 = callable у экземпляров

**Закрыт правилом автора о merge 2026-09-24 (план §4 «Merge: правило автора»: простыня + offset в дескрипторе + lastIndex + копирование методов + интерпретация callable-Structure).** Состояние: 2026-09-24, **отвечен: Д** (дословно в `LMX_blog/2026-09-24.md`): child 0 = дескриптор, как у `sub`, только без аргументов и результата; переделка ядра — дескриптор при построении и merge, сдвиг индексов в трансляторе, `implements` с child 1. Следствие — вопрос автора о merge → `q21.md`. Вопрос Opus перед коммитом 4 (`FABLE-OPUS-RECEIVER-CONTRACT-20260924-139`), решает раскладку графа и ABI, поэтому — вам. Ответить можно строкой `Q20 Б` или `Q20 Д`.

## Сегодня

- Вхождение метода: child 0 = `LmxCallable`, затем own-поля (child 1 + k); E — так же.
- Экземпляр именованной Structure `S` в единице (ns_base + rank) — только поля (children 0..n−1); он же — тип/модель для `S: x`, merge и admission.
- `S\n` читает этот экземпляр; `m\x` у метода — own-ячейку вхождения.

Норма (Q19.1–Q19.3, книга §10/§12): именованная Structure исполняется голым атомом; тело исполняется целиком, как тело метода (Q19.2 = 2); `S\n` читает опубликованное поле без исполнения; результата нет — только голый `return` (в теле и как trailer).

## Варианты

**Б — только транслятор, граф не меняется (предложение Opus).** Тело `S` компилируется один раз в безымянную METHOD-строку, привязанную к `S`; строка невидима для `l2_find_method` (поэтому `S()` остаётся присваиванием по книге §12, `S: x` — объявлением, `S` — типом). Её `self` — та Structure, на которой она исполняется; own-поля — поля `S` по их собственным индексам (k, не 1 + k). Голое `S` вызывает её с `self` = экземпляр `S`; объявления заново инициализируют ячейки, операторы их меняют, checkpoint публикует, `S\n` (существующий ns-путь) читает. Та же строка исполняет экземпляр формы `S`: голое `fresh` после `Model: fresh` исполняет тело `Model` на `fresh`. Объём: примитивные поля (int/size_t/char/unsigned/ulong) + исполняемые операторы; голый `return` — да, `return: v` — отказ; `fm` — явный located «not supported yet». Явные отказы (пока): исполнение `S` со структурными полями (вложенные/ссылка/fn/массив — повторный запуск такого объявления = повторный merge); `S` во время исполнения — передача в callable-формал, исполнение walker/L3 (у экземпляра нет `LmxCallable`, ядро его callable не видит). Ни один существующий индекс не сдвигается; все фикстуры байт-в-байт, кроме двух отказов коммита 1, которые становятся исполнением.

**Д — изменение ABI ядра.** Экземпляры именованных Structure становятся callable-вхождениями: child 0 = `LmxCallable`, поля с child 1 — ровно как у методов и E; экземпляры от merge тоже несут его, поэтому `fresh` callable и во время исполнения (walker/L3, callable-формалы). Единообразная модель («именованная Structure — callable»), но каждый ns-индекс полей сдвигается на 1, merge и implements должны считать child 0 callable, а не полем; правка — в файлах ядра (Grok) и в исполнении L3/walker, далеко за пределами коммита 4.

## Рекомендация

**Б сейчас** (коммит 4), **Д — позже отдельным тикетом ядра**, если вам нужна callable-природа именованных Structure во время исполнения (передача `S` в callable-формал, исполнение интерпретатором). Б сохраняет формы графа, роль типа и все свидетели; Д — единообразнее, но переезд всех индексов и merge/implements.
