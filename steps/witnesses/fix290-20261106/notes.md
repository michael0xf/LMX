## Где было

Корень вызывает метод части, оставив его скрытый вход `scale` свободным (`lmx_walk_value_free_mark`): в активациях вызывающих имени нет. Вызываемый разрешает вход по цепочке активаций (`lmx_activation_resolve_input`), не находит и читает лексический источник — поле корня части, `l2_call_code\parent`, слот 0. Источник читается, но место отсутствующего входа делалось с типом `LMX_TYPE_NONE` (`lm_compiler_emit_native_input_store`), а у входа без значения и без ячейки типа нет: `lmx_walk_values_arg_place` отвечает INVALID («an absent input without a value is a missing input»). gdb на p-prod.exe p290b: `lmx_call_note_walk_fail(1)` из `l2_m1` (part_scale) после `lmx_walk_values_arg_place`. Обходчик в том же случае типизирует место значением дефолта (`lmx_walk_place_mode`, ARG: `type: holder\type`). Срез 270 (45cafc25) дал обоим сохранениям входа тип существующего места — верно для SET, неверно для дефолта при входе; до него тип брался из значения.

Запись без чтения (`scale: v` в `set_scale`): native удерживает лексический источник при входе для каждого скрытого входа, у которого он есть (`lm_compiler_emit_native_input_entry`); обходчик — только входы, которые тело читает (ARG с источником ARG_ENTRY, `lmx_walk_snapshot_args`). У записи SET_ARG источника нет, вход оставался отсутствующим, и допуск при входе (`lmx_walk_admit_free_inputs`) отвечал `implements` (gdb: третий вызов допуска возвращает 0xa), хотя лексический источник есть.

Перевод `absent_name: v`: сбор присваиваний регистрирует голову как поле этой местной декларации (`lm_compiler_own_add`) и сразу спрашивает её декларацию (`lm_compiler_declaration_model`); `lm_compiler_declaration` (:936) спрашивает, известна ли голова как Structure (`lm_compiler_head_resolve(...) = 5`); голова — только что зарегистрированное поле, и `head_resolve` для роли value-own (3 или 4) спрашивает декларацию этого поля (`lm_compiler_own_method_requirement`) — ту же самую, кэш ещё пуст. gdb: 17 700 кадров `declaration → own_method_requirement → head_resolve → declaration`.

## Механизм

- **Native: место дефолта типизирует значение дефолта.** `lm_compiler_emit_native_input_store` (l2_frontend_lower.lm2): сохранение при входе (`at_entry`, его делает только `lm_compiler_emit_native_input_default` — выбранный лексический дефолт отсутствующего входа) делает место свободного входа с типом значения (`(cast: (int) l2_isv<N>.type)`), как ARG обходчика; запись в существующий вход (SET) по-прежнему берёт тип существующего места.
- **Обходчик: запись входа с лексическим источником удерживает источник при входе.** `lm_compiler_rw_input_write` (l2_frontend_emit.lm2): если у записываемого скрытого входа есть лексический источник (`lm_compiler_hid_source`, тот же предикат, что у чтения `lm_compiler_rw_arg_fb`), кадр SET_ARG получает пятое поле — ARG с источником ARG_ENTRY и тем же дефолтом; снимок входа (`lmx_walk_entry_node`) берёт его, как берёт чтение; SET_ARG читает свои первые четыре поля. Теперь обходчик удерживает те же входы, что native. Ядро не менялось.
- **Транслятор: вопрос «голова — Structure» без роли value-own.** `lm_compiler_head_structure` (в конце l2_frontend_resolve.lm2) отвечает, как `head_resolve(...) = 5`: для поля, к которому разрешается голова, — по его определению (метод — 2, Structure — 5), иначе — ответ `head_resolve`; роль value-own (её берёт декларация поля) ему не нужна. Три вопроса `= 5` внутри `lm_compiler_declaration` (:936, :975, :1039) спрашивают его. Рекурсия снята; `absent_name: v` получает уже существующий отказ трансляции `an unknown head needs a Structure body` — текущее поведение реализации для головы без привязки и без прежнего чтения (решение автора 2026-10-05 в `lm_compiler_local_absent_def`: такая голова — местное определение), а не новая норма.
- **Инструмент: список команд.** `lmxtool checks LIST` и `lmxtool steps LIST` (tools/lmxtool_methods.lm2, `checks_run`): каждая строка — команда инструмента со словами через табуляцию, исполняется в процессе, как `tool_main` исполняет командную строку; её вывод, затем `CHECK <exit> <слова>`; строка `checks`/`steps` отвергается (2); `steps` кончается на первой команде с ответом не 0; итог `CHECKS <n> lines, <m> failed`. Самотест `test_check_lists` проверяет оба режима, вложенный список и нечитаемый список.

- **Запись голого имени без источника — две формы ведут себя по-разному.** `absent_name: v` (хвост — имя) отказывает при трансляции (выше), а `absent_name: 5` (литерал) в том же методе переводится и исполняется без отказа (p290k, 7 во всех четырёх запусках): транслятор считает его строкой собственного поля метода (`lm_compiler_local_absent_def`: содержимое VALUE). Книга :773 запрещает «молчаливое создание нуля или нового поля при исполнении», а :691 — возникновение поля, которое не объявлено явно; решение автора 2026-10-05 различает только прежнее чтение. Не менял: это вопрос нормы, отправлен Codex (ABSENT-HEAD-WRITE-NORM, OPEN). Поправка 291 (ответ Codex на 290, п. 1): вопроса нормы нет — книга :470–476, такая голова определяет Structure; отказ `absent_name: v` — предел реализации, ABSENT-HEAD-WRITE-NORM — долг общего построения ([запись 291](../fix291-20261106/notes.md)).

## Стоимость

Native: отсутствующий вход метода части при входе один раз читает дефолт и делает место по его типу — прежде место не делалось (INVALID). Обходчик: кадр SET_ARG входа с лексическим источником держит пятое поле, снимок при входе читает дефолт записываемого входа один раз. `lm_compiler_head_structure` отвечает одним разрешением головы до поля и его определением вместо роли value-own. `checks`/`steps` исполняют строки в процессе инструмента. Отдельно не замерено. Код: G2 l2trans `15fe8a83…`, G2 tool `4f1c9009…`. Whole quick 692.99 с против 647.20 с у boot151a — измерение всего конвейера, не контролируемое сравнение.
