Ответы сверены 2026-11-15 с текущим допуском и M14. Дословные ответы автора —

## Q1. Известный при построении кандидат и фактический приём

Вопрос: нужно ли для кандидата, известного при построении, выполнять `test` при первом фактическом приёме
во время исполнения, или `test` относится только к динамически выбранному кандидату?

Автор [указал вопросом](../2026-11-13.md#runtime-candidate-admission), что исполнитель необоснованно
противопоставил эти случаи. Исполнитель снимает такое разделение: при построении только интерфейсная часть;
при фактическом допуске во время исполнения — второй шаг `test`. Известность кандидата не отменяет второй шаг
и не требует повторять уже завершённую первую часть. Это вывод из общего правила, не отдельный режим допуска.

## Q2. Где может исполниться test при наличии data

Наличие `test: op check` среди данных Consumer само по себе его не запускает.
При построении чистого графа готовые объявления сворачиваются без вызовов программы.
Вход в вызов только собирает namespace по корням data/code и не исполняет
инициализаторы. Отдельного прохода, который ищет test во вложенных данных, нет.

Когда исполнение достигает ресивера по общим правилам, его контракт может
выполнить переданный код и тем самым дойти до test. Это тот же путь исполнения,
что для любого другого кода; одного соседства с объявлением недостаточно.

~~~text
Consumer:
    @: op Model
    test: op check
~~~

Пример не означает, что вход в Consumer автоматически исполняет вторую строку.
[Правило достижения кода через ресивер](../../docs/LMX_semantics.ru.md#data-root-declaration-execution),
[уточнение M14 без входной инициализации](../../docs/LMX_semantics.ru.md#call-frame-20261115).
Исходный [ответ автора о достижении test](../2026-11-13.md#data-root-receiver-execution)
читается вместе с последующим [уточнением об отсутствии входного исполнения](../2026-11-15.md#m14-value-reading).

## Q3. Несколько проверок и первый результат 0

Вопрос: после первой неуспешной проверки выполнять остальные или прекратить допуск?

[Ответ автора](../2026-11-13.md#test-first-failure): «сразу прекращаем».
При первом `0` остальные проверки не исполняются. Все проверки должны быть успешны для допуска;
прежняя фраза «исполняет все» не означает продолжения после отказа.
