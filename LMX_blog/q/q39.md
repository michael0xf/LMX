# Q39. Допуск Structure с переставленными полями: как индексные пути модели находят поля значения

Состояние: 2026-09-27, открыт (Opus; дефект D-105, находка fable_pc в REVIEW 3e4c9a0); в тот же день отвечен автором
в чате fable_pc (~21:06 UTC), закрыт и перенесён в `LMX_blog/q/`.

## Факт

```text
Model:
    size_t: a 1U
    size_t: b 2U
end: Model
Other:
    size_t: b 20U
    size_t: a 10U
end: Other
fn: rd (Model: m) size_t
return: m\a
fn: go () size_t
    Other: o
    return: rd(o)
```

`go()` возвращает 20 (поле `b` у `Other`), а не 10. Аналитический `implements` пропускает `Other` в `Model`
по именам — книга :733: «Проверка не подменяется сравнением одинаковых физических позиций. Перестановка различно
названных полей при сохранении путей не меняет результат». Исполнение же адресует поля индексом: ядро,
`lmx_implements.h.lm1` :125 — «names are absent from ordinary execution», и `m\a` у транслятора — слот 0 модели.
Нативный вызов передаёт `o` в формал без допуска в ходе. Обход в том же месте отказывает; в поле `Model` корня
значение другого типа сегодня не попадает никак (присваивание, результат вызова и запись из метода отказаны).

Та же граница решает исполнение голой структурной переменной (`steps/named-struct-exec.md` §10–11): шаги тела `Model`
адресуют слоты `Model`; над переставленным значением они писали бы не те поля. Срез 4 поэтому исполняет только
поля-слоты корня `Model: v` (копии merge, раскладка модели) и отказывает формалу.

## Вопрос

Как значение, допущенное по именам с другой раскладкой, отвечает индексным путям потребителя?

1. Допуск даёт значение раскладки потребителя — переразложение (копия или вид) в момент допуска.
2. Допуск требует той же индексной раскладки используемых путей — перестановка отказывается (расходится с :733).
3. Иное — например, путь потребителя разрешается по значению при каждом доступе.

## Предложение Opus

(1): «names are absent from ordinary execution» и :733 вместе оставляют только переразложение в момент допуска —
потребитель видит свою раскладку, код и чтения потребителя адресуют её индексами. Где его делать (копия, вид,
таблица индексов при допуске) и как оно сочетается с тестами Consumer (:733 выше — «отсутствие набора тестов не
считается успешной runtime-валидацией») — порт `implements` (§7), порядок за автором.

## Ответ автора (2026-09-27)

Дословно — `LMX_blog/2026-09-27.md` (раздел Q39). Как прочитано (fable_pc; при расхождении действует цитата):

1. Выбран вариант (1) вопроса — исполнение должно имитировать получение по именам; механизм — любой, который это даёт («делайте любой механизм»). Отказ перестановки (вариант 2) снят.
2. Порядок: сначала в интерпретаторе (путь обхода), потом нативно.
3. Механизм: если потребителю подставлена его исходная Structure (раскладка типа модели) — поля берутся прямо по смещению исходной, как сегодня; если подставлена другая Structure (допущенная по именам с иной раскладкой) — к ней прикрепляется таблица преобразования индексов (индекс пути потребителя → индекс поля поставленного значения).
4. Место таблицы — сам `implements`: тяжёлым (аналитическим, по именам) должен быть только первый `implements`; он же строит таблицу, и последующие проверки берут соответствие адресов из своей таблицы, а не повторяют разбор по именам. Там же (в проверке) сразу видно, что для доступа нужно взять таблицу преобразования индексов.
5. Следствие для D-105 и `steps/named-struct-exec.md` §10–11: значение другой раскладки не отказывается и не переразлагается копией — оно несёт таблицу, и индексные пути потребителя разрешаются через неё; пример из «Факта»: `rd(o)` возвращает 10. Что именно «прикрепляется» к значению физически (где живёт таблица и как путь потребителя её находит) — решение ведущего в порте `implements` (§7); при неясности — следующий вопрос.
