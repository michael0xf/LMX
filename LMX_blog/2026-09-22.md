## Приоритет вызова, присваивания и объявления

Источник: прямое уточнение автора, доставлено в задачу Codex 2026-09-22. Дословно:

```text
"ping: 7
текущий тест считает вызовом известного метода: [unit\_colon\_callable\_receiver.lm2 (line 6)](C:/Nyasha_Planet/LMX/dev/l2src_sandbox/tests/unit_colon_callable_receiver.lm2:6). Но правило «если имя уже существует — обычное присваивание» может сделать ту же запись присваиванием callable-значению. Особенно это неразрешимо для callable-поля: физически оно существует, но нынешний код считает сам факт callable достаточным основанием для вызова."&#x20;

1\) правило вызова метода в высшем приоритете №1
2\) правило присвоения в приоритете №2
3\) правило объявления или объявление неизвестного типа -- в низшем приоритете&#x20;
То есть&#x20;
1\)если у нас уже есть callable поле ping -- вызываем его с аргументом 7
2\)Если у нас есть ping но он не callable -- делаем присвоение
3\)Если ping нет и тип его неизвестен (не объявлен ранее) -- ошибка, если известен -- объявление (в данном случае это примитив и если его тип уже фигурировал то объявление сделано)

Как присвоить callable поле? Никак. Только неявные варианты (и в будущем не будем вводить  доп семантику, только общую):
1\)merge двух структур в которой последняя содержит свой ping заменяющий первую.(выполняется implements)&#x20;
2\) динамическая перегрузка вызывающим callable -- если ping объявлен выше то вызывающий его в приоритете перегружает (если у него нет то не перегружает
3\)явная передача в аргументах вызывающего (то есть ping передается в дескрпиторе аргументов callable)
И вам это легче. Уточнения есть?
```

## Дверь `c.*`: без name-specific `c.puts` / `c.array` в L2

Источник: прямая авторская инструкция, доставлена через Codex AUTHOR RESUME / follow-up ticket `GROK-BOT-C-DOOR-UNIFY-20260922-11` (2026-09-22). Организационные части опущены. Техническая выдержка дословно по смыслу поручения:

```text
L2 specification cannot define `c.array` or name-specific `c.puts` semantics. `c.*` is one general external door. `c.puts` must use the ordinary foreign-call path; remove name-specific check/emitter/simple-main/leaf semantic branches. An L2 puts library is ordinary L2 code without `c.`; a C puts implementation is external C used through the same general c.* door. Remove `c.array` from L2 docs and L2 translator/input corpus; migrate the actual parser_dump_port raw buffer and tests using already-general L2 mechanisms or an external library through c.*. Do not invent replacement syntax or another hard-coded helper. `c.sizeof` may be a genuine foreign operator rather than call; classify by declared/builtin kind, not exclusion list. Audit before changing L1: if current L1 c.array can be eliminated with an existing general mechanism, do so in a separately bounded part with tests; otherwise record the exact blocker and do not invent an exception.
```

Дополнительно автор потребовал блокирующий clean-kernel GATE перед L2 self-build/migration: самосборка только на чистом ядре (нет special `c.puts`/`c.array`, нет дублирующих discard/call путей, нет мёртвых helpers/shims/contradictory docs, нет hidden fallback; inventory нулевых ссылок; L1 `c.array` при необходимости — отдельно owned foreign-backend debt).
