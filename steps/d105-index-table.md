# D-105 по ответу Q39: таблица преобразования индексов в `implements` — замер и предложение (Opus, 2026-09-27)

Ответ автора — `LMX_blog/2026-09-27.md`, «Q39» (вопрос — `LMX_blog/q/q39.md`, дефект D-105). Записка — замер и
предложение для ревью; кода нет.

## 1. Норма — дословно

```text
Q39: -- "Аналитический `implements` пропускает `Other` в `Model`" -- делайте любой механизм который позволяет имитировать получение по именам. Сначала сделайте в интерпертаторе и потом нативно. Механизм примерно  понятен: если поставляется исходная структура то берется прямо по смещению исходной. Если подставляется другая то надо ей прикрепить таблицу преобразований индексов. ОЧевидное место длятакой таблице -- сам implements. Все равно там тяжелеовесный только первый implements должен быть а в дальнейших проверках он должен брать соответствие адресов из своей таблицы, там же сразу и понятно будет что надо взять таблицу преобразования индексов
```

## 2. Замер

1. **Где известны имена.** Только у транслятора: аналитический допуск `l2_admit_implements` →
   `l2_descriptor_implements` / `l2_descriptor_used` сравнивает поля по именам (книга :733 — перестановка различно
   названных полей не меняет результат). Ядро имён не знает: `lmx_runtime_implements` идёт по индексным путям
   (`lmx_implements.h.lm1` :125 — «names are absent from ordinary execution»).
2. **Где значение уходит в место другого типа.** Нативно — вызов метода с формалом Structure-типа: `rd(o)` пишется
   `l2_m0(l2_c0\parent, l2_c0, (cast: (@: Lmx) l2_q2_from[0]))` — допуска в ходе нет (замер D-105). В корне
   (обход) передача значения другого типа в такой формал отказывается («root operation not walkable yet: an admission
   to a Structure type»); присваивание значения другого типа в поле `Model` — отказ транслятора («graph assignment
   admission requires receiving-expression tests»); запись поля единицы из метода — «assignment value has
   incompatible type».
3. **Как читается поле.** Нативно — фиксированный слот типа: `m\a` у `rd` — `lmx_arena_ref_cell(l2_p0_0, 0U)`.
   В обходе — `OF(ARG j, слот)` / `PUT_OF` (`l2_rw_path_value`, путь от формала — `path[0]` = 6): слот — число
   в кадре, тип основания кадр не несёт.
4. **Где допуск в ходе уже есть.** Примитив обходчика `lmx_walk_admit` (`[admit, значение, модель]` →
   `lmx_walk_admit_against` → `lmx_runtime_implements`) — для присваивания в типизированное поле корня; результата,
   кроме «допущено / бросок implements», он не оставляет.

## 3. Предложение

**Кто тяжёлый.** «Первый implements» — аналитический, у транслятора: он знает имена обоих типов и строит таблицу
`T[j]` — слот в `Cand` поля, которое у `Req` стоит на слоте `j`. Если `Cand` = `Req` (подставлена исходная
Structure), таблицы нет — поле берётся по смещению исходной, как сегодня. Таблица — обыкновенная Structure из ячеек
`size_t` (как таблица пар `merge`), строится при построении графа.

**Где таблица живёт — в `implements` ядра (вариант Б, рекомендую).** Допуск в ходе (в месте, где значение `Cand`
уходит в место `Req`) регистрирует соответствие «адрес значения, тип `Req` → таблица» в таблице `implements` ядра
(арена программы). Дальнейшие проверки и доступы берут соответствие по адресу: поле через место типа `Req` читается
по слоту `T[j]`, если значение зарегистрировано, иначе по `j`. Это буквально «в дальнейших проверках он должен брать
соответствие адресов из своей таблицы». Ключ — пара (адрес значения, тип `Req`): одно значение может быть допущено в
разные типы. Тип `Req` в ходе — адрес узла именованной Structure (дочерний единицы).

Вариант А (не рекомендую): таблица едет с аргументом активации (кадр хранит таблицу на формал). Проще, но теряется,
когда значение уходит дальше (в локальное, в поле, в следующий вызов), — снова D-105.

**Интерпретатор первым (срез 1).** Транслятор: в месте допуска `Cand` ≠ `Req` — шаг допуска с таблицей
(расширение `ADMIT`: `[admit, значение, модель, таблица]`), он регистрирует соответствие; кадры `OF` / `PUT_OF`,
основание которых типа `Req` (формал Structure-типа), несут `Req` — и обходчик переводит слот по зарегистрированной
таблице. Первый свидетель — пример D-105 (`go` передаёт `Other` в `rd (Model: m)`) под knob: `m\a` = 10 и запись
`m\a` меняет `o\a`; мутант — перевод слота снят (снова 20). В корне отказ «an admission to a Structure type»
снимается тем же шагом.

**Нативно (срез 2).** Тот же шаг — вызов ядра при передаче аргумента; доступ к полю формала Structure-типа — через
функцию ядра (перевод слота по таблице `implements`), а не фиксированным `lmx_arena_ref_cell(m, j)`. Транслятор знает
все места вызова (замкнутый юнит): формал, в который ни одно место не подаёт другой тип, остаётся на фиксированных
смещениях — цена платится только там, где подстановка есть.

**Не делается здесь.** Переразложение (копия/вид в раскладке `Req`) — автор выбрал таблицу; тесты Consumer (:733,
«отсутствие набора тестов не считается успешной runtime-валидацией») — порт `implements` §7, отдельно.
