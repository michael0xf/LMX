## Норма среза 1 (PAP), без T6 и T7

Поверхность — тело из одного оператора `merge(y: 5; add)` у объявленного заголовка `fn: add5 (int: x) int`. Это три операнда, не два: модель — `add`, затем `{y: 5}`, затем объявленный заголовок (`LMX_blog/2026-09-25.md`, итог правила merge, пункт 5). Порядок `merge(y: 5; add)` без заголовка моделью сделал бы `(y: 5)` — не этот свидетель.

- Части попарно: `args` ← `args`, `return` ← `return`, `body` ← `body`. Простая Structure — только `body`; недостающая часть — пустая. Поздний операнд внутрь модели. Одноимённое поле — в слот, новое — в конец. Имена только в трансляторе; ядро получает прежние пары позиций.
- Заголовок результата — объявленная сигнатура `(int: x) int`. Формал `y` связан полем данных `y` = 5 и из сигнатуры уходит. `x` остаётся входом кадра (`ARG 0`).
- Безымянные операторы: у `{y: 5}` и у заголовка их нет, поэтому тело результата — операторы `add`. Кадр, который читает связанный `y` как `ARG`, для результата читает поле данных (holder 0, слот поля). Это не общий `Cadd`: у `add` формал `y` по-прежнему вход. Общие остаются кадры, которые связанное имя не читают.
- `native` результата — 0. Вызов `add5: 1` — walked, через `lmx_call_prim` / узел CALL, не символ `_tr`. Ожидание: 6.
- Тело вне walkable-подмножества T4a/T4b — located «a callable merge needs a walkable body», merge не собирается. Нативный трамплин модели не сливается.

Не в этом срезе: makeAdder (T6), конвертер Structure→callable (T7), полный `implements`, дверь `c.*`, D-81, тихий каст. q22 и q20 не переписывать.
