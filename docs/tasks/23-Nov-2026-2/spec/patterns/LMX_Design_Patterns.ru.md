# Шаблоны проектирования на Lingvamyxa

Русская версия · 21 ноября 2026 года · Согласовано с docs

В этом руководстве девять знакомых задач записаны через обычные структуры, методы и связывание LMX. Архитектурной отправной точкой служат Python-примеры из сравнительных файлов: связанные функции собираются в естественную группу, общее DATA описывается один раз, demo располагается рядом с используемыми методами. Decorator приведён в точной форме, предложенной автором, с автопередачей value.

Все основные листинги буквально совпадают с текущими девятью файлами сравнений. Код LMX проверен по согласованным правилам и уточнениям автора; **запуска этих примеров на ядре LMX не было**. Ожидаемые результаты отделены от отчётов о выполнении программ на других языках.

## Как устроены программы

Каждый раздел — самостоятельная программа. Повторяющиеся имена не надо объединять в один модуль. Основной блок содержит определения, а указанный рядом внешний вызов помещается в исполняемый контекст. Результат возвращается, библиотека печати не предполагается.

**DATA и методы.** DATA вызываемого кода — его фактический parent. Одна структура может объединять данные и несколько связанных методов; каждый метод использует нужные ему поля. Поэтому demo естественно помещается в ту же группу. Общее описание DATA не объединяет локальные рабочие значения всех вызовов в одну переменную. Метод, вызванный ради эффектов, может закончить выполнение без результата; достижение конца тела не создаёт синтетическое значение return. [Структурный вызов и return](../LMX_semantics.en.md#structural-call)

**Обычная ссылка на метод.** `@: selected twice` сохраняет ссылку на twice, не вызывая его. `selected := thrice` меняет её значение, а `selected(...)` запускает выбранный метод. Отдельный `Name :: Data` нужен, когда программа задаёт самостоятельное требование к форме callable; он не является обязательной частью каждого объявления ссылки или прямого вызова. В этих девяти программах такой дополнительный контракт не требуется. Типы полей, результатов и правила допуска конкретного вызова продолжают действовать. [Контракт @ и fn](../LMX_semantics.en.md#fn-signature)

**Автопередача и изменение места.** Объявленный, но не инициализированный вход может получить копию одноимённого значения непосредственного вызывающего. Так числовой value передаётся в арифметические методы. Свободное имя без собственного объявления может обозначать место непосредственного вызывающего; передача уже установленного alias сохраняет исходное место. Старый транзитивный fallback сам по себе не превращает копию в alias. В Command эту разницу учитывает required: value в посреднике. [Правила связывания](../LMX_semantics.en.md#binding-places)

**Defaults и private.** Готовое собственное начальное значение автоматически не вытесняется одноимённой локалью: замену подают явно. private действует на неявное динамическое связывание в обе стороны — закрывает источник вызывающего и защищает лексическое объявление получателя от подмены. Явная передача и разрешённый лексический доступ сохраняют свои правила.

**Лексическое node.** `node\` выбирает лексическое поле. Это не оператор перехода к parent. Позиция итератора, прототип Factory и состояние Observer явно изменяются таким способом там, где значение должно сохраняться между отдельными вызовами.

**Границы.** Пустая физическая строка, в том числе строка только из пробелов или табуляций, завершает весь обычный синтаксический блок как `---` на виртуальном уровне −1 над root. Внутри root она не служит произвольным форматированием. Вложенный `---` нужен, чтобы закрыть внутреннюю структуру и продолжить внешнюю; такой маркер есть в Visitor. Последний обычный блок закрывается на EOF. Литералы и защищённые лексические формы сохраняют собственные правила. [Правило пустой строки](../LMX_grammar.en.md#levels)

**Импорт и переданные формы.** import открывает корневые const-объявления DATA; пользовательские структуры константны без отдельного const. Обычные переменные не импортируются, DATA импортированного метода не меняется. Квалифицированный вызов также может обойтись без import. В Iterator аргумент-декларация сохраняет свою форму до исполнения iteration(), затем предоставляет общее место item телу. [Import и декларации в аргументах](../LMX_semantics.en.md#declaration-arguments)

**Копирование и потоки полей.** `import`, `copy` и `merge` в любом месте записи получают обычные аргументы в роли CODE. `copy` принимает один допущенный источник, `merge` — не меньше двух; оба выдают поток полей. Когда нужен один объект, поток явно собирается в группу: `(copy(Product))` или `(merge(Model Settings))`. Текущая принимающая структура не становится дополнительным источником `merge`. Ресиверы остаются в исходном графе, а их результаты обрабатываются в namespace. У обычных вызовов W/E-правила сохраняются и после группировки. У операндов действует отдельное условие: слева написана безымянная Structure, а единственный правый аргумент — ещё одна написанная безымянная Structure. Тогда ровно один внешний уровень снимается только справа; левая группа остаётся целой, повторного раскрытия и снятия в P0 нет. [Копирование, композиция и группировка][S]

## 1. Iterator — итератор и пользовательский iterate

В Python Numbers хранит позицию, iterate принимает шаг и обработчик, demo накапливает total. В LMX сохраняются эти роли: numbers содержит next и demo, а cycles — пользовательский iterate. Переданная форма объявления связывает текущий item с телом.

```lmx
numbers:
    int: position 0
    return: int
    next:
        throws: Stop
        if: node\position >= 3
            throw: Stop()
        node\position += 1
        return: node\position
    demo:
        node\position := 0
        int: total 0
        cycles\iterate: int: item numbers\next()
            item *= 2
            total += item
        return: total

cycles:
    @: iteration
    @: body
    iterate:
        while: 1
            iteration()
            catch: Stop ()
                break
            body()
```

**Вызов:** `numbers\demo()`. **Ожидаемый результат: 12.**

node\position адресует лексическое хранимое поле numbers. demo сбрасывает его, создаёт локальный total, затем напрямую вызывает qualified head cycles\iterate:. Форма int: item numbers\next() и общий контекст тела сохранены буквально; total меняется в локальном месте demo. После трёх значений 1, 2, 3 тело накапливает 2, 4, 6; следующий Stop завершает цикл.

Последовательные значения 1, 2, 3 удваиваются до 2, 4, 6; total становится 12. Следующий вызов next даёт Stop. Позиция сбрасывается в начале demo, а total создаётся заново как локальная переменная.

**Границы:** Пример содержит конкретную последовательность из трёх значений и пользовательский цикл. Stop завершает последовательность; обработчик охватывает весь оборот, поэтому Stop из тела также завершит цикл. Обобщённый API контейнеров не предполагается.

## 2. Strategy — заменяемый алгоритм

Python-функции twice, thrice, apply и demo стали методами одной группы strategy. Общие объявления DATA заменяют повторение параметров; selected остаётся настоящей переназначаемой ссылкой, а apply сохраняет default операции.

```lmx
strategy:
    int: value
    @: operation twice
    return: int
    twice:
        return: value * 2
    thrice:
        return: value * 3
    apply:
        return: operation()
    demo:
        @: selected twice
        int: first apply(5; selected)
        selected := thrice
        return: first + apply(5; selected)
```

**Вызов:** `strategy\demo()`. **Ожидаемый результат: 25.**

Все методы используют объявления value, operation и return общего DATA. Не каждый метод обязан обращаться ко всем полям. apply(5; selected) явно задаёт value и operation. operation() вызывает выбранный метод; его объявленный value получает копию 5 от непосредственного apply. Собственное operation этого арифметического метода имеет исходный default и не используется телом. demo — обычный метод группы. @: selected twice создаёт ссылку на метод без вызова; selected := thrice переназначает её по общим правилам. Отдельного fn-требования программа не вводит. Прямой apply(5) использует ready default twice; одноимённая локаль сама default не вытесняет.

Первый apply(5; selected) использует twice и возвращает 10. После selected := thrice второй возвращает 15. Отдельный apply(5) сохраняет исходный default twice.

**Границы:** Сохранены два алгоритма, общий потребитель, default и смена ссылки. Дополнительный именованный fn-контракт переменной не входит в задачу. Все вызовы подчиняются обычному допуску аргументов выбранного метода.

[Полное сравнение на восьми языках](02_strategy_comparison.md).

<a id="factory"></a>

## 3. Factory — создание продукта из прототипа

Как Python Product, исходная структура содержит payload, read и фабричные методы, которые сначала записывают значение, затем возвращают копию. execute и demo собраны в add1. Первый результат сохраняется, второй сразу участвует в сумме.

```lmx
Product:
    int: payload
    return: int
    read:
        return: payload
    create:
        return: Product
        small:
            node\payload := 10
            return: (copy(Product))
        large:
            node\payload := 20
            return: (copy(Product))

add1:
    @: product Product
    return: int
    execute:
        return: product\read() + 1
    demo:
        import: Product
        int: first execute(create\small())
        return: first + execute(create\large())
```

**Вызов:** `add1\demo()`. **Ожидаемый результат: 32.**

node\payload в create выбирает лексическое поле Product, не непосредственный parent. Каждый метод записывает 10 либо 20 до (copy(Product)), поэтому продукты остаются независимыми. Поле product потребителя получает созданный продукт явно. demo не обязан обращаться к каждому полю своего DATA. import: Product открывает create, а execute уже виден в собственном DATA.

small возвращает продукт с payload = 10, large — с payload = 20; потребитель возвращает 11 и 21. Если удержать оба продукта, поздний large не меняет значение первого. Исходный прототип после серии содержит 20.

**Границы:** Это фабричные методы с копированием прототипа. Сравнивается независимость одного числового поля и возможность вызвать read у продукта. Общая графовая семантика copy не приравнивается к поверхностному копированию произвольных вложенных объектов других языков.

[Полное сравнение на восьми языках](03_factory_method_node_prototype_comparison.md).

<a id="adapter"></a>

## 4. Adapter — согласование порядка аргументов

В Python legacy_subtract и subtract имеют разные порядки параметров. Поэтому LMX сохраняет два DATA: legacy и adapter. demo находится рядом с адаптером и вызывает его непосредственно.

```lmx
legacy:
    int: right
    int: left
    return: int
    subtract:
        return: left - right

adapter:
    int: left
    int: right
    return: int
    subtract:
        return: legacy\subtract(right; left)
    demo:
        return: subtract(8; 3)
```

**Вызов:** `adapter\demo()`. **Ожидаемый результат: 5.**

Два DATA описывают два разных порядка входов. subtract(8;3) в adapter получает left=8,right=3. Вызов legacy\subtract(right;left) направляет 3 в первый legacy-вход right и8 во второй left. Получается8−3=5. Декларации результата и аргументов используются методами группы, включая demo. fn, import и отдельная Demo не нужны. Без адаптации прямой legacy\subtract(8;3) дал бы3−8=−5.

adapter.subtract получает left = 8 и right = 3, затем передаёт legacy значения в обратном порядке: right = 3, left = 8. Результат 5. Прямой legacy.subtract(8; 3) дал бы −5.

**Границы:** Адаптер реально делегирует старому методу после перестановки аргументов. Внешняя одноразовая callable-переменная удалена во всех языках. Возможность хранить произвольную заменяемую внешнюю реализацию отдельным требованием не задаётся.

## 5. Observer — два подписчика события

Python хранит одно состояние и две ссылки на обработчики. В LMX связанные данные, обработчики, notify и demo собраны в observer. Два callback-слота сохранены; отдельные классы или namespace-обёртки не требуются для этой демонстрации.

```lmx
observer:
    int: value
    int: last 0
    int: total 0
    @: first remember
    @: second accumulate
    return: int
    remember:
        node\last := value
    accumulate:
        node\total += value
    notify:
        first()
        second()
    demo:
        node\last := 0
        node\total := 0
        notify(3)
        notify(8)
        return: node\total
```

**Вызов:** `observer\demo()`. **Ожидаемый результат: 11.**

Как в исходном Python, remember и accumulate работают с одним состоянием, а notify вызывает две сохранённые ссылки. В LMX эти методы естественно принадлежат одной структуре observer. first и second первоначально указывают на remember и accumulate через обычную форму @: name value; отдельный fn-контракт не добавляется. notify(3) и notify(8) задают собственный value, а вызовы обработчиков без аргументов заполняют их объявленный value копией через autofill. node\last и node\total явно выбирают лексическое состояние observer, сохраняющееся между уведомлениями. demo сбрасывает это состояние перед серией. Общее DATA может иметь поля, которых отдельный метод не читает. return:int описывает допустимый числовой результат demo; вызовы notify и обработчиков используются только ради эффектов, не потребляют результата и не требуют синтетического return.

Событие 3 даёт last = 3 и total = 3; событие 8 — last = 8 и total = 11. По два обработчика на событие: четыре вызова. Повторный demo начинает новую серию с явного сброса состояния.

**Границы:** Два синхронных callback-слота и одно состояние. Очередь, динамический список подписок, отписка и политика ошибок требуют дополнительной логики. Python и другие варианты могут представлять состояние и издателя отдельными объектами; LMX объединяет их в одной группе для данного сценария.

[Полное сравнение на восьми языках](05_observer_comparison.md).

## 6. Decorator — цепочка обёрток

Авторский перевод Python base / with_one / with_three / demo использует одну группу transform. value и return объявлены один раз, вложенные вызовы используют autofill. Во всех восьми версиях demo непосредственно вызывает внешнюю обёртку.

```lmx
transform:
    int: value
    return: int
    base:
        return: value * 2
    with_one:
        return: base() + 1
    with_three:
        return: with_one() * 3
    demo:
        return: with_three(10)
```

**Вызов:** `transform\demo()`. **Ожидаемый результат: 63.**

demo вызывает with_three(10). Затем with_one() и base() получают свои значения value через обычное автодозаполнение объявленного входа от непосредственного вызывающего. base возвращает 20, with_one — 21, with_three — 63. Это разные рабочие места вызовов, записи в граф не нужны. demo — обычный метод той же группы; ему не требуется пользоваться каждым полем её DATA.

with_three(10) вызывает with_one(), тот вызывает base(). Каждый получает свой value = 10; результаты возвращаются как 20 → 21 → 63. Выбор base(10) или with_one(10) дал бы 20 или 21.

**Границы:** Фиксированная цепочка обёрток. Произвольная сборка или перестановка цепочки во время выполнения не реализована ни в одном листинге. Прямой внешний вызов применён одинаково ко всем языкам.

[Полное сравнение на восьми языках](06_decorator_comparison.md).

<a id="command"></a>

## 7. Command — действия над локальным состоянием

Python demo содержит локальный счётчик, две команды и invoke. В LMX связанные методы находятся в commands, а изменяемая value остаётся локальной в demo. invoke получает это место до вызова выбранной команды.

```lmx
commands:
    @: command add_two
    return: int
    add_two:
        value += 2
    twice:
        value *= 2
    invoke:
        required: value
        command()
    demo:
        int: value 0
        invoke()
        invoke(command := twice)
        return: value
```

**Вызов:** `commands\demo()`. **Ожидаемый результат: 4.**

Структура commands собирает связанные методы ровно как локальные Python-функции внутри demo. Объявление @: command add_two задаёт обычную ссылку со значением по умолчанию; отдельный fn не нужен для конкретного примера. value объявлен в code demo, а не в общей DATA, поэтому в invoke и телах команд это свободное имя. required: value в invoke обращается к месту непосредственного caller до command(), не объявляет собственную копию и устанавливает связь с demo.value. Команда затем получает от invoke уже установленный alias к тому же месту. Первый вызов даёт 2, второй — 4; каждый новый demo создаёт собственную локальную переменную. Общее return:int описывает числовой результат demo; остальные методы вызываются как действия и их результаты не потребляются.

В начале demo value = 0. invoke() использует add_two и меняет её на 2. invoke(command := twice) явно выбирает вторую команду и меняет ту же переменную на 4. Повторный demo создаёт новую локальную value.

**Границы:** Синхронное исполнение двух команд при доступном локальном контексте. Очередь, undo и сериализация не входят в пример. Обычная ссылка на метод сама по себе не продлевает время жизни локальной переменной.

[Полное сравнение на восьми языках](07_command_comparison.md).

## 8. Template Method — постоянный порядок заменяемых шагов

Python increment / twice / square / pipeline / demo собраны в группу pipeline. execute сохраняет последовательность шагов, а demo задаёт prepare и finish обычными ссылками. Данные шага передаются через autofill.

```lmx
pipeline:
    int: value
    return: int
    increment:
        return: value + 1
    twice:
        return: value * 2
    square:
        return: value * value
    execute:
        value := prepare()
        return: finish()
    demo:
        @: prepare increment
        @: finish twice
        int: first execute(4)
        finish := square
        return: first + execute(4)
```

**Вызов:** `pipeline\demo()`. **Ожидаемый результат: 35.**

demo объявляет локальные ссылки @: prepare increment и @: finish twice без дополнительного fn-контракта. В execute имена prepare и finish не объявлены в собственных DATA или code и связываются с контекстом непосредственно вызывающего demo. execute(4) имеет собственное value=4. prepare() вызывает increment и через autofill передаёт ему копию4; результат5 присваивается локальному value текущего execute. finish() получает свою копию5 и возвращает10 либо25. finish := square меняет ссылку в demo между вызовами. Общий исходный граф value не меняется. Методы DATA не обязаны пользоваться всеми его полями; отдельная Demo не нужна.

execute(4) передаёт 4 в prepare и получает 5. После локального присваивания finish получает 5 и возвращает 10. Во втором проходе выбран square, поэтому получается 25. Итоговая сумма — 35.

**Границы:** Постоянный порядок двух независимо заменяемых шагов. LMX передаёт ссылки на шаги через текущий контекст, другие варианты могут передавать их явно. Не вводится дополнительная обязательная иерархия классов.

## 9. Visitor — действия для разных видов узлов

Python отделяет Actions от NumberNode и PairNode. В LMX этому соответствуют Actions и два узла в Nodes. Методы действий уже доступны в контексте demo; дополнительные копии-ссылки и переименование полей узлов не нужны.

```lmx
Nodes:
    return: int
    on_number:
        throws: NoAction
        throw: NoAction()
    on_pair: copy(on_number)
    Number:
        int: value 3
        return: int
        accept:
            throws: NoAction
            return: on_number()
    ---
    Pair:
        int: left 4
        int: right 5
        return: int
        accept:
            throws: NoAction
            return: on_pair()

Actions:
    return: int
    on_number:
        return: value
    on_pair:
        return: left + right
    demo:
        int: result 0
        result := Nodes\Number\accept()
        result += Nodes\Pair\accept()
        catch: NoAction ()
            result := -1
        return: result
```

**Вызов:** `Actions\demo()`. **Ожидаемый результат: 12.**

Структурные/методные имена on_number и on_pair доступны в namespace Actions\demo при открытии. Свободное имя обработчика у accept сначала получает значение из доступного caller-context; Nodes fallback остаётся ниже по приоритету. Примитивные value/left/right являются объявленными входами DATA Number/Pair, поэтому обработчик получает их из контекста accept без дополнительных n/a/b. Записи в них не производятся. При удалении Actions\on_pair доступен Nodes\on_pair, который выдаёт NoAction; catch устанавливает -1.

Number передаёт через текущий контекст value = 3; Pair — left = 4 и right = 5. Обработчики возвращают 3 и 9. Если убрать Actions.on_pair, будет выбран Nodes.on_pair, возникнет NoAction и demo вернёт −1.

**Границы:** Два посещения с выбором действия по виду узла и доступному контексту. Оба обработчика NoAction сохранены. Хранение и рекурсивный обход произвольного дерева не включены.

## Общие механизмы

| Механизм | Примеры |
|---|---|
| Одна группа DATA и связанных методов, включая demo | Strategy, Adapter, Observer, Decorator, Command, Template Method |
| Обычная ссылка на метод без дополнительного fn | Strategy, Observer, Command, Template Method |
| Автопередача объявленного числового входа | Strategy, Observer, Decorator, Template Method |
| Место непосредственного вызывающего и дальнейший alias | Command |
| Callable-имена в контексте вызывающего | Visitor |
| Переданное объявление и общее место тела | Iterator |

Содержание задачи остаётся в коде: кого уведомлять, какой элемент считать следующим, как переставить аргументы, какой продукт создавать и в каком порядке вызывать шаги. Общие механизмы уменьшают количество описаний, необходимых для соединения этих частей.

### Сопоставимость и проверки

- В Adapter и Decorator одноразовая внешняя callable-переменная и её дополнительный тип удалены во всех восьми вариантах. В Factory второй одноразовый результат одинаково подставлен непосредственно в return.
- Сохраняются границы сценариев: Observer с двумя слотами, фиксированный Decorator, два посещения Visitor, синхронный Command без очереди и undo. Различия систем типов и устройства контекста не объявляются исчезнувшими из-за одинакового числового результата.
- Factory сравнивает самостоятельность одного числового поля. Общий контракт графового копирования LMX и способы копирования произвольных вложенных объектов других языков здесь не уравниваются.
- Статус исполнения и проверки других языков приведён в отдельных сравнительных файлах. Изменения документации и пересчёт размеров сами по себе не являются новым запуском этих программ или ядра LMX.
- Все 72 листинга пересчитаны программно. В обеих языковых версиях руководства девять LMX-блоков и сводные числа одинаковы.
