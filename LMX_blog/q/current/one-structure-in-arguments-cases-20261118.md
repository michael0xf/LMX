# Одна Structure в аргументах в роли `code`: спорные случаи

Дата: 2026-11-18. Задаёт исполнитель (сессия fable_pc) по поручению автора «Находи все спорные случаи»
([журнал](../../2026-11-18.md#receivers-in-data-code-role)). Статус: **OPEN**.

Правило, о котором речь ([книга](../../../docs/LMX_semantics.ru.md#whole-arguments),
[журнал](../../2026-11-18.md#one-unnamed-structure-for-receivers)): в аргументах, которые считаются `code`, ровно одна
Structure — это вся структура аргументов; правило вызова общее для вызываемого и ресивера; парсер ничего не
раскрывает. Ниже — случаи, где правило сталкивается с другим написанным правилом или даёт два прочтения. В каждом —
программа, наблюдаемые варианты и ответ принятого инструмента чистого графа (режим интерпретации, пробы исполнителя).

Общие данные проб:

```lmx
A: (int: x 7; int: y 8)
One: (int: x 9)
Args: (int: a 1; int: b 2; int: c 3)
@: Model (int: x 0)
fn: MR (@: value Model) int
    return: value\x
fn: h (int: x) int
    return: x
sub: g (int: a; int: b; int: c)
    seen := a * 100 + b * 10 + c
```

## С0. Что снято словами «про модификаторы я наврал»

Перед этим было сказано: «когда ресиверы объявлений и модификаторы исполняются в data то аргументы у них тоже в
роли code», а ещё раньше — что `private`, `required`, `const`, `immutable`, `independent` «очевидно выполняются и
переменные которые им передаются считаются "корневыми"» и что всем им нужны многоаргументные формы. Варианты:

- (а) снято только «аргументы модификаторов в роли `code`»: модификаторы в `data` исполняются, переменные под ними
  корневые, но Structure, поданная модификатору, не раскрывается (см. С3);
- (б) снято и «модификаторы исполняются в `data`»: при проходе по данным исполняются только ресиверы объявлений;
- (в) другое.

От ответа зависят С3, С4 и уже внесённые в книгу фразы о пяти ресиверах и их многоаргументных записях.

## С1. Одна Structure подана вызываемому, чей формал сам принимает Structure

```lmx
MR(A)
MR((A))
```

- `MR(A)`: (а) 7 — `A` подана формалу `value`; (б) отказ — `A` раскрыта, аргументы 7 и 8, формалу нужна Structure.
- `MR((A))`: (а) 7 — группа раскрыта, аргумент `A`; (б) отказ — формалу подана сама группа.

Сегодня: `MR(A)` — 7, `MR((A))` — отказ. Код сначала связывает записанные аргументы по позиции и имени и только
когда ни одна форма не связалась, читает единственный аргумент как всю структуру аргументов. При этом
`h(One)` — 9, `h((5))` — 5, `h(A)` — отказ (два поля на один формал). Пять записей из примера автора для `g` дают
один ответ.

## С2. Ресивер, чей операнд — сама Structure

```lmx
length(Args)
length((1 2 3 4))
typeof(Args)
call: Self
call: (Self)
call: Data Code
call: (Data Code)
```

Сегодня: `length(Args)` — 3, `length((1 2 3 4))` — 4, `typeof(Args)` — 13 (Structure); `call: Self`, `call(Self)` и
`Self()` запускают `Self`, а `call: (Self)` отказа не даёт и кода `Self` не запускает; `call: Data Code` запускает
`Code` над `Data`, `call: (Data Code)` отказа не даёт и кода не запускает (в обоих случаях запущена сама группа).
Тот же вопрос у `merge`, `return`, `send`, `adopt`, `sys\compile`, `sys\toLmx`.

- (а) у такого ресивера единственная Structure — операнд: правило «вся структура аргументов» действует, только
  когда по позиции она не подошла; тогда `call: (Data Code)` запускает группу, как сегодня, и «пять одинаковых
  вызовов» для `call` не выполняются;
- (б) правило действует всегда: `call: (Data Code)` — то же, что `call: Data Code`; тогда `call: Self` и
  `length(Args)` раскрывают `Self` и `Args`, и чтобы подать саму Structure, её надо писать в скобках: `length((Args))`;
- (в) правило действует для записанной на месте группы и не действует для Structure, поданной по имени или
  ссылке: `call: (Data Code)` — как `call: Data Code`, `call: Self` запускает `Self`. Это расходится со словами
  «общий случай -- мы подготовили структуру и передали ссылку на нее».

## С3. Модификатор и одна Structure

```lmx
S: (int: a 1; int: b 2)
immutable: S
immutable: (int: a 1; int: b 2)
const: immutable: S
```

- `immutable: S`: (а) неизменяемой становится сама `S` — одно значение; (б) `S` раскрыта — два отдельных
  неизменяемых `int`.
- `immutable: (int: a 1; int: b 2)`: (а) два объявления, каждое неизменяемое, — многоаргументная запись; (б) одна
  безымянная неизменяемая Structure с двумя полями.
- `const: immutable: S`: аргумент `const` — запись `immutable: S`. (а) она исполняется, и `const` получает её
  результат одним значением; (б) результат — Structure, и `const` получает её поля.

Сегодня объявление под `const`, `immutable`, `independent` чистый граф не исполняет вовсе (отказ).

## С4. `required` и `private` с именем Structure

```lmx
required: S
private: S
```

- `required: S`: (а) проверяется, что инициализирована сама `S`; (б) `S` раскрыта — проверяется каждое её поле.
- `private: S`, где `S` объявлена раньше: (а) помечается поле `S`; (б) `S` раскрыта — помечаются её поля.

Сегодня `required` чистому графу неизвестен; `private` принимает только объявление в скобках.

## С5. Вложенные скобки

```lmx
g((1 2 3))
g(((1 2 3)))
```

(а) раскрывается ровно один уровень: вторая запись — отказ; (б) пока аргумент один и он Structure, раскрытие
продолжается: обе дают 123. Сегодня — (а): 123 и отказ.

## С6. Путь к полю, объявленному под модификатором

```lmx
Lib: private: (int: x 10)
seen := Lib\x
```

- (а) 10 — путь видит поле `x`;
- (б) отказ — путь читает граф как записан, а в `Lib` записано поле `private`.

Сегодня — 10: путь проходит сквозь запись модификатора. Так же написано в книге
([примеры private](../../../docs/LMX_semantics.ru.md#private-examples)): `Library\x := 30` при
`private: (int: x 10)`. Это расходится со словами «struct\fields вообще никаких ресиверов не знает, ресиверы
подготавливают данные в data только для выполнения в code». Тот же вопрос для поля под `const:` и для обычного
объявления: `int: x 10` в данных — тоже запись ресивера `int`, и путь `Lib\x` читает её значение.

## С7. `merge` с одним операндом там, где аргументы в роли `code`

```lmx
@: R merge(Args)
R := merge(Args)
```

Форма `S: merge: A B` в данных — исключение, операнды — Structure, правило не действует (слова автора). Здесь `merge`
стоит аргументом ресивера объявления и в коде. (а) `Args` — операнд: результат — копия `Args`; (б) `Args` раскрыта:
операнды — её поля.

## С8. Объявление без значения, имя которого называет видимую Structure

```lmx
fn: f () int
    int: Args
    Args := 5
    return: Args
```

(а) 5 — имя берётся как записано, объявлен локальный `int`; (б) `Args` раскрыта: `int: a b c`. Сегодня — 5.
Исполнитель считает спора нет: первый аргумент объявляющего ресивера — имя, а не значение; случай записан для
полноты.
