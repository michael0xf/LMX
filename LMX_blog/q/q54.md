# Q54: until closing a labeled block — loop body or named Structure procedure?

**Date:** 2026-09-29  
**Source:** Opus WALKLOOP-20260929-11, labeled block semantics  
**References:** lingvamyxa_prev spec §19.4; L2 spec §22; book §13  
**Status:** CLOSED by author answer, 2026-09-29; implementation verification pending

## Author's resolution

An anonymous `until` is an ordinary loop in the current activation, like the other control bodies. It does not create a procedure activation or a separate data graph. A named `readLoop` is an ordinary named Structure: its declaration does not execute it; an explicit call executes its body, where `until` remains an ordinary loop. The named Structure follows the same free-name/hidden-input rule as any procedure (Q52); writing a bare free name does not write back to the caller. These rules must not be changed just to make an example terminate. `if`, `while`, `for`, and `until` are not lowered as independent procedure calls merely because their bodies are Structures. `node` retains its defined method-lexical meaning and is not the immediate parent of a nested control body.

Neither a named Structure nor `sub` requires an explicit trailer or a `return` statement. Reaching the end of the body is normal completion without a result; bare `return` is an optional early exit. Trailer notation is a source/P0 boundary device, not a semantic obligation.

The two alternatives below are the original question, not current competing rules. The still-needed parser/native/walker witnesses and implementation work do not reopen this semantic decision.

## Question (English)

In the proposed syntax for labeled blocks with `until:` closing:

```
readLoop:
    { body }
until: condition
```

Where `readLoop:` is a named Structure (a procedure without arguments and without a return value per Q45), the closing `until:` can be interpreted two ways:

1. **As the body of a loop in the current activation:** The named Structure's body is treated as the loop body (like a `while:` body); assignments within it modify the current activation's values (not hidden inputs), and the loop repeats based on `until:` condition.

2. **As a procedure of the named Structure:** Each execution enters the named Structure as a separate occurrence, so free names are hidden inputs (per Q52), and assignments within do not write to the caller's values.

Which semantics is correct?

## Question (Russian)

В предложенном синтаксисе для меток с `until:`:

```
readLoop:
    { тело }
until: условие
```

где `readLoop:` — именованная Structure (процедура без аргументов и без результата по Q45), закрывающий `until:` можно прочитать двумя способами:

1. **Как тело цикла текущей активации:** Тело именованной Structure рассматривается как тело цикла (как тело `while:`); присваивания внутри меняют значения текущей активации (не скрытые входы), и цикл повторяется по условию `until:`.

2. **Как процедура именованной Structure:** Каждое выполнение входит в именованную Structure как отдельное вхождение, поэтому свободные имена — скрытые входы (по Q52), и присваивания внутри не пишут в значения вызывающего.

Какая семантика верна?

## Evidence and Contradiction

### The problem:
If `readLoop:` is a named Structure (procedure), and `i` is free in the body:

```
i: 0
readLoop:
    i: i + 1
until: i = 3
```

Then by Q52 (free names are hidden inputs), `i: i + 1` inside the body reads the current value of `i` but does not write back to the caller's `i`. The condition `i = 3` would never become true (assuming no message-like side effect changes `i`), and the loop runs forever.

### Current specification gap:
The lingvamyxa_prev spec §19.4 proposes labeled blocks with `until`, but does not specify whether the body's assignments escape to the enclosing scope or remain local to the procedure.

**Book §13** notes: "The complete set of kinds of areas to which a label can attach requires a separate grammatical definition" — this question is part of that definition.

## Related Decisions

- **Q45** (named Structure as procedure): A named Structure is called without arguments, returns no value
- **Q51** (local declaration visibility): forward and down only, not outward
- **Q52** (free names are hidden inputs): assignments inside don't write to caller

These three decisions constrain the answer: if `readLoop:` is a named Structure, its semantics must respect Q52.

## Why This Matters

**Blocks the walking for `until`** (L2 spec §22 mentions `synchronized` and labeled statements with `until`).

The answer determines:
- Whether `until` is a loop control (body semantics) or a procedure exit (structure semantics)
- Which syntactic heads can be labels (book §13: "complete set of areas")
- Whether assignments in labeled blocks are local or escape to the caller
