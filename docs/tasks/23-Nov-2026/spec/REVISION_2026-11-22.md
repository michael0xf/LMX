## Documentation and naming

- [The unified chapter](CORE_SEQUENCES_REGEX.en.md) connects the complete type requirements, dense/reference arrays, shared sequence access, Pattern operations, and callable adapters.
- Current declarations use composed postfix heads: `type[]: array` for an array place and `Struct@: ptr candidate` for a reference with a complete structural requirement. `Struct@: ptr` remains uninitialized without an initializer; universal `@: ptr Struct` instead refers to Struct itself. Initialized and zero-payload uninitialized values stay distinct. Directed type-pair admission metadata is shared; successful admission does not change actual storage layout.
- The common Expression rule opens one outer RIGHT container only when left is a written unnamed Structure and right contains exactly one written unnamed Structure. P0 does not perform this transformation. A returned value is not automatically opened by this rule.
- [The naming review](NAMING_2026-11-22.md) records the approved **15 renames and three additions**. The former target-returning `splice` is `replaceRange`; a new `splice` returns removed elements. New `hasPrefix` and `hasSuffix` complement whole-source matching. Text `replace` keeps its existing meaning. No additional lowercasing or foreign-API rewriting is implied.
- Implementation tasks connect the applicable requirements directly to source files and acceptance fixtures. The uploaded priority task is preserved separately as reference material.

## LMX implementation work

The [core source package](patterns/LMX_Fn_Receivers/README.md) has **115 unique public callable/operand names**: 61 generic/container operations, 14 sequence operations, and 40 text-pattern operations. A separate **24 named Pattern values, models, settings, and declared failures** remain non-callable entries. The combined source has **32 parts**. All 61 pre-existing public operations remain represented with their current names.

### Sequences

The implementation uses one access path for dense arrays and Structures/reference arrays. Dense reads use the actual element type and stride. Addressable primitive values are prepared with ordinary value machinery; a dense input is not converted wholesale into boxes. Selection preserves the source profile where specified. `range` checks result size and overflow before emission.

`replaceRange`, `splice`, `append`, `insert`, and `deleteAt` share one mutation algorithm. Bounds, final size, and dense-target admission are checked before mutation; overlapping insertion inputs and the required removed snapshot are stabilized before writes or resize. `replaceRange` and the three specialized wrappers return the same target descriptor. New `splice` returns a fresh outer container of removed elements, preserving actual element type and dense/reference storage profile. Reference targets and their lexical parents remain shared; an empty removed interval yields an initialized empty result of the same profile. Higher-level collection operations use the same access path where appropriate.

Sources and remaining integration duties: [SEQUENCES_IMPLEMENTATION.md](patterns/LMX_Fn_Receivers/SEQUENCES_IMPLEMENTATION.md).

### Text patterns

Pattern builders, composition, repetition, captures, lookarounds, search, splitting, replacement, and iterator behavior are written as ordinary LMX structures and methods. There is no added native regex matcher, regex bytecode machine, or alternate parser. The existing `|` dispatch is extended only for the Pattern case; unrelated operand behavior is retained.

A public TextView stores its source descriptor and profile. Each operation prepares a current index once; `eachMatch` retains that prepared context through iteration. Results retain the source identity and their operation-specific context. A later operation can revalidate a changed source without overwriting an earlier result's index.

`hasPrefix` returns int 1/0 for a candidate starting at 0; `hasSuffix` returns int 1/0 for a candidate ending at source end from any valid start. Suffix testing includes later alternatives and overlapping starts, with the original source context and explicit `atomic` restrictions retained. Both accept Pattern or literal text. `wholeMatch` returns Maybe of the entire-source Match; `matches` returns the corresponding int 1/0. Text `replace` still returns new text and does not mutate source.

Sources and remaining integration duties: [REGEX_IMPLEMENTATION.md](patterns/LMX_Fn_Receivers/REGEX_IMPLEMENTATION.md).

### Callable adapters

The priority work is attempted in source: source-declaration policy is separate from type identity; omitted actuals have real deferred frame slots; defaults retain their lexical origin and full source DATA context. Partial application and currying preserve ordinary optional, required, and private behavior instead of replacing omission with a fabricated value. `uncurry` follows the actual signatures of intermediate callables. A zero-input step is called once; a final callable result is returned as a value.

The implementation requires five ordinary call-phase kernel entries, in addition to the existing reflection and execution boundary. Their interfaces are declared; their kernel bodies and four execution modes remain integration work. The adapter source is not reported as runtime-proven.

Sources and acceptance: [GENERIC_IMPLEMENTATION.md](patterns/LMX_Fn_Receivers/GENERIC_IMPLEMENTATION.md), [KERNEL_REQUIREMENTS.md](patterns/LMX_Fn_Receivers/KERNEL_REQUIREMENTS.md), and [ADAPTER_ACCEPTANCE.md](patterns/LMX_Fn_Receivers/tests/ADAPTER_ACCEPTANCE.md).
