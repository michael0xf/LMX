85 паттернов проектирования, не входящих в классический список GoF 23, сгруппированы по архитектурным уровням и снабжены ссылками на классические каталоги и репозитории с примерами кода (включая каталог Мартина Фаулера, Azure Architecture Center и открытую библиотеку Java Design Patterns).

1. Архитектурные паттерны (15 штук)

Определяют общую структуру приложения и взаимодействие между крупными подсистемами.
1. MVC (Model-View-Controller) — разделение данных, интерфейса и управляющей логики (Martin Fowler, Java Design Patterns).
2. MVP (Model-View-Presenter) — пассивное представление, вся логика UI вынесена в презентер (Martin Fowler, Java Design Patterns).
3. MVVM (Model-View-ViewModel) — связывание данных (data binding) между моделью представления и UI (Microsoft Learn, Java Design Patterns).
4. Flux / Redux — однонаправленный поток данных и единое иммутабельное состояние (Java Design Patterns).
5. Layered Architecture (Слоистая архитектура) — разделение системы на горизонтальные слои (UI, бизнес-логика, БД) (Microsoft Learn, Java Design Patterns).
6. Hexagonal Architecture (Ports and Adapters) — изоляция ядра бизнес-логики от внешних зависимостей через порты и адаптеры (Java Design Patterns).
7. Clean Architecture (Чистая архитектура) — концентрические слои с правилом зависимостей строго внутрь (Java Design Patterns).
8. Onion Architecture (Луковая архитектура) — доменная модель в центре, инфраструктура на периферии (Java Design Patterns).
9. Microservices (Микросервисы) — декомпозиция приложения на независимые развёртываемые сервисы (Microsoft Learn, Microservices.io).
10. Event-Driven Architecture (EDA) — взаимодействие компонентов через генерацию и обработку событий (Microsoft Learn, Java Design Patterns).
11. CQRS (Command Query Responsibility Segregation) — разделение моделей чтения и записи данных (Martin Fowler, Microsoft Learn).
12. Event Sourcing — хранение состояния системы в виде неизменяемого журнала событий (Martin Fowler, Microsoft Learn).
13. Pipe and Filter (Каналы и фильтры) — последовательная обработка потока данных через цепочку независимых фильтров (Microsoft Learn, Enterprise Integration Patterns).
14. Blackboard (Классная доска) — совместная работа независимых модулей над общим пространством данных (Java Design Patterns).
15. Microkernel (Микроядро / Plug-in) — минимальное ядро с расширяемой функциональностью через плагины (Java Design Patterns).

2. Корпоративные паттерны и работа с БД (22 штуки)

Классика из книги Мартина Фаулера Patterns of Enterprise Application Architecture (https://www.google.com/search?kgmid=%2Fm%2F06d5vs3&q=%D1%81%D0%BA%D0%BE%D0%BB%D1%8C%D0%BA%D0%BE+%D0%BF%D1%80%D0%B8%D0%BC%D0%B5%D1%80%D0%BD%D0%BE+%D1%81%D1%83%D1%89%D0%B5%D1%81%D1%82%D0%B2%D1%83%D0%B5%D1%82+design+patterns+%D0%B2+%D1%8F%D0%B7%D1%8B%D0%BA%D0%B0%D1%85+%D0%BF%D1%80%D0%BE%D0%B3%D1%80%D0%B0%D0%BC%D0%BC%D0%B8%D1%80%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F%3F+patterns+of+enterprise+application+architecture) (полный каталог PoEAA).
16. Repository (Репозиторий) — абстракция коллекции объектов над слоем доступа к данным (Martin Fowler, Java Design Patterns).
17. Unit of Work (Единица работы) — отслеживание изменений объектов в рамках транзакции и их пакетная запись (Martin Fowler, Java Design Patterns).
18. Data Mapper — слой преобразователей, полностью изолирующий доменные объекты от схемы БД (Martin Fowler, Java Design Patterns).
19. Active Record — объект, оборачивающий строку таблицы БД и содержащий как данные, так и логику (Martin Fowler, Java Design Patterns).
20. Table Data Gateway — объект, выступающий шлюзом ко всей таблице БД (Martin Fowler, Java Design Patterns).
21. Row Data Gateway — объект, представляющий одну конкретную запись в таблице БД (Martin Fowler).
22. DAO (Data Access Object) — интерфейс, скрывающий детали работы с конкретным хранилищем данных (Java Design Patterns).
23. DTO (Data Transfer Object) — объект для передачи данных между подсистемами без бизнес-логики (Martin Fowler, Java Design Patterns).
24. Domain Model (Модель предметной области) — объектная модель, объединяющая данные и сложную бизнес-логику (Martin Fowler).
25. Transaction Script (Сценарий транзакции) — организация бизнес-логики в виде процедур, каждая из которых обрабатывает один запрос (Martin Fowler).
26. Table Module — один экземпляр класса, обрабатывающий бизнес-логику для всех строк таблицы (Martin Fowler).
27. Service Layer (Слой сервисов) — определение границ приложения и набора доступных операций (Martin Fowler, Java Design Patterns).
28. Identity Map — кэш загруженных из БД объектов в рамках сессии для предотвращения дубликатов (Martin Fowler, Java Design Patterns).
29. Lazy Load (Ленивая загрузка) — отложенная загрузка связанных данных до момента первого обращения (Martin Fowler, Java Design Patterns).
30. Query Object — объект, представляющий SQL-запрос в объектно-ориентированном виде (Martin Fowler).
31. Specification (Спецификация) — инкапсуляция бизнес-правил в виде комбинируемых логических предикатов (Martin Fowler, Java Design Patterns).
32. Value Object (Объект-значение) — неизменяемый объект, равенство которого определяется его значениями, а не ID (Martin Fowler, Java Design Patterns).
33. Optimistic Offline Lock — проверка конфликтов версий при сохранении без блокировки записи в БД (Martin Fowler).
34. Pessimistic Offline Lock — явная блокировка записи в БД на время редактирования пользователем (Martin Fowler).
35. Front Controller — единый обработчик всех входящих HTTP-запросов приложения (Martin Fowler, Java Design Patterns).
36. Page Controller — отдельный обработчик для каждой конкретной страницы или действия сайта (Martin Fowler, Java Design Patterns).
37. Application Controller — централизованное управление навигацией и потоком экранов приложения (Martin Fowler).

3. Облачные и микросервисные паттерны (20 штук)

Решения для отказоустойчивости, масштабирования и интеграции в распределённых системах (из каталога Microsoft Azure Architecture).
38. Circuit Breaker (Автоматический выключатель) — разрыв цепи при частых сбоях удалённого сервиса для предотвращения каскадных отказов (Martin Fowler, Microsoft Learn).
39. Retry (Повтор) — автоматическая повторная отправка запроса при временных сетевых сбоях (Microsoft Learn, Java Design Patterns).
40. Bulkhead (Переборка) — изоляция пулов ресурсов между сервисами, чтобы сбой одного не уронил остальные (Microsoft Learn, Java Design Patterns).
41. Saga (Сага) — управление распределёнными транзакциями через цепочку локальных транзакций и компенсирующих действий (Microsoft Learn, Microservices.io).
42. API Gateway — единая точка входа для клиентов, маршрутизирующая запросы к микросервисам (Microsoft Learn, Microservices.io).
43. BFF (Backends for Frontends) — создание отдельных бэкенд-сервисов под нужды разных типов клиентов (Web, Mobile) (Microsoft Learn, Java Design Patterns).
44. Sidecar — развёртывание вспомогательных компонентов (логирование, прокси) в отдельном контейнере рядом с основным (Microsoft Learn, Java Design Patterns).
45. Ambassador (Посол) — вынесение клиентской сетевой логики (повторы, мониторинг, TLS) в локальный прокси-сервис (Microsoft Learn, Java Design Patterns).
46. Anti-Corruption Layer (ACL) — слой-транслятор между современной системой и устаревшим монолитом (Legacy) (Microsoft Learn, Java Design Patterns).
47. Strangler Fig (Душащий фикус) — постепенная миграция монолита на микросервисы путём поэтапной замены функциональности (Martin Fowler, Microsoft Learn).
48. Transactional Outbox — атомарная запись данных в БД и публикация события в брокер сообщений через промежуточную таблицу (Microservices.io, Java Design Patterns).
49. Cache-Aside (Ленивое кэширование) — загрузка данных в кэш приложением по требованию при промахе кэша (Microsoft Learn, Java Design Patterns).
50. Materialized View (Материализованное представление) — предвычисленная денормализованная проекция данных для быстрого чтения (Microsoft Learn).
51. Sharding (Шардирование) — горизонтальное разделение базы данных на независимые партиции (Microsoft Learn, Java Design Patterns).
52. Throttling (Троттлинг) — ограничение числа запросов к сервису для защиты от перегрузок (Microsoft Learn, Java Design Patterns).
53. Queue-Based Load Leveling — сглаживание пиковых нагрузок с помощью буферной очереди перед обработчиком (Microsoft Learn, Java Design Patterns).
54. Competing Consumers (Конкурирующие потребители) — параллельная обработка сообщений из одной очереди несколькими воркерами (Microsoft Learn, Enterprise Integration Patterns).
55. Leader Election (Выбор лидера) — координация распределённых узлов для выбора одного управляющего экземпляра (Microsoft Learn, Java Design Patterns).
56. Health Endpoint Monitoring — предоставление специальных эндпоинтов для проверки жизнеспособности сервиса (Microsoft Learn, Microservices.io).
57. Claim Check — передача тяжёлых данных через внешнее хранилище с отправкой в очередь только ссылки-квитанции (Microsoft Learn, Enterprise Integration Patterns).

4. Паттерны многопоточности и асинхронности (14 штук)

Шаблоны безопасной работы с потоками, блокировками и параллельными вычислениями.
58. Thread Pool (Пул потоков) — переиспользование заранее созданного набора потоков для выполнения множества задач (Java Design Patterns).
59. Producer-Consumer (Производитель-Потребитель) — разделение генерации и обработки данных через потокобезопасную очередь (Java Design Patterns).
60. Actor Model (Модель акторов) — изоляция состояния внутри акторов, общающихся только асинхронными сообщениями (Java Design Patterns).
61. Active Object — отделение вызова метода от его выполнения в собственном потоке управления (Java Design Patterns).
62. Reactor — событийно-ориентированный демультиплексор для обработки множества I/O-запросов в одном или нескольких потоках (Java Design Patterns).
63. Proactor — асинхронная обработка событий, при которой операционная система сама завершает I/O-операцию перед вызовом обработчика (Java Design Patterns).
64. Future / Promise — объект-заглушка для результата асинхронной операции, который станет доступен в будущем (Java Design Patterns).
65. Read-Write Lock — разрешение одновременного чтения множеству потоков при эксклюзивной блокировке на запись (Java Design Patterns).
66. Double-Checked Locking — минимизация накладных расходов на синхронизацию при ленивой инициализации (Java Design Patterns).
67. Guarded Suspension — приостановка выполнения потока до тех пор, пока не выполнится определённое условие (Java Design Patterns).
68. Balking — немедленный отказ от выполнения действия, если объект находится в неподходящем состоянии (Java Design Patterns).
69. Thread-Local Storage (TLS) — хранение данных, изолированных индивидуально для каждого потока (Java Design Patterns).
70. Monitor Object — синхронизация доступа к методам объекта с помощью мьютекса и условных переменных (Java Design Patterns).
71. Half-Sync / Half-Async — разделение системы на асинхронный слой ввода-вывода и синхронный слой бизнес-логики (Java Design Patterns).

5. Идиомы ООП, управления зависимостями и функционального стиля (14 штук)

Паттерны уровня классов и функций, дополняющие базу GoF в повседневной разработке.
72. Dependency Injection (Внедрение зависимостей) — передача зависимостей объекту извне вместо их создания внутри (Martin Fowler, Java Design Patterns).
73. Service Locator — центральный реестр, предоставляющий ссылки на нужные сервисы по запросу (Martin Fowler, Java Design Patterns).
74. Null Object (Пустой объект) — замена null специальным объектом с нейтральным поведением по умолчанию (Martin Fowler, Java Design Patterns).
75. Object Pool (Пул объектов) — переиспользование дорогостоящих в создании объектов (например, соединений с БД) (Java Design Patterns).
76. Simple Factory (Простая фабрика) — статический метод или отдельный класс для инкапсуляции логики создания объектов (Java Design Patterns).
77. Multiton (Мультитон) — расширение Singleton, управляющее словарём именованных экземпляров (Java Design Patterns).
78. Marker Interface (Маркерный интерфейс) — пустой интерфейс для добавления метаданных классу во время компиляции или рантайма (Java Design Patterns).
79. Fluent Interface (Текучий интерфейс) — проектирование API через цепочку вызовов методов для читаемости кода (Martin Fowler, Java Design Patterns).
80. Type Object — замена жёсткой иерархии подклассов динамическим объектом-типом (Game Programming Patterns, Java Design Patterns).
81. Extension Object — добавление новых интерфейсов объекту без изменения его исходного класса (Java Design Patterns).
82. Monad (Монада) — функциональный контейнер для выстраивания цепочек вычислений с контекстом (ошибки, асинхронность) (Java Design Patterns).
83. Trampoline (Батут) — оптимизация хвостовой рекурсии в циклах для предотвращения переполнения стека (Java Design Patterns).
84. Execute Around — обёртывание пользовательской лямбда-функции в шаблонный код открытия и закрытия ресурсов (Java Design Patterns).
85. Currying (Каррирование) — преобразование функции от многих аргументов в цепочку функций от одного аргумента (Java Design Patterns).
