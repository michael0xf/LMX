# Q35. Ход L3-потока: пустое тело — успех или отказ; ответ нативного обработчика — статус хода или его дело

Состояние: 2026-09-26, открыт (Opus, дефект D-90 в `steps/defects.md`; замер §GATE «нет скрытого fallback», `steps/gate-fallback-audit-20260926.md`). Ответ — сюда или в чат; закрытый файл переносится в `LMX_blog/q/`. Пункт §GATE о fallback закрывается только после этого ответа.

## Факт

Ход потока: `dev/l2src_sandbox/lmx_thread.lm1` :557–:561. Когда привязан L3 (`l3_thread_bind` ставит `lmx_call_install_walk_status`, `dev/l3_interp/l3_thread.lm1` :348, :383), результат `lmx_call0(arena, graph)` читается как статус хода:

```text
st: lmx_call0(arena, graph)
if: lmx_call_walk_returns_status() != 0
    if: st = c.LMX_CALL_NOT_CALLABLE      # 2
        return: c.LMX_TURN_BODY_OK        # 0
    return: st
```

`lmx_call0` (`lmx_call.lm1` :106–:142) даёт два разных рода чисел:

- граф без нативного слова (или не Structure) уходит в обходчик L3 (`l3_thread_call0_walk`), и тот возвращает статус `LMX_INTERP_*`: OK 0, INVALID 1, **NO_GRAPH 2** (у callable нет узла тела — `lmx_walk.h.lm1` :181), NOT_CALLABLE 4;
- граф с нативным словом зовёт трамплин и возвращает **значение** обработчика (int), а его статус броска кладёт отдельно (`lmx_call_note_walk_fail`).

Поэтому ветка «2 → успех» ловит два разных случая: `LMX_INTERP_NO_GRAPH` (тоже 2) и нативное значение 2. Любое другое нативное значение становится статусом хода: обработчик, вернувший 1, проваливает ход. Без привязки L3 это не так — там значение игнорируется, и ход проваливают флаги Message или статус броска (модель 31, комментарий :535–:540: «ответ обработчика — его дело и не переосмысляется»). Кода `LMX_CALL_NOT_CALLABLE` обходчик L3 не возвращает вообще.

## Вопрос

1. У L3-потока граф хода — callable **без тела** (`NO_GRAPH`). Это пустой ход — успешный (как пустая программа), или отказ хода?
2. Если у графа L3-потока есть нативное слово, его возвращённое значение — статус хода или, как без L3, «дело обработчика» (модель 31), а ход проваливают только флаги Message и статус броска?

## Рекомендация Opus

П.2 — модель 31 без исключения: в режиме статуса различать путь нативного слова (значение не читать; провал — по статусу броска, как без L3) и путь обходчика (читать `INTERP_*`). П.1 — по ответу автора: либо `NO_GRAPH` → `LMX_TURN_BODY_OK` явно, по имени этого кода, либо отказ хода. В обоих случаях ветка сравнивает с кодом обходчика, а не с `LMX_CALL_NOT_CALLABLE`, и получает свидетеля-селфтест хода с пустым телом и с нативным словом, возвращающим 2 и 1; мутант — сегодняшняя ветка.

## Мнение fable_pc (2026-09-27, REVIEW ffdcde0)

По п.2 согласен с рекомендацией Opus: значение нативного обработчика — его дело (модель 31 без исключения), статус хода — только по каналу статуса броска, как без L3; путь обходчика читает `INTERP_*`. По п.1 рекомендую отказ: callable без тела у графа хода — не пустая программа, а нарушенное обещание, и успех здесь был бы тем же скрытым fallback, что D-90. Решение — автора; до ответа `LMX_TURN_BODY_OK` для `NOT_CALLABLE`/`NO_GRAPH` остаётся дефектом D-90 OPEN.
