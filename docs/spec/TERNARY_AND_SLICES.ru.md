# Условное выражение и срезы последовательностей

Редакция 26 ноября 2026. Нормативное дополнение к общей грамматике и семантике Expression. Реализации нормализации и вычислительного договора приведены в [проверочной модели](tools/ternary_slices_reference.py); её исполнение проверено отдельно от парсера, транслятора и runtime LMX. Статусы последней группы остаются **NOT_RUN**.

<a id="conditional"></a>
## 1. Условное выражение `condition ? yes : no`

`?:` — каноническое имя одной условной операции с двумя разделёнными ветвями. Её запись в Expression — `condition ? yes : no`; ресиверная запись — `` `?:`(condition; yes; no) ``. Обе формы используют одно тело выбора и обычный механизм получения RAW-вхождений с их живым контекстом. Это не вызов обычной eager-функции с тремя уже вычисленными значениями.

Условие получается ровно один раз и принимается тем же договором истинности, что `if`: `int` 0 — ложь, ненулевое значение — истина. Затем ровно один раз получается только выбранная ветвь. Невыбранная ветвь не вызывает функции, не выполняет присваивания и не порождает динамические исходы. Проверка структуры и доступных статических договоров обеих ветвей не исполняет их. Общий `throws` учитывает потенциальные исходы условия и обеих ветвей; отсутствие исполнения одной ветви не разрешает скрывать исходы другой при статическом описании метода.

Результат — целое обычное значение выбранной ветви, с её ссылочной идентичностью и договором жизни. Массив не раскрывается в поток элементов, не копируется и не превращается в маску. Совместимость результата с принимающей позицией определяется обычным допуском; безусловного приведения разных типов ветвей к `int` или `double` нет.

Приоритет слабее `||`, но сильнее `:=`, `.:` и `::`; направление связывания — справа. Используется готовый `sys\priority("?:")` на общей шкале. Конкретное числовое кодирование шкалы остаётся общим для всех операндов. P0 сохраняет условные разделители и внешний структурный контекст. Конечные RAW-границы ветвей определяют общий группировщик и обычная подготовка применения, сохраняя LeftView, максимум один левый атом и зависимости получения значений. Их нельзя получить простым отсечением всех более слабых операндов: действует та же политика, что для `1 + v := 2 + 3`. Для демонстрации присваивания внутри ветви ниже дана явно ограниченная группа; непроверенное чтение сокращённой формы без неё не устанавливается. Присваивание сохраняет обычный договор места, без исключения для `:=`.

```lmx
return: count > 0 ? total / count : 0
return: flag ? first : second ? other : fallback
return: flag ? (x := first) : (x := second)
return: `?:`(flag; first; second)
```

Вторая строка означает `flag ? first : (second ? other : fallback)`. В третьей выполняется одно выбранное присваивание. Операнд получает ровно одно левое вхождение условия и два правых RAW-вхождения ветвей. Общий публичный заголовок содержит `left`, числовой `depth`, `right`, затем константные `PASS_ARGS_AS_IS` и `PRIORITY`; условная форма не добавляет собственных полей. Обычное применение имеет depth=0 и режим 1. Выражение глубины получают только при востребованности: невыбранная ветвь не даёт и эффектов depth; см. [общую норму](OPERATOR_DEPTH.ru.md#evaluation). Обычная форма операнда без `left` остаётся отдельной формой подачи; разрешать её или переупорядочивать аргументы может только метод, а не группировщик. Ресиверная адаптация передаёт три явно названные роли одному телу.

<a id="colon-contexts"></a>
## 2. Три роли двоеточия

P0 сохраняет исходные вхождения и связывает разделители по структурной вложенности, без поиска имён и вычисления значений. Он не превращает `yes:` в Frame, если это двоеточие закрывает ожидающий `?` на том же уровне. Вложенные bounded-формы и уже сформированные Frames имеют собственный уровень. Двоеточие связывается с ближайшим незакрытым `?` данного уровня; поэтому вложенность обеих ветвей однозначна.

| Форма | Роль двоеточия |
| --- | --- |
| `print: value` | Обычный разделитель head/body |
| `Name :: int -> int` | Один токен операнда `::` |
| `flag ? first : second` | Разделитель ветвей одного `?:` |
| `values[start:stop:step]` | До двух разделителей полей одного среза |
| `values[::2]` | Два разделителя среза и пропущенные start/stop |
| `values[(flag ? 1 : 2):6]` | Вложенное условие и внешний разделитель среза |
| `values[flag ? 1 : 2:6]` | То же разделение: первое `:` принадлежит `?`, второе — срезу |

В индексном суффиксе его верхнеуровневое `::` означает два разделителя среза; там оно не захватывается токеном сигнатуры. Внутри вложенной группы действует обычный контекст, включая `::`. Вне индексного суффикса токен сигнатуры остаётся прежним. Текст и exact-идентификаторы защищают свои символы как раньше. Составные токены `.:` и `:=` распознаются раньше одиночного двоеточия и не становятся разделителями; `.=` — поэлементное сравнение, не присваивание.

Если ветви требуется собственная короткая colon-форма, её нужно ограничить группой, например `flag ? (f: x) : (g: y)`, либо использовать компактный вызов `flag ? f(x) : g(y)`. Иначе двоеточие текущего уровня уже имеет роль разделителя условной формы. Незакрытый `?`, отсутствующая ветвь и лишний разделитель — ошибки подготовки до эффектов. Текстовые двоеточия обрабатывает P0; группировщик получает структурные границы и исходные ссылки и не ищет скобки в тексте. Такое же применение можно построить обычными графовыми средствами без текстового источника.

<a id="slice-contract"></a>
## 3. Срез `[start:stop:step]`

После значения последовательности индексный суффикс с одним или двумя разделителями двоеточиями означает срез. Все три поля могут быть явно пропущены. Отсутствие поля — самостоятельное состояние описания, а не ноль, `-1`, пустая Structure, null или запрос на динамическое автозаполнение.

`source[start:stop]` имеет шаг 1. Положительный шаг выбирает индексы меньше stop, отрицательный — больше stop; конечная граница не включается. Явная отрицательная граница считается от конца и затем ограничивается допустимым диапазоном. Границы вне диапазона обрезаются; нулевой шаг отвергается с `SequenceStep`.

| Случай | start по умолчанию | stop по умолчанию | Диапазон нормализованных явных границ |
| --- | --- | --- | --- |
| `step > 0` | 0 | length | От 0 до length |
| `step < 0` | length − 1 | −1 как исключённая граница | От −1 до length − 1 |

Пропущенный stop при отрицательном шаге принципиально отличается от явно записанного `-1`: `a[::-1]` выбирает всю последовательность в обратном порядке, а `a[:-1:-1]` пуст. Пустая последовательность, равные нормализованные границы и шаг, направленный от stop, дают пустой результат. Арифметика границ и числа элементов выполняется точно: отрицательная граница не превращается в большое unsigned-значение, а промежуточное переполнение не допускается. Допустимость размера и выделения проверяется до построения результата.

Исходная последовательность получается один раз. Затем присутствующие start, stop и step получаются по одному разу в записанном порядке. Длина и фактическое хранилище исходного объекта читаются после эффектов этих выражений. Нельзя сохранить сырой указатель на backing до вычисления границ и использовать его после возможного resize. Исходная ссылка, тип элементов, допустимость чтения и жизнь объекта следуют обычным правилам LMX.

<a id="slice-values"></a>
## 4. Значение, место и ранги

В позиции VALUE срез возвращает новый внешний контейнер с фактическим профилем хранения исходной последовательности. Численные элементы остаются плотными значениями своего типа; элементы `[]@` сохраняют исходные ссылки. Их цели и `parent` не копируются и не меняются. Текст `[]char` режется в единицах его элементов, без неявного Unicode-декодирования. Это обычное значение Array, не новый скрытый вид массива и не постоянное представление для исполнения.

В позиции назначения `.:` тот же выбор индексов обозначает настоящие места исходной последовательности. План выбора принадлежит одной операции. Все нужные правые значения получают до первой записи, поэтому перекрытие корректно, включая `a[::-1] .: a`. Число/shape элементов и допуск записей проверяются до первого store; размер назначения не меняется. Если эффекты подготовки правой стороны изменили shape назначения относительно выбранных мест, операция отказывает до записи. Обычные запреты `const`/`immutable`, владение и фактический stride сохраняются.

```lmx
(a b c) .: (b c a)
values[1:5:2] .: (8 9)
values[::-1] .: values
```

Первая строка — та же поэлементная операция над Structure, то есть массивом элементов свободного типа. Правая последовательность получается до записи; результат перестановки не зависит от порядка store. Общий механизм current-level consumption и упаковки одного `left` остаётся прежним. Нового «tuple»-типа нет. Скалярное `x := value` сохраняет свой отдельный договор. Срез не вводит Python-подобного изменения длины через `:=`: для изменения размера остаются явные `replaceRange`/`splice`.

Один суффикс `array[start:stop:step]` выбирает плоскую последовательность по
общему length при любом rank; новый результат этой плоской выборки имеет
одну ось, исходные rank/extents сохраняются. Цепочка соседних суффиксов
со срезами выбирает сохранённые оси: скаляр снимает ось, срез оставляет её
с новой длиной, неупомянутые оставшиеся оси сохраняются. `matrix[1:3][::-1]`
выбирает строки 1 и 2 и обращает столбцы; `matrix[i][:]` явно выбирает строку.
Один `matrix[i]` остаётся линейным элементом, а не неявным Array строки.
Используются настоящие extents/strides, без вывода формы из первого элемента.
`struct[i]\[j]` использует обычный путь по полям Structure: он соответствует
`struct\struct2\field`, когда i и j выбирают эти поля. Дополнительный шаг
`struct[i]\[j]\[k]` соответствует `struct\struct2\field[k]`.
Отдельного механизма вложенных контейнеров нет. `s\[N]field` сохраняет
собственный смысл выбора N-го одноимённого поля. [Полный договор хранения](ARRAY_STORAGE.ru.md#indexing).

Полная цепочка только скалярных координат сохраняет прежний договор:
сначала row-major сведение, затем проверка итогового элемента по length,
без новых верхних границ каждой координаты. При extents `[2,3]` доступы
`a[0][3]` и `a[1][0]` дают k=3. Нормализация выбранных осей среза —
отдельный принимающий договор и не заменяет эту скалярную проверку.

<a id="slice-receiver"></a>
## 5. Одно имя `slice`, два явных договора

Суффикс использует общий профиль `slice(source; spec)`. `spec` — обычная Structure с независимо присутствующими start/stop/step; её явно переданное описание не дополняется одноимёнными переменными вызывающего. Отсутствие можно физически представить обычными признаками присутствия и неинициализированными полями; читать payload отсутствующего поля нельзя. Это описание аргумента операции, не второй граф программы.

У вызова `slice(source; spec)` обе роли — **VALUE/VALUE**: `spec` является
готовым значением Structure, а не объявлением DATA. RAW-вхождения source и
границ сохраняются при подготовке суффикса только до их обычного получения.

Существующий `slice(source; begin; end)` остаётся строгим профилем: `0 <= begin <= end <= length`, без clipping и без интерпретации отрицательных границ от конца. Неподходящие границы дают `ReceiverIndex`. Два профиля имеют один общий обход уже выбранных индексов и построение результата; различается только явная политика получения плана. Это перегрузка одного канонического имени, не второе имя-алиас и не копия алгоритма.

Нормализация `SliceSpec` задаёт start, stop, step и count. Для положительного шага непустой count равен `1 + (stop - start - 1) div step`; для отрицательного — `1 + (start - stop - 1) div (-step)`. Пустой случай проверяется до деления. Обход выполняет ровно count чтений и не вычисляет следующий индекс после последнего элемента.

<a id="negative-index"></a>
## 6. Отрицательный скалярный индекс и L2

Корректный скалярный индекс Array — целый индекс в его допустимых границах, начиная с нуля. `values[-1]` не означает последний элемент и не является допустимым доступом. Заведомо отрицательное значение диагностируется при подготовке; вычисленный индекс проверяется при исполнении L3 и при интерпретации **обоих** уровней L2/L3. Минус в индексном выражении сам по себе не запрещён: `values[-offset]` может быть корректен, когда полученный индекс допустим.

Нативное L2-исполнение не добавляет автоматической проверки границ. Это не делает отрицательный или иной выходящий за границы Array-индекс корректным и не добавляет отсчёт с конца. Если нужна операция смещения назад от уже имеющегося адреса, её следует выразить через указатель и соблюдать общий договор адресов:

```lmx
L2:
    []int: values [10 20 30]
    @int: p @values[1]
    int: previous \(p - 1)
```

Здесь `p - 1` смещается к предыдущему элементу в том же допустимом хранилище; это не `values[-1]`. Такой способ нужен, в частности, потому, что интерпретация L2 всё равно проверяет границы Array. Адрес не даёт права выйти за выделенный объект, нарушить выравнивание, жизнь или защиту памяти.

Отрицательные числа в срезах имеют другой, явно заданный договор: `values[-1:]` выбирает последний элемент в виде одноэлементного Array, `values[:-2]` исключает два последних, `values[-4:-1]` выбирает соответствующий полуоткрытый диапазон.

<a id="receiver-algorithms"></a>
## 8. Тела ресиверов и границы реализации

Ниже алгоритмический псевдокод, а не новый синтаксис LMX. `obtainValue`,
`admitIfCondition`, `readElement` и `allocateLike` обозначают места подключения
существующих механизмов namespace, допуска `if`, доступа Array и выделения с
полным профилем хранения. Это не новые системные функции или kernel-заглушки.
Исполнимые тела host-модели находятся в
[`ternary_slices_reference.py`](tools/ternary_slices_reference.py).

### Одно тело условного выбора

```text
conditionalMethod(conditionOccurrence, yesOccurrence, noOccurrence):
    condition = obtainValue(conditionOccurrence, его исходный контекст)
    admitIfCondition(condition)
    selected = yesOccurrence если condition != 0, иначе noOccurrence
    return obtainValue(selected, его исходный контекст)
```

Входы — RAW-вхождения, а не готовые значения. В `a ? b : c` метод получает
условие через единственный `left`, ветви через два `right`; ресивер `` `?:` ``
предоставляет те же три роли. Ни группировщик, ни адаптер не получают значение
невыбранной ветви. Результат сохраняет идентичность выбранного значения.
Статическая проверка договоров ветвей не запускает их тела.

### Получение описания и единый путь выдачи

```text
prepareSliceSuffix(sourceOccurrence, boundOccurrences, receivingRole):
    source = obtainValue(sourceOccurrence, его исходный контекст)
    для каждого поля start, stop, step в этом порядке:
        если поле отсутствует: сохранить absence, не читать payload
        иначе:
            value = obtainValue(вхождение поля, его исходный контекст)
            немедленно проверить целый тип value
            сохранить presence и value
    shape = фактический shape(source)  # после эффектов всех границ
    plan = normalizeSlice(выбранная длина оси, явное описание границ)
    return consumeSelection(source, shape, plan, receivingRole)

slice(source, explicitSpec):
    # source и присутствующие поля уже получены обычным механизмом вызова.
    shape = фактический shape(source)
    plan = normalizeSlice(выбранная длина оси, explicitSpec)
    return consumeSelection(source, shape, plan, VALUE)

slice(source, begin, end):
    N = фактическая длина source
    проверить целые begin/end и 0 <= begin <= end <= N
    plan = (start=begin, stop=end, step=1, count=end-begin)
    return consumeSelection(source, фактический shape(source), plan, VALUE)
```

Присутствие поля проверяется в `explicitSpec`, без запроса одноимённого поля
из другой динамической области. Ошибка типа ранней границы останавливает
получение последующих границ. Backing не захватывается до эффектов границ;
вызов и суффикс используют один алгоритм после получения описания.

### Нормализация Python-like профиля

```text
normalizeSlice(N, spec):
    проверить N >= 0
    s = spec.step, если присутствует; иначе 1
    если s = 0: отказ SequenceStep
    (low, high) = (0, N), если s > 0; иначе (-1, N-1)

    normalizeBound(present, value, default):
        если не present: return default
        если value < 0: value = N + value
        return min(high, max(low, value))

    a = normalizeBound(spec.hasStart, spec.start, 0 если s > 0, иначе N-1)
    b = normalizeBound(spec.hasStop, spec.stop, N если s > 0, иначе -1)
    если s > 0:
        count = 0, если a >= b; иначе 1 + (b-a-1) div s
    иначе:
        count = 0, если a <= b; иначе 1 + (a-b-1) div (-s)
    проверить count и размер результата до выделения
    return (start=a, stop=b, step=s, count=count)
```

Промежуточная арифметика точная и знаковая: `-s` при минимальном машинном
значении не должен переполняться. Условная запись `spec.start` не разрешает
читать отсутствующий payload: проверка presence выполняется до чтения.
Omitted stop возвращает default `-1` до преобразования отрицательной явной
границы, поэтому он отличается от записанного `-1`.

### Общая выдача и запись

```text
consumeSelection(source, sourceShape, plan, VALUE):
    result = allocateLike(source, shape с длиной выбранной оси plan.count)
    index = plan.start
    для position от 0 до plan.count-1:
        result[position] = readElement(source, index)
        если position+1 < plan.count: index = index + plan.step
    return result

consumeSelection(source, sourceShape, plan, PLACE):
    return временный выбор исходных мест (source, sourceShape, plan)

elementwiseStore(selectedPlaces, incoming):
    получить и сохранить все необходимые правые значения
    проверить неизменность shape назначения, число/shape и допуск записей
    записать сохранённые значения в выбранные исходные места
    вернуть назначение по обычному договору результата .:
```

Цикл не читает элемент пустого результата и не прибавляет шаг после последнего
чтения. Для нескольких осей используется композиция из §4 и общий обход shape;
этот одномерный алгоритм не означает flatten матрицы. `readElement` сохраняет
ссылки и `parent`; VALUE выдаёт отдельный внешний Array. PLACE не выделяет
пользовательскую копию Array. Если единственный RHS — возвращённый Array,
его непосредственные элементы выбирает `.:`; три соседних Array остаются
тремя элементами. Группировщик не исполняет и не раскрывает результат вызова.

## Источники заимствованной политики

Правила пропусков, обрезания границ и знака шага сопоставлены с первичными [Python sequence types](https://docs.python.org/3/library/stdtypes.html#common-sequence-operations) и [Python slicing syntax](https://docs.python.org/3/reference/expressions.html#slicings). LMX заимствует именно указанный договор срезов; отрицательные скалярные индексы Python, изменение длины присваиванием срезу и другие свойства Python из этого не следуют.
