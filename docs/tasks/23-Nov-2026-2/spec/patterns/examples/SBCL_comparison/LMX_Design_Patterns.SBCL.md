# Характерные приёмы Common Lisp / SBCL и их LMX-варианты

## Последовательности

- [S01. MAPCAR: преобразование списка](S01_comparision.md): Умножить каждый элемент конечного списка целых на 3; сохранить порядок, вход не менять. Числа и промежуточные результаты помещаются в LMX int.
- [S02. REMOVE-IF-NOT: устойчивый отбор](S02_comparision.md): Оставить положительные целые в исходном порядке; ноль не проходит. Вход не меняется; независимость хранения результата от входа не требуется.
- [S03. REDUCE: левая свёртка](S03_comparision.md): Вычесть слева направо все элементы из начального значения 20; пустой список возвращает 20.
- [S04. MAPCAR по двум спискам](S04_comparision.md): Попарно умножить элементы двух списков; остановиться на конце более короткого. Порядок сохраняется, входы не меняются.
- [S05. SOME и EVERY: короткое замыкание](S05_comparision.md): Двумя независимыми проходами проверить наличие положительного элемента и положительность всех элементов. Вернуть [any, число вызовов any, all, число вызовов all]; логические значения нормализованы в 0/1. Порядок вызовов слева направо.
- [S06. POSITION-IF: первый подходящий индекс](S06_comparision.md): Вернуть индекс первого отрицательного целого, начиная с нуля, либо -1 при отсутствии. Вход не меняется.
- [S07. STABLE-SORT: ключ и устойчивость](S07_comparision.md): Стабильно отсортировать пары [целый ключ, строковая метка] по ключу. Сохранить порядок равных ключей и значения входа; пары не изменять.
- [S08. REMOVE-DUPLICATES: сохранить первые](S08_comparision.md): Убрать повторные целые, сохранив первое вхождение каждого значения и исходный порядок первых вхождений. Вход не меняется; идентичность результирующего контейнера не входит в контракт.
- [S09. REPLACE: ограниченный диапазон](S09_comparision.md): Заменить диапазон [start,end) в копии списка. 0 <= start <= end <= длина; длина replacement равна end-start. Размер результата неизменен; оба входных списка не меняются. Выход за эту область не сравнивается.

## Вызовы и окружения

- [S10. Замыкание add5](S10_comparision.md): Фабрика make-adder захватывает любое целое first и возвращает унарную функцию. Пример создаёт add5 и применяет её к value; захват живёт после возврата фабрики.
- [S11. APPLY: сумма аргументов из списка](S11_comparision.md): Просуммировать конечный список целых; пустой список даёт 0. Размер входа ниже CALL-ARGUMENTS-LIMIT установленной реализации; сумма помещается в LMX int.
- [S12. Ключевые аргументы и значение по умолчанию](S12_comparision.md): Функция area имеет width=1 и height=1 по умолчанию. Вернуть [area с явно переданными width,height в обратном порядке; area только с width]. Нулевые размеры не равны отсутствию аргумента.
- [S13. Динамическая переменная SPECIAL](S13_comparision.md): read-scaled читает текущий scale без отдельного аргумента scale. Внутри динамического связывания factor вернуть value*factor; затем value*2, подтверждая восстановление внешнего связывания. Сравниваются этот путь чтения и восстановление, не все правила окружений.
- [S14. LABELS: локальная рекурсия](S14_comparision.md): Вычислить n! для целого 0<=n<=12. Локальный рекурсивный helper принадлежит вызову example; нет глобального изменяемого счётчика.
- [S23. Мемоизация через HASH-TABLE](S23_comparision.md): Внутри одного вызова example кешировать квадрат целого по EQL-ключу. Вернуть [список квадратов в порядке запросов, число фактических вычислений]. Повтор нуля должен попадать в кеш. Кеш свежий для каждого example, не разделяется между потоками.

## Данные и структуры

- [S15. Несколько возвращаемых значений](S15_comparision.md): Для целого n>=0 и целого divisor>0 вернуть [quotient,remainder], где n=quotient*divisor+remainder и 0<=remainder<divisor. Числа помещаются в LMX int.
- [S16. DESTRUCTURING-BIND: вложенная форма](S16_comparision.md): Получить структуру ровно [a,[b,c]] и вернуть a+b*c. Неподходящая форма находится вне этой пары; автоматическое рекурсивное раскрытие аргумента LMX не предполагается.
- [S18. CLOS: общий вызов для разных объектов](S18_comparision.md): Создать прямоугольник width,height и квадрат side; вызвать общий area у каждого и вернуть [width*height,side*side]. Поля и методы не подменяются вычислением в драйвере. Эта пара не реализует всю систему CLOS, множественную диспетчеризацию или method combination.
- [S19. CLOS: изменяемый слот и сохранение полей](S19_comparision.md): Создать прямоугольник width,height, изменить только width на new-width через accessor и вернуть [width,height,area]. Высота сохраняется и участвует в результате.

## Управление вычислением

- [S17. LOOP: условное накопление](S17_comparision.md): Сложить квадраты нечётных целых из списка; пустой вход даёт 0. Отрицательные нечётные числа тоже включаются. Вход не меняется.
- [S20. Макрос: вычислить форму ровно один раз](S20_comparision.md): Связать результат producer один раз, использовать его дважды в теле и вернуть [двойное значение, число вызовов producer]. Макрос показывает синтаксическое связывание, но сравнение ограничено этим эффектом; это не реализация произвольного MACROEXPAND в LMX.
- [S21. Условие и HANDLER-CASE](S21_comparision.md): Функция checked удваивает неотрицательное целое, а для отрицательного сигналит конкретное условие input-failure. Example перехватывает только это условие и возвращает 99. Возобновляемые restart-сценарии не включены.
- [S22. UNWIND-PROTECT: полный жизненный цикл](S22_comparision.md): Ресурс содержит value=42 и width=8. Acquire/action/release добавляют 1/2/3 к десятичному trace. Mode 0: успех [50,123]; 1: сбой action [-2,123]; 2: сбой acquire [-1,1] без release; 3: сбой release [-3,123]; 4: action и release ошибаются, побеждает release [-3,123]. Вызовы и cleanup выполняются ровно по одному разу.

## Message и потоки

- [S24. SBCL: очередь сообщений и отдельный поток](S24_comparision.md): Один producer посылает конечный список целых одному worker в FIFO mailbox, затем маркер :STOP. Worker суммирует числа и завершает работу. Хост создаёт mailbox/thread и ожидает результат; профиль гарантирует локальную доставку и отсутствие внешнего прерывания. Это не сравнение таймаутов, отказоустойчивости или разделяемой памяти.
