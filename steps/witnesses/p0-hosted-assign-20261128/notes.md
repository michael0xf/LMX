# Адресный отказ атома `:=` в понижении типов размещённого пути: срез грамматики (28 ноября 2026 года)

Ведущий `coder`. Поручение Sol (08:26, `SOL-CODER-V3-RESUME-20261129`): после публикации среза однострочной формы
сделать отдельным небольшим срезом адресную диагностику размещённого пути для атома `:=` — «конкретная причина вместо
“unsupported body”, не новое правило исполнения»; текст — как у построителя графа. Проверки адресные, по политике
компонентной сборки. База: набор `coder-depthline03` (`84c96da36`). План: этап 1, переходный критерий (5)
([очередь](../../../next_core_tasks_v3.md#grammar-complete-20261127)).

## Норма

- `docs/spec/LMX_grammar.ru.md:61`, `:424`: непустая ограниченная Structure перед `:=` — левая часть записи; P0
  сохраняет группу, роль выбирает потребитель.
- До среза размещённый путь (P0 → `lm_p0_lower_types` → L1) отказывал форме общими словами ядра frontend
  («unsupported body», `detail: atom=:=`).

## Что сделано

- **Одно условие в `lm_p0_lower_types_node` рядом с отказом для `?`.** Атом ровно из двух байтов `:=` (сравнение как
  написано) отказывает кодом 6 на своём диапазоне: «bare := requires its Expression projection». Это покрывает и
  голый префиксный токен. Чистый P0 не меняется; Frame ASSIGN обычной записи (`a := b`) и именованного фактического
  аргумента (`f(x := y)`) — Frame, не атом; точное имя держит кавычки; строка остаётся данными.
- Больше ничего не менялось: правило исполнения не вводится, L1 не выдаётся. Десять строк одного модуля.
