# LMX: Архитектура и границы компонентов

Java представляет явные интерфейсы, классы и модульную серверную разработку; Go — композицию функций и небольшие сервисные контракты. Пара позволяет проверить, требует ли паттерн иерархии классов или достаточно одинаковых границ и эффектов.

Все 11 исходных позиций сохранены. Layered, Hexagonal, Clean и Onion перекрываются по приёмам, но различаются акцентом на направления зависимостей. Message служит владельцем изменяемого состояния. Microservices/EDA/Strangler учитывают описанный HTTP и Message transport; их листинги показывают ядро и точные порты, а не обещают реализованную инфраструктуру.

## Каталог

### 005. [Layered Architecture](005_layered_architecture_comparision.md)

Представление вызывает прикладной слой, а тот — слой данных.

**Сценарий:** Вычислить стоимость трёх единиц товара с ценой 10 через три явно разделённых слоя.

**Наблюдение:** 30.

Короткий пример показывает зависимость application от concrete data; это намеренно отличается от инверсии зависимостей следующих трёх паттернов.

### 006. [Hexagonal Architecture (Ports and Adapters)](006_hexagonal_architecture_comparision.md)

Прикладное ядро получает внешние зависимости через порты.

**Сценарий:** Одно ядро вычисляет стоимость двух единиц с адаптерами цены 10 и 12.

**Наблюдение:** 20 + 24 = 44; ядро не меняется при замене адаптера.

Во всех языках порт имеет контракт ()→int и вызывается один раз. Функционального порта достаточно; отдельный класс адаптера здесь необязателен.

### 007. [Clean Architecture](007_clean_architecture_comparision.md)

Политика предметной области и use case отделены от внешнего представления.

**Сценарий:** При доходе 100 и расходах 60 правило требует остаток не менее 30; внешний presenter переводит решение в код 200.

**Наблюдение:** 200; при доходе 70 и расходах 60 — 422.

Важна направленность зависимостей к policy/use case. Один файл показывает связи; отсутствие ссылок внутрь UI проверяется по выделенным модулям реального проекта.

### 008. [Onion Architecture](008_onion_architecture_comparision.md)

Доменная сущность находится в центре; прикладная операция использует внешний порт сохранения.

**Сценарий:** Сохранить Order(quantity=3, price=10) через переданный репозиторий и получить доменный total.

**Наблюдение:** 30; сохранён именно переданный объект заказа.

Сценарий подчёркивает entity-centric устройство Onion. Это близкий родственник Hexagonal/Clean, но отдельная исходная позиция сохранена.

### 009. [Microservices](009_microservices_comparision.md)

Сервисы имеют собственные границы развёртывания и общаются через транспортный контракт.

**Сценарий:** Checkout запрашивает стоимость трёх единиц у Catalog по endpoint и route; fixture возвращает 30.

**Наблюдение:** Один запрос к https://catalog.example/quote, quantity=3; успешный semantic reply содержит 30.

LMX уже имеет HTTP transport profile. Java/Go Exchange — тот же явно исключённый адаптер. Общий внешний fixture передаёт quantity=3, проверяет endpoint/route и вызывает catalog; это проверка бизнес-границы, не доказательство сетевого развёртывания.

### 010. [Event-Driven Architecture](010_event_driven_architecture_comparision.md)

Издатель сообщает о факте, а подписчики независимо обрабатывают событие.

**Сценарий:** Событие quantity=3 направить в Audit и Stock через две Message-доставки.

**Наблюдение:** Каждый адрес получает одно событие 3; completion одного обработчика не означает completion другого.

Явные адресаты делают пример детерминированным; каталог подписок можно вынести в отдельный router Message. Java/Go Delivery обязаны обеспечивать такие же раздельные delivery lanes.

### 013. [Pipe and Filter](013_pipe_and_filter_comparision.md)

Независимые преобразования соединяются в упорядоченный поток данных.

**Отдельное сравнение реализации:** [093. Pipe — generic implementation](093_pipe_implementation_comparision.md)

**Сценарий:** Для одного элемента -3 выполнить нормализацию знака, удвоение и смещение +1.

**Наблюдение:** 7; промежуточные значения 3 и 6.

LMX использует обобщённую композицию ядра, Java — настоящий andThen, Go — обычные вызовы. Сравнение093 не является зависимостью иностранных клиентов.

### 093. [Pipe — generic implementation](093_pipe_implementation_comparision.md)

Реализовать обобщённую последовательную композицию без привязки к int.

**Примеры использования:** [013. Pipe and Filter](013_pipe_and_filter_comparision.md)

**Сценарий:** Скомпоновать A→B и B→C в A→C; вызвать этапы по одному разу и не выполнять второй при отказе первого.

**Наблюдение:** Пример с int возвращает7; string→length→Boolean тоже допустим; отказ первого этапа пропускает второй.

Все три реализации хранят callable и явно компонуют обычные вызовы. LMX сохраняет исходные inputs и declared failures через общий адаптер; Java/Go используют generic-типы.

### 014. [Blackboard](014_blackboard_comparision.md)

Независимые источники знаний читают общую доску и добавляют применимые факты.

**Сценарий:** В доске raw=4. Эксперт A выводит normalized=5, эксперт B выводит result=10. Планировщик пробует B раньше A.

**Наблюдение:** 10; требуется следующий проход после добавления normalized.

Порядок B→A показывает отличие от фиксированной цепочки фильтров. Источник знаний проверяет применимость; controller повторяет проход до отсутствия изменений.

### 015. [Microkernel / Plug-in](015_microkernel_comparision.md)

Стабильное ядро предоставляет точку расширения с заменяемой реализацией.

**Сценарий:** Установить plugin x*2, выполнить 5; затем установить x*3 и повторить без изменения ядра.

**Наблюдение:** 10 + 15 = 25.

Сравнивается минимальная extension point; registry множества имён и discovery не нужны для одной точки. Все реализации используют заменяемое поведение.

### 046. [Anti-Corruption Layer (ACL)](046_anti_corruption_layer_comparision.md)

Переводчик сохраняет смысл доменной модели при обращении к чужой системе.

**Сценарий:** Legacy возвращает цену 12 в целых долларах; новый домен ожидает центы. Для quantity=2 получить 2400.

**Наблюдение:** 2400; 12 превращается в 1200 ровно на ACL-границе.

ACL отвечает за смысловые различия, а не только переименование метода. Перенос Legacy за HTTP не меняет эту обязанность; transport adapter работает отдельно.

### 047. [Strangler Fig](047_strangler_fig_comparision.md)

Маршрутизатор постепенно переводит отдельную функциональность на новую реализацию.

**Сценарий:** Маршрут 1 сначала обслуживает legacy, затем new; маршрут 2 остаётся на legacy.

**Наблюдение:** Ответы 101, 201, 102; demo возвращает сумму 404.

Переключение одной capability отделено от обновления всей системы. Включённый флаг не означает fallback после уже выполненных побочных эффектов нового сервиса.
