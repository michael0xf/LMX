# Требования к общему интерфейсу ядра

Это список **недостающих опубликованных интерфейсов**, а не заявление, что
внутри ядра отсутствуют соответствующие алгоритмы. Репозиторий реализации ядра
в архив не входит и здесь не изменялся. Fable должен найти и переиспользовать
имеющиеся механизмы, затем подключить приведённые LMX-исходники и выполнить
приёмку на интерпретаторе и нативных переходах.


## 0. Все операции — часть текущего ядра

61 публичное имя и все контейнеры включаются в стандартный namespace ядра.
Это не optional package и не несколько runtime-версий. Точные исходные
owning-field exports находятся в `fun\const` файла [public.lmx](src/public.lmx).
Подготовка ядра использует их в общем проходе корневых constant declarations;
пользователь не исполняет import. Ссылки сохраняют actual parent своих методов.
Не добавлять отдельный постоянный реестр и не обходить общую семантику имён.
Прежние материалы служат только происхождению/процедурным аналогам.

## 1. Неизменяемые архитектурные условия

Работают один парсер, один чистый граф, обычный owner/DATA/CODE, имеющиеся
арены Message и call machinery. Нельзя добавлять второй callable graph,
постоянный глобальный реестр операторов или hidden captured environment.
Анализ сигнатуры и `satisfies` не вызывают candidate, default, test или converter.
Штатные admission/test/conversion запускаются только на предусмотренной
обычным вызовом стадии. Автоматической native-компиляции адаптера нет.

P0 сохраняет контейнеры исходника. Исключение операнда требует одновременно:
написанную безымянную Structure слева, right.length = 1 и написанную безымянную
Structure в right[0]. Снимается только внешний контейнер right[0], один уровень;
left остаётся целым, вложенный RHS не открывается повторно. Function result,
ссылка на структуру и произвольный Array по этому правилу не открываются. При обычном левом type-токене `R signatureTypes
(T0 T1)` не превращается в два типа. Контракт обычных callable W/E не меняется.

`Name :: DATA` и `signatureTypes` создают один вид описания сигнатуры. Существующее отношение
именованного `Name :: DATA` с `call` сохраняется без изменений. Во всех других
контекстах описания от `signatureTypes` и от `Name :: DATA` взаимозаменяемы; сравнение игнорирует
имена/defaults/body, но сохраняет полные ordered input requirements и R/void.

### 1.1 Общий операнд объявления `::`

`Name :: DATA` разбирается тем же выражением и тем же `OPERANDS_TEMPLATE`, что и
остальные операнды. Сохранение исходных форм использует общий режим 1:
декларационный потребитель получает левый идентификатор как объявляемое имя.
Новый специальный разделитель, отдельный парсер или правило склейки RHS не нужны.
`::` не открывает Frame; левое имя не создаёт цель `end:`, действуют обычные границы выражения.
`Name :: A B` имеет два правых аргумента; `Name :: (A B)` — один аргумент-Structure.
Действующий именованный контракт принимает один DATA-шаблон справа. Его
дальнейший разбор полей сигнатуры не меняет right.length и не является operand
unwrapping. Значение/описание результата в произвольном векторе не угадывается;
смысл нескольких правых аргументов декларации здесь не задаётся.

## 2. Восемь мостов

Их декларации находятся в [src/kernel_contracts.lmx](src/kernel_contracts.lmx).
`FxKernel` — имя внутреннего адаптера ядра, не восемь новых псевдопакетов и не
обязательная конечная форма имён в ядре. Если действующий публичный API уже
даёт контракт, достаточно тонкого связывания с ним.

### 2.1 signature(subject)

Принимает callable либо существующее описание сигнатуры. Возвращает обычную структуру:

| Поле | Значение |
|---|---|
| `inputTypes` | Structure / Array<@> полных требований в семантическом порядке |
| `resultType` | Полное каноническое требование, включая void |
| `hasResult` | Готовый int-флаг наличия результата |
| `names` | Имена семантических входов в том же порядке |
| `throws` | LMX-строки объявленных именованных исходов |

Физические поля `return`, методы, const-свойства и свободные имена не становятся
входами только потому, что лежат в DATA. Реальный анализ должен совпасть с
именованного объявления и `satisfies`, а не обходить поля наугад. Для `Name :: DATA` и `signatureTypes` различается
лишь происхождение/отображение меток, не критерий совместимости. Отсутствующий
return, готовое @0, uninit:@ и пустая возвращаемая Structure различаются.

### 2.2 normalizeType(token)

Готовая int-запись: **payload** — код нужного типа. Не заменять его физическим
тегом самой int-записи. uninit:T: читать только tag и получить T, не читать
несуществующие байты значения. Явный void: каноническое отсутствие результата.
Существующее полное требование: сохранить reference model, element constraints,
полные требования сигнатур и квалификаторы. Голый код @ не заменяет полную модель ссылки.
Неверный/неизвестный код даёт FxTypeToken. Не разыменовывать произвольный @
рекурсивно и не смешивать готовый нулевой указатель с отсутствием значения.

### 2.3 signatureData(inputs; result; labels)

Принимает уже нормализованные полные требования; число labels равно числу
inputs. Строит обычный DATA с декларациями, пригодный для существующего
`Built :: DATA`. R=void означает отсутствие return. Метки p0…pN допустимы как
уникальные публичные имена; функция не присваивает им роль identity signature.
При использовании такого описания как требования native/интерпретатор должны
отобразить actuals по позиции на входы candidate с любыми исходными именами.

### 2.4 callable(contract; labels; bodyGraph; state; failures)

Создаёт обычные owner → DATA → CODE. Фактический parent(CODE) равен созданному
DATA, связь DATA с владельцем корректна. CODE видит переданное состояние как
`node\private\state`; состояние сохраняется **по ссылке**, а не копируется
неявно при каждом вызове. В текущем builder входы required/private; это явный контракт адаптера. Без private ядерные locals
могли бы случайно участвовать в динамическом заполнении чужого callable.

Контракт — обычное описание сигнатуры: точные входы и R/void, не универсальный @-return.
Обычные имена `failures` интернируются как текущие `throws`. Проверить допустимые
имена до публикации; устранить повторы. Никакого вызова F во время построения.
Строитель не сохраняет native entry чужого ABI и не компилирует автоматически.
Перестройка/сборка выполняется существующим разрешённым путём изменения графа.

### 2.5 attempt(operation; args; failures)

Обычный вызов operation с **вектором записей actuals** args, принятым как
готовый явный список аргументов. Здесь нет повторного исполнения выражений.
Для каждого actual учитывается его полный тип; входная Structure не теряет
свою целостность из-за повторного применения W/E. Реализация может использовать
штатный call transport и его уже выбранные позиции, а не новый invokeByIndex VM.

В результате обычная `FxOutcome {ok,value,failure,payload}`:

- успех: ok=1, value указывает на готовую запись настоящего R;
- процедура: ok=1 и value — явная void-запись без payload;
- именованный отказ из failures: ok=0, failure — исходное каноническое имя,
  payload — исходная типизированная запись/структура параметров отказа.

Мост выставляет ordinary catch handlers лишь для разрешённых имён. Он не
перехватывает системные implicit failures, нарушенные инварианты, stop/abort
или любую неизвестную ошибку под общим «catch all». Обязательные language
проверки, порядок эффектов, DATA caller, private и границы Message сохраняются.
На native↔interpreter переходах память результата принадлежит живой арене;
нельзя вернуть адрес native local или читать type из `native_address - 4`.

### 2.6 raise(name; payload)

Тонкая форма существующей именованной доставки throw. Нужна generated wrapper,
который знает полный конечный список failures, но получает конкретное имя как
данные. Сначала разрешить имя через текущую таблицу и проверить его наличие
в declared contract данной точки CODE, затем обычная доставка того же payload.
Не обходить ни throws, ни private, ни обычную обработку catch. Если нужен
выбор обычной структурной формы throw во время генерации, допустима генерация
ветвей по конечному списку failures вместо нового публичного builtin.

При отсутствии runtime-формы динамического имени Fable может реализовать этот
bridge через generated обычные catch/throw branches; список конечен и известен
builder. Нельзя выдавать неизвестный идентификатор за уже разрешённый atom.

### 2.7 fieldNames(source)

Читает существующую service association owning-field record → canonical name.
Возвращает по одному элементу в физическом порядке, включая повторные имена.
Именованный элемент — готовая LMX-строка; анонимный — uninit:Array<char>.
Пустая строка точного имени, если допустима грамматикой, не означает анонимность.
`sys\name(identifier)` — другая операция: она не получает имя поля по указателю.
Никакой второй таблицы имён в Lmx-полях не добавляется.

### 2.8 renameFields(target; indices; labels)

Применяет согласованный полный набор имён к выбранным owning fields target.
Проверить весь набор индексов/меток/ограничений имён до первой записи, сохранить
обычную семантику повторных имён. Никакого текстового replace в sys\toLmx.
Набор ресиверов ядра предварительно делает один общий copy(source), поэтому source не
изменяется и сохраняется общая карта копирования, parent и циклы. Не обещать
переименование всех внешних исходных текстовых ссылок: это операция над
выбранными именами записей, а не refactoring whole program.

## 3. Конечные ошибки и wrappers

`attempt` делает произвольные declared target failures обычными данными.
Внутри generic-набора ресиверов ядра `FxApply` сообщает `FxCallFailure(outcome)`; это
конечное имя разрешено в обычных `throws` helpers. Typed wrapper имеет полный
список исходных target failures, ловит оболочку и делает raise исходного имени.
Его собственные FxIndex/FxArity/FxRecordArity/FxTypeToken/FxKernelFailure также
входят в список. Семейства дополнительно перечисляют LazyCycle, Predicate,
NoMatch/Ambiguous там, где они реально могут возникнуть.

Не заменять это недокументированным `throws:*`. Для typed wrapper, построенного
с неизвестными эффектами внешней ступени, контракт failures подаётся явно;
именно так устроен `uncurry`. Ошибки handler/логгера не исчезают автоматически.

## 4. Приёмка и оптимизация

Сначала исполнить [подготовленные fixtures](examples/run_all.lmx), затем матрицу
из [ACCEPTANCE.md](tests/ACCEPTANCE.md): interpreter→interpreter,
interpreter→native, native→interpreter и native→native. Сверить ordinary admission,
эффекты, время жизни записей и actual parent с действующим ядром.

Оптимизация обязательна, но не должна менять контракт: не хранить вторые
копии графа и имён, использовать прямые Structures как @-массивы, не делать
глубокую copy captured primitives/references ради одной ячейки, не повторять
семантический разбор неизменного контракта в каждой итерации, если уже имеется
законный current-traversal prepared view. Prepared view живёт в допустимой
служебной области, не становится persistent hidden global cache. Нативный
путь может убрать промежуточные materializations, когда значение не выходит
за его время жизни и типовой/эффектный контракт сохранён.

Фактическая готовность подтверждается только тестами ядра. В этом пакете
подтверждены исходные алгоритмы и механическая согласованность публикации;
восемь интерфейсов и исходный runtime не исполнялись здесь.
