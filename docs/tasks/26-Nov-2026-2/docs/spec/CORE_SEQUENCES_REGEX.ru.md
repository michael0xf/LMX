## 1. Выражения типов и объявления

Тип публично представляется обычным кодом `int`. `T[]` строит интернированный тип массива, элементы которого удовлетворяют полному требованию T. `T@` строит тип указателя. Повторные постфиксы применяются слева направо: `int@[]`, `int[]@`, `int[][]` и `int@@` — разные требования. Последовательные пустые `[]` задают мерность одного плоского Array: `int[][][]: arr` имеет три оси; они не требуют отдельных объектов строк. Rank/extents хранятся в служебной записи арены рядом с capacity, без полей Lmx или TYPE-record ([хранение](ARRAY_STORAGE.ru.md)). Глубина указателя — любое конечное значение, допустимое имеющимися ресурсами; языкового предела в три уровня нет.

Общий нормализатор роли TYPE принимает допустимый код, символический атом типа, неинициализированную типизированную запись или полную модель — как уместно. Он сохраняет полные структурные требования и требования к вызываемым. В `@[]` левый `@` — универсальное требование ссылки; результат — существующий тип Structure/массива ссылок. Это не ещё одна категория STRUCT/ARRAY, и значение массива не выделяется. Числовое значение, случайно равное коду типа, само по себе роли типа не получает.

| Запись | Смысл |
| --- | --- |
| `[]: pending` | Неинициализированное место, принимающее любой Array, включая плотный Array и обычную Structure |
| `@[]: refs` | Неинициализированное место, требующее конкретного типа — массива ссылок/Structure |
| `int[]: values` | Неинициализированное место массива int |
| `int[]: values []` | Инициализированный пустой массив int |
| `int[]: values [1 2 3]` | Инициализированный именованный типизированный массив |
| `int[]: [1 2 3]` | Одно анонимное значение типизированного массива |
| `[]: [1 2 3]` | Одно анонимное значение обычной Structure/массива ссылок |
| `[]: values [1 2 3]` | Именованное место общего массива, инициализированное Structure |
| `@: values [1 2 3]` | Универсальная ссылка на Structure; дополнительной обёртки нет |
| `T[]: [copy(S)]` | Типизированный массив из явного потока элементов внутри квадратной группы |
| `T[]: destination Source` | Именованное место, инициализированное подходящим существующим значением |
| `@: p` / `T@: p` | Неинициализированная универсальная/типизированная ссылка |
| `T@: p 0` | Инициализированная нулевая ссылка; отличается от uninit |
| `int@: 65536` | Одно значение ссылки на int, заданное адресом 65536; место не объявляется |
| `@x` | Адрес фактического места x по контракту адресов выбранного уровня |
| `x@` | Тип указателя, построенный из x в роли TYPE |
| `@(name)` / `[](name)` | Обычные компактные объявления, равные `@: name` / `[]: name` |

Одобренные автором структурные формы `Model@: p`, `int@: left`, `Model[]: arr`, `int[]: values`, `Model[]: arr [Model Model]`, `Model[]: [Model Model]`, `int[]: values [1 2 3]` и `int[]: [1 2 3]` явно сохранены в [матрице положительных форм](TYPE_DECLARATION_FORMS.md). Полный тип всегда стоит слева от двоеточия. В инициализаторах Model оба элемента ссылаются на существующее значение Model; построение не копирует его поля, не меняет родителя и не заменяет полное требование физическим кодом ссылки. Именованные и анонимные квадратные инициализаторы используют обычный допуск элемента.

Единственный идентификатор объявления потребляется как NAME до поиска; единственная квадратная группа даёт анонимные данные. NAME, за которым стоит квадратная группа, даёт явный инициализатор. Существующее значение с тем же именем не может изменить эту классификацию. Общий путь ресивера определяет роли аргументов раньше, чем присоединяет группу-инициализатор как индекс. Особого парсера массивов, зависящего от пробелов, нет.

Первый аргумент отличает именованное место от значения без имени у ссылок так же, как у массивов.
`int@: p` объявляет место; `int@: 65536` строит значение ссылки из адреса. Безымянных переменных нет.
Это общее различие NAME/VALUE, а не отдельное правило объявления или разбора.

Анонимный типизированный конструктор массива требует квадратной группы. `T[]: copy(S)` не является альтернативным
анонимным конструктором. `@[]: [S]` держит одну ссылку на S; `@[]: [copy(S)]` получает явно выпущенные поля.
Выражение типа не выполняет ни копирования, ни исполнения инициализатора, ни компиляции.

Записанный пустой суффикс `T[]` строит тип. Суффикс с записанным выражением индекса использует индексирование, даже если это выражение позже даст пустой поток: `a[()]` и `a[copy(empty)]` конструкторами типа не становятся. Исходные группы и постфиксные вхождения остаются в исходном графе.

`Struct@: p` и `(Struct)@: p` нормализуют каждое свою полную левую часть; охватывающая группа во втором случае молча не снимается. Префикс `@Struct` по-прежнему берёт адрес. Чтобы взять адрес поля, пишите `@D\field` или `(@D\field)`; голое `@(D\field)` теперь читается как обычное компактное объявление, исключения для адреса нет.

`sys\typeof` переменной int, содержащей код типа, сообщает int. Потребитель роли TYPE читает этот код из нагрузки. Для `uninit:T` нормализация читает его информацию о типе, не читая отсутствующих байтов значения. Любой неинициализированный массив или указатель имеет нулевую нагрузку; это не пустой дескриптор и не нулевой указатель.

### Строки typed initializer и независимые DATA-поля

`int[][]: [a b c; a b d; a b c]` и
`int[][]: [[a b c] [a b d] [a b c]]` равнозначно создают один плоский
rank=2 Array с extents `[3,3]`. Числовая пара `[1 2; 3 4; 5 6]` и
`[[1 2] [3 4] [5 6]]` даёт shape `[3,2]`. Принимающий typed-контракт
проверяет прямоугольность строк и получает элементы однократно; область
каждой строки задаёт общий P0. `;` внутри вложенной области не разделяет
внешнюю строку; вне инициализатора он заканчивает короткую форму.

Длины 3/4/5 или 3/3/4 в таком typed-конструкторе дают диагностику формы.
Но `Struct: [a b c] [a b d] [a b c d]` корректно и равнозначно
`Struct: (a b c) (a b d) (a b c d)`: это три обычных безымянных DATA-поля,
а не один rank=2 flat-конструктор. Нет особой сущности вложенного массива.
VALUE `[arr2]` по-прежнему сохраняет целое поле arr2. Ни группировщик,
ни приёмка готового VALUE не читают flags исходных скобок для раскрытия.
[Договор и полный алгоритм](ARRAY_STORAGE.ru.md#constructors).

### Интернирование, допуск и раскладка

Общий контекст типов интернирует полные производные требования. Длина и вместимость — свойства значений, а не отдельные типы массивов. Attach обязан сохранять существующие коды записей, их адреса и метаданные типов. В контекстах, чьи чанки арены можно присоединять без перекодирования, один и тот же код не может обозначать несовместимые типы. Восстановление из независимого контекста разрешает полные описания типов по существующим правилам; случайное числовое равенство тождества типов не устанавливает.

Направленное отношение:

```text
A[] satisfies B[]  iff  A satisfies B
```

Общее ядро ведёт таблицу завершённых проверенных пар типов с их направлением, полными требованиями и применимым контекстом преобразований. Повторная проверка той же стабильной пары использует готовый результат, в том числе между вызовами, пока требования и контекст остаются применимыми. Рекурсивное сравнение, ещё не завершённое, не считается доказанным успехом. Изменяемые проверки, зависящие от значений, конкретные карты полей, границы, время жизни и права доступа по-прежнему проверяются там, где требуется. Эта таблица — метаданные типов, а не второй исполняемый граф и не постоянный снимок namespace.

Успешный допуск не меняет фактическое хранение. Допущенный Array<A> читается по фактической раскладке и шагу A; запись должна быть допустима для его фактического требования к элементу. Проверка типов не выполняет пользовательского конвертера. Пустые массивы следуют тому же отношению типов, что и непустые.

### Подробности типовых форм

Записанная форма обрабатывается в одном порядке: сохраняются её исходный вид и границы; устанавливается роль, которую для неё задаёт потребитель (имя объявления, описание типа или обычное значение); она разрешается по этому общему контракту; затем достигнутая операция выполняется в установленном порядке, каждая один раз. Внешнее двоеточие и постфиксные части головы определяются структурно; фрагмент никогда не выполняется первым, чтобы затем по его результату или отказу признать его частью головы или описания типа. В роли VALUE внутри границ аргумента действует обычный префиксный и постфиксный механизм: в начале требуемого выражения `@` может начинать операнд-адрес; после завершённого левого операнда `@` может быть постфиксом типа. Недостающие квадратные скобки не угадываются, и ни одна ветвь не выбирается по успеху вычисления.

Снятые чтения не сохраняются ни как второй стандарт, ни как второй путь разбора: типизированные `[](T): …` и `@(T): …`, префиксные коды типов `@int`, `@@int`, `[]T`, типизированные головы `@Struct: p`, `@(Struct): p`, `[]@` как тип Structure/массива ссылок (теперь `@[]`), `@(int)` или `@: int` как тип указателя на int (теперь `int@`), `[]: int values …` и `[]: char text` (теперь `int[]: values …`, `char[]: text`), а также `@: p Model Other` (теперь `Model@: p Other`). Их байты читает общий разрешитель по их обычному смыслу, если он есть; в новые головы они не преобразуются. Компактная эквивалентность `@(name)` ≡ `@: name` и `[](name)` ≡ `[]: name` — свойство обычного ресивера, применённого к сохранённой форме, а не ранняя текстовая подстановка, теряющая роль или границы формы. Компактное объявление с недопустимым или занятым именем получает обычную диагностику имени.

```lmx
int: value 7
int: typeCode sys\typeof(@value)
```

`@typeCode` — адрес int-места `typeCode`; `typeCode@` — код типа указателя на тип, хранящийся в `typeCode`; `typeCode[]` — код массива этого типа. Нагрузка, случайно равная известному коду типа, не меняет операции адреса. Добавление двоеточия, `typeCode@: p`, использует уже определённый тип; оно не переключает смысл оператора.

Три результата различны: код типа (`int[]`, `int@` дают обычное значение int), объявленное место без значения (`int[]: pending`, `int@: ptr`) и построенное значение (`int[]: [1 2 3]`, инициализированное место ссылки). `sys\typeof` — единственный запрос типа; `typeof` в примерах обозначает тот же запрос, а не второй API. Пользовательской обёртки Type, нового класса токенов и указателя на служебное описание вместо кода нет.

```lmx
int: numbersType int[]
int[]: numbers [1 2 3]
```

`numbersType` хранит код конкретного массива int, а тип `numbers` согласуется с этим кодом при обычной рефлексии. `sys\typeof(@numbersType)` сообщает тип самого int-места. Потребитель роли TYPE, получивший недопустимый или недоступный код, отказывает обычным отказом по типу; число никогда не считается произвольным адресом метаданных.

Компактная форма существует на любой глубине: `@@(name)` в позиции завершённого Frame — это `@@: name`, и так далее для `@@@(name)`. Она объявляет универсальную ссылку этой глубины и никогда не получает тип из `name`.

Группа слева от постфикса типа сохраняет свой смысл: `(Struct)[]` и `(Struct)@` используют полное требование, которое общий нормализатор получает из группы; их не объявляют равными `Struct[]` и `Struct@` снятием скобок — когда `(Struct)` является анонимной Structure из одного элемента, это другая структурная модель, и равенство нормализованных требований устанавливает общий механизм. `[]: [Name]` содержит группу из одного элемента и не равно `[]: Name`. `[]: []` и `int[]: []` содержат присутствующую пустую группу и строят пустое значение; отсутствующий инициализатор — другое состояние. Пустые группы и группы из одного элемента сохраняются в чистом графе и при круговом обходе. Самостоятельное `[]` в позиции VALUE создаёт обычный пустой Array; `[items]` создаёт обычный анонимный Array, как `@[]: [items]`. Символическая голова `[]:` сохраняет объявляющую роль. Это не постфиксный конструктор с отсутствующим TYPE слева.

`int@[]` — массив указателей на int, `int[]@` — указатель на массив int, `int[][]` — один плоский Array int с двумя логическими осями, `int@@` — указатель на указатель на int, `int@@[]` — массив указателей глубины 2 на int. Глубина сверх доступных ресурсов отклоняется обычным отказом по ресурсам; глубина никогда не усекается и не оборачивается. Глубина типа не задаёт цепочки объектов: `int@@@: p 0` инициализирует одну нулевую ссылку и не выделяет промежуточных ячеек.

`int[]@[]` — обычная композиция требований к ссылкам и Array. Structure уже
является `@[]`, и её поле может ссылаться на другую обычную Structure; отдельной
сущности «массив массивов» нет. Именованный путь `struct\struct2\field`
соответствует `struct[i]\[j]`, если i и j выбирают эти поля;
`struct\struct2\field[k]` соответствует `struct[i]\[j]\[k]`.
Одна запись `arr[k]` остаётся линейным доступом и при rank>1; полная цепочка
`arr[i][j][k]` использует координаты того же плоского Array. Одномерные операции
не запрещаются из-за мерности. Их договор результата определяет сохранение
формы либо новую плоскую выборку ([полный договор](ARRAY_STORAGE.ru.md#indexing)).

В роли TYPE n постфиксов `@` означают n уровней указателя, и вложенное требование каждого уровня сохраняется. В цепочке адресуемых мест

```lmx
int: value 7
int@: p1 @value
int@@: p2 @p1
int@@@: p3 @p2
```

каждый уровень адресует реальное место предыдущего уровня: `p2` хранит адрес ячейки `p1`, а не цель, хранящуюся в ней, и ни один уровень не пропускается из-за того, что у машинных указателей один размер. То же верно для n > 3.

Самостоятельное `[arr2]` в VALUE-позиции создаёт один внешний элемент, содержащий исходное целое значение arr2. Оно сохраняет его идентичность, не разворачивает поля и не включает singleton broadcasting; `[items]` не снимается как прозрачная группа Expression.

Анонимный конструктор даёт одно значение Array и не объявляет имени; обычное выражение потребляет его непосредственно: `2 * (int[]: [1 2 3 4])` даёт `[2 4 6 8]` без внутренней переменной. Именованное построение использует обычные правила места, области видимости и допуска объявлений; его инициализатор не исполняется второй раз, чтобы получить результат выражения.

Сбор потока в конструктор — не второе копирование: `copy` и `merge` сохраняют своё глубокое копирование, карты и лексические связи; контейнер не становится владельцем скопированных методов и не запускает хранимых тел. Пустой поток в `@[]: [copy(S)]` даёт пустой Array, а не один пустой элемент. Выражения, записанные для получения элементов, исполняются один раз в установленном порядке; потребление готового поля графа не запускает его вычисляемого объявления.

В DATA `array(int: first 1; int: second 2)` и его вертикальная форма `array:` с теми же полями объявляют обычную именованную Structure, которая одновременно является Array. Её имя сохраняет объявляющий контракт Structure; это не присваиваемая переменная, хранящая ссылку. В CODE те же формы сохраняют обычную роль вызова. Операции над последовательностями принимают такую Structure непосредственно; её именованные поля и физические элементы остаются её обычными полями и элементами. Чтение графа не исполняет хранимых в нём форм ресиверов, а методы в ней не создают отдельного вызываемого контейнера. Две отдельно записанные группы строят собственные значения. Когда два места, одно объявленное через `[]`, другое через `@`, получают одну и ту же существующую Structure, оба ссылаются на неё: допуск через `[]` или `@` не копирует, не создаёт обёртки и не меняет `parent`; `sys\typeof` и дескриптор не различают двух искусственных видов объекта.

В активной арене получение того же производного типа с теми же полными параметрами возвращает существующий код; отсутствующий тип регистрируется один раз. Ключ различает по меньшей мере конструктор и его полное исходное требование: массив T, указатель на T на любой глубине и их композиции. `int[]`, `char[]`, `int@` и `int@@` не сливаются из-за равенства машинных размеров. Производный тип Structure сохраняет её полное структурное требование; два разных требования не заменяются физическим кодом обычной Structure, и ни одна пользовательская Structure не получает физического типа лишь за своё имя — производный тип создаётся, когда конструктор типа действительно применён. Коды выдаёт общая выдача кодов ядра; локальный индекс независимого вектора кодом не является. Два эквивалентных кода, полученные раньше, распознаёт общий механизм эквивалентности; старые записи не переписываются ради одного номера.

Один путь нормализации и разрешения обслуживает всех потребителей: операнды-типы `T[]` и типы указателей, типизированные головы и объявления, `sys\typeof`, проверки кодов и доступ к раскладке, `satisfies` и полные сигнатуры, интерпретатор, native-снижение и общие транспорты вызовов, copy/merge, а также сохранение и восстановление значений. Подготовленный native-код сохраняет тот же контракт типов без автоматического отслеживания записей в граф.

Это отношение сохраняет своё направление; оно не есть равенство кодов A и B, не есть равенство размеров хранения и не симметрично. Полные модели, ссылочные требования, вложенные типы Array и сигнатуры вызываемых остаются частью A и B и не стираются до общей метки Structure или void-указателя. Для типов указателей на любой глубине применяется существующий общий контракт соответствия их полных требований; эта редакция другого правила для указателей не добавляет. Совместимость типов — это не проверка текста по Pattern, не вызов функции, не запуск конвертера и не проверка изменяемого состояния объекта.

<a id="expressions"></a>
## 2. Один механизм выражений

`::`, существующие реализации операндов `->` и `record`, построение постфиксных типов и пять слов шаблонов используют установленный механизм выражений. Константы `PASS_ARGS_AS_IS` и `PRIORITY`, обычная подготовка левого и правого, вычисление по зависимостям и обычное обнаружение ресиверов сохраняются. Второго ABI операндов и парсера regex нет.

Expression — обычный граф Structure с [семантическим группировщиком](LMX_semantics.ru.md#expression-structural-grouping): он определяет приоритеты, полные выражения и потоки текущего уровня дерева независимо от исходного написания. Отдельная подготовка применения Expression упаковывает left одним actual/пакетом ссылок, а right — Array ссылок. Общая форма — `arg0 operand arg1 arg2 arg3`; бинарный договор использует один правый элемент без автоматической свёртки и без переноса первого правого элемента в отсутствующий left. Принимающий договор выбирает целое значение либо последовательность текущего уровня. Поэтому `(a b c) .: (a c b)` даёт один левый пакет и три правых значения; три соседние RHS-группы остаются тремя элементами Structure. Дополнительного условного раскрытия после группировки нет. Группировщик читает чистый граф. В Expression атом-ссылка по графу на Structure образует группу только вне роли операнда. Трансляция отклоняет неоднозначные чтения до эффектов. Для остальных достигнутых Structure действует правило имени и фактического parent. Разрешение ссылки сохраняет фактический parent. Целый материал VALUE/TYPE/DATA автоматически не становится CODE. `1 + ((2))` равно 3; коллектор `(copy(Model))` остаётся контейнером для нуля, одного или нескольких полей. `::` и модификаторы сохраняют DATA и общий механизм чтения непосредственных полей, без собственного исполнителя RHS. P0, обычный W/E вызываемых и правила эффектов/времени жизни сохраняются. См. [архитектуру и приёмку](EXPRESSION_GROUPING.md); исполнение — **NOT_RUN**.

`map`, `apply`, `partial`, `compose`, `pipe`, мутации и поиск последовательностей сохраняют свои настоящие контракты приёма в обеих формах. Разобранная роль выбирает представление ресивера или операнда одного опубликованного семейства операций, затем действует обычный выбор объявления. Общий транслятор сохраняет пропуски, именованные фактические аргументы, исходный порядок и все роли, кроме VALUE; он не переинтерпретирует вслепую DATA одного вызываемого как другой ABI. Встроенные ресиверы уже попадают в Expression через P0 и нуждаются в семантическом понижении, а не в новом парсере. Операнды VALUE, построенные библиотекой, используют `FxAsOperand`. См. [формы операций](OPERATION_FORMS.md) и [публикацию](GENERIC_OPERATIONS.md#32-публикация-под-одним-именем-и-пересечение-перегрузок).

Наличие Array среди потребляемых значений выбирает соответствующий массивный/матричный профиль. Structure неотличима от массива элементов свободного типа @[] и не исключается. Обычный `*` теперь выполняет допустимое векторное/матричное произведение либо умножение на скаляр; `.*` — поэлементное умножение. Сложение/вычитание одинаковых форм и распространение скаляра сохраняют порядок аргументов. Точечная арифметика использует выбранные скалярные операции, без сужения к int/double. `.=` — поэлементное равенство; `.:` — поэлементное присваивание, включая `(a b c) .: (b c a)`. Форма берётся из существующего описания, а не угадывается по глубине указателя, длине или вложенным строкам. Полная семья, хранение результата, общие LMX-алгоритмы и примеры матриц — в [массивных выражениях](ARRAY_EXPRESSIONS.ru.md). [fuse](FUSION.ru.md) требует один пригодный поэлементный обход и не превращает матричную свёртку в поэлементную операцию.

<a id="sequences"></a>
## 3. Универсальные операции над последовательностями

Универсальный `@` указывает прямо на запись `{type value}`. Операция над последовательностью просматривает фактический тип массива. Для Structure/@[] чтение элемента получает хранимую ссылку на запись; для плотного T[] чтение получает T типизированным доступом. Подготовка адресуемого примитивного фактического аргумента, если она нужна, использует обычный механизм вызовов и значений и достаточное время жизни. Она не требует упаковывать весь источник или вставлять видимую пользователю обёртку `{value: ...}`.

Каждый массив имеет переменную длину и существующий дескриптор `parent/length/storage`. Вместимость остаётся в существующей отдельной таблице. Новые результаты выбора получают новый внешний контейнер; общие адресуемые цели и их фактические родители остаются общими. Выбор из плотного массива копирует значения. Выбор — не записываемое представление и не выводит прямоугольную форму.

| Ресиверы | Контракт |
| --- | --- |
| `map(items; transform)` | Один обычный обратный вызов на элемент; массив ссылок на записи результатов |
| `filter(items; accepts)` | Устойчивый выбор, сохраняющий фактический профиль хранения элементов |
| `foldl(items; seed; step)` | Левая свёртка; пустой источник возвращает seed |
| `scanl(items; seed; step)` | Seed, за которым следуют все накопленные записи результатов |
| `zip(first; second)` / `zipWith(first; second; combine)` | Пары или комбинации до меньшей длины; в отличие от арифметики массивов равной длины |
| `traverse`, `bind`, `list`, `groupBy`, `transpose` | Прежний смысл для контейнеров; теперь принимают плотные и ссылочные источники через общий доступ |
| `select`, `omit`, `reorder` | Физические индексы; выбор сохраняет профиль хранения; reorder требует полной перестановки |
| `project` | Выбор, за которым следует одно общее копирование/отображение графа |
| `range(start; stop; step := 1)` | Материализованный полуоткрытый диапазон через явный профиль шага и порядка; профиль точных целых по умолчанию сохраняет плотный вывод int и проверенный размер |
| `slice(source; begin; end)` | Существующий строгий профиль полуоткрытого интервала |
| `slice(source; spec)` / `source[start:stop:step]` | Общая нормализованная выборка с шагом, знаковыми границами и различимыми пропусками; [договор](TERNARY_AND_SLICES.ru.md#slice-contract) |
| `reverse(source)` | Новый контейнер в обратном физическом порядке |
| `concat(parts)` | Тот же плотный T, когда все части — плотные массивы того же T; иначе массив ссылок |
| `compress(source; mask)` | Маска истинности int той же длины, устойчивый выбор |
| `any`, `all`, `index`, `count` | Обычные вызовы предиката по порядку; ранняя остановка там, где указано; index возвращает Maybe индекса int, none() при отсутствии |
| `replaceRange`, `append`, `insert`, `deleteAt` | Явная мутация, возвращается тот же дескриптор цели |
| `splice(target; begin; end; values)` | Та же мутация интервала, свежий снимок удалённых элементов с сохранением фактического типа элемента и профиля хранения цели |

Точные границы, значения по умолчанию, пустые случаи и имена отказов определены в [спецификации последовательностей](#sequences-details) и [контракте реализации](patterns/LMX_Fn_Receivers/SEQUENCES_IMPLEMENTATION.md). Публичные имена — прямые ресиверы ядра. Семейства преобразования `toArray` и отдельного пользовательского вида коллекции нет.

Обратные вызовы получают один явный фактический аргумент для map/filter/запросов и два — для fold/scan/zipWith. Считаются поданные фактические аргументы, а не общая арность допустимой цели: обычные необязательные входы, полные типы, правила private/required и объявленные выходы остаются в силе. Вложенные Structure и возвращённые вызываемые — единичные значения, и неявно не вызываются. Пропуск — не ноль, не nil, не пустой массив и не uninit-запись. Эффекты происходят слева направо в одном Message; обратные вызовы не должны менять состав или длину обходимой последовательности. Отказ прекращает дальнейшие обратные вызовы и не возвращает частичного успеха.

### Мутация и правка графа

`replaceRange(target; begin; end; values)` заменяет полуоткрытый интервал `[begin,end)` непосредственными вставляемыми значениями до записи и возвращает **тот же дескриптор цели**. Новый `splice(target; begin; end; values)` выполняет ту же мутацию, но возвращает **свежий внешний контейнер удалённых элементов до записи**. Это отдельные обычные имена ресиверов. См. [различия по соглашению об именах](NAMING_2026-11-22.md#1-sequences-and-mutation).

Обе входные формы сначала проверяют границы, итоговый размер, вид источника и допуск всех плотных целей. Пересекающиеся вставляемые значения и удаляемый интервал, нужный `splice`, стабилизируются до первой записи или изменения размера, которые могли бы их изменить. Так добавление A к самому себе дублирует исходные элементы ровно один раз. Фиксация не запускает пользовательских конвертеров и обратных вызовов. Ошибки диапазона и типа оставляют цель без изменений; уже вычисленные эффекты фактических аргументов и отказы ресурсов общего транзакционного отката не получают.

Удалённый результат сохраняет фактическое требование к элементу и профиль хранения цели. Плотный T[] даёт новый плотный T[]; Structure/@[] даёт новый @[] с исходными ссылками на записи. Это мелкий снимок: адресуемые узлы сохраняют идентичность и фактических лексических родителей. Замена внешнего элемента результата не заменяет элемент цели; изменение общего адресуемого объекта остаётся общим. При `begin == end` результат — инициализированный пустой контейнер того же профиля. Удаление всего интервала возвращает все исходные элементы, оставляя исходный дескриптор цели на месте. `replaceRange` не обязан выделять неиспользуемый снимок удалённого результата.

`append`, `insert` и `deleteAt` делегируют тому же алгоритму мутации и возвращают цель. `insert` принимает последовательность вставляемых значений; `deleteAt` берёт явный полуоткрытый интервал. Элементы Structure принимают прямые ссылки, не наследуя прежнего требования удалённого поля. Плотные элементы сохраняют свой фактический тип. Ссылка на элемент в L3 хранит дескриптор и индекс, поэтому вставка меняет содержимое в этой позиции; она не отслеживает перемещённый логический элемент. Отдельно сохранённая ссылка на запись по-прежнему обозначает эту запись. Сырые адреса L2 после перемещения хранилища не исправляются. Несвязанная операция выбора `compress` по-прежнему требует равных длин источника и маски.

Код — тот же редактируемый граф. Эти операции могут просматривать и править его непосредственные поля, не исполняя сохранённых форм. Правки во время выполнения и последующая интерпретация не требуют ни текстовых круговых обходов, ни compile/endturn. Явная native-компиляция и установка на границе хода сохраняют свои существующие независимые правила; запись в граф не обнаруживает обратных зависимостей и не переписывает старых native-вызывающих.

<a id="sequences-details"></a>
### Точные контракты последовательностей

`unique(items; same := 0)` сохраняет первого представителя каждого класса равенства и их исходный порядок в новом внешнем контейнере с фактическим профилем хранения источника. `same=0` — явная политика API, выбирающая равенство по умолчанию; это не общеязыковая эквивалентность пропуска, null и неинициализированного состояния. Поданный компаратор получает две целые типизированные записи — сначала прежнего представителя, затем кандидата, — а его результат принимается общим потребителем предиката. Состав и длина источника не меняются.

`equalFields(first; second; same := 0)` проверяет упорядоченные длины и элементы. Компаратор выбирает `FxValueSame`; единственный парный обход — `FxSequenceDifference` с независимыми началами первого и второго и проверенным числом. Сравнение скаляров по умолчанию использует фактический контракт `=`. Две конечные ациклические последовательности рекурсивно проходят тем же обходом; скаляр и последовательность различны. Маски сравнения массивов не принимаются за один Boolean. Сравнение текста точное и чувствительное к регистру, включая нулевые символы. Физическое равенство Structure не выводит равенства имён полей, модели или лексического родителя. Циклические и специальные доменные значения требуют явного компаратора. Ошибки типов и отказы обратных вызовов распространяются, а не превращаются в неравенство. Дополнительного цикла `sameText` нет. [Полный контракт равенства](GENERIC_EQUALITY.md) включает все гарантии по отказам, тождеству, числовому профилю и сложности.

`range(start; stop; step := 1)` использует профиль шага и порядка и материализует свой конечный результат. Профиль точных целых по умолчанию возвращает плотный `int[]`. Положительные шаги включают значения ниже stop, отрицательные — значения выше stop; stop не включается. Нулевой или непродвигающийся шаг отклоняется отказом `SequenceStep`. Равные границы или шаг, направленный от stop, дают пустой результат. Каждый фактический аргумент вычисляется один раз. Профиль точных целых считает количество в `bigint`, проверяет maxLength и размер в байтах до выделения и не вычисляет значения после последнего включённого элемента: `range(MAX_INT - 1; MAX_INT; step := 2)` содержит один элемент без искусственного переполнения. Другие допущенные числовые и доменные профили определяют построение следующего значения, порядок, направление, пределы длины и полное требование к элементу. Округлённая арифметика проверяет фактическое продвижение; знак записанного шага сам по себе не доказывает завершения. Результат — не ленивый итератор и не грамматический смысл двоеточия.

`slice(source; begin; end)` возвращает новый контейнер из непосредственных элементов с `begin <= i < end`. Требуется `0 <= begin <= end <= length(source)`; пустой интервал допустим, в том числе в конце массива. Отрицательный индекс не отсчитывается от конца, а граница вне диапазона отклоняется отказом `ReceiverIndex`, а не обрезается. Результат имеет профиль хранения источника. У этого строгого трёхаргументного профиля нет параметра шага; для шага и знаковых границ используются перегрузка `slice(source; spec)` либо `source[start:stop:step]` с общим обходом выборки, или явная композиция `select` с `range`.

`reverse(source)` возвращает новый внешний контейнер в обратном физическом порядке с профилем хранения источника. Пустые источники и источники из одного элемента допустимы. Источник не меняется; цели ссылок не копируются глубоко и не получают нового родителя.

`concat(parts)` принимает один обычный фактический аргумент — последовательность последовательностей — и соединяет только непосредственные элементы частей в их порядке. Непустой `parts`, все части которого — плотные массивы одного и того же полного T, даёт новый плотный `T[]`; любое другое допустимое сочетание, включая смесь плотных массивов и Structure, даёт новый `@[]` из значений; пустой `parts` даёт пустую Structure/`@[]`. Пустая плотная часть по-прежнему несёт свой T и участвует в выборе профиля. Числовых преобразований для угадывания общего типа не делается; плотный результат смешанного входа получают явно типизированным конструктором. Вложенный массив внутри части остаётся одним элементом: рекурсивного уплощения нет. Соединение физических элементов не сопоставляет имён полей, поэтому `concat` не реализуется через `merge`.

`compress(source; mask)` принимает источник и int-маску истинности той же длины: 0 исключает элемент, любое ненулевое int включает его. Результат — устойчивый выбор с профилем хранения источника. Маска — плотный `int[]` или обычная последовательность целых через `@`; её значения проверяются по фактическому типу, а массив ссылок маской не является, так как его адреса ненулевые. Длина и типы элементов проверяются до построения результата; пустая маска допустима ровно для пустого источника. Отдельное имя разделяет индексы `[0 1]` и маску `[0 1]`.

`any`, `all`, `index` и `count` принимают `items; accepts`. `accepts` получает один явный фактический аргумент — текущее значение, а его результат читается как int ноль или не ноль. `any` останавливается на первом истинном и даёт int 0 или 1, а для пустого входа — 0. `all` останавливается на первом ложном и даёт 0 или 1, а для пустого входа — 1. `index` останавливается на первом истинном и даёт существующий Maybe от индекса с нуля, `some(i)`, либо `none()`, когда ничего не подошло или вход пуст. `count` обходит каждый элемент слева направо и даёт число истинных результатов, а для пустого входа — 0. После решающего элемента обратные вызовы больше не делаются, и ни один вызов не делается заранее, чтобы определить тип. Нет ни SearchResult, ни сигнального значения −1, ни второй обёртки вокруг Maybe.

| Условие | Отказ |
| --- | --- |
| Недопустимый физический индекс; недопустимые границы строгого `slice(source; begin; end)`, `replaceRange` или `splice` | `ReceiverIndex` |
| Не полная перестановка | `ReceiverPermutation` |
| Неравные длины числовых массивов или маски; строки неравной длины | `FxShape` |
| Недопустимый или неподдерживаемый токен типа | `FxTypeToken` |
| Нулевой шаг `range` или знакового/шагового среза | `SequenceStep` |
| Размер или длина, которые нельзя представить без переполнения | `SequenceSize` |
| Элемент, недопустимый для плотной цели; элемент маски, не являющийся int | `SequenceElement` |
| Результат `accepts` нового запроса — не int | `FxPredicate` |
| Объявленный отказ пользовательского обратного вызова | `FxCallFailure` с исходным именем и нагрузкой |

Это обычные объявленные отказы, а не новый механизм исключений. Отказы прямой скалярной арифметики, допуска пользовательского метода, системные пределы памяти и неявные отказы сохраняют свои существующие каналы. Новый запрос явно проверяет тип результата `accepts`, прежде чем потребить его как int; это не перехватывает и не переименовывает неявный отказ, возникший при вызове обратного вызова или при его возврате. Существующий `filter` сохраняет свой обычный допуск результата как int. "A sequence was expected" сообщается обычным допуском этого требования: ссылка на число не превращается в массив из одного элемента, а сырой адрес не принимается лишь потому, что он имеет машинный размер указателя.

`foldl` даёт шагу два явных фактических аргумента — предыдущий накопитель и элемент — в строго левой свёртке и возвращает ссылку `@` на последнее значение накопителя; для пустого входа он возвращает исходный seed без вызова. `scanl` возвращает seed, за которым следуют n последующих накопителей, и хранит ссылки на возвращённые состояния: когда шаг возвращает одну и ту же изменяемую цель, история ссылается на эту цель, и глубоких снимков не делается; пустой `scanl` содержит один seed. `bind` вызывает `next` один раз на элемент и соединяет возвращённые последовательности на один уровень вглубь в новый `@[]`; вложенный массив остаётся одним элементом. `traverse` возвращает существующий Maybe и останавливается на первом `none`; при успехе он содержит обычную последовательность `@` результатов. `groupBy` берёт текущий целый элемент как ключ при `keyOf=0`, иначе вызывает выбранный `keyOf` один раз на элемент; `sameKey=0` выбирает общее равенство по умолчанию; порядок групп и членов устойчив; у каждой группы поля `key` и `items`, а `items` — обычная последовательность `@`. Плотный источник не делает эти вложенные результаты плотными. Пустые `map`, `filter`, `zip` и `bind` дают пустой результат своего установленного вида. `zip` сохраняет свою форму пары с полями `first` и `second`; для элементов Structure поля ссылаются на исходные значения, а для плотных примитивов хранимое значение — обычная примитивная запись: адрес внутри плотного хранилища никогда не выдаётся за адрес независимой `{type value}`.

`select`, `omit` и `reorder` принимают индексы через `@` как последовательность целых: плотный `int[]` или обычную Structure из целых. `select` допускает повторы, а порядок его результата — порядок индексов. `omit` сохраняет порядок оставшихся элементов, а повторный индекс исключения не удаляет дополнительных элементов. `reorder` требует полной перестановки: нужной длины, допустимых индексов и без повторов. Индексы проверяются полностью до построения наблюдаемого результата. Источник Structure/`@[]` даёт прямые ссылки на выбранные значения; плотный источник даёт выбранные значения в новом типизированном хранилище. `transpose(rows)` принимает последовательность строк равной длины, каждая из которых — последовательность, читаемая через тот же универсальный доступ, и возвращает последовательность столбцов, каждый из которых — обычная последовательность `@`. Пустой внешний `rows` даёт пустой результат, а n пустых строк дают ноль столбцов. Строки неравной длины отклоняются отказом `FxShape`; `transpose` — не неявное изменение формы плоского прямоугольного массива. `list(values)` делает новый `@[]` из значений любой допустимой последовательности и никогда не требуется перед `map`, `filter` или `foldl`.

`replaceRange` требует `0 <= begin <= end <= length(target)`. Новая длина равна `oldLength - (end - begin) + length(values)`, и каждая величина проверяется без переполнения. `values` — обычная последовательность любого допустимого вида, принимаемая через `@`. В цель Structure/`@[]` непосредственные ссылки записываются без проверки по имени, типу или требованию прежнего элемента. В плотную цель T каждый вставляемый элемент должен быть допустимым T без скрытого пользовательского преобразования, при обычных встроенных преобразованиях, и весь набор проверяется до изменения цели; источник другого вида хранения не причина для отказа, если его значения допустимы. `append(target; values)` — это `replaceRange` с `begin = end = length(target)`, взятой до вызова; `insert(target; position; values)` — `replaceRange` с `begin = end = position`; `deleteAt(target; begin; end)` — `replaceRange` с пустыми values.

Плотные массивы, массивы ссылок и смешанные пары из них — допустимые операнды; единый физический тип всего входа не требуется. Операцию над каждой парой решают фактические типы её двух значений по обычному скалярному контракту. `@[]` может содержать значения разных типов: каждая достигнутая пара должна допускать операцию, и несовместимый элемент не пропускается и не заменяется нулём. Правила скалярных преобразований действуют без изменений, а профиль не добавляет автоматического повышения. Деление сохраняет скалярный тип результата, округление и отказы; массив не вводит преобразования во float. Исходные массивы не меняются. Несовпадение длин обнаруживается до первой поэлементной операции, поэтому отказ поэлементной операции, например нулевого делителя, никогда его не заменяет. `result := A + B` присваивает месту новую ссылку; это не поэлементная запись в массив, который `result` держал раньше. Составное присваивание сохраняет обычный смысл, `a += b` — это `a := (a + b)`, и не обещает изменения прежнего хранилища; когда важна идентичность контейнера цели, используется явный ресивер мутации.Материальные группы в `(2; 5; 9) * (3; 4; 2)` следуют общему группировщику и выбранному последовательностному договору; они не уплощаются рекурсивно и не становятся скалярными выражениями только по количеству потомков.

Явный фактический аргумент подавляет инициализатор своего входа. Пропущенный вход со своим значением по умолчанию сохраняет это значение, а неиспользуемое вычисляемое значение по умолчанию не исполняется ради общего транспорта. Пропущенный фактический аргумент никогда не заменяется нулём, пустой Structure, null или искусственной uninit-записью. `private` фильтрует неявное связывание по обычному правилу, а явная подача остаётся допустимой. Состояние обхода защищено от случайного связывания с пользовательскими именами; адаптеры не чинят снятием каждого `private` или объявлением каждого входа обратного вызова required или private. Служебный формат уже подготовленных фактических аргументов, такой как у `attempt`, внутренний и не является обязательным пользовательским форматом коллекции. Вложенная Structure — один фактический аргумент: транспорт не применяет к ней W/E повторно и не исполняет её. Фактические DATA/parent обратного вызова сохраняются; контейнер элементов, внутренний движок и место вызова не становятся его лексическим владельцем. Динамическое связывание следует фактической цепочке вызовов: операция, добавляющая собственный обычный вызов, не обещает пропускать этот уровень и восстанавливать алиас внешнего вызывающего, и глобального снимка окружения нет. Во время обхода обратный вызов не меняет состав обходимой последовательности, её длину и хранимые элементы; другие объекты могут меняться, и изменение видно последующим вызовам. Глубокий снимок источника не делается, а правилу не нужна система, отслеживающая каждую запись. Отказ на элементе i останавливает обход: элементы i + 1 и далее не обрабатываются, частичный результат `map`, `filter` или `scanl` не возвращается как успех, а уже сделанные эффекты остаются. Общие вызовы сохраняют `FxCallFailure` с исходным именем и нагрузкой; неявный или системный отказ не превращается в `FxCallFailure`, `none`, false, повтор или универсальный Result.

Обязательные входы новых ресиверов принимаются явно: отсутствующий обязательный фактический аргумент не заполняется одноимённой локальной переменной. Их собственные значения по умолчанию, такие как `step := 1`, сохраняются, а служебные места реализации приватны. Эти правила не меняют политики входов подаваемого обратного вызова.

Нулевое значение, нулевая ссылка, пустая последовательность, void, `None` и `uninit:T` остаются разными случаями. Перенос ссылки на запись `uninit:T` не читает нагрузки; чтение значения или его допуск конкретным обратным вызовом — обычная проверка этого использования, а не обязанность каждого обхода.

Сохранение профиля хранения сохраняет вид элементов и способ их хранения; оно не угадывает новой многомерной формы. Линейный обход посещает непосредственные элементы в физическом порядке, а `length` остаётся общим числом элементов. Новый выбранный результат имеет линейное описание: операция не строит строк или формы из одной длины и не переписывает внешних описаний размерностей, а вставка или удаление в плоском хранилище не обещает пересчитать внешнее многомерное описание.

Четыре обычных действия различаются: новый внешний контейнер ссылок не меняет элементов источника; `copy` или `project` создаёт скопированный граф под одной общей картой; явная запись в выбранный граф меняет его содержимое; присваивание локальной переменной активации меняет её собственное место и не публикуется в графе. Скопированный метод сохраняет своего скопированного лексического владельца, а контейнер не становится родителем метода оттого, что держит на него ссылку. Отдельные операции копирования имеют собственные карты; одна общая операция использует одну карту. Физическая запись в элемент Structure не добавляет проверки по требованию прежнего содержимого элемента. Копия метода с неизменным телом не обязывает очищать совместимую native-реализацию; последующая запись в граф ни обновляет, ни очищает её вход.

Массив char — это массив физических элементов char точной длины: внутренний NUL — обычный элемент, завершающий NUL не добавляется. Срез элементов char — не срез Unicode; позиции скалярных значений Unicode используют явно выбранный текстовый профиль из [текстовых шаблонов](#patterns).

Новые результаты следуют обычным правилам Message и арены; одна ссылка не продлевает жизнь завершённой активации. Хранимое примитивное значение никогда не указывает на завершённую локальную переменную C-стека, а перенос или возврат ссылок не разрешает скрытого глубокого копирования окружения ради исправления времени жизни. Результат, держащий ссылки на источник, — независимый внешний контейнер, а не обещание, что каждый достижимый объект независим; `copy` и `project` дают независимый граф.

Профиль последовательностей не добавляет ни общего широковещания размерностей, ни скрытых представлений строк, ни хранилища для изменения формы, ни ленивого конвейера, ни рекурсивного уплощения, ни синонимов `foldl`, `scanl` или `each`. Многомерные массивы, iterator/yield и обычное описание других алгоритмов Structure остаются. `each` сохраняет свои правила iterator/yield/Stop. `compose` строит вызываемое, сохраняя исходную политику входов и точный результат; `pipe` применяет этапы к целому типизированному значению и возвращает фактический итоговый результат. `repeat` и `lazy` сохраняют свои различные контракты исполнения, включая кэшируемый результат `lazy`. [Канонические операции](GENERIC_OPERATIONS.md) отличают построение от применения к значению.

<a id="patterns"></a>
## 4. Шаблоны над типизированными источниками

Pattern — обычное вызываемое структурное требование над `RxPreparedSource`, позицией и текущим состоянием захватов. Подготовленный источник содержит типизированную последовательность единиц, исходное представление и явный профиль области. `arrayView(xs)` сохраняет полные типизированные элементы конечного Array. `utf8Text` и `byteText` сохраняют свои существующие профили декодирования и границ байтов. Один курсор, один журнал захватов и один порядок кандидатов обслуживают любую область. Текст в роли текстового шаблона остаётся литеральным текстом и никогда не разбирается как строка regex. Обычные структуры и вызываемые LMX реализуют механизм без байткода regex и без второго рабочего графа.

| Выражение | Операция | Приоритет |
| --- | --- | --- |
| `P times n`, `P atLeast n`, `P atMost n`, `(P optional)` | Точное, ограниченное снизу, ограниченное сверху или 0..1 повторение | Существующий приоритет умножения |
| `P then Q` | Упорядоченная смежная последовательность | Существующий приоритет сложения |
| `P \| Q` | Упорядоченная альтернатива с возвратом | Существующий приоритет побитового или |

Значения приоритета берутся из обычного `sys\priority`. Повторение и затем группы обрабатываются слева направо. Слова-операнды объявляют приватные места left/right; отсутствующий левый остаётся пропущенным, а постфиксное вхождение даёт пустой правый вектор. Ветвь Pattern добавляется к существующему `|` только когда хотя бы один логический аргумент уже является Pattern. Иначе всё прежнее числовое/массивное поведение и существующие правила связывания не меняются. Остальные аргументы ветви Pattern должны удовлетворять выбранному Pattern или явной роли литерального источника; неоднозначные структурные значения не выбирают область по своим полям. `|=` следует общему правилу составного присваивания с однократным вычислением.

Операндные формы `then` и Pattern `|` принимают не менее двух логических аргументов; форма с пустым левым может дать больше. Обычный `then` принимает 0/1/N частей: ноль даёт `emptyPattern`, одна часть возвращает этот Pattern. `times/atLeast/atMost` принимают один шаблон и счётчик; `optional` — один шаблон. Арность проверяется после обычной группировки и никогда не используется, чтобы задним числом поглотить соседний исходный текст. Для двух составных групп пишите `(then (P | Q) (R | S))`; левого аргумента нет и случайного открытия только правого нет. Обычный `then(P; Q)` приходит к тому же алгоритму композиции через объявленное отображение фактических аргументов на части.

| Группа API | Прямые имена |
| --- | --- |
| Примитивные построители | `literal`, `element`, `oneOf`, `noneOf`, `within`, `satisfy` |
| Композиция | `then`, `choice`, `repeated`, `atomic` |
| Захваты и контекст | `capture`, `sameAs`, `ahead`, `notAhead`, `behind`, `notBehind`, `boundaryOf` |
| Готовые шаблоны | `emptyPattern`, `neverPattern`, `anyElement`, `lineChar`, `lineBreak`, `asciiDigit`, `asciiLetter`, `asciiWord`, `asciiSpace`, `start`, `end`, `lineStart`, `lineEnd`, `wordBoundary` |
| Значения повторения | `extendFirst`, `stopFirst`, `unbounded` |
| Представления источника | `arrayView`, `utf8Text`, `byteText` |
| Сопоставление и поиск | `matchAt`, `wholeMatch`, `find`, `eachMatch`, `contains`, `matches`, `hasPrefix`, `hasSuffix` |
| Доступ к результатам | `matchedSpan`, `matchedValue`, `captureSpans`, `lastCapture`, `captureValue`, `captureValues` |
| Порождение с сохранением профиля | `replaceFirst`, `replace`, `split` |

`then/choice` принимают любой подходящий массив через @, включая Pattern[] и Structure, не преобразуя его вид. Пустая последовательность успешна с нулевым потреблением; пустой выбор не успешен никогда. `repeated` по умолчанию имеет минимум 0, максимум `unbounded` и порядок `extendFirst`. Границы неотрицательны, а конечный максимум не меньше минимума. `unbounded` — отдельное обычное значение настройки, а не отрицательный счётчик. `stopFirst` пробует остановку перед очередной итерацией в каждой допустимой точке; это локальный порядок попыток, а не обещание глобально кратчайшего результата составного Pattern. Существующие `some`, `none`, `repeat`, `lazy`, `record`, `guard` и `match` сохраняют свой смысл. В частности, `lazy` остаётся нульарной вызываемой оболочкой, кэширующей первый успех.

### Предикаты всего источника и границ

Все эти операции принимают Pattern или явную совместимую роль литерального источника. Текст никогда не разбирается как синтаксис regex. Позиции используют единицы и допустимые границы выбранного профиля источника; элемент Array остаётся целым.

| Ресивер | Результат | Принимаемое совпадение |
| --- | --- | --- |
| `wholeMatch(source; pattern)` | Maybe от Match | Начинается в 0 и заканчивается в конце источника |
| `matches(source; pattern)` | int 1/0 | То же условие на весь источник |
| `hasPrefix(source; pattern)` | int 1/0 | Начинается в 0; может закончиться раньше конца источника |
| `hasSuffix(source; pattern)` | int 1/0 | Начинается в любой допустимой позиции и заканчивается в конце источника |
| `contains(source; pattern)` | int 1/0 | Может начинаться и заканчиваться где угодно |

`hasSuffix` рассматривает кандидатов в каждом значимом допустимом начале, включая перекрывающиеся начала и более поздние альтернативы с тем же началом. Его нельзя определять как проверку последнего неперекрывающегося результата `find`/`eachMatch`. Для источника `ab` шаблон `literal("a") | "ab"` успешен как суффикс: отклонение более раннего неполного кандидата должно позволять более позднему полному. Для `ababa` и литерала `aba` успешен кандидат, начинающийся в 2, хотя неперекрывающийся перебор мог выбрать совпадение в 0. Это не отменяет явного ограничения `atomic` шаблона.

Пустой Pattern — допустимый префикс в 0 и суффикс в конце; те же граничные правила действуют для пустого источника. `wholeMatch`/`matches` по-прежнему требуют полного покрытия. Якоря и lookaround видят исходный контекст всего источника: проверка суффикса не разворачивает текст и не сопоставляет срезанную подмену. Ошибка сопоставления распространяется как ошибка, никогда как false. Существующие требования к завершению и эффектам предикатов не меняются.

### Порядок кандидатов, захваты и нулевой прогресс

Sequence исследует продолжение после каждого более раннего кандидата, возвращаясь, когда нужно. `matchAt` выбирает первого кандидата в своём начале; `wholeMatch` может отвергнуть более раннего неполного кандидата и принять более позднего полного. `atomic(P)` сохраняет только первый локальный успех P, не подавляя альтернатив вне P.

Повторение пустого совпадения может выполнить конечный минимум, но дальнейшее расширение с нулевым прогрессом прекращается. Каждый захват принадлежит своей успешной ветви; неудачные попытки отбрасывают свои изменения захватов. Повторные имена сохраняют историю. Отсутствующий захват и присутствующий захват нулевой длины различаются. `sameAs` сравнивает предшествующий захваченный диапазон с текущим диапазоном через `FxSequenceDifference`, используя оба начала; его поведение — явно расширенный, не чисто регулярный профиль. Lookaround восстанавливает и внешний курсор, и журнал захватов; ошибка сопоставления никогда не толкуется как успех отрицательного lookaround.

`eachMatch` отличает кандидата нулевой длины от непустого кандидата в том же начале и не пропускает последнего. Он продвигается по допустимым позициям единиц источника и завершается, в том числе в конце ввода. `emptyPattern` на `ab` даёт позиции 0, 1, 2; замена на `-` даёт `-a-b-`; разбиение даёт четыре части, включая два пустых края. Каждый возвращённый Match хранит свои устойчивые диапазоны и историю захватов. Обратные вызовы замены выполняются один раз на каждое выбранное совпадение, и вставленные единицы повторно не ищутся. `replace` возвращает вновь порождённое значение, собранное профилем источника, не изменяя источник; `replaceFirst` сохраняет предел в одно совпадение. Текст сохраняет свою кодировку, а вывод Array сохраняет описанное требование к элементу и результату. Эти операции независимы от интервальных мутаций `replaceRange` и `splice`.

`matchedSpan` возвращает Span, хранящий своё представление источника и `[begin,end)`. `matchedValue` материализует выбранный фрагмент через профиль этого источника: текст даёт текст, представление Array — соответствующий Array. `captureSpans` и `captureValues` сохраняют историю захватов; `lastCapture` и `captureValue` возвращают Maybe и различают отсутствие и присутствующий пустой захват. Представление и ссылки на подготовленный источник сохраняют тождество и время жизни; указатель на перемещаемое хранилище не публикуется. Материализация копирует внешний выбранный фрагмент; сами диапазоны, опирающиеся на источник, снимка не обещают.

### Профили источников, эффекты и время жизни

Поиск принимает явно допущенное представление источника. `arrayView` показывает целые типизированные элементы, не превращая плотное хранилище в массивы ссылок. Следующие текстовые правила относятся к TextView. `utf8Text` считает скалярные значения Unicode, а не байты и не кластеры графем, и отклоняет некорректный UTF-8 по заданной политике проверки. `byteText` считает байты и проверяет своё основание по фактической раскладке char. Локали, нормализации и свёртки регистра по умолчанию нет. Классы ASCII зафиксированы; `lineBreak` считает CRLF одним логическим разделителем и не совпадает отдельно с его LF.

Обратные вызовы предикатов, используемые при исследовании кандидатов, должны завершаться и не иметь внешне видимых записей, на которые опирается возврат. Сопоставитель изменяет только собственное состояние попытки. Аргументы построителя вычисляются один раз при построении, даже если последующий счётчик повторения равен нулю; сопоставление отложено. Эффекты замены происходят после выбора совпадения. Объявленные и системные ошибки остаются ошибками, а не несовпадением, false, None или повтором.

Публичный TextView хранит исходный дескриптор источника и явный профиль, а не кэшированный индекс единиц и смещений. Каждая публичная операция поиска, замены или разбиения один раз готовит текущие единицы и смещения; итератор `eachMatch` сохраняет этот подготовленный контекст на время приостановки и завершения. `Match.source` и `Span.source` сохраняют идентичность исходного TextView, а их закрытый подготовленный контекст хранит индекс для породившей их операции. Новые операции никогда не перезаписывают подготовленный индекс более раннего результата.

Источник должен оставаться живым и неизменным на протяжении операции, приостановленной итерации и доступа к результатам, опирающимся на источник. После завершения этих использований вызывающий может изменять источник и использовать тот же TextView в новой операции. Эта операция читает текущие байты, перестраивает границы скаляров и проверяет текущую кодировку. Это не добавляет требования неизменности на всё время жизни, снимка источника или обнаружения изменений во время активной операции.

### Точные контракты текстовых шаблонов

`Pattern`, `RxPreparedSource`, `ArrayView`, `TextView`, `Match` и `Span` — обычные структурные требования и значения. Они не регистрируют ни специфичных для шаблонов физических кодов типов, ни дополнительных полей `Lmx`, ни новой категории указателей, ни языка инструкций; массивы и типизированные ссылки, которые они используют, получают свои коды от общего механизма типов. Pattern — обычная вызываемая Structure с настоящими DATA/parent. Применение его ко входу, позиции и текущему состоянию захватов даёт упорядоченную последовательность возможных продолжений; продолжение держит новую позицию и журнал захватов своего пути. Это описывает наблюдаемый контракт: реализация может перечислять продолжения обычным итератором, хранить явные продолжения или использовать подготовленный native-код. Построители строят готовые значения Pattern: они ничего не сопоставляют, не читают будущего ввода и никогда не вызывают тело поданного Pattern. Pattern можно хранить, передавать, возвращать и собирать из значений времени выполнения; действуют обычные правила вызова и допуска, и статически фиксированной арности всего Pattern не требуется. Строка в позиции Pattern принимается по контракту потребителя как литеральная последовательность, а пустая строка равна `emptyPattern`; это решение потребителя, а не преобразование P0 и не грамматика regex внутри строки. Одно число не означает ни символа, ни диапазона, ни числа повторений: его смысл задаёт конкретный параметр ресивера. Готовое имя, такое как `anyElement`, читается как значение; это не неявный вызов без аргументов. `Match` держит как минимум `source`, `begin`, `end` и `captures`; `source` хранит исходное представление и его подготовленный источник/профиль с правилом толкования позиций.

Пять слов-операндов используют `PASS_ARGS_AS_IS = 0`. Их логический список аргументов — записанный левый аргумент, если он есть, за которым следуют элементы `right`; это внутреннее правило метода, ABI не меняется. `left` не переносится в `right` и не дублируется, а строка или массив остаются одним аргументом:

| Форма | `left` | `right` | Логический список |
| --- | --- | --- | --- |
| `P then Q R` | P | Q, R | P, Q, R |
| `(then P Q R)` | отсутствует | P, Q, R | P, Q, R |
| `P times 3` | P | 3 | P, 3 |
| `(times P 3)` | отсутствует | P, 3 | P, 3 |
| `(P optional)` | P | присутствующий пустой массив | P |
| `(optional P)` | отсутствует | P | P |

Префиксная форма `(| P Q R)` перечисляет ветви в записанном порядке по тому же расширенному контракту `|`. Пустая или одноэлементная последовательность частей записывается через `then` или `choice`. У `P optional Q` лишний аргумент; последовательность записывается `(P optional) then Q`. По общему правилу открытия `(x y) op (a b)` даёт целиком `(x y)` как left, а `a`, `b` как right, тогда как `(x y) op ((a b))` даёт один `(a b)` как right. `then(patterns := S)` передаёт S целиком через именованный фактический аргумент без обычного выбора W/E. Обычная и операндная формы сохраняют своё объявленное отображение аргументов и делят одну операцию: `atomic(pattern := P)` получает один Pattern через представление ресивера, а его операндное представление сохраняет ту же роль целого Pattern. Ссылки на методы и Patterns сами по себе не вызываются. Сложный счётчик группируется: `P times (n + 1)`.

`|` получает одно новое значение — упорядоченную альтернативу Patterns, одинаково используемую в `asciiLetter | asciiDigit` и `literal("cat") | "dog"`. Классы символов — обычные Patterns из одного символа; отдельной ветви, объединяющей классы, убирающей совпадающие пути или меняющей правила ошибок, нет. Когда хотя бы один логический аргумент `|` — готовый Pattern, каждый другой должен быть Pattern или текстом, принимаемым буквально; произвольная Structure или число Pattern не становится. Когда Pattern нет, действует прежний контракт `|`, а внешний `wholeMatch` не меняет смысла уже вычисленной операции. Альтернатива одних текстов записывается `literal("a") | "b"` или `choice(patterns := ("a" "b"))`. Строка LMX — массив типа `char[]`, поэтому `"a" then "b"` и `"a" times 3` имеют смысл сразу, без начального маркера Pattern и без затрагивания `+` или `*`. Арифметические `+`, `*` и операции `&`, `-`, `~` не получают смысла Pattern; слов `or`, `and`, `xor` нет. Последовательность — это `then`, просмотр вперёд и назад имеют явные ресиверы, а более сложный набор символов задаётся `satisfy` с обычным предикатом. Логические `&&`, `||`, `!` и побитовые `&`, `^`, `~` сохраняют свои смыслы.

`literal(value)` строит Pattern для блока единиц источника. Для текстового профиля он декодирует сохранённый текст; для профиля Array сравнивает целые типизированные элементы. `element(value)` сопоставляет одно целое значение, включая вложенный Array или ссылку. Захват аргумента конструктора происходит один раз. Зависящая от области совместимость литерала проверяется, когда источник готовится к сопоставлению; явно типизированная текстовая запись может сохранить раннее допущение char[] без отдельного алгоритма сопоставления. Пустой литерал означает успешное нулевое потребление, а не None.

`oneOf(values)` и `noneOf(values)` после подготовки области используют общий поиск `FxKeyIndex` и равенство `FxValueSame`. Их порядок и повторяющиеся члены не вводят альтернативных захватов. Пустые наборы членов дают `neverPattern` и `anyElement`. Каждый успешный класс потребляет одну единицу. `within(first; last)` использует явно выбранный профиль упорядоченных значений; включающие границы и отказ при обратных границах остаются определёнными. Текстовый профиль допускает по одной декодированной единице на границу и сохраняет прежний числовой порядок символов. Этот контракт отличен от числового конструктора последовательностей `range`.

`satisfy(predicate)` и `boundaryOf(predicate)` проверяют настоящую сигнатуру вызываемого при построении, не выполняя его: один допущенный вход и результат `int`. Эта проверка выполняется ещё до сопоставления с пустым источником. Каждый достигнутый обратный вызов получает фактический целый типизированный элемент; общий потребитель предиката проверяет его результат. Несовместимость и отказы обратного вызова остаются ошибками, а не несовпадением. Поданный предикат чист и завершается по контракту сопоставления.

Классы ASCII остаются текстовым профилем: `asciiDigit` — U+0030..U+0039, `asciiLetter` — A..Z/a..z, `asciiWord` добавляет цифры и подчёркивание, а `asciiSpace` состоит из SPACE, TAB, LF, CR, FF и VT. Зависимости от локали нет. `anyElement` потребляет одну единицу в любом допущенном источнике; `lineChar`, `lineBreak` и якоря строк и слов сохраняют свой явный текстовый профиль. CRLF — один логический разделитель из двух текстовых единиц, без независимого совпадения с его LF. Эти правила областей не создают второго движка Pattern.

`then(patterns := S)` и `choice(patterns := S)` принимают готовую последовательность S через универсальный `@`; вид массива и доступ к его непосредственным элементам следуют фактическому значению и его существующему типу. Каждая часть допускается как существующий Pattern или явно выбранная роль литерального источника. Одно число само по себе не становится Pattern по физической форме; `element` выражает одно значение явно. Вложенный Pattern остаётся одной частью; рекурсивного открытия нет. Один элемент сохраняет своё поведение. Обычная Structure принимается как `@[]`: категория или способ объявления контейнера не повод для отказа. Передача той же Structure через инициализированную переменную `[]` или `@` сохраняет идентичность контейнера, ссылки на его части и их обычные связи parent; требования частей проверяются как прежде. Операнды — удобные формы `repeated`: `times n` задаёт обе границы равными n, `atLeast n` задаёт минимум n, `atMost n` — диапазон от 0 до n, а `optional` — диапазон от 0 до 1; все они используют `extendFirst`. `atomic(pattern := P atLeast 0)` даёт повторение, не отдающее уже выбранный текст обратно последующей части.

`start` и `end` проверяют точные границы всего ввода; завершающий перевод строки для `end` не исключение. `lineStart` успешен в начале ввода и сразу после полного `lineBreak`; `lineEnd` успешен в конце ввода и перед началом полного `lineBreak`. Якоря строк не успешны между CR и LF. Пустая строка и позиция после последнего разделителя имеют обе обычные границы. `wordBoundary` успешен там, где принадлежность соседних единиц к `asciiWord` различается; вне ввода считается «не слово». Это техническая граница ASCII, а не определение слова естественного языка. Другую границу задаёт `boundaryOf(predicate := F)`: чистая завершающаяся проверка одной единицы задаёт принадлежность. Ресивер сравнивает результаты по двум сторонам позиции, принимает результат вне ввода как ложь без вызова F и не пытается анализом доказать, что произвольный Pattern имеет один символ.

В одной начальной позиции каждый Pattern задаёт порядок кандидатов. `P | Q` рассматривает кандидатов P раньше кандидатов Q. `P then Q` для текущего кандидата P рассматривает подходящие продолжения Q; когда они исчерпаны, возвращается к следующему кандидату P. Порядок сохраняется при вложении. `extendFirst` пробует ещё одну итерацию раньше остановки в каждой допустимой точке; `stopFirst` пробует остановку раньше ещё одной итерации. Остановка запрещена до достижения минимума, а продолжение запрещено на максимуме; внутри тела сохраняется его собственный порядок альтернатив. Это локальный порядок поиска, а не глобальная сортировка по длине или по числу итераций: альтернативы `literal("aa") | "a"` могут дать одну итерацию `aa` раньше двух итераций `a`, а ни начальная позиция, ни порядок записанных альтернатив не перестраиваются ради более длинного совпадения. `emptyPattern times 3` успешен, а `emptyPattern atLeast 0` не создаёт бесконечной цепочки: при `extendFirst` он делает одну пустую итерацию, а при `stopFirst` сначала предлагает ноль итераций. Когда у тела есть другие варианты, возврат сохраняет возможность их перебора, а захваты отражают в точности выбранное число выполненных итераций. Из этого не следует отката внешнего графа: отбрасываются только собственные данные попытки, позиция и журнал захватов. Обычный `retry` не переопределяется и не становится транзакцией.

`capture(name; pattern)` запоминает начальную позицию, запускает `pattern` и добавляет его успешный диапазон в историю имени. Имя — обычная строка, сравниваемая по содержимому; глобального реестра захватов нет. История хранит все завершённые захваты успешного пути, включая повторения. Несколько вхождений одного явного имени добавляют элементы в одну историю в порядке завершения: внутренний захват того же имени завершается раньше внешнего. `sameAs(name)` потребляет диапазон, равный последнему завершённому захвату этого имени на текущем пути, используя общий двухстартовый компаратор в единицах выбранного источника. Без такого захвата это обычное несовпадение, а более поздний захват справа не считается уже полученным. Захваты не пишут в локальные переменные вызывающего и не используют их как резервный источник. `ahead(pattern := P)` проверяет, что у P есть результат от текущего начала. `behind(pattern := P)` проверяет, что у P есть результат, заканчивающийся точно в текущей позиции; его возможные начала лежат между 0 и этой позицией, статически известная ширина не требуется, хотя оптимизация фиксированных диапазонов разрешена. Отрицательные формы успешны, когда такого результата нет; внешняя позиция не меняется. Lookaround — чистая проверка: его внутренние захваты наружу не публикуются, а более ранние захваты можно читать через `sameAs`. Ошибка внутри проверки остаётся ошибкой и никогда не становится успехом отрицательной формы. Полная совместимость с поведением захватов Perl не заявляется.

`find` пробует начальные позиции от 0 до длины включительно, выбирая наименьшее успешное начало и, внутри него, первого допустимого кандидата. `contains` проверяет наличие результата `find`, а `matches` — наличие результата `wholeMatch`; ни один из них не материализует текст захватов, чтобы получить булево. После непустого результата `[s,e)` `eachMatch` ищет заново с e. После пустого результата `[s,s)` он сначала снова проверяет то же начало, исключая каждого кандидата нулевой длины: непустой кандидат там выдаётся, иначе начало сдвигается на одну единицу. В конце ввода поиск завершается после последнего пустого результата. `eachMatch` не обязан заново выдавать каждый вариант нулевой длины одного начала. История захватов каждого выданного совпадения начинается заново. Итератор использует обычный `yield` и завершение через `throw: Stop`; любой другой объявленный выход остаётся ошибкой. `replaceFirst` использует первый результат `find`, а `replace` — последовательность `eachMatch`; оба возвращают новое значение, собранное выбранным профилем источника, и не меняют источник. Без совпадений результат равен источнику по значению; идентичность адреса не обещается. Когда обратный вызов замены отказывает, частичный результат не возвращается, а внешние эффекты уже выполненных обратных вызовов не откатываются. Копирующий курсор фрагментов источника и позиция следующего поиска — разные значения, поэтому продвижение после пустого совпадения не теряет ни одного элемента источника между вставками. `split` использует тот же порядок непересекающихся разделителей. Он порождает значения профиля источника между их интервалами, исключает разделители и сохраняет пустые поля, включая внешние; захваты разделителя в результат не добавляются, а части — новые внешние массивы, допущенные профилем источника. Без разделителя результат — один элемент, весь ввод; пустой ввод без разделителя даёт один пустой элемент. Пустой ввод с `emptyPattern` имеет один пустой разделитель и даёт два внешних пустых поля. Неявных режимов, убирающих внешние пустые поля, вставляющих захваты, ищущих с перекрытием или ограничивающих число замен, нет.

`utf8Text(source)` делает обычное представление корректного UTF-8. Его единицы и все публичные позиции — скалярные значения Unicode, а не кодовые единицы UTF-16 и не графемы; CRLF занимает две единицы. Источник остаётся исходным массивом `char[]` точной длины: завершающий NUL не добавляется, а внутренний U+0000 — обычный символ. `byteText(source)` читает каждый элемент как байт со значением от 0 до 255 независимо от знаковости C `char`; байтовый профиль требует восьмибитной байтовой основы, и другой машинный профиль молча не получает другого диапазона значений. Позиции считаются в байтах. Текстовые литералы в Pattern толкуются в том же выбранном профиле; примеры ASCII одинаковы в обоих. Некорректный UTF-8, включая суррогатные кодировки и недопустимые последовательности, отклоняется отказом `PatternEncoding`; декодер никогда не вставляет U+FFFD. Будущие свойства Unicode потребуют явно поданной версии своих таблиц и описанного профиля, а смена этих таблиц не должна молча менять смысл уже подготовленного Pattern. Построитель не хранит временных служебных ссылок `left`/`right` на записи завершённой активации. Числовые параметры хранятся по значению; ссылки на Patterns, тексты, имена захватов и последовательности частей хранятся в собственных обычных DATA построителя с допустимым временем жизни. Зависимости по ссылкам остаются живыми и неизменными, пока не завершатся применения Pattern и доступ к результатам, которые их держат; независимые копии вызывающий делает явно.

| Ситуация | Исход |
| --- | --- |
| Pattern не подходит, включая отсутствующий захват `sameAs` | Нет результата или кандидата |
| Успешное пустое совпадение | Присутствующий результат с равными границами |
| Отрицательный счётчик повторений, неверная арность, обратный диапазон | `PatternArgument` |
| Недопустимая кодировка | `PatternEncoding` |
| Позиция вне диапазона от 0 до длины | `PatternPosition` |
| Несовместимый обратный вызов, неверное значение вместо Pattern | Обычная ошибка допуска LMX |
| Объявленный выход обратного вызова | Обычное распространение по его контракту |
| Исчерпание применимого явного предела ресурсов | Отдельная ошибка предела, а не "не найдено" |

`PatternArgument`, `PatternEncoding` и `PatternPosition` — обычные объявленные отказы; нового канала исключений не требуется. Подавление ошибок внутри `notAhead` и `notBehind` запрещено.

Основной интерфейс использует готовые значения Pattern и `PASS_ARGS_AS_IS = 0`. Отдельный потребитель исходного Expression может использовать `PASS_ARGS_AS_IS = 1`, но это его собственный контракт с явно заданным моментом вычисления и захвата контекста; он не заменяет режима `|` или слов-операндов, и этому словарю такой потребитель не нужен. Общей гарантии линейного времени для произвольных расширений не заявляется. Рекурсивные правила, преобразование захватов в произвольные значения при возврате, условия на захват и предикаты с эффектами не входят в эту версию; они могут стать обычными расширениями вызываемых или ресиверов с точными контрактами, а наличие общего `sys\eval` эти контракты автоматически не определяет.

<a id="adapters"></a>
## 5. Адаптеры вызываемых и точные сигнатуры

Одна публикация библиотеки сохраняет представления ресивера и операнда под одним каноническим именем. Роль формы записи источника выбирает представление этого семейства до обычного выбора перегрузки. Maybe или Result физически тоже Structure/Array; семейство по смыслу определяет явный полный контракт приёма, а не физическое хранение или порядок объявления. Настоящие пересечения остаются обычной неоднозначностью и никогда не разрешаются выполнением тел кандидатов. [Общий контракт операций](GENERIC_OPERATIONS.md) определяет входы VALUE, TYPE, RAW и PLACE, адаптивные конструкторы, общие источники Pattern и операции профиля источника.

[Контракт адаптеров](LMX_semantics.ru.md#adapter-observations) загруженной семантики сохраняется. Тождество типа остаётся упорядоченными требованиями к входам плюс требованием к результату; метки, значения по умолчанию, политики private/required и объявленные выходы — дополнительное поведение вызова, а не выдуманные компоненты типа. Именованное `Name :: DATA` и форма токена типа остаются взаимозаменяемыми, кроме указанного существующего отношения между именованными сигнатурами и `call`.

Построение адаптера должно сохранять политику исходного объявления и позиционную проекцию. Подготовленный вызов представляет фактическое присутствие и отложенные места. Порождаемый CODE не должен нетерпеливо читать каждое `p0…pn` до входа в свой движок. Пропущенные исходные входы сохраняют свои вычисляемые значения по умолчанию и контекст; захваченные префиксы доступны значениям по умолчанию, которые от них зависят. Служебные поля остаются приватными. Вызов оболочки добавляет задокументированную границу вызова; обещания скрытого алиаса через каждый промежуточный кадр нет.

Попадания `once` не принуждают к вычислению неиспользуемых пропущенных значений по умолчанию. Пассивные события трассировки могут описывать состояния «присутствует/отложено», не вычисляя их. `guard/contract` читают лишь те места, которые нужны их предикату или телу. Мемоизация документирует, какие принятые значения наблюдает её ключ, различает пропуск и ноль/nil и не кэширует отказов. `uncurry` смотрит фактически достигнутую ступень и выполняет ровно то число вызовов, которое задано плоским контрактом, не выдумывая промежуточных сигнатур `Ti -> @` и не вызывая вызываемый итоговый результат.

Реализация LMX держит алгоритмы адаптеров на LMX и изолирует доступ к существующим фазам подготовки вызова ядра. Эти мосты не создают постоянного окружения, новой VM или автоматической native-компиляции. См. [реализацию адаптеров](patterns/LMX_Fn_Receivers/GENERIC_IMPLEMENTATION.md), [границы ядра](patterns/LMX_Fn_Receivers/KERNEL_REQUIREMENTS.md) и [приёмку](patterns/LMX_Fn_Receivers/tests/ACCEPTANCE.md).

<a id="acceptance"></a>
## 6. Приёмка и публикация

Сценарии базовых типов, сценарии последовательностей, исходные сценарии шаблонов и требования адаптеров A01–A20/B01–B11 остаются обязательствами приёмки для интерпретатора, native и обоих переходов. Добавленные случаи покрывают различные результаты `replaceRange` и `splice` и оба граничных предиката, включая альтернативы, перекрытие, пустые границы, фактические профили элементов и алиасинг. Их необходимо запускать на настоящем ядре. Этот архив отдельно фиксирует покрытие исходников, нерешённые обязанности интеграции и воспроизводимые подсчёты символов. Ни ссылка в документации, ни совпавший токен исходника не являются прохождением во время выполнения.

Примеры сохраняют действительно разные алгоритмы из загруженного архива; мелкие однострочные варианты становятся примечаниями. Миграции синтаксиса применяются и к сохранённым алгоритмам. Более короткий кандидат допустим, только если он сохраняет весь сценарий, поля, эффекты, поведение при отказах и сопоставимую границу библиотеки. Использование в LMX вызывает прямые функции ядра из [общего перечня](CORE_FUNCTIONS.md); использование в контрольном языке вызывает действительные библиотеки или встроенные средства, а не наши реализации для сравнения. Сравнения реализаций сохраняют полные заявленные контракты на обеих сторонах и считают общие зависимости отдельно. Длина кода не является измерением производительности.

Строгий трёхаргументный профиль интервала остаётся строгим. Новая перегрузка `slice(source; spec)` и суффикс используют [нормализованные знаковые границы среза](TERNARY_AND_SLICES.ru.md#slice-contract) и тот же обход выборки. Отрицательные границы среза не являются отрицательными одиночными индексами Array.
