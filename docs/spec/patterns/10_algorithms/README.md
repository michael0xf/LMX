## Как устроены полные листинги

`examples/lmx/common` содержит по одному телу каждого общего шага и подготовки данных. Процедурные drivers лежат в `examples/lmx/procedural`, функциональные — непосредственно в `examples/lmx`. Общий AlgorithmArray выделяет память и заполняет её явной ядровой операцией fill; нули после resize не предполагаются.

У BFS, Kahn, union-find и Dijkstra общий runner принимает выбранный driver. Этот параметр является частью fixture выбора стиля, а не дополнительным условием задачи. Общие скаляры и ссылки рабочего состояния передаются помощникам через существующее динамическое связывание. Их не нужно дублировать в каждом DATA-контракте; private на них не ставится. Все callbacks выполняются синхронно в пределах достигнутого вызова.

Процедурная форма показывает явные while и ветвления. Функциональная максимально использует уже существующие map/foldl/collect/range в главных проходах; локальные таблицы и очередь остаются изменяемыми. Слово «функциональный» здесь не обещает persistent-представление или чистоту всего графа состояний. У lowerBound функциональная форма рекурсивна; у edit distance внешний и внутренний проходы выражены foldl.

Каноническое процедурное тело lowerBound размещено в общем ядре; в сравнении показано и учитывается всё тело. Fixture-alias не подменяет стоимость реализации. fill обобщён на существующие профили Array и произвольную одну готовую запись значения. Новый код не объявляет скрытых heap, deque, сортировщиков или equality-операций.

## Общая подготовка массива

[Канонический исходник AlgorithmArray](examples/lmx/common/array.lm3) показан один раз для BFS, Kahn, union–find и Dijkstra. Полное тело включено в измеряемую границу каждого из двух стилей соответствующего сценария ровно один раз; при сборке общего приложения исходник подключается один раз.

```lmx
AlgorithmArray:
    int: arrayType
    int: size
    @: value
    return: @
    make:
        throws: copy(FxSeqAllocate\make\throws) copy(FxArrayFill\fill\throws)
        @: out FxSeqAllocate\make(arrayType; size)
        return: FxArrayFill\fill(out; value)
```

Параметр `arrayType` задаёт существующий тип массива, `size` — его размер, а `value` — одну готовую запись начального значения для общего `fill`. Выделение не предполагает начальных нулей: каждый достигнутый элемент заполняется явно. Ошибки берутся из действительных контрактов выделения и заполнения.

## Область договоров

Графовые вершины индексные, поэтому их int — часть предметного представления, а не ограничение элементов generic search или токенов edit distance. LowerBound принимает независимые типы элемента и ключа через less; edit distance принимает произвольные токены через same. Dijkstra использует точные неотрицательные веса и явно описанную общую машинную область контрольного C++-примера; LMX хранит расстояния в []bigint.

Input validation не добавляется только одной стороне: допустимые индексы, размеры, формы пар и числовые границы являются предусловиями всех реализаций. Входные массивы не меняются, рабочие массивы создаются внутри. У topological sort цикл — нормальное отсутствие результата, причём пустая успешная сортировка от него отличается.

Все scenario-вызовы выполняются после обычного запуска корня как L3 Thread. Main, именованный runner или DATA-загрузка не становятся новой точкой запуска.

## Проверка и публикация

[Фиксированные случаи](tests/cases.json) полностью перенесены в страницы. [Runner](tests/run_foreign.py) дополнительно порождает по 120 входов на алгоритм с seed 20261125; проверяет реальные Python/C++/Java/JavaScript-реализации, generic comparator, порядок callback, отсутствие мутаций Python-входа и независимые свойства графов.

Выполнено **1492 проверки результатов** иностранных программ на **26 фиксированных и 720 генерируемых входах**, плюс отдельные callback/generic probes. [Фактический отчёт](tests/validation.json) — источник этих чисел. Java компилируется через присутствующий модуль `java -m jdk.compiler/com.sun.tools.javac.Main`; наличие исполняемого файла по имени go не считается наличием Go compiler.

P0 и L3 LMX **NOT_RUN**: соответствующего исполнителя нет. Чтение исходников и совпадение foreign результатов не заменяют запуск LMX.



## Воспроизведение

```sh
python3 tests/run_foreign.py
```

Команда запускается из этой директории; временные foreign drivers удаляются после проверки. Сравниваемые исходники не содержат тестовой сериализации. Все языковые реализации показаны на страницах целиком; существующие стандартные runtime/контейнеры не разворачиваются заново.
