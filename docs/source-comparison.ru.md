Прежнее имя слияния для копирования из одного источника — историческое. Нынешний `copy` принимает один допущенный
источник, `merge` — не менее двух; оба поставляют потоки полей. `import`, `copy` и `merge` всегда потребляют обычные
аргументы CODE, в том числе когда их результат принимается в DATA. Голые ссылки и анонимные Structure остаются
значениями; явные вызовы источников исполняются при потреблении. Все эти и прочие действующие контракты определяются
[семантикой](LMX_semantics.ru.md) и [грамматикой](LMX_grammar.ru.md), а не старым
сравнением.

P0 сохраняет единственную анонимную Structure, в том числе пустую. `f()`, f: и явно пустое вертикальное тело имеют
пустое тело Frame; f: () — это `f(())` с одним пустым полем Structure. Пустая физическая строка вне экранированного
содержимого завершает весь текущий блок до корня документа, не создавая поля и не создавая return. Эти правила заменяют
любое историческое раскрытие P0 и аннотацию пустой строки только на уровне 0. См.
[пустые тела](LMX_grammar.ru.md#empty-colon) и [уровни исходника](LMX_grammar.ru.md#levels).

Операнд раскрывает группу только при одновременном выполнении трёх условий: `left` — написанная безымянная
Structure, `length(right) = 1`, а `right[0]` — написанная безымянная Structure. Снимается только одна внешняя
группа справа, один раз при применении этого операнда; её непосредственные поля становятся `right`. LEFT
остаётся той же целой Structure и лишь задаёт условие. Вложенные группы повторно не раскрываются, а Structure,
возвращённая функцией, автоматически не раскрывается. P0 это преобразование никогда не выполняет. Выбор W/E
обычного вызываемого — отдельное правило, а не дополнительный проход раскрытия операнда. В именованном
объявлении, например `Name :: (A B)`, слева стоит имя, поэтому единственная Structure справа остаётся целой;
`Name :: A B`, напротив, имеет два правых аргумента.

Все ресиверы остаются в исходном графе так, как записаны; терминальные примитивные объявления представлены
непосредственно как `{type value}` по адресам, которые держат ячейки Structure. Эти листья входят в полный буквальный
исходный граф. Семантика также фиксирует, что [uninit](LMX_semantics.ru.md#uninit-zero-payload) — один код типа с нулевой нагрузкой значения, и обычную замену фрагмента графа, в том числе
исполняемых структур-ресиверов ([присваивание в граф](LMX_semantics.ru.md#graph-fragment-assignment)); существующая граница compile/endturn обслуживает обязательные машинные обновления.
Вычисления и преобразования принадлежат namespace. Исторические выдержки и примеры не разрешают перезапись графа,
исполняемые формы fn/sub, реестр операндов sys или слияние со значением-контейнером.

## Дополнительные формы ресиверов

| Форма или понятие | Роль |
| --- | --- |
| `satisfies` | Текущее написание обычного направленного допуска; правила Consumer и позиционного сопоставления сигнатур не меняются |
| `Name :: DATA` | Существующее описание именованной сигнатуры; её отношение к call не меняется |
| Операнд `signatureTypes` с токенами типов | Тот же вид сигнатуры через стандартный контракт операнда; в остальных применениях взаимозаменяем |
| `import: fun`, затем `curry`, `partial`, `map` и др. | Обычные прямые имена ресиверов, ссылающиеся на своих настоящих владельцев |
| Structure как вектор аргументов или результатов | Существующее хранение Array<@> без оболочки items |
| `(value record)` | Ссылка на подготовленную типизированную запись значения с обычными правилами срока жизни |
| Maybe / Result / Bounce | Обычные библиотечные Structure над ссылками на записи и явными тегами |

Контракты, ссылки на реализацию и условия приёмки — в [полной главе о
ресиверах](LMX_semantics.ru.md#functional-receivers) и в [интеграции в
ядро](kernel-implementation.ru.md#receiver-kernel-integration).
