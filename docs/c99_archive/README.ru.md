# C99 — архив человеческих программных возможностей

Коллекция встраиваемых библиотек сохраняет алгоритмы, форматы, кодеки,
протоколы и операции с устройствами для длительной автономной работы.
Глобальная сеть может отсутствовать, а локальная сеть продолжать работать.
Предполагаются скромные вычислительные ресурсы и возможность разобраться
в исходниках без внешней команды сопровождения.

**Основная опись функций и LMX-структур теперь находится в
[docs/core_catalog](../core_catalog/README.ru.md).** Эта директория — обзор:
какие задачи закрывает коллекция, какие внешние данные она понимает и как
найти точную запись о сборке. Полные списки C API здесь не дублируются.

## Что входит в обновление

Сохранена принятая исходная коллекция; добавлены gb, восемь C99 компонентов
cute_headers, выбранные алгоритмы Embedded Artistry libc, APR/APR-Util,
SDL3 и восемь NetSurf библиотек. Научный слой включает HDF5 2.3.0 с полным
C HL, netCDF-C 4.10.1, PnetCDF 1.15.1 и libxml2 2.15.4 как зависимость DAP4.
matio 1.6.0 получает MAT7.3 через HDF5. C99Containers найден как исторический
вариант уже имеющегося STC; отдельный старый fork не добавлен.

Состав фиксируется в [SOURCES.json](../../third_party/lmx_c99_compact/SOURCES.json).
Публичные API, типы данных, c.* вызовы, L3 контракты и условия доступности —
в [каталоге ядра](../core_catalog/README.ru.md). Наличие API в описи отдельно
отмечается от наличия реализации в выбранном C-профиле и от внедрения в ядро.

Текущий этап сохраняет полноту принятой коллекции для последующего анализа
профилей. Для многофункциональных наборов и согласованных научных библиотек
порог одного мегабайта снят. Это не отменяет очистку исходников: сохраняются
сборочные inputs, полезные платформенные ветви, лицензии, короткая документация
и код тестов/примеров; downloaded archives, repository history и build outputs
в рабочую коллекцию не входят. Альтернативные реализации полезны и не удаляются только
из-за совпадения назначения.

## Файлы и применение патча

Эта документация относится к дереву LMX. Поставляемый архив является патчем
к загруженному снимку: содержит новые и изменённые файлы с их относительными
путями. Его накладывают на исходное дерево, а не используют как отдельный
полный source distribution. Работающее ядро не объявляется автоматически
обновлённым до всех возможностей каталога: LMX-структуры и adapters служат
конкретным руководством переноса с приоритетом спецификации.

## Размер и ресурсы

Размер исходников, размер статических `.a`, размер финального executable и
пик RAM — разные измерения. Общие зависимости учитываются отдельно;
в частности, PnetCDF и параллельные HDF5/netCDF используют MPI runtime
подготовленной платформы. Возможность собрать библиотеку не устанавливает
стоимость её работы на любом устройстве.

Код и DATA с `independent: immutable:` общие: акторы получают ссылки,
копий этих объектов в их аренах нет. Изменяемые нативные contexts, запросы,
буферы, handles и callbacks имеют своих владельцев и отдельный расход памяти.
Полная опись библиотек сама по себе не превращается в allocation каждого актора.

## Граница назначения

LMX остаётся языком и моделью собственных данных. JSON/XML/INI нужны для
реальных внешних файлов и сервисов. SQL, регулярные выражения и SLJIT являются
специализированными механизмами. Lua, Perl и другие общие языковые runtime
не добавляются как способ программировать систему поверх LMX. llhttp даёт
механизм разбора HTTP; готовый сервисный lifecycle не подменяет архитектуру.

HDF5, CDF-1/2/5, netCDF-4, MAT4/5/7.3 — полезные внешние представления
массивов и научных данных. Они теперь включены в принятый состав с явно
указанными backend profiles. Прежнее исключение HDF5/netCDF по размеру
пересмотрено текущим поручением и не действует как правило этого снимка.

## Проверка

Полная композиция **180 компонентов собрана; 138/138 CTest PASS**.
[Итоговый отчёт](VERIFICATION_2026-11-26.json) фиксирует общий запуск,
[индекс проверок](VERIFICATION.json) — групповые доказательства и ограничения.
Отдельный [аудит символов](SYMBOL_AUDIT_2026-11-26.json) проверил 195
production static archives: 42 500 сильных глобальных имён, коллизий нет.
Число tests не равно числу проверенных API и не означает полный upstream
conformance corpus. Multi-rank MPI и физическое оборудование отмечаются
отдельно от single-rank/loopback/dummy-device сценариев.

Новые библиотеки сохраняют permissive licenses и notices всех использованных
частей. Корневая лицензия интеграции не заменяет vendor licenses. Две
унаследованные записи Mint/afan с `NOASSERTION` сохраняют эту отметку;
отсутствие лицензии не переименовано в MIT или public domain.
