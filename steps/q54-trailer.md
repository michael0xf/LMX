# Q54: `until` и объявление без замыкателя (OPUS-Q54-TRAILER-20260929-13)

Тикет Codex от ответа автора на Q54 (2026-09-29), с двумя дополнениями того же дня. Код — только Opus.

## 1. Правила, по которым сделан срез

Ответ автора на Q54 (передан Codex):
- анонимное тело, закрытое `until`, — обычный встроенный цикл с постусловием в активации объемлющего метода, как
  любое управляющее тело;
- именованный `readLoop:` с `until:` — обычная именованная Structure, в чьём исполняемом теле лежит этот цикл;
  объявление её не исполняет, исполняет только явный вызов (голое `readLoop`, вызов, путь);
- `if`/`while`/`for` не меняются; `node` — лексическое пространство над выбранным методом;
- никакой конструкции не нужен явный замыкатель: замыкатель (`end: Name`, голый `return`, `until:`) — граница P0,
  а не условие объявления;
- возврат не нужен ни `sub`, ни именованной Structure: конец тела завершает вызываемое без результата; узел
  возврата не синтезируется; голый `return` — необязательный ранний выход.

Книга, §13 «Ветвления и циклы»: «Закрывающий `until` задаёт проверку после тела». Разрешение головы — книга, §9
«Построение значений» (`docs/LMX_semantics.ru.md` :559–:565): найденное callable вызывается; найденная
non-callable привязка получает присваивание; при отсутствующей цели и значении-Structure объявляется структурная
переменная; литерал (`arg: 7`) не объявляет.

## 2. Замер на `b7b0868`

P0 (дерево printTree):
- `readLoop:` + тело + `until: c` — Frame `readLoop` с хвостом `Tail cutter trailer spelling="until"`;
- `---` + тело + `until: c` — анонимная Structure с тем же хвостом; в методе так же;
- `Counter:` + блок без замыкателя — Frame `Counter`, тело — его элементы.

Хвосты есть все; транслятор их не потребляет.

Пробы (тело считает в `node\hits`, метод читает обратно):
- `Counter:` с `end: Counter` — 0 после объявления, 1 после вызова: верно;
- `sub` без `return` и без замыкателя — 0, затем 2: верно уже сейчас;
- `Counter:` без замыкателя — отказ: в корне «unknown field path root», в методе «a call path must end at a
  callable field». `l2_unit_role` знает только формы с `end:` и с голым `return`;
- `readLoop:` + `until:` — отказ «unsupported trailer»;
- **тихий дефект**: `---` + тело + `until: x >= 3` исполнялся один раз и терял `until` (x 1, не 3) — в корне и
  в методе, натив и обход. Блок строился как `if: 1` / IF(LIT 1), хвост его Structure не читал никто;
- именованная Structure в теле метода отказана даже с `end:` («unsupported trailer») — прежний пробел (семейство
  строки GATE «Оператор во вложенной … именованной Structure»), вне этого среза.

## 3. Ступень 1: анонимный блок с `until`

- Помощник `l2_block_until`: условие хвоста `until:` анонимного блока, иначе 0.
- Скан читает имена условия в области блока после тела; проверка проверяет условие в области блока и допускает
  `break`/`continue` в теле.
- Натив: `while: keep` с флагом первого оборота. Условие стоит в начале каждого оборота, кроме первого, поэтому тело
  исполняется хотя бы раз, а `continue` приходит к условию; тело — под `if: keep`.
- Обход: узел ядра UNTIL (op 41) `[until, cond, body]` — сначала тело, затем условие, конец — когда оно
  выполнено; `continue` идёт к условию, `break` заканчивает цикл успехом.

Свидетели (строки харнесса), в каждом четыре цикла: счёт до 3; тело исполнено один раз, хотя условие уже верно;
`continue` приходит к условию (z 2, c 0; пропуск условия дал бы z 4, c 1); `break`:
- `unit_until_block_method` — натив;
- `unit_walk_until_block_method` — обход, пин «метод не нативный»;
- `unit_walk_until_block_root` — корень.

Прежний транслятор отказывал всем трём у `continue` («unsupported loop»: блок не был циклом), а без `continue` —
исполнял блок один раз.

Корпус `b7b0868` → ступень 1: 1119 файлов, 2238 трансляций, 2232 тождественны, L1 не изменился ни у одной;
исход изменился только у трёх новых свидетелей (отказ → трансляция). `until` в существующих программах не
встречался.

Мутанты (в каждом цикле свидетеля стоит страж: счётчик больше 50 прерывает цикл, так что сломанный цикл
кончается, а не зависает), все красные поведением:
- KU1 — UNTIL кончается, когда условие НЕ выполнено: 68;
- KU2 — `continue` минует условие: 67 (z 4, c 1);
- KU3 — `break` не кончает цикл: 68 (b 10);
- TU1 — натив без первого оборота, условие до тела: 66 (once 0);
- TU2 — натив кончает цикл при невыполненном условии: 68.

## 4. Ступень 2: объявление без замыкателя; именованная Structure с `until`

- Роль элемента корня (`l2_unit_role`) — общим разрешением (книга §9, :559–:565), не замыкателем. Именованную
  Structure объявляет голова, не разрешённая ни во что (`l2_head_absent`), с хвостом-Structure
  (`l2_tail_is_structure`), чем бы её ни закрыли: `end: Name`, голый `return`, `until:`, отступ — граница P0.
  Возврат не нужен. Прежний признак — `l2_end_text` / `l2_ns_ret_closed` с эвристикой первого поля — снят.
  - Голова не разрешена, если она не метод, не поле корня, не дверь C или объявленная функция, не примитивное слово
    типа, не ресивер языка (`l2_receiver_word`) и не имя именованной Structure, объявленной **более ранним**
    элементом корня. Прежнее объявление — привязка: `S()` после `S:` — присваивание с допуском (:561), а второе
    `Model:` + поля — тоже присваивание, отказанное как присваивание.
  - Хвост — одно значение, если он атом, прогон операторов или вызов: первый элемент называет вызываемое
    (`add5: makeAdder 5`, `R: merge: A B` с телом). Пустой хвост — пустая Structure. Всё прочее — Structure.
  - Ответ читается из порядка исходника, не из регистрации. Проход подсчёта (до регистрации именованных Structure) и
    проход заполнения (после) обязаны дать одну роль; первая версия спрашивала регистрацию — транслятор упал
    (0xC0000374) на `unit_empty_assign_*`: подсчёт счёл `S()` объявлением, заполнение — оператором.
- `l2_unit_declares` читает имя `@: Type name` вторым (L2: `Type` и `var` — отдельные поля хвоста); прежде он
  считал объявленным сам тип, и `@: Model slot` делал `Model` привязкой.
- Именованная Structure, закрытая `until`: тело её процедуры — один анонимный блок над её элементами с тем же
  хвостом `until` (`l2_ns_loop_body`), то есть общий цикл ступени 1; её поля остаются её полями. Объявление её не
  исполняет; `l2_take_named` принимает `until` как замыкатель.

Свидетели (строки харнесса; тело считает в `node\hits`, метод читает обратно):
- `unit_ns_noclose_root`, `unit_ns_noclose_method` и `unit_walk_ns_noclose_method` — Counter без замыкателя, первый
  элемент исполняемый: 0 после объявления, 1 после вызова (прежде отказ «unknown field path root»);
- `unit_sub_noreturn` и `unit_walk_sub_noreturn` — `sub` без `return`: 0, затем 2 (работал и прежде —
  положительный свидетель);
- `unit_ns_until_root`, `unit_ns_until_method` и `unit_walk_ns_until_method` — readLoop, закрытый `until`: 0, затем
  3 (прежде отказ «unsupported trailer»);
- `unit_decl_literal_refused` — `x: 7` при отсутствующем `x`: «unresolved name» (литерал не объявляет, :565).

Корпус `9dfd2b0` → ступень 2. Первая версия изменила исход 74 программ: хвост-вызов в двоеточии считался
Structure; `l2_prim_type_word` отвечал и за зарегистрированную Structure; `l2_unit_declares` читал `@: T name`
первым. Итог: 1119 файлов, 2238 трансляций, 2232 тождественны. L1 изменился у 2 программ, исход у них тот же:
- `mystruct: ()` в `unit_call_args_refuse_struct` и первое `E()` в `unit_empty_assign_untyped` — теперь путь
  именованной Structure, единственный путь пустой Structure по книге.

Исход изменился у одной строки — `unit_duplicate_named_struct_refused`, поимённо: второе `Model:` — присваивание
существующей привязке, «assignment target must be a declared typed mutable value» (было «duplicate named Structure»
— форма «определения», закрытого `end:`).

Первый гейт харнесса (`s7b34`) был красным на одном пине: `unit_empty_assign_untyped` — «the generated L1 still
names lmx_walk_admit»; пины проверяются до запуска, программа не исполнялась. Первое `E()` теперь объявляет
именованную Structure E общим путём — один путь с `E: ()` и `end: E` (:563), её тип — пустая Structure. Поэтому
следующие `E()` и `E: ()` — присваивание с допуском к собственному типу E (:561), и () его проходит. Пин прежнего
пути -132 (поле без имени модели, запись без `lmx_walk_admit`, `2c2041e9`) переожидан поимённо: строка требует
`lmx_walk_admit`. `m()` над нетипизированным письмом по-прежнему пишет без допуска; выход 4, как прежде.

Мутанты (копии транслятора), все красные поведением:
- C2M1 — общий путь объявления выключен: все шесть свидетелей Counter и readLoop отказаны («unknown field path
  root», «unsupported trailer»);
- C2M2 — литерал считается Structure: `x: 7` объявляет, `unit_decl_literal_refused` принят (exit 0);
- C2M3 — ресиверы языка не исключены: корневое `sendMessage: exit(...)` объявляет Structure — «unknown method»
  (frame=exit_code) в `unit_ns_noclose_root` и `unit_sub_noreturn`;
- C2M4 — `until` именованной Structure не зацикливает: тело исполняется один раз, 64 вместо 7 у всех трёх
  `unit_*ns_until_*`;
- C2M5 — более раннее объявление не привязка: `S()` после `S:` объявляет снова — «duplicate named Structure» у
  `unit_empty_assign_named` и `unit_duplicate_named_struct_refused`.

Не сделано: именованная Structure в теле метода (отказ, как прежде); в методе пустая Structure `f()` идёт путём -132
(поле), в корне — путём именованной Structure.
