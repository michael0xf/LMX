<a id="implements-and-test-phases"></a>
## Фазы implements и test

Сообщение автора целиком, полученное после замечания исполнителя об отложенных вопросах допуска:

```text
для динамического кандидата test это второй шаг, implements выполняется один раз для каждого кандидата, а при построении графа test выполнять смысла нет -- там только первая чатсь implements
```

Нормативное изложение — [семантика, §7](../docs/LMX_semantics.ru.md#admission).
При построении графа выполняется только интерфейсная часть; `test` там не исполняется.
Для динамического кандидата `test` — второй шаг. `implements` выполняется один раз для каждого кандидата.
Это уточнение нормы, не свидетельство готовности её реализации.

<a id="runtime-candidate-admission"></a>
## Фактический приём кандидата во время исполнения

Исполнитель противопоставил первый фактический приём известного при построении кандидата и динамический
выбор кандидата как два возможных режима `test`. Ответ автора целиком:

```text
а чем отличается первый фактический прием во время исполнения от "динамической выборки" ?
```

Вывод исполнителя из ответа и общего правила допуска: для второго шага такого разделения нет.
Знание кандидата при построении позволяет выполнить интерфейсную часть заранее, но не заменяет `test`
при фактическом допуске во время исполнения. Это не повод повторно выполнять уже завершённую первую часть.

<a id="data-root-receiver-execution"></a>
## Прямой проход по data и исполнение переданного ресиверу кода

Ответ автора на вопрос о том, где может исполниться `test`, целиком:

```text
проход по data замечает только объявления корневого уровня и только ресиверы объявления на корневом уровне выполняются, то есть факт выполнения ресивера уже открывает ворота выполнению кода который передается в ресивер. Обрати внимание что это все общее поведение а не просто я "так решил". Ты понял "где" может исполнится "test" а где они никак не может исполнится? Мы не запускаем _прямо_ из data ничего кроме корневых ресиверов объявления
```

Это общее поведение ресиверов, не исключение для `test`. Прямое чтение записей данных и исполнение кода,
переданного исполняемому ресиверу, — разные действия. Сама запись кода среди данных не запускает его.

<a id="test-first-failure"></a>
## Первый неуспешный test прекращает допуск

На вопрос «Если у Consumer несколько test и первая проверка вернула 0, сразу прекращаем допуск или
выполняем оставшиеся проверки?» автор ответил дословно:

```text
сразу прекращаем
```

При первом результате `0` допуск прекращается, оставшиеся проверки не исполняются. Успешный допуск
требует успеха всех заданных проверок; это не требование продолжать список после отказа.
