## 3. Разрешение объявления, присваивания и вызова

### Общая последовательность

- [ ] Сначала построить одинаковую Structure/Frame независимо от формы записи.
- [ ] Разрешить голову и применить единый приоритет: существующее callable-поле → вызов; существующая non-callable привязка → присваивание; объявление → только конструкцией, явно задающей тип. Неизвестная голова без применимой типизированной объявляющей конструкции — ошибка; вывода типа новой переменной из RHS нет.
- [ ] Затем по уже выбранной роли выполнить одну физическую операцию: callable invocation, assignment/rebind либо declaration/construction.
- [ ] Интерпретаторы должны получать уже различённые операции (`CALL`, `SET`/`ASSIGN`, `PUT`), а не повторно угадывать их по исходной пунктуации.

### Объявление

- [ ] Если имя цели отсутствует, а справа синтаксически находится Structure, создать структурную переменную: тип явно задан самой Structure согласно принятому структурному правилу.
- [ ] Произвольный RHS не выводит тип. `ping: 7` при отсутствующем `ping` — ошибка; примитив объявляется только с явным типом (`int: ping 7`).
- [ ] Для непримитивного нового значения полностью выделить требуемую память/графовую структуру согласно его конструктору; неизвестный тип — ошибка.
- [ ] Для пустой Structure одинаково обработать `mystruct: ()`, пустой вертикальный вариант и вариант с `end: mystruct`.
- [ ] Не требовать `KnownModel`, зарезервированное имя или отдельную ветку для пустой Structure.
- [ ] Удалить обратное правило `Model: fresh` → `fresh: merge(Model)` как универсальную реализацию нового объявления; пересмотреть тесты, которые сейчас закрепляют эту ориентацию.

### Присваивание

- [ ] Если существует non-callable binding, выполнить обычное присваивание с полным admission/`implements` до записи.
- [ ] Считать `ping: 7` присваиванием только когда типизированный non-callable `ping` уже объявлен; «тип ранее фигурировал» означает существующую привязку, а не повторное объявление.
- [ ] Присваивание известного значения всегда семантически выполняет `implements`, даже при кешированных проверенных адресах и оптимизированных C-local slots.
- [ ] При неуспешном admission не менять цель и её `dirty`.
- [ ] Примитивы записывать как значения; Structure/Array и другие non-callable ссылочные значения — как ссылки согласно их контракту, без неявного `merge`, копии или переподчинения.
- [ ] Закончить terminal Structure-reference assignment для прямых имён и путей.
- [ ] Унифицировать direct own/local/formal, explicit graph path и unit-level stores через одну семантическую admission boundary, сохраняя допустимые backend-оптимизации после проверки.

### Вызов

- [ ] Если разрешённая голова является callable-полем, всегда выбирать вызов с высшим приоритетом — независимо от `COMPACT`, colon или блочной формы.
- [ ] Если сигнатура или admission такого вызова не принимают аргументы, выдавать ошибку вызова без fallback к assignment/declaration.
- [x] Сохранить `l2_is_asgn`-исключение для известного метода/имени и auto-invoke пути с terminal callable: после решения автора это правильные следствия call-first, а не дефекты. Отдельно исправляется unsupported terminal Structure assignment-path.
- [ ] Голый callable в statement position вызывает нульарную операцию.
- [ ] Не поддерживать прямое присваивание callable-полю. Его замена допускается только общими механизмами: `merge` структур с `implements`, динамической перегрузкой одноимённым callable вызывающего либо явной передачей callable в дескрипторе аргументов вызывающего.
- [ ] Проверять полную сигнатуру, dynamic inputs, admission и checkpoints одинаково для native lowering и интерпретатора.

### Решённый дискриминатор

- [x] Для `f: g`, `f(g)` и вертикального эквивалента существующий callable `f` всегда вызывается; любой failure остаётся ошибкой вызова, assignment-fallback запрещён. Если существующий `f` non-callable, выполняется присваивание. Если `f` отсутствует, сама эта запись ничего не объявляет; требуется отдельная конструкция с явно заданным типом либо структурное правило, где тип задан Structure справа.
- [x] Правило «три формы равноценны» действует *везде в языке*, следовательно включает L1 projection. Текущие ветвления L1 по `LM_P0_FRAME_COLON` для assignment/type routing подлежат аудиту и устранению; stable/self-build corpus входит в будущую отдельную write-партию после аварийного checkpoint.
