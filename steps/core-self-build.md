# Линия DeepSeek: перенос текущей работы и самосборка ядра

Поручение автора от 2026-09-20: DeepSeek переносит в LMX все текущие дела и весь код myxa_manager **как есть**, затем занимается самосборкой ядра. Последнее уточнение оставляет эту линию DeepSeek и возвращает Codex к контролю L3; Grok продолжает интерпретатор. Рабочая запись, не изменение семантики языка.

## Состояние и владельцы

- DeepSeek восстановил seed и сообщил PASS цепочки L1. Codex независимо повторил её: 8/8 файлов в неподвижной точке, 9 секунд. После публикации `2d24852` DeepSeek также сообщил PASS L1 из чистого клона без готового EXE; этот второй прогон Codex самостоятельно не повторял. **Полная локальная цепочка L2/manager пока не доказана**.
- DeepSeek сообщил о переносе `L1/dev/mixa_sandbox` → `LMX/dev/mixa_sandbox`: 963 файла, 22,1 МБ, без старого build, exe и логов; ключевые файлы проверены им поимённо. Codex не выполнял полного побайтового аудита этих 963 файлов. В Git `2d24852` находятся seed, pin и runner; это не публикация всего manager.
- DeepSeek и его текущая команда ведут перенос и исправление цепочки самосборки. Codex не копирует поверх их файлов и не запускает конкурирующую переработку ядра.
- Grok продолжает L3 в dev; в `GROK-CODEX-PING-N48-20260920` сообщил, что адаптер заголовков mixa оставляет DeepSeek. Не перекладывать исходники Grok ради старого сборщика. Самосборка не должна ждать полной реализации L3.
- Grok Bot после безопасного завершения уже запущенного этапа не начинает новые VM-прогоны или массовый перенос языка. Его независимый участок — аудит воспроизводимости цепочки в `steps/bootstrap-audit.md`, без изменений исходников DeepSeek/Grok.
- Codex возвращается к приёмке L3 и ведёт общий план, не дублируя реализацию самосборки. Процессные поручения не добавляются в LMX_blog.

## 1. Перенос как есть

Зафиксировать исходный каталог/revision и полный перечень переносимых единиц, включая необходимые скрипты, тесты, данные и незакоммиченные исходные изменения. Сопоставить пути и хэши перенесённых исходников; отдельно перечислить осознанно не переносимые локальные артефакты. Не совмещать перенос с рефакторингом, переименованием языка или удалением исходного проекта.

Рабочий снимок и публикация — разные действия. Локальные сборки, журналы, PID/LOCK-файлы, кеши, секреты и пользовательские данные не становятся материалом публичного Git только потому, что попали в переносимый каталог. Перед коммитом проверить точные пути; промежуточный seed учитывать явно, а не автоматически коммитить весь `bin/`.

## 2. Зафиксировать, что именно самособирается

DeepSeek должен назвать конкретные единицы ядра и транслятора, начальный seed и команду, на которой цепочка сейчас обрывается. Различать:

1. Сборку старым внешним `l1trans.exe` — это seed-сборка, сама по себе не самосборка.
2. Воспроизводимую сборку ядра из зафиксированных исходников LMX.
3. Самосборку инструмента: полученный из исходников инструмент способен снова построить соответствующий инструмент и ядро из тех же исходников.

Предлагаемый критерий замыкания: явно объявленный seed → stage 1 из исходников LMX → stage 2, построенный инструментами stage 1 → сборка ядра и его проверок новым инструментом. Точный состав стадий и цели подтверждает DeepSeek по реальной архитектуре; не вводить фиктивный «самокомпилятор», если конкретная единица им не является. Внешний C-компилятор и прочие разрешённые зависимости фиксируются отдельно и не скрываются.

## 3. Доказательства приёмки

- Один воспроизводимый запуск из LMX с явными входами/выходами в новом каталоге сборки, без подхвата прошлых артефактов по неявным абсолютным путям.
- Манифест версий и хэшей исходников, seed, промежуточных и итоговых инструментов; фактические команды и коды завершения каждой стадии. Временные результаты — вне отслеживаемых исходников.
- Stage 2 действительно запускается, а не только существует на диске; им выполняется следующая требуемая сборка и проверочный корпус. Прежние тесты сохраняются, отрицательные случаи не переписываются ради успеха.
- Сравнение выходов последовательных стадий: побайтовое для детерминированных артефактов; для недетерминированных бинарных метаданных — явно описанное сравнение содержимого и поведения. Простое совпадение ненулевого размера файлов не является проверкой.
- Все остаточные зависимости от соседнего `L1` и других старых проектов перечислены. Объявленный seed допустимо учитывать отдельно; неявная подмена нового инструмента старым или использование старого готового C делает результат незамкнутым.
- Повторный запуск с нуля в другом новом каталоге даёт тот же проверяемый результат. Не удалять существующие чужие build-каталоги для имитации чистой сборки.

До этих проверок писать точный статус: «перенесено», «seed-сборка», «stage 1», «stage 2», «тесты», «цепочка замкнута». Успех нативных P0 13/13 и 131/131, L3 smoke или одного self-test ядра не доказывает самосборку.

## 4. Независимый аудит Grok Bot

Код задания `LMX-BOOTSTRAP-PRIORITY-20260920-01`. Прочитать фактические скрипты и отчёт DeepSeek; составить таблицу «вход → какой инструмент запущен → выход → следующий потребитель», проверить абсолютные пути/старые бинарники/старый C/неучтённые библиотеки, указать первое доказанное препятствие или недостающее свидетельство. Не запускать одновременно тяжёлую сборку в каталогах DeepSeek и не редактировать его код. Собственный файл `steps/bootstrap-audit.md` проверять и коммитить отдельно; сообщать содержательный результат, не только транспортный ACK.

## Проверка Codex после checkpoint DeepSeek

Срез HEAD `dc608683`, новые файлы DeepSeek в рабочем дереве. После чтения `tools/run_self_build.ps1` выполнен независимый запуск из LMX: `& .\tools\run_self_build.ps1`. Evidence: `build/self_build/20260920_063856_071`. Прошли сборки B0/B1/B2 и три прохода; pass 3 = pass 2 для 8/8 файлов, exit 0, 9 секунд. Предыдущий прогон DeepSeek: `build/self_build/20260920_063614_081`, 8 секунд.

Фактическая цепочка: GCC компилирует локальный C-seed в B0; B0 переводит восемь единиц из `l1src` в pass 1; GCC собирает B1 из pass 1; B1 даёт pass 2; GCC собирает B2 из pass 2; B2 даёт pass 3. Старый внешний `bin/l1trans.exe` в **этом runner** не вызывается. EXE не сравниваются из-за недетерминированных бинарных метаданных; байтово сравниваются результаты pass 2/pass 3. Локальный `bin/l1trans.exe` отдельно соответствует SHA-256 из `L1_PIN.txt`.

### Препятствие публикации: обнаружено и снято в 2d24852

При первоначальной проверке `git ls-files -- lm1/build tools/run_self_build.ps1 L1_PIN.txt` не вернул файлов; `git check-ignore` указывал на `build/`. После ответа DeepSeek проверен коммит `2d24852`: восемь C/h-файлов, pin, runner и исключение `.gitignore` опубликованы. Повторный `git ls-files` показывает все десять путей seed/pin/runner. Поручение автора включить сгенерированный seed в Git выполнено этой партией; повторное добавление Codex не требуется.

В `2d24852` `Get-SelfBuildBlob` сравнивал файлы **рабочего дерева**; DeepSeek исправил PASS/FAIL на «working-tree seed C» и добавил пояснение. Следующий коммит `1c25a78` исправил верхний комментарий/путь запуска и добавил отдельное сравнение `HEAD:<path>` с неподвижной точкой; Codex проверил diff, новый прогон пока не повторял. Исключение `!lm1/build/**` открывает весь seed-подкаталог, поэтому будущие коммиты всё равно должны добавлять точные восемь файлов, не весь build.

Получен содержательный ответ `LMX-L1FIXPOINT-AUDIT-20260920-01`: DeepSeek подтвердил дефекты аудита, commit/push `2d24852` и запуск из нового локального клона (1857 файлов, нет `bin/l1trans.exe`), PASS 8/8 за 9 с, evidence в его `lmx_clone/build/self_build/20260920_064407_564`. Codex проверил состав коммита, но не выдаёт чужой прогон за собственный. Pin готового EXE не совпадёт с произвольной локальной пересборкой: политика доставки/проверки инструмента для manager требует отдельного решения владельца; C-bootstrap от этого готового EXE не зависит.

### Следующий функциональный блокер: L2-ядро в LMX

Локальная сборка L2 остаётся незавершённой. В первоначально исследованном `dev/mixa_sandbox/tools/build_mixa.ps1` общий `$depsRoot` переключал и kernel, и seed на старый `C:/Nyasha_Planet/L1`. DeepSeek сообщил об исправлении: независимые `$kernelRoot`/`$lm1Root` и печать путей/хэша транслятора; по его симуляции seed теперь локальный, но kernel headers ещё старые. Это отдельное изменение manager, не состав коммита C-seed. Grok оставил адаптацию сборщика DeepSeek; исходники песочницы сохраняют свою раскладку.

Критерий завершения этой части — не только отсутствие строки NOTE. Gate должен сообщить фактические пути/хэши локальных L2-заголовков, объектов и транслятора и пройти проверки без обращения к старому дереву L1. Потребитель сейчас ищет `dev/l2src_sandbox/build/l2src/<stamp>/headers/l2src`; способ генерации этих файлов согласует владелец Grok с DeepSeek. Граф и расположение исходников не менять лишь для удовлетворения старого сборщика.

Checkpoint `766c40e` снял этот блокер для локального gate ядра: в LMX перенесены шесть kernel-side единиц `dev/l2src_sandbox/l1src`, а `tools/build_l2src.ps1` собирает staging только из LMX. Codex независимо выполнил `powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_l2src.ps1 -Run`: `GREEN: 200 targets, no failures`, exit 0, evidence `build/l2src/20260920_073313`. В выводе указаны локальные staged sources, локальный `bin/l1trans.exe` с проверенным `L1_PIN.txt` и локальные generated headers; путь `C:\Nyasha_Planet\L1` не потреблялся. Это подтверждает L2 kernel gate на текущем Windows host, но не объявляет завершёнными весь manager, clean-checkout bootstrap и POSIX-переносимость.

## Перенос bootstrap на новую платформу: передано DeepSeek

Codex прочитал оба исходных файла `C:\Nyasha_Planet\lingvamyxa_old_worked_version\buildCore.lm0.bat` и `.sh`, не запускал и не изменял старый проект. Они собирают из готового C библиотеки parser/own и инструменты trans/make/finalize/buildCore; сами **не выполняют** цикл проверки неподвижной точки.

Для LMX переносится принцип: корень относительно скрипта, выбираемые инструменты `LM_CC/LM_AR/LM_RANLIB/LM_CMAKE`, C99, include-пути и платформенный провайдер потоков. В старых скриптах default — single; auto выбирает win32 или pthread по платформе; shell-вариант также задаёт `_POSIX_C_SOURCE=200809L`. Старый `trans.lm1.c` нельзя механически подставить вместо текущего объединённого `l1trans.lm1.c` и повторно прилинковать уже включённые parser/own.

На новом host его C-компилятор строит B0 из **текущего отслеживаемого** C-seed LMX, без запуска Windows EXE на иной платформе. Далее — проходы B0/pass1/B1/pass2/B2/pass3 и сравнение восьми файлов, отдельно с HEAD. Портируемые entrypoints должны соответствовать нынешнему составу исходников и проходить чистый checkout; наличие исторических `.bat/.sh` не означает, что современный LMX уже проверен на POSIX. Продолжение этой реализации и локальная L2/manager-цепочка — участок DeepSeek.

Checkpoint `1c25a78` добавил `tools/bootstrap_l1.sh` и опубликовал дерево manager. Это пока только B0 текущего L1, не переносимый полный цикл самосборки и не готовый L2/manager. DeepSeek сообщил smoke на этом host: `build/self_build/bootstrap_20260920_064733/l1trans.exe`, usage exit 1; повторный цикл с HEAD-сравнением — `build/self_build/20260920_064647_830`, 8/8 за 8 с. Независимые новые прогоны Codex не выполнены. Следующий checkpoint владельца — `.bat` и clean-checkout bootstrap; POSIX-проверка полного цикла ещё не заявлена.

При публикации manager в `1c25a78` видны остатки прогонов `.txt/.pid`; владелец затем сообщил очистку 22 файлов в `89aa6a2` и узкие ignore-правила. Коммит очистки подтверждён локальной историей. Codex не удалял файлы и не переписывал историю; ранее опубликованное остаётся в истории Git.

По заданиям аудита и последующего инвентаря Bot возвращает коррелированные транспортные ACK, но содержательного отчёта пока нет; начало/завершение работы ими не подтверждается. Последнее уточнение очереди и ID доставки — в [плане L3](l3-receiver.md).
