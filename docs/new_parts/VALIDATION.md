# Проверка редакции 22 ноября 2026 года

Отчёт относится к текущим исходникам, метрикам и документам. [Прежний отчёт](VALIDATION_2026-11-21.md) сохранён отдельно: его сведения о выполнении контрольных программ не объявляются новым запуском. [Обзор изменений](CORE_RECEIVERS_REVIEW.md) содержит принятые правила и решения по сравнению.

## Комплектность

Сохранены **90 паттернов + 9 реализаций = 99 расширенных сравнений / 297 основных листингов**, отдельно — **23 GoF-сравнения / 184 листинга** и **24 корневых LMX-примера**. Альтернативы, исторические исходники и реализации зависимостей не удалены ради уменьшения метрики.

Все 606 файлов переданного `docs.tar.gz` сохранены по своим путям. Изменения разрешены текущим заданием; размеры и хеши находятся в [сверке исходного архива](validation/original_preservation_20261122.json). Новый пакет ресиверов, задачи, отчёты и общие таблицы добавлены к комплекту.

Все 99 записей `comparison_sources/catalog_manifest.json` согласованы с девятью `patterns.json`. Trampoline 083 связан с реализациями 092 и 099; 099 — с обоими клиентами 085 и 083.

## Нормативная сверка

- Публичный `fn` заменён на обычный expression-операнд `Name :: DATA`; именованный DATA перенесён полностью. Конструктор по типам — `signatureTypes`, извлечение сигнатуры — `signature`.
- `::` не открывает особый Frame и не получает цель `end: Name`. Один правый шаблон и несколько правых аргументов различаются. Чтение полей DATA-шаблона не является раскрытием аргументов.
- При трёх совместных условиях снимается только внешний контейнер в `right`; `left` остаётся целым. P0 ничего не снимает, правило не применяется рекурсивно, результат функции автоматически не раскрывается. [Точная норма](../LMX_semantics.en.md#operand-right-only-opening).
- Ресивер LMX `implements` переименован в `satisfies`. Ключевые слова контрольных языков не менялись.
- Все операции входят в одно ядро; клиентские версии библиотек и обязательный `import: fun` не используются.
- `width` присутствует во всех восьми Flyweight. Сохранены значимые поля, copy/identity/effects и динамическая модель LMX; многопоточность остаётся на Message и описанном HTTP-транспорте.

[Аудит раскрытия](validation/operand_right_unwrap_review.json) и [интеграция в ядро](../kernel-implementation.ru.md#receiver-kernel-integration) содержат подробные условия.

## Числа и варианты

GoF: **LMX — 5734**, **Python — 6870** непробельных символов; разница **16,54%**. LMX короче Python в **19 из 23** случаев и минимален среди восьми языков в **17**. Частные таблицы обновлены, включая Composite **296 против 295**.

Выбирается минимум среди корректных вариантов одного договора и сопоставимого уровня подсчёта. Историческая специализация или иной API не подменяет текущую общую задачу. Сохранённый второй вариант не входит в основной размер. Стоимость общих тел ядра показана отдельно и учитывается один раз.

Для четырёх функциональных компонентов полное множество общих определений без повторов — **7010 символов / 405 непустых строк**. Внутренний общий набор экспортов добавляет **1751 символ** один раз при оценке полного набора. Размер листинга не является измерением скорости или памяти.

## Исполнение и оставшаяся интеграция

**Новые LMX-программы, интерпретатор и нативные переходы здесь не запускались.** Проверки относятся к публикации; `runtime_executed: false` сохранено. Новые Haskell/Scala-листинги также не выдаются за исполненные.

Восемь мостов перечислены в [KERNEL_REQUIREMENTS](LMX_Fn_Receivers/KERNEL_REQUIREMENTS.md). В [разделе о поведении адаптеров](../LMX_semantics.ru.md#adapter-behavior) отдельно зафиксированы обязательные задачи: сохранение defaults/autofill и поведения пропущенных actuals в создаваемых адаптерах; допуск промежуточных результатов `uncurry`. Это ограничения текущего проекта адаптеров, а не статическая типизация LMX.

После интеграции нужно выполнить подготовленные сценарии на интерпретаторе, при нативной компиляции и смешанных переходах, включая lifetime, объявленные отказы и связи owner → DATA → CODE. Эти проверки не объявляются завершёнными.
