# Q54: `until` и объявление без замыкателя (OPUS-Q54-TRAILER-20260929-13)

Тикет Codex от ответа автора на Q54 (2026-09-29), с двумя дополнениями того же дня. Код — только Opus.

## 1. Правила, по которым сделан срез

Ответ автора на Q54 (передан Codex):
- анонимное тело, закрытое `until`, — обычный встроенный цикл с постусловием в активации объемлющего метода, как
  любое управляющее тело;
- именованный `readLoop:` с `until:` — обычная именованная Structure, в чьём исполняемом теле лежит этот цикл;
  объявление её не исполняет, исполняет только явный вызов (голое `readLoop`, вызов, путь);
- `if`/`while`/`for` не меняются; `node` — лексическое пространство над выбранным методом;
- никакой конструкции не нужен явный замыкатель: замыкатель (`end: Name`, голый `return`, `until:`) — граница P0,
  а не условие объявления;
- возврат не нужен ни `sub`, ни именованной Structure: конец тела завершает вызываемое без результата; узел
  возврата не синтезируется; голый `return` — необязательный ранний выход.

Книга, §13 «Ветвления и циклы»: «Закрывающий `until` задаёт проверку после тела». Разрешение головы — книга, §9
«Построение значений» (`docs/LMX_semantics.ru.md` :559–:565): найденное callable вызывается; найденная
non-callable привязка получает присваивание; при отсутствующей цели и значении-Structure объявляется структурная
переменная; литерал (`arg: 7`) не объявляет.

## 2. Замер на `b7b0868`

P0 (дерево printTree):
- `readLoop:` + тело + `until: c` — Frame `readLoop` с хвостом `Tail cutter trailer spelling="until"`;
- `---` + тело + `until: c` — анонимная Structure с тем же хвостом; в методе так же;
- `Counter:` + блок без замыкателя — Frame `Counter`, тело — его элементы.

Хвосты есть все; транслятор их не потребляет.

Пробы (тело считает в `node\hits`, метод читает обратно):
- `Counter:` с `end: Counter` — 0 после объявления, 1 после вызова: верно;
- `sub` без `return` и без замыкателя — 0, затем 2: верно уже сейчас;
- `Counter:` без замыкателя — отказ: в корне «unknown field path root», в методе «a call path must end at a
  callable field». `l2_unit_role` знает только формы с `end:` и с голым `return`;
- `readLoop:` + `until:` — отказ «unsupported trailer»;
- **тихий дефект**: `---` + тело + `until: x >= 3` исполнялся один раз и терял `until` (x 1, не 3) — в корне и
  в методе, натив и обход. Блок строился как `if: 1` / IF(LIT 1), хвост его Structure не читал никто;
- именованная Structure в теле метода отказана даже с `end:` («unsupported trailer») — прежний пробел (семейство
  строки GATE «Оператор во вложенной … именованной Structure»), вне этого среза.

## 3. Ступень 1: анонимный блок с `until`

- Помощник `l2_block_until`: условие хвоста `until:` анонимного блока, иначе 0.
- Скан читает имена условия в области блока после тела; проверка проверяет условие в области блока и допускает
  `break`/`continue` в теле.
- Натив: `while: keep` с флагом первого оборота. Условие стоит в начале каждого оборота, кроме первого, поэтому тело
  исполняется хотя бы раз, а `continue` приходит к условию; тело — под `if: keep`.
- Обход: узел ядра UNTIL (op 41) `[until, cond, body]` — сначала тело, затем условие, конец — когда оно
  выполнено; `continue` идёт к условию, `break` заканчивает цикл успехом.

Свидетели (строки харнесса), в каждом четыре цикла: счёт до 3; тело исполнено один раз, хотя условие уже верно;
`continue` приходит к условию (z 2, c 0; пропуск условия дал бы z 4, c 1); `break`:
- `unit_until_block_method` — натив;
- `unit_walk_until_block_method` — обход, пин «метод не нативный»;
- `unit_walk_until_block_root` — корень.

Прежний транслятор отказывал всем трём у `continue` («unsupported loop»: блок не был циклом), а без `continue` —
исполнял блок один раз.

Корпус `b7b0868` → ступень 1: 1119 файлов, 2238 трансляций, 2232 тождественны, L1 не изменился ни у одной;
исход изменился только у трёх новых свидетелей (отказ → трансляция). `until` в существующих программах не
встречался.

Мутанты (в каждом цикле свидетеля стоит страж: счётчик больше 50 прерывает цикл, так что сломанный цикл
кончается, а не зависает), все красные поведением:
- KU1 — UNTIL кончается, когда условие НЕ выполнено: 68;
- KU2 — `continue` минует условие: 67 (z 4, c 1);
- KU3 — `break` не кончает цикл: 68 (b 10);
- TU1 — натив без первого оборота, условие до тела: 66 (once 0);
- TU2 — натив кончает цикл при невыполненном условии: 68.

## 4. Ступень 2: объявление без замыкателя; именованная Structure с `until`

- Роль элемента корня (`l2_unit_role`) — общим разрешением (книга §9, :559–:565), не замыкателем. Именованную
  Structure объявляет голова, не разрешённая ни во что (`l2_head_absent`), с хвостом-Structure
  (`l2_tail_is_structure`), чем бы её ни закрыли: `end: Name`, голый `return`, `until:`, отступ — граница P0.
  Возврат не нужен. Прежний признак — `l2_end_text` / `l2_ns_ret_closed` с эвристикой первого поля — снят.
  - Голова не разрешена, если она не метод, не поле корня, не дверь C или объявленная функция, не примитивное слово
    типа, не ресивер языка (`l2_receiver_word`) и не имя именованной Structure, объявленной **более ранним**
    элементом корня. Прежнее объявление — привязка: `S()` после `S:` — присваивание с допуском (:561), а второе
    `Model:` + поля — тоже присваивание, отказанное как присваивание.
  - Хвост — одно значение, если он атом, прогон операторов или вызов: первый элемент называет вызываемое
    (`add5: makeAdder 5`, `R: merge: A B` с телом). Пустой хвост — пустая Structure. Всё прочее — Structure.
  - Ответ читается из порядка исходника, не из регистрации. Проход подсчёта (до регистрации именованных Structure) и
    проход заполнения (после) обязаны дать одну роль; первая версия спрашивала регистрацию — транслятор упал
    (0xC0000374) на `unit_empty_assign_*`: подсчёт счёл `S()` объявлением, заполнение — оператором.
- `l2_unit_declares` читает имя `@: Type name` вторым (L2: `Type` и `var` — отдельные поля хвоста); прежде он
  считал объявленным сам тип, и `@: Model slot` делал `Model` привязкой.
- Именованная Structure, закрытая `until`: тело её процедуры — один анонимный блок над её элементами с тем же
  хвостом `until` (`l2_ns_loop_body`), то есть общий цикл ступени 1; её поля остаются её полями. Объявление её не
  исполняет; `l2_take_named` принимает `until` как замыкатель.

Свидетели (строки харнесса; тело считает в `node\hits`, метод читает обратно):
- `unit_ns_noclose_root`, `unit_ns_noclose_method` и `unit_walk_ns_noclose_method` — Counter без замыкателя, первый
  элемент исполняемый: 0 после объявления, 1 после вызова (прежде отказ «unknown field path root»);
- `unit_sub_noreturn` и `unit_walk_sub_noreturn` — `sub` без `return`: 0, затем 2 (работал и прежде —
  положительный свидетель);
- `unit_ns_until_root`, `unit_ns_until_method` и `unit_walk_ns_until_method` — readLoop, закрытый `until`: 0, затем
  3 (прежде отказ «unsupported trailer»);
- `unit_decl_literal_refused` — `x: 7` при отсутствующем `x`: «unresolved name» (литерал не объявляет, :565).

Корпус `9dfd2b0` → ступень 2. Первая версия изменила исход 74 программ: хвост-вызов в двоеточии считался
Structure; `l2_prim_type_word` отвечал и за зарегистрированную Structure; `l2_unit_declares` читал `@: T name`
первым. Итог: 1119 файлов, 2238 трансляций, 2232 тождественны. L1 изменился у 2 программ, исход у них тот же:
- `mystruct: ()` в `unit_call_args_refuse_struct` и первое `E()` в `unit_empty_assign_untyped` — теперь путь
  именованной Structure, единственный путь пустой Structure по книге.

Исход изменился у одной строки — `unit_duplicate_named_struct_refused`, поимённо: второе `Model:` — присваивание
существующей привязке, «assignment target must be a declared typed mutable value» (было «duplicate named Structure»

Первый гейт харнесса (`s7b34`) был красным на одном пине: `unit_empty_assign_untyped` — «the generated L1 still

- C2M2 — литерал считается Structure: `x: 7` объявляет, `unit_decl_literal_refused` принят (exit 0);
- C2M3 — ресиверы языка не исключены: корневое `sendMessage: exit(...)` объявляет Structure — «unknown method»

- C2M4 — `until` именованной Structure не зацикливает: тело исполняется один раз, 64 вместо 7 у всех трёх
  `unit_*ns_until_*`;
- C2M5 — более раннее объявление не привязка: `S()` после `S:` объявляет снова — «duplicate named Structure» у
  `unit_empty_assign_named` и `unit_duplicate_named_struct_refused`.

Не сделано: именованная Structure в теле метода (отказ, как прежде); в методе пустая Structure `f()` идёт путём -132
(поле), в корне — путём именованной Structure.

## 5. Ступень 3: документы тикета

Грамматика и книга порождаются: грамматика — из `provenance/grammar.json` (`tools/build_docs.py`), книга — из
`provenance/semantics-book.md` (`tools/build_semantics.py`). Правлены источники, документы перегенерированы.
`provenance/semantics-inventory.json` не входит: генератор из рабочего дерева пишет в него пути дерева, эталон —
пути машины автора.
- Грамматика §17 (RU/EN): анонимное тело, закрытое `until:`, — встроенный цикл с постусловием; именованный Frame,
  закрытый `until:`, — обычная именованная Structure, чьё тело — этот цикл, исполняемый только явным вызовом.
  Замыкатели не обязательны: это границы P0, а не условие объявления. Именованная Structure, закрытая срезом
  уровня, объявляется общим разрешением. Конец тела именованной Structure или `sub` завершает их без результата,
  возврат не синтезируется.
- L2 §21 (RU/EN), управляющие формы: то же о `until:` и замыкателях — отсутствующая голова со значением-Structure
  объявляет именованную Structure, чем бы её ни закрыли; ни ей, ни `sub` не нужен `return`.
- Книга §11 «Вызываемые выражения» и §13 «Ветвления и циклы» (RU/EN) — те же правила; таблица переходов §13 уже
  говорит, что `continue` в `until` проверяет постусловие.

## 6. Тикет OPUS-Q54-CONTINUE-20260929-14, срез 1: `f()` одинаково всюду

Тикет Codex (автор: не останавливаться, убрать оставшееся расхождение общего правила). Одна и та же пустая голова
`f()` разрешается одинаково в корне и в методе: отсутствующая f объявляет, существующая не-callable привязка получает
присваивание с допуском, интерфейс вызова вызывается — не по форме и не по месту.

Замер (транслятор `3d0038a`, только трансляция, оба режима):
- D1: в методе `f()` `f()` `f: ()` проходили без допуска. Отсутствующая f объявлялась полем без типа (путь -132, «no
  l2_own_nsty_set»), и следующее `f()` писало без допуска. Те же строки в корне дают два `lmx_walk_admit`: там E —
  именованная Structure.
- D2: `f()` на формале-Structure отказан («unsupported body»), и любое присваивание такому формалу — «const write».
  Это ограничение вида привязки, не места, — вне среза.
- D3: `g()` во вложенном теле корня объявляется, а следующее `g()` отказано («root operation not walkable yet: this
  statement»): обход корня не умеет поле-Structure вложенного тела. Вне среза.

Сделано (натив):
- `l2_own_self_typed`: собственное поле, объявленное `f()` / `f: ()` / закрытой пустой вертикалью, типизировано своим
  объявлением — пустой Structure (книга §9 :561–:563). Признак читается из самого объявления (Frame с именем поля и
  пустым телом), не из состояния разрешения.
- Проверка: следующее `f()` на таком поле — место допуска (`l2_admit_site`), как на поле объявленного типа.
- Натив (`l2_emit_admit_own`): новый пустой узел допускается к Structure на месте поля — к рабочему значению
  (`l2_q<k>`), иначе к слоту. Так `S()` в корне допускается к дочернему единицы (`l2_type_inst`). Отказ — неявный
  `implements`.
- Обход: место допуска ставит метод на канал throw, а обход не берёт метода, который бросает (`l2_rw_may`), — как
  любой допускающий метод. Поэтому под ручкой такой метод натив. В корне `f()` верхнего уровня — именованная
  Structure (ступень 2).

Свидетели (строки харнесса):
- `unit_empty_self_admit_method` и `unit_empty_self_admit_nested` — `f()` + `f()` (+ `f: ()`) в методе и во вложенном
  теле: 7, допуск в L1 (пин: модель — рабочее значение `l2_q3`); допуск к типу S (поле v) дал бы пойманный
  `implements`: 64;
- `unit_walk_empty_self_admit_method` — то же под ручкой: метод натив (пин), 7;
- `unit_empty_admit_typed_method` и `unit_walk_empty_admit_typed_method` — `S: fresh` + `fresh()` в методе: допуск
  отказан и пойман, fresh сохраняет v — 74, как в корне (`unit_empty_assign_named`).

Корпус `3d0038a` → срез 1: 1128 файлов, 2256 трансляций, все тождественны: ни одна программа не переприсваивала в
методе поле, объявленное `f()`.

Мутанты:
- S1M1 — без допуска: исход 7 не меняется (допуск к пустому типу проходит всегда), красен пин — строка требует
  допуск в L1;

Остаётся (срез 2): присваивание Structure с полями и объявление `S:` + поля в методе. Второе `Model:` + `other` в

## 7. Срез 2a: присваивание существующей именованной Structure — по правилу

Замер (`4d8860c`): существующая именованная Structure — не цель присваивания ни для какого значения, кроме пустой
Structure. `Model:` + поля, `Model: (поля)`, `Model: R` (R — результат merge) и `Model: 5` отказаны одинаково:
«assignment target must be a declared typed mutable value». Это утверждение ложно: по правилу существующая
не-callable привязка получает присваивание с допуском (книга §9 :561).

Правило в трансляторе:
- допуск — по имени (Q39, D-105: первый, тяжёлый `implements` — по имени). Позиционный `lmx_runtime_implements`
  («the legacy positional RuntimeImplements walk is not that operation», `l2_colon_check_assignment`) не годится:
  `{other}` прошёл бы как `{value}`;
- литерал Structure (`l2_lit_admits`): у каждого поля Model — ровно одно поле того же имени и вида (size_t, char,
  int, unsigned, ulong); иначе допуск отказывает — «the assigned Structure lacks a field of the named Structure»;
- одно значение (`l2_value_admits`): не Structure — «assignment value has incompatible type»; Structure
  объявленного именованного типа — по той же таблице D-105 (`l2_d105_table`);
- допущенная Structure ещё не перепривязывается — «a Structure assigned to a named Structure is not rebound
  yet». Причина: чтения полей Model (`Model\value` в обходе корня — `OF` без типа, прямой слот) должны идти через
  соответствие допущенного значения (D-105), а у именованной Structure они так не идут. Это названный пробел, а не
  утверждение, что Model — не привязка.

Одно правило в корне и в методе (проверка общая). Свидетели (отказ транслятора, оба режима):
- `unit_duplicate_named_struct_refused` (переожидан по правилу), `unit_assign_named_lacks_method` — нет поля value:
  отказ допуска;
- `unit_assign_named_kind_refused` — поле value, но int: отказ допуска;
- `unit_assign_named_number_refused` — число: значение другого типа;
- `unit_assign_named_not_rebound` — `{value 5U}`: допущено, пробел назван.

Корпус `4d8860c` → срез 2a: 1133 файла, 2266 трансляций, 2264 тождественны; исход изменился только у
`unit_duplicate_named_struct_refused`.

Мутанты:
- A1 — допуск без имени: два отказа допуска стали «not rebound yet»;
- A2 — без вида: `int value` прошёл;
- A3 — ветка правила выключена: все пять — прежнее «assignment target must be…»;
- A4 — число не отказано: «not rebound yet».

Вопрос автору (не решён правилами). `Model: X` при существующем X: книга §9 делает `Model: fresh` объявлением

типизированное объявление. Транслятор читает `Model: X` как объявление X типа Model всегда

раннему `X:` + поля: оно перестаёт быть объявлением и отказано («assignment value has unknown type» в строке `X:`).

Ответ автора (docs `55c1abc`, `5b2979d`; дословно — `LMX_blog/2026-09-29.md`): вопрос A/B снят. Для `a: b` при
отсутствующем b и модели a — `merge(a, empty)` строит b; при обоих известных примитив или явная ссылка получают
присваивание с допуском, а callable, в том числе обычная именованная Structure, вызывается с b как аргументом.
`Model: Other` — вызов. Срез 2a (`9bd346a`) прочёл существующую именованную Structure как цель присваивания — это
расходится с ответом; перечень расхождений — §8.

## 8. Срез 2b-1: собственная именованная Structure метода

Срез касается только отсутствующего имени: `S:` + поля в теле метода, где S не разрешается ни во что. Это объявление
(книга §9: отсутствующая цель со значением — явной Structure).

Сделано (натив):
- Признак `l2_local_ns_shape`. Голова — идентификатор, не разрешённый в методе: не формал и не динамический вход, не
  поле метода (кроме объявляемого этим оператором), не слот, не результат merge, не метод, не функция C, не
  примитивное слово типа, не ресивер языка, не именованная Structure и не поле единицы. Хвост начинается с
  объявления числового или char-поля с именем и инициализатором (`l2_tail_decl_first`). Не объявление другой формы
  (`l2_is_char_decl`, `fn:`…).
- Корпус опроверг два первых признака:
  - «хвост — Structure» (`l2_tail_is_structure`): в методе известны части программы, и голова `size_t:` читалась
    как вызов преобразования;
  - «голова не разрешена»: привязки, которые регистрируются после предпрохода, принимались за отсутствующие —
    локал с типом C `L2TestAllocFn: f av\alloc` и присваивание `count_address: @: count` (16 L1 и 1 исход).
- Тип — запись таблицы именованных Structure, локальная для метода (`l2_ns_local`), только метаданные трансляции:
  поля, их виды и слоты. Это не дочерний единицы, и по имени запись не находится: четыре поиска по имени и циклы
  сборки единицы её пропускают.
- Регистрация — в предпроходе (`l2_collect_asgn_body`), как у `Model: fresh`: до чтения имён метода
  (`l2_dyn_local`). Иначе позднее `S\v` делает S динамическим входом.
- Во время исполнения есть только объявленная в исходнике Structure. Оператор строит её (`l2_emit_local_ns`): это
  дочерняя Structure метода (`self`) с ячейкой-литералом на каждое числовое поле, связанная в слоте S. Каждое
  исполнение строит новую.
- `S\v` — путь через слот.
- `S()` — нульарный вызов S (книга §9 после `55c1abc`). Исполнение собственной Structure метода не построено, поэтому
  отказ на месте. Оператор в теле и поле другого вида (не число) — тоже отказ на месте.
- Обход метод с такой Structure не берёт: под ручкой он натив.

Свидетели:
- `unit_local_ns_method` — S с полями v, w и `S\w: S\v + 3U`: 7. Пины: построение `lmx_struct_new_owned(self, …)`;
  дочернего единицы нет (`l2_nsp[0]: lmx_struct_new_owned` отсутствует);
- `unit_walk_local_ns_method` — то же под ручкой: натив (пин), 7;
- `unit_local_ns_nested` — объявление в теле `if:`: 7;
- `unit_local_ns_fresh` — два вызова: первый пишет v 9, второй видит новую S (v 4): 94. Одна сохранённая S дала бы
  99;
- отказы: `unit_local_ns_call_refused` (`S()`), `unit_local_ns_stmt_refused` (оператор в теле),
  `unit_local_ns_kind_refused` (поле-массив).

Корпус `55c1abc` (транслятор `9bd346a`) → срез 2b-1: 1137 файлов, 2274 трансляции, все тождественны.

Мутанты (копии транслятора), все красные:
- B1 — без регистрации в предпроходе: «unknown method» у всех трёх положительных;
- B2 — поля получают 0 вместо литерала: 0, 0 и 90;

## 9. Тикет 15: правило вызова в корне, в срезе 1 и в срезе 2a

Решение Codex по правилу автора (`55c1abc`, `5b2979d`): переменная m, объявленная `Model: m`, — именованная
Structure, и она callable. Объявление (merge) тела не исполняет; позднее `m` или `m()` — нульарный вызов. Особого
не-callable класса нет: ни по происхождению, ни по пустоте, ни по месту (корень или метод), ни по синтаксису
объявления. Когда Model и m существуют оба, `Model: m` — вызов Model с m, а не присваивание Model и не допуск к Model.
Отказ — временный статус реализации, не правило языка и не запасной путь.

Сделано:
- `f()` на существующей привязке Structure (`l2_empty_struct_assign_shape` = 1 или 2) — нульарный вызов f, тот же,
  что голый атом f. Это один Frame P0 с `f: ()` (`l2_empty_call_shape`). Одна проверка (`l2_check_struct_call`), одна
  эмиссия (`l2_emit_struct_call`), один шаг обхода (`l2_rw_struct_call`). Присваивания пустой Structure с допуском
  больше нет: ветки допуска в проверке и эмиссии удалены, `l2_rw_empty_assign` удалён.
- Что исполняет вызов, решает тип привязки:
  - собственное имя именованной Structure единицы — её процедура: на корне обходом, в методе единицы нативно или
    обходом под ручкой;
  - поле корня, объявленное `Model: v`, — тело Model над v (обходом);
  - поле, тип которого пустая Structure, ничего не исполняет, шага нет (`l2_struct_call_inert`). Это поле,
    объявленное `f()`, или поле пустой именованной Structure: в теле её объявления нет полей и операторов, и её не
    замыкает `until` (`l2_ns_empty`). Голый f — так же; раньше это был отказ;
  - остальное не построено — отказ на месте словами голого атома («executing a named Structure is not supported
    yet»): поле метода типа именованной Structure с телом, собственная Structure метода, письмо без объявленного
    типа, формал.
- Скан исполнения (`l2_ns_exec_scan`, `l2_ns_exec_mark`) отмечает `S()` так же, как голый S.
- `T: value`, где T — существующая именованная Structure, — вызов T с аргументом: Structure полей (в методе и на
  корне), число, другая именованная Structure, имя, связанное раньше. Не построен: отказ «a call of a named Structure
  with an argument is not built yet». `l2_lit_admits` и `l2_value_admits` удалены.
- «Связано раньше» (`l2_colon_bound_before`) учитывает поле, объявленное раньше в том же теле через merge
  (`Model: m`), письмо (`receiveMessage: m`) или пустую Structure (`m()`). Предпроход и скан свободных имён такое имя
  не объявляют. Поэтому второе `Model: m` — вызов Model с m. Раньше в методе это было повторное объявление m, а на
  корне после `int: m` — «incompatible entry signature».
- `f()`, объявляющее f в методе, регистрирует f в скане свободных имён (`l2_scan_body`), где известны машинные локалы
  метода (`l2_ml_rebuild`). Поздний голый `f` поэтому не делает f динамическим входом; раньше объявление отказывалось
  («unsupported body»). Первая версия регистрировала в предпроходе, и корпус её опроверг: предпроход читает таблицу
  машинных локалов чужого метода, и `L2TestTickFn: f av\tick` + `f()` получали лишнее поле (2 фикстуры, только L1).

Строки (переименованы, чтобы имя говорило правду о поведении):
- `unit_empty_assign_untyped` → `unit_empty_call_root`: первое E() объявляет E, следующие E() и E: () её вызывают.
  Пин — кадры EXEC; допуска и узла EMPTY нет: 7. Часть с письмом `m()` → `unit_letter_call_refused`: отказ на месте;
- `unit_empty_assign_named` → `unit_named_struct_call`: Counter() и Counter: () исполняют тело Counter с корня и из
  bump. Counter\n — 1 после каждого вызова, хотя перед ним записано 5: 7. Близнец обхода
  `unit_walk_named_struct_call`: оба метода обходятся (пин);
- `unit_empty_assign_admit` → `unit_model_var_call`: `Model: m`, затем m() и m: () исполняют тело Model над m. m\v —
  1 после объявления, 2 после каждого вызова; Model\v остаётся 1: 7;
- `unit_empty_self_admit_method`, `unit_walk_empty_self_admit_method`, `unit_empty_self_admit_nested` →
  `unit_empty_call_method`, `unit_walk_empty_call_method`, `unit_empty_call_nested`: f(), f: () и голый f на поле,
  объявленном f(), ничего не исполняют. Допуска нет (пин), метод под ручкой обходится (пин): 7;
- `unit_empty_admit_typed_method` → `unit_model_var_call_method_refused`: `S: fresh` + `fresh()` в методе — отказ на
  месте (было 74). Близнец обхода `unit_walk_empty_admit_typed_method` удалён: отказ одинаков в обоих режимах;
- новые `unit_empty_type_call_method` (поле пустой именованной Structure: ничего не исполняется, 7) и
  `unit_until_type_call_method_refused` (пустая, но замкнутая `until`: вызов исполняет цикл — отказ);
- срез 2a: `unit_assign_named_lacks_method` → `unit_ns_call_arg_method_refused`, `unit_assign_named_not_rebound` →
  `unit_ns_call_arg_lit_refused`, `unit_assign_named_number_refused` → `unit_ns_call_arg_number_refused`.
  `unit_assign_named_kind_refused` удалена: это тот же случай, что `_lit`. Новые `unit_ns_call_arg_name_refused`
  (пример автора `Model: Other`, в методе), `unit_ns_call_arg_bound_refused` (второе `Model: m` в методе),
  `unit_ns_call_arg_bound_root_refused` (`int: m 5` + `Model: m` на корне). `unit_duplicate_named_struct_refused` и

Корпус: `1c48f55` (транслятор b16) → этот срез: 1149 файлов, 2298 трансляций; 2260 тождественны, 8 расходятся только L1 и 30 исходом — все в 19 строках этого среза (новых, переименованных или переожиданных); вне среза расхождений нет.

## 10. Срез 2c-1: исполнение собственной именованной Structure метода

Правило (книга §12; §9 после `55c1abc`): `S` и `S()` — вызов S; именованная Structure — процедура без аргументов, и её
исполнение — её тело над ней самой. Для собственной Structure метода это то же, что для Structure единицы.

Сделано:
- Метод, который исполняет свою S (голый `S` или `S()` в его теле, `l2_body_calls_name`), получает процедуру S
  (`l2_local_ns_proc` → `l2_ns_proc_add`, как у Structure единицы). Это метод, чьё тело — тело S, а собственные поля —
  поля S в её слотах.
- Процедура регистрируется в предпроходе вместе с записями метода — после входа E. У метода после E нет дочернего
  единицы (`l2_occ_n`), и он не нужен: вхождение процедуры — сама S, построенная при её операторе.
- Регистрация идёт вне области, в которой стоит S: стек областей метода откладывается и восстанавливается. Поля
  процедуры — поля S, а не тела, где S объявлена; иначе процедура называла контейнер тела `if:`, которого у неё нет.
- Таблица, которую единица отвела до предпрохода (`l2_m_value_used`), растёт вместе с методами.
- Построение (`l2_emit_local_ns`): S — вхождение процедуры (R9). Ширина — `l2_ns_width` (поля, затем тела управления
  и шаги), слово native — трамплин процедуры.
- Сборка единицы не строит процедуре частей (`l2_emit_parts`), обход её не берёт (`l2_rw_may`): она всегда нативна.
- Вызов (`l2_check_struct_call`, `l2_emit_local_exec`): `lmx_call_prim(S, S)` над Structure на месте S (рабочее
  значение или слот). Владелец = данные = S, поэтому `node` в теле S — родитель S, вхождение метода (книга §2: `node`
  — пространство над методом).
- Тело S пока — только объявления полей: каждый вызов сохраняет инициализаторы заново. Оператор в теле по-прежнему
  отказ; это срез 2c-2.

Строки:
- `unit_local_ns_call_refused` → `unit_local_ns_call`: `S()`, `S: ()` и голый `S`. S\v записывается 9 перед каждым
  вызовом и после каждого равно 4: 7. Пины: слово native на S и вызов `lmx_call_prim` над рабочим значением S;
- `unit_walk_local_ns_call` — то же под ручкой: метод натив (пин), процедура не обходится: 7;
- `unit_local_ns_call_nested` — S объявлена в теле `if:` и вызвана там и из анонимного блока: 7.

Корпус: `ea5b24a` (транслятор b21) → этот срез: 1151 файл, 2302 трансляции; 2296 тождественны, L1 не изменился
нигде; исход изменился у 6 трансляций — трёх строк этого среза, которые b21 отказывал.

Мутанты (копии транслятора на итоговых байтах):
- D1 — нет процедуры: вызов снова отказ («executing a named Structure is not supported yet») у всех трёх строк;
- D2 — S без слова native: вызов уходит в крюк обхода, S не сбрасывается — 0 вместо 7;
- D3 — вызов ничего не эмитирует: 0 вместо 7 у всех трёх строк;
- D4 — сборка единицы строит процедуре части у несуществующего дочернего единицы: сборщик программы R0 падает;
- D5 — обход берёт процедуру: под ручкой сборщик программы R0 падает;
- D6 — процедура регистрируется внутри области, где стоит S: процедура называет `l2_h0`, которого у неё нет (ошибка
  компиляции);
- D7 — S строится шириной «число полей», а не шириной вхождения: эквивалентен сейчас (три строки зелёные). Ширины
  расходятся, только когда в теле S есть тела управления или шаги, а это становится возможным со срезом 2c-2/2c-3;
  формула — та же, что у Structure единицы (R9).

## 11. Срез 2c-2: операторы собственной именованной Structure метода

## 13. Срез 2c-4: `node` в собственной именованной Structure метода

Правило (книга §2): `node` — пространство над процедурой, её лексический родитель; у каждой вложенной Structure
родитель — непосредственно объемлющая Structure. Явный путь `node\x` адресует граф, а не рабочую копию (§12). Передача
управления другому вызываемому — граница публикации: помеченные рабочие поля публикуются до вызова (§12).

Сделано:
- `l2_node_seg`: у процедуры собственной S хозяин — метод, где S объявлена. `node\name` — поле тела метода на его
  слоте, как у вложенного метода — поле хозяина; для S, объявленной в теле, — поле, объявленное в этом теле (на его
  слоте в теле). Формал метода — никогда: это часть args, которую `node` не называет.

  рабочая копия ещё не опубликована.

## 17. Класс A в условии метода

Найдено в §16: в условии метода класс A не отказывался — `if: k = j`, `if: k + j = 7U`, `while: j < k` при int `k` и
size_t `j` транслировались, и сравнивал компилятор C; обход на корне те же условия отказывает. Нативная проверка вида
(`l2_check_value_kinds`) типизирует каждую операцию метода, но смешение (-3) пропускала: класс A отказывался только у
потребителя значения (возврат, присваивание, объявление, преобразование), а условие — не потребитель.

Сделано:
- `l2_check_value_kinds` отказывает смешение у первого операнда операции, как отказывает потребитель значения:
  «mixed numeric types (a conversion)».
- Операция, читающая свободное имя, которому замыкание ещё не дало тип, ждёт его (вид ожидания 3, `l2_wait_kinds`),
  как ждут две проверки значения (`steps/free-names.md` M2). Без ожидания `while: j < k` со свободным `k` проходило бы
  и после отказа смешения: при проверке `k` ещё без типа.
- Замер до кода: копия транслятора только с отказом смешения, без ожидания, — корпус `59be148` (1175 файлов, 2350
  трансляций) тождествен весь. Ни одна принимавшаяся программа корпуса не смешивает типы в условии, ни один прежний
  отказ не сменил места или слов.

Строки (у отказов — обходимые двойники `unit_walk_*`):
- `unit_cond_mixed_refused` — `if: k = j` над локальными, 8:9;
- `unit_free_cond_mixed_refused` — `while: j < k`, `k` — свободное имя вызывающего: ждёт, затем отказ, 5:12;
- `unit_cond_same` — условия одного типа: `k = 5 && j = 5U` (каждое сравнение — своё условие, `&&` даёт int; `k`

## 18. Путь к числовому полю в составном значении метода

Найдено после §17: операнд без типа (-99) делает без типа всё составное значение и прячет смешение соседей. Путь к
полю (`P\v`, `node\k`) нативный типизатор составного не типизировал вовсе: `k + j + P\v` и `P\v + k + j` при int `k` и
size_t `j` транслировались. Обход на корне их отказывает у первого `+`, где встретились два типа: путь-операнд он
типизирует по полю (`l2_rw_opty`).

Сделано:
- `l2_native_path_ty`: путь к числовому полю — значение типа этого поля (`l2_path_kind` → `l2_path_kind_ft`, как
  читает путь проверка записи через путь); иной путь по-прежнему без типа (-99). `l2_native_leaf_ty` типизирует им
  атом-путь; примечание о типизаторе («путь отравляет значение») исправлено.
- Следствия одного правила: класс A с путём отказан в значении и в условии (проверка вида из §17 читает тип пути), а
  составное значение с путём берёт ребро преобразования своего типа: `v: P\v + 1U` в int `v` без строки-приёмника —
  «the program has no method `lm_stg_convert_size_t_int`».
- Замер до кода: копия транслятора с этим изменением (её сгенерированный C тождествен итоговому) — корпус `7dd6d03`
  (1180 файлов, 2360 трансляций) тождествен весь. Ни одна принимавшаяся программа корпуса не смешивает путь с другим
  типом и не отдаёт составное с путём месту другого типа.
- Остаётся: операнд без типа иного рода — голый callable-формал или его вызов — по-прежнему прячет смешение соседей;
  обход там разрешающий (неизвестный операнд — любой тип, и два известных типа он видит).
