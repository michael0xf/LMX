# UNIQUE-NAME-REFERENCE-MIGRATION — 2026-10-14

Статус: OPEN. Начальная авторская формулировка сохранена дословно в [LMX_blog/2026-10-14.md](https://github.com/michael0xf/LMX/blob/0a764078/LMX_blog/2026-10-14.md); последующие уточнения автора того же дня ниже её заменяют в вопросах повторного имени, пустого `@` и вызова указателя. Старые тесты и checkpoint-ы — свидетельства прежнего поведения, не действующий контракт.

**Уточнение 2026-10-14 — общий порядок аргументов:** в плоском
объявляющем хвосте L2/L3 имя первым (`@: ptr Model`, `@: p int`), затем
требование и необязательное значение. Плоские `@: Model ptr` и `@: int p`
не отдельная норма; вложенные `@: Model: ptr`, `@: int: p` разбираются как
вложенные применения. После зависимостно замкнутой миграции L2/L3 тем же
порядком обновить генерируемый L1, L1-транслятор, спецификацию и bootstrap
pin/seed вторым этапом; обратный порядок L1 не сохранять как постоянное
исключение. См. [план v3 M3–M4](../../next_core_tasks_v3.md).

**Действующее дополнение 2026-10-15 — две согласованные формы части ресиверов:**
внешняя композиция (`i: int: 5`, `ptr: @: Model: 0`) остаётся; встроенные
ресиверы значения/типа, для которых утверждён соответствующий контракт,
также принимают имя места первым полем: `int: i 5`, `@: ptr 0`,
`@: ptr Model`, `@: ptr Model: 0`. В `@: ptr Model: Other` два поля:
атом `ptr` и вложенный Frame `Model: Other`. Первое поле не вызывается;
второе потребляется как обычное выражение, без записи в `Model` только из-за
вложенности. P0 не вводит особый разбор и не решает роли полей; их задаёт
контракт конкретного ресивера. Это не перенос контракта на `merge` или
`call`. Существующие трёхпольные `@: ptr Model 0` и `@: ptr Model Other`
отслеживаются отдельно в M3; добавление двухпольной формы само по себе их
не отменяет.

**Read-only пограничная проверка L1 (снимок `codex_hidden_entry_full_330`):**
в `build/l2_harness/codex_hidden_entry_full_330/gen` находится 2176 `.lm1`;
поиск однословных операторов `rg -n --glob '*.lm1'
'^\s*[A-Za-z_][A-Za-z0-9_]*\s*(#.*)?$'` дал 13192 строк:
`return` 7574, `break` 5087, `continue` 531, иных — 0. Это собственная
повторная read-only сверка результата независимого обзора, но не новый полный
gate и не доказательство будущего G1/G2. В старом L1-трансляторе
`l1src/l1trans.lm1:3521–3533` голая нульарная голова в позиции оператора
пока вызывает функцию; текущий генерируемый корпус в эту ветвь не попадает.
После миграции M1–M3 повторить счётчик на новом полном gate и проверить
второй этап M4 по отдельному доказательству, не перенося L1-исключение в L3.

## Норма и границы

- Одно пространство имён в непосредственно объемлющей Structure для примитивных полей, обычных Structure, ссылок, методов и `catch`. Первое объявление поля заводит место; повторная объявляющая форма того же поля на этом уровне выбирает существующее место и является **присваиванием**, проходящим обычную проверку совместимости. Это общее правило для полей, в том числе `int: i 5; int: i 6`, `@` и обычной именованной Structure; оно не создаёт второго физического поля. `catch` остаётся точкой управления с отдельным контрактом обработчиков: этот срез не превращает второе одноимённое `catch` в присваивание. Вложенная Structure может затенить имя. Каждый написанный оператор сохраняется отдельно в исходном графе.
- Неизвестная голова `Model` с одиночным атомом в `Model: ptr` — ошибка трансляции, когда разрешение ролей оставляет попытку определить новую Structure из атома, который не даёт ни принимаемого значения, ни описания. Счёт атомов сам по себе не правило. Известный callable или известная Structure в хвосте дают привязку и не отвергаются: `b: tick` связывает `b` с вхождением `tick`, `box: Model` — ссылка (Codex, OPUS-CODEX-20261015-11; `docs/LMX_semantics.ru.md:304,311-319,398,416,422`; `steps/current.md`, граница атомного хвоста). `Model: ()` с новой головой объявляет пустую Structure. Повторная форма `Model: ()` на том же уровне обращается к существующему месту и проверяется как присваивание пустой Structure, а не отбрасывается как дубль.
- Известная обычная Structure `Model` с неизвестным `ptr`: `Model: ptr` = `@: ptr Model` — новое поле-ссылка с адресом именно этого экземпляра. `@: ptr Model 0` даёт null; `@: ptr Model Other` записывает адрес `Other` только после `implements(Model, Other)`.
- При уже существующем `ptr` форма `Model: ptr` выбирает место головы `Model`: это присваивание значения `ptr` в `Model` после проверки совместимости, а не запись в `ptr` и не новое физическое поле (`A: B` означает `A := B`). Обратная запись `ptr: Model` для обычного ссылочного `ptr` адресует `ptr`; для указателя на метод тот же синтаксис является вызовом по его роли. Повторный `@`-ресивер для существующего места выбирает присваивание. Отказ допуска не меняет цель.
- Первое `@: ptr` или `@: ptr 0` объявляет указатель без требования к референту (`void`), во втором случае с нулевым адресом. Позднейшая запись адреса в это место не создаёт задним числом модель и не запускает `implements` для неё. Явное `@: ptr Model 0` сразу объявляет ограничение Model; `@: ptr myFunc` — указатель на метод с его контрактом. Имя метода `myFunc()` вызывает его прямо. Для хранимого указателя на метод `ptr_f()` и `(\ptr_f)()` оба вызывают текущее вхождение; `ptr_f: args` — тот же вызов с аргументами. По общему приоритету `\ptr_f()` разыменовывает **результат вызова** `ptr_f()`, а не служит специальным синтаксисом вызова указателя. Перепривязка указателя записывается повторной формой `@: ptr_f newMethod` (или другим обычным адресным присваиванием), не `ptr_f: newMethod`. `catch` сохраняет свой контракт; иностранный C99 `fnptr:` не переинтерпретировать.
- Удалить *именованные* селекторы `node\[N]field`, `s\[N]name` и корневой `[N]name` из языка и транслятора. Оставить безымянный индексный шаг Array: `arr[i]\[j]\[k]` следует ссылкам на отдельные Array, а `arr[i][j][k]` индексирует один прямоугольный Array.
- Карта `implements` по-прежнему переводит физические позиции требуемых полей в позиции кандидата. Две прежние половины ordinal/LAST после запрета дублей избыточны. Не удалять карту целиком, не возвращаться к предположению одинаковых слотов и не вводить runtime-имена. На переходе допустимо заполнить обе половины одинаково, затем согласованно сократить producer, native, walker, copy и `exec_map` до одной карты.

## Минимальные свидетели

```text
Model: ()
Model: ptr             # новое ptr: адрес Model
@: null_ptr Model 0
Other: ()
@: other_ptr Model Other  # только после допуска
ptr: Other             # попытка записать Other в ptr
Model: ptr             # при известных именах: записать значение ptr в Model
```

Отрицательные: неизвестное `Model: ptr`, когда атом справа не даёт значения или описания (например, неизвестное имя); несовместимое повторное присваивание существующему месту (включая столкновение видов); именованный `node\[0]field`, отказ `implements` для типизированной ссылки и ошибочный фактический аргумент метода. Положительные: `int: x 1; int: x 2`, повторная структурная форма как присваивание, затенение во вложенной Structure, void-указатель из `@: ptr` и `@: ptr 0` с последующей записью адреса без Model-`implements`, сохранение исходного дерева, оба вызова `ptr_f()` / `(\ptr_f)()`, оба вида многомерной индексации и перестановка полей кандидата.

## Текущий срез проверки (2026-10-14)

Следующие датированные результаты измерены **до** последнего уточнения автора о повторном имени и вызове указателя. Они объясняют состояние реализации, но не задают требуемое поведение; зелёный старый gate не подтверждает новую норму. Прежний OPEN для `\ptr()` как вызова указателя отменён: общий оператор `\` и его грамматика здесь не меняются.

- На прежних байтах `ptr()` и `ptr: ()` нормализовались парсером в один Frame и проверялись как присваивание; оба отказа для указателя на метод и разрешённая запись пустой Structure в обычную ссылку прошли тогдашний gate `build/l2_harness/20261014_043734`. Для известного указателя на метод это **отменённый oracle**: Frame с аргументами вызывает его.
- На прежних байтах `ptr: Model` обрабатывалось как присваивание и отказывало для дескриптора Structure (`build/l2_harness/20261014_044802`). По текущему правилу это попытка вызова `ptr` с аргументом `Model`; её допустимость определяется сигнатурой вызова, не приёмом нового адреса указателя.
- `@: Model: p` прежде добавлял второй уровень ссылки к уже ссылочному `Model: p`. Композиция исправлена: прямое и вложенное объявление теперь проходят native/walker внутри обычной Structure и метода (`build/l2_harness/20261014_043714`).
- Прежний положительный свидетель `\ptr()` как *вызова через указатель* был красным (`unknown field path root`, `build/l2_harness/20261014_043907`). Его ожидание отменено; этот gate не доказывает дефект общего префиксного `\`. Вызов через указатель теперь проверяется через `ptr()` и `(\ptr)()` с обычной проверкой сигнатуры, физического текущего вхождения и `interpreter` throw при null.
- `build/l2_harness/20261014_deref_baseline2` и `20261014_rebind_baseline` фиксировали прежнюю ошибочную гипотезу о роли `\ptr()` и `ptr: twice`; их `unknown field path root` и `assignment value has incompatible type` не являются текущими acceptance-oracle. Требуемый вызов — `ptr()` / `(\ptr)()` (и `ptr: args` для аргументов); текущий адрес читается из ячейки перед вызовом, null даёт обычный `interpreter` throw. Не подставлять метод первоначальной инициализации вместо переназначенного. Общий `\` не переделывать в этом тикете; нового полного gate после смены правила ещё нет.
- Текущие точечные проверки после смены правила: `ptr()` без аргументов прошёл native/WalkRoot/WalkMethods (`build/l2_harness/20261014_ptrcall_check6`); первое `@: ptr 0` прошло native/walked (`build/l2_harness/20261014_voidnull_check1`). Это не полный gate. `@: ptr twice` пока получает `duplicate declaration in one Structure` (`build/l2_harness/20261014_ptrcall_check7`), поэтому проверка вызова после перепривязки ждёт общего пути повторного объявления-присваивания. В отдельной пробе `(\ptr)()` пока даёт `unsupported body` (`build/l2_harness/20261014_ptrcall_check4`); тест прямого `ptr()` отделён от этого пробела. Никто не добавлял специального вызова через `\ptr()` и не менял общий оператор `\`.

## Долг M3: устаревшие оракулы K03 «`Model: args` — вызов Model» (Opus, 2026-10-15)

Строки найдены трассировкой трансляции всех 3296 зарегистрированных строк. В
них общая проверка присваивания видела запись в место над активацией. Все 22

`build/l2_harness/opus_m2_20261015_01`, затем

Указание Codex (OPUS-CODEX-20261015-05): ожидания пачкой не переписывать.
