# D-24 — address arithmetic on `@array[i]`

## План

L2 §18.2: `@array[i]` — адрес элемента; дальнейшая адресная арифметика — машинный контракт C. D-22 закрыл дыру «указатель как int» сплошным отказом. Из-за него `q: @ buf[0] + 1` в `@: int` тоже не переводится.

Срез — только эта форма, без полного вывода типа любого составного выражения:

- `@` + элемент примитивного own-массива (`int` / `char` / `size_t` / `ulong`) имеет тип указателя на элемент (коды 11 / 12 / 9 / 38, те же, что у `@: int` и соседей).
- Дальше только `+` или `-` и число: литерал, числовое имя или элемент такого же массива. Тип остаётся указателем. Несколько шагов — тоже (`@ buf[0] + buf[1] + buf[2]` — указатель на int).
- Посадка: присваивание в объявленное имя того же типа указателя, либо `return` метода. Иной тип — «assignment value has incompatible type». Иная форма после элемента — прежний отказ D-22.
- Не этот срез: `p + 1` у уже взятого указателя, массив указателей, аргумент вызова, корень (Q7), D-81, полный `implements`. Ядро не меняется: в методе это C-арифметика указателей, не узел walker.

Свидетель `unit_addr_own_array_arith`: `q: @ buf[0] + 1` пишет 9 в `buf[1]`, `r: @ buf[2] - 1` пишет 8 туда же, Entry 7. Прежняя строка `unit_addr_own_array_arithmetic_refused` остаётся отказом, но уже по типу (return int). Мутант — снять проверку совместимости: эта строка переводится.
