# Находки к следующему патчу документации

Записано 2026-11-23 исполнителем fable_pc по слову автора: «запишите баги какие нашли, я скоро пришлю новый патч
к документации». Это не вопросы, которые останавливают работу: по каждому пункту исполнитель либо уже действует по
выводу из нормы, либо ждёт патча. Пробы сняты на принятом наборе шага 22.4 (Graph `fable-b4-graph02`).

## А. Язык: записи с двумя чтениями и места, где норма молчит

**А1. `@: X` с одним аргументом читается двумя способами, различает их только позиция.**

- В позиции типа (исходники ядра на L2) это тип «ссылка на X»: `(cast: (@: int) x)`, результат функции
  `) @: void`. Таких записей около 13 000, из них 5205 с `@: int`.
- В позиции объявления это нетипизированная ссылка с именем X: `@: plain`, `private: @: value`.
- Разборщик даёт для `@: int` и `@: plain` одно дерево. Проба: строка `@: int` в коде объявляет место с именем
  `int`; после неё `int := shared` и `int\Observed\seen := 5` исполняются, отказа нет. Тот, кто написал
  `@: int` в смысле «указатель на int», молча получает void-указатель по имени `int`.
- Норма: имя стоит первым (`@: p Model`, `@: left int`); тип «ссылка на int» у элемента пишется `@(int)`
  (`[]: @(int) right`). Запись `@: int` как тип есть только в исходниках ядра, в документах её нет. Норма не
  запрещает слово типа именем места и не говорит, чем пишется тип ссылки в приведении и в результате функции.
- Возможные правила: слово типа не может быть именем места; тип ссылки пишется только как `@(T)`.
- Снято пакетом 2026-11-22 (2): тип ссылки пишется постфиксом `T@`, объявление с требованием — `T@: имя`.
  Остаётся одно: `@: int` по-прежнему молча объявляет место с именем `int`.

**А2. Объявление массива.** Порядок «тип, имя» (`[]: char name`, `[]: @ rows`, `[]: @ right`) расходится с
порядком ссылки «имя, тип». Автор решил выровнять на `[]: имя тип значения`
([журнал](../../2026-11-23.md#array-declaration-order)). К патчу:

- в самой норме две формы: глава книги о массивах пишет конструктор `[]: arr (...)`, сигнатуры и примеры —
  `[]: char name`;
- не сказано, как пишутся длина и элементы: в тестах `[]: int cells 2` число — длина; в старом корпусе разбора
  длина стояла перед элементами (`[]: int values 4 10 20 30 40`); в примерах значение — строка, пустая группа,
  имя или вызов (`[]: char digits "0123456789"`, `[]: char out ()`, `[]: char expected sys\name(X)`).
- Решено пакетом 2026-11-22 (2) иначе: тип в голове, элементы квадратной группой — `int[]: values [1 2 3]`.

**А3. У кода корня нет записи, которой он называет сам корень.** Особый смысл `data` снят; `node` начинается в
лексическом пространстве над выбранным методом, а над R0 его нет, так что `node[0]` и `node\x` в коде корня
отказывают (ответ 3). Именованную Structure корня код корня называет по имени, а безымянную ведущую группу и
место корня по индексу — ничем.

- 364 программы проверки переведены на `@: shared node[0]` внутри тел, которые ссылкой пользуются: в методе,
  объявленном в корне, `node` начинается в корне.
- 29 программ под это не подходят: ссылкой пользуется сам код корня (5) либо он пишет `data\x`, `data[touch()]`,
  `data\[1]x` (24). Записи, одинаковой для прежнего и нового ядра, у них нет.
- Вопрос к норме: должен ли код корня уметь назвать корень или его безымянные поля, и если да — чем.

**А4. Вход с собственным значением не видит записи вызывающего; переменная корня поэтому не глобальна.**
Программа:

```lmx
int: seen 0
int: x 5
C:
    node\seen := x
Main:
    x := 9
    C()
```

Файл читается как описание данных, запуск называет тело `Main`. По общему порядку заполнения входа C читает 5:
данные вызова C — его родитель, корень; `x` — вход с собственным значением 5; `x := 9` меняет место кадра
`Main`. Если у `x` нет собственного значения, C получает 9 автозаполнением. Исполнитель закрепляет это строками
среза ядра (решения Р146, Р148); принятое ядро сегодня даёт 9. Если задумано иначе, нужна фраза в норме.

**А5. Имя неявного отказа допуска не названо.** Книга говорит только общее: оператор без написанного `throws`
бросает отказ со своим именем (пример — `merge`). Исполнитель вывел, что отказ допуска носит имя ресивера
проверки соответствия, `satisfies`, и перевёл программы на `catch: satisfies ()` (Р142).

**А6. Слитное `Name::A`.** Грамматика называет `::` обычным токеном оператора и о пробелах молчит. Исполнитель
допускает слитное написание общим правилом двухсимвольных операторов (Р143).

**А7. Из кода корня Structure не объявить; где её объявляет программа из одного файла, сказано не прямо.**

- Запись `Name:` с вертикальным телом в коде корня — вызов головы (заметки о редакции, D2). Проба: `Pair:` с
  телом `int: v 5` отвечает 5 на этой записи, с телом-кодом — 3.
- Ведущая безымянная группа и группа в `@: Name (...)` тоже стоят в роли кода — ваши слова от 2026-11-18
  ([журнал, §30](../../2026-11-18.md#leading-group-is-code)).
- Остаются данные метода (`sub: main (Pair(int: v 5))`, а `sub` снят) и файл, который читается как описание
  данных, а запуск называет тело. Примеры книги и пакета, где `Name:` стоит на верхнем уровне файла, — такие
  файлы.
- На этом за один день трижды ошиблись сами исполнители: программа проверки и пример решения были написаны
  через `Pair:`, `C:` и `@: Pair (...)` в корне.
- Рядом с правилом R0 стоит сказать прямо, чем программа из одного файла объявляет Structure и какой вход
  исполняет файл-описание.
- Принятое ядро ведущую группу и группу в `@:` пока не исполняет. На этой обвязке стоят почти все программы
  проверки; их перевод — отдельный срез.

**А8. Поставленное объявление и объявление формала разных типов.** По книге форма, чьё имя найдено в данных
вызываемого, заменяет это объявление в namespace вызова. Не сказано, судится ли форма контрактом формала и что
происходит, когда типы расходятся.

- Программа: `fn: g (int: a 1; @: b) int` с телом `return: a + b`, вызов `g(int: b 5)`. По букве правила место
  `b` в этом вызове описано формой, тип `int`, результат 6. То же для формала `long: b` или `@: b Any`.
- Три возможных чтения: место получает тип формы без проверки; форма обязана удовлетворять объявлению формала,
  иначе отказ; значение формы приводится к типу формала.
- Сегодня ядро судит такую форму допуском значения у формала: литеральная отвечает так же, как `g(b := 5)`,
  вычисляемая исполняет инициализатор по требованию и получает отказ допуска уже после его эффектов.
- Исполнитель выводит правило заново в проекте библиотеки `satisfies` (шаг 21.8 (а)), решение Р149.

**А9. Массив заданной длины без элементов (пакет 2026-11-22 (2)).** Таблица объявлений пакета даёт место без
значения (`int[]: values`), пустой массив (`int[]: values []`), массив с элементами (`int[]: values [1 2 3]`) и
место от готового значения (`T[]: destination Source`). Записи «массив из N элементов» в ней нет, а длина
названа свойством значения. Тридцать строк проверок прежнего пути пишут `[]: int cells 2`, где число — длина.

- Вопрос к норме: чем объявляется массив длины N с элементами без значения — отдельной записью, операцией
  изменения размера после `int[]: cells []`, или такая форма снята.
- До ответа эти тридцать строк остаются в прежней записи; исходники ядра массивов так не объявляют.

**А10. Объявление-аргумент, которому не осталось позиции.** Раздел книги об объявлениях-аргументах говорит:
форма, чьего имени нет среди входов, целиком занимает текущую позицию. Что происходит, когда позиции кончились,
сам раздел не говорит; ответ стоит в алгоритме выбора объявления по вызову.

- Программа: вход один, `fn: h (@: it Any) int`; вызов `h(int: item 5; int: other 7)`.
- По алгоритму выбора такая форма — обычный позиционный аргумент; лишний аргумент отклоняет кандидата (шаг 3),
  а без единого принятого кандидата вызов отказывает (шаг 5) — до исполнения аргументов.
- Принятое ядро так и делает: одна форма на один вход и две на два принимаются; две на один, три на два, форма
  при вызываемом без входов отказывают, ответ 5; вычисляемый инициализатор лишней формы не исполняется.
- К патчу: одна фраза в разделе об объявлениях-аргументах со ссылкой на шаг 3 алгоритма выбора.

**А11. Три места записи составной головы, где текст нормы краток (пакет 2026-11-22 (2)).** Исполнитель читает
их из правила грамматики «основа и ноль или более суффиксов» (решение Р156) и действует так:

- группа-основа, перенесённая на несколько строк, хранится в голове дословно;
- группа перед двоеточием без суффикса, `(Model): p`, — голова; годится ли она, решает потребитель головы;
- постфиксный `@` — тот, что написан вплотную к концу операнда слева; `T@x` читается как `T@` и `x`.

## В. Код: дефекты ядра, найденные попутно

Это дефекты реализации, не документации; они привязаны к шагам плана.

- **В1.** `return: @` — построение графа отвечает 2: одиночный атом `@` читается префиксным оператором без
  операнда. Шаг 21.7, срез результата.
- **В2.** Допуск: `@: q int n` (типизированная ссылка на int с кандидатом) — ответ 4; вход `u8` или `long` не
  принимает никакого значения; Structure у нетипизированной ссылки отклоняется. Шаг 21.8 (а).
- **В3.** Пустая Model под ссылкой видна как Structure из одного поля (`length(p) = 1`). Проверить при шаге
  21.17.
- **В4.** Вычисляемые объявления корня остаются в выводе графа невычисленными (`grouped_actual_contract`). Шаг
  21.17.
- **В5.** Редкий медленный режим интерпретатора: вставка в упорядоченный индекс диапазонов арены сдвигает хвост,
  цена зависит от раскладки кучи. Это тип по адресу; план, M15 и шаг 21.17.
- **В6.** Автозаполнение из места, объявленного без значения и затем записанного (`int: x`, потом `x := 9`),
  отдаёт входу вызываемого незаписанную ячейку: чтение отвечает 5. С объявлением `int: x 1` значение 9 доходит.
  Шаг 21.7, срез K1b (Р150).
- **В7.** Голый `return` или `break` отдельной строкой тела не прерывает: после `inside := 1`, `return`,
  `inside := 2` значение равно 2. По книге голый `return` завершает исполнение, а пример `iterate` выходит из
  цикла строкой `break`; программы проверки до сих пор писали переходы вызовом (`break()`). Шаг 21.9 (б) (Р151).
