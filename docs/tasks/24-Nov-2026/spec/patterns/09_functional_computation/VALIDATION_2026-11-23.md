# Проверка функциональной группы

Восемь сравнений сохраняются: четыре клиентских сценария082–085 имеют две полные LMX-формы, а091/092/098/099 содержат по одному общему телу ядра. Всего28 сравниваемых листингов, включая контрольные Haskell/Scala с симметричным сокращением локальных переменных в 085.

`tools/check_publication.py` проверяет обе source/JSON/Markdown-копии, полные метрики, отсутствие запрещённых процедурных обходов, постфиксные объявления типов ссылок, точные общие тела ядра и реальные library-клиенты контрольных языков. Для084 проверяются полный локальный Around, один общий Trace в каждом стиле и закрытый набор отказов функционального bracket.

[Машинный отчёт](validation_2026-11-23.json) содержит актуальный результат. [Подготовленные случаи](acceptance_cases.json) описывают33 наблюдения общих реализаций; [стилевые случаи клиентов](style_acceptance_cases.json) применяют одинаковый договор к обеим формам. Они имеют статус NOT_RUN и не выдаются за parser/runtime-проход.

Haskell использует Maybe/Just/Nothing/(>>=), Free Identity/iter, Control.Exception.bracket и обычное каррированное применение. Scala использует Option/Some/None/flatMap, TailCalls, Using.resource и Function2.curried. Исходные foreign-программы не заменены ручными имитациями.

Сравнение считает полный текст каждого варианта, включая все объявления и Throws. Общие зависимости описаны отдельно в[IMPLEMENTATION_DEPENDENCIES](IMPLEMENTATION_DEPENDENCIES.md); исходники мостов и native runtime не объявляются бесплатными. Ни одна форма не исключается ради более короткой второй формы.

## Запуск корня и дальнейшие операции

Всегда запускается корень R0 как L3 Thread. У корня нет DATA и пользовательских аргументов. Локальные объявления и вызовы обрабатываются общим механизмом языка.

Именованные операции из invoke, inputs и тестовых cases выполняются корнем или обычным обработчиком уже после старта. Main и Example\run не являются альтернативными точками запуска программы. Заглушка-родитель может иметь собственные аргументы и отправить корню сообщение; эти аргументы не становятся DATA корня.

load_before обозначает необходимые определения фикстуры. Отдельного режима запуска через загрузку в DATA он не вводит; import открывает доступные имена. Для короткого фрагмента явно задаётся принимающий контекст последующей обычной операции. Новая команда CLI или API запуска здесь не определяется. LMX runtime: NOT_RUN. [Норма запуска](../../LMX_semantics.en.md#source-entry-profiles).
