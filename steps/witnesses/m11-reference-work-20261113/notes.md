Инициализированные ссылки на int и Structure поддержаны в собственных данных, bare-присваивании,
явном пути и кодовом ресивере @. Ресивер в коде проверяет и пишет место выбранной data.
Коллектор own сохраняет исходное описание типа; implicit reference-place получает настоящий
slot → uninit:T → заранее выделенная typed cell, без обещанного начального null.
Первый и последующие writes меняют payload той же ячейки. Новые физические kinds8/9
декодируют только служебную связь к поддержанным reference kinds5/6.

Карта прежнего кадра хранит собственный рабочий снимок ссылки. Bare-имя и путь через него читают
снимок; явный путь через data читает опубликованное поле. После RHS строка заново находится,
write ставит dirty. Стандартная публикация меняет физическую ячейку и очищает dirty,
сохраняя рабочий снимок. Первая публикация вычисляемого объявления не помещает рабочий clone
в физический слот. Данные собственного вызываемого по-прежнему проходят только корневые
реализованные объявления; новые копии не делают скрытого рекурсивного обхода test.

Общий known_place выполняет preflight до RHS; known_int остаётся строгой числовой обёрткой.
Проба другой data выявила ослабление модели: int-модель допускала ссылочное фактическое место.
Оно исправлено: ожидаемый primitive kind один раз сохраняется при связывании модельной строки
в expected_kind и проверяется до RHS. Это поле прежней карты обхода, не новая таблица или журнал.
API graph68/run52; описание Work расширено полем контракта, заголовки созданы штатным инструментом.

Native использует тот же preflight, снапшот и writer. Поддержанная арифметика остаётся прямой.
Фиксированный вид собственного места метода позволяет выпустить одну RHS-ветвь с runtime guard;
формалы, свободные входы, пути и обычная C остаются динамическими. В динамической ветви лишь
один receiving context исполняется. Числовой контекст отказывает нечисловой форме до её эффектов;
ошибки трансляции не подавляются. Новые вложенные проверки снимка сначала дали недопустимый
отступ L1; исправлен производитель, исходники L1/C вручную не правились.

## Открытая граница

GC живых/приостановленных кадров остаётся задачей M14/K11: существующий mark ещё не обходит
frame.rows, рабочие ссылки, operands и inputs. Штатный сбор вызывается после завершения исполнения,
автоматического сбора из аллокаторов нет; обычная арена не объявляется особым non-collecting режимом.
Текущие проверки не доказывают сохранность снимков при явном GC внутри живого кадра.

Это не закрытие всего M11. Вычисляемые fn/sub в данных и коде, root/self, индексированные
повторные методы, остальные адресные/модельные формы и миграция временных root-держателей
продолжаются по to_sol. Reference-place overlap в merge остаётся открытым M6/M13:
int-only alias/write не расширены механически; wrapper нельзя терять при composition.
Void/null, произвольная глубина ссылок, мерность массивов и descriptor — M13;
обычный C-native, совместимый native копии, dirty-код и языковой flush — M14.
M11.7/test и рабочий frontend M11.8 также открыты. Норма и грамматика этим срезом не меняются.
