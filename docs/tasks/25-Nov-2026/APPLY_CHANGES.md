# Как применить дополнение

Это **архив только новых и изменённых файлов**, рассчитанный относительно `spec.tar(2).gz`, SHA-256 `d88d7732d511ebb5679cc045cd5764fc1d02b25f8242c46d4eb728edc147ed00`. Полное содержимое прежнего архива не повторяется.

В корне целевого проекта должны находиться `spec/` и `doc_examples/`. Новые примеры уже слиты в `doc_examples` по существующему формату `src/*.lm3` и TSV-индексов; отдельного ручного импорта примеров не требуется.

## Вариант с проверкой хэшей

Распакуйте дополнение **в отдельную директорию**. Из неё выполните:

```sh
python3 apply_changes.py --target /path/to/project
python3 apply_changes.py --target /path/to/project --apply
```

Первая команда только проверяет. Вторая сначала проверяет весь список, затем применяет изменения. Для замен и удалений проверяется исходный SHA-256; для добавлений ожидается отсутствие файла либо уже установленное точное новое содержимое. Если локальный файл был изменён иначе, программа останавливается до начала записи и перечисляет конфликты. Проверяются также хэши самих файлов дополнения. Неизвестные файлы проекта не затрагиваются; повторное применение допускается.

Запись каждого файла атомарна, но применение всего дополнения не является транзакцией файловой системы. При конфликте используйте обычное слияние в системе контроля версий. Символические ссылки в целевых путях не принимаются.

## Ручное слияние

`CHANGES_2026-11-24.json` перечисляет все добавления, изменения и удаления с хэшами до и после. Скопируйте добавленные и изменённые файлы, затем обработайте список `REMOVED_FILES.txt`. Удаления нужны прежде всего для переезда Haskell и переноса старых тестовых текстов в историю `doc_examples`; простое наложение файлов оставит старые пути рядом с новыми.

Обновлённые манифесты `spec` описывают полное состояние **после слияния**, а журнал `CHANGES_2026-11-24.json` — только это дополнение. Сам журнал явно исключён из собственного хэширования.

## Повторная сверка каталога примеров

В комплекте есть [merge_doc_examples.py](tools/merge_doc_examples.py) и независимый [audit_merged_catalogue.py](tools/audit_merged_catalogue.py). После слияния из корня проекта:

```sh
python3 -B tools/merge_doc_examples.py . --baseline /path/to/unpacked-original --check
python3 -B tools/audit_merged_catalogue.py . --output /tmp/lmx-doc-examples-audit.json
```

Для последующей пересборки координат вместо проверки уберите `--check`. `--baseline` должен указывать на отдельно распакованную неизменённую исходную загрузку. Новые тексты не получают P0 автоматически.
