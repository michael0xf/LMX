# Интерпретатор L3 (не L2)

По уточнению автора: интерпретатор исполняет **только L3**. Не `c.*`, не специальные операции L2 (арена, сырые адреса, synchronized, METHOD.addr как вход в C).

Цепочка трансляции: **L3 → L2 → L1 → C99 → L0**. L1 — промежуточная стадия, не носитель графа. Исходники постепенно переписываются с `.lm1` на `.lm2`; в итоге `.lm1` в исходниках не остаётся. Интерпретатор ходит граф L3. Native `lmx_call0` — результат трансляции, не представление программы.

## Предложение Grok Codex (GROK-L3-SUBSET-20260920)

**Ресивер L3.** Принимающее выражение, которое допускает уже построенный граф `.lm3` (скриптовый профиль: корневое тело файла). Парсер строит граф; ресивер проверяет, что это L3-подмножество; интерпретатор ходит структуры и связи. Юнит-тесты допуска — тот же интерпретатор ([семантика](../../docs/LMX_semantics.ru.md#admission)).

**Подмножество L3 для первого интерпретатора** (без низкого уровня):

| есть | нет |
| --- | --- |
| структуры, поля, вложенность, пустое `()` | `c.*`, `#include`, `os:` |
| вызываемые Structure, заголовок в дескрипторе, тело M после слота 0 по порядку | L2: `lmx_arena_take`, диапазоны как пользовательские операции, synchronized |
| `return:` и прочие выходы **в дереве тела** (их может быть много) | одиночный `return_arg` на дескрипторе |
| ветвления/циклы как тела в графе | сырой METHOD.addr как смысл программы |
| аналитический implements + тесты ресивера | позиционный `lmx_runtime_implements` как семантика |

Codex подтвердил якорь `#l3-receiver`. Узлы: [V1.md](V1.md). Прогон: `python tools/run_l3_selftest.py`. `return:` читает аргумент. Только `LMX/dev`.

## Бюджет имён типов

Единица L3 с Thread тянет через `predef` почти всё ядро, а `l1trans` отводит на имена типов одного замыкания 64 записи. Сейчас у `l3_thread_bind`, `l3_n9_walk` и `l3_n10_walk` по **62**; до `4ab2877` было ровно 64 из 64, после него 66 — и наборы перестали транслироваться с ошибкой в постороннем заголовке (`lmx_manager.h.lm1:45`).

Что сделано (`FABLE-L3-TYPE-BUDGET-SHED-20260921-36`): `l3_thread.h.lm1` больше не подключает `l3_recv.h.lm1`, из которого ничего не использовал (−4 имени); проверки `l3_admit` вынесены из N10 в `tests/l3_admit_selftest.lm1`, где нет Thread (N10 −4 имени). Девятый `predef` в `lmx_walk.lm1` остался: его удаление дало бы 64 из 64 без запаса, а единице, которая линкует примитивы, не дало бы ничего.

Проверка — `python tools/l3_type_budget.py`, она же входит в `python tools/run_l3_selftest.py` без `--test`. Число имён даёт сам закреплённый транслятор (пробная единица подключает список `predef` набора и заголовок из K фиктивных `fnptr:`; имён = 64 − K), байты считает модель исходников, и оба счёта обязаны совпасть. Запас 2 — это отсрочка, а не решение: 24 из 62 имён — typedef'ы API-таблиц ядра, встроенных в записи по значению, и снять их может только владелец модели.

Правило для авторов ядра записано в [../README.md](../README.md).
