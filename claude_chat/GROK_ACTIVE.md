# Связь с уже открытым чатом Grok

Common operational guide for Codex and Grok: [chat_config.md](../chat_config.md).

Проверена 2026-09-19 с активной сессией `01a0baf9-6401-7dc3-9819-f322b493bec6`, PID 17220, рабочая директория LMX. Это именно прежний терминальный чат пользователя, не новая ACP-беседа и не Claude.

## Проверенный обмен

1. Codex присоединился к консоли работающего процесса через Windows `AttachConsole`, проверил пустую строку запроса и передал текст через `WriteConsoleInputW`.
2. В родной истории этой сессии Grok появился запрос и ответ `ACK ACTIVE-GROK-93281`. Grok спросил, какой ID сессии видит Codex.
3. Codex ответил напрямую с ID той же активной сессии, не повторяя тестовый код. Grok ответил `ACTIVE-CONSOLE-CONFIRMED`, затем `ACTIVE-GROK-93281`.
4. Ответы прочитаны из родного `updates.jsonl` Grok и завершены событиями `turn_completed` с `end_turn`. Пользователь независимо увидел первый ответ в своём окне. Человеческая пересылка для получения ответов не использовалась.

## Клиент

```powershell
python claude_chat/grok_active.py --session 01a0baf9-6401-7dc3-9819-f322b493bec6 "Сообщение Grok"
```

Перед отправкой клиент заново проверяет ID/PID в `~/.grok/active_sessions.json`, отсутствие незавершённого хода по родной истории и видимую пустую строку запроса. Не использует `resume`, не перезапускает процесс, не создаёт нового агента. Читает ответ до события завершения хода. После тайм-аута нельзя автоматически повторять отправку.

Ввод посылается прямо в консоль. Чтение `updates.jsonl` — чтение штатного журнала ответа, не файловая почта: в этот файл клиент ничего не записывает и постоянных вотчеров не создаёт.

## Ограничения

- Это Windows-консольный адаптер, а не штатный удалённый интерфейс Grok. Нужны живой CLI-процесс, доступная консоль и пустой ввод. Не печатать одновременно с клиентом. Он не является атомарной блокировкой клавиатуры пользователя.
- Grok может преобразовать путь внутри введённого текста автодополнением. Такое преобразование наблюдалось во втором тесте; ответ модели при этом получен. В клиент добавлен уникальный префикс для сопоставления, а фактически доставленный текст и признак `input_transformed` возвращаются вызывающему агенту. Эта последняя доработка не прошла полный повторный цикл: следующая попытка корректно остановилась до отправки из-за непустого ввода.
- Проверка не подтверждает фоновую инициативную доставку от Grok в простаивающую задачу Codex. Codex получает ответ, читая журнал после собственного запроса.
- Адрес актуальной сессии не следует заменять ID другой беседы; после закрытия чата требуется заново определить активную сессию.
- Агенты L1 и сессии Claude не используются этим каналом.

Отдельный ACP-клиент `grok.py` остаётся отдельной новой беседой; его нельзя выдавать за подключение к этому открытому чату.
