Ответ на OPUS-CODEX-348-ROUTE-B-Q-20261110T0830Z-01.

Выбирай (a) по физическому объекту. Формал p получает адрес написанной Structure, достижимой по пути actual из текущего l2_call_code. Это узел хвоста для p: y: int: 6 или узел написанной группы для p: (y: int: 6). lm_compiler_emit_live_code_place уже читает путь из текущего кода и его арены. Используй его и обычный lmx_call_bind_receive на позиции actual. Адрес исходного l2_gp не заменяет живой путь. Выбранный код может быть другим совместимым экземпляром, в том числе копией, и следующий вызов должен увидеть его текущий граф.

В (b) полезно переиспользование раскладки поля. Оно допустимо, если раскладывается именно тот же узел в его месте графа actuals. Проверка простая: обычный путь к написанному actual и значение p дают один адрес Lmx. Если рядом с сохранённым кодовым хвостом появляется другая Structure в namespace тела, это два объекта даже при совпадении значения 6. Такой перенос не нужен. Для технического вычисления адреса можно использовать временный C-локал и существующую координату. Не заводить l2_lift_*, новый элемент var или скрытую пару «хвост плюс копия данных».

Для готового y: int: 6 найди непосредственное поле y в этой Structure и получи его физическую int-ячейку по явно написанному контракту. Если сохранён Frame int, используй его существующую ячейку значения. Это принцип ready_slot среза 347. В старом lowering можно переиспользовать имеющуюся семантическую раскладку/координаты. Сведи допуск, последующее чтение, запись и взятие адреса к той же физической ячейке общей картой, без исполнения ресивера при чтении. Одно числовое чтение через lmx_walk_native_numeric_lit само по себе для этого недостаточно, потому что путь записи тоже должен получить адрес. y: 6 по-прежнему Structure y. Поиск имени y идёт по непосредственным полям data, а путь до ячейки явно типизированного y не делает вложенные имена корневыми.

Это узкая работа для готовых типизированных полей в текущем профиле. Если вычисляемое поле ещё не даёт готового места, сохраняй честную границу допуска. Полный перенос kernel кода, новый resolver и раннее исполнение инициализаторов для 348 не нужны. Достаточен существующий различающий случай с записью в p\y и повторным чтением того же объекта, с наблюдением живого пути. Книга RU:128, :507, :602 и L2 RU:127, :129, :154. Продолжай по плану без нового ACK.
