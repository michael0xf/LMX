Дата: **23 ноября 2026 года**. Основа — свежий загруженный `spec.tar(1).gz`, SHA-256 `9d1820dd6c9c459ceff17eb0b92e148f31041bebfef8d641e6e71b314d8eb13a`. Более ранние редакции сохранены только как происхождение уже включённых решений; для чтения и сборки этой поставки они не требуются.

**Ответы Fable включены в архив:** [FABLE_CLARIFICATIONS.md](FABLE_CLARIFICATIONS.md). В нём разобраны все пункты полученной записки, а принятые исправления внесены в сами постоянные главы. Последнее авторское уточнение запуска также включено: **начинает исполнение корень как обычный L3 Thread, без DATA и пользовательских actuals; родитель может передать аргументы обычным сообщением. Запуска через Main нет.**

## Постоянные главы и общие реализации

Содержание четырёх требований перенесено в нормативную документацию, исходники, описания договоров и примеры. Читателю не нужен отдельный каталог поручений.

| Глава | Включённые правила и реализация |
| --- | --- |
| [Общее равенство](GENERIC_EQUALITY.md) | Generic `unique` с обычным равенством по умолчанию; пользовательское сравнение там, где оно нужно; точный регистрозависимый текст; общие рекурсивные обходы без копирования графов. |
| [Монадические операции](MONADIC_OPERATIONS.md) | Общее имя `bind`, адаптивные конструкторы `some/ok/err/done`, один захват целого `{type value}`, точные результаты и конечные договоры отказов. |
| [Общие операции](GENERIC_OPERATIONS.md) | Обобщённые семейства по действительным типам, общие Patterns, сигнатуры `to`, последовательности и канонические имена без старых callable aliases. |
| [Ресиверная и операндная формы](OPERATION_FORMS.md) | Общая операция и одно имя, роли аргументов, исходная форма и общий lowering, exact identifiers, PLACE-аргументы и четыре варианта инкремента/декремента. |

Текущий каталог содержит **212 канонических публичных имён и 224 типовых варианта**. Операндная и ресиверная запись используют одну реализацию соответствующего договора. Разные значения одной записи не объединяются только ради одинакового написания: например, Pattern-последовательность `then` и контейнерный `bind` имеют разные обязанности. Старые имена не публикуются как совместимые вызовы. [Каталог](patterns/LMX_Fn_Receivers/CATALOG.md), [миграция имён](patterns/LMX_Fn_Receivers/CANONICAL_MIGRATION.json), [карта функций](CORE_FUNCTIONS.md).

Динамическое связывание сохраняется, включая передачу допустимого свободного имени через промежуточный вызов, который его не потребляет. Копирование полей и действительные reference identities не заменены лексическими обходами. Собственный готовый default, разрешённое автозаполнение, свободное имя и явный путь к графу различаются по общему договору.

Запуск корня использует [общую подготовку активации](kernel-implementation.en.md#root-activation). Отсутствие DATA пропускает только подготовку входных мест этой активации. Локальные места CODE, разрешение имён, достигнутые объявления, вызовы, выходы и cleanup используют общий путь. Заглушка-родитель принадлежит дереву Thread; она не создаёт лексического родителя и не подставляет DATA=CODE. Именованные операции проверочных примеров выполняются после старта корня.

В `reference/operation_forms` находится [исполняемая Python-модель общего lowering](reference/operation_forms/README.md). Это проверяемая модель реализации и её наблюдений; она не объявляется production-транслятором или исполнением LMX.

## Примеры и сравнения

**100 клиентских договоров сравнивают обе полные формы LMX:** 24 исходных сценария/Haskell, 24 Julia, 24 Perl, 24 Common Lisp/SBCL и четыре функциональных клиента группы09 с Haskell/Scala. Всего получается **200 стилевых измерений**.

Процедурный вариант показывает явный алгоритм: последовательность действий, циклы, ветвления и изменения мест. Функциональный вариант использует общие операции, композицию и Expression. Оба варианта сохраняют один наблюдаемый договор, порядок эффектов, состояние ошибок и границы контрольной программы. Когда предметом примера является единственная низкоуровневая операция и обе минимальные записи совпадают, хранится один исходник с пояснением и двумя равными измерениями. Общие реализации библиотеки не размножаются по стилям.

В SBCL применяется общий механизм Expression с подходящим шаблоном операнда; он не объявляется отдельным «префиксным типом». Haskell, Scala, Julia, Perl и Common Lisp используют сохранённые контрольные листинги. Сравнения реализаций отделены от клиентского использования; замыкание зависимостей учитывается целиком, а общая зависимость не прибавляется заново к каждому клиенту.

В [общем руководстве по примерам](patterns/LMX_examples_and_analogies.ru.md) сохранены также 18 дополнительных учебных фикстур, пояснения и карта покрытия. Генератор собирает их из постоянного supplementary source и проверяет полноту обязательных разделов; обновление сравнительных таблиц не удаляет эти главы.

Все ссылки `copy(target\throws)` и все написанные объявления ошибок входят в полный размер исходника. Отдельной сокращённой Throws-колонки в текущих публикациях нет. Для перегрузки указывается выбранный метод или конечное объединение действительно достижимых договоров. Опубликованное описание системных ошибок должно соответствовать реальному исполнителю; пустая выдуманная native-заглушка этим правилом не разрешается.

Подсчёт использует непробельные Unicode-символы полного листинга. JSON дополнительно хранит строки, байты и контрольные суммы. Аналогии и случаи без контрольной программы явно отмечены и исключены из сравнительных отношений; отсутствие программы не считается нулём. Разные наборы задач не образуют общий рейтинг языков.

**18 PDF и 18 XLSX** построены из общей [модели публикации](patterns/PUBLICATION_DATA.json). Оба LMX-стиля имеют собственные колонки. Зелёным подчёркивается минимальное число сопоставимой строки; все равные минимумы отмечаются одинаково. В XLSX правило привязано к числам через conditional formatting, итоги содержат проверяемые формулы. Сохранён порядок вкладок исходных книг.

Сводки: [все языковые примеры](patterns/examples/STATISTICS.md), [Haskell/Scala](patterns/09_functional_computation/LMX_Comparison_09_functional_computation.md), [Julia](patterns/examples/julia_comparison/LMX_Comparison_Julia.md), [Perl](patterns/examples/perl_comparison/LMX_Comparison_Perl.md), [SBCL](patterns/examples/SBCL_comparison/LMX_Comparison_SBCL.md).

## Уточнения по находкам Fable

Исправлены реальные расхождения грамматики и пояснений составной головы; явно закреплены `Name::A`, многострочная группа-голова и `T@x`. Объявление-аргумент занимает обычную позицию целой Structure: внутреннее имя не выбирает формал и не заменяет его описание. Лишний actual отклоняется до эффектов его initializer.

Общий шаблон готовых библиотечных операндов теперь является обычной `FxPreparedOperands`, а приоритет каждого потребителя задан явно. Указаны реальные обращения к `raise` в создаваемом CODE. Адаптеры сохраняют исходную политику required/private/defaults. `replaceRange` возвращает изменённую цель, `splice` — удалённый диапазон; `stopFirst` задаёт локальный порядок попыток. Граница compile/endturn уточнена как обновление машинной реализации, без задержки обычного чтения изменённого графа.

А4 объяснён собственным default и отсутствием неявной записи обратно в граф. А5 прямо связывает автоматический отказ reached admission интерпретатора с именем `interpreter`. А7 приведён к последнему авторскому решению о единственном запуске с корня. В4 уточнён: невычисленный initializer в сериализованном графе сам по себе не ошибка исполнения.

Остающийся узкий вопрос А3 сформулирован в [ответах](FABLE_CLARIFICATIONS.md#a3): требуется ли универсальное source-обращение корня к себе, когда подходящей доступной ссылки нет. Уже существующий путь `parent(child)` при действительной прямой дочерней связи описан отдельно; новое специальное имя не введено.

Парсер, production-транслятор и runtime этого языка в рабочей среде отсутствовали; для изменённых листингов установлен **NOT_RUN**.
