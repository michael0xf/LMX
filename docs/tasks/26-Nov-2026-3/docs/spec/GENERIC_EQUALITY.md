# Общее равенство, сравнение диапазонов и unique

Нормативный контракт: `unique(items)` удаляет повторения обычным сравнением фактических значений; явный `same` выбирает пользовательское равенство. `equalFields`, поиск и Pattern используют общий проход диапазонов.

Код ниже описывает общий алгоритм ядра и его интеграцию с типизированными записями. Он должен сохраняться в единственном исполняемом определении. Проверка текста не является runtime-приёмкой; исполнение LMX в этом пакете — **NOT_RUN**.

Связанные разделы: [общие операции](GENERIC_OPERATIONS.md), [две формы операций](OPERATION_FORMS.md), [последовательности](CORE_SEQUENCES_REGEX.en.md#sequences).

## 1. Общий договор

Публичный оператор `unique` в [экспортах ядра](patterns/LMX_Fn_Receivers/src/public.lmx) предоставляет обычное сравнение по умолчанию. В примере не должно требоваться объявление функции, единственное действие которой — `return: left = right`.

Обобщение опирается на фактические типы значений и штатные операции последовательностей. Вход допускает типизированные плотные массивы, строки, массивы ссылок, смешанные последовательности и вложенные конечные ациклические последовательности. `int` остаётся у индексов, счётчиков и результата предиката; тип данных пользователя он не определяет.

У `equalFields` сравнение элементов также необязательно. Единственный общий выбор сравнения находится в `FxValueSame`, единственный обход пары диапазонов — в `FxSequenceDifference`; `FxEqualFields` проверяет длины и делегирует этому обходу. `unique` использует эти определения. Основание: [действующие операции последовательностей](CORE_SEQUENCES_REGEX.en.md#sequences), [текущий `unique`](patterns/LMX_Fn_Receivers/src/corePerlExamples.lmx), [текущий `equalFields`](patterns/LMX_Fn_Receivers/src/coreComparisonGroups.lmx) и [существующий `FxValueSame`](patterns/LMX_Fn_Receivers/src/generic_runtime.lmx).

## 2. Публичный контракт

| Вызов | Поведение |
| --- | --- |
| `unique(items)` | Удалить повторы с обычным сравнением, сохранив порядок первых представителей. |
| `unique(items; same)` | То же, с явно переданным сравнением двух целых элементов. |
| `equalFields(first; second)` | Сравнить две последовательности по длине и упорядоченным элементам; вложенные последовательности сравнивать тем же способом. |
| `equalFields(first; second; same)` | Сравнить соответствующие элементы указанным предикатом; целый элемент передавать предикату без автоматического раскрытия. |

`items`, `first` и `second` передаются как ссылки на полные записи значений с фактическим типом. Профиль входной последовательности проверяют существующие `FxSeqInfo` и остальные `FxSeq*`.

У `same` объявлен инициализатор `0`. В этом API **значение `0` явно означает выбор обычного сравнения**; поэтому `unique(items; 0)` имеет тот же режим, что и `unique(items)`. Ненулевое значение должно быть допустимой вызываемой операцией согласно `FxApply`. Это конкретное соглашение данного параметра, а не правило, что любое отсутствующее, неинициализированное или нулевое значение языка взаимозаменяемо.

Для пользовательского сравнения сохраняется существующий протокол: фактические записи двух значений передаются через `FxTwo` и `FxApply`; результат проверяется `FxSeqPredicate`. Порядок аргументов в `unique` — сначала ранее сохранённый представитель, затем рассматриваемый элемент. Предикат должен задавать выбранное отношение равенства и не менять обходимые значения.

## 3. Код общего алгоритма

Ниже приведены определения общего сравнения и удаления повторов. Полное тело `FxSequenceDifference` находится в [диапазонном сравнении](GENERIC_OPERATIONS.md#51-диапазоны); второго цикла `equalFields` нет. Их зависимости уже существуют в ядре: `FxKernel`, `FxSeqInfo`, `FxSeqRead`, `FxSeqAllocate`, `FxSeqStore`, `FxSeqPredicate`, `FxSequenceDifference`, `FxApply`, `FxTwo` и `FxThrows`. Копировать тела этих зависимостей в новый файл не требуется.

### 3.1. Общий выбор сравнения

Разместить `FxEqualityTypes` и единственное определение `FxValueSame` в [src/generic_runtime.lmx](patterns/LMX_Fn_Receivers/src/generic_runtime.lmx). Прежнее определение `FxValueSame` из `src/coreStandardLisp.lmx` убрать при интеграции, чтобы не возникло двух реализаций одного помощника. Действующие вызовы с явным `same` сохраняют свой протокол.

```lmx
FxEqualityTypes:
    array:
        []: value

FxValueSame:
    private:
        @: first
        @: second
        @: same 0
    required: first second
    return: int
    test:
        throws: copy(FxThrows\predicate)
        if: same != 0
            return: FxSeqPredicate\truth(FxApply\apply(same; FxTwo\make(first; second)))
        private: int: firstArray FxKernel\acceptsRequirement(
            candidate := first;
            requirement := FxEqualityTypes\array[0]
        )
        private: int: secondArray FxKernel\acceptsRequirement(
            candidate := second;
            requirement := FxEqualityTypes\array[0]
        )
        if: firstArray != secondArray
            return: 0
        if: firstArray != 0
            return: FxEqualFields\equalFields(first; second)
        return: \first = \second
```

`[]: value` здесь — обычное объявление типа «любой Array», включая плотные массивы и Structures. Оно используется как TYPE-токен; его неинициализированное значение читать не нужно. `@[]` для этой проверки не подходит: это конкретный профиль массива ссылок. Оба различия уже описаны в [типах последовательностей](CORE_SEQUENCES_REGEX.en.md#types).

`FxKernel\acceptsRequirement` — существующая точка интеграции [AR01](patterns/LMX_Fn_Receivers/KERNEL_REQUIREMENTS.md#interface-probe-ar01). Она должна возвращать `1` или `0` по установленной совместимости с требованием, без пробного вызова кандидата, конвертера или инициализатора. Ошибки `FxTypeToken` и `FxKernelFailure` сохраняются: перехватывать их и выдавать «не массив» нельзя. Нового операнда или ресивера данный код не требует; необходима реализация уже описанного AR01 в среде исполнения.

### 3.2. Один общий обход последовательностей

Заменить существующее определение `FxEqualFields` в [src/coreComparisonGroups.lmx](patterns/LMX_Fn_Receivers/src/coreComparisonGroups.lmx).

Единственное тело `FxEqualFields` приведено вместе с
[FxSequenceDifference](GENERIC_OPERATIONS.md#51-диапазоны): оно проверяет профили
и длины, затем передаёт полные диапазоны в этот общий обход. Отдельного цикла
сравнения здесь нет.


При обычном сравнении вложенный Array снова проходит через этот же обход. При явном `same` соответствующие элементы передаются ему целиком: рекурсивно раскрывать их вместо пользовательской операции нельзя. Две пустые последовательности равны; при разной длине или первом несовпадении обход заканчивается сразу.

### 3.3. `unique` без обязательного компаратора

Заменить существующее определение `FxUnique` в [src/corePerlExamples.lmx](patterns/LMX_Fn_Receivers/src/corePerlExamples.lmx).

```lmx
FxUnique:
    private:
        @: items
        @: same 0
    required: items
    return: @
    unique:
        throws: copy(FxThrows\predicate) SequenceElement SequenceSize
        private: @: info FxSeqInfo\get(items)
        private: int: count length(items)
        private: @: result FxSeqAllocate\make(info\arrayType; count)
        private: int: used 0
        private: int: i 0
        while: i < count
            private: @: item FxSeqRead\read(items; i)
            private: int: duplicate 0
            private: int: j 0
            while: j < used
                private: @: previous FxSeqRead\read(result; j)
                if: FxValueSame\test(previous; item; same) != 0
                    duplicate := 1
                    break
                j += 1
            if: duplicate = 0
                FxSeqStore\write(result; used; item)
                used += 1
            i += 1
        sys\resize(result; used)
        return: result
```

Результат выделяется по `info\arrayType`. Поэтому плотный массив сохраняет свой фактический тип; превращать весь вход в `@[]` не требуется. Чтение и запись остаются типизированными и проходят через существующие [src/sequences_core.lmx](patterns/LMX_Fn_Receivers/src/sequences_core.lmx).

Алгоритм делает не более `n(n−1)/2` сравнений верхнего уровня для `n` входных элементов. Стоимость каждого сравнения зависит от значений, особенно для вложенных последовательностей. Дополнительный внешний контейнер занимает `O(n)` мест; рекурсивное сравнение использует стек по глубине вложенности. Хеширование не требуется, поэтому пользовательское отношение равенства не обязано сопровождаться отдельным хешером.

## 4. Обобщённый пример для документации

```lmx
Example:
    []: xs
    return: @
    run:
        throws:
            FxCallFailure
            FxKernelFailure
            FxPredicate
            FxTypeToken
            ReceiverIndex
            SequenceElement
            SequenceSize
        return: unique(xs)
```

`[]: xs` принимает любой Array. Сам вызов не зависит от `int`, строк или конкретного типа элемента. Для исходного сравнительного сценария с целыми числами можно оставить его исходную сигнатуру `int[]: xs`, если это часть согласованного контракта сравнения языков; локальный `Equal` при этом всё равно удаляется.

Полный `throws` показывает ошибки, которые может породить метод. Считаю такую явность преимуществом языка: длинный список не создаёт необходимости скрывать контракт. При многократном использовании одного списка применяется штатное `throws: copy(Throws)`; в ядре выше уже переиспользован существующий `FxThrows\predicate`.

## 5. Точное значение «обычного сравнения»

| Значения | Правило |
| --- | --- |
| Два скалярных значения | Обычный `=` над их фактическими значениями, с действующими правилами совместимости типов. |
| Две последовательности | Равная длина и попарно равные элементы в том же порядке; вложенные последовательности сравниваются рекурсивно. |
| Последовательность и скаляр | Не равны. Распространение скаляра на элементы массива здесь не применяется. |
| Два `char[]` | Точное сравнение последовательностей символов: длина, регистр и каждый элемент значимы, включая нулевой символ. |
| Две Structures | Сравнение физических упорядоченных элементов по контракту `equalFields`; имена полей и лексический родитель не входят в это отношение. |
| Разные типы скаляров | Сравнение допустимо ровно там, где его допускает обычный `=`. Несовместимость сохраняет штатную ошибку. |
| Разные профили хранения последовательностей | Равенство определяется элементами; равенство TypeRef контейнеров не требуется: сравнение элементов не заменяется тождеством их полных типов. |

Правила исходят из [Expression](CORE_SEQUENCES_REGEX.en.md#expressions), [записи `{type value}`](L2_spec_en.md#value-record) и существующего контракта [упорядоченного сравнения полей](patterns/LMX_Fn_Receivers/src/coreComparisonGroups.lmx).

Обычный `=` над массивами в LMX возвращает поэлементный результат. Поэтому в коде выше массивы сначала распознаются и направляются в `equalFields`: маска сравнения не выдаётся за один логический результат. Нельзя заменить весь `FxValueSame` выражением `\first = \second` и объявить задачу обобщения решённой.

Отдельная функция `sameText` не вводится. Строка сравнивается существующим общим обходом последовательностей. Нового цикла посимвольного сравнения, автоматического снятия регистра, нормализации текста или неявной регулярной интерпретации здесь нет.

Значения пользовательских моделей — например, словаря, множества или именованной записи — могут требовать собственного отношения равенства. Физический тип Structure сам по себе не устанавливает семантику такой модели. В этом случае используется явный `same`.

Область рекурсивного режима — конечные ациклические последовательности. Код не содержит учёта посещённых пар объектов и не реализует сравнение циклических графов. Для значений с циклами нужен явный компаратор с определённой семантикой; добавлять отдельный обход графа внутрь `unique` не следует.

Не вводится сокращение «ссылки совпали — значения равны»: такое сокращение могло бы изменить результат обычного скалярного сравнения. В частности, поведение специальных числовых значений должно следовать выбранному числовому профилю LMX.

## 6. Результат, ссылки и ошибки

Результат — новый внешний контейнер даже для пустого входа и входа из одного элемента. Исходный контейнер не изменяется. Из каждой группы равных значений сохраняется первый представитель и исходный порядок представителей. Плотные значения переносятся с их типом, а выбранные ссылочные элементы сохраняют свои цели; глубокого копирования объектов нет. Это следует из [контракта выборки последовательностей](CORE_SEQUENCES_REGEX.en.md#sequences) и используемых `FxSeqAllocate`/`FxSeqRead`/`FxSeqStore`.

Сравнение может признать значения разных допустимых типов равными. Тогда в результате остаётся именно первый представитель; преобразовывать его в тип более позднего элемента нельзя.

Набор именованных ошибок не сокращается:

| Метод | Именованные ошибки |
| --- | --- |
| `FxValueSame\test`, `FxEqualFields\equalFields` | `FxCallFailure`, `FxKernelFailure`, `FxPredicate`, `FxTypeToken`, `ReceiverIndex`. |
| `FxUnique\unique` | Тот же набор плюс `SequenceElement`, `SequenceSize`. |

Первые пять имён уже объединены в [FxThrows\predicate](patterns/LMX_Fn_Receivers/src/failures.lmx). Ошибка пользовательского вызова сохраняет существующий путь `FxCallFailure`; нецелочисленный результат предиката отвергается через `FxPredicate`. Ошибки ядра, допуска элемента и размера сохраняются. Обычные ошибки скалярной операции и системные ошибки идут по действующим каналам LMX.

При ошибке метод не возвращает частично заполненный результат. В коде не нужен перехват с посимвольной проверкой имени ошибки. Новый `FxRecordArity` в эти объявления не добавляется: нового механизма record-операндов здесь нет.

## 7. Связи реализации и клиентских примеров

1. Сопоставить определения в новой версии и применить три блока кода из раздела 3. Оставить ровно одно определение `FxValueSame` и один диапазонный алгоритм `FxSequenceDifference`.
2. Проверить сборку общего ядра и разрешение взаимных ссылок `FxValueSame`/`FxEqualFields`. При интеграции помощника обновить список исходников, если сборка перечисляет их явно.
3. Сохранить существующие публичные имена `unique` и `equalFields`. Новых публичных имён для той же операции не вводить.
4. Обновить описания сигнатур: у `unique` обязателен только `items`; у `equalFields` обязательны `first` и `second`; `same` необязателен и имеет документированный выбор `0`.
5. Обновить документацию, метаданные и проверки в новой версии. Заменить устаревшие утверждения об обязательном сравнении и отсутствии рекурсивного режима `equalFields`.
6. Удалить локальные обёртки простого равенства из следующих примеров, сохранив их остальной контракт:

| Пример | Новый основной вызов |
| --- | --- |
| [Julia J21](patterns/examples/julia_comparison/source/lmx/J21.lm3) | `unique(xs)` |
| [Perl P09](patterns/examples/perl_comparison/source/lmx/P09.lm3) | `unique(items)` |
| [SBCL S08](patterns/examples/SBCL_comparison/source/lmx/S08.lm3) | `unique(items)` |

Если исходный пример действительно использует особое равенство, его предикат сохраняется. Реальный выбор ключа, преобразование записи или сравнение по отдельному полю не считаются пустой обёрткой.

Общее правило аудита остаётся прежним: возможность оператора или стандартной библиотеки сравниваемого языка, которая сокращает запись, должна иметь соответствующую удобную возможность ядра LMX. Тот же общий выбор равенства следует использовать при дальнейшей проверке `groupBy`, `groupAdjacent`, операций принадлежности и множеств, поиска ключей и мемоизации, не размножая реализации сравнения.

`groupBy(items; keyOf := 0; sameKey := 0)` использует уже прочитанную полную запись элемента как ключ по умолчанию. Явный `keyOf` вызывается один раз на элемент; `sameKey = 0` выбирает общее равенство. Таков также короткий вызов в примере Perl P10. `FxIdentity\identity(typeToken)` остаётся фабрикой типизированной функции и не выдаётся за уже готовое универсальное тождество.

Статистика и PDF/XLS рассчитываются по полным текущим клиентским исходникам. Функциональное сравнение содержит самостоятельные процедурную и функциональную LMX-формы одного договора; все объявления ошибок и ссылки `copy(target\throws)` учитываются целиком. Списки копируются из фактически выбранных методов, без неоднозначного выбора первой перегрузки. Зелёным отмечаются минимальные полные значения в сопоставимой строке; статистического сокращения Throws нет. Алгоритм `unique` в библиотеке остаётся одним общим телом.

## 8. Проверки при приёмке

Все перечисленные проверки — требования к запуску в проектной среде; статус исполнения в этом пакете — **NOT_RUN**. Обозначения входов в таблице описывают значения, а не вводят новый синтаксис литералов LMX.

| № | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| U01 | `unique(xs)` без объявления `Equal` | Обычный вызов принимается; второй аргумент не требуется. |
| U02 | Пустой массив; массив из одного элемента | Новый внешний контейнер того же профиля; ноль сравнений. |
| U03 | Значения `3, 1, 3, 2, 1` | `3, 1, 2`, с сохранением порядка первых представителей. |
| U04 | Разные целочисленные и вещественные плотные массивы, `char[]` | Тип контейнера сохраняется; нет принудительного преобразования в `int[]` или `@[]`. |
| U05 | Смешанные допустимые скалярные типы | Равенство соответствует обычному `=`; первый представитель сохраняет свой фактический тип. |

## 9. Сопоставление с Julia

Для исходного примера удаления повторяющихся обычных целых чисел короткая форма LMX должна быть такой же прямой: `unique(xs)`. При этом обобщение требует честно назвать отношение равенства.

В Julia [`unique`](https://docs.julialang.org/en/v1/base/collections/#Base.unique) использует `isequal` и `hash`, сохраняет порядок первых представителей. Контракт [`isequal`](https://docs.julialang.org/en/v1/base/base/#Base.isequal) отличается от обычного числового равенства, в частности для NaN, знакового нуля и `missing`. Поэтому приведённый режим LMX нельзя без отдельной реализации и проверки объявлять полной копией семантики Julia для всех типов. Совпадение на согласованном домене примера и обобщённость входных данных — отдельные требования.

Имена новых пользовательских операций, если они понадобятся при дальнейшем расширении, должны следовать согласованному lowerCamelCase и по возможности сохранять привычное название исходной операции. В данном изменении достаточно уже существующих `unique` и `equalFields`.
