## Вся структура аргументов: два метода и неоднозначность

Источник: ответ автора в чате Codex 2026-11-08 на вопрос Codex, которым было удержано решение среза 304
(CODEX-FABLE-304-CHOICE-HOLD-20261107T233359456Z-01): даны два метода `fn: f (Pair: p) int` и `fn: f (int: x; int: y) int`
и вызов `f(s)`; спрошено, этот ли случай имелся в виду. Передан fable_pc сообщением
CODEX-FABLE-AUTHOR-STRUCTURE-AMBIGUITY-RESOLVED-20261108044825Z-01. Выдержка из ответа автора (технический фрагмент;
фразы о непонимании вопроса и встречный вопрос Codex о «другой записи» опущены), дословно:

```text
Если s состоит из двух полей "x y" то ошибка потому что не понятно какую функцию из двух вызывать.
```

Пояснение Codex при передаче (не слова автора): автор подтверждает описанную неоднозначность двух методов — когда
подходят оба (один принимает саму Structure одним аргументом, другой полный набор её полей), `f(s)` неоднозначен и
должен отказать, а не выбрать один; единственный подходящий метод разрешается обычным сопоставлением, принудительного
раскрытия и переписывания прежних вызовов нет; именованная подача `f(v := s)` подаёт `s` формалу `v`. Удержание снято;
реализация whole-arguments продолжается под этим правилом. Книга:
[вся структура аргументов](../docs/LMX_semantics.ru.md#whole-arguments).

## Применимость метода при неоднозначности: первая часть `implements` при трансляции

Источник: уточнение автора в чате Codex 2026-11-08 к ответу о двух методах (выше); передано fable_pc сообщением
CODEX-FABLE-AUTHOR-IMPLEMENTS-MATCH-20261108T052418Z-01. Дословно:

```text
и этотолько в случае если fn: f (d: S) тоже требует S с двумя такими полями. Вы сейчас сверку типов каким образом делаете? При трансляции надо первую часть implements вызывать
```

Пояснение Codex при передаче (не слова автора): при `f(s)`, где `s` содержит `x` и `y`, неоднозначность даёт не само
наличие двух методов и не совпадение числа или названий полей — метод с формалом `d: S` должен действительно принимать
эту Structure по требованиям `S`, и метод с набором полей тоже должен быть применим; только два действительно подходящих
метода неоднозначны, один подходящий вызывается. Применимость при трансляции устанавливается первой частью `implements` —
общей Consumer-relative проверкой совместимости с существующей таблицей преобразований, без исполнения преобразователей
и тела и без отдельного аналитического теста; числом полей, равенством kind/type или сокращённой проверкой её не
подменять. Книга: [вся структура аргументов](../docs/LMX_semantics.ru.md#whole-arguments).

Пояснение Codex при передаче (не слова автора): вопрос 50/15 был его собственной недоказанной постановкой, а не выбором

Пояснение Codex при передаче (не слова автора): для каждого примитива T — отдельный тип «T без инициализации», определяемый по

переклассификация его адреса; различие обязательного формала и умолчания 0 задаётся тем же типом адресованной ячейки, этот

вопрос показывать минимальным случаем Codex, затем при необходимости автору; саму модель автора не переоткрывать.
