2. Замена — связи ячейка → места кода, отдельно от companion:
- запись связи = пара (holder, slot), одна на каждую ТЕКУЩУЮ установку ребёнка в место кода; ведутся только рёбра кода (установка, при которой code_write(holder, slot, old, new) истинно по (1)–(4)); установка в данные записи не создаёт — ячейки данных связей не имеют и ничего не стоят;
- хранение: таблица арены «адрес ребёнка → цепочка (holder, slot)», хеш по адресу как copy-map; таблица и записи — блок арены (как записи чанков chunk_block), не ячейки графа: GC не маркирует/не чистит, копирование и merge не видят, освобождаются с ареной (lmx_arena_release :690); companion остаётся saved Value-context и о местах не знает;
- поддержание: одна функция ядра lmx_graph_slot_rebind(arena, holder, slot, old, new), через которую идут все три физических пути: lmx_graph_ref_fill_in (holder/index — аргументы, old — текущее \slot), lmx_arena_ref_store (parent/index — аргументы), lmx_value_cell_fill для ячейки kind CHILDREN/REF — holder/slot восстанавливаются из ячейки-слота: пул CHILDREN — массив детей ровно одной Structure (lmx_arena_refs_open_profiled :248–283: lmx_pool_make_profiled на каждую, parent\array.data = данные его чанка) — в запись пула добавляется обратная ссылка holder, проставляемая там же, slot — порядковый номер в чанке; пул REF (lmx_array_ref_owned.lm2:65) — holder = сам Array. Семантика: old ≠ 0 → снять ровно запись old → (holder, slot), остальные связи old остаются (перепривязка одного слота не трогает актуальную связь другого); new ≠ 0 и ребро — код → добавить new → (holder, slot); затем сброс по code_write;
- использование при фактической записи в ячейку (store_with_writer: числа — store_numeric_raw, ссылки — не-слотовая ячейка; место любого вида — слот, проекция, ELEM, deref): один lookup по place\address; нет связей → данные, ничего не сбрасывается; есть → для каждой (h, s): native: 0 у h и подъём от h (у узла с собственными связями — по всем его holder'ам, у узла без связей — по цепочке parent с native != 0, как в ред. 4). Запись через @p снимает слова C1 и C2 — оба и ровно их. Поля holder/slot у LmxWalkPlace сняты из дизайна;
- смерть держателя: единственная точка, где массив покидает арену — lmx_arena_array_drop lmx_arena.lm2:186 (вызовы :264, lmx_pool.lm2:309/570, в т.ч. sweep GC): для пула CHILDREN/REF снимаются связи его ненулевых слотов (O(слотов), которые drop и так освобождает), для пула ячеек — головы цепочек по адресам его ячеек; связи слабые, держателя не удерживают.
Ничего из этого не запрещает допустимое разделение ячейки, не обходит/не проверяет программу, не снимает native на записях данных; рёбра известны в момент установки. Стоимость: O(1) на установку ребра кода, O(1) lookup на запись данных, O(связей × глубина) только на запись в код.
