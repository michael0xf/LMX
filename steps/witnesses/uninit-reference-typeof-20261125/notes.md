# typeof ссылки без значения: фикстура исправлена по норме, 2026-11-25

Строка регрессии `uninit_reference_visibility` (pin `0 1 0`) была записана в плане 29.3 как дефект ядра (д4): `typeof`
даёт 1001025 вместо 1001028. По решению Sol и Astra это дефект фикстуры: норма требует замены фрагмента при явной
записи по пути, ядро не менялось. Ожидание прежней фикстуры утверждало состояние до записи, которого её чтение не
видело. Фикстура переписана: `typeof(D[0])` читается в исполненном теле трижды, ожидание выведено из нормы до прогона;
строка зелёная в трёх режимах.

## Решение

Sol, Astra (`CODER-D3-D4-DESIGN-QUESTION-20261125-01-ASTRA-ANSWER`). Сохранение обёртки при записи по пути отклонено:
`#uninit-record-control`, `#frame-and-graph-assignment` и `#get-type` требуют замены фрагмента у `D\p`. Состояния: при
свежем `D[0]` после установки — готовая int-reference (1001025); после typed null — та же готовая форма с payload 0; у
установленной ссылки проверяется цель. Механизм path store остаётся общим по смыслу для обоих маршрутов; адрес прежней
записи не обязан следовать за заменой, другой слот, ссылающийся на старый фрагмент, не меняется. Реальное наблюдение по
прежней строке (`early=1001025, late=1001025, seen=7`) не доказывает состояние до записи: `early` — вычисляемое
объявление DATA, `build\data\early` читают после `build()`; одной правкой цифр старый тест не закрывается. Требуется
наблюдать `typeof(D[0])` в исполненном теле: непосредственно до записи (uninit-int-ref), после ненулевой ссылки (int-ref),
после typed null (int-ref), значение 7 до null. Проверка нулевого payload старого uninit держится отдельно — в M13/M14.

## Норма

- P01 (`docs/spec/kernel-implementation.en.md:331`, рус. `kernel-implementation.ru.md:306`, якорь `#primitive-storage`;
  `docs/spec/L2_spec_en.md:202` `#uninit-record-control`): `uninit:T` — это только его код типа, `sizeof(value) = 0`;
  нет ни внутренней записи T, ни заранее выделенной ячейки T, ни незаписанной полезной нагрузки T, ни лишнего указателя
  на такую ячейку; логический принимающий тип остаётся T, отсутствие отличается от инициализированного значения.
- Там же, следующий абзац, и `#frame-and-graph-assignment` (`provenance/semantics-book.md:1501`, `:2498`): явное
  присваивание графу заменяет материал графа в адресованном структурном месте. `#get-type` (`:4846`, `:4891`).

## Маршрут (ядро не менялось)

До записи слот `D\p` держит объявленную обёртку типа `LMX_TYPE_UNINIT_GRAPH_INT_REF` (1001028). Запись по пути
`lmx_graph_store_path_reference` (`lmx_graph_run.lm2:1942–1955`) берёт новую ячейку через
`lmx_graph_reference_holding` (`lmx_graph.lm2:2293–2304`) типа `LMX_TYPE_GRAPH_INT_REF` (1001025) и замещает ею
фрагмент поля (`lmx_graph_replace_leaf`); `typeof` отвечает типом региона ячейки, стоящей в слоте. Typed null — та же
готовая форма с payload 0 (ноль — типизированная нулевая ссылка, `lmx_graph_run.lm2:1957–1961`).

## Что изменено

- `selfbuild/tests/graph/uninit_reference_visibility.lm3`: три чтения `typeof(D[0])` простыми операторами тела
  `build`, каждое записано в место данных по пути (локалы не публикуются): `data\before_write := typeof(D[0])` до
  записи; `D\p := @(data\i)`; `data\after_set := typeof(D[0])`; `data\seen := \(D\p)`; `D\p := 0`;

  наблюдении. Заголовок называет норму (P01, `#frame-and-graph-assignment`).
- `selfbuild/tests/graph/uninit_reference_visibility.expected`: каноническая печать AFTER инструмента

- `selfbuild/inputs.sha256`: 1788 входов, `37b940fa…`.

## Свидетельства

**Ожидание до прогона.** Значения выведены из нормы до первого запуска и записаны в частный файл ожидания:
`before_write 1001028` (объявленная обёртка, записей не было), `after_set 1001025` (замещающая ячейка после
ненулевой ссылки), `after_null 1001025` (та же готовая форма после typed null), `seen 7` (значение до null).

**Прогон.** Первый запуск — частная копия программы с заглушкой ожидания, комплект `coder-c99x`: все три маршрута
печатают одинаковый AFTER (`cce21545…`) ровно с этими значениями; этот блок и стал ожиданием. Затем строка из
репозитория: `exit 0`, `interp=PASS native=PASS forced=PASS`, AFTER трёх режимов равны (`CF/d4-01/rows02`).
Прежняя фикстура на том же комплекте: `FAIL` в трёх режимах, AFTER `75d17c25…` (`CF/d4-01/rows01`).

**Соседние строки.** 22 строки — все фикстуры `tests/graph` с `typeof` и семейства `uninit_reference*`,
`checks_pointer_nulled*`, `deferred_reference_*`, `physical_reference_*`, `deferred_numeric_type_refused` — на
комплекте `coder-c99x` (`CF/d4-01/d4-rows.tsv`): изменилась только строка д4; остальные 21 отвечают как широкая
проверка на G2 (код выхода, вердикты режимов, AFTER). Красные остались красными с теми же ответами:
`uninit_reference_merge`, `uninit_reference_places` (M13/M14), `received_structure_values`, `struct_index`, `typeof`,
`deferred_reference_head_refused` и `deferred_reference_read_refused` (интерпретатор).

**Расписки.** Строка была зелёной с прежним ожиданием (`early 1001028`) на комплектах acc275 — расширенные списки
свидетелей вплоть до 2026-11-23 (`steps/witnesses/declaration-arguments-20261123/witness-rows.tsv:113`,
`kernel-types-context-20261123`, `declaration-form-name-not-looked-up-20261123`: `0 1 0`, PASS в трёх режимах). План
29.3 записывает, что раньше присваивание меняло внутреннюю ячейку, сохраняя обёртку, а запись по пути теперь заменяет
фрагмент; с этим изменением прежнее ожидание перестало проходить, фикстура не была пересмотрена.

**Docs check.** Python-проверка и L2-проверка (индекс 295) на этом дереве красны только по правилу control-байтов —
145 находок в 70 сторонних исходниках нового пакета автора `third_party/lmx_c99_compact` (коммиты `443350e0e`,
`538c7511d`); к этому срезу отношения не имеет, решение Sol — `CODER-THIRDPARTY-COMPACT-20261125-02-ASTRA-ANSWER`
(исключение по паре путь + байт, отдельный срез инструмента).
