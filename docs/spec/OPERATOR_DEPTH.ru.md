# Depth операции: один внешний обход

Общий модификатор `.(expression)op` передаёт **depth**, не rank ячейки. Положительное d проходит d внешних логических осей. **Явный ноль означает максимальную глубину.** Rank Array остаётся числом его осей, а `math\linear\rank` — математической операцией. [Полный нормативный договор](TENSOR_EXPRESSIONS.md#operator-depth).

<a id="syntax"></a>
## 1. Синтаксис и default

| Форма | Смысл |
| --- | --- |
| `A + B` | Default обычной арифметики: максимальный поэлементный обход |
| `A .(0)+ B` | Явная максимальная глубина |
| `A .(1)op B` | Пройти одну внешнюю ось, передать оставшиеся ячейки базовому handler op |
| `A .(d)op B` | Получить неотрицательное целое из обычного выражения d |
| `.(d)method(A; B)` | Тот же префиксный модификатор перед именем метода |
| `A [*] B` | Целостный/индексный договор произведения без внешнего модификатора |

Общих сокращений `.op`, `..op`, `...op` нет. `.:` — отдельное присваивание срезу с транслированием, не depth-one `:=`; `.(d):` не является алиасом присваивания. Суффиксный вариант `method.(d)(...)` не вводится.

Точка непосредственно перед `(` начинает этот модификатор, не дробную часть числа. Внутреннее выражение использует общий парсер и сохраняет исходный контекст. Строки, комментарии и точные имена в кавычках защищают содержимое. Границы записи определяет [грамматика bracket-subparser](BRACKET_SUBPARSER.ru.md). Документация не объявляет production-приёмку парсером/транслятором/runtime выполненной.

<a id="abi"></a>
## 2. Присутствие и общий транспорт

Служебный параметр имеет объявленный тип int. Правила обхода этой главы принадлежат **стандартным Map-профилям**. Custom handler может трактовать depth иначе; пока он не выбрал общий Map, проверки неотрицательности, depth>K и frame не навязываются глобально. В частности, такому custom-методу может передаваться отрицательный int. Произвольный не-int аргумент этим уточнением не разрешается.

Подготовленные actual сохраняют порядок **left, depth, right**:

```lmx
ExpressionActuals:
    @: left
    int: depth
    []@: right
```

Это DATA-фрагмент транспорта, не полный шаблон операнда. Отсутствие left и depth сохраняется. Неинициализированное число не читается, универсальный default-ноль не подставляется, отдельный depthPresent и числовой маркер отсутствия не вводятся. Присутствие принадлежит actual подготовленного вхождения; чужое динамическое поле depth не создаёт написанный модификатор.

Явное выражение depth получается один раз по востребованности в исходном контексте. Сам метод может использовать динамические данные для своего default. Для обычной арифметики default — максимальная поэлементность. Для whole `[op]`, редуктора или DATA/TYPE/RAW отсутствие сохраняет default этого ресивера. **Отсутствие и явный ноль различаются:** `A [*] B` получает целые матрицы; `A .(0)[*] B` выбирает скалярные ячейки, которые базовый product-handler должен отдельно допускать, иначе применение ошибочно.

Общий шаблон операнда сохраняет PASS_ARGS_AS_IS и PRIORITY. Поиск кандидатов изучает роли и готовый приоритет без вычисления depth и callbacks. Обычных положений по-прежнему два: отсутствие left либо один левый атом. Ни группировка, ни связывание не переносят right[0] в left; эквивалентность поддержанных префиксной/инфиксной форм реализует сам операнд.

```lmx
DepthProbe:
    @: left
    int: depth
    []@: right
    const: int: PASS_ARGS_AS_IS 1
    const: int: PRIORITY sys\priority("+")
    required: depth
    return: int
    read:
        return: depth

@: myOperator DepthProbe\read
int: observed 10 .(1 + 1)myOperator 20
```

Служебный actual равен 2. Исходные скаляры не имеют недостающих Array-осей для диагностики. Пользовательский метод читает actual по своей объявленной роли; не любой операнд принудительно превращается в eager VALUE map. Пример нормативный, production-исполнение **NOT_RUN**.

<a id="receiver"></a>
## 3. Ресиверная форма и точные имена

```lmx
@: values `*`(A; B; depth := 0)
@: rowProducts `[*]`(A; B; depth := 1)
```

Ресивер использует ключ фактически объявленного метода и тот же именованный depth. В листинге ключи включают внешние обратные кавычки. Голые операции `*` и `[*]` имеют свои ключи. Ссылки, зависевшие от прежнего совпадения имён, мигрируют по [договору](LMX_semantics.ru.md#field-name-keys). Второй пример передаёт соответствующие строки двумерных A и B. Это объявленный интерфейс логических аргументов, не позиционный вызов трёх полей транспорта. Метод, непосредственно публикующий транспорт, именует left/depth/right.

Обратные кавычки сохраняют точный идентификатор. Декорация не становится частью стандартного callable-имени, кавычки не декодируют его. Старых dotted-алиасов нет. Ошибки копируются из реально выбранных базовых методов. Служебный depth обёртки и одноимённый собственный аргумент чужой функции имеют разных владельцев; общего перехвата всех depth нет.

<a id="evaluation"></a>
## 4. Один обход, затем выбранное базовое тело

Для перебираемого Array ранга K положительное d требует d≤K. Первые d осей составляют frame, последние K−d — ячейку. Явный ноль выбирает все K осей. В отличие от прежнего предложения cell-rank, d>K — ошибка, не clipping.

| Форма | depth | Ячейка | Frame |
| --- | ---: | --- | --- |
| `(2,3,4)` | 0 — максимум | Один элемент | `(2,3,4)` |
| `(2,3,4)` | 1 | `(3,4)` | `(2)` |
| `(2,3,4)` | 2 | `(4)` | `(2,3)` |
| `(2,3,4)` | 3 | Один элемент | `(2,3,4)` |
| `(2,3,4)` | 4 | Диагностика | — |

После выбора ячейки механизм вызывает **базовый handler без повторного входа в ту же автоматическую Map-обвязку**. Иначе рекурсивный Map стирал бы depth. Неподдержанные оставшиеся Array-входы дают обычную ошибку допуска, а не скрытый дальнейший спуск. Явно написанные операции внутри пользовательского тела сохраняют нормальные договоры.

```lmx
[2][2]int: A [1 2; 3 4]
[2][2]int: B [5 6; 7 8]
@: cells A * B
# [5 12; 21 32]
@: sameCells A .(0)* B
# [5 12; 21 32]
@: explicitCells A .(2)* B
# [5 12; 21 32]
@: rows A .(1)[*] B
# [17 53]
@: product A [*] B
# [19 22; 43 50]
```

Здесь `A .(1)* B` не превращается скрыто в row-dot или повторный автоматический scalar Map: базовому скалярному `*` нужен отдельный допуск Array-ячеек, иначе они диагностируются. `A .(3)* B` ошибочно: входы имеют две оси. Для трёхмерного пакета depth=1 передаёт матричные ячейки whole-методу. Внутренние оси `.(d)[op ...]` относятся к оставшейся ячейке, не к снятым осям frame.

Frame перебираемых Array совпадают точно. Формы ячеек могут различаться при допуске handler. Исходные скаляры не добавляют осей и могут повторяться. `$x` или `$(expression)` удерживает actual целиком для этого обхода, получая его один раз по востребованности без копирования. Для Z `(rows,cols)` и bias `(cols)` запись `Z .(1)rowAdd $bias` передаёт строку и весь bias. Объявленный rowAdd может явно использовать обычный `+` в теле; обвязка скрытого внутреннего Map не добавляет. Явный ноль передал бы элемент Z и весь bias, никогда не скрытый bias[j].

Пустой кортеж frame означает один вызов. Нулевая длина frame — ноль вызовов. Договор результата и пустая сборка объявлены, не угадываются пробным вызовом. Нужные размеры берутся из actual-типа и проверенного контекста доступа. Забытые строки инициализатора не восстанавливаются. Ячейки используют тот же flat backing и временный parent-контекст; escape требует удержанного контекста или материализации.

Structure `[]@` участвует с actual-типизированными записями. Ссылки не придумывают тензорные оси, `struct[i]\[j]` сохраняет путь. Неподдержанное действие диагностируется по элементам, не исключением класса контейнера.

<a id="assignment"></a>
## 5. Особые роли и запись

Обычное `:=` поэлементно, требует точных Array-форм и допускает скалярное заполнение по своему договору. `.:` транслирует RHS до выбранного среза. Явно поддержанное `.(d):=` выбирает реальные места одним внешним обходом и вызывает базовый PLACE-договор; строка не становится фиктивным pointer-слотом.

Назначение получается один раз. Все нужные значения RHS до записи и допуски назначения устанавливаются перед stores, включая перекрывающиеся перестановки:

```lmx
int: a 1
int: b 2
int: c 3
(a b c) := (b c a)
```

Готовый Array назначения сохраняет длину, форму и идентичность. Объявленные ссылочные места сохраняют отдельный допуск присваивания ссылки. Составные/приклеенные обновления используют базовую арифметику и общий writer. Имена prefix/postfix остаются `++var`, `var++`, `--var`, `var--`; новых точных имён декорация не создаёт. DATA/TYPE/RAW/NAME/PLACE и void сохраняют объявленные роли.

Начальный fuse получает новый окончательный результат перед внешним присваиванием, не выбирая скрытую потоковую запись. Неверный depth, недостаток нужных осей, несовместимый frame или неподдержанный метод диагностируются транслятором/интерпретатором. Обычные отказы depth-выражений и методов сохраняют throws.
