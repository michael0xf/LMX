## Продолжение Codex: повторный обход и запись кода (graph06/tool09/rt05)

Исправлен дефект: вычисляемое объявление заменялось значением через конструкторный lmx_graph_put, оставляя native,
который по-прежнему содержал исчезнувший инициализатор. Построение теперь использует raw put, публикация вычисляемого
объявления — lmx_graph_publish и общий runtime lmx_graph_write_slot. Имя результата берётся адресом канонической
строки из самого объявления, без повторного интернирования; регистрация не переименовывает именованный адрес молча.

Перед записью строится временная карта достижимых Lmx от переданной области и её parent-связей. По самим операторам
ищутся физические места изменяемого кода; список затронутых native готовится целиком до снятия входов и записи.
Карты освобождаются в этом же обходе. Обычное значение x, читаемое через слово x, не является самим оператором;
запись сохраняет вход. Литерал, физически общий с местом в другой Structure данных, остаётся кодом: запись через этот
алиас снимает входы, содержащие литерал. Первое присваивание uninit:int пишет в прежнюю ячейку T и меняет указатель
своего поля; обычная запись данных сохраняет native и в этом случае.

lmx_graph_call выбирает текущий native через существующий nullary call, иначе вызывает чистый обходчик с новой
служебной активацией, освобождаемой на выходе. Это пока граница плоского среза, не полный dispatch fn/data/Message.
Выпущенное тело использует фактически переданный lmx_call_code, не глобальную переменную программного корня.
В emit-check отдельный тестовый R0 держит ссылку на программный корень: снятие его native не удаляет адаптер и
не меняет lexical parent программы. Обычный emit автоматического Message.success не получает.
run FILE [COUNT] и emit-check FILE OUT native|forced [COUNT] вызывают один текущий граф повторно;
graph-check ... EXPECTED [EXPECTED-EXIT=0|1] [COUNT] сравнивает окончательное содержимое.
