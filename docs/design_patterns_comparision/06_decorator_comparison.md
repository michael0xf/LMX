# 06. Decorator: сравнение исходников LMX и семи других языков

20 ноября 2026 года · Архитектурная редакция · Один сценарий, восемь реализаций

## Задача и границы примера

Базовая операция удваивает аргумент. Первая обёртка вызывает базовую и добавляет `1`; вторая вызывает первую и умножает результат на `3`. Выбранная внешняя операция получает `10` и возвращает `(10 × 2 + 1) × 3 = 63`.

Сохранены три отдельно выбираемых метода, цепочка делегирования и типизированная ссылка на внешний метод. В LMX все три метода имеют одинаковые вход и результат, поэтому пользуются общим DATA `Transforms`. Каждая активация получает своё значение аргумента.

Показана фиксированная цепочка функциональных декораторов. Динамическое построение цепочек произвольной длины и отдельная иерархия Component в объём этого сценария не входят.

**Ожидаемый результат демонстрации: `63`.**

Во всех LMX-листингах применяется новое правило: пустая строка завершает синтаксический блок до виртуального уровня `−1`; внутри незавершённого корневого блока она не используется для оформления. Последний блок закрывается на EOF. `node\` означает явное лексическое связывание. `import` вводит корневые const-объявления, включая пользовательские структуры; переменные и parent методов он не переносит.

Основание: [согласованные правила связывания и fn](https://chatgpt.com/library?file_id=libfile_fde3_f-a38201c30fb88191b7207c0e48955c30_bbe92b09b62881918d17958175103ded&account_id=personal), [объявления-аргументы и import](https://chatgpt.com/library?file_id=libfile_fde3_f-02443abbc4508191b7c8fd7894e3ac24_bbe92b09b62881918d17958175103ded&account_id=personal), [пустая строка как полная граница](https://chatgpt.com/library?file_id=libfile_fde3_f-9d15a59bc5d881918724924fcef45b04_bbe92b09b62881918d17958175103ded&account_id=personal) и последнее авторское уточнение лексического `node\`. Сетевые образцы служат ориентирами по ролям шаблонов; их код адаптирован к этому сценарию.

## Как считались символы

Главная величина — **число непробельных символов** в показанном блоке исходника: все символы, для которых Python `str.isspace()` возвращает false. Пробелы, табуляции и переводы строк не учитываются. Это счётчик, а не преобразование кода в исполняемый минифицированный вариант; пробельные символы внутри строк также не считаются.

Дополнительно показаны полный размер в символах Unicode и число физических строк. Для полного размера используется LF, без начальных и конечных пустых строк и с одним LF в конце. Здесь все исходники ASCII, поэтому при UTF-8 число байтов совпадает с полным числом символов.

Считаются объявления, импорты, обязательные классы-оболочки или `package`, вспомогательные функции и весь демонстрационный сценарий внутри `demo` / `Demo` / LMX `run`. Внешний запуск, `main`, печать результата, тестовый harness, Markdown и пояснения не входят. Реализация стандартной библиотеки и runtime не входит ни для одного языка. В измеряемом коде нет комментариев.

Обычные функции, замыкания и стандартные типы callable разрешены. Python приведён без необязательных аннотаций типов; это не равенство статических гарантий с LMX или другими типизированными вариантами. Имена и учебная разбивка не нормализованы: числа описывают эти конкретные листинги, а не минимально возможную длину программы на языке.

| Язык | Непробельных символов | Всего символов | Строк | К размеру LMX |

| LMX | 225 | 338 | 18 | 1.00× |
| Python | 159 | 210 | 15 | 0.71× |
| Java | 295 | 419 | 20 | 1.31× |
| C++ | 209 | 275 | 18 | 0.93× |
| C# | 248 | 390 | 25 | 1.10× |

## 1. LMX

```lmx
Transforms:
    int: value
    return: int
    base:
        return: value * 2
    withOne:
        return: base() + 1
    withThree:
        return: withOne() * 3

fn: TransformSignature Transforms

Demo:
    return: int
    run:
        import: Transforms
        @: transform TransformSignature withThree
        return: transform(10)
```

Внешний вызов: `Demo\run()`. Он не входит в подсчёт.

Общий DATA содержит `int: value` и `return: int`. Это общий шаблон входа, но у каждого вызова своё место `value`.

`transform(10)` выбирает `withThree`. Вызов `withOne()` получает копию его `value` через одношаговый autofill; `base()` тем же правилом получает свою копию от `withOne`. Результаты проходят цепочку `20 → 21 → 63`. Это не транзитивный alias и не общий изменяемый аргумент всех звеньев.

`fn: TransformSignature Transforms` выводит сигнатуру из того же DATA. Публичное имя её входа теперь `value` вместо прежнего `x`; показанный вызов позиционный. Типовое требование `int → int` сохранено. Подстановка `base` или `withOne` в `transform` дала бы соответственно `20` или `21`.

`import` вводит три константных имени методов, не импортируя переменную `value` и не меняя данные методов.

## 2. Python

```python
def base(value):
    return value * 2


def with_one(value):
    return base(value) + 1


def with_three(value):
    return with_one(value) * 3


def demo():
    transform = with_three
    return transform(10)
```

Внешний вызов: `demo()`.

Каждая функция имеет одинаковую форму вызова и добавляет действие после делегирования. Синтаксический @decorator Python здесь не требуется; статических аннотаций нет.

## 3. Java

```java
import java.util.function.IntUnaryOperator;

class Example {
    static int base(int value) {
        return value * 2;
    }

    static int withOne(int value) {
        return base(value) + 1;
    }

    static int withThree(int value) {
        return withOne(value) * 3;
    }

    public static int demo() {
        IntUnaryOperator transform = Example::withThree;
        return transform.applyAsInt(10);
    }
}
```

Внешний вызов: `Example.demo()`.

IntUnaryOperator позволяет выбрать любое звено без отдельной иерархии классов. Внутренняя цепочка фиксирована, как и в LMX.

## 4. C++

```cpp
using Transform = int (*)(int);

int base(int value) {
    return value * 2;
}

int withOne(int value) {
    return base(value) + 1;
}

int withThree(int value) {
    return withOne(value) * 3;
}

int demo() {
    Transform transform = withThree;
    return transform(10);
}
```

Внешний вызов: `demo()`.

Захватываемого состояния нет, поэтому используется обычный указатель на функцию без std::function и дополнительных объектов.

## 5. C#

```csharp
using System;

static class Example
{
    static int Base(int value)
    {
        return value * 2;
    }

    static int WithOne(int value)
    {
        return Base(value) + 1;
    }

    static int WithThree(int value)
    {
        return WithOne(value) * 3;
    }

    public static int Demo()
    {
        Func<int, int> transform = WithThree;
        return transform(10);
    }
}
```

Внешний вызов: `Example.Demo()`.

Все звенья подходят к стандартному Func<int, int>; делегат в клиенте может ссылаться на базовую операцию или любую обёртку.

## 6. TypeScript

```typescript
type Transform = (value: number) => number;

function base(value: number): number {
    return value * 2;
}

function withOne(value: number): number {
    return base(value) + 1;
}

function withThree(value: number): number {
    return withOne(value) * 3;
}

function demo(): number {
    const transform: Transform = withThree;
    return transform(10);
}
```

Внешний вызов: `demo()`.

Функциональный тип служит общим интерфейсом. Метапрограммные decorators TypeScript не используются: это другой механизм, который для данной задачи не нужен.

## 7. Go

```go
package main

type Transform func(int) int

func base(value int) int {
    return value * 2
}

func withOne(value int) int {
    return base(value) + 1
}

func withThree(value int) int {
    return withOne(value) * 3
}

func demo() int {
    var transform Transform = withThree
    return transform(10)
}
```

Внешний вызов: `demo()`.

Именованный тип функции задаёт общий интерфейс всех звеньев; методы и структурные интерфейсы для этого небольшого примера не нужны.

## 8. Rust

```rust
type Transform = fn(i32) -> i32;

fn base(value: i32) -> i32 {
    value * 2
}

fn with_one(value: i32) -> i32 {
    base(value) + 1
}

fn with_three(value: i32) -> i32 {
    with_one(value) * 3
}

pub fn demo() -> i32 {
    let transform: Transform = with_three;
    transform(10)
}
```

Внешний вызов: `demo()`.

Одинаковый тип fn(i32) -> i32 сохраняет заменяемость звеньев. Здесь не требуются trait-объекты, владение или захват окружения.

## Изменения редакции

Три DATA-контейнера сведены в один Transforms. Между звеньями используется прямое автодозаполнение общего имени входа; сигнатура извлекается из готового DATA. Цепочка вызовов сохранена.

LMX: **352 → 225 непробельных символов**. Это размер показанных исходников; снижение включает организацию кода, написание имён и новые правила завершения блоков. Оно не является измерением скорости исполнения.

Семь иностранных листингов сохранены; их абсолютные размеры прежние, отношения к LMX пересчитаны.

## Проверка и воспроизводимость

LMX проверен чтением по согласованной модели: область каждого объявления, источник связывания, число явных входов fn, роль import и синтаксические границы. Ядро LMX в этой среде не запускалось; числовой результат указан как ожидаемый.

Python, Java, C++ и TypeScript побайтово совпадают с ранее проверенными листингами; сохранён результат двух запусков `63` и `63`. Повторное исполнение неизменённого кода не проводилось. Для Java использовался OpenJDK 21, для C++ — C++17, для TypeScript — Node.js 24 с удалением типов без отдельного `tsc --strict`. C#, Go и Rust остаются проверенными статически.

Таблица размеров пересчитана непосредственно из восьми блоков исходника. Внешние проверочные программы не входят в измерение.
