# Что отвечает сравнение с `nil` после присваивания в место, объявленное без значения

Дата: 2026-11-17. Задаёт исполнитель (сессия fable_pc). Статус: **OPEN**.

Две записи нормы расходятся в одном наблюдаемом месте.

- Решение 2026-11-08 ([журнал](../../2026-11-08.md#uninit-pointer-preserved)): «Сделайте тип "int без инициализации"
  указателем  на ту самую ячейку …, при этом даже отпадает необходимость менять тип при первом пирсваивании»;
  [L2 §3](../../../docs/L2_spec_ru.md#value-record): «`uninit:T` описывает форму объявления без начального значения, а не
  признак „ещё ни разу не записано“».
- Решение 2026-11-17 ([журнал](../../2026-11-17.md#typed-nil)): `nil` — «но это значение»; «мы можем переменную
  сравнить с nil». Книга о `required` (редакторская фраза, не слова автора): он проверяет «наличие значения,
  заданного объявлением, поданным actual или присваиванием».

## Минимальная программа

```lmx
fn: f (int: a) int
    if: a = nil
        a := 5
    if: a = nil
        return: 1
    return: a
```

`f(7)` в обоих вариантах возвращает 7. Различается `f()`.

- **А.** `f()` возвращает 5. Присваивание даёт месту значение, и оно перестаёт быть `nil`: `required: a` после
  `a := 5` проходит, вывод печатает `int: a 5`. Тогда при первой записи тип места меняется с «int без инициализации»
  на `int`; адрес ячейки и взятый раньше `@a` остаются прежними.
- **Б.** `f()` возвращает 1. Тип места при присваивании не меняется, как записано 2026-11-08: `a = nil` и
  `required: a` отвечают о форме объявления и о подаче аргумента, а не о присваиваниях; вывод печатает `int: a`,
  записанное 5 в текст не попадает.

Сегодня реализовано Б: тип не меняется. `required` и `nil` ещё не реализованы.

Предложение исполнителя: А — раз `nil` значение, присваивание другого значения его заменяет. Цена — одна
дополнительная запись кода типа при присваивании в место графа.
