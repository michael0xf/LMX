# Q19. Исполнение именованной Structure: какой Frame закрывает `return`-trailer, и перезапускаются ли объявления полей

Состояние: 2026-09-24. **Q19.1 отвечен** («любая структура не закрывается return. Закрываться return может только callable-структура (любая), без аргументов если нет возвращаемого значения»; уточнение: «любая — это включая тип "именованная структура" (сегодня добавленный как callable)» — дословно в `LMX_blog/2026-09-24.md`): `return` закрывает любую callable-Structure — `fn`/`sub`/`fm` **и обычную именованную Structure**; голый `return` — без результата. Это чтение **А**; остаётся уточнение Q19.3 ниже (управляющие головы). **Q19.2 отвечен: 2** — тело целиком, как у метода; путь `Counter\n` — чтение опубликованной ячейки поля, не объявление и не исполнение `Counter`, даже если `Counter` — метод (измерено на `f0837c7`: вызовов не эмитируется). **Поправка автора к примеру:** в именованной (не-`fn`) callable-Structure `return: n` недопустим — она значения не возвращает; допустим только голый `return`, в теле и как trailer; `return: value` — только у `fn`. Пример ниже читать с `return` без аргумента и `return: Counter\n` как чтение поля из E. **Q19.3 ОТКРЫТ — см. раздел Q19.3 ниже (перед «Что уже измерено»).** Два вопроса из read-only аудита Opus (`FABLE-OPUS-NAMED-STRUCT-AUDIT-20260923-138`, база `717a325`, 23 минимальные программы, два парсера-мутанта) по вашей норме от 2026-09-23 (книга §10/§12/§13; план §3 «Исполнение именованной Structure и контракт получателя»). ## Q19.1 — какой Frame закрывает terminal `return`

Норма (ваша, через Codex): «На уровне открытия `return` может также закрывать именованную Structure как trailer по общему правилу» — включая обычную именованную Structure без `fn`/`sub`.

Сегодня в P0 (`l1src/parser.lm1` :637–:659, четыре копии + три C-зеркала): trailer-строка закрывает предыдущий соседний Frame в своей колонке; `end:`, `until:`, `---` закрывают любой незаполненный Frame/Structure; **`return` закрывает только Frame с текстом головы `fn`** — это жёстко зашитое имя за мёртвым реестром (`lm_p0_registry_*` — шесть заглушек, всегда 0). Измерено: `fn` — соответствует; `sub` с голым `return` в колонке 0 — `return` остаётся элементом единицы (отказ «unsupported body»); `fm` — транслятор не знает головы `fm` вовсе; обычная `S:` + тело + `return: 9` — отказ, транслятор признаёт именованную Structure только с `end: S`.

Трудность: **у P0 нет имён**. Он видит только текст головы и форму. Дерево обычной именованной Structure `S:` / `    size_t: v 4U` / `return: 9` **совпадает по форме** с вертикальной записью присваивания/вызова:

```
ping:
    7
return: 0
```

Сегодня это `ping: 7` (вертикальная форма) и `return: 0` — возврат E (фикстура `unit_universal_absent_vertical.lm2`). По норме «return закрывает обычную именованную Structure» тот же текст — определение Structure `ping` с телом `7` и возвратом `0`, а у E возврата нет.

Измерено двумя парсерами-мутантами (изменившиеся деревья относительно `717a325`):
- **«return закрывает любой незаполненный Frame»** (таблица снята): меняются 342/501 фикстур, 35/118 L1-источников (включая `l2trans.lm1` и `parser.lm1`), 61/86 других L2-источников; `if: m = 0` / `    return: 1` / `return: 0` делает возврат E trailer'ом `if`; `x: 5` / `return: x` — trailer'ом присваивания. **Исключено.**
- **«return закрывает fn/sub/fm или `Name:`-Frame без inline-хвоста с вертикальным телом»**: меняются 2/501 фикстур, 1/118 L1, 1/86 L2 — `else:` перехватывает `return` в 9 местах (`parser.lm1` ×7, `parser_alloc_port.lm2`, `unit_own_dirty_rhs.lm2`), вертикальная `ping:` / `7` — один раз; `if:` и присваивания не затронуты.

- **А — по форме:** `return` закрывает Frame определения (`fn`/`sub`/`fm` — явная грамматическая таблица) **или** `Name:`-Frame без inline-хвоста с вертикальным телом, **кроме управляющих голов** (`else:` — явная таблица исключений). Цена: вертикальная запись вызова/присваивания, за которой в той же колонке идёт `return`, требует резака `---`; программа выше меняет смысл (1 фикстура); нужна таблица исключений для `else`.
- **Б — только определения:** `return` закрывает только `fn`/`sub`/`fm` (явная таблица). Обычная именованная Structure закрывается `end: S` или `---`; её `return:` — оператор внутри тела, не trailer. Тогда слова нормы «включая обычную Structure» — не правило P0-trailer, а правило исполнения (`return:` внутри тела работает как в методе). Деревья не меняются.

Оба варианта заменяют скрытый fallback «fn» явной таблицей и удаляют мёртвый реестр. Рекомендация: **Б** — P0 остаётся без имён и без таблицы исключений для управляющих голов; обычная Structure закрывается как сегодня.

## Q19.2 — перезапускает ли исполнение обычной именованной Structure объявления её полей

```
Counter:
    size_t: n 0U
    n: n + 1U
return: n

Counter
Counter
return: Counter\n
```

- **1 — поля = построение:** объявления полей выполняются при построении (по норме «построение не исполняет тело»), исполнение голым `Counter` выполняет только операторы. Результат **2**; `Counter` — объект с состоянием.
- **2 — тело целиком, как у метода:** исполнение выполняет всё тело; `size_t: n 0U` — оператор на своём месте (как объявление локала в `fn`, которое выполняется в каждой активации и пишет каноническую ячейку). Результат **1**. *(Поправка автора: состояние тела **публикуется в граф** после исполнения (dirty load, checkpoint) и читается путём `Counter\n` без исполнения; «не сохраняется» было ошибкой — при следующем исполнении объявление как оператор тела заново инициализирует ячейку.)*

Принято: **2** (автор). Единообразие: тела `fn`/`sub`/именованной Structure исполняются одним механизмом, объявление — оператор на своём месте; последнее состояние публикуется в граф и читается путём без исполнения. Если вам нужен `Counter`-объект с состоянием — это вариант 1, и тогда нужна граница «поля vs операторы» в теле, которой в грамматике сейчас нет.

## Q19.3 — ОТКРЫТ: управляющие головы (`else:` и др.) при `return`-trailer в P0

У P0 нет имён: `Name:` + вертикальное тело без inline-хвоста — одна и та же форма для определения именованной Structure (`S:` / `    size_t: v 4U`), для вертикального вызова/присваивания (`ping:` / `    7`) и для управляющей головы `else:` (`if: c` имеет inline-хвост `c` и не затрагивается). По правилу «`return` закрывает любую callable-Structure» P0 обязан присоединять `return` в той же колонке к любому такому `Name:`-Frame. Измерено (мутант R-shape): меняются 9 мест с `else:` в наших исходниках (`parser.lm1` ×7, `parser_alloc_port.lm2`, `unit_own_dirty_rhs.lm2`) — `return` после `else:`-блока в той же колонке станет trailer'ом `else`, а не следующим оператором — и 1 фикстура с вертикальным вызовом.

```
if: c
    r: 1
else:
    r: 2
return: r
```

- **А1 — таблица управляющих голов в P0:** `if`/`else`/`while`/`for`/`until`… — слова языка, не имена; `return` их не закрывает (явная грамматическая таблица, как таблица callable-голов `fn`/`sub`/`fm`). Программа выше не меняется. Вертикальный вызов перед `return` в той же колонке всё равно требует `---` (1 фикстура).
- **А2 — без таблицы:** P0 закрывает любой `Name:`-Frame с вертикальным телом; 9 мест с `else:` и 1 фикстура переписываются (`---` перед `return` или перенос `return`).

Рекомендация: **А1** — управляющие головы уже слова языка для транслятора; `return` после `else:` в той же колонке всегда означает следующий оператор.

Ответить можно строкой `Q19.3 А1` или `Q19.3 А2`.

## Что уже измерено и делается без вашего ответа (для сведения)

- Голый атом-оператор (`m`, `s`, `2`, `y`, `S`) **роняет транслятор** (segfault в `l2_check_body` :13592, чтение `frame\head` у атома) — исправляется: fn/sub → нульарный вызов, литерал/поле/формал → discard, обычная Structure → located-отказ до Q19.2.
- Контракт получателя: имя метода в позиции значения (`g(m)`) сегодня передаёт **ссылку на вхождение как int** (entry −1287876288 вместо 7); `sub` в позиции значения — то же (указатель как int); trailer `return: m` — ссылка как int, тогда как `return: m` в теле вызывает; `return: s` (sub) ломает эмиссию (столбец 0). Исправляется: результатный callable исполняется, `sub` в позиции значения — отказ, trailer = путь тела.
- В ядре нет бита «callable с результатом» (`LmxMethod {addr, sig}`, `LmxCallable {method, header}`, `lmx_call_ready` отвечает только «callable ли») — walker RET активирует любой callable, для `sub` норма требует ссылку. Отдельный коммит после -134 (Grok, ядро).
- Именованная Structure не принимает поле `int:` (только size_t/char/вложенные/массивы) и не принимает исполняемые операторы в теле («a Structure reference field needs a name») — раскрывается после Q19.2.
- L3/walker: голый callable-оператор молча «OK» — станет исполнением или явным unsupported.
