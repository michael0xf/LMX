# Q28 (fable_next §7 Q14). Запись в связанный формал внутри вложенного тела: норма или дефект?

Поставлен fable 2026-09-25, REVIEW 3f68f41 п.1 (`steps/review-log.md`); свидетель — `dev/l2src_sandbox/tests/unit_walk_nested_own.lm2` (T4b класс 3, Grok, main `3f68f41`). Ответ Grok: ANSWER 3f68f41-1 — новых строк на это поведение не ставит, ждёт решения автора.

## Факт (измерен нативно и под `--walk-methods`, Entry 7)

```text
fn: keep (int: n) int
    int: n
    if: 1
        n: n + 1
    return: n
```

`keep(3)` даёт **3**, не 4.

Что делает транслятор (`l2_collect_asgn`, нативный путь; walk класса 3 повторяет его):

1. `int: n` на уровне метода переносит аргумент в own-поле метода `n` (правило связывания формала: первая запись связывает).
2. `n: n + 1` внутри тела `if` заводит **новое** own-поле `n` у Structure этого тела (запись в формал внутри вложенного тела считается связыванием поля этого тела), пишет 4 туда.
3. `return: n` после `if` читает поле метода — там по-прежнему 3.

Для сравнения `branch(3)` = 43 в том же свидетеле: `int: n` внутри `if` переносит аргумент в поле тела, после тела имя `n` — снова аргумент (3), а не поле.

## Чего нет

В `docs/L2_spec_ru.md` / `docs/L2_spec_en.md` правила о записи в формал внутри вложенного тела нет: раздел о формалах говорит о первой записи как о связывании, но не говорит, где живёт поле, если первая (или очередная) запись стоит внутри `if`/`while`.

## Вопрос автору

1. **Норма.** Запись в формал внутри вложенного тела связывает поле **этого тела**, и наружу приращение не выходит (`keep(3) = 3`). Тогда — абзац в спеку L2 RU/EN с этим примером, и свидетель остаётся как есть.
2. **Дефект.** Ожидается `keep(3) = 4`: после того как `int: n` связал поле метода, `n: n + 1` в любом вложенном теле пишет в это же поле; новое поле тела заводит только объявление (`int: n`) внутри тела. Тогда — D-79 на оба пути сразу (нативный `l2_collect_asgn` и walk класса 3), свидетель перевернуть на 4.

До ответа: новых строк harness на это поведение не ставить (Grok согласен).
