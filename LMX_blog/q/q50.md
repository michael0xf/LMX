# Q50. Адрес `@p` указательного поля, объявленного в теле метода: ячейка графа или рабочий локал (выходной параметр `printTree`)

Состояние: 2026-09-28, fable_pc по вопросу Opus при коде §7b-1 (рабочее состояние load/cache/dirty). Не решаю сам — два правила расходятся на существующей программе.

## Два положения

1. L2-спека §18.2, таблица «что адресует `@x`», строка «собственное поле графа»: типизированный адрес его ячейки; запись через результат меняет ячейку графа, рабочая копия не присваивается и не помечается `dirty`. Книга §12 и 21.6 автора: после записи через адрес перечитывания нет — голое имя продолжает читать рабочее значение (пример W2: `p: @x`, `\p: 9` — голое `x` 5, явное чтение 9).

2. L2-спека §18.2, строка «машинный адресный слот»: адрес самого слота; запись через результат меняет адрес, хранимый в нём. Абзац рядом: «Адрес локального машинного слота нужен, например, для выходного параметра: `printTree.lm2` … в методе передаёт `@document` в `lm_p0_parse_file`, чтобы функция сохранила указатель на результат. Это адресует переменную-указатель, не документ». Дальше в методе читается голое `document`.

По L2 §10 объявление в теле метода — поле данных метода (own-поле). Указатель `@: LmP0Document document 0`, объявленный в теле, — по (1) own-поле с рабочей копией: `@document` — адрес ячейки графа, `lm_p0_parse_file` пишет в ячейку, а следующее голое чтение `document` видит рабочую копию, загруженную при входе (0), — `printTree` ломается; по (2) — машинный слот: `@document` — сам слот, запись C-функции видна следующему голому чтению.

## Наименьший пример

```text
fn: run () int
    @: LmP0Document document 0
    lm_p0_parse_file(path, @ document)   # c.* пишет указатель через адрес
    return: (document != 0)              # (1): 0 — рабочая копия; (2): 1 — слот
```

## Один вопрос

Указатель, объявленный в теле метода и адресуемый голым `@p`, — это машинный слот (строка 4 таблицы: адрес самого слота, C-запись видна следующему голому чтению; для графа — публикация как у объявленного поля), или own-поле графа (строка 1: адрес ячейки, рабочая копия не перечитывается, и `printTree` должен читать поле явным путём после вызова)? Если слот — тогда же: относится ли это ко всем типам объявлений с `@` в теле (указатели любой глубины) или только к указателям.

До ответа Opus держит в 7b-1 сегодняшнее поведение для указательных полей, адресуемых `@` (без рабочего значения — ячейка), как явно названный открытый пункт, не как исключение модели.
