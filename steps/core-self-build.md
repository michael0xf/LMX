Codex не выполнял полного побайтового аудита этих 963 файлов. На момент проверки перенос, pin и runner ещё не закоммичены в LMX, seed игнорируется Git.

- Codex поддерживает общий план, сверяет доказательства и согласует непересекающиеся задачи. Процессные поручения не добавляются в LMX_blog.

## 1. Перенос как есть

Зафиксировать исходный каталог/revision и полный перечень переносимых единиц, включая необходимые скрипты, тесты, данные и незакоммиченные исходные изменения. Сопоставить пути и хэши перенесённых исходников; отдельно перечислить осознанно не переносимые локальные артефакты. Не совмещать перенос с рефакторингом, переименованием языка или удалением исходного проекта.

Рабочий снимок и публикация — разные действия. Локальные сборки, журналы, PID/LOCK-файлы, кеши, секреты и пользовательские данные не становятся материалом публичного Git только потому, что попали в переносимый каталог. Перед коммитом проверить точные пути; промежуточный seed учитывать явно, а не автоматически коммитить весь `bin/`.

## 2. Зафиксировать, что именно самособирается

DeepSeek должен назвать конкретные единицы ядра и транслятора, начальный seed и команду, на которой цепочка сейчас обрывается. Различать:

1. Сборку старым внешним `l1trans.exe` — это seed-сборка, сама по себе не самосборка.
2. Воспроизводимую сборку ядра из зафиксированных исходников LMX.
3. Самосборку инструмента: полученный из исходников инструмент способен снова построить соответствующий инструмент и ядро из тех же исходников.

Предлагаемый критерий замыкания: явно объявленный seed → stage 1 из исходников LMX → stage 2, построенный инструментами stage 1 → сборка ядра и его проверок новым инструментом. Точный состав стадий и цели подтверждает DeepSeek по реальной архитектуре; не вводить фиктивный «самокомпилятор», если конкретная единица им не является. Внешний C-компилятор и прочие разрешённые зависимости фиксируются отдельно и не скрываются.

## 3. Доказательства приёмки

- Один воспроизводимый запуск из LMX с явными входами/выходами в новом каталоге сборки, без подхвата прошлых артефактов по неявным абсолютным путям.
- Манифест версий и хэшей исходников, seed, промежуточных и итоговых инструментов; фактические команды и коды завершения каждой стадии. Временные результаты — вне отслеживаемых исходников.
- Stage 2 действительно запускается, а не только существует на диске; им выполняется следующая требуемая сборка и проверочный корпус. Прежние тесты сохраняются, отрицательные случаи не переписываются ради успеха.
- Сравнение выходов последовательных стадий: побайтовое для детерминированных артефактов; для недетерминированных бинарных метаданных — явно описанное сравнение содержимого и поведения. Простое совпадение ненулевого размера файлов не является проверкой.
- Все остаточные зависимости от соседнего `L1` и других старых проектов перечислены. Объявленный seed допустимо учитывать отдельно; неявная подмена нового инструмента старым или использование старого готового C делает результат незамкнутым.
- Повторный запуск с нуля в другом новом каталоге даёт тот же проверяемый результат. Не удалять существующие чужие build-каталоги для имитации чистой сборки.

До этих проверок писать точный статус: «перенесено», «seed-сборка», «stage 1», «stage 2», «тесты», «цепочка замкнута». Успех нативных P0 13/13 и 131/131, L3 smoke или одного self-test ядра не доказывает самосборку.

## 4. Независимый аудит Grok Bot

Код задания `LMX-BOOTSTRAP-PRIORITY-20260920-01`. Прочитать фактические скрипты и отчёт DeepSeek; составить таблицу «вход → какой инструмент запущен → выход → следующий потребитель», проверить абсолютные пути/старые бинарники/старый C/неучтённые библиотеки, указать первое доказанное препятствие или недостающее свидетельство. Не запускать одновременно тяжёлую сборку в каталогах DeepSeek и не редактировать его код. Собственный файл `steps/bootstrap-audit.md` проверять и коммитить отдельно; сообщать содержательный результат, не только транспортный ACK.

## Проверка Codex после checkpoint DeepSeek

Срез HEAD `dc608683`, новые файлы DeepSeek в рабочем дереве. После чтения `tools/run_self_build.ps1` выполнен независимый запуск из LMX: `& .\tools\run_self_build.ps1`. Evidence: `build/self_build/20260920_063856_071`. Прошли сборки B0/B1/B2 и три прохода; pass 3 = pass 2 для 8/8 файлов, exit 0, 9 секунд. Предыдущий прогон DeepSeek: `build/self_build/20260920_063614_081`, 8 секунд.

Фактическая цепочка: GCC компилирует локальный C-seed в B0; B0 переводит восемь единиц из `l1src` в pass 1; GCC собирает B1 из pass 1; B1 даёт pass 2; GCC собирает B2 из pass 2; B2 даёт pass 3. Старый внешний `bin/l1trans.exe` в **этом runner** не вызывается. EXE не сравниваются из-за недетерминированных бинарных метаданных; байтово сравниваются результаты pass 2/pass 3. Локальный `bin/l1trans.exe` отдельно соответствует SHA-256 из `L1_PIN.txt`.

### Препятствие публикации: seed ещё не в Git

`git ls-files -- lm1/build tools/run_self_build.ps1 L1_PIN.txt` на момент проверки не вернул файлов. `git check-ignore -v -- lm1/build/l1trans.lm1.c` указывает на правило `build/`. Следовательно, чистый клон LMX пока не содержит нужного seed/runner.

Фраза runner «committed generated C» сейчас технически сильнее его проверки: `Get-SelfBuildBlob` вызывает `git hash-object --path=...` для файлов **рабочего дерева**, а не извлекает blob из HEAD. Это подтверждает равенство нормализованного рабочего seed неподвижной точке, но не наличие тех файлов в коммите. Счётчик `git status ... -uno` также не видит отсутствия в индексе игнорируемого seed.

Владельцу runner направлен через relay запрос `LMX-L1FIXPOINT-AUDIT-20260920-01`: сохранить точный необходимый seed и происхождение в LMX отдельной проверенной партией, не весь build; отличать working-seed от committed-seed и проверять последний по конкретной revision/HEAD. Запись сообщения в relay подтверждена, ответ DeepSeek по этому дополнению ещё ожидается. После публикации повторить проверку из чистого checkout. Не переименовывать локальный PASS в FAIL самосборки L1, но и не объявлять готовность чистого клона преждевременно.

### Следующий функциональный блокер: L2-ядро в LMX

DeepSeek ожидает решения Grok о сборке L2 из плоского `dev/l2src_sandbox`, без переноса чужих исходников в новый подкаталог по умолчанию. `dev/mixa_sandbox/tools/build_mixa.ps1` подтверждает явный fallback `$depsRoot` на `C:/Nyasha_Planet/L1`, когда нет локального kernel build или `lm1/build`. Сейчас C-seed уже появился, но локальная сборка L2 остаётся незавершённой. Более того, общий `$depsRoot` переключает одновременно обе зависимости — это надо учитывать при удалении fallback.

Критерий завершения этой части — не только отсутствие строки NOTE. Gate должен сообщить фактические пути/хэши локальных L2-заголовков, объектов и транслятора и пройти проверки без обращения к старому дереву L1. Потребитель сейчас ищет `dev/l2src_sandbox/build/l2src/<stamp>/headers/l2src`; способ генерации этих файлов согласует владелец Grok с DeepSeek. Граф и расположение исходников не менять лишь для удовлетворения старого сборщика.
