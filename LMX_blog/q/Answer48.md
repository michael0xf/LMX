# Answer48 — разбор модели «код один, merge над данными» как ответа на Q48

Состояние: 2026-09-28, разбор fable_pc по просьбе автора («если ответ — напиши Answer48.md рядом»). Это не решение: вывод делает автор. Ниже — что говорит вставленная модель, отвечает ли она на Q48, и что именно меняется в общих правилах книги (`docs/LMX_semantics.*.md`), если её принять и применить.

## 1. Что говорит модель

Вставка автора (дословно по смыслу): `fn: add (int: x; int: y) int / return: x + y` даёт `code(add)`; `add5: merge(y: 5; add)` не обязан трогать тело; итог:

```text
add:   Code = Cadd    Data = Dadd
add5:  Code = Cadd    Data = merge(Dadd, { y: 5 })
```

«Разница сигнатур тоже может быть частью структурного результата `merge`, но машинное тело остаётся одним».

Прочтение по общим правилам (книга :1024–:1036, §12, §20; блог 2026-09-25 «код — дерево операторов, данные — объявленные поля»): метод — пара из кода и данных, роль задаётся позицией; `merge` — структурная операция над Structure, то есть над **данными**. Значит `merge` метода с данными есть тот же код над слитыми данными, и никакого особого правила для вызываемых у `merge` нет: части `args`, `return`, `body` — обычные Structure данных, а машинное тело (нативная реализация или дерево операторов) не композируется, не копируется и не перенумеровывается. Это ровно общий принцип «никаких специальных конструкций»: вызываемое ничем не отличается от остального.

## 2. Отвечает ли это на Q48

Да. Q48 спрашивал: при `args` модели `[x, y]` и объявленном заголовке `[x]` — рекурсивная композиция сохраняет `y` или заголовок заменяет часть целиком. По модели ответ — **композиция, ничего не заменяется**:

- `args` — данные; общее правило поля: одноимённое поле операнда пишется в слот модели, новое дописывается; `{y: 5}` пишет 5 в слот формала `y` (у формала это его ячейка данных); `y` из `args` не исчезает.
- «Разница сигнатур — часть структурного результата»: интерфейс `add5` отличается от интерфейса `add` не тем, что часть `args` заменена, а тем, что формал `y` **уже имеет значение**: для вызова обязателен только `x`. Фраза «сигнатура `add` пропадает» читается так и только так — «множество обязательных входов уменьшилось на `y`».
- Объявленный заголовок `fn: add5 (int: x) int merge(…)` — не операнд, заменяющий части, а **объявленный тип места**: результат `merge` допускается в это место обычным допуском (`implements`/admission) — «у нас всё конвертируется» и есть допуск, общие ворота, а не особая процедура приведения. Если заголовок всё же считать операндом, его `args = [x]` по тому же правилу поля обновляет слот `x` и не удаляет `y` — итог тот же.

Иллюстрация к D01–D12 предыдущего задания: `add5: 1` — `x = 1`, `y` — ячейка со значением 5 → 6. `y` — формал, не свободное имя: голое `y` вызывающего ему не подаётся; подать другое значение можно только явно (`add5(1; y: 25)` — если формал с значением остаётся передаваемым; см. §5 п. 3). Случай D05–D07 (`x = 10 / 25 / 40`) остаётся для **свободных имён** тела, читающих объемлющую Structure (`merge((n: 5); addN)`, `n` в теле `addN`), — там приоритет §12 действует как записан.

## 3. Что меняется в общих правилах книги, если применить

Формулировки — предложение к правке; сейчас в книге стоят цитируемые ниже фразы.

1. **§20, «Явное описание вызываемого».** Сейчас: «объявленный заголовок переопределяет `args` и `return` (сигнатура `add` пропадает)» и «приводится к нему ещё одним `merge` с методом как моделью: `merge(add; {y: 5}; объявленный заголовок)`». Станет: части `args`/`return`/`body` композируются по общему правилу поля на каждом уровне (это уже написано выше по тексту); формал, получивший значение из операнда, остаётся формалом с ячейкой, и интерфейс результата — обязательные формалы (без значения) плюс свободные входы тела (§7, §8 случай 9); объявленный заголовок — тип места, результат допускается в него обычным допуском; отдельного «второго `merge` с заголовком» и «переопределения `args` и `return`» нет. «`add5: 1` даёт 6» — с пояснением «`y` — ячейка формала со значением 5». Фраза о том, что `y` «остаётся свободным входом с запасным путём» (внесена по прошлому заданию), уходит: `y` — формал, не свободное имя.

2. **§20, «Нативная реализация и копия вызываемого вхождения».** Сейчас: «У результата слово `native` пусто, поэтому он исполняется интерпретатором; операции адресуют поля по слоту `node` и перенумеровываются картой позиций». Станет: результат `merge` с данными исполняет **тот же код**, что и модель — нативную реализацию, если она есть, или то же дерево операторов; перенумерации нет: раскладка модели сохранена (слоты модели первыми, новые поля в конце), поэтому код адресует те же слоты. Это обобщает Q44 (нативная реализация получает узел графа, ссылку на неё можно сохранить) с поля-ссылки на любой результат `merge`. **Внимание:** это меняет чтение, подтверждённое автором 2026-09-25 («да, подтверждаю»: «merge методов допустим, результат интерпретируемый — один дескриптор без нативного адреса, ops по слотам») — при принятии модели то подтверждение относится только к случаю, когда операнд несёт **код** (см. п. 3), а не данные.

3. **§20, «Композиция структурных частей».** «Операторы операнда заменяют операторы модели, если у операнда они есть» (автор 2026-09-25: «тело операнда заменяет тело модели») — остаётся и получает точный смысл в терминах модели: если операнд несёт код (операторы), кодом результата становится код операнда; если операнд — только данные, код результата — код модели. В обоих случаях машинное тело одно, никогда не составное. Нужно сказать явно, что происходит с `native` в первом случае (код операнда — его слово `native`; если у него тела-операторов нет, а есть только нативная реализация — она и есть его код).

4. **§20, «Возвращаемый вложенный метод».** Сейчас: «один такой `merge` с тремя операндами: метод, Structure из реально используемых значений активации, объявленный заголовок». Станет: `Data = merge(D_addN, {n: значение активации})`, `Code = C_addN`; объявленный заголовок результата `fn` — тип места, допуск. «Скрытого окружения замыкания не возникает» — остаётся; «копирование не есть частичное применение» — остаётся (значение легло в ячейку формала по правилу поля, а не «применилось»).

5. **§11 (интерфейсы) и §12 (динамические входы).** Формал с ячейкой, получившей значение через `merge`, — не свободное имя: правило приоритета §12 (локальная привязка вызывающего → унаследованный вход → лексический запасной путь) к нему не применяется; вызывающий меняет его только явной подачей аргумента. Добавить в §11 одно предложение: «формал, у которого есть значение в ячейке, не обязателен для вызова; явная подача заменяет значение». Правило прошлого задания «копирование не связывает аргументы» остаётся верным дословно: `merge` ничего не связывает — он пишет в ячейку поля данных по общему правилу поля, а обязательность формала следует из данных.

6. **§7 и §8 (случай 9), `DynRequired`/`sig`.** Сигнатура результата = формалы без значения + свободные динамические имена тела. «Сигнатура пропадает» нигде не должна означать исчезновение требований тела: `add5` по-прежнему требует всё, что требует тело `add` сверх `x` и `y`.

7. **L2/ядро (не книга L3, но следствие).** Merge вызываемого не создаёт нового дескриптора кода: у результата тот же указатель на метод (child 0, Q20 = Д: «при merge — как разделяемая ссылка на метод»); транслятор сегодня выдаёт для слитого вызываемого интерпретируемый результат с картой позиций (`l2_mad_*`, `l2_t7_*`, «ops по слотам») — при принятии модели это переходная реализация, подлежащая замене на «тот же код над слитыми данными»; нативный вызов слитого метода — вызов той же реализации с `self` = слитые данные. Что при этом делать с формалом, получившим значение, в нативном ABI (аргумент из ячейки, если не подан) — пункт плана, не книги.

## 4. Что не меняется

Раскладка модели и дописывание новых полей в конец (Q21 = А); одна ячейка там, где объявление (Q29); последнее вхождение у неуточнённого имени (Q22.2); исключение вечной ветви `independent: const: immutable`; отсутствие окружения замыкания; приоритет динамических входов для **свободных** имён и явный `node\` путь; правило «копирование не связывает аргументы» (оно становится следствием: `merge` не знает про аргументы, только про поля).
