## Проверка LMX

Сверены актуальные правила Message/Thread, ownership, serial turn, post, HTTP §32, actual parent DATA, node, сохранение source graph и завершение блоков пустой строкой. Новые структуры не названы встроенными типами; библиотечные порты имеют явные обязанности в notes и общем MESSAGE_HTTP_PROFILE.md.

В P54 первоначальный синхронный pull заменён на события `start → post → received → post`: owner завершает текущий turn до входа собственного answer. Это устраняет ожидание события, которое могло бы исполниться только после завершения заблокированного turn.

Синхронный HTTP provider используется только как синхронная transport операция с непосредственным HTTP response. Асинхронный HTTP и post нуждаются в позднем handler turn. Admission acknowledgement не считается результатом бизнес-операции.

Peer review исправил P54 C#: оба Worker запускаются через Task.Run, чтобы заполненный Channel и синхронный process не позволяли первому Worker полностью вычитать очередь до запуска второго.

Независимый узкий review LMX не обнаружил случая, где вычисляемая анонимная группа пересылалась как уже вычисленный DTO. Локальные значения в P58/P71/P90 передаются как ordinary actual в post; подготовка actual предшествует публикации по выбранному контракту.

В P65 явно сохранено отличие последовательного Message от RW-lock с параллельными читателями. P66 не обещает DCL fast path для Message. P69 различает Message-local и OS-thread-local state. P88 различает cooperative cancellation Go, Message close и Erlang shutdown.

## Исполнение и инструменты

LMX runtime/компилятор в поставленном архиве отсутствует; LMX-примеры не исполнялись и parser acceptance не заявляется. Полные буквальные post fixtures в нормативном пакете отсутствуют, поэтому формы ask/answer помечены как авторские применения описанного профиля.

В доступной среде не обнаружены компиляторы Java, Rust, Erlang и .NET. Попытка `go test ./...` не является Go-проверкой: найденный `/usr/bin/go` оказался одноимённым desktop-приложением и отверг опцию test. Успешная компиляция контрольных листингов также не заявляется. Ожидаемые результаты получены разбором алгоритмов и подлежат проверке в соответствующих toolchains.
