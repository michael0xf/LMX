# Q25. `MainLetter: m` … `receiveMessage: m` — что кладётся в поле типа `MainLetter`?

Уточнение после реплики автора («как можно объявить переменную без типа? Такого не бывает у нас»): переменных без типа нет; все три формы приёма типизированы.

1. `receiveMessage: m` — ресивер `receiveMessage` объявляет `m`; тип `m` — письмо, модель обёртки `(sender: @: LmxMsg; payload)`.
2. `receiveMessage: m Model` — то же, `m\payload` типизирован моделью `Model` пользователя; приём выборочный (K1: NO — письмо пропускается).
3. `MainLetter: m` … `receiveMessage: m` — `m` уже объявлен как `MainLetter` (модель пользователя описывает payload); `receiveMessage` присваивает в существующее типизированное поле: берёт **следующее** письмо и допускает его по `MainLetter`; отказ — неявный throw `implements` (правило 2026-09-23, B2 = α; строки `unit_admit_letter_not_model`, `unit_admit_letter_extra_field` пинуют Thrown 2 / Stopped). Так написаны 18 строк harness’а.

Минимальная программа (форма 3):

```text
MainLetter: m
receiveMessage: m
c.puts: m\mainArgs[0]
```

Вопрос — что держит `m` (типа `MainLetter`) после приёма:

- **(i) письмо целиком** `(sender; payload)`: допуск payload’а по `MainLetter`, в `m` кладётся письмо; чтения — `m\payload\mainArgs`, доступен `m\sender`. Минус: поле объявлено как `MainLetter`, а держит не `MainLetter` — объявление пришлось бы читать по-особому только для receive.
- **(ii) payload**: допуск payload’а по `MainLetter`, в `m` кладётся сам payload — поле держит то, что говорит его тип; чтения — `m\mainArgs`, как в фикстурах сегодня; `m\sender` в этой форме недоступен (для ответа — формы 1 и 2, где `m` — письмо). Общее правило без особого случая: **поле держит то, что говорит его объявление** — объявлено обёрткой (формы 1, 2) → письмо; объявлено пользователем как `T` (форма 3) → `T`.

Рекомендация: **(ii)**.

Побочная находка (Opus -178, к.3, измерено; D-57): нативный путь `l2_emit_admit` допускает по `T` **письмо целиком** (`sender; payload`), поэтому после -173 отказывает любому письму (поле `sender` vs `mainArgs`) — строки были root-pending, никто не видел. Чинится вместе с ответом.
