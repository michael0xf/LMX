# Методика дополнительных сравнений LMX

Редакция: 21 ноября 2026 года.

## Единица сравнения

Каждый пункт содержит конкретный общий сценарий, ожидаемое наблюдение, три листинга и границу их ответственности. LMX сравнивается с двумя языками, выбранными для соответствующей группы. В разных группах контрольные языки различаются. Исходные 85 пунктов сохранены с номерами; пять добавлений имеют номера 86–90.

Один короткий сценарий показывает механизм паттерна, но не заменяет весь проект. Для архитектурных паттернов листинг показывает зависимости, приём запроса или преобразование данных. Deployment, сетевой стек и транзакционный движок остаются явно обозначенными компонентами. Несколько близких паттернов могут решать сходную задачу, однако каждый имеет свой разбор и отличается обязанностями участников.

## Границы листингов

- **core / ядро сценария:** весь показанный алгоритм с перечисленными входами и библиотечными зависимостями. Это не обязательно полная запускаемая программа.
- **protocol / протокол и порты:** обработчик или участник протокола. Host, планирование, БД, очереди, codec или deployment заданы явным контрактом.
- **executable / самостоятельный пример:** листинг задуман как завершённая программа в указанном профиле. Это обозначение объёма, а не автоматическое утверждение о проведённом запуске.

Внешний порт обязан иметь понятные входы, результат и эффект. Например, compareAndSet выполняет один атомарный UPDATE; он не скрывает раздельные read/check/write. База данных обеспечивает заявленную транзакцию, а учебный обработчик определяет, какие записи она охватывает. Листинг клиента готовой библиотеки и реализация этой библиотеки имеют разный охват; эта разница описывается, а не исправляется искусственным раздуванием другого языка.

## Норма LMX

Используется документация docs и последнее уточнение автора от 21 ноября. Исполняемый метод — обычная Structure, DATA — её фактический parent. fn описывает сигнатуру. Обычное локальное присваивание не публикует значение в исходный граф. Явные пути выбирают графовые слоты. Пустая строка закрывает текущий блок до корня документа.

copy/merge выдают поток полей. Явная группа собирает отдельный контейнер; она не становится лексическим владельцем скопированного метода. Сохраняемое состояние метода меняется через его фактического владельца. При обычном вызове передача структуры может участвовать в выборе W/E; именованная передача целому формалу устраняет E в тех случаях, где это требуется сценарию. Это не правило операндов. У операнда открывается только единственный правый аргумент, если это написанная безымянная Structure и слева тоже написана безымянная Structure; снимается ровно один внешний уровень справа, слева ничего не снимается, повторного раскрытия и преобразования P0 нет.

## Message и HTTP

Многопоточные LMX-сценарии используют исполняемые Message с собственными аренами и последовательными полосами исполнения. Название структуры с суффиксом Message само по себе не запускает поток: создание и передача необходимых зависимостей указаны в профиле окружения. Письмо не превращается автоматически в новый Thread.

HTTP уже описан в языке: endpoint и route, application/lmx, декодирование и admission, исполнение на принимающем Message, синхронный семантический ответ либо асинхронный ответ с replyTo/correlation. Приём письма отличается от выполнения запроса. Дополнительный профиль примеров находится в MESSAGE_HTTP_PROFILE.md.

Последовательный владелец состояния не гарантирует транзакционный rollback, отсутствие дубликатов, распределённый consensus или параллельное чтение. Такие свойства указываются отдельно. Пример owner-message может решать ту же прикладную задачу, что и shared-memory lock, при другой модели доступа. В частности, Message-local state не равен OS-thread-local storage, если Message меняет OS worker между turn.

## Подсчёт исходников

Авторитетный источник каждого нового каталога — patterns.json. Из него получаются Markdown, отдельные исходники, CSV, XLSX и PDF. На листинг вычисляются:

1. **Непробельные символы:** количество Unicode-символов, для которых Python str.isspace() ложно. Комментарии входят. Пробелы внутри строковых литералов тоже не входят в эту механическую метрику.
2. **Непустые строки:** число строк, у которых strip() не пуст.
3. Размер UTF-8 в байтах сохранён в данных сборки, но не подменяет число символов.

Вся показанная реализация, import, объявления типов и вспомогательные функции входят в счёт. Внешний вызов, которого нет в блоке, и тестовый host не входят. У клиента готовая библиотека исключена; в связанном сравнении её реализации полный показанный код библиотеки включён. Отношение в Excel равно числу символов LMX / числу символов контрольного листинга; значение больше единицы означает более длинный LMX-листинг. Оно не измеряет скорость, качество или объём production-системы. Суммарный рейтинг по всем группам не строится.

Для повторного подсчёта выполните `python tools/recount_patterns.py` из корня распакованного архива. Проверяются все 90 исходных ID и 9 дополнительных ID реализаций, по три языка и совпадение вынесенных исходников с JSON. Изменив источник, сначала пересоберите производные таблицы; CSV, XLSX и PDF являются снимками этой редакции. Excel пересчитывает отношения и суммы после ручной правки чисел.

## Источники и проверка

Первичные сетевые источники подтверждают определения паттернов и контракты языков/библиотек. Полный указатель — SOURCE_INDEX.md; источники каждого сценария стоят рядом с ним. Листинги написаны для сравнения, с отдельным указанием использования примера H03 для каррирования. Измерения относятся к этим листингам, а не к длине исходной веб-страницы.

LMX-ядро в архиве не предоставлено и не запускалось. Реально проведённые проверки контрольных примеров, полноты архива и форматов перечислены в VALIDATION.md. Ожидаемый результат является заданием для исполнения, пока отдельная проверка не сообщает обратное. Старые receipts исходного GoF-набора остаются сведениями исходной редакции.

## Использование и реализация библиотек

В этой редакции исходные 90 паттернов сохранены. Дополнительные строки с номерами выше 90 — реализации импортируемых компонентов. Они не выдаются за новые паттерны. В руководствах и таблицах реализация расположена сразу после основного связанного примера; один общий компонент может обслуживать несколько примеров.

Граница сравнения задаётся одинаково для всех трёх языков. Прикладной листинг получает готовую библиотеку, но сохраняет собственные данные, шаги, предикаты, настройки и наблюдаемое поведение. Реализация библиотеки целиком посчитана в соседнем сравнении. Нельзя убрать helper из LMX и оставить его реализацию в контрольном языке, либо считать готовый Maybe/Option только в двух из трёх языков.

Сокращение прикладного листинга и сокращение всей программы с библиотекой — разные измерения. Excel показывает отдельные суммы основных примеров и реализаций библиотек. Вынесенные компоненты перечислены в LIBRARY_COMPONENTS.md; полный аудит всех 90 исходных примеров находится в OPERAND_LIBRARY_REVIEW.md.

В LMX используется готовый sys\OPERANDS_TEMPLATE из корневого примера Interpreter. Строка копирования входит в реализацию операнда; клиент импортирует показанную библиотеку. Режим, приоритет, арность, обработка продолжений и отсутствие автоматического fold описаны в OPERAND_USAGE_PROFILE.md.
