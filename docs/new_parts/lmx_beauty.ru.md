# Красота LMX: операция сверху, выражение снизу

21 ноября 2026 года. [English version](lmx_beauty.en.md).

Обновлённый [пример Interpreter](23_interpreter_comparison.md) занимает **159 непробельных символов против 185 у Python**. Общий заголовок операнда теперь берётся из шаблона ядра, а пользовательская часть сохраняет то, что особенно ценно для чтения: определение операции и обычное выражение с ней расположены рядом.

Задача — сохранить выражение `(x + 3) + x`, вычислить его при `x = 2` и `x = 5`, затем сложить результаты. Получаются `7`, `13` и в итоге `20`. В LMX вход называется `n`; смысл вычисления тот же.

## Сверху — операция, снизу — выражение

Полный прикладной листинг из [сравнения Interpreter](23_interpreter_comparison.md):

```lmx
operands:
    copy: sys\OPERANDS_TEMPLATE
    return: int
    add:
        return: \left + \right[0]
    example:
        int: n
        return: int
        calculate:
            return: (n add 3) add n
        demo:
            return: calculate(2) + calculate(5)
```

Внешний вызов — `operands\example\demo()`; он не входит в подсчёт.

Сверху видны общий заголовок через `copy`, конкретный результат `int` и тело сложения. Ниже находится `(n add 3) add n`, затем два вызова с разными значениями. Вложенная `example` видит `add` лексически, поэтому дополнительный импорт не нужен.

Запись `return: \left + \right[0]` действительно выглядит механически. Она показывает, откуда получены значения: `left` — ссылка на левый аргумент, `right` — общий массив ссылок на правые аргументы, и `[0]` выбирает первый из них. Эти имена не возникают из специальной ветки парсера: перед методом явно стоит `copy` известного шаблона.

### Что содержит шаблон

Это определение ядра показано для понимания и **не входит в подсчёт прикладного кода**:

```lmx
sys:
    OPERANDS_TEMPLATE:
        @: left
        []: @ right
        const: int: PASS_ARGS_AS_IS 0
        const: int: PRIORITY priority("+")
```

`PASS_ARGS_AS_IS 0` задаёт передачу ссылок на подготовленные значения. `PRIORITY priority("+")` внутри `sys` использует приоритет встроенного сложения. Обязательные поля по-прежнему присутствуют в эффективном DATA операнда: их поставляет обычный `copy` через namespace. Исходная запись `copy` сохраняется в графе.

В шаблоне нет `return`: результат принадлежит конкретной операции и здесь задан `return: int` в `operands`. Это не замена одного объявления результата другим. `example` отдельно описывает результат собственных методов в своём DATA. [Контракт операндов](../tasks/to_fable_operands_arguments_priorities.md) · [Потоки полей](../tasks/LMX_Fable_TZ_Import_Copy_Merge_Field_Streams_2026-11-21.md).

Формула остаётся узнаваемой. Чтобы увидеть два сложения, не приходится сначала переводить вложенные конструкторы в арифметическую запись. Общий разбор и исполнение обеспечивает механизм выражений языка; пользователь задаёт тело нового операнда и использует его обычное имя.

## Почему короткий Python приходится мысленно разворачивать

Python-вариант в [том же сравнении](23_interpreter_comparison.md) выглядит так:

```python
def number(value):
    return lambda x: value

def variable():
    return lambda x: x

def add(left, right):
    return lambda x: left(x) + right(x)

def demo():
    v = variable()
    tree = add(add(v, number(3)), v)
    return tree(2) + tree(5)
```

Сложность чтения связана с тем, что привычные имена обозначают вещи другого уровня:

| Запись | Что она означает в этом примере |
|---|---|
| `number(3)` | Создать функцию, которая при последующем вызове вернёт `3`. |
| `variable()` | Создать функцию, которая при последующем вызове вернёт переданный ей аргумент. |
| `add(left, right)` | Создать функцию, которая потом вызовет `left` и `right` и сложит результаты. |
| `tree(2)` | Запустить собранное вычисление с аргументом `2`. |

Поэтому `v` здесь — функция. `number(3)` тоже возвращает функцию. `add(...)` при построении выражения ещё ничего не складывает. Отдельного явного объекта «дерево» в этом Python-листинге нет: `tree` — составная функция, сохраняющая связи с другими функциями.

Короткое `lambda` создаёт объект функции; его тело выполняется при последующем вызове. В [справочнике Python](https://docs.python.org/3/reference/expressions.html#lambda) эта форма сопоставляется с обычным определением функции, возвращающей значение выражения.

Чтобы увидеть устройство нашего `add`, достаточно развернуть эту запись:

```python
def add(left_calculator, right_calculator):
    def calculate(x):
        left_value = left_calculator(x)
        right_value = right_calculator(x)
        return left_value + right_value

    return calculate
```

Создаётся новая функция, сохраняющая доступ к двум другим функциям. После возврата из `add` она продолжает ими пользоваться. Это и есть работа замыкания в данном примере.

Теперь строка:

```python
tree = add(add(v, number(3)), v)
```

читается так: собрать вычислитель суммы; слева поставить вычислитель другой суммы, соединяющий чтение переменной с выдачей постоянной тройки; справа снова поставить чтение переменной.

Весь алгоритм присутствует в листинге. Однако читателю нужно одновременно держать в голове **построение будущего вычисления** и **его последующий запуск**. Имена `number`, `variable` и `add` сами по себе этого различия не показывают. Короткая запись вмещает создание функций, сохранение связей с внешними именами и отложенное выполнение.

Опытный читатель Python может узнавать эту конструкцию сразу. Тем не менее число символов не сообщает, сколько предварительного знания требуется для такого узнавания.

## Что именно входит в размер

| Основной листинг | Непробельных символов | Всего символов | Строк |
| --- | ---: | ---: | ---: |
| LMX | 159 | 266 | 12 |
| Python | 185 | 247 | 13 |

По основной метрике LMX короче на **26 символов, или 14,05%**. Полный размер с отступами и переводами строк у LMX на **7,69% больше**. Эти показатели отвечают на разные вопросы; нормализация у обоих листингов одинаковая.

Строка `copy: sys\OPERANDS_TEMPLATE` полностью включена в размер LMX. Отдельное определение шаблона относится к предоставляемому ядру и исключено, как исключены внутренние реализации стандартной библиотеки других языков. Показать его рядом полезно для понимания, но это не превращает справочный листинг в повторно написанный код каждого приложения.

Изменение размера получилось из обычного повторного использования описания. Поля `left`, `right`, `PASS_ARGS_AS_IS` и `PRIORITY` остаются частью контракта. Их больше не нужно выписывать в каждом примере. Подсчёт фиксирует стоимость конкретного приложения и его обращения к общему механизму.

## Почему и остальные варианты выглядят иначе

В выбранных реализациях одно выражение представлено разными способами:

| Языки | Как представлено вычисление |
|---|---|
| Python, C++, Go | Функциями, которые сохраняют связи с дочерними вычислениями и вызывают их. |
| Java, C# | Объектами `Number`, `Variable`, `Add` с методом `eval` / `Eval`. |
| TypeScript | Объектами с методом `eval`, использующим сохранённые связи. |
| Rust | Вариантами `enum` и рекурсивным вычислением через `match`. |
| LMX | Обычным выражением языка с лексически доступным пользовательским операндом. |

Это описание именно листингов из [файла сравнения](23_interpreter_comparison.md). Java, C# и Rust довольно явно показывают узлы и обход. Однако саму формулу там приходится восстанавливать из конструкторов и служебной записи. В Python, C++ и Go создание вычисления дополнительно выражено через возвращаемые функции.

Обычную арифметическую формулу Python тоже позволяет записать непосредственно. В этой подборке его пример реализует отдельное представление вычисляемого выражения. LMX использует для показанной задачи собственный механизм выражений: новый метод становится частью привычной записи.

## Архитектурная красота: общий механизм работает на пользователя

В LMX для этого примера не потребовались отдельные пользовательские конструкции «число как вычислитель», «переменная как вычислитель» и «сумма как создатель вычислителя». Форму вычисления уже хранит граф тела `calculate`. Два вызова передают разные значения входа, сохраняя записанное выражение.

Общий механизм expression берёт на себя разбор, подготовку аргументов и исполнение операций. Пользователь копирует общий заголовок, определяет результат и тело своего метода и использует его в выражении. Сложность однажды решена в общей модели и доступна через обычную запись языка.

Это соответствует замыслу LMX: получать разные возможности из небольшого числа общих механизмов. На данном примере обычный метод, его DATA, разрешение имени и механизм выражений вместе дают пользовательский операнд. Для чтения применения этого операнда достаточно видеть саму формулу.

Режим `PASS_ARGS_AS_IS 1` также предусмотрен контрактом: он позволяет получать исходные аргументные вхождения и явно вычислять их через `sys\eval`. В показанном сложении используется режим `0`. Оба режима описываются тем же обязательным полем; приоритет остаётся отдельным свойством. Так расширение возможностей сохраняет видимый контракт операции. [Правила двух режимов](../tasks/to_fable_operands_arguments_priorities.md).

## Краткость, понятность и содержательность

Подсчёт символов отвечает на один точный вопрос: сколько знаков занимает конкретная запись. Для оценки примера полезны ещё два вопроса:

- Насколько непосредственно из записи виден ход вычисления?
- Какие свойства и договорённости явно выражены в этих знаках?

В этой редакции LMX имеет и самый короткий листинг по непробельным символам, и узнаваемую математическую форму применения. Читаемость, однако, объясняется устройством записи: операция, её общий заголовок и использующее её выражение связаны явно.

Читатель LMX может пройти пример сверху вниз: увидеть источник общих полей, результат и тело операции, затем выражение и два его вызова. Если нужно уточнить `left`, `right[0]` или настройки, полное определение шаблона приведено рядом.

**Сверху определена операция. Снизу написано выражение с этой операцией. Обычный `copy` связывает короткую запись с видимым описанием её устройства.**

Тот же пример продолжает объяснять замысел языка после сокращения: универсальный механизм доступен пользователю, а его применение остаётся читаемым выражением.
