# Протокол облачных сессий: тикеты и отчёты через git (fable, 2026-09-25)

Сессии `fable`, `opus`, `sonnet` живут в отдельных контейнерах claude.ai/code. Прямых сообщений между ними нет (SendMessage по именам не резолвится; автор не знает, как их связать). Единственный общий носитель — `origin` (`michael0xf/LMX`). Автор — ретранслятор коротких строк между чатами; всё содержательное — в git.

## 1. Ветки

- `main` — только fable вливает (`git merge --no-ff`, после гейта).
- У каждой сессии — своя рабочая ветка, та, что назначена сессии (`claude/continue-opus-next-doc-…`, `claude/continue-sonnet-next-doc-…`). Пушить только в неё: `git push -u origin <своя ветка>`. Один тикет — можно один коммит-план + коммиты кода на той же ветке; отдельные тикеты одной сессии — последовательно на той же ветке, RESULT называет sha каждого.
- База — свежий `origin/main`: в начале каждого тикета `git fetch origin main && git merge origin/main` (в своей ветке). Rebase/force-push чужих и своих запушенных веток — нет.

## 2. Как получить тикет

1. `git fetch origin main`
2. `git show origin/main:steps/tickets-20260925.md` — текущие тикеты; `git show origin/main:fable_next.md` §3/§8 — очередь и состояние. Новые тикеты fable кладёт в `steps/tickets-<дата>.md` и вливает в main; автор пишет в чат сессии одну строку: «тикеты в main <sha>».
3. Нет тикета в файле — тикета нет. Записка `*_next.md` — контекст, не поручение.

## 3. Как отвечать (STARTED / QUESTION / RESULT / GATE?)

Каждый ответ — файл `steps/<тема>-<N>.md` в своей ветке (для к.1 read-only это и есть план) **и** первая строка сообщения коммита:

- `STARTED <ID>: <ветка>@<sha> база main <sha>` — первый коммит по тикету (можно вместе с планом к.1).
- `QUESTION <ID>: <одна строка вопроса>` — в файле тикета раздел «Вопросы fable» с минимальным примером и точными местами кода; коммит, push. Работу, не зависящую от ответа, продолжать.
- `RESULT <ID>: <ветка>@<sha>` — в файле: база, что и почему, строки harness (имена, новые факты Entry/Says/Debt), мутанты (как именно мутировано, что стало RED/GREEN), числа гейта, что НЕ запущено в облаке (честно, см. §4), сгенерированный L1 перевёрнутых строк — путём под `build/` не годится (ignored): вставить фрагмент в файл отчёта.
- `GATE? <ветка> <sha>` — когда ветка готова к машинному гейту.

Пересылка через автора — необязательна: fable каждые полчаса сам обходит ветки `claude/continue-opus-*` и `claude/continue-sonnet-*` (`git fetch --all`, первые строки коммитов, файлы `steps/`) и отвечает в `steps/tickets-<дата>.md` или в файле тикета на main. Opus и Sonnet в начале каждого шага делают `git fetch origin main` и читают ответы там же. Строка через автора (дословно первая строка коммита, например `QUESTION FABLE-OPUS-ROOT-MERGE-20260925-199: …`) нужна только когда ждать полчаса нельзя — прежде всего для QUESTION и GATE?.

## 4. Что проверяется где

- В облаке (у всех): `python tools/check_docs.py`, `git diff --check`, `python tools/build_l2src.py` (174/230 на main — красные только модули с `<windows.h>` и их замыкание: `lmx_clock`, `lmx_process_deadline`, `lmx_manager_running`, транзитивно `lmx_thread`/`lmx_turn`/`lmx_root`/`lmx_settle`/`lmx_manager` и их селфтесты; `--only <имя>` для своих селфтестов), сборка l2trans и перевод фикстур `.lm2 → .lm1 → .c` (см. `steps/tickets-20260925.md` §0), `python tools/run_l3_selftest.py --translator <b0>` (6/11 до POSIX-двойника).
- Только на машине автора (Grok CLI, `grok_next.md` §3): `build_l2src.ps1 -Run` 100 %, `l2_harness.ps1` (eternal-runs, факты Entry/Says), L3 11/11. Запрос — `GATE? <ветка> <sha>` через fable; результат Grok CLI кладёт в `steps/gate-results.md`.
- Красное в облаке вне замыкания `<windows.h>` — настоящее красное; чинить до RESULT.

## 5. Что не делать

- Не пушить в main и в чужие ветки. Не править чужие файлы-владения (`l2trans.lm1` — Opus; ядро `lmx_*.lm1`, walker, L3 — Sonnet) без тикета.
- Не коммитить `build/`, `*.stackdump`, `lmx_root_*_selftest.err/.out`.
- Не ждать ответа молча: нет ответа fable больше часа работы — продолжать по плану тикета там, где ответ не нужен, и записать QUESTION.
