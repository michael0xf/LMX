# Q26. Присваивание Structure в Structure-типизированное поле по пути: `o\inner: a`

Контекст: Opus -183 строит записи через ссылку в интерпретируемом корне (`m\f: v` — PUT_OF). Две строки harness’а (`unit_field_path_struct_rebind_refused`, `unit_matrix_path_struct_rebind_refused`) пинуют **отказ** трансляции для присваивания целой Structure в путь, оканчивающийся Structure-типизированным полем; отказ был моим временным решением (fail-closed, -131/-146), и аудит соответствия блогу уже отмечал «присваивание графа графу отказано» как расхождение с вашими ответами. Сейчас в корне это остаётся именованным отказом («a Structure assigned through a path»), пока нет правила.

Минимальная программа:

```text
Inner: (int: value)
Outer: (Inner: inner)
Outer: o
Inner: a
a\value: 5
o\inner: a
c.puts: o\inner\value    # 5? и что такое o\inner после этого
```

Чтения:

1. **merge на месте (Q21 = А):** `o\inner: a` = `merge(o\inner; a)` — одноимённые поля `a` записываются в слоты `inner`, новые дописываются; `inner` сохраняет идентичность (тот же адрес), `a` — модель-операнд. Так же читается любое `x: v` для Structure-полей — «любое присваивание — occurrence поля» + «merge как в git».
2. **перепривязка:** слот `inner` теперь ссылается на `a` (адрес `o\inner` = адрес `a`); осмысленно для поля-ссылки `@: Inner inner`, для own-поля `Inner: inner` — подмена владения.
3. **отказ** (как сегодня).

Рекомендация: **1** для own-поля (`Inner: inner`), **2** для поля-ссылки (`@: Inner inner`) — оба без особых случаев: own-поле держит своё значение (merge в него), ссылка держит адрес (перепривязка), ровно как для чисел (`int: x` — значение, `@: int p` — адрес).

Ответ автора (2026-09-25, дословно в блоге): «у нас есть ссылки "@" вы помните? Заодно их проверите. Это ответ?» — да: рекомендация подтверждена — own-поле `Inner: inner` = merge на месте (1), поле-ссылка `@: Inner inner` = перепривязка через `o\inner: @ a` (2); отказа (3) нет. **Закрыт.** Реализация: Opus -183 (follow-up: own-поле — двухоперандный merge на месте, для корня нужен n-операндный merge-примитив walker’а; ссылка — PUT адреса в слот); свидетель проверяет и `@`-ссылки.

Уточнение автора: «Там не банальная логика потому что ссылка на структуру получается двойным указателем — но это разруливалось уже в старом проекте, и надо чтобы сейчас разруливалось» → D-53 (двойная косвенность `@` Structure-типизированного own-поля) решается по образцу `lingvamyxa_prev`; Opus цитирует место в записке -183.
