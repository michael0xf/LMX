# Обычное значение `[]char` на графовом маршруте: предпосылка П1.1 имён (28 ноября 2026 года)

Ведущий `coder`. Очередь v3, следующий срез грамматики, пункт 2: закрепить общий синтаксис создания и выбора
именованного поля по `[]char` ([очередь](../../../next_core_tasks_v3.md#identifier-bytes-priority-20261128)).
Паре операций — создать поле по строковому ключу и выбрать его по строковому ключу — нужно на графовом маршруте
обычное значение `[]char`. Три проекта (NAMES-1, NAMES-2, NAMES-3) ушли к Sol до кода; первые два не приняты как
написанные; из третьего согласованы две независимые предпосылки: П1 — обычное значение `[]char`, П2 — вставка в ту
же запись Structure. Этот срез — П1.1, частичный технический шаг П1, согласованный с Sol и Astra перед кодом
(заметки `build2/coder-grammar-20261127/DESIGN-NAMES-1.md`, `DESIGN-NAMES-2.md`, `DESIGN-NAMES-3.md`,
`DESIGN-P1-1.md`). База: набор `coder-assign02` (`bbad344aa`).

## Норма

- `docs/spec/LMX_semantics.ru.md:237`: Array использует общий дескриптор графа и фактический тип хранения своих
  элементов; «Плотный `[]T` хранит T непосредственно»; последовательность соседних `[]` или `[extent]` задаёт оси
  одного плоского Array.
- `docs/spec/LMX_semantics.ru.md:260–266` и `docs/spec/reference/field-name-keys.md:9`: в позиции явного именования
  строкой ключом служат длина и содержимое значения `[]char`; для строкового литерала это результат обычного чтения
  литерала; «В позиции значения строка остаётся данными».
- До среза на графовом маршруте значения строки не было: литерал в позиции значения читался как имя (ответ 3);
  записанный `[]char` был записью Lmx из слов; `length` знал только Array of int и Structure.

## Что сделано

Шесть исходников, одна механика для int и для char.

- **Построитель** (`l2_graph_build.lm2`). Основание `char` читается в `lm_graph_build_type_reference` как тот же
  буквальный TYPE, что `int`, и составляется тем же рецептом. `lm_graph_build_typed_composition` включает
  построение массива для записанного квадратного литерала с основанием char. Статический допуск
  `lm_graph_char_literals`: каждое число среди элементов принимается рядом char на своём месте; вне ряда —
  отказ на координате литерала (`graph: 5:26: the literal is out of the range of the char row`, ответ построителя 2).
- **Модуль типов** (`lmx_types.lm2`). Два новых постоянных описания, `char` и `[]char`; `lmx_types_reference_details`
  различает четыре постоянных описания и выдаёт основание, ранг, оси и глубину одним выходом;
  `lmx_types_composed_base` допускает основание char.
- **Построение литерала** (`lmx_graph_run.lm2`, `lmx_graph_array_literal`). Одна геометрия для ссылки типа
  буквального литерала и для ссылки, составленной при достижении объявления: `lmx_graph_literal_cells` считает
  и принимает ячейки, `lmx_graph_flat_array_extent` сверяет их с произведением осей; затем хранилище по основанию
  (`lmx_array_new_int_with_reference` или `lmx_array_new_chars_with_reference`), и в оба уходит вся ссылка типа.
- **Чтение** (`lmx_graph.lm2`, `lmx_graph_run.lm2`). `lmx_graph_length` даёт число элементов Array of int и Array of
  char. Array of char проходит значением (`lmx_graph_eval_value`); шаг индекса его допускает
  (`lmx_graph_index_parts`). Литерал, востребованный как значение, становится обычным временным значением
  (`lmx_graph_literal_chars`). Декодер разделён: `lmx_graph_string_bytes` даёт байты и длину (нулевой байт —
  данные), `lmx_graph_string_value` держит договор имени и отказывает на нулевом байте.
- **Читатель символьного литерала.** `lmx_graph_char_read` читает один простой однобайтовый токен `'x'`; применяется
  только в допуске элементов массива.
- **Дамп.** Печать основания `char` и готового Array of char с кодами элементов.
- `lmx_array_owned.lm2`: `lmx_array_new_chars_with_reference`. `tools/build.lm2`: таблицы имён (9 имён массивов,
  116 имён графа) и два поля `LmxTypes`.

## Границы среза

Решения Sol по расписке (`SOL-CODER-P1-1-SHAPE-REVIEW-20261128`, 13:50).

1. Отказ формы остаётся общим кодом 2 построителя без нового сообщения — как у базы для int.
2. Индекс даёт char-ячейку. Существующее чтение её как int (ответ 1) и запись в скалярное место char (ответ 4 на
   обоих наборах) не расширялись. Неявного char → int нет.
3. Допуск символьного литерала — только простой однобайтовый токен внутри массива. Эскейп (`'\n'`) и два символа
   (`'ab'`) оставляют объявление записанным вычислением. Скалярная декларация `char: c 'a'` не менялась.

## Что этим не заявлено

- Материализация вычисляемого элемента, полная матричная форма `[*f():f2(args)]` и обратный проход исходника
  (`p0 FILE print`) — отдельные работы общей грамматики.
- Положительное значение строки на размещённом маршруте не заявляется: размещённый frontend кандидата даёт тот же L1,
  что база, на 201 исходнике.
- Передача Array of char и Array of int аргументом (П1.2), вставка в ту же запись Structure (П2), обычный путь `sys`
  и операции `sys\place` / `sys\field` — следующие шаги.
