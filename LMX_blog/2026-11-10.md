# Технические уточнения автора — 2026-11-10

## Сквозная видимость — внутри code метода; корень — у структуры data (var)

Источник: уточнение автора, переданное Codex (CODEX-OPUS-AUTHOR-CODE-DATA-SCOPE-20261110T074510Z-01), дословно:

```text
сквозная ведимость в методе внутри code, а про корень я говорил когда говорил о структуре data (var) -- из неё берутся только корневые значения и автозаполняется она так же
```

Пояснение Codex при передаче (не слова автора): сквозная видимость относится к собственным местам внутри code метода —
место готовится до исполнения, инициализатор исполняется при достижении строки; слова о корне относятся к
непосредственным полям выбранной data или var: если code передан самому себе как data, корневой `if` — одно поле этого
уровня, его внутренние головы не поля data; при автозаполнении var существующие поля проверяются на её корне, недостающие
собственные места добавляются туда же; вложенное поле data не заменяет корневое место; обычная переданная data
автоматически не дополняется.

## Пустая короткая форма допустима; раскрытий в P0 нет

Источник: сообщение автора Codex, вставленное автором и в сессию Opus (2026-11-10; передано также Codex,
CODEX-OPUS-AUTHOR-EMPTY-SHORT-NO-P0-EXPANSION-20261110T115250Z-01), дословно:

```text
отменяем правило что пустые короткие формы запрещены. Разрешаем "short:" без аргументов  и тогда никаких раскрытий в парсере нигде не нужно -- передавй to opus чтоб он внес изменения в документацию и в код
То есть сейчас валиден такой код:
short0:
short1:
short2:; short3:
short4:
```

Пояснение Codex (не слова автора): это пять соседних коротких Frame с нулём полей тела; сосед на прежнем уровне, `;`
и конец входа закрывают их обычным механизмом, более глубокое продолжение может дать тело; в `f(a:)` присутствует пустой
Frame `a`, его связывание и допуск — у потребителя; пустой `short:` метки применения не получает; P0 не раскрывает
написанных дочерних контейнеров (ни единственного анонимного, ни пустого): нулевое тело пишется прямо `A:`, явно
написанная дочерняя Structure сохраняется, в том числе пустая.

Дополнение автора там же (передано Codex, CODEX-OPUS-AUTHOR-EMPTY-SHORT-CALL-SCOPE-20261110T115355Z-01), дословно:

```text
только при вызове функции транслятор или интерпретатор заполняют аргументы из единичной переданной структуры, но это не парсер
```

Форма деревьев (передано Codex, CODEX-OPUS-AUTHOR-EMPTY-P0-SHAPES-20261110T115634Z-01), дословно:

```text
То есть теперь `A:`  и `A{}`  и A() дают пустую структуру в парсере, а `A: {}`  и `A: ()` содержат одну пустую структуру внутри. Передай Opus, чтобы в доках не осталось старого равенства.
```

Пояснение Codex (не слова автора): у `A:`, `A{}` и `A()` ноль непосредственных полей тела, у `A()` — метка применения;
у `A: {}` и `A: ()` одно непосредственное поле — явно написанная пустая Structure, и для завершённой короткой формы тоже;
прежнее правило, приравнивавшее её дерево к `A{}`, отменено.

Дополнение автора (передано Codex, CODEX-OPUS-AUTHOR-EMPTY-DOTTED-20261110T115850Z-01), дословно:

```text
A:
.
end: A
тоже дает пустую структуру так как нас интересует что внутри A -- а там ничего
A: {}
B: {}; C: {} #дают структуры с еще одной пустой структурой внутри
```

Поручение автора (передано Codex, CODEX-OPUS-AUTHOR-EMPTY-CHILD-DOC-20261110T120332Z-01), дословно:

```text
То есть `A{{}}`, `A: {}` и `A: ()` дают одно и то же содержимое A — одну пустую структуру. Пусть Opus явно покажет это в документации.
```
