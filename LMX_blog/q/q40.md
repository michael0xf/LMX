# Q40. Ход L3 после Q35: значение входа как код выхода (E1) и аргумент-субъект

Состояние: 2026-09-27 открыт (Opus; уточнение к ответу Q35; замер — `steps/turn-runnable-q35.md`); в тот же
день отвечен автором в чате Opus. Дословно — `LMX_blog/2026-09-27.md`, «Q40: код выхода L3 и «аргумент-субъект»».

## Факт

Ответ Q35: «куда возвращаемый статус и зачем?», «"success" выставляет пользовательский код», «если корень это
стуктура без аргументов и возвращаемого значения, то он вызывается на каждый turn как будто это runnable такой».

Корень L2 этому уже отвечает: у юнита нет частей аргументов и результата, `return` со значением в корне
отказывается; выход — письмо выхода или `success`, оба ставит программа.

Корень L3 — нет. `dev/l3_interp/l3_thread.lm1` `l3_thread_dispatch` применяет граф хода с **одним аргументом** —
самим графом (`args = @ subject`, `nargs 1U`) — и сохраняет его int-результат как **код выхода хозяина** (E1,
`l3_thread_result`). Селфтест `l3_thread_bind_selftest`: «an entry returning 7 is an ordinary successful turn», «the
entry's 7 is observed as the host's exit value».

## Вопрос

1. E1 для L3 снимается — значение, которое вернул граф хода, не становится кодом выхода (выход — только то, что
   выставил пользовательский код)?
2. Аргумент-субъект L3-хода (граф получает самого себя аргументом) — остаётся частью L3-хода, или корень-runnable
   вызывается без аргументов, как в L2?

## Предложение Opus

1 — да: это тот же «возвращаемый статус», только под именем кода выхода. 2 — без аргументов, как в L2: runnable
по ответу — «без аргументов».

## Ответ автора (2026-09-27)

Дословно — `LMX_blog/2026-09-27.md`. Как прочитано (Opus; при расхождении действует цитата):

1. E1 («код выхода процесса — целое, которое вернул entry») — давно отменённая норма. Выбор D1 = E1 — `LMX_blog/2026-09-22.md` («Точка входа L2: код выхода…»); заменён 2026-09-24 (`LMX_blog/2026-09-24.md`, на «exit code = последнее выражение»): запуск идёт через родителя R0, родитель принимает от R0 Message `exit(exit_code: <code>; stdout: ""; stderr: "")`, а если закрытие произошло без Message — смотрит флаг `success` R0. В плане — `next_core_tasks.md` :270 («Пересмотр автора (2026-09-24, вечер; дословно в блоге)»), посажено в `da40aa3` и `5b1a4be`; в коде — `lmx_root_launch_tapped` («THE EXIT: R0's letter, or else R0's success»). Значение, которое граф хода L3 сохраняет как код выхода (`l3_thread_result`), — остаток отменённой нормы; снимается.
2. Аргумента-субъекта нет: исполнение — всегда execute(code data); у корня data = code — неявный принцип исполнения, а не аргумент, и граф, не описанный как процедура с аргументом, аргумента не получает. Обойти execute(code data) нельзя. `l3_thread_dispatch` должен звать граф как пару (код = граф, данные = граф) без аргументов.
