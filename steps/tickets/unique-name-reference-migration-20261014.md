# UNIQUE-NAME-REFERENCE-MIGRATION — 2026-10-14

Статус: OPEN. Авторская норма сохранена дословно в [LMX_blog/2026-10-14.md](../../LMX_blog/2026-10-14.md). Этот тикет заменяет прежнее правило повторных одноимённых вхождений, их селекторов и неявного вызова через сохранённый указатель. Существующие старые тесты и checkpoint-ы — свидетельства прежнего поведения, не действующий контракт.

## Норма и границы

- Одно пространство имён в непосредственно объемлющей Structure для примитивных полей, обычных Structure, ссылок, методов и `catch`; второе объявление имени на том же уровне запрещено. Вложенная Structure может затенить имя. Повторный оператор присваивания или вызова не является объявлением и остаётся отдельным исходным оператором в полном графе.
- Неизвестная голова `Model` с одиночным атомом в `Model: ptr` — ошибка трансляции независимо от известности `ptr`; `Model: ()` с новой головой объявляет пустую Structure. Структурное тело объявляет на своём уровне, но повторное объявление там же запрещено.
- Известная обычная Structure `Model` с неизвестным `ptr`: `Model: ptr` = `@: ptr Model` — новое поле-ссылка с адресом именно этого экземпляра. `@: ptr Model 0` даёт null; `@: ptr Model Other` записывает адрес `Other` только после `implements(Model, Other)`.
- При обоих известных именах `Model: ptr` пытается присвоить значение `ptr` месту `Model`, а `ptr: Model` — значение `Model` месту `ptr`. Это разные направления. Отказ преобразования/допуска не меняет цель. Запись через `@` в существующее поле не сводить к новому объявлению: её отдельный контракт не выводить из синтаксиса объявления.
- Указатель на метод можно объявить `@: ptr myFunc`. Имя самого метода вызывает прямо: `myFunc()`. Для указателя `ptr()` = `ptr: ()` — попытка присвоить пустую Structure; `ptr: a` — попытка присвоить `a`. Только `\ptr()` вызывает по адресу. `catch` остаётся ресивером обработки отказов; его описание головы/аргументов проходит общий алгоритм, но не превращается в обычный `fn`. Не смешивать с иностранным C99 `fnptr:`.
- Удалить *именованные* селекторы `node\[N]field`, `s\[N]name` и корневой `[N]name` из языка и транслятора. Оставить безымянный индексный шаг Array: `arr[i]\[j]\[k]` следует ссылкам на отдельные Array, а `arr[i][j][k]` индексирует один прямоугольный Array.
- Карта `implements` по-прежнему переводит физические позиции требуемых полей в позиции кандидата. Две прежние половины ordinal/LAST после запрета дублей избыточны. Не удалять карту целиком, не возвращаться к предположению одинаковых слотов и не вводить runtime-имена. На переходе допустимо заполнить обе половины одинаково, затем согласованно сократить producer, native, walker, copy и `exec_map` до одной карты.

## Порядок исправления

1. Сверить общий разбор полной модели «голова—аргументы» и классифицировать *операцию* до проверки уникальности. Нельзя отвергать `Model: ptr` с двумя известными именами как дубль: это попытка присваивания. Ввести один compiler-only контроль объявления по (непосредственный контейнер, нормализованное имя) до выделения нового поля, общий для всех перечисленных видов; вложенное затенение разрешено. Не помещать имя в runtime-граф.
2. Завершить начатый срез объявления ссылок. Проверить начальный адрес `Model: ptr` и `@: ptr Model` native/walked, null, `Other` после допуска, отказ и исходную последовательность операторов. Убрать старый положительный `unit_known_model_repeat_name_ref.lm2`: заменить его отрицательной проверкой дублирующего объявления и положительной проверкой присваивания с двумя известными именами.
3. Единым диспетчером выбранной роли разделить прямой `myFunc()` вызов метода, `ptr()`/`ptr: ()` запись в сохранённый указатель и `\ptr()` вызов по адресу. Поддержать указатель на `fn`/`sub`; `fm` по плану ещё не реализован и не должен маскироваться фиктивным успехом. `catch` сохраняет собственный контракт. Перенести прежние `unit_held_call_*`, `unit_make_adder_*` и родственные fixtures с вызова сохранённой ссылки через `h: args` на `\h: args`; прямые методы оставить прямыми. Иностранные `c.fnptr` не переинтерпретировать.
4. Запретить именованный occurrence selector при трансляции с диагнозом по месту. Мигрировать или сделать отрицательными `unit_occ_selector_*`, `unit_q24_repeated_decl`, `graph_shape_*occ*`, `unit_reference_crossing_occurrences` и прочие старые свидетели. Сохранить и повторно проверить `unit_arrarr_field_*`, `unit_steps_*`, `unit_arr_path_*` и различие ровного массива с массивом ссылок.
5. После отсутствия дублей в успешных графах заполнить прежние две половины карты `implements` одинаковой единственной проекцией как переходный ABI. Затем одним срезом удалить вторую половину во всех производителях и потребителях (`lmx_implements.lm1`, `l2_d105_table`, `OWN`, native/walker, копирование и композиция `exec_map`). Проверить кандидат с переставленными полями и перенос тела `merge`.
6. Согласовать нормативные RU/EN семантику, грамматику, L1/L2, архитектурную карту, словарь, руководство и план. Длинные объяснения держать в парных ненормативных соседних guides; старые датированные результаты не переписывать как якобы новые прогоны. Исполнить точечные native/walked тесты, затем релевантный полный gate, `build_semantics.py --check`, `check_docs.py` и `git diff --check`. Известные чужие CRLF у `claude/fable_chat*.bat` не править ради зелёного чекера.

## Минимальные свидетели

```text
Model: ()
Model: ptr             # новое ptr: адрес Model
@: null_ptr Model 0
Other: ()
@: other_ptr Model Other  # только после допуска
ptr: Other             # попытка записать Other в ptr
Model: ptr             # попытка записать ptr в Model
```

Отрицательные: неизвестное `Model: ptr` с атомом справа; повторные объявления `int: x` / `int: x`, `Model: ()` / `Model: ()`, межкатегорийное столкновение в одном контейнере, именованный `node\[0]field`, отказ `implements` для `Other` и ошибочный фактический аргумент метода. Положительные: затенение во вложенной Structure, обычные повторные *присваивания* без новых полей, сохранение исходного дерева, `\fn_ptr: args`, оба вида многомерной индексации и перестановка полей кандидата.
