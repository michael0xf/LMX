# Закрытые вопросы о test и data — 2026-11-13

Вопросы подготовил Codex при повторном чтении документации по поручению автора.
Дословные ответы сохранены в [журнале](../2026-11-13.md); ниже отделены ответы от выводов исполнителя.

## Q1. Известный при построении кандидат и фактический приём

Вопрос: нужно ли для кандидата, известного при построении, выполнять `test` при первом фактическом приёме
во время исполнения, или `test` относится только к динамически выбранному кандидату?

Автор [указал вопросом](../2026-11-13.md#runtime-candidate-admission), что исполнитель необоснованно
противопоставил эти случаи. Исполнитель снимает такое разделение: при построении только интерфейсная часть;
при фактическом допуске во время исполнения — второй шаг `test`. Известность кандидата не отменяет второй шаг
и не требует повторять уже завершённую первую часть. Это вывод из общего правила, не отдельный режим допуска.

## Q2. Где может исполниться test при наличии data

Вопрос: является ли `test: op check` среди данных Consumer особой декларацией проверки, или её нужно исполнять?

[Ответ автора](../2026-11-13.md#data-root-receiver-execution): прямой проход по `data` замечает только объявления
корневого уровня и исполняет только их ресиверы объявления. При исполнении такого ресивера может исполниться
переданный ему код. Следствие для `test` то же, что для любого кода: исполнение должно быть достигнуто обычным
механизмом; наличие записи среди данных само по себе её не запускает. Особого обхода данных ради `test` нет.

Поэтому пример из вопроса

```text
Consumer:
    @: op Model
    test: op check
```

не служит свидетельством исполнения второй строки при прямом проходе по данным `Consumer`.
Ресивер объявления `@` выполняется по своему контракту; из этого не следует вызов соседнего `test`.

## Q3. Несколько проверок и первый результат 0

Вопрос: после первой неуспешной проверки выполнять остальные или прекратить допуск?

[Ответ автора](../2026-11-13.md#test-first-failure): «сразу прекращаем».
При первом `0` остальные проверки не исполняются. Все проверки должны быть успешны для допуска;
прежняя фраза «исполняет все» не означает продолжения после отказа.
