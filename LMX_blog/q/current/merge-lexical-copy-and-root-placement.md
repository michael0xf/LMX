## Задокументированное противоречие

[Семантика §20](../../../docs/LMX_semantics.ru.md#composition), строка 943
русского и английского текста. Один абзац содержит оба предложения:

- «Копируется полный используемый граф с необходимыми ссылками и лексическими
  цепочками до нулевого родителя. … ссылки и `parent` явно переписываются.»
- «Лексический родитель нового корня определяется местом выражения `merge`.»

Строка 976 того же раздела (возвращаемый вложенный метод) и строка 980
(динамические источники и лексический запасной путь) называют запасным
источником свободного имени скопированный лексический контекст и говорят, что
явный путь `node\…` выбирает этот контекст.

Пока модель объявлена там же, где исполняется `merge`, оба предложения дают
один результат. Таков пример makeAdder: `addN` вложен в активацию, которая его
возвращает. Они расходятся, когда модель объявлена в одном месте, а `merge`
исполняется в другом, где есть одноимённое поле. Как согласовать второе
предложение с первым, книга не говорит.

## Наблюдаемая реализация

Измерено 2026-10-04 на `0781bf65`, транслятор `b450f0c014fde9c2`, пробниками
вне гейта. Ни одна строка здесь не выбирает чтение.

- Узел `merge` метода единицы строит нативный код метода, в котором стоит
  `merge`. Родителем узла становится `node` этого метода, то есть место, где
  метод объявлен, а не его активация. Узел живёт в арене программы.
- Тело узла — вид тела модели, построенный для этого места `merge`. Свободное
  имя тела, которое не подал вызывающий, читается из ячейки поля единицы по
  адресу, впечатанному при построении. Копии лексического состояния модели на
  момент `merge` нет. Поля метода, исполняющего `merge`, в чтении не участвуют.
  Это прочитано в порождённом коде узла; прогоном отдельно не выделено по
  причине, названной ниже.
- Возвращаемое вложенное определение (`return: add` из активации, где `add`
  вложен) копирует используемые значения активации в данные узла. Вызов из
  места, где `other` никто не подаёт, читает копию: 9 и для собственного поля
  активации, и для её формала.
- Метод, у которого до `return: merge(...)` объявлено поле, отвергается
  трансляцией ([T7-HOST-BODY](../../../steps/defects.md#t7-host-body)).
  Значение для такого примера сегодня не измеримо.
- Метод с формалом `other` возвращает `merge(add)`, корень держит результат и
  вызывает его: 9. После присваивания `other: 11` в корне: 11. Это не
  различает чтения: корень сам владеет `other` и подаёт его как вызывающий, а
  динамический источник старше любого запасного.
- Модель вне цепочки вызывающих дала бы различающий пример: `merge(g)`, где `g`
  держит возвращённое вложенное определение. Трансляция отвергает его: «a
  callable merge binds a name that is not a formal». Моделью `merge` в
  вызываемом месте сегодня может быть только метод единицы.

Следствие для примера: в программе из одной единицы, где модель объявлена в
корне, корень владеет её лексическим `other` и стоит первым в каждой цепочке
вызовов. Условие «вызывающий не подаёт `other`» там не выполняется. Пример
различает чтения, когда лексическое место модели не входит в цепочку
вызывающих.

## Предлагаемые чтения

Пример Codex: `add` без аргументов читает лексическое `other`, равное 9.
`merge(add)` с одним операндом исполняется в `make`, у которого своё поле
`other`, равное 50. Копию вызывают там, где `other` никто не подаёт.

```text
int: other 9

fn: add () int
    return: other

fn: make () fn: () int
    int: other 50
    return: merge(add)
```

- Чтение «копия состояния модели». При `merge` копируется используемое
  лексическое состояние модели: `other`, равное 9 на момент `merge`. Эта копия —
  запасной источник свободного имени и то, что читает явный `node\other`.
  Место выражения `merge` определяет, куда прикреплена копия: её верхний
  `parent`, владение и срок жизни. Имена тела по месту выражения заново не
  разрешаются. Результат 9. Последующее изменение исходного `other` копии не
  видно.
- Чтение «место выражения». Лексический родитель нового корня — место, где
  исполнен `merge`. Запасной источник свободного имени тела копии — поле этого
  места, затем его цепочка. Результат 50. Скопированное состояние модели
  запасным источником не служит.

Сегодняшняя реализация не совпадает ни с одним чтением: тело узла читает живую
ячейку поля единицы и видит её последующие изменения.

Ни одно чтение не вводит имён при исполнении, постоянного побочного графа
контекста или новой записи идентичности. Копия существующих достижимых
Structure источника — обычное копирование графа.

## Вопрос

Что получает вызов копии в примере, когда `other` никто не подаёт: 9 или 50?
Как при этом читается предложение «Лексический родитель нового корня
определяется местом выражения `merge`» рядом с правилом полной копии
используемых лексических цепочек? Что читает явный `node\other` в теле копии?
Видит ли копия изменение исходного `other` после `merge`?

## Что не входит в вопрос

Путь `node\x` — явный путь через выбранную Structure узла. Если у неё нет поля
`x`, путь не разрешается; предки вместо неё не просматриваются. Так Codex читает
действующее правило путей, это не новое решение автора. Какая Structure
является выбранным узлом у копии, зависит от ответа на вопрос выше.

Запись `merge(y: k; add)` с данными первым операндом — отдельное расхождение
реализации с книгой. Оно записано в
[T7-DATA-FIRST-SHAPE](../../../steps/defects.md#t7-data-first-shape) и этим
вопросом не решается.
