# Корень единицы при R0 без данных: где программа объявляет Structure

Дата: 2026-11-19. Задаёт исполнитель (сессия fable). Статус: **открыт**. Документальный срез нормы 2026-11-19
от ответа не зависит: в документах R0 описан словами ТЗ. От ответа зависят шаги 5 и 8
[плана](../../../next_core_tasks_v3.md#binding-callables-20261119): запуск R0 и перенос программ.

## Что записано

[ТЗ 2026-11-19](../../../docs/new_parts/LMX_Fable_TZ_Binding_and_Callables_v2_2026-11-19.md), §4.3:

~~~text
R0 запускается как процедура без data и без пользовательских аргументов. Отсутствие data не компенсировать D = C, пустой служебной Structure или искусственным полем data.

У R0 могут быть собственные исполняемые объявления и обычные доступные ссылки.
~~~

То же ТЗ, решения R09 и R13:

~~~text
Для выбранной исполняемой Structure C роль data выполняет её фактический parent. Специальное слово `data` и отдельный параметр data в call удаляются.
~~~

~~~text
`fn` описывает только сигнатуру, строго по тому же data-шаблону, включая поле return. Наличие return отличает возвращающий значение контракт от процедурного. `sub` удаляется.
~~~

Книга, [роли data и code](../../../docs/LMX_semantics.ru.md#data-code-roles): «В роли `code` всякая запись —
вызов»; «Объявлений Structure в коде нет: код пользуется именами Structure из данных»; правило «форма с
неизвестной головой объявляет Structure» действует только в данных.

До 2026-11-19 корень единицы запускался как Structure над самой собой. Каждая его запись читалась по обеим
ролям: в данных объявляла, в коде вызывала свою голову. Автор о таком запуске,
[журнал](../../2026-11-11.md#self-launch-no-own-rules):

~~~text
П7. -- просто следуйте общим правилам и генерируйте ошибки в случае неопределенностей, никаких своих правил для call(code code) нет, что получится то и получится, нет смысла обсуждать все конфликты
~~~

## Где они встречаются

Запуск над самой собой снят: у R0 данных нет, а данными исполняемой `C` служит `parent(C)`. Собственные записи
исполняемой `C` читаются в роли кода. Корень единицы — та `C`, которую исполняет R0. Тогда запись корня, которая
объявляет Structure, читается в роли кода, а в коде объявлений Structure нет.

## Программа

Пример ТЗ §8.3, записанный в корне единицы. Наблюдаемое — значение `seen` после последней записи.

```lmx
SumContext:
    int: a
    int: b
    return: int
    sum:
        return: a + b
int: seen SumContext\sum(a := 2; b := 3)
```

## Три чтения

1. Запись корня читается только в роли кода, как собственная запись любой исполняемой `C`. Первая запись —
   вызов головы `SumContext`. Structure с таким именем нет: данных у R0 нет, а в коде Structure не объявляются.
   Программа отказывает на первой записи. Объявить Structure в корне единицы нельзя. `sub` снят, `fn`
   вызываемого не создаёт, поэтому программа из одного файла не объявляет ничего вызываемого.
2. Запись корня читается по обеим ролям, как до 2026-11-19; снята только подстановка «данные R0 — сам корень».
   Проход по данным объявляет `SumContext` и место `seen`. Корень служит `parent`, то есть данными, для
   объявленных в нём Structure. Затем R0 исполняет те же записи в роли кода. Первая запись в роли кода —
   вызов своей головы: `SumContext` вызывается с блоком как фактическими аргументами, раньше последней строки.
   Исход определяет общий выбор по этим аргументам. Запись примера ТЗ в корне тогда не является объявлением без
   запуска, и нужно сказать, как её писать.
3. Запись, которая в проходе по данным объявила Structure, R0 в роли кода не исполняет; остальные записи корня
   исполняются. `seen` равно 5. Такого правила нет ни в ТЗ, ни в книге.

## Что ещё зависит от ответа

- Куда переносится часть `data` метода `main`. Сегодня программы тестов объявляют обычные Structure в части
  `data` метода — `sub: main () ( … )`, — а корень держит места и вызов `main()`
  ([план, подшаг 5в](../../../next_core_tasks_v3.md#m11)). Так записано потому, что запись корня с головой —
  Structure читается и запуском. `sub` снят; замена — Structure, данными которой служит её `parent`, — сама
  объявляется записью корня.
- Место корня `int: seen …`. При чтении 1 это место активации R0, и нужно сказать, что о нём печатает дамп
  после запуска. При чтениях 2 и 3 это поле корня в графе.
- Исходники ядра и транслятора на L2: объявления `fn:` и `sub:` стоят в корне файла.
