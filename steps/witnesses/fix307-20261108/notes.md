# Срез 307 — одна Structure как вся структура аргументов (CALL-WHOLE-ARGUMENTS-STRUCTURE)

fable_pc, 2026-11-08. Норма — [книга, whole-arguments](../../../provenance/semantics-book.md): вызов с единственным
аргументом-Structure не отличается от вызова с цепочкой её полей; решения автора 2026-11-07 ([журнал](../../../LMX_blog/2026-11-07.md):
позиционная передача одной Structure даёт ошибку только из-за неопределённости — когда определены два метода, один с одной
Structure в аргументах, другой с полным набором её полей; остальные случаи — общее сопоставление, ничего специально не
раскрывается; `f(v := s)` — отдельный случай) и 2026-11-08 ([журнал](../../../LMX_blog/2026-11-08.md): при двух подходящих
методах `f(s)` — ошибка, «не понятно какую функцию из двух вызывать»; применимость метода с формалом `d: S` устанавливается
при трансляции первой частью `implements`). Поручения Codex: CODEX-FABLE-AUTHOR-STRUCTURE-AMBIGUITY-RESOLVED-20261108044825Z-01
и CODEX-FABLE-AUTHOR-IMPLEMENTS-MATCH-20261108T052418Z-01 ([копии](../fix304-20261107/records/pins/)); приёмка —
`mytest(merge(mytest\args; (a: int: 5)))` = 35, та же Structure через переменную, обе однозначные формы, неоднозначный
случай, native и forced; ранние проверки имён и формы, AXBY и однократный выбор вызываемого сохраняются. Реестр —
[CALL-WHOLE-ARGUMENTS-STRUCTURE](../../defects.md).

## Проект

1. Решение — при трансляции, по статической форме фактического и формалам выбранного вызываемого (поручение автора: первая
   часть `implements` при трансляции). Связыватель (`lm_compiler_bind_value_actuals_into`) помечает кандидата — один
   позиционный фактический, который может дать Structure (имя, путь, `merge`, вызов; не литерал, не операция, не адрес `@`),
   у известного метода языка с хотя бы одним формалом — `L2ApplicationActuals.whole` = 2 и откладывает проверку опущенных
   формалов (`lm_compiler_bind_defaults_check`, прежний цикл связывателя) до решения CHECK; проход связывания
   (`lm_compiler_bind_calls`) идёт до готовности путей и описи использований, поэтому решать там нельзя.
2. CHECK (`lm_compiler_check_call_arguments` → `lm_compiler_whole_decide`): статическая форма фактического
   (`lm_compiler_whole_shape`: именованная Structure или объявленный результат `merge` по разрешённому листу пути
   `lm_compiler_value_span_path` — путь к числу, массиву, вызываемому не Structure; вызов — по модели результата; `merge`,
   записанный в вызове, — по операндам: типизированное объявление (форма 3), часть `args` вызываемого (форма 4, срез 304),
   именованная Structure или объявленный результат (форма 2); иной операнд — форма неизвестна). Форма «всё» (`lm_compiler_whole_fields`):
   каждое поле — формал своего имени и класса рода (число ↔ числовой формал, Structure (род 2/3/10 с моделью) ↔ Structure-формал;
   callable-, указательный, массивный формал полем не связываются — обычное позиционное чтение), каждый формал без поля — с
   построенным умолчанием (`lm_compiler_formal_default_kind` = 1, как требует связыватель от опущенного формала). Форма не
   «всё» — `whole` 0 и отложенная проверка опущенных формалов (прежний отказ `… has no argument …`). Форма «всё» — применимость
   второго чтения: первый формал — Structure-формал, остальные с умолчаниями, модель фактического подходит ему первой частью
   `implements` (`lm_compiler_descriptor_used` под `lm_compiler_uses_select(idx, 0)` — Consumer-relative проверка используемых
   путей, без исполнения преобразователей; `cand = req` — подходит) → оба чтения применимы — отказ «the Structure given to f is
   its argument p and its arguments: an ambiguous call». Одно чтение — `whole` 1; каждое Structure-поле допускается у своего
   формала той же первой частью (`lm_compiler_admit_consumer_ix`, обычное сообщение `implements is false in function argument`).
   Фактическое проверяется как выражение (`lm_compiler_check_value_span`, D-108), место допуска отмечается (`lm_compiler_admit_site`).
3. Ядро — одно связывание для обоих исполнителей после вычисления единственного фактического: `lmx_call_bind_whole(arena, code,
   data, count, whole, values, routes…)`: форма против текущей части `args` выбранного вызываемого — каждое поле значения
   называет формал (`lmx_implements_view_name`, `lmx_callable_named_formal`; имя без формала, имя только скрытого входа, два поля
   одного имени, безымянное поле — неявный `call`), каждый формал без поля держит текущее умолчание (читается, не вычисляется;
   нет — `call`); затем приёмы в порядке формалов вызываемого: число — маршрутом, который место вызова разрешило для типа формала
   (`lmx_walk_receive_selected`; маршрут k называет формал, числовой тип и вхождение ресивера), иначе неявный `convert`; прочее —
   собственным приёмом входа формала (`lmx_call_receive_formal`, срез 306); формал без поля — умолчание (`lmx_call_formal_default`);
   транспортное хранение каждого (`lmx_walk_argument_storage`). Значение не Structure — неявный `implements`; выбранное без
   собственной сигнатуры (результат `merge`, Structure как вызов) — `call`.
4. Native (`lm_compiler_emit_whole_call`): фактическое вычисляется один раз как графовая ссылка (`LmxWalkValue l2_wv`,
   `lmx_walk_value_ref(…, LMX_TYPE_LMX, …)`), маршруты числовых полей по формалам (`lm_compiler_emit_whole_routes`: для каждого
   числового поля и каждого числового типа — прямой ресивер программы, как у NAMED), `lmx_call_bind_whole(l2_call_arena, l2_c, 0,
   nact, @ l2_wv, l2_av, …)`, статусы `call`/`convert`/`implements` — неявные броски вызывающего; затем обычная отправка по `l2_av`.
   Обходчик: операнд `LMX_WALK_OP_WHOLE 65` (`OP_COUNT` 66) `[whole, payload, (formal, witness, occurrence)*]`
   (`lm_compiler_rw_whole_routed`; payload — `lm_compiler_rw_reference_span` графовой ссылки); `lmx_walk_selected_values` при одном
   записанном операнде формы WHOLE идёт в `lmx_walk_whole_values`: соответствие скрытого суффикса как у любого выбранного вызова
   (`lmx_callable_bind_written` над одним позиционным операндом), вычисление payload один раз, маршруты из кадра
   (`lmx_walk_whole_routes`), `lmx_call_bind_whole`, вычисление суффикса, публикация, готовая фаза с подстановкой формалов
   (`lmx_walk_selected_ready_values`, параметры `whole_values`/`whole_count`). Путь без сигнатуры (`lmx_walk_actuals_values`) при
   WHOLE — неявный `call`.
5. Инструмент (`tools/build.lm2`): поле `whole` записи `L2ApplicationActuals`, код операции `LMX_WALK_OP_WHOLE`, экспорт
   `lmx_call_bind_whole` (walk_value_names[174]), `lmx_implements_view_name` и `lmx_callable_named_formal` (implements_names[71–72]);
   `l2_driver.lm2`: слово WHOLE в `shape_op_code`.
6. Фикстуры: `whole_arguments` (оба исполнителя; 35 через `merge`, 35 через место, 46 через объявленную Structure без записи в неё,
   Structure-поле у Structure-формала 10, char-поле у int-формала через ресивер программы (считается, 25), место вызываемого 10,
   вызываемое других имён в месте — `call`, обычное единственное чтение 12, `take(p := Point)` 12, Structure с лишними полями —
   единственный аргумент 51, `mytest(a := 5)` 35), `whole_ambiguous_refused` (отказ трансляции по неоднозначности).

## Границы

- `merge`, записанный в самом вызове (`mytest(merge(mytest\args; (a: int: 5)))`, каноническая форма автора): решение о целом по статической форме (`lm_compiler_whole_merge_shape` читает операнды — типизированное объявление, часть `args` вызываемого, именованную Structure) есть, но раньше него трансляция фактического отказывает для каждого формала — merge-выражение сегодня опускается только как оператор объявления («merge expression is not lowered in this receiving context», `lm_compiler_check_word_value`, core.lm2; путь T7 покрывает только `merge` вызываемых). Предел реализации, не правило: фикстура `whole_merge_inline_refused` закрепляет отказ; та же Structure, держимая местом (`pack: merge(…); mytest(pack)`), — 35.
- Фактический без статической формы — свободное значение, результат вызова без модели результата, путь в неизвестный лист — остаётся позиционным: форма целого решается только трансляцией (`whole` 1 ставит CHECK), ядро при исполнении её не выводит; операнд WHOLE и вызов `lmx_call_bind_whole` появляются только по этому решению.
- «Два метода» автора недостижимы как перегрузка: два `fn` одного имени в одной единице отказывают при определении («duplicate definition», проба ea_w1), вызов выбирает одно вызываемое по имени до аргументов (срез 304). Реализованная неоднозначность — два чтения одного вызова (Structure единственным аргументом первому формалу `d: S`, применимая по первой части `implements` при трансляции, и её поля аргументами); решение автора 2026-11-08 выполнено в этом объёме.
- Поля значения в ядре — его именованные ячейки (`lmx_implements_view_name` ≠ 0). Безымянная ячейка пропускается: native-раскладка объявленной Structure держит ячейку шага рядом с каждым местом (ширина процедуры — kids + steps, `lm_compiler_ns_width`/`lm_compiler_m_width`), её значение при исполнении — STRUCT без имени места. Анонимное поле (например `(5; a: int: 3)`) до связывания не доходит — трансляция не решает для него целого (`lm_compiler_whole_fields`: имя поля должно совпасть с формалом); ядро анонимное поле от ячейки шага не отличает — граница физической раскладки, не правила.
- Форма целого у вызова через вызываемое место проверяется ядром после вычисления единственного фактического (имена полей читаются из значения); трансляция решила целое по статической форме против объявленного вызываемого, ядро проверяет против держимого сейчас. Фикстура `other_names` подаёт объявленную Structure без эффектов, поэтому порядок «неявный `call` до эффектов фактического» у целого вызова через место с держимым другого состава имён не измерен; перенос проверки до вычисления по статическим именам не сделан.
- Заголовок `lmx_implements.h.lm1` (рукописный текст в tools/build.lm2) не объявляет `lmx_implements_view_name` и `lmx_callable_named_formal`, как не объявляет и прежние экспорты `lmx_callable_part`, `lmx_implements_own_head_slot`: ядро зовёт их внутри своей единицы трансляции (driver.o), программы зовут только `lmx_call_bind_whole`, объявленный генерируемым `lmx_walk_values.h.lm1` (`--header`). Объекты rt170c/rt170d равны rt170b по байтам в части экспорта: список `--machine` меняет только заголовок.
- Native передаёт связывателю `data` = 0; ядро берёт собственные данные вызываемого (`lmx_call_unary_data`), как у связанного вызова 306. Маршрут приёма есть только у числового поля при числовом формале (char → int через ресивер программы, один вызов); число иного типа без ресивера — неявный `convert`, как у 305.
- Границы 305–306 (скрытый вход EXEC, поданный отсутствующим; путь `lmx_walk_actuals_values` без приёма формала) не затронуты; операнд WHOLE в `lmx_walk_actuals_values` — неявный `call` (путь без формалов).
