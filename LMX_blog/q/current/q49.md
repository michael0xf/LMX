# Q49. Формула допуска вызываемого листа при необязательных формалах: как записать `sig(aVar.p) = sig(bVar.p) = ExpectedSig(Consumer, p)`

Состояние: 2026-09-28, fable_pc, по заданию автора `docs/new_parts/dirty.md` §2 («If the existing meaning of `sig`, `ExpectedSig`, and `implements` does not uniquely determine how to express this, ask the author before choosing a new formula»). Проза §7 уже описывает механизм автора; формула оставлена как была. Вопрос — только о записи формулы.

## Два положения

1. Книга §7, формула `implements` (`provenance/semantics-book.md`, блок `implements(aVar, bVar, Consumer) ⇔ …`):

```text
∧ (invoked_callable(p) ⇒
    sig(aVar.p) = sig(bVar.p) = ExpectedSig(Consumer, p)
  )
```

   Это точное равенство трёх сигнатур; полная сигнатура листа включает объявленные и динамические входы, имена, порядок, способы передачи, результат, выходы и ABI.

2. Решение автора (`dirty.md` §2; ответ на Q48 §5): проверка относительна к Consumer — использование `p` в Consumer задаёт требования; принимаемый интерфейс кандидата обязан их принять; недостающие входы формируются дефолтами и допустимыми преобразованиями; сформированный вызов должен удовлетворять описанию выбранного вызываемого; результат/выходы/способы передачи — Consumer. Необязательный формал не удаляется из `sig`.

## Наименьший пример с разным результатом

```text
A: fn (int: x; int: y = 5) int      # y — формал с дефолтом
B: fn (int: x) int
Consumer1 использует p как f(1)
Consumer2 использует p как f(1; y: 25)
```

По (1), с образцом `bVar = B`: `sig(A) ≠ sig(B)` (у A есть `y`) — A отвергается для Consumer1, хотя по (2) A допустим (дефолт формирует `y`). По (1), с образцом `bVar = A`: B отвергается для обоих; по (2) B допустим для Consumer1 и недопустим только для Consumer2 (нет `y`).

## Один вопрос

Как записать формулу, чтобы она выражала механизм (2)? Два варианта записи, между которыми я не выбираю сам:

```text
(а) invoked_callable(p) ⇒
        accepts(sig(aVar.p), ExpectedUse(Consumer, p))
        ∧ formed(aVar.p, ExpectedUse(Consumer, p)) ⊨ descriptor(aVar.p)
        ∧ result_exits_modes(aVar.p) ⊨ ExpectedSig(Consumer, p)
    — образец bVar в проверке вызываемого листа не участвует: требования задаёт использование в Consumer;

(б) оставить `sig(aVar.p) = sig(bVar.p) = ExpectedSig(Consumer, p)`, определив `sig` здесь как
    «сигнатура сформированного вызова» (после дефолтов и преобразований), а `ExpectedSig(Consumer, p)` —
    как требования конкретного использования; тогда равенство — равенство сформированного вызова
    ожидаемому, и необязательные формалы в нём есть ровно тогда, когда Consumer их подаёт.
```

Или третья запись автора.
