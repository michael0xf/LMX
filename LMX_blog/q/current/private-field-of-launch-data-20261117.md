# Видит ли запущенный код поле своих данных, объявленное `private:`

Дата: 2026-11-17. Задаёт исполнитель (сессия fable_pc). Статус: **OPEN**.

Два исполнителя отвечают на одну программу по-разному, и норма читается двояко.

```lmx
int: seen 0
D: private: (int: x 5)
C: node\seen := x
call(D C)
```

- **А. `seen` равно 5.** Корневые объявления данных запуска дают входные места вызова
  ([книга](../../../docs/LMX_semantics.ru.md#fields): «Namespace вызова готовится по корневым объявлениям `data` и
  `code`»). `x` для `C` — его собственное место, а не динамическая связь с чужим полем; так же формал под
  `private:` виден своему коду (`fn: DataPrivate (private: (int: x 20)) int`, `return: x * 100 + …` даёт 2010).
  `private:` действует на вызовы, которые делает сам `C`: их свободное `x` это поле не получит. Так отвечает
  чистый граф в трёх режимах (замер sonnet).
- **Б. Запуск отказывает**, а при корневом `int: x 7` читается 7. Поле данных запуска под `private:` коду `C` не
  даётся: `x` в `C` — свободное имя, и оно ищется динамически. Так отвечает прежний путь исполнения (замер opus);
  так исполнитель назвал норму в снятом вопросе о признаке.

Слова автора 2026-11-15: «ресивер private: который лишает вызовы динамической связи с этим полем, прямой видимости
откуда угодно его это не лишает».

Предложение исполнителя: А. Чистый граф не чинится под Б до ответа.
