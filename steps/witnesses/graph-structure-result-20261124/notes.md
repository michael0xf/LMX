# Результат-Structure структурного вызова по описанию блоком, 2026-11-24

Принят компонент 21.7 K3 (вложенный результат, часть 1). Результат вызова, описанный в данных вложенным блоком мест
(`return:` с `int: first`, `int: second`; книга `#structure-result`, `#return-in-data`), — это Structure, которую
вернуло тело, и она переходит без копирования: запись через принятую ссылку меняет поля возвращённой Structure.
До среза такой вызов отвечал 5: запуск нёс только скалярное слово и `return: @`.

## Решение дизайна

Решение codex (`CODER-K3-NESTED-DESIGN-20261124-01-ANSWER`, после запроса к Astra): блок выбирается **один раз, когда
вызов готовится** (`lmx_graph_launch_structure_value`), и кадр хранит его в **одном новом поле**
`result_description` записи `LmxGraphFrame` — по тождеству, без копии; поле отмечается сборщиком в существующем
`lmx_gc_graph_frames`. Метки-слова в графе нет, и перечитывание `frame\data` в момент `return` нет: тело может
заменить `D\return` другим блоком и собрать мусор — вызов обязан остаться с тем блоком, по которому он начался
(свидетельство ниже различает эти два устройства). Выбранное блок закрепляется исполненным корнем до установки кадра.
`frame\result` остаётся за скаляром и `@`. Форма записи решает по строению: каждое поле блока объявляет место —
одно поле или несколько; не по условию «полей больше одного».

Части: (1) одно выражение, возвращающее существующую Structure, сверяется с выбранным описанием существующим
`lmx_graph_source_interface`; только его YES — результат, UNKNOWN — не совпадение, инициализатор не исполняется,
Value передаётся тем же, с той же ссылкой; (2) хвост `return: 1 2 3` с построением результата по полям — открыта.

## Свидетельства

**Строки Graph** (12 строк, 36 проверок в interp/native/forced, пакет `rows.tsv`). Приняты: `sc_nested_identity`
(`@: result Box`, `observed 7`, `D\Box\second 11` — запись через принятую ссылку меняет возвращённую Structure),
`sc_nested_emitted_body` (тот же вызов в эмитированном теле `fn`, маршрут K4), `sc_nested_extra_field` (у
возвращённой Structure есть поле сверх описания), `sc_nested_explicit_call` (`call(code := D\C)`),
`sc_nested_one_field` (блок из одного места — описание Structure, а не скалярное слово), `sc_nested_statement`
(вызов-оператор). Отказы с сохранившимся эффектом: `sc_nested_missing_field` (нет `second`), `sc_nested_number`
(число под блоком из двух мест), `sc_nested_statement_mismatch` (контракт вызова — тот, что описывают его данные,
потреблён результат или нет), `sc_nested_one_field_number` — 4; `sc_nested_bare_return`,
`sc_nested_end_of_body` — 5 там, где значение потребляется. Значения ожиданий выведены вручную и сверены с AFTER
интерпретатора; AFTER трёх режимов равны в каждой строке. На принятом до срезе комплекте все 12 строк красные:
интерпретатор отвечает 5.

**Самопроверка ядра** `graph_structure_result` (`gsr_check` = 7 в native и forced, корни 0 и 1). Три Structure
данных получают блоки, построенные во время выполнения; нативный Swap внутри тела проверяет по тождеству, что кадр
структурного запуска в цепочке держит выбранный блок, заменяет ребро `return` данных другим блоком и чистит следующее
поколение; затем проверяет, что откреплённый от данных блок цел и его chunk отмечен в этом проходе. Случай 1:
описание x, y, подставлен x, y, z — Box (x, y) принят. Случай 2: описание x, y, z, подставлен x, y — Box отклонён (4).
Случай 3: описание x, y, подставлен x — Other (x) отклонён (4). Блок пробного файла, которого ничто не именует,
уходит вместе со своим chunk при чистке.

Мутанты (у каждого своя стадия и runtime, репозиторий не менялся): **A** — блок читается из данных снова
там, где тело возвращает (отвергнутое устройство): случай 1 отклоняет Box с ответом 4. **BC** — блок не отмечен кадром
и не закреплён корнем запуска: чистка уносит его chunk, проверка 4 даёт 106. Оба пойманы; поодиночке мутант B (только
без отметки кадра) и C (только без корня) эта самопроверка не различает: во время запуска каждое из двух держит блок.

Прочие самопроверки ядра (`dyn/graph_*`, 13 строк): как на принятом runtime — все зелёные, кроме тех же четырёх
известных отказов `graph_call_frames`.

**Регрессия** — 125 строк: список K4 (113 строк: K1a 8, K3, return-at, typed297, compat и 76 строк полной приёмки

**Скорость.** Два замера.
(1) Функции запуска внутри нативного модуля самопроверки (по 10 000 структурных вызовов-операторов подряд, два
промежутка; принятый runtime HEAD и кандидат): вызов без части `return` — 31/34 мкс против 30/34; `return: int` —
39/57 против 39/55; новый путь (результат блоком) — 56–63 мкс на вызов, из них сверка
`lmx_graph_source_interface` — 2–3 мкс (10 000 сверок за 16–32 мс). На неизменённых путях комплекты равны в пределах
разброса.
(2) Интерпретируемый цикл Main целиком (16 000 итераций, 9 чередующихся раундов, медианы): вызов-оператор — база
1,276 с, контроль 1,325 с (+3,8 %), кандидат 1,373 с (+7,6 %); скалярный результат — 1,797 с, контроль 1,910 с
(+6,3 %), кандидат 1,922 с (+6,9 %). Контроль — ядро HEAD с одной никогда не вызываемой функцией в начале модуля (тот
же алгоритм, другая раскладка кода): его отличие от базового исполняемого файла того же порядка, что и отличие
кандидата. Добавленная работа на этих путях — O(1) (один поиск части `return` у данных без неё и несколько
сравнений), поэтому разница целого запуска отнесена к раскладке кода пересобранного исполняемого файла, а не к
алгоритму; подтверждение счётчиками операций — в срезе диагностики (ниже).

Найдено при замере и не зависит от среза (на принятом комплекте так же): цена вызова растёт с числом вызовов — между
первым и вторым десятком тысяч 39 → 57 мкс; таблица «адрес → имя» графа (`g\names_len`) растёт на одну строку на
каждый вызов с одной явной записью по пути в теле (10178 → 60178 за 60 000); результат-ссылка, записываемый в корневое
место в цикле, растёт быстрее (предельная цена итерации 224 → 307 мкс). Отдельный срез диагностики и устранения
роста — после части 2.

## Границы

- Хвост `return: 1 2 3` (построение результата по полям описания) — часть 2, открыта: сегодня отвечает 5.
- Вызываемое пула FN (`fn`) сохраняет своё правило; результат блоком принадлежит только обычной Structure,
  исполняемой над другим данными.
- Тело обычной Structure не получает нативной функции (`lm_graph_collect_methods` берёт только `fn` и `sub`):
  структурный запуск идёт интерпретатором ядра во всех трёх режимах; эмиттер не менялся.
- Сверка с описанием — существующая проверка интерфейса по полям: типы полей не сравниваются детально, значение
  инициализаторов описания не участвует.
- Полный набор, G1/G2 и fixedpoint на этом срезе не запускались: одна широкая проверка — на границе связанного
  изменения (после части 2), поскольку изменилась запись кадра.
