# Общие операции, найденные при сравнении с Common Lisp

Статус: **реализации на LMX подготовлены; исполнение LMX — NOT_RUN**.
Исходник: [coreStandardLisp.lmx](src/coreStandardLisp.lmx).
Экспортируемые имена и точные размеры: [metadata](CORE_STANDARD_LISP_ADDITIONS.json).
Набор приёмки: [core_standard_lisp_cases.json](tests/core_standard_lisp_cases.json).
Обе формы всех имён используют один алгоритм по [общему договору](../../OPERATION_FORMS.md) и [публикации](PUBLICATION_CONTRACT.md).

Модуль решает задачи обычными массивами, записями `{type,value}` и существующими
вызовами. Он не вводит тип Lisp-списка, таблицу символов, отдельный интерпретатор
или новый способ связывания переменных. Свободные имена по-прежнему проходят по
обычной цепочке вызовов, в том числе через функции, которые их не используют;
`private` сохраняет свои два фильтра.

## Таблицы ассоциаций и свойств

| Функция | Входы | Результат |
| --- | --- | --- |
| `assoc` | `rows; key; same=0; keyIndex=0` | `Maybe` первой исходной строки, соответствующей ключу |
| `pairlis` | `keys; values; tail=()` | Новый внешний массив пар, затем строки `tail` |
| `getProperty` | `properties; key; same=0` | `Maybe` значения первого найденного свойства |
| `setProperty` | `properties; key; value; same=0` | Тот же изменённый массив свойств |
| `removeProperty` | `properties; key; same=0` | `int` 1 при удалении первой пары, иначе 0 |
| `getProperties` | `properties; indicators; same=0` | `Maybe` записи с полями `key`, `value`, `index` |

`rows` — массив строк. Строка является обычным массивом или Structure; все
поля сверх ключа и значения сохраняются. `keyIndex=1` решает обратный поиск
по значению тем же алгоритмом. Пустая строка пропускается; непустая строка без
нужного поля получает обычную ошибку `ReceiverIndex`. Найденная строка не
копируется. Никакая запись не исполняется при её выборе.

`properties` — обычный массив `[key0,value0,key1,value1,...]`. Его длина должна
быть чётной: нарушение даёт `FxShape` до сравнений и изменений. Это может быть
`[]@` с разными типами или плотный массив одного совместимого типа. Значения
передаются полными записями; нулевое число, нулевая ссылка и пустой массив
сохраняются как присутствующие значения. Их нельзя спутать с `none()`.

При `same=0` действует общее равенство `FxValueSame`: обычное скалярное сравнение и поэлементное равенство конечных ациклических последовательностей. Явный `same` принимает два готовых значения и возвращает `int` с обычным значением
истинности. Он должен задавать отношение эквивалентности и не менять состав
просматриваемых массивов. Единственный `FxKeyIndex` проверяет ключи в порядке
входа и останавливается на первом совпадении. Для одиночного поиска порядок
аргументов — `(queryKey, storedKey)`; `getProperties` вызывает тот же поиск
индикаторов для очередного ключа свойства, поэтому сравнивает
`(propertyKey, indicator)`. Отношение эквивалентности делает выбор результата
одинаковым; число и порядок вызовов остаются описанными здесь.

`setProperty` заменяет только первое значение; остальные одноимённые свойства
сохраняются. Новый ключ добавляется в конец. `removeProperty` удаляет только
первую пару. Обе операции используют существующий `replaceRange`: снимок
вставляемых значений и проверка типа предшествуют записи, дескриптор цели
сохраняется. Обёртка не обещает дополнительной транзакции при нехватке памяти.
Ошибка `same` возникает до первого изменения этим вызовом.

`pairlis` проверяет равенство длин, затем переиспользует `zip` и `concat`.
Порядок новых пар совпадает с входным. Объекты ключей, значений и готовые строки
хвоста сохраняют свои цели; глубокого копирования нет. Несовпадение длин даёт
`FxShape`, а не молчаливое усечение.

`getProperties` выбирает первую подходящую пару в порядке **свойств**, независимо
от порядка списка индикаторов. Возвращаемый `index` — индекс её ключа в том же
массиве. Это явное отличие представления от CL `get-properties`, который также
возвращает хвост списка, начинающийся с найденной cons-ячейки. Здесь не обещана
несуществующая cons-ячейка или изменяемый хвост массива.

Стоимость одиночного поиска и изменения — O(n) сравнений/перемещений в худшем
случае; `getProperties` — O(nm) для n свойств и m индикаторов. Эти операции не
называются универсальной хеш-таблицей. Новые алгоритмы поиска/мутации не
размножены по каждой публичной функции.

## Поиск и замена в последовательностях

| Функция | Входы | Результат |
| --- | --- | --- |
| `mismatch` | `first; second; same=0` | `Maybe` первого различающегося индекса |
| `searchSequence` | `items; pattern; same=0; start=0` | `Maybe` начала первого полного вхождения |
| `substitute` | `items; oldValue; newValue; same=0` | Новый массив того же физического профиля |

`mismatch` сравнивает элементы слева направо и останавливается на первом
различии. Если общий префикс совпадает, но длины различаются, результат содержит
длину короткого входа; два одинаковых, в том числе пустых, массива дают `none()`.
`searchSequence` использует единственный `FxSequenceDifference` для очередного
кандидата. Этот же диапазонный проход обслуживает `equalFields`, литеральные
Patterns и `sameAs`; оба смещения и длина проверяются без повторения сравнения. `start` должен лежать в `[0,length(items)]`; иначе `ReceiverIndex`.
Пустой образец находится в `start`, без вызовов `same`.

`substitute` заменяет каждое совпадение, сохраняя порядок, длину и плотный тип
исходного массива. Неподходящий для выбранной плотной цели `newValue` даёт
`SequenceElement`, если действительно встретилось совпадение. Исходный массив
не меняется. Внешний результат новый, а выбранные ссылочные значения сохраняют
свои цели. Все три операции используют один `FxValueSame`, тот же, что и
ассоциативные функции выше.

Это полный договор перечисленных LMX API, с общим default либо явным equality callback и линейным
направлением поиска. CL-варианты `:key`, `:from-end`, `:count` и произвольные
парные `:start/:end` не подразумеваются. При необходимости диапазон задаётся
уже имеющимся `slice`; собственная несокращаемая матрица опций не дублируется.
`mismatch` и `substitute` требуют O(n) сравнений, простой `searchSequence` —
O(nm) в худшем случае; обещания KMP или универсального хеширования нет.

## Один callable как обычный операнд Expression

`asOperand(operation; priority)` создаёт обычный callable, у которого DATA
соответствует [общему структурному требованию операнда](../../LMX_semantics.en.md#operand-receiver): `left`, `right`, готовые
константы `PASS_ARGS_AS_IS=0` и `PRIORITY`. `priority` задаётся явно, например
`sys\priority("+")`. Возвращаемый callable имеет настоящий обычный результат
**R исходной функции**, включая отсутствие результата для процедуры.
Это не обращение к неявному системному объекту-шаблону. Прямые объявления
пакета явно копируют обычный `FxPreparedOperands` и отдельно задают приоритет;
все значения перечислены в [договоре публикации](PUBLICATION_CONTRACT.md#prepared-operand-data).

```lmx
Numbers:
    int: a
    int: b
    int: c
    int: d
    int: e
    return: int
    add:
        return: (+ a b c d e)

Example:
    return: @
    run:
        throws: copy(FxThrows\selection)
        @: myOp asOperand(Numbers\add; sys\priority("+"))
        return: ((myOp 1 2 3 4 5); (1 myOp 2 3 4 5))
```

Оба результата — 15. Это два положения **одного** операнда с одним телом;
особого «префиксного типа», второй регистрации или второго парсера нет.

Первое написание не подаёт `left` и подаёт пять значений в `right`. Второе
подаёт 1 в `left`, затем четыре значения в `right`. Эти разные векторы сохраняются
до входа в созданный метод операнда. Его тело явно вызывает общий
`RxLogicalArguments` и собирает последовательность: присутствующий `left`, если
он есть, затем все элементы `right`. Пустой `right` — присутствующий массив.
Сборка — алгоритм этого метода, а не автоматическое выравнивание аргументов
парсером, транспортом или универсальным binder перед вызовом.
Поля `left/right` закрыты через `private`, поэтому одноимённая переменная
вызывающей функции не подставляется вместо отсутствующего левого actual.

Каждый полученный элемент — один готовый actual. Массив, строка, Structure и
ссылка на функцию остаются одним значением, без повторного W/E, автоматического
раскрытия или вызова сохранённой функции. Группировщик Expression обрабатывает
дерево, приоритеты, группы и потоки; отдельный адаптер применения собирает left
в один actual, а right — из ссылок на элементы потока текущего уровня. Это
разные работы; `RxLogicalArguments` и библиотечный `asOperand` получают уже
подготовленный вектор, без дополнительного прохода раскрытия.
Формы без actual допустимы для исходной функции с подходящим
обычным договором. Опциональные входы, `required`, defaults и динамическое
связывание исходной функции проверяются обычным транспортом готовых actual.

Адаптер использует подготовленные значения; короткое замыкание или управление
неисполненным CODE требуют собственного обычного raw-операнда с
`PASS_ARGS_AS_IS=1`. `asOperand` не выдаёт eager-функцию за такой оператор. Все ресиверы уже входят в Expression; для иных ролей общий транслятор сохраняет TYPE, NAME, DATA, RAW/BODY и PLACE вместо вызова этого VALUE-адаптера.
Именованные actual исходной функции не кодируются внутри `right`: при
необходимости остаётся прямой обычный вызов `operation(name := value)`.

Конструирование не вызывает исходную функцию и не читает её опциональные
значения. `signatureData` переносит полный результат R без печати и потери
структурного требования. Однократный `fromLmx` создаёт лишь DATA с числовой
готовой константой приоритета; её десятичную запись даёт общий `format`.
`FxBuild` строит обычные owner→DATA→CODE, используя собственный договор DATA.
На каждом применении работает одно общее тело: сбор actual, `FxTry`, точная
передача исходного имени/полезной нагрузки через `FxKernel\raise`, обычный
возврат R. Это не превращает все ошибки в одно имя `FxCallFailure`.

Существующий provider `callable` обязан сохранить DATA с его константами и
модификаторами после выхода фабрики; это проверяемое требование текущего
строителя, а не новая kernel-функция. Для procedure готовый void-исход не
превращается в нулевое значение выражения. Не допускается исполнение другой
native ABI под видом новой функции.
