# Запись результата фабрики `add5: makeAdder 5` и определение именованного тела

Статус: вопрос автору задан Codex 2026-10-04 (о передаче сообщает ответ
FABLE-CODEX-20261004-11); ответа пока нет. Это вопрос о языковом правиле, не
выбор следующего тикета. До ответа спецификация не меняется, ожидания
действующих строк не переворачиваются, запись именованных фактических фабрики
не реализуется.

## Два источника автора

Пример makeAdder, [журнал 2026-09-24](../../2026-09-24.md). Выдержка,
дословно:

```text
fn: makeAdder (int: n) fn: (int: x) int
    fn: addN (int: x) int
        return: n + x

    return: addN

add5: makeAdder 5
add100: makeAdder 100

[add5: 1; add100: 1; add5: 1]
Ожидаемый результат:

[6 101 6]
После makeAdder 5 структура add5 логически содержит:

fn: addN (int: x) int
    int: n 5
    return: n + x
```

Ответ на [Q58](../q58.md), 2026-10-01. Дословно:

```text
Q58:
****
fn: put (int: n) int
return: n
Batch: (put: 7)
****
Batch разумеется хранит одну структуру  (put: 7) в которой "сохраненный вызов" put: 7. "сохраненный вызов" не понимаю что означает, тут максимум что может быть нативный вызов у самого Batch так как дерево в бинарном виде сохранятся целиком (а комментарии -- с текстом, имено тоже можно найти в таблице) и интерпретатору можно попытаться отдать
```

## Действующие якоря

- [Семантика §9](../../../docs/LMX_semantics.ru.md#construction), строка 569:
  блочная, короткая и скобочная записи выражают одно применение «голова
  принимает хвост»; строка 585: скобки сами по себе не являются признаком
  вызова, определение не вычисляет результат.
- [Q58](../q58.md): пустота, число аргументов, скобочная, короткая и блочная
  форма и конкретное имя не предлагаются как различитель объявления и вызова.
- [T6](../../../steps/callable-merge-t6.md): корень `add5: makeAdder 5`
  сохраняет узел; `add5: 1` его вызывает.
- Реализация: `l2_unit_role` считает оператор значением вызова, когда хвост
  отсутствующей головы начинается атомом метода юнита (`l2_call_value`), и
  объявлением именованной Structure, когда хвост — один вложенный Frame.
- Строки гейта. Запись результата: строки T6 и удерживаемого callable
  (`unit_held_call_*`, `unit_named_actual_held`). Удержанное тело:
  `unit_q58_batch_retained` (`Batch: (put: 7)`),
  `unit_named_struct_call_body_retained` (блочная форма `q:` с телом
  `show(7)`).

## Формы P0

Измерено 2026-10-04 на `a96d43c3`, дерево выведено из P0 отладочной сборкой.

| Запись | Дерево |
| --- | --- |
| `h2: make2 100` | Frame `h2` [ атом `make2`, атом `100` ] |
| `h2: make2 n: 100` | Frame `h2` [ атом `make2`, Frame `n` [ `100` ] ] |
| `h2: make2 (n: 100)` | Frame `h2` [ атом `make2`, Structure [ Frame `n` [ `100` ] ] ] |
| `h2: make2(n: 100)` | Frame `h2` [ Frame `make2` [ Frame `n` [ `100` ] ] ] |

Блочная запись `h2:` с телом `make2(n: 100)` даёт то же дерево, что и
последняя строка.

## Что измерено

- `h2: make2 100` при отсутствующем `h2`: фабрика исполняется в этом
  операторе, `h2` удерживает её результат, `h2(1 2)` его вызывает.
- `h2: make2(n: 100)` при отсутствующем `h2`: после оператора фабрика не
  исполнена; голое `h2` исполняет её один раз, с привязанным именованным
  фактическим. Это поведение Q58.
- `h2: make2 n: 100` и `h2: make2 (n: 100)`: отказ, `unknown method` у `n`.
- Чтение хвоста из одного вложенного вызова как значения головы переводит
  `unit_named_struct_call_body_retained`, `unit_named_actual_structure_body`
  и `unit_q58_batch_retained` из OK в отказ (эксперимент на отдельной копии
  транслятора).

## Вопрос

Сохраняет ли короткая запись `add5: makeAdder 5` своё историческое значение:
`add5` связывается с результатом вызова `makeAdder` с аргументом 5, и тогда
её запись с именованным фактическим — `add5: makeAdder n: 5`? Или она тоже
подчиняется общему правилу определения именованного тела из Q58: `add5` —
именованная Structure, удерживающая оператор, а результат фабрики
принимается отдельной явной записью?

Различие в двух одинаково устроенных записях: в первой хвост головы
начинается именем известного метода и продолжается его аргументами, во
второй хвост — один вложенный оператор с известной головой. Действующие
строки держат для первой запись результата, для второй — удержанное тело.
