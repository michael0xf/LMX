## Q19.1: какой Frame закрывает terminal `return`

Источник: ответ автора на `q19.md` в чате fable 2026-09-24, дословно:

```text
любая структура не закрыввается return. Закрываеться return может только callable-структура (любая), без аргументов если нет возвращаемого значения
```

Итог: обычная (не-callable) именованная Structure `return`-trailer'ом не закрывается; `return` закрывает только callable-Structure — любую (`fn`, `sub`, `fm`), голый `return` без аргумента — когда возвращаемого значения нет. Чтение Б из `q19.md` принято; ошибочная фраза книги «включая обычную Structure» — к правке Codex.

Источник: уточнение автора к Q19.1 в чате fable 2026-09-24, дословно:

```text
" (любую: fn/sub/fm)" -- любая у нас это включая тип "именованная структура" (сегодня добавленный как callable)
```

Итог: «callable-структура (любая)» включает именованную Structure (по норме 2026-09-23 она исполняема голым атомом, т.е. callable); значит `return`-trailer закрывает и обычную именованную Structure. Моё сужение «fn/sub/fm» было ошибкой.

## Q19.3: управляющие головы при `return`-trailer

Источник: ответ автора на `q19.md` в чате fable 2026-09-24, дословно:

```text
Да. Q19.3 A1 но пример выше корректный "if: c / r: 1 / else: / r: 2 / return: r" так как по правилам парсера не требуется закрывать один уровень. Явно закрывать обязательно только больше уровней чем 1. То есть return стоит в теле какого-то внешнего метода.
```

Итог: Q19.3 = **А1** — в P0 явная таблица управляющих голов (`if`/`else`/`while`/`for`/`until`…), которые `return` не закрывает; пример с `else:` корректен как есть: по правилам парсера один уровень явно закрывать не требуется (обязательно — только более одного), поэтому `return: r` в колонке метода — оператор тела внешнего метода.
