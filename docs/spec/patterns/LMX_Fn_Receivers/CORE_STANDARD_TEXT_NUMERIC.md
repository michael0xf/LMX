# Последовательности, текстовые и числовые профили ядра

Редакция 23 ноября 2026. Реализации находятся в [coreStandardText.lmx](src/coreStandardText.lmx) и [coreStandardNumeric.lmx](src/coreStandardNumeric.lmx). Явные профили и точные текстовые представления находятся в [sequence_profiles.lmx](src/sequence_profiles.lmx). Канонические lowerCamelCase-имена имеют обе формы; профили используют общие алгоритмы и [публикацию](PUBLICATION_CONTRACT.md), а не отдельные пользовательские библиотеки.

## Что уже было в ядре

Точное равенство текста уже выражается как `matches(byteText(first); second)`. Текстовый аргумент Pattern принимается буквально: отдельный `literal(second)` не нужен. `wholeMatch` возвращает Maybe с Match, а `matches` возвращает int. Регистр учитывается, Unicode-нормализации нет. Публичный `sameText` не добавляется.

По той же причине не добавляются вторые публичные реализации `startsWith`, `endsWith`, `replaceText` и `splitText`. Используются существующие `hasPrefix`, `hasSuffix`, `replace` и `split` с выбранным `byteText` или `utf8Text`. Имена в конечных контрактах ошибок сравниваются существующим `equalFields`. Его тело и буквальный Pattern используют один `FxSequenceDifference`; отдельного текстового цикла, case folding или Unicode-нормализации в общем равенстве нет.

Основание: [Pattern operations и TextView](../../CORE_SEQUENCES_REGEX.en.md#patterns), [matching source](src/regex/operations.lmx), [literal source](src/regex/primitives.lmx).

## Текстовые операции

Основные операции принимают общие последовательности и сохраняют их фактические профили; прежнее имя параметра `text` не сужает вход до `char[]`. Текстовое представление добавляет только свои defaults, правила кодировки и точный результат `char[]`. В байтовом профиле индексы, ширина и длина измеряются octet-элементами, а не графемами или экранными колонками. Точное unsigned-octet упорядочение `compare` проверяет восьмибитный профиль. Для поиска по Unicode scalar values используется существующий `utf8Text` с Pattern. Никакого неявного locale или case folding нет.

| Имя | Контракт |
| --- | --- |
| `indexOf(text; part; start=0; same=0)` | Первый индекс подпоследовательности; отрицательный start становится 0, отсутствие даёт −1. Пустой part совпадает с допустимой границей. Default равенства общий; explicit same получает целые элементы |
| `lastIndexOf(text; part; start=length(text); same=0)` | Последний индекс не правее start; перекрывающиеся кандидаты проверяются, start ограничивается допустимым диапазоном |
| `compare(first; second; order=0)` | Лексикографический −1/0/1 по выбранному порядку элементов; текстовый профиль сохраняет unsigned-octet сравнение. Равный префикс разрешается сравнением длин |
| `trim(text; chars; predicate=0; same=0)` | Новый срез без принятых граничных элементов с обеих сторон. Текстовое представление по умолчанию использует SPACE, TAB, CR, LF, VT, FF; для общего T множество или предикат задаётся явно |
| `trimStart(text; chars; predicate=0; same=0)` / `trimEnd(...)` | То же общее тело для одной стороны и те же правила текстового default |
| `cycle(items; count; rejectNegative=0)` | Общий конечный повтор. Неположительный count даёт пустой результат; с rejectNegative отрицательный count даёт SequenceSize. Типизированный текстовый результат сохраняет char[] |
| `padLeft(text; width; fill)` / `padRight(...)` | Дополнить до width общими cycle/slice/concat; пустой fill допустим только без расширения. Только текстовое представление имеет default `" "` |
| `translate(text; from; to; same=0)` | Одновременная замена целого элемента по двум таблицам одинаковой длины; первое соответствие выигрывает, неизвестные элементы сохраняются |
| `join(parts; separator)` | Соединить готовые последовательности одним алгоритмом. Для текста separator по умолчанию `""`; скрытого преобразования других значений в текст нет |
| `format(value; base=10)` / `format(value; profile; arguments=())` | Точный целочисленный профиль: знаковое bigint, база 2…36, буквы a…z. Общий профиль вызывает явный кодек над целым значением и дополнительными аргументами, сохраняя его результат |
| `parse(text; base=10)` / `parse(source; profile; arguments=())` | Точный bigint-профиль читает весь вход с необязательным знаком; оба регистра цифр допустимы, пробелы/0x/хвост запрещены, ошибка NumericDomain. Общий профиль задаёт явный декодер |
| `removePrefix(text; affix; same=0)` / `removeSuffix(...)` | Удалить одно совпавшее граничное вхождение под общим равенством; всегда вернуть новый срез фактического профиля |


Прежнее имя текстового повтора удалено; его отрицательная граница сохраняется вызовом `cycle(text; n; rejectNegative := 1)`. Это параметр политики единственного тела.

`indexOf` и `lastIndexOf` используют один проход с выбранным направлением; последний кандидат обрабатывается без переполнения индекса. `trim`, padding и удаление affix также имеют по одному общему телу. Срезы, склейка, выделение памяти, проверка размеров и повторение переиспользуются из последовательностей, а не реализуются заново для строк.

Выбор знакомых имён сопоставлен с первичными справочниками [Julia Strings](https://docs.julialang.org/en/v1/base/strings/), [Perl functions](https://perldoc.perl.org/perlfunc) и [Python text sequences](https://docs.python.org/3/library/stdtypes.html#text-sequence-type-str). Собственные границы LMX перечислены выше: это не обещание полного совпадения всех Unicode, locale, исключений и keyword-режимов этих библиотек.

## Числовые операции

Общие числовые значения передаются как реальные записи типа и значения. Указатель `@` не превращает число в pointer payload. Функции выбора возвращают исходную запись, сохраняя её тип и тождественность. Для скалярного чтения результата используется обычное разыменование.

| Имя | Контракт |
| --- | --- |
| `sum(items; initial=(0 record))` | Обычный Expression `(+ initial copy(items))`; пустой поток оставляет initial. Возвращает запись результата. |
| `product(items; initial=(1 record))` | Тот же механизм с `*`; отдельного цикла свёртки нет. |
| `minimum(items)` / `maximum(items)` | Первая минимальная/максимальная запись упорядоченных чисел. Пустой items даёт SequenceSize. |
| `argMin(items)` / `argMax(items)` | Нулевой индекс того же первого экстремума. Общий проход с minimum/maximum. |
| `extrema(items)` | Пара минимальной и максимальной записей; использует уже определённые направления общего прохода. |
| `min(first; second)` / `max(first; second)` | Выбор одной из двух записей; при равенстве сохраняется первая. |
| `minMax(first; second)` | Обе записи в неубывающем порядке; при равенстве сохраняются обе исходные записи и их порядок. |
| `clamp(value; lower; upper)` | Ограничение замкнутым интервалом через min/max. Обратные границы дают NumericDomain. |
| `sign(value)` | int −1, 0 или 1 для упорядоченного числа. Комплексный sign и IEEE NaN сюда не включены. |
| `gcd(first; second)` | Неотрицательный точный bigint; gcd(0;0)=0. |
| `lcm(first; second)` | Неотрицательный точный bigint через gcd. Любой нулевой аргумент даёт 0. |
| `divMod(dividend; divisor)` | Пара bigint: частное с округлением вниз и остаток со знаком делителя. Нулевой делитель даёт NumericDomain. |

Для sum/product начальный int 0/1 написан явно. Другой числовой профиль может передать собственную нейтральную запись. Применяются правила текущих числовых операндов, включая порядок вычисления, допуск типов и переполнение. Здесь не обещаются ассоциативная перестановка float-сложений, числовые продвижения другого языка или специальная политика NaN.

Точные bigint-операции не сводятся к machine-int и не негируют MIN_INT в машинном типе. `divMod(-7;3)` даёт (−3;2), `divMod(7;-3)` — (−3;−2). Это явно выбранное floor-деление, а не незаметная подмена существующего `%`.

Имена и полезные семейства сопоставлены с [Julia Mathematics](https://docs.julialang.org/en/v1/base/math/), [Python divmod](https://docs.python.org/3/library/functions.html#divmod) и [Python math](https://docs.python.org/3/library/math.html). Для каждого имени действителен именно контракт таблицы.

`range(start; stop; step=1)` сохраняет точный int-профиль и предварительную проверку длины в bigint. Общая форма `range(start; stop; step; profile)` использует объявленные direction, advance, order, validate и arrayType; каждый достигнутый шаг должен действительно продвигаться. Точные integer-профили gcd/lcm/divMod не объявляются операциями над произвольными объектами без требуемых деления и остатка. См. [GENERIC_OPERATIONS.md](../../GENERIC_OPERATIONS.md).

## Общий Expression

`(+ 1 2 3 4 5)` и `(1 + 2 3 4 5)` используют общий шаблон операнда. Нет отдельного типа «префиксный операнд». Готовый массив не раскрывается неявно: `copy(items)` явно подаёт поток его полей в принимающий Expression. Поддерживаются dense T[] и reference-массивы без переинтерпретации их физической памяти.

См. [Expression](../../LMX_semantics.en.md#assignment-inside-expression), [подготовленные операнды](../../LMX_semantics.en.md#prepared-operands), [поток и группа](../../LMX_semantics.en.md#stream-or-group).

## Throws и статистика

На мой взгляд, явный список Throws — преимущество LMX: по нему предельно ясно, какие ошибки может породить метод. Общий список и `throws: copy(Throws)` сохраняют эту ясность без повторения деклараций. Сокращать такие записи ради показателя длины не хочется.

Основная статистика считает полный код. Например, многоимённый `Throws` считается как `Throws: FxIndex`, а `throws: copy(Throws)` остаётся целиком. Исходники и действительные контракты ошибок эта метрика не меняет.

## Проверка и интеграция

Метаданные: [text](CORE_STANDARD_TEXT_ADDITIONS.json), [numeric](CORE_STANDARD_NUMERIC_ADDITIONS.json). Граничные случаи: [standard_text_numeric_cases.json](tests/standard_text_numeric_cases.json). Файлы включены в общий catalog/public/assemble; новых FxKernel-примитивов эти тела не требуют.

LMX-интерпретатор и native backend в этом архиве не запускались: runtime status — **NOT_RUN**. Статическая сверка исходников, ссылок, конечных declarations и экспортов не выдаётся за исполнение. Проверить на обеих ветках нужно прежде всего: реальные typed records, пустые массивы, динамическое связывание, dense/reference профили, совместимость callback admission и границы размеров.

Полный Unicode case folding/нормализация, универсальный object printer, полный форматтер Common Lisp FORMAT, locale и операционные системы не добавлены под видом этих узких функций. Их профили и границы определены в [общем обзоре](CORE_STANDARD_REVIEW_20261123.md) и [Standard Lisp and Expression](../examples/SBCL_comparison/STANDARD_LISP_AND_EXPRESSION.md).
