## 1. Нормы

- **Q38:** «"outside the copied operand subtree is a shared reference" -- это какая-то чепуха написана потому что merge
  " does not copy unused " -- куда и зачем и для чего и кому тогда shared reference за пределами копируемого? Оно не
  видно за пределами копируемого.»
- **Q42 п. 1** — «да» на формулировку: общая ссылка по адресу — только вхождение метода / вечная ветвь
  `independent: const: immutable` по контракту; всякая иная Structure, до которой доходит используемый граф операнда,
  копируется как изменяемое состояние, где бы ни лежал её родитель. **п. 2:** копируются только читаемые поля.
- **Q44** (автор, 2026-09-28, чат fable_pc; `LMX_blog/2026-09-27.md` «Q44», `LMX_blog/q/q44.md`): фраза книги «поле
  `A: fn: M` … остаётся при `merge` общей ссылкой на то же вхождение: оно не копируется, а `node` метода не меняется»
  отвергнута — имелась в виду ссылка на **нативную реализацию**: она получает узел графа, поэтому ссылку на неё можно
  сохранить; «К структурам это отношения не имеет»; и «Уровень файла ничемне отличается от других уровней».
- **Книга после Q44** (`provenance/semantics-book.md`, `merge`, правка fable_pc b1e9904): «Поле другой Structure,
  ссылающееся на метод (`A: fn: M`), сохраняет при `merge` общую ссылку на его нативную реализацию … уровень объявления
  метода (файл, тело операнда) ничем не отличается от других уровней … Вхождение метода, как любая достигнутая
  Structure, копируется по общему правилу и сохраняет свои номера полей.» Вечная ветвь не копируется; прочее
  используемое изменяемое состояние получает своё хранилище.
- Решение Q22 = II («ссылка на вхождение, `node` не меняется», 2026-09-24) — пересказ агента поверх реплики автора
  «у нас нет методов объявленных вне структуры потому что файл это структура» (`LMX_blog/2026-09-24.md`); Q44 его
  отменил, и пины Q22 = II (§3) воплощали пересказ, не норму.

## 2. Код сегодня

`lmx_copy_value` (`lmx_graph_copy_owned.lm1`, ветка `kind = LMX_KIND_STRUCT`): Structure, чей родитель вне копируемого
поддерева (или `parent = 0`), — общий терминал по адресу. Это обобщение (k.4, 2026-09-26) шире нормы: вхождение метода
в нём — лишь частный случай «родитель снаружи». Общими по адресу остаются ещё кадры кода (OP/ROLE, K-OT1) и удерживаемые
профили (`retain_profiles` — вечные ветви по контракту). Признака «вхождение метода» у ядра нет: номер домена
`LMX_DOMAIN_KIND_CALLABLE` только объявлен (`lmx_implements.h.lm1` :111), его никто не читает — комментарий о нём там (:104–:110: «lmx_fresh.lm1 and lmx_graph_copy_owned.lm1's Q22=II shared-method-reference terminal test still read it») устарел: ни один из двух модулей его не читает.

## 4. Сделано после Q44 (Opus, 2026-09-28)

Вариант из вопроса («признак метода») снят ответом: общего по адресу среди Structure нет вовсе.

- **Ядро** (`lmx_graph_copy_owned.lm1` + заголовок, близнец `l2src`): ветка «родитель вне копируемого → тот же адрес» снята
  целиком. Всякая достигнутая Structure копируется, вхождение метода — тоже; его реализация (`native`) переносится при
  правке родителей как есть — как и было. Общими по адресу остаются кадры кода (OP/ROLE, K-OT1), удерживаемые профили
  (вечные ветви) и терминалы `lmx_copy_is_terminal_profiles`. Комментарии копировщика и `lmx_implements.h.lm1` (о
  `LMX_DOMAIN_KIND_CALLABLE`) переписаны.
- **Пины перевёрнуты.** `lmx_merge_selftest` №3: Structure с внешним родителем — копия в арене назначения, у копии
  безродительской Structure родителя нет, ссылка операнда не тронута. `lmx_shared_method_selftest`: `M` копируется
  (другой адрес), копия несёт `native` `M` и висит под копией своего лексического родителя, исходный `M` не тронут.
- **Транслятор**, проверки результата `merge` для поля `A: fn: M`: 77 — поле результата не само вхождение и несёт его
  `native`; 79 — у копии своё хранилище, не ячейка вхождения.
- **Фикстуры** (замер, не предположение): `unit_q22_merge_in_method` (3), `unit_q20_merge_in_method` (5) и
  `unit_s4_ret_conv_merge_catch` (7) проходят без правки — копия `M` висит под копией файла, `node\tag` = 3;
  `unit_merged_callable` падал кодом 83 — у `R` теперь своё `hits`, скопированное при слиянии (0): ожидания переписаны
