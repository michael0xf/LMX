# Рабочее состояние без публикации load/cache/dirty

**Статус:** применённое требование к документации, обновлено в английской версии по 2026-11-21. Парная [английская версия](dirty.md).
Прежний механизм load-dirty и правила его публикации сняты. Файл сохраняет прежний адрес для
ссылок и излагает действующий [контракт кадра вызова](../spec/LMX_semantics.ru.md#call-frame-20261115);
он не служит свидетельством завершённой миграции runtime.

## 1. Что остаётся

Обычный независимый вызов готовит свой namespace из корневых объявлений DATA/CODE по общим правилам
модификаторов. Обязательные вклады `import`, `copy` и `merge` потребляются через их заданные источники CODE в namespace, без произвольного прохода исполнения тела DATA и без раскрытия P0. Его DATA — фактический родитель выбранной исполняемой Structure; у R0 нет DATA и пользовательских аргументов.
Все ресиверы остаются в исходном графе как написаны. Вычисление, связывание, преобразования и приём
потоков полей происходят в namespace. Терминальные примитивные объявления используют прямое представление `{type value}`.
Эти листья входят в полный буквальный исходный граф по адресам, которые держат ячейки Structure.
Обычное явное присваивание графа может заменить любую структуру ресивера, включая `for`, `if`, `merge`,
`copy` и `import`; исполняемые обновления при необходимости используют существующую границу compile/endturn.
Из снятия dirty не следует ни отдельного неизменяемого представления кода, ни ограниченного протокола изменения графа.

Обычное поданное значение подавляет свой инициализатор. Неиспользованный вычисляемый вход не вызывается, а при входе
общего прохода инициализаторов нет. Поданная форма объявления места остаётся DATA и сохраняет свой инициализатор
для последующего исполнения; её корневое объявление может дополнить namespace принимающего исполнения по
[контракту аргументов-объявлений](LMX_Fable_TZ_Declaration_Arguments_and_Import_v2_2026-11-20.md).

Переменные/const видны последовательно; пользовательские объявления Structure/callable сохраняют видимость в обе стороны.
Голое x и `@x` выбирают связанное логическое место. Явно поданные аргументы, автозаполнение и сохранённый fallback порождают собственные
места; запись меняет это место без копирования наружу. Прозрачное связывание вызывающего вместо этого нацелено на
реальную ячейку вызывающего, поэтому запись меняет её немедленно. Двустороннее private фильтрует каждый неявный динамический канал.
Собственные выбранные значения/описания остаются независимыми от последующей замены полей исходника, без глубокого копирования
объектов, на которые они ссылаются. Востребованный вычисляемый вход инициализирует локальное место активации; последующие чтения используют
текущее значение места. Повторное достижение объявления может вычислить и присвоить новый RHS. Снятие dirty-
публикации не требует повторного вычисления при каждом чтении, а это локальное состояние — не постоянный кеш, хранимый
в исходном графе.

Явные пути `D\x` и `C\x` обращаются к исходному графу. Для `int: field getValue()` форма `@(D\field)` адресует исходную
запись объявления и не вычисляет `getValue()`. Для вычисляемого входа x в namespace `@x` вычисляет вход по
необходимости и адресует его локальную ячейку. Готовый терминальный примитив уже имеет типизированную запись значения.
Зарезервированный node выбирает лексический контекст и не заменяется на `parent(C)` или получателем потока полей.

Вход в вызов не копирует исполняемый граф и не строит другого программного окружения. Его обычные значения
кадра и выбранные места не образуют рабочего графа под другим именем. Исполнение native и интерпретатором
разделяет одно поведение мест; у native-локалов нет арена-тега непосредственно перед их машинной ячейкой.
Правки графа не обнуляют native автоматически. Явная компиляция, за которой следует обычная граница endturn,
определяет обновлённый машинный код; до этой границы время применения исполняемых правок не гарантировано.
[Компиляция](../spec/LMX_semantics.ru.md#explicit-compilation).

## 2. Что отменено

Нет публикации load-dirty, автоматической обратной записи при вызовах/выходах, таблицы публикации, общего кеша
значений прямого доступа и ресивера flush. Прозрачная запись через место вызывающего не должна заменяться временным
состоянием, скопированным наружу при выходе, а собственная копия fallback не должна превращаться в алиас.

`S[n] := p` записывает ссылочный элемент по общему контракту Structure/`Array<@>`; у него нет требования бывшего поля заменяемого
элемента. Именованный `S\x := value` следует обычному допуску и контракту записи целевого поля и
заменяет выбранный фрагмент графа. Последующий доступ к этому структурному месту наблюдает
новый фрагмент; ссылки на прежний фрагмент автоматически не перенаправляются. `uninit:T` имеет нулевую полезную нагрузку,
поэтому замена его на `{T value}` не может сохранить ранее существовавший адрес ячейки T. Записи в локальные места кадра остаются локальными.
[Уточнение автора](LMX_Author_Clarification_Uninit_Graph_Assignment_2026-11-21.md).

## 3. Что означает публикация после этого решения

Публикация Message и выдача результата построения сохраняют собственные контракты; они не являются обратной записью локальных
кадров. Обычные локальные значения, GC, типизированное хранение, карты фактического копирования и общий допуск остаются необходимыми.
Приём вывода import/copy/merge в DATA — работа namespace, а не неявная публикация вычисленных полей
в чистую исходную Structure. `import`, `copy` и `merge` всегда потребляют аргументы CODE, даже при размещении в DATA: голые ссылки и анонимные Structure остаются значениями; явные вызовы источников исполняются при потреблении. Import сохраняет исходные ссылки и родителей; copy/merge сохраняют
связи графа своей собственной операции.

## 4. Где выполнять проверку

Проверка чистого графа использует общие механизмы подготовки/допуска, не исполняя тела кандидатов,
инициализаторы или `test`. Достигнутые вызовы интерпретатора используют стандартный `implements` с фактами допуска, ограниченными своей операцией/приёмом;
подготовленные native-вызовы не запускают runtime `implements` автоматически. Явный `implements` исполняется на любом
пути, а фактические проверки приёма/значения сохраняют свои контракты. `sys\compile` отдельно выполняет свою обязательную
фазу сборки/проверки после чистого графа и до C через обычные контракты приёма; она не сканирует все тесты DATA
и не запускает вход приложения. `sys\check`, `sys\checkL3` и `sys\translate` не исполняют ни код приложения,
ни тесты. translate возвращает текст L1 и ошибки, а не второй авторитетный граф LMX.
Никакой спекулятивной инфраструктуры, универсальной обёртки, скрытого компилятора или постоянного кеша окружения не следует
из снятия состояния dirty.
Фактические результаты native/интерпретатора и моста фиксируются отдельно от этих требований к документации.
