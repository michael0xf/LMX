## Изменение

Принят для интеграции сохранённый код fable-p0: шесть WIP-коммитов от ce5fecc8
до 048bf48c, изменения ожиданий, 60 новых входов и четыре отдельных эталона
previous-l1. Исторический Python-harness из WIP не перенесён.
Исходные рабочие деревья не менялись; их диффы и списки untracked сохранены
в каталоге квитанций.

- Многострочные группы всех видов проходят через общий вложенный документ
  того же потокового парсера; общий механизм сохраняет границы и диагностику.
- Каждый вложенный документ постобрабатывается один раз, его дерево
  переносится в арену внешнего документа с пересчётом исходных координат.
- Потерянные закрывающие скобки дают ошибку 33; комментарий Mix кончается
  на границе своего документа.
- Строковый атом сохраняется целиком, правильная отметка хранит отдельное
  дерево и номер символа в атоме; неправильная отметка строку не роняет.
- К существующему инструменту L2 добавлена команда parser-suite. Она читает
  прежние JSON-ожидания и проверяет дерево/фрагменты/диагностику отдельно от
  выхода процесса, сохраняет исходный вывод и report.tsv. Случаи не пересобираются.
- Именованный блок с трейлером строится одним конструктором на корне и во
  вложенной позиции. Прежняя отдельная ветвь корневого поля убрана:
  вложенный именованный post-loop больше не теряет имя.
- post_loop перенесена в данные main. Все 13 внешних значений сверены с
  прежним независимым эталоном и сохранены. Вариант RepeatOwn сохраняет
  прежний дочерний блок data до M11.5в; цикл в нём записан явно.
- close_stray_end теперь содержит настоящий лишний трейлер после закрытия
  Point отступом; добавлена сквозная p0_method_data с закрытием двух уровней
  внутри многострочных данных метода.

## Красные попытки и границы

Первый build-self на пустой стадии отказал: ещё не был сгенерирован импорт
lmx_array_owned.h.lm1. Штатный build-runtime породил объявления, затем tool02
собрался. Никакой старый заголовок не копировался.

Первая сквозная проба выявила потерю имени у вложенного блока с until:
устранено переносом существующего конструктора в общий путь. У первой
пробы p0_method_data return стоял трейлером fn: P0 сохранял его правильно,
но чистый граф его пропускал. Это прежнее ограничение построителя; в
сквозной пробе использован обычный внутренний return без лишнего end.
Полнота поддержки return-трейлера чистым графом этим срезом не утверждается.
Минимальный [пример](fn-return-trailer.lm2) на baseline graph-f28 и graph02
одинаково отвечает 5; квитанции return-baseline.out и return-candidate.out.

L1 и C инструмента G1 и G2 совпали побайтно; tool, frontend и backend совпали
командой exe-same (кроме PE-времени линковки). Runtime graph02, G1 и G2
побайтно одинаков: f383c5274bfb135effa194d06ab895a4fc6caae3a49e16f4748e269eb2befefc.
Нормальный канонический inputs.sha256 обновлён до 597 файлов и побайтно
совпадает с source04.sha256. Полный тестовый режим не запускался.
