# Проверка функциональной группы — 2026-11-22

## Что проверено

В группе сохранены все восемь сравнений: четыре паттерна 082–085 и четыре реализации 091, 092, 098, 099. Первичные LMX-листинги используют прямые операции единого текущего ядра; отдельный импорт `fun` не нужен. `eligible_variants` перечисляет допустимые реализации текущего контракта: историческая специализация контейнера или callable не становится короткой заменой общей реализации. Контрольные реализации также обобщены по полезным типам; собственные Maybe, Bounce, bracket и partial остаются показанными исходниками, а не заменяются неоплаченным импортом стандартной библиотеки.

Все восемь прежних LMX-листингов и все шестнадцать прежних контрольных листингов сверены с `patterns.json` из исходного `docs.tar.gz`: содержимое сохранено точно. Прежний LMX-код находится в каждом сравнении и в закомментированном хвосте каждого `.lm3`; прежние Haskell/Scala-коды — в соответствующих Markdown-файлах и JSON. Архивные варианты не исполняются вместе с новыми и не входят в новые метрики.

[Механическая проверка](tools/check_publication.py) сверяет JSON, основные исходники, шесть Markdown-блоков каждого сравнения, сохранённый код и опубликованные размеры. [Отчёт](validation_2026-11-22.json) фиксирует 160 проверок и отсутствие ошибок, включая выбор минимального допустимого листинга по символам. Это проверки согласованности публикации, а не статическая типизация LMX. [Реестр реализаций](IMPLEMENTATION_DEPENDENCIES.md) раскрывает общие зависимости и их стоимость без повторного счёта.

## Что ещё является приёмкой реализации

В среде этой редакции не обнаружены LMX-интерпретатор, `ghc`, `scala` или `scalac`. Новые листинги не представлены как успешно исполненные. Требуемые интерфейсы ядра и время жизни записей описаны в [пакете ресиверов](../LMX_Fn_Receivers/KERNEL_REQUIREMENTS.md). Статический пересчёт символов не подтверждает семантику, производительность или работу нового provider.

| ID | Проверка после интеграции | Ожидаемый результат |
| ---: | --- | --- |
| 082 | `Example\run(8)`, `(6)`, `(3)`; счётчик продолжения для отсутствия | Присутствующее 2; отсутствие; отсутствие. bind отсутствия не вызывает продолжение. |
| 091 | some для 0, null, double, строки и структуры; A→Maybe&lt;B&gt; с A≠B | Presence не определяется значением payload; тип результата продолжения сохраняется. Чтение uninit по-прежнему подчиняется обычному правилу. |
| 083 | n=0,1,100001; число вложенных активных even/odd вызовов | 1,0,0 в LMX; true,false,false в контролях. Шаги возвращаются драйверу и не накапливают рекурсивный стек. |
| 092 | done произвольной типизированной записи; more с отложенным шагом | done не запускает функцию. more не запускает thunk при создании. Один thunk вызывается ровно один раз за итерацию. |

| 098 | Типы ресурса и результата различны; action возвращает void; ошибка acquire/action/release | После успешного acquire release выполняется один раз; при ошибке acquire — ни разу. Тип результата не фиксирован; обычная семантика finally сохраняется. |

Ни одна цифра из метрик не является замером скорости. В частности, construction partial/thunk в примере батута не объявляется столь же дешёвым, как встроенное замыкание другого языка: это отдельная задача реализации и оптимизации общего построителя.

## Воспроизведение

Из этой директории последовательно выполнить `python3 tools/sync_receiver_bodies.py`, `python3 tools/select_shortest.py`, `python3 tools/regenerate_publication.py`, `python3 tools/check_publication.py`. Первый инструмент заново берёт точные тела из пакета ресиверов, второй выбирает минимальную допустимую реализацию текущего контракта, третий обновляет Markdown/CSV/JSON/листинги, четвёртый проверяет согласованность. PDF и XLSX строятся из тех же текущих JSON-показателей при сборке всего архива.
