## 4. Первая незакрытая общая причина — C-door unevaluated operand

**Актуализация 2026-10-22 после Verified169 (`d54223d`):** описанная ниже точка168 — исторический исходный контрпример; в169 literal `c.sizeof(touch())` уже проверен как7/touches0, без заявления общей C-door closure. Нормативный вопрос **P4 закрыт прямым ответом автора**: «Да: C-функции и макросы получают заранее вычисленные L2-значения; буквальный c.sizeof имеет роль оператора C, а не вызова функции.» См. [дословный источник](LMX_blog/2026-10-22.md) и [L2 §20](docs/L2_spec_ru.md#lowlevel-abi). В вычисляемом `c.BYTES(touch())` при `#define BYTES(x) sizeof(x)` L2-вызов выполняется один раз до макроса; макрос не получает роль literal C-оператора по своей развёртке. Общая подготовка предшествует определению роли; отдельного C-name parser/registry нет. Это новая норма от автора, не подтверждение старого emitter и не утверждение, что все её случаи реализованы. Проверить реальные эффекты/значения на BYTES, повторяющем и неиспользующем параметр макросах, literal sizeof control и обычных C-вызовах. VM/VLA, вложенные C-операнды, оставшиеся поиски callee/пути (R169-1), retained source и interpreter остаются самостоятельными обязательствами; их не закрывает ответ P4.

Точный положительный свидетель: [storage168-machine-unevaluated-open.lm2](steps/witnesses/used-scope-20261020/storage168-machine-unevaluated-open.lm2). **`c.sizeof(touch())` должен закончиться7 при touches0; parent167 и current168 дают88 при touches1.** Два исполнения сохранены как OPEN, не GREEN. См. `build2/codex_primary_contract168/machine-unevaluated-parent167-02` и `machine-unevaluated-current168-02`. В notes168 ссылка «L2 section19» исторически неточная: C-door контракт находится в **§20 External types/ABI** [L2 EN](docs/L2_spec_en.md).

Общий foreign-call adapter сейчас eagerly emits actuals; `_emit_ccall_value` вызывает `l2_emit_native_span`, может boxing-ом превратить char в int-temp и публикует эффекты до вызова. Исправлять **общий контракт подготовленного операнда и его вычисления/типизации/эффектов**, используемый CHECK, native, COUNT/EMIT и type/effect consumers. Не добавлять native-only `if name == c.sizeof`, второй parser/обход пути, whitelist C-функций или запасной поиск имени. Полное выражение сначала готовится, затем классифицируется роль receiver и применяется общий контракт.

Важно сохранить **валидность C-операнда**, а не только его размер. Типовая проекция не должна прятать невалидный INDEX/operator, opaque C type или менять исходный C99 смысл. Обычный raw machine INDEX часть ограничений оставляет C compiler. Нужны явные negative controls invalid index/operator и позитивные opaque C случаи. Не выдумывай primitive type для opaque результата; не подменяй операнд неубедительным `0`/`void*`.

Исследование перед остановкой **не дало реализованного решения169**. Рассматривались typed expression/thunk representations, но это не утверждённая архитектура и не готовый код. Опасности: C99 sizeof VLA может вычислять bounds; замена живых значений null/type holes меняет смысл; unknown C macros/types нельзя покрыть перечнем имён; GNU typeof/statement expressions не заменяют контракт C99. Dead `if(0)` с обычным эмиттером также может менять compiler effect state. У L2 native ABI status + outResult: обычный вызов нельзя просто вставить как C expression. Если выберешь thunk, он обязан сохранять реальные activation cells, взятые адреса, статус throw/stopped-call и однократность, а не копии формалов/адреса temporaries. Это исследовательские предостережения, **не повод ждать разрешения на самостоятельную реализацию**.
