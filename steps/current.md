# LMX: текущие рабочие инструкции

Обновлено 2026-10-15. Это точка входа в **текущую** работу, а не журнал всех прежних запусков. Предыдущая редакция с датированными checkpoint доступна в Git (`0e0a2978:steps/current.md`); подробные долги и свидетельства остаются в [плане v3](../next_core_tasks_v3.md), [тикетах](tickets/README.md) и [дефектах](defects.md). Прежние планы сохранены в истории Git.

## Полномочия и цель

По явной передаче автора 2026-10-15 единственный writer/build ядра — Opus; [точный handoff](../to_opus.md). Codex отвечает на вопросы через `lmx_uds` и не запускает конкурентную сборку. Помощники могут независимо исследовать и править назначенные непересекающиеся документы, но не менять ядро без новой передачи слота. Рабочий маршрут — [план v3](../next_core_tasks_v3.md); прежние планы доступны только в истории Git. Цель — полный kernel gate, затем две действительные самосборки из L3 со вставками L2 и почтовая матрица T01–T26. L1 допустим только как генерируемый промежуточный язык к C, не как поддерживаемый рукописный исходник.

В текущей рабочей копии есть незавершённые изменения кода и тестов. Не объявлять их принятыми по факту наличия. Проверять точные исходные байты и зависимую полноту каждого среза. Историческая передача Fable/Opus/Grok не назначает второго writer/build; для связи с внешними агентами служит [маршрут](../work_chat/README.md), а не заметки о старых ACK.

## Действующая модель и граница исследования

- Правило языка универсально в своей области: один раз построить дерево P0, один раз разрешить выражение, затем проверить контракт принимающего места. Никаких исключений по имени, форме записи, типу или удобству backend. Если решения конфликтуют, остановить зависимый срез и представить автору минимальный пример с двумя нормами и фактическим поведением; независимую работу продолжать.
- Голый атом читает разрешённое значение или ссылку, но не вызывает. Обычная именованная Structure исполняется через `call: A`; `A()` и `A: ()` не являются её вызовом. Плоские объявляющие хвосты L2/L3 имеют порядок «имя — требование — необязательное значение», например `@: p Model`, как `int: i 5`. Миграция этих правил и затем генерируемого L1 ещё открыта в v3 M1–M4.
- Runtime хранит адреса, а не имена или отдельный граф значений. Обычный `merge` копирует используемый граф и перенаправляет внутренние ссылки через одну карту; допущенные `independent: immutable` ветви имеют отдельное правило владения. Числовой ключ, имя или специальная таблица не заменяют физический адрес. Основной контракт — [L3](../docs/LMX_semantics.ru.md), физический — [L2](../docs/L2_spec_ru.md).
- `Lmx` имеет заданное при построении число слотов и после публикации **не растёт**: адрес `@field` должен оставаться стабильным. Растущий `List` — другой механизм, он не меняет этот контракт.
- Явные части метода `args`/`return`/`var`/`body`, полуавтоматическое наполнение `var` и `call: code data` — **утверждённая цель кодинга, ещё не готовый ABI**. Размер будущего `Lmx` вычисляется до построения; уже созданный узел не расширяется. Если явно переданный `data` не содержит необходимого коду поля, допуск отказывает до исполнения. Действующую инициализацию сохраняем. Решения и зависимые вопросы, начиная с `ptr: int: 5`, собраны в [миграционном описании](next_generation_model_20261014.md); порядок и gate — [v3 §2a](../next_core_tasks_v3.md).
- Исследование двусторонней видимости отложено автором. Не мигрировать код под неё без отдельного решения.

## Проверяемый остаток

Перед самосборкой закрыть M1–M4, [critical_graph_bug](tickets/critical_graph_bug.md), [critical_pointer_to_struct_bug](tickets/critical_pointer_to_struct_bug.md), K01–K12 и общий native/walker-контракт. Последний документированный kernel gate — `codex_hidden_entry_final_331`, GREEN 305/305; L3 `codex_hidden_entry_final_332` — 11 suites и четыре type budgets. Полный L2 `codex_hidden_entry_full_330` имел 102 прежних отказа среди 3101 целей, новых отказов относительно указанной в журнале базы не выявил. Эти числа подтверждают только тот checkpoint: позднейшую рабочую копию нужно проверять заново. [MERGE-COPIED-METHOD-HIDDEN-ENTRY](defects.md#merge-copied-method-hidden-entry) оставался OPEN. Узкий GREEN не закрывает ни один critical-тикет или §§8/8a.

Для каждого принятого среза записывать исходный SHA/commit, команды и число проверенных целей, наблюдаемый результат положительных, отрицательных и mutant-свидетелей, настоящий native и принудительный walker, список оставшихся FAIL-ID и следующую зависимость. Не корректировать старые goldens так, чтобы спрятать расхождение; исторический корпус парсера и текущие ожидания различаются. Стабильную копию заменять только после проверки полной dependency closure.

### G1: источник примитива и точный частичный оракул (2026-10-14)

Предыдущие абзацы этого раздела описывают байты указанных там checkpoint, а не текущий layout `PRIM_PUB`. На нынешней рабочей копии `PRIM`/`PRIM_PUB` могут владеть единственным исходным телом в слоте 2; слоты 3+ заимствуют адреса действительных исходных аргументов из этого тела. Обходчик до вычисления проверяет физическую принадлежность и непересечение заимствований, включая значение внутри `NAMED`, а не только саму обёртку. Его целевой selftest прошёл **57 проверок** на `build/l2src_py/fable_named_payload_20261014_02/bin/lmx_primitive_selftest.exe`, включая два отрицательных мутанта, копию в другую арену и исполнение после освобождения исходной арены. Это не полный kernel gate.

Транслятор сохраняет для корневого `sendMessage` одно тело `exit` с полями `exit_code`, `stdout`, `stderr` в исходном порядке и алиасы тех же `NAMED` в аргументах `PRIM_PUB`. Native-отправитель читает байты текста из выбранного текущего графа, в том числе из скопированного метода: отдельный native/`--walk-methods` тест `g1_send_current_code_text.lm2` вернул `G1 native text` и exit 0 в обоих режимах (`build/g1send_final_check/bin`). Строгий P0→graph-свидетель проверяет всё это тело, значения, порядок и тождество алиасов в native и walker, но **не** остальные поля корня; его 11 unit-тестов прошли, а фокусный harness `graph_shape_decl_init` дал GREEN **5 целей** (`build/g1send_harness_oracle_20261014_02`). Старые точные shape-ожидания перенесены без удаления проверок: три фокусных прогона `build/fable_prim_pub_focus_20261014_02`, `build/fable_prim_pub_sites_20261014_01`, `build/fable_prim_pub_literal_20261014_01` дали соответственно **15, 42 и 31 цель без отказов**; независимый повтор `graph_shape_occurrences24` дал GREEN **5 целей** (`build/g1send_oracle_named_recheck_20261014_01`). Затем все **197 зарегистрированных `graph_shape_*`** прошли вместе с тремя P0-оракулами: GREEN **204 цели, 0 отказов** (`build/g1send_graph_all_20261014_01/summary.txt`). Это полный фокусный графовый корпус, но не полный L2/kernel release gate.

Открыто: числовые поля и необязательный `Ref` native-отправитель пока вычисляет из сохранённого P0, а walker — из выбранного графа. Тестовый driver получил общую физическую мутацию `int-path`, не зависящую от имени поля. На неизменённой `graph_shape_decl_exact.lm2` после изменения единственной сохранённой ячейки `exit_code` с 7 на 9 native по-прежнему выдаёт 7, а принудительный walker — 9: `build/fable_int_path_20261014_02/bin/graph_shape_decl_exact.exe 0 mutate int-path 7 5 2 0 1 0 2 1 9 entry 7 [walkroot 1]`. Оба дампа перед исполнением показывают `int=9`; Codex независимо повторил оба запуска. Обычные зарегистрированные цели `graph_shape_decl_exact` и `graph_shape_decl_init` на этом driver прошли GREEN **6/6**, так что RED — именно дифференциальный свидетель ещё не исправленного native-пути, а не регрессия чистых программ. Нужен общий graph-backed native-путь операндов с текущими рабочими привязками, не исключение по имени `sendMessage`; для `Ref` аналогичная мутация выбранного графа ещё не проверена.

До исправления необязательное выражение `Ref` было последним операндом `PRIM_PUB` вне исходного тела: `unit_send_ref_driver_tap_walk` завершался `lmx: walk error: INVALID` (`build/g1send_ref_walk_probe_20261014_01`, native-двойник GREEN). Теперь выражение создаётся внутри единственного source-body перед письмом и последний операнд заимствует этот же узел; проверка физического владения обходчика не ослаблена. На этих байтах фокусные Ref-тесты и корневой частичный оракул прошли GREEN **11/11** (`build/g1send_ref_owned_20261014_03`), unit-тесты компаратора — **21/21**, весь зарегистрированный `graph_shape_*` корпус — **204/204** (`build/g1send_ref_graph_all_20261014_01`). Старое native-ожидание обновлено с двух фактических входов до четырёх (три поля письма плюс `Ref`) без снятия адресной проверки. Ref-оракул доказывает исходный порядок `[Ref, письмо]`, тождество заимствованного Ref и полей письма, но пока не реконструирует внутреннюю цепочку `m\sender`; полный G1 остаётся OPEN. Также открыты комментарии/`toLmx`, остальные конструкции корня, `merge`/`for`, полный kernel/L2 gate и самосборка. Ни один из двух critical-тикетов этими частичными результатами не закрыт.

При независимой проверке тестового `int-path` найден и исправлен приём десятичного числа вне диапазона `int` через `atoi`: теперь границы проверяются до преобразования. ### M2: межпроцедурное замыкание кандидатов (Opus, 2026-10-15)

Корневой анализ `l2_m2_root_current` и статический выбор тела по объявленной
модели в методах заменены одним проходом `l2_m2_close`. Он выполняется до CHECK,
то есть до фиксации рёбер вызовов, скрытых входов, `throws` и размеров кадров.
Проход проигрывает тела корня, методов и процедур именованных Structure над
состоянием физических мест: own-строк и мест именованных Structure. Для каждого
места известно одно из трёх: доказанное тело (ns), доказанная пустая Structure
или «неизвестно». Вход метода — объединение состояний всех мест его прямого
вызова, включая вызовы внутри выражений. Процедура Structure получает состояние
тех `call:`, чей сертификат указывает на её тело. Метод, имя которого читается
как значение, передаётся, удерживается или служит шагом пути, а также любой
метод библиотеки начинают с неизвестного состояния. Сертификат каждого `call:`
— объединение всех посещений этого узла. CHECK, подсчёт, native и walker во всех
методах читают один и тот же сертификат. Если сертификат не доказан, вызов
отклоняется с диагностикой `the current Structure body is not proved at this
call`; запасного выбора тела объявленной модели нет. Если операнд вообще не
адресует место, остаётся прежний отказ `executing a named Structure is not
supported yet`.

Место исходной Structure, которое не пишет ни один оператор, везде сохраняет
сконструированное тело. Вызов забывает только места, которые вызываемая
процедура может записать по транзитивной сводке. К ним добавляются места с
взятым адресом, места, записываемые маршрутом, который не назван ни в одной
сводке, а для вызова без названного вызываемого — сводки всех методов,
входимых иначе. Оператор, чью собственную запись нельзя назвать, забывает всё,
кроме сконструированных мест. Запись по пути, включая `Outer\Model()`, забывает
все места, имя которых совпадает с последним шагом. Ветвления объединяются.
После `return`, `throw`, `break` или `continue` путь дальше не идёт. Тело цикла
и обработчик `catch` видят только неизменяемые места. Локальное определение
Structure заново строит на своём операторе сконструированное тело. Результат
`merge` держит тело своего выбранного источника (правило Q8 — в разделе
«M1/M2: голое имя копии, выбранное тело `merge`, две регрессии» ниже).
Вспомогательная проверка «чистоты» тела при вызове удалена: её заменили сводки
записей. До этого она читала контракт пути не в методе процедуры.

Свидетель `unit_named_struct_call_method_rebound_hidden` теперь исполняет B с
её скрытым входом `status`. В сгенерированном `run` вызов `lmx_call_prim`
передаёт один вход. Native и принудительный walker проходят. Добавлены два
свидетеля. Положительный `unit_named_struct_call_method_chain` проводит тело
через два метода и вызовы внутри выражения. Отрицательный
`unit_named_struct_call_method_branch_refused` объединяет два разных тела на
входе метода и даёт отказ в `13:5`. Фокус из 115 прежних M2/копий/Structure
фикстур дал **105 из 118 целей** (`build/opus_m2_close_20261015_01/summary.txt`)
против **86 из 118** на исходной рабочей копии
(`build/opus_m2_baseline_20261015_01/summary.txt`). Восстановлены 19 фикстур, в

Проверку обнаружения дали три мутанта транслятора (сборки в scratchpad,

### M1/M2: голое имя копии, выбранное тело `merge`, две регрессии (Opus, 2026-10-15)

Голое имя результата `merge` как оператор теперь читается и отбрасывается
(`docs/LMX_semantics.ru.md:422`). Раньше транслятор падал с
`internal: an expression site has no construction temp` на 46 строках полного
gate. Причина и исправление — в
[BARE-COPY-READ-NO-SITE](defects.md#bare-copy-read-no-site); свидетель —
`unit_bare_merge_copy_stmt` (+`_walk`).

23 фикстуры исполняли копию голым именем — форма до M1. Исполнение обычной
Structure записывается `call:` (Codex, OPUS-CODEX-20261015-10 Q12). Где
оракулу нужно, чтобы тело исполнилось, голая строка стала `call: X`. Оракулы
(Entry, Needle, проверки после запуска) не менялись.

Правило выбранного тела `merge` (Codex, OPUS-CODEX-20261015-10 Q8).
`call: R` для `R: merge: Model Later` исполняет одно выбранное полное тело,
Later, над составленными данными R. Замыкание M2 берёт выбор самого результата
(`l2_mres_code_k`), а не ветку для Model:
- тело `merge` — литерал объявления; ни один оператор его не переписывает;
- выбранный операнд k: доказано, только если место k держит ровно выбранное
  тело;
- без исполняемого источника цельная копия одного операнда держит текущее
  тело операнда, пока в нём нет кода.

На этом правиле транслируются и проходят `unit_merge_selected_body_*`,
`unit_merge_data_only_compiled`, `unit_merge_body_{stmt,expr}_*` и
`unit_empty_type_call_method`. Два отрицательных свидетеля переписывают место
операнда до `merge`:
- `unit_merge_selected_body_rewritten_refused` — `Later: Other`;
- `unit_merge_copy_codefree_rewritten_refused` — `E: Model`.

Оба получают отказ в точке вызова. Три мутанта правила (без сверки места
выбранного операнда, без проверки «нет кода», без ветки тела `merge`) делают
красным ровно свой свидетель.

Состояние места в замыкании пока не различает целое вхождение B и тело B,
выбранное над составными данными `merge`. Для прямого `call:` это одно и то
же. Корню пути (`call: Outer\Inner`) нужно именно целое вхождение. Срез
путевых операндов вводит для этого отдельное приватное кодирование
(Codex, OPUS-CODEX-20261015-12 Q1).
