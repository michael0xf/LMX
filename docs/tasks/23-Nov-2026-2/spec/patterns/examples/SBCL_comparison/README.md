## Как выбраны варианты

**Основной вариант — кратчайший из рассмотренных допустимых вариантов при одинаковом уровне задачи.** Краткость не оправдывает потерю полей, эффектов, обработки ошибок или важных частей алгоритма. Существенный другой подход сохраняется отдельно; однострочные перестановки не размножаются в полные примеры.

Common Lisp использует настоящие средства языка и SBCL. Сравнительные reference-реализации из `source/implementations/common-lisp` в клиенты не загружаются. LMX использует существующие операции своего единого ядра там, где это соответствует уровню операции другой стороны. Реализации общих функций показаны отдельно, поэтому стоимость за коротким вызовом можно проверить.

В **S23** Common Lisp самостоятельно строит кеш через `hash-table`. Основная LMX-пара тоже содержит алгоритм кеширования. Вариант с готовым `memoize` сохранён отдельно: это иной уровень абстракции, его меньшее число символов не подставляется в основное сравнение. Полное тело `memoize` и зависимости показаны в **SI06**.

Сами архитектуры не обязаны совпадать. В **S18** CLOS generic function сопоставляется обычному вызову метода структуры LMX для тех же объектов и результатов. Это не заявление о реализации всей CLOS-диспетчеризации. В **S20** сравнивается конкретное однократное вычисление и повторное использование значения; преобразование произвольного Lisp-кода макросами в LMX этим не объявляется. Для **S15** результат из нескольких значений Lisp представляется обычной структурой результата LMX.

## Области договоров

Числовые примеры ограничены значениями и промежуточными результатами, помещающимися в выбранный LMX `int`. Это не сравнение всех возможностей целых, rational и bignum Common Lisp. `NIL` как отсутствие результата и пустой список не механически приравнивается к нулевому указателю: нормализация результата указана в конкретном примере.

Позиции начинаются с нуля, диапазоны имеют исключённую верхнюю границу. Различия `replace` Common Lisp и `replaceRange` LMX согласованы явным доменом **S09**, а не замаскированы названием. В сортируемых записях сохранён идентификатор, чтобы устойчивость была наблюдаемой. У прямоугольника в **S19** сохраняются оба измерения; ресурс **S22** содержит и `value`, и `width`.

**S22** проверяет успешный проход, отказ получения ресурса, отказ действия, отказ освобождения и отказ действия вместе с освобождением. Порядок событий и причина окончательного отказа входят в результат. Простое наличие `finally`/`unwind-protect` без этих наблюдений не считается полной демонстрацией договора.

## Message и граница S24

**S24** содержит настоящий SBCL-код с `sb-concurrency` и `sb-thread`, исполняемый стенд и LMX-протокол на `Message`/`post`. Создание конкретных исполняемых Message, отдельные арены и адреса задаёт host-профиль текущей документации. Здесь не вводится новый API запуска и не обещается сохранение стека между turns.

Общий [профиль Message/HTTP](../../MESSAGE_HTTP_PROFILE.md) прямо отмечает отсутствие полного проверенного parser fixture для показанных деревьев `post`. Поэтому S24 помечен как **протокольная аналогия с ожидающей интеграцией LMX** и **не входит в итоговый коэффициент**. Код SBCL host-адаптера сохранён отдельно и его размер виден в отчёте. Его исключение из клиента не означает нулевой стоимости запуска.

Остальные 23 строки — полные пары **в своих явно ограниченных договорах**. Такой статус не означает тождество всей семантики двух языков или успешный запуск LMX. Синхронным операциям не добавляется отдельный планировщик: при необходимости целый метод владельца можно вызывать через существующий `post`.

## Метрика

Главная метрика — число **Unicode-символов без пробельных символов**. Дополнительно публикуются все Unicode-символы, непустые строки, UTF-8-байты и SHA-256. Переводы строк нормализуются в LF, внешние пустые строки убираются, остаётся один завершающий LF. Комментарии внутри основного листинга считаются; код не минифицируется.

Тестовые входы и harness вынесены отдельно у обеих сторон. Основные клиенты, альтернативы, самостоятельные реализации и общая инфраструктура — разные совокупности. Общие LMX-определения в замыкании зависимостей считаются один раз. Нельзя сложить пересекающиеся замыкания всех строк и назвать это размером единственного приложения.

Дополнительная колонка **«без сложного Throws»** сохраняет заголовок и первый синтаксический аргумент объявления Throws или его общего банка; только последующие аргументы исключены из дополнительного счёта. `throws: copy(Throws)` и ссылки сохраняются целиком. Банк учитывается в своём исходнике/замыкании, не прибавляется повторно каждому использующему его клиенту. Единственная реализация правила — [общая utility](../../tools/throws_metrics.py); она входит в полную `spec` и нужна локальным генераторам.

**Авторская оценка: явные Throws и `copy(Throws)` — преимущество LMX. Видно, какие ошибки метод может бросить; такие объявления не хочется сокращать.** Поэтому дополнительная колонка помогает оценить вклад декларации в размер, но исходные контракты и основной коэффициент остаются полными.

В PDF/XLSX зелёным показан минимум сопоставимой строки. Для LMX участвует дополнительная колонка, если она строго меньше полной; при равенстве выбирается полная, чтобы не подсвечивать одну запись дважды. Равные минимумы разных языков подсвечиваются вместе. S24 не получает отметку победителя. XLSX использует формулы условного форматирования, которые пересчитывают минимум при изменении чисел.

Коэффициент **Lisp / LMX** вычисляется из сумм полных пар. Значение меньше единицы означает меньше символов у Lisp в этой выборке. Непроверенная протокольная аналогия не маскируется нулём. Эта метрика не измеряет быстродействие, потребление памяти, сложность компилятора или качество языка в целом.

## Проверки

- [Клиенты Common Lisp](validation/common_lisp.json): фактическое исполнение в SBCL, версия и числа проверок находятся в отчёте.
- [Reference-реализации](validation/implementation_execution.json): отдельное исполнение; они не используются клиентским стендом.
- [Покрытие использованных функций](validation/library_coverage.json).
- [Целостность исходников и публикаций](validation/source_checks.json).
- [PDF/XLSX](validation/artifact_validation.json): расчёты, экспорт и визуальная проверка.
- [Подробный счёт Throws](validation/throws_metrics.json): ссылки, copy и первый аргумент сохранены.

**LMX не исполнялся (`NOT_RUN`)**: доступного интегрированного ядра и исполнителя нет. Текущие LMX core-модули также содержат ранее документированные обязательства интеграции FxKernel. Проверка листингов, зависимостей и ожидаемых результатов не подменяет их выполнение. Общая ревизия содержит полные новые LMX-тела, но не выдаёт их подготовку за успешный runtime-запуск.

## Воспроизведение

Из этой директории:

```sh
python3 tools/rebuild_implementations.py
python3 tools/rebuild.py
python3 tools/build_expression_review.py
python3 tools/build_cl_coverage.py
python3 tools/run_common_lisp.py --sbcl /path/to/sbcl
python3 tools/run_implementation_tests.py --sbcl /path/to/sbcl
python3 tools/build_pdf.py
node tools/build_workbook.mjs
python3 tools/validate.py
python3 tools/refresh_manifest.py
python3 tools/verify_manifest.py --spec-root ../../..
```

SBCL должен находить свой `sbcl.core`; для распакованной установки задайте `SBCL_HOME`. Python/Node-генераторы не устанавливают пакеты и не скачивают зависимости. PDF требует ReportLab и шрифты DejaVu; XLSX строится через `@oai/artifact-tool`. Команды фактических стендов и требования к окружению уточнены в [VALIDATION.md](VALIDATION.md).

Клиентские `.lm3` и `.lisp` — редактируемые исходники. `examples.json` хранит договоры и пути; встроенные в него листинги и размеры обновляет `rebuild.py` из файлов. Копии тел ядра обновляются только локальным `tools/rebuild_implementations.py` из соответствующей текущей `spec`, без записи наружу. Если директория передана отдельно, сохранённых копий достаточно для чтения, подсчёта и запуска Lisp-reference-кода; LMX требует базовое ядро.

После изменения исходников нужно заново выполнить соответствующий языковой стенд, обновить статистику, PDF/XLSX и манифест. Устаревший успешный отчёт не считается проверкой нового кода.
