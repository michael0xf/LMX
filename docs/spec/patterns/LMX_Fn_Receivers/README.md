## Единое ядро и границы интеграции

Все 61 операции входят в одно текущее ядро и доступны пользователю напрямую.
Опциональной загрузки, пользовательского import или альтернативных версий
этих библиотек нет. `fun` — только внутренняя группа исходных описаний;
подготовка ядра добавляет её const-экспорты в обычный корневой namespace,
сохраняя фактические parent/DATA методов. Для явного устранения коллизии можно
использовать физический путь `fun\const\name`.

Сборка `LMX_Receivers.lmx` и отдельные src-файлы — два представления **одних
исходников ядра**, а не разные варианты runtime. Прежние материалы
не являются подключаемой альтернативой.

Именованная сигнатура объявляется только как `Name :: Signature`; прежний
receiver и публичный конструктор с прежним именем удалены без alias. Операнд
`signatureTypes` строит описание из явных result/inputs. Reflection остаётся
`signature(operation := F)`. Смысл именованного описания и его существующее
отношение с call сохраняются; остальные применения описаний взаимозаменяемы.

Репозиторий исполняемого ядра в этот архив не входит: реализация восьми внутренних
мостов и подключение стандартных имён — задача интеграции Fable. Исходные тела
готовы как проект изменения ядра; факт исполнения/готовности бинарника не заявлен.

Все пользовательские данные сохраняют полный тип. Служебные `int` обозначают
индексы, длины, коды типов, числа повторов и логические состояния. Примеры с
`int` остаются примерами предметной области. Ограничения наподобие `N=2` у
частичного применения или «результат всегда int» в основной реализации убраны.
При этом `flip` меняет именно первые две позиции по определению операции,
`zip` образует пары, а `lazy` получает именно thunk без аргументов.

Всякая Structure уже является массивом `@`: коллекции, actuals, префиксы и
результаты хранятся прямо в такой структуре. Дополнительного контейнера
`{items: ...}` вокруг списка нет. Плотный `Array<T>` не переинтерпретируется как
`Array<@>`; он может быть одним полноценным значением в этой структуре.

При конфликте с прежними материалами действуют нынешние документы `docs` и эта
редакция; особенно это относится к раскрытию операндов и текущему имени `satisfies`.

## Правило честного подсчёта

Ядерный helper исключается из размера usage-примера только при аналогичном
уровне абстракции контрольного языка: готовая библиотека или оператор, который
инкапсулирует ту же работу. При сравнении самостоятельных реализаций считаются
тела и оговорённые зависимости. Основной вариант — самый короткий допустимый
по этой границе; дополнительный короткий вызов ядра и процедурный аналог
сохраняются рядом. Сам статус «входит в ядро» не даёт исключения из подсчёта.

При этом архитектурно оптимальный LMX не переписывается ради совпадения алгоритма
контрольного языка. Собственные общие примитивы LMX — copy, merge, binding,
обычный вызов и работа с графом — законно остаются примитивами языка; их runtime
реализацию не разворачивают в каждом сравнительном листинге. Проверка границы
касается сокрытия специфической работы helper за коротким вызовом, когда другая
сторона показывает эту работу вручную, а не требования одинакового алгоритма.
