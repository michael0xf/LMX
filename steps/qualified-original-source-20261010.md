## Connected implementation boundary

Before continuation23, the qualified constructor captured its real inner `()`
body through `l2_take_ns_body`, but `l2_ns_original_body` excluded that entry
and `l2_ns_procs` refused any qualified statement. The dense NSF adapter
allocated the qualified root and its fields; ordinary source COUNT/PLACE/FILL
did not own those occurrences. Merely removing the refusal would have executed
a body without a complete physical source producer. A named qualified Structure still
has a complete source-ordered body under the normative semantics: declaration
does not execute it; a later explicit nullary call may execute retained
expressions, while immutable-field writes are forbidden.

Move the actual qualified body through the common source producer in both
program and library modes. Keep one root occurrence: source shell aliases the
already allocated `l2_nsp` root, never a second graph or helper Structure.
Use identity-based suppression of NSF-owned children, not a special Array or
primitive-type branch. Qualified widths, field slots, schema/path readers and
the copy/merge consumers must all use the same completed physical placement.
Pass the exact owning branch profile through common shell, CHILDREN, cell,
atom and walk-frame allocations; leave ordinary unqualified profile 0.
Complete source FILL and roles before sealing all actual exact-profile ranges;
copy synthesized model payloads only after sealing. Library mode needs the
same internal source traversal but must not export anonymous producer rows as
public methods. Preserve existing raw LINK/SYMBOLS checks.

## Read-only preparation of the next connected dependency

At the time full30 owned the frozen inputs, no next-slice source was changed or
built. The following read-only dependency analysis still applies.
The consumer gap is concrete: `l2_actual_path` and `l2_emit_actual_path` each
parse an alternating name/slash subset and only accept namespace field kinds
2/3. `l2_actual_ns` also has a separate joined single-atom path branch with
the same restriction. These are not the general path implementation.
`l2_path_resolve_contract` already resolves the final reference contract and
receiving model, and `l2_path_text_read` loads either the selected occurrence
or the final reference cell through `l2_emit_path_receiving`. That common
emitter preserves the selected holder and the ordinal/LAST mapping at each
admitted-reference crossing. The walker has corresponding path-value and
reference-value producers; their connection must be checked, not assumed.

The next bounded consumer migration should reuse those routes for arguments,
returns and captures, preserving located negative diagnostics. It must not
widen `l2_reference_path_leaf` indiscriminately: `l2_reference_source` uses
that helper to claim an original physical layout. A reference field has a
receiving model and possible actual sources, not necessarily that model's
layout. `l2_reference_path_source` already retains the original declaration's
source coordinate for this distinction. Cases to distinguish include a
reordered admitted holder, repeated-name LAST/ordinal selection, multiple
crossings, a changed reference and a copied holder. Primitive leaves and
extra reference depth must still follow the receiving contract, not be cast
to Structure merely to pass the checker. No new depth or spelling limit.

The binding producer (`into: E\deep`) is a related but separate connection:
`l2_ref_tail_atom`, `l2_unit_ref_bind`, `l2_ns_bind_item`/`l2_ns_bind_target`
and `l2_ref_bind_site` currently require one atom. Its extension must retain
source-site visibility, consume a complete single value span and preserve
the original source node. It must not select a later declaration from the
finished namespace table or replace an actual reference by its model.
Callable/value/local binding debts remain recorded, not silently classified
as fixed by enabling a path at an argument site. These observations establish
the next implementation route, not executed acceptance for that route.
