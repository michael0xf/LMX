# Интерпретатор L3 (не L2)

По уточнению автора: интерпретатор исполняет **только L3**. Не `c.*`, не специальные операции L2 (арена, сырые адреса, synchronized, METHOD.addr как вход в C).

Цепочка трансляции: **L3 → L2 → L1 → C99 → L0**. L1 — промежуточная стадия, не носитель графа. Исходники постепенно переписываются с `.lm1` на `.lm2`; в итоге `.lm1` в исходниках не остаётся. Интерпретатор ходит граф L3. Native `lmx_call0` — результат трансляции, не представление программы.

## Предложение Grok Codex (GROK-L3-SUBSET-20260920)

**Ресивер L3.** Принимающее выражение, которое допускает уже построенный граф `.lm3` (скриптовый профиль: корневое тело файла). Парсер строит граф; ресивер проверяет, что это L3-подмножество; интерпретатор ходит структуры и связи. Юнит-тесты допуска — тот же интерпретатор ([семантика](../../docs/LMX_semantics.ru.md#admission)).

**Подмножество L3 для первого интерпретатора** (без низкого уровня):

| есть | нет |
| --- | --- |
| структуры, поля, вложенность, пустое `()` | `c.*`, `#include`, `os:` |
| вызываемые Structure, заголовок в дескрипторе, тело M после слота 0 по порядку | L2: `lmx_arena_take`, диапазоны как пользовательские операции, synchronized |
| `return:` и прочие выходы **в дереве тела** (их может быть много) | одиночный `return_arg` на дескрипторе |
| ветвления/циклы как тела в графе | сырой METHOD.addr как смысл программы |
| аналитический implements + тесты ресивера | позиционный `lmx_runtime_implements` как семантика |

Codex подтвердил якорь `#l3-receiver` и шаги L3-01…04 (`steps/l3-receiver.md`). Узлы: [V1.md](V1.md). L3-01: `l3_recv.lm1` + `tests/l3_01_selftest.lm1`. Реализация только в `LMX/dev`.
