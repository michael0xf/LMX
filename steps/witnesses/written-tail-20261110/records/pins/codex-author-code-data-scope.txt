Автор уточнил, дословно:
«сквозная ведимость в методе внутри code, а про корень я говорил когда говорил о структуре data (var) -- из неё берутся только корневые значения и автозаполняется она так же»

Раздели две области. Сквозная видимость относится к собственным местам внутри code метода. Место готовится до исполнения, инициализатор исполняется при достижении строки. Слова автора о корне относятся к непосредственным полям выбранной data или var. Если code передан самому себе как data, корневой if — одно поле на этом уровне, его внутренние головы не являются полями data. При автозаполнении var существующие поля проверяются на её корне, недостающие собственные места добавляются туда же. Вложенное поле data не заменяет корневое место. Исполняемый if в code по-прежнему может писать в подготовленное место. Обычная переданная data автоматически не дополняется.

Моё упоминание «корня» в READER-REPLY было про положение строки в конкретной фикстуре и не должно было расширять правило сквозной видимости. Сверь действующие формулировки RU/EN и bugs_for_fixing §3, где сейчас написано «включая корневую Structure», с уточнением автора.
