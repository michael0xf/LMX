## Written calls and graph places

The new ordinary L2 module `l2_consumer_uses.lm2` has five machine exports:
call note, snapshot release, exact fixed-point snapshot, cell counting and
end-of-view emission. Call observations retain original P0 identity, method,
checked signature and the complete saved source environment. Different
calls and environments remain different rows even when a field is shared.
Temporary scope snapshots are freed on duplicate or refusal; retained scope
arrays are released before the ordinary binding allocation ledger.

The compiler records role4 only for the successful original written EXEC,
not synthetic converter EXECs. The existing PLACE pass binds its physical
GraphPlace. The source-plan snapshot includes occurrence identities and
environment values, not newly allocated metadata addresses; a changed or new
call after freeze refuses before mutation. Rebuilding the source plan also
resets the flattened use-scope cache while retaining its borrowed unit.

Receiving records have six ordinary graph slots. The sixth holds:

```text
[count, (coverage-field-coordinate, Consumer-code, written-CALL,
         result-receivers, required-exits)*]
```

COUNT, PLACE and FILL reserve the same `1+5*n` holder. The end-of-view
fixup runs after all method frames are attached and writes existing graph
references; it neither builds another CALL nor evaluates the call. Coverage
coordinates count every row at their level, including duplicate path
occurrences, rather than deduplicating by name or physical field.

A cursor selects the committed source root by construction view and actual
declaring method. The main projected root uses its existing target alias;
nested definitions keep their own aliases. Only a genuine external normal
source uses the supplied entry unit. A present ambiguous or unbound
preferred-view site is not replaced by an original occurrence. An absent
preferred site may use its unique normal source. A missing projected
construction root still refuses in the cursor. The three
fixup sites are normal construction, T7 and dynamic merge construction.

Four receiving-record width checks change5 to6 in the common runtime.
ADMIT_AS itself stays width5 and its semantics are unchanged. There is no
new language grammar, parser, hidden module/root/context, runtime provider
lookup or library-specific comparator. All new runtime edges are ordinary
graph references, subject to the existing copying and qualification maps.

callable formals and forwarding contexts still need occurrence-bearing
coverage; a called bit alone is insufficient. Consumer execution code/data,
the required declaration home and selected provider home must remain

admission, for known and runtime-built candidates. Null demands are not

default or converter body may run merely to answer admission.
