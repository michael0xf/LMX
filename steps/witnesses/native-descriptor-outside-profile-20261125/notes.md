# Нативные дескрипторы вне профиля значения, 2026-11-25

Принята малая правка ядра по регрессии компонента W4 (план 29.3, д7): строка полного списка `immutable_formal` и
`immutable_formal_cell` и три строки RR2 дымового списка отвечали 3 в нативном режиме. Причина: копия значения под
профилем (квалификатор `immutable`) делала дескриптор нативного входа своей копии кода в пулах этого профиля, хотя
дескриптор достигается только через нативную таблицу и дереву значения не принадлежит; проверка покрытия профиля
поэтому отказывала. Теперь ячейка, достигнутая через нативную таблицу, делается без унаследованного профиля
назначения. Все пять строк зелёные; самопроверка ядра расширена двумя функциями.

## Решения

Sol, 2026-11-25 (`CODER-D7-IMMUTABLE-NATIVE-QUESTION-20261125-01-ASTRA-ANSWER`, уточнение
`…-APPLIED-REPLY`). Вариант A с поправкой: в общем `lmx_copy_native_finish` передать нулевой наследуемый профиль в
обе точки — `lmx_copy_value` и `lmx_copy_drain`; реальные `profile_map`, `retain_profiles` и `requested_type`
сохранить. Пробная передача второго нуля (`profile_map = 0`) неверна: для `forest_remapped_staged` и reparent теряется
карта — дескриптор, достигающий запечатанного P, должен идти в P' или отказывать, при нулевой карте ветвь может
молча скопироваться вне P'. Обычный граф копируется первым; если D уже достигнут через обычное поле, общая карта
даёт тот же D' вместе с ссылками self/owner на конечные адреса. Правило зависит от способа достижения новых ячеек,
поэтому `parent == 0` не критерий; комментарий привязан к свежим ячейкам, достигнутым через нативную таблицу.
Проверки coverage и seal остаются строгими. Смена физического семейства и новый ABI не нужны. Мёртвый параметр
`dst_profile` возвращать не нужно; `lmx_graph_copy_native_mapped` — внутренний стык с двумя вызовами в
`lmx_merge_owned` и генерируемой декларацией из `tools/build.lm2`: все три согласованы, это изменение C-сигнатуры
стыка при прежнем имени символа; в итоговой сборке декларация, вызывающий модуль и реализация — из одного комплекта.

## Норма

- Книга, #qualification (`provenance/semantics-book.md:2629`): перед публикацией нового immutable-значения
  исследуется всё выбранное дерево; содержащаяся Structure — ветвь дерева только когда её обычное структурное поле
  `parent` указывает на рассматриваемого родителя.
- `docs/spec/kernel-implementation.en.md`, §7 (:996): нативный дескриптор — обычная Structure с подготовленными
  вариантами сигнатуры; таблицы вызовов хранят его связывание с выбранным исполняемым вхождением; у Lmx нет поля
  заголовка native. Книга (:267): нативные дескрипторы живут в таблицах вызовов арены Thread'а; (:5180): копия и merge
  сохраняют разрешённые нативные связи по существующему договору.
- RR2a (`steps/qualifier-receivers-20261010.md:60–69`): каждая достигаемая ячейка результата отвечает профилем.
  Профилем владеет дерево результата; дескриптор, достигнутый только через таблицу, — не его ячейка.

## Причина (gdb, образ `immutable_formal` с ядром с отладочной информацией, принятый комплект)

В точке `lmx_qualify_profile_coverage` для копии `b` под профилем Q: две строки нативной таблицы с кодом — ячейками Q
(сам результат merge, 3 слота, и его дочерний код, 1 слот); у обоих дескриптор лежал в пулах Q (пул рода 6 с профилем
Q, ячейки его CHILDREN там же). Проверка покрытия требует, чтобы каждая использованная ячейка пулов Q принадлежала
дереву значения; дескрипторы дереву не принадлежат — `lmx_qualify_spans_complete` отвечал INVALID,
`lmx: walk error: INVALID`, выход 3. Шагаемый маршрут (forced) нативной связи не ставит и давал 7. Вносил дескрипторы
в Q вызов `lmx_copy_native_finish` из `lmx_copy_run` (копия `lmx_graph_copy_qualified_leaves_staged`) с профилем
назначения Q и из `lmx_graph_copy_native_mapped` (merge с одним операндом, `lmx_merge_owned.lm2:602`, `:913`).

## Находки за пределами среза

- **Находка 2 закрыта — ошибка измерения.** В вопросе Sol сообщалось, что число связанных строк нативной таблицы в
  точке покрытия меняется от запуска к запуску (2–8). Я считал ненулевые `row.code` только по индексам меньше `len`;
  занятые строки распределены по всей `cap` хешем адреса (`lmx_native_hash`, `lmx_call.lm2:18–21`), а `len` — счётчик
  занятых (`lmx_native_put`, `lmx_native_remove`, `:34–100`). По всей `cap` в четырёх прогонах (до и после, root0 и
  root1) число ненулевых кодов равно `len`; потерянных связей нет. Методика Sol — считать по всей `cap` в таблице
  фактического `range_home` — применена.
- Значение с явным ребром на дескриптор своего кода полный preflight отказывает на обоих комплектах. Отказ
  наблюдался раньше, чем был найден в норме; место отказа уточнено Sol и Astra
  (`CODER-D7-DONE-20261125-01-ALIAS-ANSWER`) — вывод из кода, новых прогонов не требовалось: установка делает
  дескриптор с `parent = 0` (`lmx_graph.lm2:545`), копия его сохраняет; `lmx_qualify_saved_child` через
  `lmx_qualify_parent_path` (`lmx_graph_copy_owned.lm2:1058`) пропускает его и оставляет вне замыкания; DATA-ребро
  корня на него получает INVALID в `lmx_qualify_edge` (`:838–844`: Structure вне замыкания и вне прежних профилей);
  полный preflight обрывается до проверки покрытия, защитная ветвь `:1260–1265` местом отказа этой фикстуры не
  является. Норма — книга, #qualification (`LMX_semantics.en.md:1466`): внешняя DATA-ссылка на ещё не запечатанную
  Structure отвергается. Случай не обобщается на уже запечатанную цель и на собственную ветвь. Теперь это контроль
  `nd_qualified_alias`; ожидание INVALID закреплено Sol. (В коммите `2740a59ab` место отказа было названо неверно —
  защитная ветвь `:1260–1265`; поправлено здесь.)
- `immutable_reached_write`: отказ транслятора в нативном и forced режимах на обоих комплектах (`:136`, operand
  beside a runtime-typed value); строка красна с W3 и вне списков регрессии. Отдельная строка долга.
- Графические строки (`rows_set.py`) и список нельзя пускать одновременно на этой машине: свободный commit около
  3,3 ГБ, и с началом frontend-сборок списка каждый новый процесс инструмента падает со старта (3221225794,
  0xC0000142) с пустым логом — 236 строк из 272 в остановленном прогоне. Прогоны последовательны.
- В частной стадии надо сохранять `src/l2src/<модуль>.h.lm1`: инструмент импортирует их до того, как новый
  инструмент перепишет заголовки (`l1trans error: cannot read import l2src/lmx_graph_copy_owned.h.lm1`;
  `CF/d7-01/chain02-failed-no-h-lm1`).
