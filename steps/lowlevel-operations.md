# Низкоуровневые операции: исследование Codex, 2026-09-20

## Граница работы

По поручению автора дополнены `docs/L1_spec_ru.md`, `docs/L1_spec_en.md`, `docs/L2_spec_ru.md`, `docs/L2_spec_en.md`. В каждую спецификацию добавлено шесть разделов с одинаковыми якорями: `lowlevel-scope`, `lowlevel-address`, `lowlevel-array`, `lowlevel-abi`, `lowlevel-expression`, `lowlevel-sync`. Это описание контрактов и проверенной поддержки, не исправление исполняемого кода.

Источник контрактов — прежняя `L1/Lingvamyxa_spec.txt`, особенно §§11.3.1, 20, 21, и технические [уточнения автора](../LMX_blog/2026-09-20.md). Машинные конструкции вынесены из семантики L3. Новое правило индексов имеет приоритет над старым требованием проверять Array в обоих уровнях.

Срез для статического исследования: стабильные `LMX/l1src` и `LMX/l2src`, перенесённые Grok. Синхронизация исторического корня L1 описана в [отчёте миграции](l1-l2-migration.md). Параллельная разработка Grok в `dev/l2src_sandbox` не объявляется тем же самым снимком.

## L2: адрес элемента и проверки

Норма автора: `@array[i]` допустимо, адресует настоящий элемент backing графового массива и не выполняет проверку индекса или дескриптора. Обычное чтение/запись L2 также не проверяет границы. Проверяемая операция относится только к L3. Получение backing через дескриптор не равнозначно проверке дескриптора.

| Место в стабильном `l2src/l2trans.lm1` | Наблюдаемое поведение | Значение для исправления |
| --- | --- | --- |
| `l2_array_literal`, строка 6601 | Требует десятичный литерал и сравнивает его с `l2_own_count`; значение вне диапазона отклоняет | Это проверка во время трансляции и ограничение формы индекса; не найденная runtime-проверка |
| `l2_own_index_head`, 6625; `l2_own_index_tail`, 6659 | Используют ограниченный literal-разбор | Для выражений индекса нужен согласованный путь чтения, записи и взятия адреса |
| 9732, 9933, 10059 | `own array index requires an in-bounds primitive literal` | Диагностика отражает прежнее ограничение, не новую норму L2 |
| `l2_check_addr`, 10556; `l2_prep_addr`, 10597 | Различают параметры и own-payload; прямой own-Array отвергается | Неполную поддержку не превращать в запрет языка |
| `l2_emit_array_ptr`, 11350 | Из графового слота получает `LmxArrayDesc`, затем `desc.data`, приведённый к типу элемента | Подходящий существующий путь получения реального backing; проверки границ здесь не обнаружено |
| `l2_emit_array_load`, 11419 | Получает backing и загружает элемент во временную переменную | Адрес этой временной переменной не является адресом элемента |

Существующие отрицательные `l2src/tests/address_array_element.lm2` и `address_array_element_sum.lm2` не подтверждают новую норму. В них встречается возврат адреса из функции с результатом `int`; для положительного теста адреса нужен согласованный указательный тип, а не только смена ожидаемого кода завершения.

Модули `lmx_array_owned.lm1` и `lmx_array_ref_owned.lm1` обслуживают построение/владение массивом. Проверки выделения памяти и служебных структур нельзя удалять автоматически под видом устранения bounds-check при доступе к элементу. Ни одна проверка сгенерированного C или выполнения отрицательного индекса в этом исследовании не запускалась.

## Действительно локальные адреса

`l2src/printTree.lm2` читает путь из письма `mainArgs` и в методе передаёт `@document` как выходной параметр `lm_p0_parse_file`: это адрес переменной, содержащей указатель, не адрес самого документа. `l2src/tests/library_struct_local_forms.lm2` берёт адрес локальной записи импортированного C ABI. Таким образом, адрес локальной переменной имеет реальное назначение, но не заменяет адрес элемента массива или own-payload.

Прежний §11.3.1/§21 отдельно задаёт одноимённую привязку входного параметра к own-полю с момента исполненной строки. Она сохраняет адрес и время жизни той же переменной-параметра и добавляет dirty-публикацию в поле тела, а не в источник аргумента. Это частный контракт параметра, не разрешение адресовать временную копию произвольного own-поля. Его полная реализация отдельно не подтверждена.

## Прочие проверенные границы

- L1 `l1_emit_bracket_array` / `l1_emit_c_array` понижают массивы в C-хранилище; L2 обычный Array использует графовый дескриптор. Разница размещения не добавляет проверок в L2.
- L2 `l2_array_local` покрывает более узкий вариант `c.array`, чем прежний §20.1. Перечень нормативных форм не является утверждением о полной поддержке.
- `@` в выражении отличается от `@:` в типе; `\` для графового пути отличается от сырого доступа к импортированному ABI. В спецификациях приведены соответствующие ограничения парсера и эмиттера.
- Машинный `cast`, C ABI, `foreign`/`extern`, заголовки и `c.sizeof` не подменяют численные преобразователи, именованные пути и допуск L3.
- Для `synchronized` в прочитанных `l1trans.lm1` / `l2trans.lm1` не найден обработчик. Контракт прежней спеки сохранён с явным статусом реализации; готовность синхронизации не заявлена.
