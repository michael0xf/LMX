# Q57. C: makeA() — объявление структуры, не вызов

Дата: 2026-09-30. Статус: **закрыт ответом автора; вопрос был ошибочным**.
Оба предложенных Codex варианта исходили из неверной посылки, что
`makeA()` здесь уже означает вызов. Автор не выбирал между немедленным
и отложенным вызовом: объявляется C, в которую входит именованная
пустая Structure `makeA`.

Это у тебя не вопрос а издевательство. При неизвестном `C` запись `C: makeA()`, мы уже утвердили что **это объявление структуры в которую входит именованная пустая структура &#x20;**`makeA`
То что оно "привычно" выгляит как какой-то вызов -- чистейшая галлюцинация.

## Исправление исследовательского вывода — историческое изложение Codex

В этом объявлении `makeA()` задаёт именованную пустую Structure,
входящую в C. Не вычисляется результат функции и не сохраняется её
вызов для последующего исполнения. Само определение C не исполняет
его содержимое. Внешнее сходство записи с вызовом в другом языке
не является семантическим основанием для вызова в LMX.

Это исправление неверного прочтения уже утверждённого правила,
не новый особый случай для имён C или makeA. Не переносить отвергнутые
варианты ниже в спецификацию, план реализации или новые вопросы.
Код и нормативные документы в рамках закрытия Q57 не изменялись.

### Контекст исходного вопроса

Редакционное уточнение 2026-10-06: префиксная запись merge в следующем
историческом изложении была ошибочным прочтением разговорной опечатки.
Она не является нормой или исключением: правильные применения —
`b: merge: A C`, `b: merge(A C)` либо равнозначный вертикальный Frame.
См. [дословное уточнение автора](../2026-10-06.md#explicit-receiver-frames).

- Неизвестная голова позволяет определить именованную Structure;
  само определение не исполняет её тело. Свободные имена тела не обязаны
  быть известны при определении.
- `B: A` при неизвестном B и существующем A автор назвал присваиванием.
  Это уточнение не заменяем догадкой «B — обёртка, вызывающая A».
- При известной callable-голове действует вызов, а не такое объявление.
- `b: merge A C` сохраняет текущий контракт: явный merge вычисляет
  результат для внешнего получателя. Объявляющий merge с именем результата
  первым аргументом больше не рассматривается.
- Сигнатура не исполняется; её правила не являются ответом для тела.

### Минимальный вопрос в ошибочной постановке

```text
A: ()

fn: makeA () A
return: A

B: A
C: makeA()
```

A — уже существующая Structure; B и C до этих строк отсутствуют.
`makeA` — функция с результатом-Structure. Нас интересует последняя
строка, не повторный выбор смысла `B: A`.

**Что означает `C: makeA()` при новом C?**

1. Выполнить `makeA` сейчас и первоначально связать C с полученным
   структурным результатом, без неявного клонирования.
2. Определить C с сохранённым вызовом `makeA` в теле; выполнить этот
   вызов только при последующем отдельном вызове C.

Это разные моменты исполнения и разные графы: в первом случае C получает
результат функции; во втором C содержит исполняемый шаг, который затем
порождает результат. Различие наблюдаемо для функции с явным побочным
действием или создающей новый результат при каждом вызове.

Нужно общее основание выбора, распространяющееся и на другие выражения
справа. Из «не исполнять тело определения» и «B: A — присваивание»
само по себе ещё не следует, где именно правая часть считается
инициализатором, а где — определяемым телом. Нельзя решить это отдельным
списком имён `merge`, `makeA` и других функций. Скобочная, короткая
и блочная формы не должны переключать семантику.
