# Вызов над callable: строка reference_model_refused переклассифицирована, парный контроль добавлен, 2026-11-25

Строка регрессии `reference_model_refused` (pin `1 1 4`) записана в плане 29.3 (д3) как дефект ядра: присваивание
голому имени читает обёртку без значения до проверки рода, интерпретатор отвечает 5 вместо 4. Трасса показала другое:
отказ интерпретатора возникает раньше тела — исполняется сам Frame `sub`, как и решил автор 2026-11-16 для прежнего
вызова `call(D s)`. Строка переклассифицирована в ошибочный исторический свидетель: источник и pin сохранены, цифра не
менялась. Для современного сценария (написанное требование в точке использования) добавлен нормативный парный контроль
без K2 — две новые строки, зелёные в трёх режимах на принятом комплекте. Ядро не менялось: поправлен один комментарий.

## Решения

Sol и Astra (`CODER-D3-TRACE-20261125-01-EXACT-C`, `CODER-D3-TRACE-20261125-01-ASTRA-ANSWER`).

- Для прежней формы `call(D s)` сохранён выбранным сам объект `s` (решение автора 2026-11-16): автоматический выбор
  `method_code(F)` в `lmx_graph_launch_value` отклонён — это был бы выбор части кода, а не сохранение `s`.
- Сохранить body = выбранная C и условие native на `lmx_graph_run.lm2:5486`; исправить лишь вводящий в заблуждение
  комментарий `launch_value`.
- Нового поиска Model в `place_name` ради этой строки не вводить: в `x := B` нет требования int; брать его из `F\data`
  значило бы неявно выбрать ещё одну Structure; подстановка `F\code` не обосновывает 4.
- В 29.3 строка переклассифицируется в ошибочный исторический свидетель: сохранить источник, pin, наблюдённые 5/1/1 и
  нулевые эффекты; цифру ради зелёного не менять. Отказы двух образов старой формы записать точно; глубокая
  локализация — только для достигаемого современного сценария.
- Нормативный парный контроль без K2: обычная C вложена в D и запускается как `D\C()` без фактических; в теле на одном
  уровне создаётся x (`int: x 0` либо `@: x 0`), пишется явная наблюдаемая метка `entered = 1`, затем
  `int: x tick()`, где tick повышает отдельный счётчик и отдаёт 7. Ожидания: совместимая пара — entered 1, tick 1, x 7;
  ссылочная доходит до проверки вида — entered 1, tick 0. Требование — написанное в точке использования (книга,
  раздел Присваивание и места объявления, `:845–858`; `lmx_graph_work_site`, `:993`; проверка до правой части —
  `lmx_graph_block_body`, `:5193–5208`).

## Норма

- Структурный вызов (`provenance/semantics-book.md:2700–2722`, таблица ресиверов): выбранная Structure C исполняется
  как CODE; вызов не может поставить подменяющего родителя или автоматически выбрать внутреннее тело; у `call(A C)`
  исполняемый объект — C, данные — `parent(C)`; `call` исполняет саму выбранную C, дочернее поле `code` автоматически
  не ищется.
- Там же (`:2724`): callable — просто Structure (решение автора 2026-11-16); особого правила для вызываемого у ресивера
  запуска нет, исполняется поданный объект по его фактическим полям и общим правилам; запрета, автоматического выбора
  тела и особого порядка для вызываемого нет, а что при этом наблюдается — следствие общих механизмов, отдельной
  нормой не закрепляемое.
- Журнал (`LMX_blog/2026-11-16.md`, раздел `call(D s)`): «Ресивер запуска не выбирает часть внутри поданной
  Structure: `call(D s)` исполняет саму `s`, а не её тело; тело `s` над другими данными записывается `call(D s\code)`».
- Присваивание и места объявления (`provenance/semantics-book.md:845–858`, англ. `docs/spec/LMX_semantics.en.md:688`):
  повторная форма на том же уровне использует существующее место; достигнутое объявление ресивера того же уровня
  (`int: i 6`) сохраняет проверку типа, вычисление RHS и присваивание; исполнение повторного ресивера переменной
  сохраняет его действия, включая `bump()` в `int: x bump()`. Присваивание входу вызываемой Structure — локальному
  месту активации — не пишет в исходный граф; явный путь пишет граф.
- Словарь ответов интерпретатора (`lmx_graph_run.lm2:2510–2512`): 3 — неизвестное имя; 4 — запись отказана (слот без
  int-места).

## Трасса прежней формы (gdb, отладочный graph producer, комплект `coder-c99x`)

Номера строк — дерева до правки комментария (после неё строка `:7061` стала `:7062`; прочие не сдвинулись).

1. Первой метки нет: отказ возникает раньше первого оператора кода F.
2. `lmx_graph_launch_value` (`lmx_graph_run.lm2:7061`) передаёт `lmx_graph_invoke_data_value(code = F, data = data,
   body = F)`: body совпадает с code.
3. Исполняется сам Frame `sub: F () (int: x 0) …` из двух ячеек: Structure с именем `data` (часть данных F, одна
   ячейка `x`) и ссылка с именем `code` (часть кода F).
4. Ячейка `data` исполняется как оператор: приложение с именем `data` и одним фактическим `x`; `lmx_graph_eval_selected`
   даёт −1, `lmx_graph_application_head` даёт цель `data`, `lmx_graph_eval_launch_record` (`:6723`) читает фактическое
   (`lmx_graph_launch_operand` даёт 0) и зовёт `lmx_graph_call_data` — ответ 5. `lmx_graph_eval_assignment`,
   `lmx_graph_place_name` и `lmx_graph_place_site` по пути не вызываются.
5. На `:5486` нативный вход недопустим (body ≠ `method_code(F)`), идёт ветка интерпретатора.
6. Проба с меткой (первый оператор кода F — `data\A\v := 5`): интерпретатор снова 5, тело не достигается.
7. Позитивный контроль прежней формы (совпадающая пара: `sub: G () (int: y 0)`, тело `y := 7`; `sub: main () (int: y 1)`;
   `call(data; G)`): интерпретатор 5, native 1, forced 1.

## Образы native и forced прежней формы

Оба образа собираются (перевод успешен); останавливаются при исполнении. В `p.lm1` корневой `call: data F` отэмиссирован
как вызов ядра `lmx_graph_call_data(l2_g, v0, v1, 0)` с возвратом 1 при ненулевом ответе; тело F отэмиссировано как
`lm_graph_body0` — ячейки кадра как операторы с проверкой рода из модели (`lm_graph_emit_model_kind`,
`l2_graph_tool.lm2:1130–1148`, `:1696`), но этот вход не используется: на `:5486` body ≠ `method_code(F)`. Запуск образов
напрямую: код выхода 1, `lmx: R0 was stopped: its turn failed`; с `walkroot 1` — FAIL [R0's program] WalkRoot executes a
nonempty physical root operator graph. Эффектов в данных вызывающего нет: ядро отвечает 5 до всякой записи. Буква 4
образами не достигается — native и forced 4 опровергнуты измерением. (Разбор эмитированных файлов — helper,
`T/red-regress-20261125/helper3/REPORT-D3EMIT.md`, сверен чтением `p.lm1`.)

Все зелёные строки `call(D; C)` имеют C — обычную Structure; с C — sub или fn красны `self_record_dispatch`,
`uninit_reference_merge`, `uninit_reference_places`; зелёна одна мера (`declsel_fncall_self_measure`).

## Парный контроль

**Программы.** `requirement_at_use_ok`: D объявляет `int: x 0`; `requirement_at_use_refused`: D объявляет `@: x 0`.
Обе: C вложена в D и запускается как `D\C()`; тело C на одном уровне — `data\entered := 1` (метка), `int: x tick()`,
`data\x := x`. Метка и последняя запись — явные пути: присваивание голым именем входному месту вызываемой Structure
пишет место активации, а не граф (книга, там же); потому первые пробы с `entered := 1` показывали в печати нули.

**Ожидания до прогона** (`CF/d3-01/pair/NORM-BEFORE-RUN.md`, записаны до первого запуска): совместимая пара — entered 1,
tick 1, x 7, ответ 0; ссылочная — entered 1, tick 0 (правая часть не достигнута), x без изменения, отказ 4 (вид
числового объявления над местом другого рода — как закрепляет `deferred_numeric_type_refused`).

**Прогон** (комплект ниже, `CF/d3-01/rows07`): обе строки `exit 0`, `interp=PASS native=PASS forced=PASS`, AFTER трёх
режимов равны — `1e89afed…` и `c211807b…`. Печать: `int: ticks 1`, `D: int: entered 1; int: x 7`; во второй —
`int: ticks 0`, `D: int: entered 1; @: x 0`; интерпретатор отвечает 4, образы останавливаются. Соседние 20 строк
(семейства `call(D; C)`, `deferred_*`, `physical_reference_*`, `uninit_reference_*`, прежняя строка д3) отвечают как
широкая проверка на G2 (код выхода, вердикты, AFTER).

**Мутант отброшен до прогона.** Проба с автоматическим выбором части кода (`body := method_code(code)` для метода)
строилась в частной стадии как диагностика; по решению Sol она не кандидат и не нужна: стадия `CF/coder-d3probe-build-01`
не завершена и не используется.

## Находки за пределами среза (не закреплены)

- `D\C()`, когда D объявлена в части данных `sub: main ()`: код исполняется над самим собой
  (`lmx_graph_callee_data`, `lmx_graph_run.lm2:1381–1388`: Structure, записанная внутри объявления fn или sub, держит
  чтение над собой). Метка и значение не попадают в D (`CF/d3-01/runs04`, `p1_path_ok`); со ссылкой ответ 1, а не 4
  (`p2_path_refused`). Поэтому парный контроль написан с D, объявленной на корневом уровне (`@: D (…)`), как зелёное
  семейство `deferred_*`.
- `call(D; C)` с C, вложенной в D: ответ 3 для голого `C` — имени нет в кадре main; пишется `call(D; D\C)`
  (`p3_call_ok`).
- `call(D; D\C)` в форме с `sub: main`: буквы 0 и 4 и счётчик tick верны (1 и 0), но явные записи `data\entered` и
  `data\x` не видны в печати части данных main (0 и 0; `p11_main_ok`, `p12_main_refused`). Не локализовано.
- Расписки 57 старых красных строк набора графа (helper, `T/red-regress-20261125/helper3/debts57/`): в списке 58
  строк (57 и `post_loop`); запись в `steps/witnesses/*/witness-rows.tsv` есть у 20, у 38 её нет; расхождений pinа
  с записью — 0.
