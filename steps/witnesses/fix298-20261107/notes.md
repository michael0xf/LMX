## Где было

Ручные запуски под gdb (команды и выводы — в records/pins, `gdb298-*`):

- **Исполнение** (`p-prod.exe` ряда p294l native из b298a, отдельный каталог `P/gdb298-a`): ни `lmx_call_bind_actuals`, ни `lmx_call_note_walk_fail` не вызывались ([bind](records/pins/gdb298-bind-a.log)); метод `call_path` (`l2_m1`) при входе разрешал два скрытых свободных входа (`lmx_activation_resolve_input` для входов 0 и 1), и R0 закрывался сразу ([path](records/pins/gdb298-path-a.log)). В L1 метода это допуск `lmx_walk_admit_free_inputs` при входе: отказ — возврат 2 с броском, который `catch: call` не ловит.
- **Трансляция** (релизный l2trans кандидата fe159c = G2 297 из `cold-tp140/src`, как шаг трансляции suite): оба входа добавляет `lm_compiler_dyn_add` из `lm_compiler_scan_actuals_value` при сборе `lm_compiler_dyn_local` ([dyn](records/pins/gdb298-dyn-b.log); первый запуск `gdb298-dyn-a` прерван ошибкой набора символов команды `x/s`); привязка места вызова получала `idx = −1`, `held = −1` ([site](records/pins/gdb298-site-a.log)); голова фрейма — `node\f0`, семь байт ([head](records/pins/gdb298-head-a.log)); `lm_compiler_path_resolve_contract` для неё возвращал −1 ([contract](records/pins/gdb298-contract-b.log); в `gdb298-contract-a` `finish` без отладочной информации не печатал возвращаемое значение); весь сбор идёт с `l2_cur_mi = −1` при `l2_here_mi` = методу ([cur_mi](records/pins/gdb298-curmi-a.log)).

Причина: сбор скрытых входов идёт до прохода привязки и без текущего метода, а корень `node` разрешается только из метода (`lm_compiler_path_root_select`: «`node` is a method's lexical parent»). `lm_compiler_scan_actuals_value` не находила вызываемого пути, оставляла место вызова несвязанным и читала фактические как написаны: метки `x:` и `y:` — фреймы с головами `x` и `y` — стали чтениями свободных имён. Проход привязки (`lm_compiler_bind_calls`) ставит метод текущим и тот же вызов связывает; эмиттер тоже — поэтому сгенерированный вызов был верен, лишними были два входа. Позиционный `node\f0(1, 2)` меток не имеет; `Places\f(...)` разрешается без метода (корень — именованная Structure).

## Механизм

`lm_compiler_scan_actuals_value` (lower) спрашивает голову вызова (`lm_compiler_call_head_method`, `lm_compiler_call_head_held`) с методом текущим, как проход привязки, и затем восстанавливает `l2_cur_mi` и флаг корня `node` (`l2_uses_node_for_root`), как путевые заметки того же сбора (`lm_compiler_path_use_note`, `lm_compiler_root_use_note`). Место вызова `node\f0(...)` связывается при сборе с объявленной сигнатурой места, именованные фактические — метки, читаются только их значения. Связыватель, эмиттеры и ядро не менялись.
