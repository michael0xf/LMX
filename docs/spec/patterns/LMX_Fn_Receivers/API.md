# Прямой API ресиверов LMX

Current names, superseded spellings, and retained contract differences are recorded in the [naming review](../../NAMING_2026-11-22.md).

## Прямые имена единого ядра

Текущий набор содержит **115 публичных вызовных имён** — callable и Expression-операнды —
и **24 прочих символа**: 14 готовых Patterns, 3 значения настроек, 4 структурных требования
и 3 именованных исхода. Все они входят в текущее единое ядро. Пользователь
пишет `partial(...)`, `map(...)`, `signatureTypes(...)`, `bracket(...)` напрямую;
ни import, ни выбор версии/варианта набора ему не требуются.

`fun` — только внутренняя группа исходных описаний ядра. Её общий `const:`
блок является точным исходным набором экспортов. Подготовка ядра включает
эти owning-field declarations в штатный корневой namespace и сохраняет
настоящие DATA/parent методов. Это не отдельный runtime registry, не второй
граф и не обязательный вызов import при каждом старте программы.
Квалифицированные физические пути `fun\const\map` и подобные остаются
средством явно выбрать соответствующий встроенный receiver при коллизии имён.

[Полный каталог с сигнатурами и ссылками](CATALOG.md) — нормативная таблица этого
пакета. Частые имена приведены к аналогам других языков:

| Было в предложении | Публичное имя | Смысл |
|---|---|---|
| `lambda` | `curry` | Последовательное связывание аргументов, не синтаксис лямбда-выражения |
| `fold` | `foldl` | Левая свёртка |
| `scan` | `scanl` | Левые префиксные результаты с начальным значением |
| `memo` | `memoize` | Кеширование по явно заданному равенству |
| `around` | `bracket` | acquire, action, finally release |
| `until` | `runUntil` | Не затеняет существующий управляющий `until` |
| `retry` | `retryCall` | Не затеняет существующий управляющий `retry` |

При одновременной видимости одноимённых операций других профилей, например
математических map/filter/contract, используется физический путь `fun\const\map`,
`fun\const\filter`, `fun\const\contract` либо предусмотренный общий выбор декларации. Никакое прежнее
значение таких имён глобально не перезаписывается.

Это аналогия назначения, а не обещание равенства всем деталям Haskell/Clojure.
Например, LMX `curry` поддерживает любое конечное число параметров; распространённый
Haskell `curry` работает с парой. LMX `bracket` здесь синхронный и не обещает
маскирование асинхронных исключений Haskell.

## Два уровня результата

**Фабрики типизированных callable** (`curry`, `partial`, `uncurry`, `flip`,
`compose`, `pipe`, `identity`, `memoize`, `fix`, `lazy`, `once`, `recover`,
`adapter`, `permute`, `overload`, `predicate`, `guard`, `trace`, `contract`)
возвращают `@` на обычный метод. Вызов этого метода имеет построенные полные
типы входов и точный `R`, включая процедуру без результата. Например:

```lmx
@: add5 partial(Addition\add; prefix := (5))
int: answer add5(7)
```

**Операции с динамическим результатом** (`apply`, `foldl`, `force`, `runUntil`,
`retryCall`, `bracket`, `trampoline`) возвращают указатель на типизированную
запись значения. Это не преобразование полезного значения в `int` или в
универсальный числовой box. Чтение выполняется обычным разыменованием:

```lmx
@: result apply(operation := chosen; args := (7))
int: answer \result
```

Для процедуры `apply` возвращает явную запись `void` без payload. Она отличается
от готового нулевого `@`, пустой структуры и неинициализированного примитива.
`force(delayed)` возвращает запись; прямой `delayed()` возвращает исходный `R`.

## Записи, Structure и массивы

`record` — подготовленный постфиксный операнд. `(value record)` возвращает
долгоживущую запись полученного значения; примитив снимется по значению, ссылка
сохранит свою цель. Сложное выражение явно группируют: `((a + b) record)`.
Пустой RHS операнда присутствует как пустой массив, а не пропущенный аргумент.

Structure уже есть массив `@`. `(5; "x"; 1.5)` непосредственно содержит записи
трёх типов. `partial` не требует упаковывать каждую такую запись повторно:
`prefix := (5)` содержит ровно требуемую запись числа. `list(values)` возвращает
саму структуру записей; объект с дополнительным полем `items` не появляется.

`map`, `filter`, `foldl`, `scanl`, `zipWith`, `groupBy`, `traverse` передают
значение записи callback его обычным контрактом. Callback для `double` получает
`double`, callback для строки — строку. Разнородный список допустим, если
выбранный callback имеет соответствующий контракт/диспетчеризацию для каждого
элемента; само слово «общий» не отменяет проверки типов.

Плотные `int[]`, `double[]` и строки также принимаются универсальными sequence-ресиверами, `apply` и `partial`. Чтение использует фактический тип и stride; `@[]`/Structure читается по уже хранимым ссылкам. Пользователь не обязан заранее перекладывать плотный массив в массив записей. Вложенный Array/Structure остаётся одним значением; `reinterpret_cast` плотного backing в `void**` отсутствует.

Типовые конструкторы `T[]` и `T@` возвращают обычный int-код: `int@@`, `int[]@`, `int@[]` сохраняют уровни. `[]: value` — неинициализированный AnyArray, а `@[]: value` — требование Structure/массива общих ссылок. Ссылка `@` внутреннего normalizer ведёт к записи кода, а не вводит пользовательскую коробку Type.

## Контейнеры

| Контейнер | Физические поля | Операции |
|---|---|---|
| Maybe | `present:int`, `value:@record` | `some(value)`, `none()`, `bind(input;next)`, `traverse(items;next)` |
| Result | `ok:int`, `value:@record`, `reason:@record` | `ok(value)`, `err(reason)`, `bindResult(input;next)` |
| List | сама Structure / Array<@> | `list(values)`, `map`, `filter`, `flatMap`, `foldl`, `scanl`, `zip`, `zipWith` |
| Bounce | `done:int`, `value:@record`, `next:@callable` | `done(value)`, `more(thunk)`, `trampoline(current)` |

`some(value := (5 record))` хранит число, `some(value := ("x" record))` — строку.
`present=0` означает отсутствие; присутствующий `@0`, ноль, пустая строка и
пустая структура отсутствием не становятся. `bind` для Maybe не выдаётся за
единую реализацию всех монад: для Result есть `bindResult`, для List — `flatMap`.
Контейнерные законы зависят также от переданных функций и их эффектов.

`more` принимает nullary callable; `partial(F; prefix := allActualRecords)`
создаёт его для любого `F`. `trampoline` останавливается по `done`, а не по тому,
является ли итоговый результат callable. Callable как значение не запускается.

## Семантика адаптеров и статус реализации

Сигнатуры анализируются из текущего графа. Порядок и полные требования Ti/R остаются тождеством сигнатуры; имена, defaults и required/private не становятся новой identity. Поведение реальных входов передаётся отдельной source policy, содержащей ссылки на исходные объявления, позиционное отображение и готовый prefix.

В текущих LMX-телах `FxWrap` больше не считывает все pN перед engine. `partial`, `flip/permute`, `once`, `trace`, `guard/contract`, `compose/pipe`, `predicate`, `recover` и `fix` используют подготовленные места реального исходного callable. Пропуск actual остаётся пропуском; собственный default сохраняет исходные DATA/node и видит связанные prefix-позиции. Служебные поля private; обязательность и private пользовательского входа берутся из его действительного объявления. У разных вызовов сохраняется текущий разрешённый контекст связывания.

`uncurry(operation; contract; failures)` выполняет ровно N unary-ступеней либо один nullary-вызов при N=0. Полная сигнатура берётся у достигнутой ступени; промежуточный результат не обязан быть объявлен `@`. Транспортный указатель на результат сохраняет его точную модель. Callable в окончательном R возвращается, а не исполняется ещё раз.

`curry` по смыслу операции принимает и сохраняет текущий вход при завершении очередной ступени; эта собственная demand не переносится на все будущие входы. `repeat/retryCall` снимают готовые явно переданные actuals, сохраняя пропущенный хвост пропущенным для каждого нового вызова.

**Статус:** это конкретная интеграционная реализация, ещё не runtime-подтверждение. Пять узких входов к обычной подготовке/исполнению вызова описаны в [KERNEL_REQUIREMENTS.md](KERNEL_REQUIREMENTS.md). Подробные алгоритмы, binding points, примеры и ограничения проверки — в [ADAPTER_IMPLEMENTATION.md](ADAPTER_IMPLEMENTATION.md). Старые тела сохранены как исторический материал, а не как вторая версия ядра.

### Наблюдение аргументов и кеширование

`trace` передаёт `event.args` как обычную Structure наблюдений. У каждого элемента есть `supplied`, `ready`, `declaration`, `state`, полное `requirement`, вид места и `value` только для готового значения. Пассивный sink не вычисляет default. Для полностью готовых actuals значение доступно как `event.args[i]\value`. Событие не хранит ссылку на живой frame. `recover` передаёт `originalArgs` в таком же формате; untouched inputs не вычисляются ради обработки ошибки.

`memoize` явно выбрал value-key policy: читает все принятые входы в позиционном порядке и фиксирует ключ до сравнения и до тела F. Это собственная операция memoize. Разные autofill-значения не совпадают только потому, что оба actual были пропущены. Default 0 и explicit 0 могут быть равны, если так определяет `sameKey` для принятых значений. Primitive захватывается по значению, reference сохраняет цель; стабильность таких целей для выбранного равенства остаётся договором ключа. Failure F не кешируется.

## Именованное объявление и конструктор типов

Для интроспекции используется `signature(operation := F)`, для построения из
типовых токенов — отдельное прямое имя `signatureTypes`:
`R signatureTypes T0 T1 ...` либо
`signatureTypes(left := resultToken; right := inputTypeRecords)`.
`left` явно означает result, `right` — только inputs. Имя результата не
угадывается по первому/последнему элементу вектора. Раздельные имена избегают
непроверенного overload двух одинаковых const-экспортов и сохраняют однозначные
физические пути. Прежнее публичное имя конструктора удалено без alias.

Единственная форма именованного объявления:

```lmx
Name :: (int: x; double: y; return: double)
```

Новый оператор имеет вид **`R signatureTypes T0 T1 ... TN`**: слева токен результата, справа
все токены входов. Его явная квалифицированная форма:

```lmx
@: requirement fun\const\signatureTypes(left := resultToken; right := inputTypeRecords)
```

`Name :: Signature` заменяет прежний declaration receiver полностью;
старого написания и совместимого alias больше нет. Слева от `::` расположен
объявляемый name atom, а не чтение существующей переменной. Справа — обычный
DATA-шаблон сигнатуры. Это объявление само не исполняет callable.

`::` — обычный операнд выражения LMX, обнаруживаемый через общий
`OPERANDS_TEMPLATE`, а не специальный синтаксический разделитель. Он не открывает
Frame: левое имя не создаёт цель `end:`, границы берутся у обычного выражения. Общий режим
сохранения форм (`PASS_ARGS_AS_IS = 1`) передаёт левый объявляемый идентификатор
декларационному потребителю, не читая его как существующую переменную.
Границы правых аргументов остаются написанными:

```lmx
Name :: A B       # right.length = 2: A, B
Name :: (A B)     # right.length = 1: одна Structure с A и B
```

Эти две формы не эквивалентны. Определённый здесь именованный контракт принимает
**один** правый DATA-шаблон (`Name :: DATA`, включая `Name :: (...)`). Анализ его
полей извлекает входы и результат сигнатуры и не является раскрытием аргументов
операнда. Для нескольких правых аргументов новая сигнатурная семантика этим
пакетом не вводится. P0 сохраняет обе написанные формы; результат функции тоже
не открывается. Конструктор `signatureTypes` отдельно имеет явно заданные
`left = result` и `right = inputs`; это его собственный контракт.

`signatureTypes` является обычным обнаруживаемым type-token операндом;
он не разделяет имя с существующим reflection receiver `signature`. Квалифицированный вызов выше
передаёт ему явные left/right; операндная запись получает их общим механизмом.
Существующее отношение именованного описания с `call` не меняется.
В прочих применениях — хранение, передача, `satisfies`,
ограничение ссылки, `signature` и все новые ресиверы — оба конструктора дают
одно и то же **семантическое** требование. Сравниваются число и порядок полных
типов входов, наличие и полный тип результата. Имена, defaults и текст тела не
становятся частью тождества. Имена сохраняются для обычной адресации actuals;
синтетические `p0`, `p1`, ... отображаются по позиции на реальные входы.

Готовая `int`-запись токена содержит код требуемого типа. `uninit:T` читается по
тегу без обращения к отсутствующему payload. Полное существующее описание
сохраняет модель ссылки/массива/функции и квалификаторы; голый физический код `@`
не заменяет такую модель. `void` обозначает отсутствие результата, не последний
входной тип и не числовой нуль.

P0 ничего не раскрывает. Для единственного исключения нужны все три условия:
**написанная безымянная Structure слева**, **right.length = 1** и **написанная
безымянная Structure в right[0]**. Снимается только её внешний правый контейнер,
один уровень. Left остаётся целой Structure; вложенные правые контейнеры повторно
не открываются. Результат функции, именованная ссылка и произвольный массив
по этому правилу не раскрываются. Поэтому `R signatureTypes (T0 T1)` при обычном
левом токене содержит один правый контейнер; для вектора типов используют
явный `fun\const\signatureTypes(...; right := types)` либо записывают цепочку типов без обёртки.
Это не меняет W/E обычного вызова callable.

## Ошибки <a id="ошибки"></a>

Объявленный именованный отказ вызывающий код либо обрабатывает через `catch`,
либо перечисляет в своём `throws` и передаёт обязанность выше. Обработчик рядом
с каждым промежуточным вызовом не требуется. Метод с необработанными именами в `throws` — компонент,
передающий отказ, а не законченный пример его обработки. Набор ресиверов ядра
не вводит `throws:*`. Общий мост `attempt` перехватывает только явно объявленные
исходы целевого callable и возвращает `Outcome {ok,value,failure,payload}`.

Повторяющийся конечный список записывают один раз и используют обычный поток
полей `copy`: `throws: copy(SharedFailures)`. Если список находится в
`Steps\throws`, ссылка имеет вид `throws: copy(Steps\throws)`. Это обычная
[композиция описания](../../LMX_semantics.en.md#shared-throws), без нового
раскрытия скобок или автоматического наследования обработчиков. Неквалифицированное
`throws` не означает специально «список родителя». Внутренние общие списки
пакета собраны под именем `FxThrows`; это описания существующих имён отказов,
а не новая операция или ещё одна категория ошибок.

Обычные операции, возвращающие запись (`apply`, `bind`, `map`, `bracket` и т.п.),
передают произвольный пользовательский исход как **`FxCallFailure(outcome)`**.
Изначальные имя и типизированный payload сохранены внутри. Пример обработчика:

```lmx
catch: FxCallFailure (@: outcome)
    # outcome\failure — исходное имя; outcome\payload — исходная запись.
```

Это явный контракт такой границы, а не утверждение, что `catch: OriginalName`
без изменений перехватит оболочку. В создаваемых типизированных адаптерах
`FxWrap` ловит внутреннюю оболочку и поднимает исходное имя в CODE с заранее
вычисленным списком `throws`. Прямые `curry/partial/flip/uncurry` также сохраняют
заявленный контракт своих генерируемых ступеней.

`FxTypeToken`, `FxKernelFailure`, `FxArity`, `FxIndex`, `FxRecordArity` обозначают
ошибки типов/строительства/формы; `FxShape`, `FxLazyCycle`, `FxPredicate`,
`FxNoMatch`, `FxAmbiguous` — явные ядерные условия. Структурные операции
сохраняют `ReceiverIndex`, `ReceiverPermutation`, `ReceiverPatchBase`,
`ReceiverPatchFormat`, `ReceiverParent`. Каждый возможный объявленный исход
должен быть обработан подходящим `catch` либо отражён в `throws` вызывающего
примера. Полностью обработанный исход не требуется ещё раз объявлять как
передаваемый выше, если нет другого пути его выхода. Включение операций в ядро
само по себе не превращает их явно объявленные отказы в implicit failures.
Системные implicit failures сохраняют отдельный обычный путь: их обработка
не становится обязательной из-за этих списков, они не объявляются обычным
Result и не подлежат безусловному retry.

`tools/sync_effects.py` разрешает и форматирует конечные списки, сохраняя
заявленные консервативные контракты. Его отчёт `tests/effect_contracts.json`
показывает имена после разрешения общих списков. Это не полный вывод эффектов,
не проверка всех динамических путей и не доказательство, что обязательства
каждого вызова и обработчика удовлетворены; их проверяет реальное ядро.

## Состояние и исполнение

Кеши `lazy/once/memoize`, префиксы и self `fix` принадлежат обычным структурам
состояния в одном Message. Это не потокобезопасное общее состояние Thread.
Межпоточные сценарии используют существующие Message и транспорт, а не
общий изменяемый кеш. Адаптер не создаёт скрытый lexical environment чужой
завершённой активации. Native обновляется только явной компиляцией; старый ABI
с изменённым DATA не переиспользуется автоматически.

## Сравнение размеров кода

Принадлежность к ядру сама по себе **не делает реализацию бесплатной** в
сравнении. Её можно исключить из usage-листинга, только если контрольный язык
тоже пользуется библиотекой или обычным оператором, инкапсулирующим ту же работу.
Если контроль показывает собственную реализацию, сравнивается соответствующее
тело LMX и учитываемое замыкание его зависимостей; короткий вызов ядра сохраняется
как дополнительный вариант. Основным выбирается самый короткий из **честно
сопоставимых** вариантов, а второй вариант не удаляется.

При этом архитектурно оптимальный LMX не переписывается ради совпадения алгоритма
контрольного языка. Собственные общие примитивы LMX — copy, merge, binding,
обычный вызов и работа с графом — законно остаются примитивами языка; их runtime
реализацию не разворачивают в каждом сравнительном листинге. Проверка границы
касается сокрытия специфической работы helper за коротким вызовом, когда другая
сторона показывает эту работу вручную, а не требования одинакового алгоритма.


## Универсальные последовательности: текущий профиль

Полный договор входов, представления результата, границ и aliasing находится в
[SEQUENCES_IMPLEMENTATION.md](SEQUENCES_IMPLEMENTATION.md) и
[нормативном дополнении](../../CORE_SEQUENCES_REGEX.en.md#sequences).
Вход — ссылка на фактический Array или Structure. Плотный массив не становится
массивом `@` из-за передачи в универсальное место. Доступ использует его
реальный element type и stride; Structure уже содержит ссылки на записи.

| Семейство | Публичные имена | Существенный договор |
| --- | --- | --- |
| Построение и выбор | `range`, `slice`, `reverse`, `concat`, `compress` | `range` исключает stop; `slice` принимает begin/end; результат выбора сохраняет профиль source |
| Короткий поиск | `any`, `all`, `index`, `count` | Порядок слева направо; ранняя остановка только у первых трёх; `index` возвращает Maybe |
| Изменение на месте | `replaceRange`, `splice`, `append`, `insert`, `deleteAt` | Проверки и захват перекрывающегося источника до commit; сохраняется descriptor target |
| Ранее существующие операции | `map`, `filter`, `foldl`, `scanl`, `zip`, `zipWith`, `flatMap`, `groupBy`, `select`, `omit`, `reorder`, `project` | Теперь принимают плотные массивы напрямую по тому же общему пути |

`replaceRange(target; begin; end; values)` меняет полуоткрытый диапазон и возвращает тот же target. `splice` с теми же аргументами возвращает снимок удалённых элементов в отдельном контейнере: dense T[] сохраняет T, массив ссылок сохраняет ссылки на записи. Пустой удаляемый диапазон даёт пустой контейнер того же профиля. Вставляемый источник, включая target, захватывается до commit. Текстовый `replace` остаётся отдельной операцией и возвращает новый текст.

`map`, `scanl`, `zip`, `zipWith`, `flatMap` строят массивы ссылок на записи;
`filter`, `slice`, `reverse`, `select`, `omit`, `reorder`, `compress` сохраняют
профиль source. `concat` сохраняет плотный T[] только когда все его части,
включая пустые, имеют один плотный T[]; иначе результат — @[]. `project`
выполняет штатное копирование выбранного графа, в отличие от shallow-выбора.
`zip`/`zipWith` используют минимальную длину. Поэлементная арифметика массивов
имеет собственное правило равной длины и не меняет договор zip.

Один элемент передаётся callback одним явным actual; остальные допустимые
optional/default входы callback не запрещаются. Порядок, собственный DATA,
required/private и тип результата сохраняются обычным вызовом. Общий receiver
передаёт объявленный отказ через `FxCallFailure` с исходным именем и payload;
точные типизированные adapters сохраняют свой declared-exit путь. Частичный
результат не возвращается; уже совершённые внешние эффекты не откатываются.

## Pattern, текст и Expression

[REGEX_IMPLEMENTATION.md](REGEX_IMPLEMENTATION.md) описывает обычные LMX-тела
matcher; [REGEX_EXPORTS.json](REGEX_EXPORTS.json) перечисляет публичные имена,
цели экспорта, готовые значения, зависимости и требуемое подключение к ядру.
Сигнатуры приведены в указанных там исходниках.

| Роль | Имена |
| --- | --- |
| Профиль текста | `utf8Text`, `byteText` |
| Построение | `literal`, `oneOf`, `noneOf`, `charRange`, `satisfy`, `boundaryOf`, `sameAs`, `sequence`, `choice`, `repeated`, `atomic`, `capture`, `ahead`, `notAhead`, `behind`, `notBehind` |
| Поиск | `matchAt`, `wholeMatch`, `find`, `eachMatch`, `contains`, `hasPrefix`, `hasSuffix`, `matches` |
| Преобразование | `replaceFirst`, `replace`, `split` |
| Чтение результата | `matchedSpan`, `matchedText`, `captureSpans`, `lastCapture`, `captureText`, `captureTexts` |
| Expression | `then`, `times`, `atLeast`, `atMost`, `optional`; расширение существующего `|` |

`hasPrefix` проверяет начало в позиции 0, `hasSuffix` — наличие совпадения, заканчивающегося точно в конце текста. Оба возвращают int 1/0, допускают успешное пустое совпадение и используют общую нормализацию literal/Pattern. `hasSuffix` проверяет конец при выборе кандидата, поэтому не теряет подходящую позднюю альтернативу или перекрывающееся совпадение. Ошибка кодировки или callback остаётся ошибкой, а не false. `matches` требует покрытия всего текста; `wholeMatch` возвращает Maybe Match.

Операнды сохраняют общий `OPERANDS_TEMPLATE`, группировку и подготовку
left/right. `|` выбирает Pattern-ветвь только при наличии Pattern среди
логических аргументов. Остальные его значения, приоритет и подготовленные
аргументы остаются действующими. Новый `or` или отдельный regex-parser не нужны.
Обычные ресиверы с именованными параметрами сохраняют обычную форму вызова.

`TextView` хранит исходный descriptor и профиль. Каждая новая операция строит
актуальные индексы текста; `eachMatch` удерживает их в своём iterator. Поэтому
один view пригоден для следующего поиска после завершённой операции и изменения
source. На протяжении самой операции, iterator и использования выданных
результатов действует нормативная стабильность источника. `Match.source` и
`Span.source` сохраняют идентичность исходного view. UTF-8 позиции считаются
в Unicode scalar, byte-профиль — в octet; ошибка кодировки не означает mismatch.

Выбор упорядочен и поддерживает backtracking. Пустой успешный матч отличается
от отсутствия, а capture отсутствующий — от capture нулевой длины. Повторение
с нулевым продвижением заканчивается по нормативному правилу после выполнения
минимума. Замена вызывает callback один раз на выбранный матч и не ищет заново
в добавленном тексте.

**Граница готовности:** исходники matcher написаны; подключение к существующему
`|` и расчёт конечных declared-exit metadata динамических Pattern/callback
зависимостей требуют проверки на настоящем ядре. В этом API ошибки callback
не превращаются в отсутствие совпадения. Внутренняя оболочка ошибки, если её
использует общий транспорт, снимается на нормативной Pattern-границе с
сохранением исходного имени и payload. Это условие интеграции явно сохранено,
а не выдано за успешно выполненную компиляцию.
