## Изменение

В lmx_graph_work_snapshot поле row.cell уже получало raw до классификации.
Для отложенного описания функция теперь сохраняет эту ссылку и возвращает 0.
Первый bare-read по-прежнему вычисляет выбранное описание в активации владельца один раз;
поздние чтения используют текущее собственное значение. Повторного поиска исходного поля нет.

Удалены lmx_graph_description_snapshot и его единственный режим копирования с policy=8.
Обычный lmx_graph_copy_value использует прежний общий copier с map_init, не принимает отдельную policy.
Удалены пять чтений/особых ветвей бита 8 в lmx_graph_copy_owned и одно восстановление parent в copy_metadata.
Биты 1/2/4 и обычное копирование значений, имён и контекста сохранены.
Проверка выбора identity — чтение присваивания row.cell=raw и прямого возврата deferred-ветви;
динамические результаты не объявляются счётчиками копий или измерением аллокаций.

Существующий lmx_gc_graph_frames уже маркирует row.cell, scope, declared и value каждой строки живого кадра.
Нового root-механизма, registry, поля структуры, kernel API, export или нативной фазы не добавлено.
Публичные сигнатуры и ABI4 прежние. Копии готовых значений собственного места не названы execution graph.
W2–W5 снимают остальные найденные зависимости отдельно; весь working graph этим срезом не объявлен удалённым.

## Проверки

Новая frame_computed_description.lm3 использует явно написанные Inputs и Code.
Обычный метод получает их ссылки, дважды вызывает Code над Inputs и сохраняет наблюдения.
На входе выбран int x tick(); тело заменяет source.x на 9 до первого bare x.
Первый вызов читает прежнее описание: tick исполняется один раз, два чтения дают 40+40=80.
Второй вызов выбирает новую 9: результат 18, tick не повторяется, source.x остаётся 9.
Ожидания ticks=1, first=80, second=18, source=9 записаны до исполнения и не ослаблялись.
Формат .expected получен build-only check по нормативному конечному виду данных; Code не исполнялся.
frame-check04.log: interp/native/forced — 3/3 PASS.

Четыре существующих graph-теста дали 12/12 PASS в existing6b.log:
bind_place_computed_once, bind_place_computed_context, bind_place_computed_default, deferred_reference_places.
Итого положительные Graph-проверки — 5 строк, 15 маршрутов.

Новая frame_description_gc.lm2 — штатная machine-строка, expectation 7 до запуска.
Она строит Graph обычным build_file и вызывает его обычным invoke_values.
В его Code обычный вызов Collect после source.x:=9 и до bare x входит в установленный C-entry.
Callback получает свой выбранный owner-data по существующему ABI, не создаёт отдельного executor.
Перед первым sweep он проверяет source.x=9 и ticks=0; перед вторым — source.x=9 и ticks=1.
Следовательно, default не выполняется при входе, а GC расположен после замены источника.
Коллектор — существующий lmx_gc_sweep с новым поколением и штатными execution roots.
Тест удерживает исходный граф и ссылки на наблюдаемые данные; удалённое описание отдельно не маркируется.
После двух вызовов проверяются 1/80/18/9, два Collect и восстановление activation/execution_roots.
