# Q46. Где лежат таблицы транслятора: рядом с программой или в одном месте транслятора

Состояние: 2026-09-28, закрыт — ответ автора (чат fable_pc, ~09:36 UTC; `LMX_blog/2026-09-27.md` «Q46»). Открыт Opus по замечанию fable_pc к срезу 2 ресивера `table` (`steps/table-receiver.md`).

## Факт

- Q36: все настройки — в таблицах `table:`, «как впредыдущем проекте lingvamyxa_prev».
- В lingvamyxa_prev таблицы транслятора — файлы проекта, одни на все программы: `lm2/primitive.lm2` (таблицы `class`,
  `primitive.description`) и `lm2/convert.lm2` (`primitive.convert`). Транслятор ищет их по относительным путям от
  каталога запуска — сначала `lm2/primitive.lm2`, затем `primitive.lm2` (то же для convert; `lm2/trans_l1_l4_registry.lm2`
  :4082–:4093, проверено fable_pc). То есть в prev дом таблиц — каталог проекта, в котором запущен транслятор, а не
  дерево самого транслятора.
- В LMX у транслятора уже есть один корень, задаваемый при запуске: `L2_RUNTIME_ROOT` → `l2_rt_root` (по умолчанию
  `l2src/`), — но им подписываются только пути `predef:` заголовков среды в порождённом L1 (`l2trans.lm1` :405–:412,
  :30081). Для `convert.lm2` каталог запуска местом поиска сделан не был («The launch directory is not a second place
  to look», `l2_convert_beside`).
- В LMX сегодня `convert.lm2` (таблица преобразований) и `convert_impl.lm2` (тела преобразований) читаются рядом с
  источником программы: программа, которой нужно преобразование, держит их в своём каталоге. Так решили агенты
  (тикет fable 2026-09-26-05), не вы.
- Замер (Opus, 2026-09-28, транслятор с пробой): из 873 источников песочницы 279 спрашивают список примитивов, 198 из
  них — только присваивание в тот же тип (`int` в `int`). Когда список примитивов станет таблицей
  (`primitive.description` вместо зашитого `l2_prim_kind`), почти каждая программа без этой таблицы не переведётся.

## Вопрос

Где лежат таблицы транслятора (`primitive.description`, `primitive.convert`, дальше — остальные настройки)?

1. Рядом с источником каждой программы (как сегодня `convert.lm2`): программа носит их с собой и может иметь свои.
2. В одном месте, одни на все программы: (а) как в lingvamyxa_prev — `lm2/` каталога запуска (проекта), в котором
   запущен транслятор; (б) в дереве самого транслятора (`l2src`, рядом с `l2trans.lm1`), а путь к нему задаётся при
   запуске (как сегодня `L2_RUNTIME_ROOT` для заголовков).
3. Иначе.

## Предложение Opus

2 — таблицы транслятора — его данные, а не свойство каталога программы, и так было в прежнем проекте (Q36). fable_pc —
так же: «Q36 говорит „как в прежнем проекте“, а там — не рядом».

До ответа срез 2 кладёт `primitive.lm2` туда же, где сегодня `convert.lm2` (рядом с источником), и обе таблицы читает
в начале трансляции одним загрузчиком: путь к ним вычисляется в одном месте, и перенос обеих — одна правка.

## Как прочитано (fable_pc; при расхождении действует цитата)

таблица — вызов ресивера `table` и часть программы: она лежит там, где программа её поставила — в любом месте программы. Ни фиксированных имён файлов рядом с источником (`convert.lm2`, `primitive.lm2`), ни корня транслятора: транслятор находит `table: source …` в программе тем же общим механизмом, что и любой вызов ресивера. Оба варианта q46 сняты как постановка вопроса о «файлах транслятора»: у транслятора нет своих файлов таблиц — есть таблицы программы. Следствие для среза 2 (`2a48dc7`): ресивер, таблицы источника и столбцы по имени остаются; загрузчик по именам файлов (`l2_input_tables`) — временный и неверный, уходит следующим срезом, до среза 3.
