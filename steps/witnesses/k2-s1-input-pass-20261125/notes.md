# K2, S1: один обход входов — свидетельство, 2026-11-25

План 29.4. Решение Sol и Astra (`CODER-K2-DESIGN-2-20261125-01-S1-BOUNDARY`, `…-ASTRA-ANSWER`): порядок S1 → S2 → S3,
`fncall` — отдельная миграция. S1 — один механизм обхода входов выбранного контракта: для структурного DATA `return` и
соседняя Structure не занимают номера; несколько объявлений под одним модификатором получают разные p, общее внешнее
поле, точные inner/at; `row.slot` — физическое поле; прежние `fn`/`sub`, каталог ресиверов и C9 сохраняют раскладку;
координаты переводятся там, где расходятся; в legacy `lmx_graph_launch_value` ширина `from` совпадает с
`bind_fields_mode`, предел чтения — с формальной шириной; проба старой тройки годится для внутреннего стыка.

## Что было (комплект д5, HEAD `02bb3da2d`; проверено чтением и прогонами до правки)

1. Кадр структурного запуска открывал строку на каждый вход (`lmx_graph_input_field`) и нумеровал строки только по
   входам, а поданные Values клались по номеру формала данных — среди всех полей и объявлений под модификаторами
   (`lmx_graph_bind_fields_mode`, `lmx_graph_invoke_data_value`). Номера расходятся, когда перед входом стоит
   Structure, `return` или callable: строка читала не тот элемент, фактический терялся.
2. То же для объявлений под модификатором: строка читала элемент по порядковому номеру входа, а не по собственному
   номеру формала.
3. `lmx_graph_launch_value` выделял `from` по числу полей данных (плюс один), а связыватель пишет по нему до
   формальной ширины, и поиск слота идёт до неё же. Когда формальная ширина больше числа полей, поиск не находил слот
   последнего входа (отказ 5 — измерен). По чтению, не инструментом: в `launch_input_after_modifier` (два поля,
   формальная ширина 4) связыватель писал одно слово за границей выделенного `from`.

## Что сделано

1. Один обход входов — генератор `lmx_graph_input_next(g, data, @ cursor, @ input)`: 1 и следующий вход, 0 в конце,
   2 для поля, чьи объявления не читаются. Поля берутся в письменном порядке; имя места вычисляется один раз
   (`lmx_graph_binding_name`). Вход держит три числа порознь: порядковый номер среди входов, физический слот данных и
   позицию объявления (holder и at: сами данные у простого поля, аргументы модификаторов поля у объявления под ними);
   отдельно — формальный номер, который дают данные (`lmx_graph_formal_width`). Структуры `LmxGraphInputCursor` и
   `LmxGraphInput` объявлены в заголовке арены. Прежние предикаты без вызывающих (`lmx_graph_input_field`,
   `lmx_graph_input_place`) сняты.
2. `lmx_graph_work_open_parts`: кадр структурного запуска (view = 1) открывает строки этим обходом; поданное Value
   читается по формальному номеру входа. Кадр прежних `fn`/`sub` и Structure над собой (view = 0) открывается, как
   прежде, по строке на поле.
3. `lmx_graph_launch_value`: ширина `from` и предел поиска слота — формальная ширина.
4. Для самопроверки экспортированы два имени ядра (`lmx_graph_formal_width`, `lmx_graph_input_next`); добавлена строка
   полного списка `machine dyn/graph_input_pass.lm2`.
5. Список входов манифеста (`selfbuild/inputs.list`) дополнен 45 файлами фикстур, которые стояли в дереве вне списка:
   11 `sc_tail_*.expected` (K3n), 6 `launch_*_refused` (малая правка `566dfb13f`), 4 `requirement_at_use_*` (д3),
   14 `computed_data_producer_*` (д5), 2 `reference_state_in_frame` (проверка состояния), 8 `launch_input_*` (это
   свидетельство), и самой самопроверкой: 1788 → 1834. Теперь `verify stage` покрывает и их.

## Норма

- `provenance/semantics-book.md:3263–3300` (#structural-call): поданный фактический заполняет выбранное место в новом
  пространстве имён; исходные данные и код не меняются; вход не исполняет инициализаторы.
- `:2498–2503` (#frame-and-graph-assignment): локальное присваивание пишет кадр, явная запись по пути заменяет
  фрагмент графа в выбранном структурном месте.
- #fn-signature: `return` описывает результат и не вход; #binding-places, Р146: вложенная Structure не формал
  автоматически.

## Границы

- Позиционный фактический старой тройки сохраняет номер своей позиции среди всех полей (прежний связыватель
  `lmx_graph_bind_fields_mode`, `slot := i`): у структурных данных, где перед входами стоят поля, не входы, он
  попадает не во вход. Именованный фактический берёт формальный номер своего входа. Связывание по порядку входов
  приходит с общим связывателем S2; S3 снимает тройку. Доложено Sol.
- Формы `C(args)`, `S(D)`, `S(data := D)` и записи `call(D; C)` не менялись — это S2 и S3.
- Values по-прежнему лежат по формальному номеру; порядковый номер входа используется только обходом.
- Самопроверка подаёт фактические только по имени.
- `graph_call_frames`, случай 122 (объявление под модификатором `bump()`: первый вызов отвечает 5, ожидание 9),
  остаётся открытой базовой строкой W4.
