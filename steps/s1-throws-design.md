## Порядок коммитов (каждый под полным гейтом)

База: main после S3 2b и после -127 (S1.1 и S1.3 трогают циклы аргументов вызова в `l2_prep`/`l2_check_primary`, которые -127 переписывает).

**S1.1 — дисциплина статусов неявного канала (без синтаксиса).** Одна нумерация: 0; объявленные 1..d (d = список метода; 0 до S1.2); неявные d+g при ФИКСИРОВАННОМ общем порядке g: `merge` = 1, отказ admission S3 2a = 2 (имя — Q17). Общий g сохраняет точность диспетчеризации через callable-формалы (caller знает d по сигнатуре формала). Места отказа (:15218, :15696 ×3, `l2_emit_admit` S3 2a): `l2_emit_checkpoint` (:13985), затем `l2_out_throw[0]: <payload>; return: d+g`. :13270 перекодирует статус callee: k > d_callee → g = k − d_callee → `return d_caller + g`. Адаптер :16822: при ненулевом статусе `l2_message\running: 0` (:16785), без значения; выход C main 1 не меняется. Внутренние отказы — X1 (инварианты маршрутом диагностики, не канал). Свидетель — ловушка драйвера как root_open/close: все программы собираются с `-Dlmx_merge_owned=l2_driver_merge_owned`, драйвер пробрасывает и валит N-й merge по факту строки `mergefail N`; факт `stopped 1` проверяет `running = 0` у R0 при закрытии. Фикстуры: unit_s1_merge_uncaught (в методе, вызванном из E), unit_s1_merge_uncaught_entry (merge в E). Мутанты: пропустить `running = 0` → RED; мутант checkpoint-на-выходе — в S1.3. Трогает: `l2_emit_body` (:14987, блок `Model: fresh`), эмиссию merge (:15218), `l2_prep` :13268–:13271, адаптер :16804–:16826, таблицу неявных имён и помощник перекодировки. Пины unit_merge_in_method / unit_throwing_callable / unit_recursion сдвигаются намеренно.

**S1.2 — объявленные `throws:` + `throw:` + статическое правило.** `l2_collect_method`: ведущие элементы `throws:` → упорядоченный список; дубликат — отказ; `throws:` не первым — отказ. `l2_body_throws` считает `throws:`/`throw:`. Intern (:3094–:3331) получает упорядоченные имена; callable-формалы сравнивают. `check_body` (:11590): `throw: Name(args)` требует имя в списке — иначе «throw of an undeclared name». Эмиссия: аргументы → payload-Structure в `l2_program_arena` (ячейки как own-поля); checkpoint; `l2_out_throw[0]: payload; return: pos(Name)`. На каждом вызове (цикл `check_primary` ~:11440, statement-вызовы): каждое объявленное имя callee отловлено в цепочке блоков (S1.3) или перечислено, иначе «unhandled throw: <Name>»; у E — «unhandled throw in entry: <Name>». Распространение отображает позицию callee в позицию того же имени у caller. Фикстуры: отказы (не перечислено, необъявленный throw, `throws:` не первым, дубликат, E без обработки) + library-links пин ABI; runtime-позитивы — после S1.3. Мутант: убрать проверку на вызове → строка «не перечислено» ПРИНЯТА (RED).

**S1.3 — `catch:` landing pads (структурно, без правки L1/пина).** На блок с catch: `int: l2_at_B 0` / `while: 1` / сегменты s_j под `if: l2_at_B <= j` / обработчики c_i под `if: l2_at_B = i` / `break`. Доставка после post-call checkpoint: `if: status = k` → связать параметры → `l2_at_B: i` → покинуть вложенные уровни (`break` из каждого промежуточного пользовательского цикла + `if: l2_go_B != 0 -> break` после него, затем `continue` на уровне pad). Catch до вызова — повторный вход в участок; после — продолжение. Вложенные if/while/for/`---` покрыты (Q14 K, :493); ищется ближайший блок, соседи не ищутся; пользовательские break/continue на уровне pad — флаги + break pad-цикла + `if: l2_ubrk_B != 0 -> break`. То же имя внутри своего обработчика — в объемлющий контекст (:495). Два catch одного имени в блоке — отказ. Параметры — позиционный префикс payload: примитивы — проверка домена + типизированная загрузка; Structure — runtime implements через `l2_emit_admit` S3 2a; короткий payload — отказ admission (Q17); без трансляционной проверки согласования (Q12, :293). `catch: merge ()` — неявное имя. Фикстуры: порт t2 (:499–:545); TC повторный вход (:22–:24), после вызова (:25–:28), int payload (:29–:32); доставка в соседний блок; повторный throw того же имени; покрытие через вложенный while; `catch: merge` с `mergefail`; dirty own-поле, опубликованное до throw (чтение после catch по явному пути); отказ дубликата. Мутанты: доставка в первый pad; убрать checkpoint на выходе; без исключения того же имени; без break-guard. Трогает: `l2_check_body`, `l2_emit_body` (понижение блоков), диспетчер `l2_prep`, таблицу pads и связывание параметров.

**S1.4 — callable-формалы:** дескриптор перечисляет throws, позиции — из списка формала; различие списков — отказ сигнатуры. Может войти в S1.2.

Вне S1: идентичность E (S2), дверь `c.*`, диспетчер путей и D1 (-121; catch-параметры типа Structure с чтением полей зависят от D1), P0 (-127), `finally` (нет в L2), `assert`, межмодульные throws библиотек (нет импортов, B1), интерпретаторы.
