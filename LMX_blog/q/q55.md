# Q55. Единый числовой смысл char в native и интерпретаторе

Состояние: решён автором, 2026-09-30. Исходный вопрос сохранён ниже как свидетель расхождения кода; ответ — в конце файла.

Минимальный пример:

~~~text
char: x 200
if: x = 200
    ...
~~~

- dev/l2src_sandbox/primitive.lm2:18 задаёт signed=1,
  range="C99-char(profile)", spelling=char.
- Нативный рабочий char понижается в C char; на текущем профиле 200
  становится -56, сравнение ложно.
- lmx_char_value_known читает байт через &255; интерпретатор сравнивает char
  как 0…255, сравнение истинно.
- unit_t6_root_held_results.lm2 специально ожидает 200 для захваченного char.
  С native верхним телом выход 0 вместо 7: build/l2_harness/s7b107.
- Передача char через типизированную байтовую ячейку уже работает; расходится
  именно числовой смысл рабочего значения, не транспорт callable.

Вопрос: char в L2/L3 — байт 0…255 независимо от знаковости C char, или число
со знаковостью машинного профиля? Native и интерпретатор должны совпадать.
Не исправлять только значение 200, этот тест или возвращённые callable.

Для байтового смысла нужно согласовать общее нативное чтение/материализацию
char и primitive.description. Для профильного — интерпретатор, допуск
литералов и тесты. Новое правило до ответа не вводится.

## Ответ автора

Источник: сообщения автора в текущем чате Codex, 2026-09-30. Каждая цитата — отдельное полное сообщение.

> все типы тупо копируем с C99 и ничего не выдумываем. Выдумываем только свои, массив с len остается C99, просто метод length берет из дескриптора.

## Последующее уточнение автора

> все типы тупо копируем с C99 и ничего не выдумываем. Выдумываем только свои, массив с len остается C99, просто метод length берет из дескриптора -- в L2 границы не проверяются. А L3 уже будет автоматчиески смотреть дескриптор -- то есть реализация массивов L2 и L3 чуть разная. Но index многомерных ровных массивов сверять в L3 только в финале при подсчете конкретного элемента -- по всем размерностям проверять индекс и хранить много длин не надо

## Следствия для реализации, не дополнительная цитата

- Машинные типы и элементы массивов следуют C99 целевой платформы; числовой char нельзя безусловно читать как unsigned char.
- Нумерация байтовых ячеек таблицы интернирования — деталь хранения, не новый числовой смысл char.
- length читает дескриптор; L2 не проверяет границы, L3 проверяет итоговый линейный индекс прямоугольного массива относительно общего числа элементов.
- Отдельные длины и проверки каждой размерности в базовый дескриптор не добавляются. Массив массивов остаётся другим значением с отдельными действительными дескрипторами.
