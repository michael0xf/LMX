# LMX и Julia: 24 характерных сравнения

Редакция **2026-11-23**. Этот самостоятельный набор добавляет Julia к существующим примерам; прежние Haskell/LMX-файлы сохранены. Здесь сравниваются полные клиенты одинаковых задач и отдельно — реализации использованных общих операций. Это сравнение выразительности и объёма исходников, не измерение быстродействия.

**Julia использует настоящие Base и SplitApplyCombine.group. LMX вызывает функции единого ядра.** Четыре модуля в [library_comparisons](library_comparisons/README.md) показывают полные самостоятельные алгоритмы для общего заявленного договора; Julia-клиенты их не импортируют. Для каждого имени ядра в [examples.json](examples.json) есть `implementation_links`, поэтому библиотечный код не исчезает за коротким примером.

## Общий договор и честные границы

Исходный код находится в `source/julia/J01.jl` … `J24.jl` и `source/lmx/J01.lm3` … `J24.lm3`. Каждый клиент загружается отдельно. Точки входа: Julia `example(...)`, LMX `Example\run(...)`. Отдельный стенд передаёт входы, проверяет результаты и нормализует физическое представление. Такой стенд не является частью алгоритма ни одной стороны.

Позиции общих примеров нулевые, полуинтервалы имеют исключённую верхнюю границу. Julia-клиенты J02/J15/J18 явно переводят позиции, и эти символы посчитаны. J01 явно согласует включённую Julia-границу с исключённой границей LMX. В J08 начальное значение добавлено в Julia-результат явно.

LMX возвращает некоторые результаты как Array<@>, Julia — как Vector или Tuple; сравниваются полные значения, порядок и обещанное разделение ссылок. Это не повод заставлять Julia хранить каждое число в отдельной LMX-подобной записи. J12 сравнивает отображение ключей в полные группы; порядок самих групп не входит в общий договор. J19 получает родную Matrix на стороне Julia и массив строк на стороне LMX. Матрицы 0xn с потерянной у массива строк метаинформацией не объявлены взаимозаменяемыми.

J10 имеет два входа одинаковой длины: расширение размерностей broadcast и обрезание zipWith вне этого домена различаются. Все показанные ленивые Julia-итераторы материализуются там, где LMX сразу создаёт массив. Числовые прикладные случаи используют значения без переполнения; из этого не следует совпадение всех числовых профилей языков. J22 ограничен ASCII и не выдаёт байтовые LMX-символы за полноценную Unicode-модель Julia.

J17/J18 сравнивают совместимые неперекрывающиеся входы, поскольку документация Julia отдельно оговаривает разделяемую память у splice!. Полные reference-реализации мутаций рядом также проверяют перекрытие и подготовку типов до записи. Обычные type-admission и allocation failures остаются свойствами соответствующего runtime; общая транзакция не обещается.

Ни один клиент не содержит специальных реализаций ядра под свои числа. Сами алгоритмы в implementation-парах принимают произвольные элементы и callbacks; только range естественным образом строит целые, а предикаты и индексы имеют свой договор. В сортируемой записи сохранены оба поля `key` и `id`; второе делает устойчивость наблюдаемой.

Все эти операции последовательны в одной Message. Асинхронного договора здесь нет, поэтому новые обёртки Message/post не добавлены. Callback не должен изменять обходной массив или ключи сортировки во время операции. Ядро сохраняет обычную динамическую привязку DATA; J13/J15/J24 используют её в прикладном коде.

## Подсчёт и публикации

Главные показатели — **число Unicode-символов без whitespace** и **непустые строки**. Дополнительно сохранено число всех Unicode-символов с пробелами и переводами строк. Комментарии внутри листинга учитываются; код не минифицируется. Тестовые данные, пояснения и harness стоят отдельно у обеих сторон. Варианты с заменой одной строки не размножены.

- [Машинный набор и договоры](examples.json).
- [Локальная статистика JSON](statistics.json) и [CSV](statistics.csv).
- [Общий набор примеров, статистика](../STATISTICS.md).
- [PDF Julia](LMX_Comparison_Julia.pdf) и [XLSX Julia](LMX_Comparison_Julia.xlsx).
- [Реестр общих LMX-зависимостей](validation/implementation_dependencies.json).

Клиенты и реализации суммируются отдельно. Общие LMX-определения считаются один раз; их нельзя заново добавлять для каждой строки. FxKernel, sys, компилятор Julia, её диспетчеризация и сборщик памяти не объявляются реализациями нулевого размера: в архиве сравниваются алгоритмические исходники, а не полные стоимости runtime.

## Проверка и запуск

В среде подготовки **Julia executable отсутствует**. Исполнение обоих языков отмечено `NOT_RUN`; результаты в [semantic_cases.json](validation/semantic_cases.json) — требования приёмки. Выполнены локальные проверки целостности листингов, текущей LMX-формы, полноты ссылок и независимая проверка логических ожиданий на Python. Последняя не называется запуском LMX или Julia.

Для исполнения требуется Julia **1.9 или новее**: этот профиль включает Iterators.flatmap и гарантированную устойчивость стандартной сортировки. Единственный внешний Julia-пакет — SplitApplyCombine. Его разрешённая версия должна быть записана в Manifest фактического запуска; невыполненная установка здесь не выдается за зафиксированное окружение.

Из этой директории:

```sh
python3 tools/rebuild.py
python3 tools/check.py
julia --project=. -e 'using Pkg; Pkg.add("SplitApplyCombine")'
julia --project=. validation/run_clients.jl
julia --project=. validation/run_implementations.jl
```

Установка зависимостей выполняется только явной Julia-командой. Python rebuild не скачивает пакеты и не исполняет языковые клиенты. Для LMX следует загрузить актуальное ядро архива, затем один `.lm3` и передать входы из JSON. Отдельно требуется реальная интеграция уже документированных FxKernel-провайдеров; фиктивного интерпретатора в этом наборе нет.
