## parent переписывается внутри копии merge

Дословное техническое сообщение автора:

```text
1\) "определение нового родителя местом `merge`  " -- я не знаю кто такой бред написал. parent к месту merge никакого отношения не имеет!  merge делает копию используемой части дерева, при этом parent переписываются *внутри копии*, какое это имеет отношение к месту копирования?
```

Это отменяет ошибочную формулировку документации о родителе из места merge.
Исторический вопрос и ответ: [копия лексического состояния](q/merge-lexical-copy-and-root-placement.md).

<a id="factory-reference-result"></a>
## Явное получение результата фабрики через @:

Дословный технический фрагмент сообщения автора; организационное поручение
переписать документы и связаться с агентом сюда не включено:

```text
очевидно надо переписать под @:
```

Речь об исправлении прежнего примера `add5: makeAdder 5`: текущая запись
`@: add5 makeAdder(5)` явно получает результат вызова фабрики. Полный
исправленный пример Codex, одобренный автором для документов, —
[в семантике](../docs/LMX_semantics.ru.md#factory-reference-result).
Историческая цитата сентября сохранена без переписывания в
[закрытом вопросе](q/held-factory-initialization-versus-body-definition.md).

<a id="unknown-head-return"></a>
## Неизвестная голова не становится примитивом из-за return

Дословный технический фрагмент следующего сообщения автора:

```text
3-- очевидно ошибка приеобразования типа при  return: x. Что такое "скрытый вход"?
```

Ответ относится к примеру `fn: f () int` с `int: j 3`, `x: j`, затем
`return: x`, при отсутствии установленного значения x.
Исторические основания и ответ сохранены в
[закрытом вопросе](q/head-role-hidden-input-fixed-point.md).
