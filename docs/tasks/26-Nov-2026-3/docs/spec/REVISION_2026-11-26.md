## 1. Мерность одного плоского массива

```lmx
int[][][]: arr
```

Это требование трёхмерного Array с плоским C-хранилищем. Мерность и размеры
осей сохраняются во внешней служебной записи рядом с capacity. Заголовок
Lmx остаётся `parent/length/storage`; дополнительных полей в пользовательской
Structure, TYPE-записи или скрытом префиксе нет. `sys\descriptor` сохраняет
свой прежний результат.

Над одним и тем же массивом доступны одномерные операции по всем элементам
и операции с учётом его измерений. Например, при размерах `(2,2,2)` обращения
`arr[5]` и `arr[1][0][1]` выбирают одно место. Плоский потребитель не должен
переписывать мерность массива или создавать копию только ради обхода.
Новый результат получает форму согласно своему принимающему договору;
изменение длины не оставляет заведомо неверные старые размеры осей.

Полная норма, сохранение метаданных при копировании/восстановлении и код
проверочной модели: [ARRAY_STORAGE](ARRAY_STORAGE.ru.md).

### Динамические постфиксы типа

Кроме повторных `int[][][]` и `int@@@`, добавлены `int[](N)` и `int@(N)`.
N задаёт число измерений одного массива или число уровней указателя.

```lmx
int[](1): [1 2 3 4]
int@(2): ptr_to_ptr
```

Это соответственно `int[]: [1 2 3 4]` и `int@@: ptr_to_ptr`.
N не является длиной массива или размером одной оси. Он получается
однократно как обычное выражение при потреблении требования типа;
построение требования не выделяет массив или промежуточные указатели.
Полный договор включён в [объявления типов](TYPE_DECLARATION_FORMS.md).

По отдельной просьбе автора динамические постфиксы внесены **только
в спецификацию и описание патча**. Их production-реализация и исполнение
не выполнялись; перечисленные далее host-тесты не являются их проверкой.

### Две записи строк

Эти две формы полностью равнозначны. Значения a, b, c и d предполагаются
уже объявленными int-значениями; пробелы между квадратными группами сохранены.

```lmx
int[][]: [a b c; a b d; a b c]
int[][]: [[a b c] [a b d] [a b c]]
```

Обе дают три строки по три элемента. В первой форме `;` завершает текущую
строку и начинает следующую. Вне инициализатора сохраняется его обычная
роль разделителя коротких форм. Вложенный разделитель вызова или защищённого
литерала не становится границей внешней строки.

Следующие формы ошибочны из-за различной длины строк:

```lmx
int[][]: [a b c; a b c d; a b c d e]
int[][]: [[a b c] [a b c d] [a b c d e]]
int[][]: [[a b c] [a b d] [a b c d]]
```

В первых двух случаях длины равны 3, 4 и 5; в последнем — 3, 3 и 4.
Это ошибки формы транслятора/интерпретатора, а не новый вид массива.

### Обычные структуры не обязаны быть прямоугольными

```lmx
Struct: [a b c] [a b d] [a b c d]
```

равнозначно:

```lmx
Struct: (a b c) (a b d) (a b c d)
```

У Struct три обычных безымянных поля-структуры; длины 3, 3 и 4 допустимы.
Structure остаётся общим `@[]`. Отдельной сущности «массив массивов» нет.
Для соответствующих индексов полей именованный и индексный доступ имеют
следующие записи:

| Именованный/смешанный путь | Индексный путь |
| --- | --- |
| `struct\struct2\field` | `struct[i]\[j]` |
| `struct\struct2\field[k]` | `struct[i]\[j]\[k]` |

Это обычный доступ к графу; он не подменяет соседние индексы координат
плоского массива. [Полные примеры](examples/array_storage/README.md) содержат
корректные и ошибочные объявления, ожидаемые значения и регистрации
doc_examples.

## 2. Depth по логическим измерениям

Общий шаблон операнда получает **left, depth, right**, после которых
сохраняются обязательные константы PASS_ARGS_AS_IS и PRIORITY.

| Форма | Depth |
| --- | --- |
| `a op b` | 0 |
| `a .op b` | 1 |
| `a .(expression)op b` | Результат обычного выражения |

Допускается одна точка; произвольная глубина задаётся в круглых скобках.
Сочетание `.(` всегда начинает модификатор оператора или функции и не
поглощается как десятичная точка, даже в `1.(3)+2.(2)+3`. Общий P0
разбирает содержимое круглых скобок. Выражение глубины получается один раз
при достижении операции; группировка, обнаружение имени и пропущенная
ветвь его не исполняют. Depth не вставляется в right. Отсутствующий left
не заполняется первым правым аргументом.

Depth использует сохранённые измерения плоского массива, начиная с внешнего.
Для двух матриц `(2,2)`:

| Форма | Действие |
| --- | --- |
| `a * b` | Обычное матричное произведение целых значений |
| `a .* b` | Базовое произведение каждой пары логических строк |
| `a .(2)* b` | Произведение каждой пары скалярных координат |

Логические строки адресуются в том же backing. Обход не создаёт отдельные
Structure для строк. Прежнее промежуточное утверждение «любой плоский Array
имеет только один уровень depth» удалено. Одна точка не меняет числовой
смысл в зависимости от ранга.

Ресиверная форма использует базовое имя и именованный depth, например
`` `*`(a; b; depth := 2) ``. Имена с точкой не публикуются как отдельные
стандартные алиасы. Таблица присваивания: `:=` — depth 0, `.:` — 1,
`.(expression):` — явная глубина. `.=` означает сравнение.

Смысл RAW/TYPE/DATA/PLACE задаёт соответствующий ресивер; единый транспорт
не превращает все операции в eager VALUE-map. Неверная глубина, несовместимые
требуемые измерения и непригодный fuse дают диагностику транслятора либо
интерпретатора. Новых пользовательских исключений и дополнительных throws
для этих ошибок нет. [Полный договор и алгоритм](OPERATOR_DEPTH.ru.md).

## 3. Inline Array, арифметика и fuse

В выражениях допускается целое Array-значение `[items]`:

```lmx
@: result a + b + [10 20] + d
@: grouped arr0 .+ arr1 .+ [arr2]
```

`[arr2]` имеет один элемент — целое arr2 с прежней идентичностью. У него
нет неявного singleton-broadcast. В примерах показаны допустимая цепочка
с внешней длиной 1 и несовместимый вариант. Конструктор получает элементы
однократно в обычном порядке. Оптимизация сохраняет группировку,
порядок эффектов/ошибок, типы и наблюдаемую идентичность.

Обычные операции выбирают допустимый массивный/матричный профиль по
фактическим входам. Полное семейство арифметики, битовых операций,
сравнений и изменений использует общую передачу depth. Реализации и
ограничения каждого профиля описаны в [ARRAY_EXPRESSIONS](ARRAY_EXPRESSIONS.ru.md).

`fuse(expression)` получает исходное выражение как RAW и требует пригодного
общего прохода. Он не превращает матричную свёртку в независимые скалярные
ячейки. Обычное присваивание сохраняет всю RHS и проверяет все цели до
первой записи. Явное fused-присваивание имеет собственный потоковый договор
с описанными ограничениями перекрытия. [Полная норма](FUSION.ru.md).

## 4. Условие, срезы и отрицательный доступ

Добавлены ленивое `a ? b : c` и срезы `[start:stop:step]` с пропусками,
отрицательными границами и ненулевым шагом. `[::-1]` разворачивает
последовательность. Источник и написанные границы получаются однократно;
значения и реальные места назначения сохраняют разные роли.

Прямой отрицательный индекс Array не получает смысл отсчёта от конца.
Отрицательное относительное смещение выполняется через указатель.
Интерпретируемый L2 проверяет границу; нативный L2 не вставляет автоматическую
проверку, что не делает неверный доступ корректным. Сохранена прежняя
проверка итогового линейного элемента для полной скалярной nD-адресации;
хранение extents не добавляет само по себе проверок каждой координаты.
[Норма и алгоритмы](TERNARY_AND_SLICES.ru.md).
