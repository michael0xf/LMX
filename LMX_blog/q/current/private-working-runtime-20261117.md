# Откуда рабочий runtime узнаёт, что поле данных запуска объявлено `private:`

Дата: 2026-11-17. Задаёт исполнитель (сессия fable_pc). Статус: **OPEN**.

Норма: [ресивер `private:`](../../../docs/LMX_semantics.ru.md#private-binding); приказ автора
[«признаков мест нет»](../../2026-11-17.md#no-place-signs): «Обходчик выполняет ресивер private прямо из чистого графа!
Транслятор тоже всё знает -- какие скрытые аргументы вставлять а какте нет из того же графа».

## Что измерено

В проекте сейчас два графа. Чистый граф строит построитель из дерева разбора; его исполняет интерпретатор чистого
графа, и запись `private:` в нём после текущего среза лежит как записана. Рабочий граф строит порождённый
транслятором код; его исполняют нативный код и нынешний обходчик (`lmx_walk*`). В рабочем графе записи `private:`
нет вовсе: конструктор для `private: (int: x 10)` кладёт в слот число 10, записывает имя и ставит признак
`binding_private`. Признак — единственный след (замер opus на рабочем наборе шага1 среза420).

Для формалов и локалов кода признак убирается без замены: у транслятора запись есть, и он просто не предлагает
такое имя динамическому связыванию. Для поля данных запуска так не выходит.

## Минимальная программа

```lmx
int: seen 0
D: private: (int: x 5)
C: node\seen := x
call(D C)
```

По норме поле `x` данных `D` не источник динамического связывания: имя `x` в `C` не разрешается, запуск отказывает
(`implements`); с корневым `int: x 7` читается лексический `x`, 7. Сегодня оба исполнителя рабочего runtime так и
отвечают — по признаку. Код `C` транслируется один раз для любых данных, пропуск поля делается на входе в
запущенный код над пришедшими данными, и в этот момент у исполнителя в руках слот со значением 5, а не запись.
Без признака и без записи он прочтёт 5.

## Варианты

- **А.** Признак остаётся в рабочем runtime только у полей данных запуска — до тех пор, пока обходчик и нативный
  вход не перейдут на чистый граф (тогда рабочий граф и его носители уходят целиком, как записано в
  [спецификации ядра](../../../docs/kernel-implementation.ru.md)). У формалов и локалов признак снимается сейчас.
  Чистый граф от признака свободен уже после текущего среза.
- **Б.** Запись `private:` кладётся в рабочий граф при поле уже сейчас, и обходчик с нативным входом читают её.
  Это меняет адресацию значений во всём рабочем runtime.
- **В.** Обходчик переводится на чистый граф раньше остальной очереди: рабочий граф перестаёт существовать, вопрос
  отпадает. Это самая большая работа из трёх.

Предложение исполнителя: А сейчас, В — как плановый путь. Новой таблицы или свойства привязки вместо признака
(вариант «статическая таблица типа») не предлагаю: это тот же признак в другом месте.
