# Реализация и приёмка сервера

<a id="runtime-acceptance"></a>
## Порядок поставки после ядра

Входом служит принятая связка всей грамматики и ядра с реальными графом, кодеком, почтой, `satisfies`, `test`, таблицей преобразований и проектными сценариями на L3. Это один этап до тензорных расширений, полного runtime SLJIT и остальных второстепенных работ. SQLite и необходимые платформенные I/O-привязки подключаются здесь как зависимости конкретных операций. Для каждого шага в расписке указываются ревизии, профиль, вход, наблюдение и незакрытое покрытие. [Полный план](../../next_core_tasks_v3.md#runtime-agent-api-20261127).

| Шаг | Что поставляет разработчик | Различающий опыт |
| --- | --- | --- |
| 3.1. Сервис на LMX | Реальные порты runtime, Service на стороне владельца, допуск, операции чтения и редактирования, пошаговое исполнение и локальные Message | На одном графе два поля указывают на одного потомка, потомок ссылается обратно. Построить из текста до трансляции, получить те же связи после экспорта/импорта в свежий контекст. Счётчики вычисляемого initializer и теста равны нулю. При передаче готового локального графа принимается исходная ссылка по договору владения. Вставить новое определение, скопировать с вложенным alias, сделать один шаг выбранного исполнения. Недопустимая запись не меняет назначение. |
| 3.2. Снимок **перед** компиляцией | Полная доступная топология L3Thread, факты подготовки, запросы навигации и транзакционная публикация | Создать Thread во время работы без исходного файла. Тест затем меняет значение: живой просмотр и каталог сборки должны показать каждый свою основу. На ошибке сборки, занятой БД и отказе gate проверить старую публикацию; после успешной замены отказ по старому курсору. |

Для сквозной приёмки агент находит в каталоге определение, читает его живой `toLmx`, посылает новую Structure через `fromLmx`, владелец устанавливает допущенный обработчик, следующий запрос наблюдает изменённое поведение до компиляции. После **отдельной** компиляции и успешной границы `endturn` запрос видит новую публикацию и соответствующие артефакты. Расписки связывают запрос, фазу, реальное наблюдение и publication token. Любую отсутствующую привязку отмечают `unavailable/notRun` вплоть до первого фактического вызова.

## Чем пользоваться при реализации

- Шесть LMX-модулей описывают порты, модели, Service, каталог, транспорт и Job. Семь потребителей задают сценарии от дерева с таблицей до поздней расписки. У моделей есть неприсоединённые порты. Для проверки реализации требуются принятые P0/Graph, реальные привязки, владельцы и журнал исполнения. [Порты](src/ports.lmx) · [Таблица и дерево](examples/01_table_and_tree.lmx) · [Сценарии](examples)
- Схема SQLite и SQL-запросы исполняемы независимо от LMX. Загрузить DDL и синтетическую публикацию в отдельную пустую SQLite ≥3.37, затем выполнить `00_validate` (ноль строк) и запросы с параметрами из `query_cases.json`. Для отрицательных проверок изменить корневой ключ, удалить обязательные метаданные, подставить отсутствующую цель, повторить ordinal. Открыть второе соединение, сравнить старую публикацию до COMMIT, после ROLLBACK и новую после COMMIT. Такой опыт проверяет хранение и изоляцию. Полноту реального коллектора проверяет LMX-сценарий 3.2. [Схема](schema/catalogue.sql) · [Данные](fixtures/catalogue/sample_publication.sql) · [Параметры и ожидаемые ответы](fixtures/catalogue/query_cases.json)
- Векторы MCP задают формы wire-сообщений, негативные случаи и отдельный поток SSE. Чтение JSON проверяет форму входного материала. Совместимость с клиентом подтверждается записью обмена с работающим LMX-сервером выбранной версии. [Перечень по версиям](fixtures/mcp/MANIFEST.json) · [Контракт протокола](MCP.md#mcp-versions)

### Проверка проектных материалов 27 ноября

На SQLite 3.50.4 синтетическая публикация из 76 фактов прошла 21 проверку запросов и 11 отрицательных проверок, включая неверный корневой ключ. Второе соединение наблюдало старую публикацию до commit и новую после него. Rollback сохранил прежнюю версию. Проверены integrity и отдельный пример FTS5. Структурная проверка ограниченного подмножества LMX прошла для 13 модулей и примеров. В перечне MCP проверены 17 JSON-векторов и один SSE-файл с двумя сообщениями. Расписки запуска LMX-сервера и обмена с клиентами входят в будущую приёмку этапа 3.
