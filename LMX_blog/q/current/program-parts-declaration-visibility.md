# Видимость обычных объявлений между файлами программы

Вопрос Codex автору, 2026-10-09 UTC. Не новый тикет плана и не решение.

Основной файл:

```text
Wide:
    int: x 2
end: Wide
```

Следующий явно переданный файл:

```text
fn: get (Wide: q) int
return: q\x
```

Должен ли следующий файл видеть Wide по общему порядку явно переданных
файлов, одинаково в сигнатуре и теле? Или обычные объявления остаются
видимыми только внутри своего файла? Видимость fn/fm/sub в обе стороны
и видимость обычных объявлений только вперёд сами по себе не определяют
порядок мест в разных документах. Отдельное правило для сигнатур не предлагается.

Факт дефекта: два комментария перед Wide в основном файле меняют принятие
сигнатуры. Каждый файл имеет собственные offsets от нуля. Текущий код
сравнивает offset объявления MAIN с offset заголовка PART:

- `dev/l2src_sandbox/l2trans.lm1`, `l2_collect_method`, 26175:
  при lexical_mi=-1 выставляется `l2_vis_from(fn_node)`;
- тот же файл, `l2_vis_from`, 2874, и `l2_vis_ok`, 2864:
  сравнение смещений без identity документа;
- тот же файл, `l2_type_model`, 20051, и `l2_ns_find`, 20039:
  поиск именованной Structure через это сравнение.

Смещения и номера строк относятся к candidate blob 9922b2ac; после правок
искать указанные символы. Для исходных диагностических пар: Wide/main
153 и getq/part 18 дают отказ; Wide/main 0 и getq/part 18 либо 0 дают принятие.
Ни один из этих случайных результатов не выбирает правило языка.

`steps/table-receiver.md` §8 содержит ответ агента fable_pc о раздельной
видимости файлов; Opus не нашёл авторского решения. RESULT
CODEX-T7-PART-FORMAL-TYPE-20261008-20 получен целиком и это различие отмечает.
Не закреплять тот ответ агента как норму без решения автора. Проверки
receiving-проекции продолжаются независимо; её наблюдаемые free-input
свидетели не требуют Wide в сигнатуре части.
