# C99 — архив человеческих программных возможностей

Компактная коллекция **встраиваемых библиотек**: алгоритмов, форматов,
кодеков, протоколов и средств работы с носителями и устройствами. Назначение —
сохранить полезный, читаемый и собираемый низкоуровневый код для длительной
автономной работы. Глобальная сеть не требуется при сборке; локальная сеть
может быть частью системы.

Это самостоятельная поставка исходников. Предыдущий архив LMX и наложение
патча для её сборки не нужны. Библиотеки находятся в
[`third_party/lmx_c99_compact/`](../../third_party/lmx_c99_compact/).
Компилятор и ядро LMX в эту поставку не включены.

## Что считается подходящим компонентом

Нужна самостоятельная прикладная возможность с C API и производственной
реализацией, собираемой как C99. Важны переносимость, понятная лицензия,
размер и пригодность для включения в приложение. Общее происхождение кода
из другого проекта не определяет его роль: SLJIT полезен как механизм
генерации машинного кода; регулярные выражения — как специализированный
движок сопоставления. Полные среды Lua, Wren, Duktape и Perl сюда не добавлены.

LMX остаётся языком программирования и определяет собственную модель данных.
JSON нужен для обмена с сервисами; PDF, MAT, TIFF и другие включённые форматы
дают доступ к внешним данным. HDF5 и netCDF исключены по итогам отбора,
причины указаны в решениях о составе. YAML/TOML/INI имеют смысл при наличии
внешнего потребителя или реальной зависимости библиотеки. Они не задают
синтаксис, семантику, конфигурационную архитектуру или систему расширений LMX.

llhttp предоставляет разбор HTTP; построение сервиса остаётся за приложением.
CivetWeb и похожий готовый сервисный слой не добавляются вместо библиотечных
механизмов. Примеры в архиве — короткие программы использования API, а не
обязательные процессы будущей системы.

## Компактность и воспроизводимость

В поставке оставлены производственные входы сборки, применимые платформенные
ветви, лицензии, полезная краткая документация и исходники примеров/тестов.
Загрузочные архивы поставщиков, история репозиториев, тяжёлые сайты документации
и результаты наших сборок не включены. Необходимые Windows runtime/import
inputs из исходной коллекции сохранены отдельно и помечены как платформенные
входы, а не как свежесобранные результаты проверки.

Размер `.a` и размер финального приложения различаются: linker выбирает
используемые object files/sections, зависимости могут разделяться. Для новых
компактных библиотек в отчёте приведён фактический размер выбранного профиля,
а не размер скачанного пакета. Размер исходников измеряется отдельно.
Число мегабайт само по себе не определяет пик RAM; размер входных данных,
буферизация, число экземпляров и алгоритм остаются частью выбора профиля.

## Проверить работу

При установленном C99 toolchain, CMake и необходимых системных development
headers/libraries:

В репозитории LMX корневой CMake-файл пакета не установлен: команда запускается от каталога коллекции,
`cmake -S third_party/lmx_c99_compact -B <build-dir> -DCMAKE_BUILD_TYPE=MinSizeRel -DLMX_ARCHIVE_VERIFY=ON`
(собственные `project` и `CTest` коллекции поддерживают ее). Ниже приведена команда самостоятельной поставки.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=MinSizeRel -DLMX_ARCHIVE_VERIFY=ON
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
```

Полная исходная композиция сохраняет графический backend, поэтому на Linux
ей нужны OpenGL development inputs. Для малого устройства можно собирать
отдельные группы и связывать только выбранные targets; примеры команд и
платформенные границы приведены в руководстве сборки.

В [сквозном примере восстановления](../../third_party/lmx_c99_compact/examples/archive/README.ru.md)
CSV проходит через zlib и код Рида — Соломона, записывается, намеренно
повреждается, заново читается и восстанавливается с проверкой CRC и полного
совпадения данных. Исходники примера небольшие и используют уже имеющиеся
библиотеки.

## Лицензии и состояние проверки

Новые компоненты отбираются с явными разрешающими лицензиями без copyleft.
Каждый upstream сохраняет свои условия и notices; лицензия интеграционного
кода не заменяет их. В унаследованной коллекции две позиции — Mint и afan
Neural-Network — сохраняют явную отметку **NOASSERTION**, как в предоставленном
исходном наборе. Они не переименованы в MIT или Public Domain.

Основная выполненная проверка относится к Linux x86_64. Сохранение переносимых
исходников и Windows/macOS/embedded ветвей не означает, что все новые варианты
уже запускались на этих платформах. Полный перечень выполненного и отдельно
отмеченных ограничений находится в отчётах. Известные дефекты и локальные
поправки сохранены рядом с соответствующим адаптером.
