# Нулевая ссылка на данные в печати графа и отказ 3 для именованного поля без формала, 2026-11-25

Приняты одним компонентом две малые правки по красным строкам регрессии (план 29.3, д1 и д2): принтер графа печатает
именованную нулевую ссылку на данные как `@: q int 0`; промах связывания полей Structure аргументов при запуске
отвечает 3, когда именованное поле не находит формала в данных, и 5 — в трёх остальных случаях. Обе строки дефектов
зелёные; добавлены три строки-контроля для трёх случаев, которые должны остаться с ответом 5.

## Решения

Sol, 2026-11-25 (`CODER-SMALLFIX-20261125-01-AND-K2-PRELIM`, уточнение Astra). (д1) именованная ссылка рода 5 с
нулевым адресом печатается `@: q int 0`: проверяется сам адрес, а не отсутствие имени цели — ненулевой адресат без
имени другой случай; в ожидании `checks_pointer_nulled_path` меняется только AFTER для q. (д2) не унифицировать:
ответ 3 только для именованного поля Args, для которого в данных нет формала (в `lmx_graph_bind_fields_mode` имя и
порядковый номер различимы); причина передаётся из того же прохода, логический результат отбора кандидатов
сохраняется; лишняя позиция, повторная подача и пропущенный обязательный формал остаются 5; контроль — строка
`declarg_no_position_left`.

## Свидетельства

**Строки дефектов.** `checks_pointer_nulled_path` на комплекте K5a: печать останавливалась (`graph: the graph does not
print`, выход 1 в трёх режимах); на кандидате три режима печатают AFTER, побайтно равный исправленному ожиданию
(`ec78f6f0…`). `declaration_site_missing` (`call(Args D Code)`, `Args (int: x 7)`, `D (int: seen 0)`: формала `x` в
данных нет) на K5a: интерпретатор отвечала 5 вместо 3; на кандидате — 3, AFTER равен BEFORE (ничего не исполнилось).

**Строки-контроля.** Ожидания записаны до прогона из решения: ответ 5, ничего не исполняется, AFTER равен BEFORE;
текст ожидания — каноническая печать программы (BEFORE), взятая у инструмента. На обоих комплектах три строки зелёные
в трёх режимах (AFTER `5c168801…`, `a4b32d41…`, `fe0147c7…`). Строка `declarg_no_position_left` (контроль по решению)
зелёная на обоих комплектах; её отказ 5 возникает в отборе (`lmx_graph_bind_call_mode`), до запуска, поэтому сама по
себе она не различает промахи места `lmx_graph_launch_value`.

**Регрессия — 272 строки.** Состав: K-список 138; 79 строк семейств `checks_*`, `declsel_*`, `declarg_*` с pinами
последнего свидетеля; добавка 52 — все фикстуры, объявляющие ссылку на данные (`@: name int`) или печатающие её
(`@: name int @цель`), и все фикстуры с записанным ожидаемым ответом 5 (`sf12_supplement_list.py`: pin из списка
свидетеля 2026-11-23, затем из списков graph-baseline); три строки-контроля. Одна фикстура без файла ожидания,
`declare_place_reference`, не запускалась. Итог сравнения комплектов K5a и кандидата (`k3n_compare.py`): 219 строк
зелёны на обоих с равными AFTER; 49 красны на обоих с теми же ответами; 2 строки дефектов стали зелёными; ещё 2 строки
изменили ответ интерпретатора на том же месте останова — `call_named` и `call_receivers`, 5 → 3. Обе остаются красными
(именованная подача и части ресиверов, M11 5е); в их остановившем запуске именованные поля `a` (и `b`) Structure
аргументов не находят формала в данных — это и есть случай решения. Место останова найдено усечением операторов: в
`call_named` без строки `int: with_args fncall(args := main\data\Args; data := main\data\Vars; …)` ответ 0 на обоих
комплектах, с ней — 5 на K5a и 3 на кандидате; в `call_receivers` строка `response := fncall(Args Vars int Body)` даёт
5 → 3 на обоих вариантах программы (с внутренним `inside` и без него). На комплектах K3n части 1, K3n части 2 и K5a
обе строки отвечали 5.

49 красных на обоих: 21 строка K-списка (известные 25 минус две ставшие зелёными и минус `call_named` и
`call_receivers`, изменившие ответ), 10 строк семейств (`declsel_b02`, `declsel_g01`–`g03`, `declarg_a03_*` три,
`declarg_a05_outer_named_inner_name`, `declarg_a17_structure_passed_as_value`, `declarg_outer_name_literal_length`) и
18 строк добавки. Ни одна не изменила ни ответа, ни AFTER.

**Мутанты** (шесть, у каждого своя стадия, runtime и graph producer; репозиторий не менялся; сводка
`runs/mutants-summary.out`):
B1 — всякий промах связывания отвечает 3: пойман тремя строками-контролями (3 вместо 5);
B2 — лишняя позиция подана как отказ требования (3): пойман `launch_extra_field_refused`;
B3 — повторная подача подана как отказ требования (3): пойман `launch_twice_field_refused`;
B4 — обязательный формал не подан — отказ требования (3): пойман `launch_required_missing_refused`;
P1 — принтер отвечает по имени адресата, а не по самому адресу (отвергнутое чтение): ни одна зелёная строка не
различает; меняется вывод одной красной строки (`k3_reference_places`: отказ печати → печать);

## Находки за пределами среза

- `k3_reference_places` (K3: ресивер, объявляющий ссылку, конструирует её) красна с комплекта W3 и красна на всех
  позднейших (K3n, K3n часть 2, K5a, этот кандидат): печать останавливается на ссылке `typed` — именованная ссылка на
  данные с ненулевым адресом, адресат которого не имеет имени. В свидетелях до 2026-11-23 включительно строка была
  зелёной и печатала `@: typed int`. Строка не входит в K-список и в число известных 25. Это и есть второй случай
  решения д1; вопрос о печати такой ссылки отправлен Sol.
- 18 строк добавки красны на обоих комплектах одинаково; среди них семь строк с ожидаемым 5 не отказывают (ответ 0):
  `formal_descriptor_refused`, `formal_empty_structure_refused`, `formal_named_structure_refused`,
  `formal_noncell_refused`, `formal_structure_refused`, `known_data_deferred`, `known_data_mutable_alias`. Они вне
  K-списка. Полный набор фикстур графа (670 строк с ожиданиями) в эту регрессию не входил — войдёт в широкую проверку
  границы этапа.
- Проверка документации (индекс 282): семантика пройдена, 81 из 82 проверок проходят; концы строк красны только от
  пакета автора `third_party/lmx_c99_bundle` (281 находка, как в индексе 281) — восстанавливается отдельным коммитом.

## Границы

- Принтер по-прежнему останавливает печать для именованной ссылки на данные, адресат которой не имеет имени; правило
  для этого случая не записано (вопрос Sol).
- Ответ 3 — только на месте `lmx_graph_launch_value`; отбор кандидатов и прочие места отказа 5 не менялись.
- д3–д5 плана 29.3 остаются.
