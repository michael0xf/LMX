## 2. Единая модель трёх поверхностных форм

### Норма

- [ ] Блочная, короткая/colon и скобочная формы должны быть семантически равноценны во всём языке.
- [ ] Только P0 различает скобочную, short/colon и вертикальную исходные записи. Все допустимые эквивалентные записи он обязан свести к одной нормальной Structure/Frame до передачи транслятору. Транслятор получает готовую нормальную структуру и вообще не рассматривает исходный синтаксис, `---`, скобки или разновидность записи.
- [ ] `LM_P0_FRAME_COLON` и `LM_P0_FRAME_COMPACT`, если сохраняются ради spans/форматирования, не являются семантическим входом транслятора. Resolution, checking и emission не могут читать их для выбора операции.
- [ ] `f(a b)`, `f: a b` и соответствующая вертикальная форма должны после P0 быть одной и той же последовательностью полей, а не тремя случаями транслятора.
- [ ] `f()`, `f: ()` и явно пустая вертикальная форма `f:` с обязательным `---` должны после P0 предоставлять один и тот же нульарный Frame-вход. Одиночное незавершённое `f:` без аргументов, вертикального тела или `---` P0 отвергает и транслятор его никогда не видит. Голый callable `f` не является исключением P0/sugar и не смешивается с этими Frame-формами: см. expression-statement / discard ниже.
- [ ] Единственный анонимный Structure-контейнер всего списка аргументов прозрачен; receiver потребляет его внутренние поля.
- [ ] Пустая Structure/unit при этом остаётся настоящим значением. Чтобы передать её как один аргумент, нужна непрозрачная позиция, например именованное поле.
- [ ] Голый `f` в исполняемой позиции — одноатомное выражение (не P0-исключение и не sugar): после успешного разрешения `f` как callable вызывается с нулём потреблённых аргументов по универсальному callable-first. P0 может сохранить атом; транслятор не различает его по синтаксическим флагам форм. Голый data-атом вычисляется нормально и не вызывается.

### Исправления P0

## 3. Разрешение объявления, присваивания и вызова

### Общая последовательность

- [ ] Сначала построить одинаковую Structure/Frame независимо от формы записи.
- [ ] Разрешить голову и применить единый приоритет: существующее callable-поле → вызов; существующая non-callable привязка → присваивание; объявление → только конструкцией, явно задающей тип. Неизвестная голова без применимой типизированной объявляющей конструкции — ошибка; вывода типа новой переменной из RHS нет.
- [ ] Затем по уже выбранной роли выполнить одну физическую операцию: callable invocation, assignment/rebind либо declaration/construction.
- [ ] Интерпретаторы должны получать уже различённые операции (`CALL`, `SET`/`ASSIGN`, `PUT`), а не повторно угадывать их по исходной пунктуации.

### Объявление

- [ ] Если имя цели отсутствует, а справа синтаксически находится Structure, создать структурную переменную: тип явно задан самой Structure согласно принятому структурному правилу.
- [ ] Сохранить явное типизированное объявление: `Model: fresh` и `Model(fresh)` — синонимы. После разрешения головы callable-модель вызывается по общему приоритету; non-callable модель/тип при отсутствующем `fresh` объявляет структуру `fresh` типа `Model`. Полное значение получается общим `merge` модели с пустой Structure. Это следствие строгой типизации и полного построения, а не отдельное правило для имён `Model`/`fresh`.
- [ ] Произвольный RHS не выводит тип. `ping: 7` при отсутствующем `ping` — ошибка; примитив объявляется только с явным типом (`int: ping 7`).
- [ ] Для непримитивного нового значения полностью выделить требуемую память/графовую структуру согласно его конструктору; неизвестный тип — ошибка.
- [ ] Для пустой Structure одинаково обработать `mystruct: ()`, пустой вертикальный вариант и вариант с `end: mystruct`.
- [ ] Не требовать `KnownModel`, зарезервированное имя или отдельную ветку для пустой Structure.
- [ ] Сделать разрешение явного типизированного объявления и его полное построение одинаковыми для блочной, короткой и скобочной форм; не вводить специальные ветки для буквальных имён `Model` или `fresh` и не превращать техническое понижение через `merge` в самостоятельное правило языка.
- [ ] Устранить зависимость `Model: fresh` от порядка/числа методов. В текущем ядре минимальная единица, где `main` является первым и единственным методом, отвергает эту строку как assignment к необъявленной цели, тогда как добавление перед `main` постороннего метода позволяет тому же объявлению пройти. Нормализация declaration должна опираться только на разрешённую голову, отсутствие binding и явно заданный тип, а не на ранее собранный метод.

### Присваивание

- [ ] Если существует non-callable binding, выполнить обычное присваивание с полным admission/`implements` до записи.
- [ ] Сохранить единственную проекцию непримитивов: Structure/Array binding уже хранит физическую ссылку на дескриптор/вхождение; assignment/call/return копируют ссылку, C by-value aggregate запрещён. `@binding` добавляет уровень адреса ячейки ссылки (`Lmx *` → `Lmx **`), а не превращает создание Structure в ссылочное объявление.
- [ ] Реализовать `@fresh` для Structure binding, созданного `Model: fresh`: разрешать имя через ту же таблицу binding/occurrence, которой принадлежит слот с `Lmx *`, и возвращать адрес именно этой ячейки (`Lmx **`). Текущие `l2_check_addr`/`l2_prep_addr` не находят такой binding и выдают `unresolved name`. Не создавать временную C-переменную, не брать адрес referent и не вводить отдельный адресный механизм.
- [ ] Исправить явный тип `@: Model slot`: именованная Structure уже проецируется как `Lmx *`, поэтому один `@` над `Model` физически означает `Lmx **`. Сейчас `l2_ptr_local_ty` ошибочно отправляет имя модели в общий foreign-C-pointer interner, и generated L1 буквально содержит `@: Model slot`. Сохранить логическую identity `Model` для admission отдельно от физической ABI-проекции; не объявлять C aggregate `Model`.
- [ ] Проверить и закрепить уже правильную ABI-часть: результат `merge`, Structure-formal и Structure-return понижаются как `@: Lmx` в L1 / `Lmx *` в C; assignment/call/return копируют тот же физический адрес. Исправление `@` не должно превратить обычное Structure-значение в `Lmx **`.
- [ ] Считать `ping: 7` присваиванием только когда типизированный non-callable `ping` уже объявлен; «тип ранее фигурировал» означает существующую привязку, а не повторное объявление.
- [ ] Присваивание известного значения всегда семантически выполняет `implements`, даже при кешированных проверенных адресах и оптимизированных C-local slots.
- [ ] При неуспешном admission не менять цель и её `dirty`.
- [ ] Примитивы записывать как значения; Structure/Array и другие non-callable ссылочные значения — как ссылки согласно их контракту, без неявного `merge`, копии или переподчинения.
- [ ] Закончить terminal Structure-reference assignment для прямых имён и путей.
- [ ] Унифицировать direct own/local/formal, explicit graph path и unit-level stores через одну семантическую admission boundary, сохраняя допустимые backend-оптимизации после проверки.
