# fuse: минимальный договор Scalar и Map

`fuse(expression)` — стандартный ресивер, потребляющий один **RAW Expression** общим механизмом. Он требует поддержанного плана без материализации промежуточных Array-результатов этого плана. Окончательный результат, скалярные значения и небольшие описания доступа разрешены. Это не обещание отсутствия RAM-доступа, обязательных регистров или ускорения любого входа.

Полный нормативный договор находится в [TENSOR_EXPRESSIONS.md](TENSOR_EXPRESSIONS.md#fuse-contract). Обычные Array-операции поэлементны. `.(d)op` задаёт один внешний обход; явный depth 0 означает максимум и скалярные ячейки. `[op ...]` внутри fuse сохраняет выбранное индексное/целостное действие. Общие `.op` и callable-алиасы прежней глубины не используются.

## 1. Начальная граница возможностей

**Обязательный первоначальный набор — Scalar и Map→Map с новым результатом.** Координаты, actual-скалярные типы, методы и сборка результата должны поддерживаться. Обычная структура настроек описывает реальные возможности; поле само по себе не реализует алгоритм.

| План | Начальный договор |
| --- | --- |
| Scalar | Поддерживается при допущенном обычном скалярном вычислении |
| Map→Map | Поддерживается для согласованных координат, типов, ролей и порядка |
| Геометрическое чтение внутри Map | Только уже реализованная и проверенная карта доступа |
| Map→Reduce | Нужна отдельная проверенная реализация; не начальный минимум |
| Contraction→Map | Нужен отдельный исполнитель/эпилог; не начальный минимум |
| Contraction→Contraction | Нужен отдельно доказанный план; это не математическая невозможность |
| Поточная запись в существующее назначение | Не начальный минимум; нужны place, alias и договор отказов |
| Общий solve, факторизация или матричная функция | Не начальный минимум; нужны численный и рабочий договоры |

```lmx
FuseMinimum:
    int: scalar 1
    int: map 1
    int: mapReduce 0
    int: contractionMap 0
    int: streamingWrite 0
    int: preserveScalarTypes 1
    int: preserveDemand 1
    int: reassociate 0
```

Это обычные поля. Установка mapReduce в 1 не создаёт редуктор и не разрешает backend нарушить обещание. Ссылки на реализации, поддержанные типы и настройки — обычные структуры и методы LMX, а не второй язык метаданных.

```lmx
[2][3]int: A [1 2 3; 4 5 6]
[2][3]int: B [2 2 2; 2 2 2]
@: result fuse(A * B + 1)
# [3 5 7; 9 11 13]
```

Array поэлементных произведений не материализуется. Один окончательный Array разрешён. Внутри стоит обычный поэлементный `*`; матричное произведение записывается `[*]` и не входит в начальный список.

Structure `[]@` не исключается по типу контейнера. План проверяет actual-типы элементов, поддержку ядра и сборку выхода. Конкретный неподдержанный Structure-результат или неизвестный callback даёт диагностику этого плана.

## 2. Подготовка, захваты и востребованность

Подготовка удерживает живые вхождения выражения, actual-требования и описания доступа. Она не копирует граф программы, не переписывает знаки в новое пространство имён и не запускает произвольные тела при поиске кандидатов. Аргумент RAW: eager-вычисление промежуточных Array до планирования не реализует fuse.

Востребованные исходные значения, удержанные actual, depth-выражения и осевые параметры получаются один раз в исходных контекстах. Захваченное вхождение не вызывается заново для каждой координаты. Два написанных вхождения остаются двумя; кэш по совпадению текста или callable не вводится. Неактивная ветвь не получает параметры заранее.

```lmx
return: fuse(enabled ? A * B : C + bias())
```

Скалярное условие выбирает достигнутую ветвь. Другая ветвь не вызывает методы и не вычисляет depth. Array предикатов не становится скалярным условием случайно; операция mask/select имеет собственный договор.

Удержанный `$value` остаётся целым actual текущего map. Скрытые индексы внутрь него не синтезируются. Явный depth использует [обычный договор обхода](OPERATOR_DEPTH.ru.md): положительное d снимает d внешних осей, d=0 выбирает все, d>K ошибочно для перебираемого Array. Базовое тело вызывается без второго автоматического Map. Неподдержанное действие над оставшейся ячейкой диагностируется; depth не обещает скалярный генератор для любого метода.

Пустой окончательный frame не вызывает ячеечные ядра. Тип и пустой результат берутся из объявленного требования, а не пробного вызова. Вхождения, необходимые для определения формы или выбора достигнутого плана, сохраняют обычную востребованность; нулевой выход не разрешает пропустить произвольные обязательные эффекты источников.

## 3. Численные границы и наблюдаемый порядок

Координаты нового выхода посещаются с последней осью, меняющейся быстрее. Для каждой координаты сохраняются обычное дерево скалярного выражения и востребованность. Промежуточные численные границы допускают и округляют в объявленные типы даже без промежуточного Array:

```text
intermediate = admitAndRound(scalarResult, declaredIntermediateType)
result = evaluateNextScalarOperation(intermediate)
```

Не разрешены неявный переход в machine double, reassociation, FMA или параллельная редукция. Конкретный численный договор может разрешить отдельные преобразования явно. Начальный план принимает только известные действия с сохраняемыми наблюдаемыми эффектами и отказами. Чистота не уничтожает исключения.

Если eager-вычисление целых Array даёт иной наблюдаемый порядок эффектов/отказов, backend обязан доказать сохранение либо отвергнуть fuse. Его написание не разрешает скрыто выбрать другую первую ошибку. Захваты, проверки численной области и допуски нельзя произвольно переставлять через наблюдаемые отказы.

Depth-выражение получается один раз на востребованное вхождение, не во время группировки или расчёта приоритета. Имена в обратных кавычках точны. Неподдержанные грамматика/план/форма диагностируются транслятором, если известны заранее, иначе интерпретатором при достигнутой операции. Пользовательские выражения и выбранные скалярные методы сохраняют обычные throws.

## 4. Окончательный результат и присваивание

Начальный профиль публикует новый окончательный результат после успеха. Он не изменяет существующее хранилище входов или назначения во время скалярного вычисления.

```lmx
result := fuse(A * B + C)
values[:] .: fuse(values * scale + bias)
```

Каждый RHS сначала получает окончательный новый Array, после чего выполняется обычное присваивание. `:=` использует точное поэлементное соответствие; `.:` транслирует до выбранного среза. Fuse справа не включает внешний store в цикл и не выбирает поведение с записанным префиксом при позднем отказе.

Обычное присваивание получает нужные значения RHS до записи и проверяет все actual-допуски назначения перед stores. Поэтому перекрывающиеся перестановки используют snapshot:

```lmx
int: a 1
int: b 2
int: c 3
(a b c) := (b c a)
```

Будущий исполнитель терминальной записи может убрать окончательный временный Array только при соблюдении своего точного договора присваивания/отказов. Он обязан учитывать реальные alias-карты: чтение текущей ячейки, смещение, транспонирование, повторение broadcast и повторная запись различны. Одинаковая форма не доказывает безопасность неизвестной зависимости. Явная streaming-возможность не может скрыто заменить RHS-до-первой-записи частичными видимыми stores.

## 5. Хранилище, View и контекст результата

Результат строится под полным объявленным/вычисленным требованием типа. Постоянная форма не придумывается из данных или забытых строк инициализатора. Временный контекст операции может описывать размеры для следующего действия; публикация соблюдает actual-договор результата/доступа. TypeRef остаётся каноническим указателем типа, capacity — независимой информацией о резерве, заголовок Array — parent/length/storage.

При необходимости системный parent содержит полный контекст экземпляра. Источник/владелец, карта, время жизни и доступ задаются обычными структурами и copy/merge. Выбранные depth-ячейки могут ссылаться на плоские области без выделения Array-строк. Сохранённая ячейка или постоянный View требуют удержанного контекста либо материализации; существующего parent для этого достаточно.

Поддержанная карта View — возможность чтения, а не обещание fusion для любых offset/stride/window/gather. Начальный default постоянного View — read-only. Удержанный владелец не допускает изменений backing/формы, инвалидирующих View. Карта сначала соблюдает логическую область источника, затем границы выделения владельца. Повторное чтение допустимо; повторные записи требуют отдельной детерминированной политики.

Inline `[items]` — явный источник с обычной идентичностью, а не группирующая вершина или арифметический промежуточный результат. Его однократный захват может поддерживаться. Устранение самого конструирования требует отдельного доказательства сохранения идентичности, времени жизни, востребованности и отказов. `[arr2]` остаётся одной целой ссылкой и не разрешает singleton-axis broadcasting.

## 6. Общий алгоритм реализации

Шаги ниже описывают интеграцию, а не новые экспортируемые `sys`-функции:

```text
prepareFuse(rawOccurrence, actualContext):
    inspect roles and supported method capabilities without running bodies
    obtain the reached demanded inputs and dynamic parameters once
    derive compatible output coordinates and complete result requirement
    validate input access maps, scalar numeric boundaries and demand/failure order
    reject any unsupported operation or guarantee
    allocate only the final result and allowed compact access metadata
    for each output coordinate in canonical order:
        obtain required scalar inputs through their checked access maps
        evaluate the original scalar tree, including intermediate admission
        store into the unpublished fresh result
    publish the result under its complete type and parent-context contract
```

Scalar-only использует выбранное обычное скалярное вычисление. Map→Map разделяет одно дерево и карты доступа, а не выделяет дерево или Array-строки для каждой координаты. Настройки — обычные данные; исполнитель должен содержать reader, скалярный генератор и сборщик результата. Договоры скаляров, ленивость и полные типы не заменяются декларацией метаданных.

Неподдержанный план диагностируется транслятором/интерпретатором. Нельзя откатиться к eager-материализации, объявить неготовый View поддержанным или скрыто вызвать общую матричную библиотеку внутри обещанного скалярного плана. Reduce, contraction, accelerators, BLAS/GraphBLAS и C-import — отдельная работа реализации. Две свёртки вне начальных возможностей, а не невозможны математически.

## 7. Проверки и границы заявления о скорости

[Host-модель](tools/array_expression_reference.py) и [тесты](tools/test_array_expression_reference.py) моделируют явный минимум и его отрицательные случаи. Они используют [транспорт depth](tools/operand_depth_reference.py). Это не проверка production-парсера, транслятора или native LMX; их статус остаётся **NOT_RUN** до запуска инструментами проекта.

Для допущенного `fuse(A * B + C)` структурная гарантия — отсутствие промежуточного Array произведений и один окончательный результат. Это не benchmark, обязательный SIMD, нулевой RAM-доступ или обещание ускорения каждого входа. Скаляры со своим хранилищем переменного размера сохраняют правила своего типа. Будущий исполнитель указывает бюджет рабочей памяти; полный промежуточный Array не становится небольшим tile от переименования.
