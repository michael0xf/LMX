# Load / dirty / тип: код LMX `l2src` и старые доки `lingvamyxa`

Сверка 2026-09-20. Стабильный код: корневой `l2src/` (совпадает с L1 root после `2a60beb`). Норма: `C:\Nyasha_Planet\lingvamyxa\Lingvamyxa_spec.txt`. Не выдумывать недостающие механизмы.

## Тип по диапазону адресов

**Док (0.0, 6.5, 9.1):** ссылки читаются по диапазонам типизированных служебных массивов; у ребёнка нет тега типа; Array — отдельный дескриптор `{len,data}` без `Lmx.node`; каждый Message держит свои описания диапазонов.

**Код:** `l2src/lmx.h.lm1` (значение ребёнка попадает в зарегистрированный диапазон; слот сам ничего не типизирует), `lmx_arena.h.lm1` (`lmx_range_classify` / `type_of` / `pool`), `lmx_pool.h.lm1` (рост чанками, адреса не переезжают).

**Итог:** соответствует. Это инфраструктура типов, не семантический `implements`.

## Load own-полей (21.5)

**Док:** на входе тело грузит в C-локали **только** own-поля, которые использует unqualified; явные `node\field` / `a[i]` каждый раз идут в граф; аргументы и dynamic не имеют write-back, пока нет same-name bind (11.3.1); слоты фиксированы.

**Код:** `lmx_own_load` в `l2src/lmx_own.lm1` грузит один слот через `lmx_arena_ref_cell`, `dirty=0`. Явный путь — `lmx_field_read` / `lmx_field_write`, не кэш.

**Итог:** машина load/write/checkpoint соответствует 21.5–21.6. Транслятор не обязан здесь доказывать, что грузит *ровно* `OwnUsed(M)` — это обязанность генератора тела, не этих функций.

## Dirty-only (21.6 / 7.4)

**Док:** dirty только от исполненного присваивания, не от сравнения с графом и не от возможности записи; `@x` не запись; чекпоинт перед вызовом и выходом публикует только dirty, затем сбрасывает флаг; clean не перезаписывает чужие изменения; после вызова нет reload; flush-all запрещён.

**Код:** `lmx_own_write` ставит dirty; `lmx_own_checkpoint` при `dirty=0` ничего не пишет; комментарий в том же файле прямо запрещает flush-all и auto-reload.

**Итог:** соответствует контракту dirty-only.

## Где док и текущий граф расходятся (нужно для интерпретатора)

**21.5.1:** «ALL executable bodies are part of the graph. Callable arguments and return arguments are not graph fields merely by being arguments.» Trailer `return:` потребляет аргумент; indentation не делает его отдельным телом.

**Факт кода:** вызываемое — Structure, слот 0 = METHOD `{addr,sig}` (`lmx.h.lm1`, `lmx_call.h.lm1`). Отдельного слота «ссылка на аргумент trailer return» в записи нет. Интерпретатор, который должен ходить **тот же граф**, что и нативный `addr`, не видит `return:` как поле, пока транслятор не положит ссылку на trailer-аргумент в слот графа.

Это не ломает load/dirty. Это **дыра представления** для интерпретатора: native прыгает в `METHOD.addr`; интерпретатор должен читать те же узлы тела и trailer. Автор 2026-09-20 поручил добавить в граф поля, **ссылающиеся** на заголовки методов и на аргументы trailer `return` — как ссылки (по тому же правилу, что слот 0 уже ссылается на METHOD), не превращая аргументы в own-поля тела вопреки 21.5.1.
