Источник: вопрос автора в чате fable 2026-09-25 (merge методов и сигнатур как частичное применение), дословно:

```text
По поводу исполнения именованных структур и одобренного плана широкого мержа в том числе методов и сигнатур:
haskell:
 add :: Int -> Int -> Int
 add x y = x + y
 add5 = add 5

возможно ли на LMX сделать так:

fn: add (int: x; int y)
 . return: x + y fn:
fn: add5 (int: x) int merge(y: 5; add) #сигнатура add пропадёт

И обратное:

 fn: add5 (int: x)
 . return: x + 5
 add: merge(add5, fn: add (int: y) int (return: x + y)) 

?
```

Ответ координатора (чтение по принятым правилам Q21 = А + «merge методов = интерпретируемый результат»): прямое — да: `fn: add5 (int: x) int merge(add; y: 5)` — модель `add` (первый операнд), `y: 5` переопределяет слот формала `y` значением (формал становится связанным полем), объявленная снаружи сигнатура `(int: x) int` — заголовок результата (сигнатура `add` пропадает), `x` тела `add` разрешается транслятором в формал `x` результата; результат интерпретируется (дескриптор без нативного адреса). Порядок операндов существенен: модель — первая, `merge(y: 5; add)` сделало бы моделью `(y: 5)` и переопределило бы поле `y` несвязанным формалом `add`. Обратное — нет в предложенной форме: тела — op-деревья, дописываемые по порядку; `return: x + 5` модели `add5` исполняется первым, и приписанное тело `return: x + y` не достигается — получится `add5` с лишним формалом `y`. Переопределения тела merge не делает (переопределяются поля, операции дописываются).

То есть если отсутствует именованный аргумент (к пример у sub нет типа return) то мержится как бы с пустой структурой анологичная по смыслу струткура. Потом body мержаться по тому же правилу. Почему, какое тут общее правило -- не знаюно как будто каждая последующа структура хоть и заменяет поля но как бы мержится внутрь. Ты не можешь смержить две директории так чтобы одна поддиректория вдруг оказалась внешней. Плюс это разрешает сиутацию с возвратом внутреннего метода по return -- вокруг него делается с помощью merge такая же обертка

Итог (чтение координатора, к подтверждению): callable = Structure из именованных частей `args`, `return`, `body`; простая Structure = только `body`-часть; merge — попарно по частям, рекурсивно, на каждом уровне по Q21 = А (одноимённое — в слот модели, новое — в конец), отсутствующая часть = пустая Structure того же смысла; модель — внешняя рамка, каждый следующий операнд мержится ВНУТРЬ (поддиректория не становится внешней): `merge(add; y: 5)` — `y: 5` уходит в body add (специализация; заголовок — объявленный снаружи), `merge(y: 5; add)` — обёртка: Structure с полем `y` получает части add и становится callable; так же строится обёртка вокруг возвращаемого вложенного метода.
