# Откуда прежний путь исполнения узнаёт, что поле данных запуска объявлено `private:`

Дата: 2026-11-17. Задаёт исполнитель (сессия fable_pc). Статус: **закрыт ответом автора 2026-11-17 — второго графа
нет, прежний путь удаляется**.

## Вопрос

В дереве два пути исполнения программы. Чистый граф строит построитель из дерева разбора, его обходит
интерпретатор чистого графа; запись `private:` лежит в нём как записана. Второй граф — исполнитель называл его
«рабочим» — строит при старте программы код, выпущенный прежним frontend; его исполняют нативный код этого frontend
и обходчик `lmx_walk*`. Записи `private:` в нём нет: конструктор для `private: (int: x 10)` кладёт число 10,
записывает имя и ставит признак `binding_private`.

```lmx
int: seen 0
D: private: (int: x 5)
C: node\seen := x
call(D C)
```

По норме поле `x` данных `D` не источник динамического связывания. Код `C` транслируется один раз для любых данных,
и на входе в запущенный код у прежнего исполнителя в руках число 5, а не запись. Варианты: А — признак остаётся у
полей данных запуска до перехода на чистый граф; Б — запись кладётся во второй граф; В — исполнение переводится на
чистый граф, второй граф исчезает.

## Ответ автора

> Объясни мне сначала что такое рабочий граф. Убирайте вообще рабочий граф. Сказал же граф не дублируется. Транслятор делает си функции которые принимаю узел чистого графа, а не какого-то другого. Интерпретатор обходит чистый граф, то что у него там свой кадр и какие то namespace не означает что он хранит копию графа. При старте обхода namespace пуст

## Редакторское пояснение (исполнитель, не слова автора)

Вопрос снят: второго графа быть не должно. Транслятор выпускает C-функции, принимающие узел чистого графа;
интерпретатор обходит чистый граф, его кадр и namespace копией графа не являются, при старте обхода namespace пуст.
Второй ответ автора ([журнал](../2026-11-17.md#native-knows-the-graph)): нативный код сгенерирован всезнающим
транслятором, при изменении графа инвалидируется механизмом `endturn` и сам видит граф; иначе нативную часть
вызывает интерпретатор. На чистом графе данные `D` приходят с записью `private:`, так что вопроса нет.
Прежний путь — граф, который строит выпущенный код, обходчик `lmx_walk*` и строки с признаками мест — удаляется
([план](../../next_core_tasks_v3.md#one-graph-plan)).
