## 1. Нормы

- **Q38:** «"outside the copied operand subtree is a shared reference" -- это какая-то чепуха написана потому что merge
  " does not copy unused " -- куда и зачем и для чего и кому тогда shared reference за пределами копируемого? Оно не
  видно за пределами копируемого.»
- **Q42 п. 1** — «да» на формулировку: общая ссылка по адресу — только вхождение метода / вечная ветвь
  `independent: const: immutable` по контракту; всякая иная Structure, до которой доходит используемый граф операнда,
  копируется как изменяемое состояние, где бы ни лежал её родитель. **п. 2:** копируются только читаемые поля.
- **Книга** (`provenance/semantics-book.md`, `merge`; L2 §13): ссылки на общие методы — терминалы своих контрактов;
  поле `A: fn: M` на метод уровня файла остаётся при `merge` общей ссылкой на то же вхождение, `node` метода не
  меняется; метод, объявленный в теле операнда, копируется вместе с операндом; вечная ветвь не копируется; прочее
  используемое изменяемое состояние получает своё хранилище.

## 2. Код сегодня

`lmx_copy_value` (`lmx_graph_copy_owned.lm1`, ветка `kind = LMX_KIND_STRUCT`): Structure, чей родитель вне копируемого
поддерева (или `parent = 0`), — общий терминал по адресу. Это обобщение (k.4, 2026-09-26) шире нормы: вхождение метода
в нём — лишь частный случай «родитель снаружи». Общими по адресу остаются ещё кадры кода (OP/ROLE, K-OT1) и удерживаемые
профили (`retain_profiles` — вечные ветви по контракту). Признака «вхождение метода» у ядра нет: номер домена
`LMX_DOMAIN_KIND_CALLABLE` только объявлен (`lmx_implements.h.lm1` :111), его никто не читает — комментарий о нём там (:104–:110: «lmx_fresh.lm1 and lmx_graph_copy_owned.lm1's Q22=II shared-method-reference terminal test still read it») устарел: ни один из двух модулей его не читает.

## 4. Предложение

1. **Правило k.4 — сузить до нормы.** Общими по адресу остаются кадры кода (OP/ROLE), удерживаемые профили (вечные
   ветви) и вхождение метода. Всякая иная достигнутая Structure копируется, где бы ни лежал её родитель (предки — как
   сегодня: ради правки `parent`, не как поля результата). Пин `lmx_merge_selftest` переворачивается: Structure с
   `parent = 0`, не метод и не профиль, — копия, не тот же адрес.
2. **Признак вхождения метода — q44** (с поправкой fable_pc: сначала спросить, не является ли вхождение метода само вечной ветвью `independent: const: immutable` — тогда признак уже есть). Если нет — рекомендация: вхождения методов лежат в своём массиве арены — вид `STRUCT`, свой
   тип; ядро узнаёт метод по диапазону, как всё остальное (`lmx.h.lm1`: «the type of a child is whichever registered
   address range its stored VALUE falls into»; метки в узле нет). Отвергнутые варианты: слово `native` — у
   интерпретируемого метода оно пусто; «родитель — файл» — детьми файла бывают и именованные Structure.
3. **«Только читаемые поля» (Q42 п. 2)** — там, где читающий известен: захват Structure в callable-merge (пункт 738) —
   транслятор знает пути, которые модель читает у захваченной `loc`; копия несёт только эти поля, и её соответствие
   (копия, тип) → таблица регистрируется в реестре `implements` арены (D-105, REVIEW f4ab0e1 п. 2) — модель читает поля
   индексами своего типа. У `merge` операндов поля операндов и есть поля результата.
