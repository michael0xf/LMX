# LMX: текущие рабочие инструкции

## Действующие решения и владелец — 2026-10-05

Opus продолжает работу Fable как единственный writer/build ядра. Codex отвечает
на вопросы и выполняет согласованный отдельный документационный ход; код Opus
и его проверки не затрагиваются. Старые роли ниже — история продолжения.

Все три вопроса, переданные автору, решены
([дословные уточнения](../LMX_blog/2026-10-05.md)):

- merge копирует используемую часть исходного дерева и переписывает parent
  внутри копии; место исполнения merge не задаёт её лексического родителя;
- результат фабрики явно принимается как `@: add5 makeAdder(5)`; обычное
  определение именованного тела фабрику не исполняет;
- при неизвестном x запись `x: j` определяет Structure; `return: x` из fn,
  возвращающей int, ошибочен по общему правилу типов/преобразования результата.
  Позднее чтение и одноимённое значение вызывающего не делают x примитивным
  скрытым входом задним числом. Свободный вход — не отдельная Structure.

Файлы вопросов перенесены в `LMX_blog/q/`. Сняты только ожидания ответа автора,
а не долги реализации или гейты G5. Opus выравнивает собственные CORE,
журнал и список дефектов по этим решениям в своей посадке.

## Правило отступа — 2026-10-02

Дословная запись автора: [закрытие уровня и return как trailer](../LMX_blog/2026-10-02.md#indent-close).
`---` или другое закрытие обязательно только при снижении больше чем на один уровень; иначе отступ как в Python.
`return` может быть trailer и закрывать свой метод на одном уровне с объявлением метода.

## Стиль записи тел: `end: <name>`, trailer `return:` и закрытие лестницы (автор, 2026-09-23)

Обязательно для всех агентов при написании фикстур, примеров и генерируемого кода; дословная реплика автора — `LMX_blog/2026-09-23.md`.

1. Форма

```text
fn: firstArg (MainLetter: m) @: char
    return: @ m\mainArgs[1][0]
end: firstArg
```

   допустима по правилам парсера, но это **плохой стиль**: `end: <name>` служит для закрытия **длинных** тел. В таком коротком теле `return:` может быть и **trailer'ом** — то есть стоять вместо `end:`:

```text
fn: firstArg (MainLetter: m) @: char
return: @ m\mainArgs[1][0]
```

2. Парсер **не требует последовательного закрытия каждого уровня**: требуется только финальное закрытие лестницы отступов (`---`, trailer или `end:` на нужном уровне). Это единственное отличие от Python. Не вставлять «закрывающие» `---`/`end:` на каждом промежуточном уровне ради симметрии.

   Повтор автора 2026-10-01 (дословно — `LMX_blog/2026-10-01.md`): «закрытия требует только снижение более чем на один уровень, иначе как в Python; в функциях и в процедурах trailer-ом может быть return». То есть `---` пишется **только** там, где лестница снижается больше чем на один уровень; при снижении на один уровень блок закрывает само снижение. В теле `fn`/`sub` трейлером тела может быть `return`. Правило действует для всех агентов при написании фикстур, примеров и генерируемого кода — не только для коротких тел из п. 1.

Следствие для инструментов: генераторы фикстур и `tools/l2_s2_migrate_main.py` должны предпочитать trailer-форму для коротких тел и не добавлять `end:` там, где тело закрывает trailer.
