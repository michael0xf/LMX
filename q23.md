# Q23. Почта: шаги ядра под `sendMessage` / `receiveMessage`

Состояние: 2026-09-25, открыт. Дизайн обёртки — `steps/mail-wrappers.md` (аналог Erlang: `!` / `receive` с выборкой). Ядро трогаем только по вашему слову.

Измерено (`7fd36d6`): `LmxPost` — FIFO-кольцо, взятие только по порядку (`lmx_post_take`); отправитель нигде не записан; родитель-заглушка R0 ящика не имеет; `LmxMsg` = {running, success, handoff_ready, graph}.

- **K1. Выборочное взятие** (для `receiveMessage: m Model`): одна функция `lmx_post_take_if(box, lane, admit, ctx)` — изымает ПЕРВОЕ письмо inbox, для которого `admit(ctx, letter) = 1` (допуск по модели, позиционный `implements`), порядок остальных не меняется. Аналог Erlang selective receive. **Да / нет?**
- **K2. Host-корень с ящиком** — **ОТВЕЧЕНО автором (2026-09-24): да, «родителя сделайте теми же механизмами»**: полноценный Thread (арена, ящик, ход); отличие от R0 — он тот, кто запускает, R0 — пользовательский код; при создании R0 — merge: платформенные `independent: const: immutable` R0 получает от родителя (общей ссылкой), сам R0 платформенно независим; «заглушка» = без родителя (родитель — ОС).
- **K3. Отправитель**: для выборки «по отправителю» и ответов нужна ссылка на отправителя. Варианты: (а) соглашение обёртки — `sendMessage` кладёт ссылку на себя первым полем письма (Erlang `{self(), Msg}`; меняет форму модели письма — `exit` станет `(sender; exit_code; …)`); (б) поле `sender` в `LmxMsg` — ссылка на отправивший Message (ваше правило: поле не из четырёх должно иметь LMX-владельца в графе — владелец здесь сам Message-отправитель?); (в) пока без отправителя — только порядок и модель. **а / б / в?**

Написание без шагов ядра (уже можно): `sendMessage: X` (без адресата — родителю; `sendMessage: Ref X` — адресату по ссылке), `receiveMessage: m` (= прежний `nextMessage`).
