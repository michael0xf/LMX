## 2. Что видит транслятор (P0 и роль единицы)

P0 (printTree из обеих копий парсера, `l1src` и `dev/l2src_sandbox/l1src`, деревья совпадают):

- `Counter:` / `    size_t: n 0U` / `    n: n + 1U` / `    return` (return с отступом) — `frame "Counter"`, тело
  из трёх полей: кадр `size_t`, кадр `n`, **атом** `return`; trailer'а нет.
- тот же `Counter:` и `return` в колонке 0 — `frame "Counter"`, тело из двух полей и **trailer**
  `Tail cutter trailer spelling="return" fields=0` — как `return: 0` в колонке 0 у `fn:`.
- `Counter:` … `end: Counter` — trailer `spelling="end"`.

Транслятор (`l2_unit_role`): именованная Structure (роль 5) — только кадр с головой-идентификатором, закрытый
`end: Name`; любой другой кадр — оператор точки входа E. Её поля строятся при конструировании программы, и
инициализаторы записываются тогда же (`l2_program_build`: для `size_t: v 4U` — `lmx_size_store_known(l2_entry_slot[0],
4U)`), что и есть книга :928. Сегодняшние отказы:

| Программа | Отказ | Почему |
|---|---|---|
| `Counter:` + поле + оператор, `return` в колонке 0 | «unsupported trailer» (1:1) | роль 0: оператор E с trailer'ом |
| то же, `return` с отступом | «unknown method» (2:5) | роль 0: `Counter: <тело>` — оператор, тело читается как аргументы, `size_t: n 0U` — как вызов |
| `Counter:` + поле + оператор, `end: Counter` | «a Structure reference field needs a name» (1:1) | роль 5, но тело принимает только объявления полей |
| `Counter:` + поле, `end: Counter`, затем голое `Counter` | «executing a named Structure is not supported yet» (4:1) | роль 5, исполнение не построено (`unit_bare_struct_refused`) |

## 3. Решения (с опорой)

1. **Trailer голого `return` закрывает именованную Structure, как `end: Name`** — Q19.1 и уточнение («любая …
   включая тип "именованная структура"»). Роль 5 — и для кадра с этим trailer'ом. `return` с отступом — оператор
   тела; у не-`fn` допустим только голый («может быть только "return" без аргументов … и в качестве trailer»).
2. **Конструирование вычисляет инициализаторы, но не исполняет тело** — книга :928 («вычисляются инициализаторы в
   исходном порядке … публикуется полностью инициализированный результат») и норма 2026-09-23 («объявление/
   построение её не исполняет»). Как сегодня: поля вхождения `S` и нового экземпляра `Model: left` (книга :934 —
   merge-копия) имеют значения инициализаторов сразу; операторы тела (не инициализаторы) не выполняются.
   Составление с U2 (Q8, 2026-09-23): `Model: left` на уровне единицы — оператор точки входа; пока он не
   выполнен, ячейка `left` пуста (U2 — о ячейках own-полей единицы до её операторов); когда выполнен —
   merge с вычисленными инициализаторами (книга :928); `left` голым атомом — тело заново (Q19.2).
3. **Исполнение `S` — всё тело, как тело метода** — Q19.2 = 2: объявления исполняются заново на своих местах
   (поле возвращается к инициализатору), операторы тела выполняются. Structure только из полей тоже исполняется:
   её поля возвращаются к начальным.
4. **Последнее состояние остаётся в полях** — книга :1094, :1122, :1124 (публикации, `dirty` и контрольных точек нет).
5. **`S\x` читает, не исполняет** — Q19.2 («не должен запускать выполнение Counter … даже если Counter это метод»);
   правило `M\x` (книга :1094).
6. **Код и данные** — книга :1028; предпочтение fable_pc в REVIEW 9f9bc6f. Шаги тела `S` — в отдельном узле кода;
   данные — узел `S` (его поля на прежних слотах, ns-таблицы `l2_nsf_*` остаются). Имена полей в теле
   разрешаются по ns-таблице `S`, не по own-таблице метода.
7. *Моё, правило G3:* **один исполнитель.** Голое `S` — исполнение пары (код `S`, данные `S`) тем же обходом,
   что исполняет методы под knob: в корне — CALL; в нативном теле метода — `lmx_call_prim(arena, код S, S, …)`
   с `native` = 0, т.е. тот же обход. Второго эмиттера тела Structure нет.

## 4. Раскладка и её свидетели

Узел данных `S` не меняется (решение 6) — ns-слоты не сдвигаются. Новое — узлы кода: по одному на исполняемую
именованную Structure; где им стоять в единице (после методов и ns — как E, чтобы номера прежних дочерних не
менялись) — решается в срезе 2 по замеру. Свидетели до/после (снимаются в срезе, «по построению» — нет): бюджет
типов L3 (`run_l3_selftest`: сегодня 70/128 имён, 999/8192 байт), `lmx_dynarray_layout_selftest` и соседние
layout-selftests (`build_l2src -Run`), Debt-пины harness со слотами единицы (`lmx_arena_ref_struct(l2_entry_unit,
N)`), корпус «до/после» с перечнем изменившихся файлов.

## 6. Срез 1 — сделан (Opus, 2026-09-27)

`l2_unit_role`: роль 5 и у кадра, закрытого trailer'ом голого `return` (`l2_ns_ret_closed`). P0 вешает `return` в колонке 0 на любой предшествующий блок, поэтому именованной Structure становится лишь кадр, который может ею быть: его голова не объявлена полем единицы (`l2_unit_declares` — по форме объявления: слово типа или адрес перед именем, или `Model: name` из одного поля; путь `got: Counter\n` P0 режет на атомы `Counter`, `\`, `n` — это не объявление), и первый элемент тела объявляет поле (`l2_ns_decl_first`; `Name: field` — только с одним полем-именем, `show(7)` — нет). `l2_take_ns_body`: оператор тела — присваивание объявленному выше полю или голый `return` (`l2_ns_body_stmt`) — откладывается; конструирование его не исполняет. Свидетели: `unit_named_struct_return` и `unit_named_struct_stmt` (бывшие `_refused`; `Counter\n` = 4 — инициализатор, не 5), `unit_named_struct_guard_field_refused` и `unit_named_struct_guard_call_refused` (прежние фразы отказа сохранены). Мутанты: без закрытия return — первый свидетель снова отказ; без откладывания операторов — оба; без проверки объявленного поля и без проверки первого элемента — строки стража меняют фразу. Корпус: 743 × 2 — 1482 из 1486 равны, 4 — два свидетеля. Гейт на `35c6fc1`: build 280/280 (103 ran), harness 543/543 (стейдж `fa26095` = блоб), L3 11/11.

## 7. Срез 2 — сделан (Opus, 2026-09-27)

Голое `S` в корне исполняет именованную Structure: CALL(код, `S`) — одна активация обходчика, как у метода. Код — свой узел, дочерний единицы после шагов корня (`l2_nsx_base`; ни один прежний дочерний не сдвинут); данные — сам `S` (книга :1028). Шаги тела: объявление поля-числа снова пишет инициализатор, присваивание полю — значение, `[put, 0, slot, V]`; слот без держателя обходчик читает как данные этой активации (`lmx_walk_data_holder`). Поля хранят последнее состояние (книга :1094). Проход проверки отмечает исполняемую Structure (`l2_check_discard`, `l2_ns_exec`); проход счёта обходит тело каждой обычной именованной Structure с оператором — исполняется она или нет, её операторы проверены там. Голый `return` в теле кончает план (REVIEW 0c601ea, урок e8b8a8d: после точки возврата ничего не строится); хвост после него только проверяется. `return` со значением отказывается своими словами (Q19.1). Анонимный блок из одного исполнения больше не инертен (`l2_body_inert`). Срез обходит только поля-числа, литералы и операторы: другое имя, вызов, преобразование, поле не-число у исполняемой Structure — located-отказ «named Structure body not walkable yet: …»; голое `S` в теле метода — прежний отказ (срез 3); оператор во вложенной или квалифицированной именованной Structure — отказ (её узел не дочерний единицы).

Свидетели (GATED, `tools/l2_harness.ps1`): `unit_named_struct_exec` (пример автора: `Counter\n` = 0 до, 1 после одного исполнения, 1 после двух; заменил `unit_bare_struct_refused`), `unit_named_struct_exec_fields` (int, char, size_t возвращаются к инициализаторам; char-поле берёт ссылку, таблица символов не пишется), `unit_named_struct_exec_return` (n = 1, не 6; исполнение из анонимного блока и тела if), отказы `unit_named_struct_stmt_operand_refused`, `unit_named_struct_dead_tail_refused`, `unit_named_struct_exec_array_refused`, `unit_named_struct_return_value_refused`, `unit_named_struct_exec_method_refused`. Мутанты (копии l2trans): объявление не пишет инициализатор снова, CALL корня не поставлен шагом — три прогона красные; анонимный блок инертен, план не останавливается на return — строка return красная; хвост после return или неисполняемая Structure не проверяются, фраза return со значением или отказ поля-массива сняты — их строки отказа красные. Корпус (0c601ea против этого, оба режима): 751 × 2 — 1486 из 1502 равны; 16 различий — восемь новых свидетелей и заменённый `unit_bare_struct_refused`.

Остаток (замечания REVIEW 0c601ea): (1) управляющий блок `if:` в теле именованной Structure отказывается чужой фразой («a Structure reference field needs a name», 1:1) — Q19.2 «тело целиком» его не исключает, нужен срез с IF/WHILE в теле; (3) `return: n` первым элементом тела — кадр не становится именованной Structure (первый элемент не объявление) и отказывается чужой фразой («assignment target must be a declared typed mutable value», 1:1); после объявления — своими словами.

## 8. Срез 3 — сделан (Opus, 2026-09-27)

Голое `S` в теле метода уровня единицы исполняет именованную Structure. Нативно — та же пара через `lmx_call_prim(arena, узел кода, S, 0, 0U, 0, @ out)` (`l2_emit_ns_exec`): у узла кода нет нативного слова, вызов уходит в крюк обходчика `lmx_walk_call_prim_dispatch` — тот же исполнитель, что у корня (решение 7). Под knob `--walk-methods` — CALL корня в кадрах метода. Нативный текст метода пишется раньше, чем считается раскладка единицы, поэтому узлы кода встали сразу за дочерними именованных Structure (`l2_nsx_base = l2_ns_base + l2_ns_top_count()`, известен заранее, как `l2_ns_base`); в программе без исполнения ничего не сдвигается. Узел кода пустой Structure держит пустую простую Structure, а не голый return: узел стоит перед шагами корня, обход корня проходит каждый дочерний единицы, и голый return прочитался бы как шаг корня.

Вне среза (явно, REVIEW 3d0747b): вложенные и квалифицированные именованные Structure (их узел не дочерний единицы — оператор в их теле отказан ещё в срезе 2), вложенные методы callable merge (`l2_mad_host_of`: исполняются только обходом как конструктор хозяина, нативная функция — заглушка; отказ прежней фразой, строка `unit_named_struct_exec_nested_refused`), библиотечный режим (нет корня и узлов кода). Остаток §7 (`if:` в теле, `return: n` первым элементом) остаётся.

Свидетели (GATED): `unit_named_struct_exec_method` (нативно: bump исполняет Counter дважды и читает 1; корень записал 5 и после вызова читает 1; заменил `unit_named_struct_exec_method_refused`), `unit_walk_named_struct_exec_method` (то же под knob), `unit_named_struct_exec_empty` (пустая Structure из корня и из метода), `unit_named_struct_exec_nested_refused`. Мутанты (копии l2trans): нативное исполнение ничего не пишет — нативная строка красная, строка под knob зелёная; CALL обхода метода не поставлен шагом — строка под knob красная, нативная зелёная; ранняя база на слот дальше — нативная и пустая строки красные («a dynamic call of a value that is not a Structure»); узел пустой Structure снова с голым return — пустая строка красная; страж вложенного метода снят — строка отказа красная (транслирует и исполняет; наблюдаемого эффекта у вложенного исполнения там нет — страж держит отказ до замера). Корпус (3d0747b против этого, оба режима): 753 × 2 — 1494 из 1506 равны; 12 различий — три исполняемые строки среза 2 (L1: сдвиг узлов кода) и три новые исполняемые.

## 9. Две исполняемые Structure (REVIEW b193fbb)

Мутант fable_pc M35 (у `l2_emit_ns_exec` снят ранг узла кода — метод всегда зовёт код первой исполняемой Structure) не менял корпус: у всех фикстур одна исполняемая Structure. Строки `unit_named_struct_exec_two` и `unit_walk_named_struct_exec_two` (проба fable_pc ns3_two_exec): корень исполняет `A`, метод `go` — `B`; `A\n` = 5, `B\m` = 11. Мутанты: ранг снят у нативного исполнения — красна нативная строка, под knob зелёная; ранг снят у CALL обхода — красна строка под knob (корень исполняет первую, его CALL тот же), нативная зелёная. Остаток — управляющий блок в теле — открытой строкой в §GATE плана, чтобы галочка :245 (а) не читалась как «всё тело».

## 10. Срез 4 — предложение: голая структурная переменная (остаток §4 :401; Opus, 2026-09-27; кода нет)

Норма — Q19.2 (автор, `LMX_blog/2026-09-24.md`), в записке §3 решение 2: «`left` голым атомом — тело заново».
Книга :1028: «Structure в позиции головы — код, переданная ей Structure — данные … одному графу разрешено быть и
кодом, и данными».

**Что сегодня.** Голый атом, связанный со Structure — поле единицы `Model: fresh`, формал `(Model: m)`, локальное
поле метода `Box: b`, — отказ проверки «executing a named Structure is not supported yet»
(`l2_check_discard` → `l2_bare_structure`; строка `unit_bare_struct_field_refused`).

**Замер.**

1. `Model: fresh` в корне — PUT/PUT_REF результата примитива `lmx_walk_merge_model` над узлом `Model`
   (`l2_rw_model`): копия merge, её слоты — слоты `Model` в том же порядке. Шагов тела в ней нет: шаги `Model`
   живут в его узле кода, не в узле данных (решение 6).

## 12. Именованная Structure — процедура: замена особого пути путём метода (Opus, 2026-09-28; план)

Норма — автор, Q45 и два её дополнения (`LMX_blog/2026-09-27.md`): «Структура ничем по выполнению не отличатеся от
всего остального. Почему для нее какие-то особые условия? Это просто процедура без аргументов и возвращаемого
значения!!!»; и общее правило того же дня — никаких особых операторов, конструкций и файлов. Особый путь срезов 1–4
этой записки (мой) — баг; правка «добавить `if`/`while` в особый путь» не садится: она латала его.

**Замер (транслятор `2a48dc7`, две программы — `sub: bump ()` и `Counter:` с тем же телом).**

- *Метод*: вхождение — дочерний единицы (`l2_unit_base + mi`): слот 0 — часть `args`, слот 1 — часть `return`,
  собственные поля — со слота 2 (`l2_m_head` = 2, `l2_own_mslot`). Тело — натив `sub: l2_mK (@: Lmx node; @: Lmx self)`,
  собственное поле — ячейка `self` (`lmx_arena_ref_cell(self, 2U)`), объявление заново кладёт инициализатор. Корень
  исполняет его `CALL(код = вхождение, данные = вхождение)`; у вхождения натив — трамплин `l2_mK_tr`, и ядро зовёт его с
  owner = данные (`lmx_walk.lm1`, CALL: «Native: entry(owner=data) … same owner=data rule as lmx_call_prim»).
  `bump\n` читает слот 2 вхождения.
- *Файл* (вход E): тот же механизм метода, но `l2_m_head(E)` = 0 — его поля с 0, «as a named Structure's do»
  (комментарий к `l2_m_head`); его вхождение — сама единица.
- *Именованная Structure*: её узел — дочерний единицы (`l2_ns_base + rank`), поля — с 0 в порядке объявления
  (`l2_ns_slot_named`). Тело — особый путь: разбор (`l2_take_ns_body`, `l2_ns_body_stmt`: объявления, присваивания
  полям, голый `return`; любое иное `X: …` — поле-ссылка) и отдельный узел кода обходчика с урезанным словарём
  (`l2_rw_ns_body`, `l2_rw_ns_item`: только PUT в числовое поле); исполнение — `CALL(узел кода, S)`, нативно
  `lmx_call_prim(узел кода, S)` через крюк обходчика.

**Предложение.**

- Именованная Structure уровня единицы — процедура без формалов и результата, как вход E: метод таблицы методов, голова
  0, тело — тело Structure, переводится общим путём метода (проверка, натив, обход, как у всякого метода). Её
  собственные поля — поля Structure, в её слотах; данные — сама Structure: `self` — её узел, у экземпляра (`Model:
  fresh`, срез 4) — сам экземпляр.
- Исполнение — вызов процедуры: `CALL(код = её вхождение, данные = S)` из корня; нативно — тот же вызов через её
  вхождение (owner = данные); экземпляр — код процедуры его объявленного типа, данные — он.
- Разбор тела: объявление поля — поле (раскладка типа Structure не меняется); всё прочее — оператор тела, в том числе
  вызов ресивера (`if`, `while`, `for`, вызов метода) — не поле-ссылка.
- Уходит особый путь: `l2_rw_ns_body`/`_item`/`_count`/`_emit`, узлы кода `l2_nsx_*`, `l2_ns_stmt`/`l2_ns_steps`,
  исполнение через узел кода (`l2_emit_ns_exec`, `l2_rw_ns_call`, `l2_rw_ns_var_call`).
- `return: n` в именованной Structure — одни слова в любом месте тела (Q45).
- Инвариант при регистрации: слот каждого собственного поля процедуры — слот поля Structure того же имени; расхождение —
  located «internal». Вложенные и квалифицированные именованные Structure — как вложенные методы (сегодня оператор в
  них отказан — это следующий шаг, строкой).

**Свидетели.** Все прежние строки этой записки (`unit_named_struct_exec*`, `_fields`, `_return`, `_method`, `_two`,
`_instance`, `_empty`) — те же результаты; новые — `if:`/`else:`, `while:`, `return` в блоке, вызов метода и `for:` в
теле `Counter`, исполненного из корня, из метода и под `--walk-methods`. Мутанты: исполнение через прежний узел кода,
тело без операторов, `self` — не данные.

## 13. §12 — сделано (Opus, 2026-09-28)

**Что сделано.** Именованная Structure уровня единицы, у которой в теле есть оператор или которую исполняют, — процедура:
метод таблицы методов (`l2_ns_proc`), зарегистрированный до входа E (`l2_ns_procs`, `l2_ns_proc_add`), без формалов и
результата. Тело процедуры — тело Structure, и собирается, проверяется, пишется нативно (`sub: l2_mK (node, self)`) и
обходится общим путём метода. Свои поля процедуры — поля Structure: `l2_own_mslot` берёт слот по имени
(`l2_ns_slot_named`). Данные — сама Structure (у экземпляра, срез 4, — экземпляр), `self` = данные. Исполнение — вызов
процедуры: CALL(код = её вхождение, данные = S) у корня и в обходе, нативно — та же пара через `lmx_call_prim` (натив
вхождения — трамплин процедуры, owner = данные).

**Три отступления от плана §12.**

1. *Голова 2, не 0.* План давал процедуре голову 0, «как у E». При посадке обходчик прочёл первое управляющее тело
   процедуры как часть `args` и отказал вызову (INVALID): `lmx_walk_arg_arity` читает слот 0 вхождения, если это простая
   Structure. Это та дыра, о которой fable_pc спрашивал до кода (REVIEW fd7d396, вопрос 1: голова 0 у дочернего
   вхождения — сочетание, которого нет). Теперь у процедуры обе части заголовка, как у любого метода, и обе пустые. Свои
   её поля лежат в Structure, поэтому во вхождении за заголовком только управляющие тела и шаги обхода
   (`l2_m_own_count` = 0 для процедуры). Пустая Structure получает вхождение из двух пустых частей.
2. *Управляющие тела и поля, объявленные в блоке тела, живут во вхождении процедуры, как у метода, а не в узле
   Structure.* Ширина узла — его тип: допуск и merge сравнивают по детям. Пути `Counter\t` к полю блока нет.
   - Нативно тело достаётся через вхождение.
   - В обходе кадр берёт само тело как простую Structure (`l2_rw_host_at`): держатель, равный исполняемому коду, ядро
     читает как данные активации (`lmx_walk_data_holder`), а данные процедуры — Structure.
3. *`l2_emit_ns_exec`, `l2_rw_ns_call`, `l2_rw_ns_var_call` остались.* Теперь они пишут вызов процедуры (код —
   вхождение, данные — S). Общий вызов метода берёт данными вхождение, поэтому свой вызов с данными S и есть
   «исполнение Structure».

**Снято.**
- Особый путь тела: переменная `l2_rw_ns` и пять её ветвей, `l2_rw_ns_body`, `l2_rw_ns_item`, `l2_rw_ns_ty`,
  `l2_rw_ns_at`, `l2_ns_kind_ty`.
- Узлы кода: `l2_nsx_base`, `l2_nsx_rank`, `l2_nsx_count`.
- Мёртвый блок `if: 0`.
- Особые отказы «named Structure body not walkable yet: …» и «a named Structure's return carries no value».

**Разбор тела — одно правило.** Поле — только форма объявления: `l2_ns_decl_first`, та же проверка, что узнаёт первое
поле именованной Structure. Всё прочее — оператор:
- вызов ресивера: `return`, `if`, `else`, `while`, `for`, метод единицы, где бы ни стоял (`l2_unit_names_method`);
- присваивание полю;
- `cells[1]: …`, `x\f: …`, `g: 5`, `sendMessage: …`.

Первая попытка — «не имя и не слово объявления» по `l2_ident` — прочла `int:` как оператор: `l2_ident` не пускает
ключевые слова C. Это поймал инвариант регистрации.

**Общие правки, найденные по пути.**
- *Пустое тело.* `E: ()` проверка отказывала без места («unsupported body» в 1:1, `l2_check_body`). Пустая Structure
  законна (book §10): проверять нечего.
- *«unresolved name» — у места чтения.* Свободное имя метода говорилось на строке метода, у корня и у процедуры — в 1:1.
  Запись свободного имени хранит текст чтения (`l2_dyn_add`), а у каждого атома свой текст
  (`lm_p0_append_atom_slice`). Поэтому узел находится по указателю (`l2_node_of_text`, `l2_free_name_at`); если не
  нашёлся, место прежнее.
- *`return` со значением в вызываемом без результата* (`sub:`, процедура) — одни слова в любом месте тела: «return
  with a value in a callable that returns nothing». Было «unsupported body» (Q45: одни слова в любом месте). Корень
  сохраняет свои слова, «return with a value at the root».

**Инварианты.**
1. *При регистрации:* каждое своё поле процедуры — поле Structure (`l2_own_mslot` ≥ 0). Иначе located «internal: a
   declaration of a named Structure's body is not a field of the Structure».

   того же имени, найденный заново по имени. Иначе located «internal: a named Structure's procedure addresses an own
   field outside the Structure's field of that name».

**Мутанты** (копией, по поведению, оба режима; C каждого отличен от C среза):

| Мутант | Что сломано | Результат |
|---|---|---|
| code | исполнение называет кодом S, не процедуру (место прежнего узла кода) | `_exec_if`, `_exec_method`, `unit_walk_…_ctl_method` красные |
| data | процедура исполняется над своим вхождением, `self` — не данные | `_exec`, `_exec_if`, `_exec_method` красные |
| slots2 (fable_pc) | свои слоты процедуры считаются, как у метода, от частей заголовка | инвариант раскладки говорит у объявления (8:5, 5:5) |

| head0 | голова 0 | `_exec_empty` и `unit_walk_…_block_field` красные; `_exec` зелёная — без тел и с шириной ≥ 2 голова не видна |
| holder | обходное тело блока через данные | обходная строка красная, нативная зелёная |
| class_decl | элемент не формы объявления прочитан как поле | `_exec_array` отказана |
| class_method | только методы выше | `_exec_call` отказана («unknown nested Structure reference») |

| loc | прежнее место свободного имени | три строки с местом красные |
| ret | прежние слова `return` | три строки `return` красные |
