## Где было

- **Приём литерала.** Native (`lm_compiler_emit_call_arguments_full`) и обходчик (`lm_compiler_rw_call_arguments`) вычисляли фактический по типу формала объявленной сигнатуры, привязанного по имени; соответствие 294 затем переносило уже типизированное число к формалу выбранного, и связыватель (`lmx_call_bind_actuals`, `lmx_walk_selected_ready_values`) отвечал `convert` на иной вид. Проверка трансляции (`lm_compiler_check_call_arguments`) мерила литерал тем же формалом.
- **Ядро.** `lmx_walk_value_receive` принимало контекстный литерал любым числовым местом: `lmx_walk_store_numeric_raw` молча усекал (300 у char).
- **Повтор.** `lm_compiler_own_add` отказывал повтору любого другого типа (`own_ty[prior] != ty`). Однополевой повтор того же типа получал в обходе слот и имя строки (`lm_compiler_emit_root_head` в `lm_compiler_rw_stmts_in`), не делая шага: следующая строка называла тот же слот, и построение R0 отказывало (p297j; в L1 пробы — два `lmx_source_name_set_at` одной ячейки).

## Механизм

- **Ядро.** `lmx_walk_value_lit_fits` (новая внутренняя, перед `lmx_walk_value_receive`): значение контекстного литерала — величина либо, у отрицательного (величина больше SIZE_MAX / 2), минус её дополнение; тип, наибольшее значение которого SIZE_MAX, берёт любую величину. Вне типа числового места `lmx_walk_value_receive` отвечает `THROWN + CONVERT`, не усекает.
- **Транспорт.** Литерал, записанный по имени (один десятичный или символьный атом у числового формала, не callable и не Structure; `lm_compiler_named_literal_actual`, lower), native пишет контекстной записью (`lmx_walk_value_lit`, `lm_compiler_emit_named_literal`), обходчик — контекстным LIT (`lm_compiler_rw_named_literal`, emit: `lm_compiler_rw_tlit` без типа хранения). Формал его имени у выбранного вызываемого принимает его при связывании. Проверка трансляции у такого фактического не мерит его формалом объявленной сигнатуры. Позиционные фактические не менялись: их формалы совпадают по типу по допуску места (p297d).
- **Знак и U.** Проверка диапазона требует, чтобы контекстный литерал знал своё значение в типе C99. Оба эмиттера литерала со знаком писали `0U - n` — перенос в unsigned int и у литерала без U: фокус f297a показал `convert` у `x: -1` при char-формале (проба p297n: 125). Ядро брало знак и дополнение литерала с U в size_t и теряло написание: реестр r297a на fe159b/rt159a отказал `unary_complement` native в обоих корнях — gdb по `lmx_walk_value_receive` ([команды](records/pins/gdb297-recv.gdb), [вывод](records/pins/gdb297-recv-a.log)) показал контекстную величину SIZE_MAX без U, принятую типом unsigned в `run` (`~0U != 0xFFFFFFFFU`). Теперь литерал без U отрицается как int (величина — дополнение до двух в size_t, `(cast: (size_t) 0U) - n`), литерал с U — в своём беззнаковом типе (`0U - nU` у эмиттеров; в `lmx_walk_value_unary` — unsigned int, когда величина в нём помещается, иначе 64-битный) с сохранением написания, и `lmx_walk_value_lit_fits` читает литерал с U как его величину (NEGATED-CONTEXTUAL-WRAP).
- **Повтор с кандидатом.** `lm_compiler_own_add` сохраняет связь повтора другого числового типа с местом (`lm_compiler_repeat_receives`; другие виды — прежний отказ). Проверка объявления (`lm_compiler_check_decl_candidate`) проверяет кандидата написанным ресивером, как прежде, затем `lm_compiler_check_repeat_type`: план числового приёма (`lm_compiler_repeat_plan`: кандидат, тип места, написанный тип, преобразователь таблицы из написанного типа в тип места), один вход преобразователя написанного типа, ребро вызова; без преобразователя — обычный отказ приёма. Native: `lm_compiler_emit_repeat_receive` (обычный `lm_compiler_emit_numeric_receive_full` с этим планом) и прежняя запись места; обходчик: `lm_compiler_rw_repeat_assign` (PUT места, значение — `lm_compiler_rw_numeric_receive` плана). Отказ преобразователя — неявный `convert` вызывающего до записи.
- **Повтор без кандидата.** Проверка: совместимость места с написанным типом тем же допуском (`lm_compiler_colon_types_compatible`), без записи и без ребра. Обход: `lm_compiler_repeat_single_field` — ни шага, ни слота, ни строки реестра.
- `z: char: 6` — та же форма объявления, что `char: z 6`, и идёт тем же путём (p297f, p297i).

## Границы

- **CALLABLE-PLACE-TYPED-RECEPTION (OPEN).** Уже типизированное значение, привязанное по имени к формалу выбранного другого числового типа, — по-прежнему `convert` у связывателя, хотя программа определяет преобразователь пары (p297q: 25 на fe159b и на итоговом кандидате).
- **REPEATED-DECL-OTHER-KINDS (OPEN).** Повтор, у которого место или написанный тип — не число (ссылка, Structure, массив, callable), — прежний отказ трансляции `assignment value has incompatible type`.
- **Фаза отказа без преобразователя — вопрос Codex.** Ревью 295: «если нет/проверка не проходит — обычный неявный convert при действительном потреблении». Повтор, как и обычный приём `z: c` с char c (p297g, без изменений), при отсутствии в программе ресивера таблицы отказывает при трансляции — `the program has no method `lm_stg_convert_char_int`, the receiver of this conversion`; тот же ответ закрепляют ряды `index_numeric_refused` и `index_numeric_write_refused`; отказывает и программа, у которой такой повтор стоит в невыполненной ветви. Ряд `var_own_repeat_norecv_refused` — свидетель этого общего ответа приёма; если норма — `convert` при исполнении, это изменение общего числового приёма для всех форм и этих рядов.
- **Изменения поведения.** Измерены: контекстный литерал вне типа числового места — `convert` вместо молчаливого усечения (коды 96, 97, 99); именованный литерал вне типа формала в прямом вызове — `convert` при исполнении вместо отказа трансляции `literal not representable` (p297m). По коду, отдельно не измерялись: отрицательный контекстный литерал у unsigned-места — `convert`; `~0U` у места size_t — 4294967295, как в C, вместо SIZE_MAX.
- Позиционные фактические и путевой вызов (NODE-PATH-NAMED-ACTUALS, OPEN) не менялись. Зависимая часть FORMAL-DEFAULT-FORMS (умолчание-имя, вычисляемые умолчания) ждёт ответа автора: p297a и p297b на 296 — `has no argument …: its written default is not a literal value and is not built` ([p297a](records/tp151-probe/b297a/p297a_structure_default-native/p.L2.log), [p297b](records/tp151-probe/b297a/p297b_name_default-native/p.L2.log)); срез их не трогал.
