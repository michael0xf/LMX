## 1. Что считать случаем исполнения

Допуск сравнивает кандидата с требованием относительно Consumer — по путям, которые Consumer действительно
использует. Случай статический, когда к построению графа известны все три: требование (модель места или формала),
Consumer (тело, читающее это место) и кандидат — записанное имя Structure, литерал, конструктор. Такой допуск
достаточно выполнить один раз, при построении. Случай динамический, когда кандидата выбирает исполнение: значение
ссылки, переприсвоенной при исполнении; данные или код, поданные ресиверу `call`; результат `merge` или вызова;
полученное письмо; вызываемое, взятое из места. Его нельзя решить раньше, чем кандидат появится.

Отдельно стоят проверки, которые `implements` не являются и решением не затронуты: `convert` — приём числа
другого типа с проверкой диапазона; отказ записи в место кода (`interpreter`); выход индекса за поля Structure.

## 2. Опись по видам

Обозначения: С — статический, Д — динамический, С/Д — зависит от того, чем записан кандидат. «Граф» — чистый граф
(интерпретатор `lmx_graph_run.lm2`, ядро `lmx_graph.lm2`, эмиттер `l2_graph_tool.lm2`); «frontend» — рабочий
frontend, который выпускает вызовы библиотеки допуска `lmx_implements.lm2` в L1; «обходчик» —
`lmx_walk_values.lm2`, он служит и обходу, и вспомогательным вызовам из `native`.

### 2.10 Учёт соответствий — не допуск, но зависит от него

Вызов допуска в L1 не только отвечает «да» или «нет»: `lmx_implements_admit_receiving` и его обёртки записывают в
арену соответствие полей кандидата и требования (`arena\impl`), и последующие чтения полей идут по этой записи —
`lmx_call_index` (`lmx_call.lm2` :49), `lmx_implements_code_slot`, `lmx_implements_exec_slot`. Копирование
(`lmx_graph_copy_owned.lm2` :3641) и `merge` (`lmx_merge_owned.lm2` :1134, :215, :1269) переносят и составляют эти
записи. Поэтому в рабочем frontend снять вызов допуска при исполнении нельзя, не дав ту же запись другим способом.

## 3. Что найдено попутно

1. Рабочий frontend выпускает допуск при исполнении и там, где трансляция тот же допуск уже выполнила: комментарий
   в `l2_frontend_emit.lm2` :1389 называет его обязательным («the mandatory runtime implements check»). Это прямое расхождение с решением «один раз» и главный
   объём шага 7 для этого пути.
2. Чистый граф между вызовами ничего не удерживает: каждый вызов заново связывает форму, заново разрешает модель
   формала по имени и заново обходит тело вызываемого (`lmx_graph_admit_paths`). Библиотеку `lmx_implements.lm2` он
   не зовёт — у него своя сверка путей.
3. В допуске `call: code data` рабочего frontend признак «может отказать» ставится только в 0
   (`l2_frontend_core.lm2` :10357), поэтому ветвь отказа `call` в выпускаемом коде недостижима, а ответ «нет» —
   аварийная остановка «a proved split call admission was refused» (`l2_frontend_lower.lm2` :17787). При трансляции
   этот допуск не выполняется. Норма требует здесь отказа вызова.
4. Пять экспортируемых входов библиотеки — `lmx_runtime_implements` и четыре его варианта — в `selfbuild` никто не
   вызывает.

## 4. Предложение

Предложение исполнителя; ни одно его положение не исполнено.

**Переносится на построение графа** — всё, где кандидат записан:

- форма вызова известного вызываемого (2.1) и приём записанной Structure или литерала формалом (2.2, 2.3);
- результат `return` и значение, принимаемое местом со ссылкой, когда источник — записанный конструктор (2.2);
- требуемые места кода в данных, когда и код, и данные — записанные имена Structure, и у метода над собственной
  частью `data` (2.4);
- вид места при присваивании числа и при объявлении — для мест собственных данных кода (2.5);
- шаг пути по записанным именам Structure (2.6);
- `merge` записанных операндов и ресиверы `fn`, `sub` с записанными аргументами (2.9).

Проход допуска идёт один раз, после построения графа и до исполнения, и отказывает построению. Служебных таблиц в
графе он не оставляет — так требует инвариант 2026-11-08. Интерпретатор при исполнении узнаёт статический случай
тем же признаком, каким его узнал проход, — вызываемое объявлено записью, кандидат записан — и допуск не повторяет;
`native` для такого места вызовов допуска не содержит вовсе.

**Остаётся при исполнении** — только то, где кандидата выбирает исполнение:

1. вызов через место-ссылку на вызываемое и через вызываемое, созданное при исполнении: форма, приём аргументов,
   `throws` (2.1, 2.2, 2.7);
2. значение из динамического источника в месте с моделью: ссылка, переприсвоенная при исполнении, результат
   вызова, формал вызывающего, переданный дальше (2.2);
3. `call` и `fncall` с данными, кодом или частями, выбранными при исполнении (2.4);
4. вся структура аргументов, полученная при исполнении (2.3);
5. почта: содержимое полученного письма, письмо выхода, содержимое пойманного отказа (2.7);
6. путь и запись через держателя, тип которого известен только при исполнении (2.5, 2.6);
7. свободные и скрытые входы на входе в активацию (2.8);
8. `merge` операндов-значений и ресивер, применённый к вычисляемым аргументам (2.9);
9. запись по индексу `S[i] := v` (2.5).

Интерпретатор исполняет граф без `native`, поэтому для него «при исполнении» — это те же девять видов, а не всякий
вызов и всякая запись.

**Что нужно решить автору.**

- Вид 2: вопрос об однократности закрыт ответом автора 2026-11-13 выше — `implements` один раз для каждого
  кандидата. На момент описи он повторялся при каждом приёме. Предложение об учёте соответствий в арене (2.10)
  не стало утверждённым устройством; соблюдать действующий запрет постоянных служебных таблиц обхода.
- Вид 7: проверка наличия свободного входа — это допуск `implements` или часть связывания имени? От ответа зависит,
  входит ли она в счёт «случаев допуска».
- Пункт 3 раздела 3: при `call: code data` с данными, в которых нет нужного места, норма — отказ вызова (`call`), а
  рабочий frontend останавливает программу аварийно. Исполнитель считает это дефектом и предлагает исправить вместе
  с шагом 8 раздела M11.
- Учёт соответствий (2.10): проход при построении для рабочего frontend должен давать ту же запись, по которой
  читаются поля. Предложение — запись со статической картой (`lmx_implements_register_map`), как уже сделано для
