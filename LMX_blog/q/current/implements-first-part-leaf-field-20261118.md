# Первая часть implements и поле-примитив; раскрытие при одном формале

Дата: 2026-11-18. Задаёт исполнитель (сессия fable_pc). Статус: **открыт; задан заново** — две первые программы
вопроса были неверными ([журнал](../../2026-11-18.md#structure-in-code-is-executed)). Автор велел случаи, когда первой
части `implements` не хватает, обсуждать с ним ([журнал](../../2026-11-18.md#both-readings-checked)).

## Что было неверно в первых редакциях

- В первой Structure была записана в коде: `@: One (int: x 9)`. Автор: строка исполняемая; безымянная Structure в
  коде исполняется, объявляет локальный `x`, а `One` получает указатель на эту ячейку. Даже в данных аргументы
  объявления `@:` принимаются в роли `code`, и получается указатель на скрытую ячейку.
- Во второй Structure стояла в безымянной группе в начале программы. Автор: эта группа тоже стоит в роли `code`, и
  `Arg: (int: x 9)` в ней — вызов метода `Arg`.

## Программа автора

```lmx
sub: test (Arg: (int: x 9) )
(
fn: h (int: x) int
    return: x
int: r h(Arg)
)
```

`Arg` объявлена в данных `test`; код `test` объявляет `h` и вызывает её.

Разбор вызова `h(Arg)` по общему алгоритму, как его понимает исполнитель:

- Раскрытое чтение. `Arg` раскрывается в объявление `int: x 9`. Оно стоит на позиции формала `x` и названо `x`,
  поэтому идёт позиционным аргументом; имя сверяется. Первая часть `implements` сверяет поля `Arg` с данными `h`:
  `x: int` против `x: int` — да. Пара допущена.
- Чтение «как записано». Сама `Arg` подаётся формалу `x`, месту `int`. Чтобы вызов ответил 9, эта пара должна
  получить отказ; иначе допущены две пары, и это ошибка неоднозначности.

## Вопрос 1. Чего не хватает первой части implements

Факты кода, проверка вспомогательной сессии opus на принятом инструменте
(`receipts/opus/one-graph/declaration-selection/Q4-LIBRARY-LEAF.txt`): первая часть библиотеки `lmx_implements`,
вызванная через читатель чистого графа, отказывает, только когда у значения нет поля модели. На поле, значение
которого — ссылка на Structure, читатель графа отвечает «неизвестно», а «неизвестно» в библиотеке не запрет. `int`
против ссылки на Structure проходит; `int` против `char` проходит. В заметках библиотеки сказано, что значения
примитивов в первой части не участвуют, а преобразования открыты.

Значит, сегодня пара «как записано» допускается, и `h(Arg)` по одной серии `implements` дал бы неоднозначность, а не 9.

Книга, [запись в известное место](../../../docs/LMX_semantics.ru.md#assign-known): соответствие нового значения
месту проверяет общий допуск `implements` с его таблицей преобразований.

Предложение исполнителя: первая часть сравнивает и тип примитивного поля модели с типом поля значения, по таблице
преобразований: тот же тип или есть переход — да; перехода нет — нет (`int` против Structure); поле-указатель void
принимает любую Structure. Это добавляется в библиотеку; отдельной проверки вида значения в связывателе нет.

Наблюдаемая разница: `h(Arg)` отвечает 9 — либо ошибкой неоднозначности.

## Вопрос 2. Раскрытие при одном формале

Из разбора автора следует, что раскрытое чтение проверяется против любого объявления, и с одним формалом тоже.

Записанная норма говорит обратное. Слова автора 2026-11-18
([журнал](../../2026-11-18.md#unwrap-when-no-one-argument-declaration)): «Раскрытие структуры при вызове с одним
аргументом-структурой происходит когда _не найдено одноаргументное объявление_ и _найдены_ многоаргументные
объявления». По ним в книге, [выбор объявления](../../../docs/LMX_semantics.ru.md#declaration-selection), записано:
раскрытое чтение проверяется только против объявлений с несколькими аргументами; в таблице связок строка «одно, `f(a)`;
`f(S)`» — «`S` — его аргумент и не раскрывается»; в плане ответ 9 сегодняшнего инструмента на такой вызов числится
багом.

Два чтения:

1. Раскрытое чтение проверяется против всех объявлений. `h(Arg)` при `Arg: (int: x 9)` отвечает 9; при
   `Arg: (int: y 9)` — отказ: имя объявления не `x`, а сама `Arg` месту `int` не подходит.
2. Раскрытое чтение — только против объявлений с несколькими аргументами. `h(Arg)` отказывает в обоих случаях.

Масштаб: правило 2 и таблица связок книги, запись о баге в плане, свидетели среза выбора объявления.

## Что исполнитель делает до ответа

Норму не меняет. Срез выбора объявления: шаги о формалах, присваивании аргументов и кандидатах от этих двух ответов
не зависят; шаг «серия = библиотека» ждёт ответа на вопрос 1. Свидетели среза, где Structure объявлена записью
`@: Имя (…)` в коде или стоит в безымянной группе, переписываются: Structure — в данных метода, который делает вызов.
