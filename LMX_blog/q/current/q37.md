# Q37. Четыре решения для примера `apply(s 10)` → 101 (порт `implements`, §7)

Состояние: 2026-09-27, открыт (Opus). Факты и нарезка — `steps/implements-port-plan.md`. Ответ — сюда или в чат; закрытый файл переносится в `LMX_blog/q/`.

## Факт

Пример автора (блог 2026-09-24):

```text
fn: s (string: x) int
return: x + "1"

fn: apply (op(fn: (int: x) int) int(value)) int
return: op(value)

print: apply(s 10)
```

Сегодня транслятор не может его выполнить по шести независимым причинам; четыре из них — выбор, которого нет в норме:

1. **Написание формала с анонимным callable-типом.** Сегодня контракт callable-формала — только имя уже объявленного метода (`l2trans.lm1` :13953); `op(fn: (int: x) int)` и скобочный `int(value)` транслятор не разбирает.
2. **Где формируются аргументы динамического вызова.** `op` известен только во время выполнения: чтобы `int 10` стал `string` для `s`, преобразование нужно выбрать по фактической сигнатуре вызываемого — в рантайме. Книга §6 «Message-local type bindings and conversion context» говорит, что таблица преобразований — явные данные Message, конвертеры — обычные приёмники; но где именно вставляется вызов конвертера для динамического вызова (в вызывающем по сигнатуре цели, в трамплине цели, в ядре при вызове), не сказано, а «отдельного adapter» автор отверг.
3. **Строковый `+`.** Книга определяет `+` как арифметику (:231), грамматика — «no implicit C concatenation» (:335); в примере `x + "1"` — конкатенация массивов char.
4. **Имя ключа строки в таблице преобразований.** `convert.lm2` (из prev) называет текстовый тип `Text` (`Text int`, `int Text`); строка по решению автора — `LmxCharArray` (`char: []:`). Ключ таблицы — `Text`, имя дескриптора или что-то третье?

## Вопрос

1. Как пишется формал с анонимным callable-типом: как в примере (`op(fn: (int: x) int)`), или только через именованный описатель?
2. Где вставляется преобразование аргументов и результата при вызове callable, известного только в рантайме?
3. Является ли `+` над массивами char конкатенацией по норме — или пример иллюстративный?
4. Как называется строковый тип в ключах таблицы преобразований?

## Рекомендация Opus

П.1 — разрешить анонимный тип как в примере: это та же сигнатура `(int: x) int`, записанная на месте, без нового понятия. П.2 — в вызывающем, по сигнатуре цели, прочитанной из вызываемой Structure (её заголовок уже есть в узле merge-callable), через обычный приёмник строки таблицы; ядро не выбирает преобразований. П.3 — решает автор; если да — строкой в книге рядом с арифметическим `+`. П.4 — имя дескриптора (`LmxCharArray`), чтобы ключ совпадал с типом значения.
