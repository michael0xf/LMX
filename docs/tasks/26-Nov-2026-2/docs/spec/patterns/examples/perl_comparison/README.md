# LMX и Perl: 24 наблюдаемых договоров

У каждого клиента опубликованы **две полные LMX-формы**: процедурная и функциональная. Процедурная показывает явный порядок, ветвления, циклы и изменение данных; функциональная использует общие операции ядра, Expression и короткие адаптивные формы. Обе сохраняют один наблюдаемый договор, включая порядок, отсутствие результата, профиль данных и эффекты.

## Источники и проверка

Функциональные исходники находятся в source/lmx; процедурные — в source/lmx/procedural. examples.json хранит обе версии, один contract_id и независимые метрики/SHA-256. Старое поле lmx — только зеркало функциональной формы и не третий участник сравнения.

Библиотечные реализации имеют один общий LMX-исходник. Их зависимости учитываются отдельно, без повторного включения тела ради каждого стиля. Foreign-исходники сохранены.

**LMX runtime: NOT_RUN.** Статическая проверка и проверка ожидаемых значений не доказывают работу нового кода на LMX runtime. Проверяются обе формы; runtime-приёмка остаётся отдельным этапом.

Редактируются examples.json и единые исходники ядра; tools/rebuild.py воспроизводит исходники, Markdown и метрики. Проверка suite выполняется tools/check.py для Julia и tools/validate.py для Perl. PDF/XLSX формирует общая сборка архива.

Считается полный текст каждой формы: все определения, вспомогательные методы, комментарии внутри листинга, обработчики, имена ошибок и полные ссылки `throws: copy(target\throws)`. Списки берутся из фактически выбранных методов или явно заданного конечного объединения договоров. Статистического удаления аргументов Throws нет. В PDF/XLSX зелёным шрифтом и подчёркиванием числа выделяются **все** равные минимумы полного счёта сопоставимой строки; неполные аналогии победителя не получают.

## Запуск корня и дальнейшие операции

Всегда запускается корень R0 как L3 Thread. У корня нет DATA и пользовательских аргументов. Локальные объявления и вызовы обрабатываются общим механизмом языка.

Именованные операции из invoke, inputs и тестовых cases выполняются корнем или обычным обработчиком уже после старта. Main и Example\run не являются альтернативными точками запуска программы. Заглушка-родитель может иметь собственные аргументы и отправить корню сообщение; эти аргументы не становятся DATA корня.

load_before обозначает необходимые определения фикстуры. Отдельного режима запуска через загрузку в DATA он не вводит; import открывает доступные имена. Для короткого фрагмента явно задаётся принимающий контекст последующей обычной операции. Новая команда CLI или API запуска здесь не определяется. LMX runtime: NOT_RUN. [Норма запуска](../../../LMX_semantics.en.md#source-entry-profiles).

## Прикладные сценарии редакции 25 ноября

Расширены P01, P02, P03, P06, P08, P09, P12, P13, P14, P15, P17, P18, P20, P21. Они выполняют обработку данных и возвращают полезный составной результат; содержательные сценарии остальных строк сохранены. Все текущие размеры пересчитаны после изменений.

В процедурных P15/P16/P17/P20 используется единственный [Ascii\letter](source/lmx/common/ascii.lm3). Полный код каждой формы состоит из упорядоченных source_files в examples.json: общий helper, затем entry. Оба фрагмента входят в показанный листинг и полную метрику; helper не копируется в entry-файлы. Все 98 проверочных входов опубликованы на страницах, LMX P0/L3 остаются NOT_RUN.
