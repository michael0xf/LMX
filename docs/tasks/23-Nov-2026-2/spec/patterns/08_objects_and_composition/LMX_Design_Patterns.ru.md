# LMX: Объекты, зависимости и композиция

Java показывает номинальные интерфейсы, классы и явные объектные контракты; Python — динамическую композицию и функции. Такое сравнение не вынуждает все языки копировать Java-иерархии и выявляет реальные различия nominal/structural.

Все десять исходных паттернов сохранены и проверены на пользу операндов и отдельной библиотеки. Fluent Interface теперь показывает реальную цепочку через OPERANDS_TEMPLATE; остальные примеры сохраняют прямые именованные операции там, где новая оболочка лишь увеличила бы механизм. Примеры работают у одного последовательного владельца; shared mutable состояние в LMX принадлежит Message.

## Каталог

### 072. [Dependency Injection](072_dependency_injection_comparision.md)

Клиент получает готовую зависимость от места сборки приложения.

**Сценарий:** Один клиент читает число из двух переданных источников и удваивает его. Источники возвращают 5 и 7.

**Наблюдение:** 10 + 14 = 24.

LMX показывает injection при вызове, Java/Python — через конструктор объекта. Контракт источника одинаков: ()→int без дополнительных эффектов.

### 073. [Service Locator](073_service_locator_comparision.md)

Клиент получает сервис через явно выбранный реестр.

**Сценарий:** По ключу 1 получить источник 42; неизвестный ключ направляется к fallback 0.

**Наблюдение:** 42.

В отличие от DI конкретный сервис клиент запрашивает внутри своей логики. Все реализации используют один фиксированный ключ и определённый fallback.

### 074. [Null Object](074_null_object_comparision.md)

Нейтральная реализация выполняет тот же контракт, позволяя не проверять null у клиента.

**Сценарий:** Выполнить работу с value=10 и отключённым журналированием через объект с пустым поведением.

**Наблюдение:** 10; logger вызван один раз и не изменяет состояние.

Нейтральный callable достаточен, если контракт состоит из одной операции. Это функциональная реализация Null Object, без принудительного отдельного класса.

### 075. [Object Pool](075_object_pool_comparision.md)

Пул выдаёт ресурс во временное пользование и принимает его обратно для повторного использования.

**Сценарий:** Пул ёмкости 1: взять ресурс, получить отказ на второй take, вернуть первый и получить ту же ссылку.

**Наблюдение:** 1 означает first=again и busy=null.

Все варианты показывают reuse identity, состояние занятости и возврат. Автоматическая очистка арены LMX не заменяет release внешнего ресурса.

### 076. [Simple Factory](076_simple_factory_comparision.md)

Одна функция выбирает и создаёт конкретный продукт по входному признаку.

**Сценарий:** Создать два продукта kind=0 и kind=1 со стоимостью 5 и 9.

**Наблюдение:** Сумма 14; каждый вызов создаёт отдельный продукт.

Выбор типа продукта инкапсулирован в функции. Это Simple Factory, без виртуального factory method и без семейства Abstract Factory.

### 077. [Multiton](077_multiton_comparision.md)

Один владелец предоставляет по одному устойчивому экземпляру на каждый ключ.

**Сценарий:** Закрытый набор ключей 0 и 1. Две выдачи ключа 0 разделяют запись value=7; ключ 1 сохраняет 0.

**Наблюдение:** 70.

В отличие от Flyweight объекты здесь изменяемы и идентифицируются ключом, а не автоматически интернированным содержимым.

### 078. [Marker Interface](078_marker_interface_comparision.md)

Отдельный признак допускает объект к операции без добавления поведенческих методов.

**Сценарий:** Проверить помеченный и непомеченный объект; результат кодируется как accepted*10 + rejected.

**Наблюдение:** 10.

Java и Python проверяют номинальную принадлежность. LMX проверяет явно требуемую структуру; такую ветвь может построить другой автор. Положительный сценарий совпадает, сила номинальной гарантии различается.

### 079. [Fluent Interface](079_fluent_interface_comparision.md)

Операции API возвращают контекст для продолжения читаемой последовательности.

**Сценарий:** Одним выражением настроить count=3 и price=7 через операнды, возвращающие тот же контекст, затем получить произведение.

**Наблюдение:** 21; оба setter возвращают исходный объект.

LMX теперь показывает саму fluent-цепочку в expression; Java и Python используют цепочку методов. Все три изменяют и возвращают тот же объект, а не создают независимые варианты конфигурации. Общий заголовок операндов учтён строкой copy.

### 080. [Type Object](080_type_object_comparision.md)

Разновидность объекта описывается обычными данными, разделяемыми его экземплярами.

**Сценарий:** Два объекта ссылаются на один TypeData с damage=2. Изменить damage на 3; второй объект увидит новое значение.

**Наблюдение:** 23: первое чтение 2, второе 3.

Общие свойства становятся данными во всех трёх языках. Возможность LMX читать/компоновать граф удобна для загрузки таких описаний, но в этом примере loader не требуется.

### 081. [Extension Object](081_extension_object_comparision.md)

Объект выдаёт отдельное расширение с дополнительным интерфейсом и доступом к его состоянию.

**Сценарий:** К Host(value=7) прикрепить Report-расширение; запросить его и получить удвоенное значение 14.

**Наблюдение:** 14; идентичность Host сохраняется.

Выдаётся дополнительный интерфейс отдельного объекта. Это отличается от замены самого Host или присваивания методу нового lexical owner.
