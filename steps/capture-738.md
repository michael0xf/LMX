# Захват Structure в callable-merge (пункт 738) — замер и предложение (Opus, 2026-09-28)

Записка — замер и предложение (§1–4, до кода; ревью 56f4f4b), сделанное в срезе 1 — §5. Нормы дословно — `LMX_blog/2026-09-27.md` «Q38», «Q39», «Q42», «Q44».
Вопрос-предшественник — `LMX_blog/q/q38.md` (случаи A и B).

## 1. Нормы

- **Q38:** общая ссылка «за пределами копируемого» — чепуха: `merge` не копирует неиспользуемое, за пределами
  копируемого ничего не видно. Значит, и случай A (захват Structure-формала хозяина) — копия, не ссылка.
- **Q42 п. 1:** `merge` создаёт полную копию всего, что вызывается; ссылкой — только ветви
  `independent: const: immutable`. **п. 2:** копируются только читаемые поля.
- **Q39 / D-105:** поля значения другой раскладки читаются через таблицу преобразования индексов, прикреплённую при
  `implements`; реестр `implements` арены (`steps/d105-index-table.md` §5) — механизм, «интерпретатор первым».
- **Q44:** общего по адресу среди Structure нет (копировщик — `steps/copier-q42.md` §4).

## 2. Замер

Пробы (скретчпад Opus `cap/fx`): случай B — хозяин `makeReader (int: n)` объявляет `Model: loc`, пишет `loc\value: n`,
модель `read (int: x)` возвращает `loc\value + x`; случай A — хозяин `makeReader (Model: m)`, модель читает `m\value`.
Оба отказываются у заголовка хозяина (6:1): «a callable merge needs a walkable body».

- **Сбор захвата** (`l2_scan_ident`, ветки хозяина): формал или собственное поле хозяина, которое модель называет,
  записывается `l2_mcap_add` только если его код проходит `l2_mcap_ty_ok` (int, char, size_t, unsigned, ulong).
  Structure (формал `Model: m`, поле `Model: loc`) молча не записывается.
- **Обход модели:** корень пути `loc` / `m` не свой формал, не своё поле и не именованная Structure — `l2_rw_path`
  отказывает тихо, у модели нет шагов (`l2_m_steps[model] < 0`), и хозяин отказывает у заголовка
  (`l2_mad_emit_into`, `l2_emit_mad_construct_one`).
- **Узел результата:** слот 0 — `args`, 1 — `return`, затем захваты в порядке сканирования (`l2_mad_slot`), затем
  шаги модели. Модель исполняется обходчиком всегда (`native` результата пуст). Узел строят нативный хозяин
  (`l2_mad_emit_into`) и конструктор обхода (`l2_emit_mad_construct_one`); захват — свежая ячейка со значением хозяина
  (`l2_mcap_new_helper`).

## 3. Предложение (срез 1)

1. **Сбор.** Формал или собственное поле хозяина именованного типа `T` (`l2_nsty_get` / `l2_own_nsty_get`) —
   захват Structure; его множество — поля `name\f`, которые модель читает или пишет (первый шаг пути). Путь глубже —
   через поле-Structure — в срезе 1 located-отказ.
2. **Построение** (нативно и в обходе, одним правилом): Structure из этих полей (в порядке полей `T`), каждое — свежая
   ячейка со значением хозяина на момент возврата (Q42 п. 2: только читаемые); таблица ширины `T`: `T[j]` — место поля
   в копии или «не перенесено»; `lmx_implements_register(арена, копия, T, таблица)`.
3. **Ядро.** Ячейка таблицы «не перенесено» (`SIZE_MAX`): тяжёлая проверка её пропускает; `lmx_implements_slot` для
   такого поля — отказ (X1: транслятор не даёт его прочесть по построению).
4. **Обход модели.** Корень пути — захват: `AT(узел, слот захвата)`, и `OF`/`PUT_OF` первого поля несут `T`
   (механизм D-105).

Свидетели: случай B — `loc\value` = 40, `read(2)` = 42; случай A — запись `left\value` после `makeReader` не видна
через `read` (копия, Q38); копия несёт только читаемое поле (второе поле `T` не перенесено — чтение его через таблицу
отказано в селфтесте ядра). Мутанты: таблица позиционная (читает `other`); регистрация снята (X1); копия целиком
вместо читаемых полей (строка ядра «не перенесено» мертва — селфтест); ссылка вместо копии в случае A (запись видна).

## 4. Вопросы к ревью

1. Случай A — копия (Q38), а не ссылка, как в предложении q38 — так ли читается?
2. Запись моделью в захваченное поле (`loc\value: v`) — пишет копию; видна ли следующему вызову той же модели (одна
   копия на узел) — да, как у захвата-ячейки сегодня?

  значения отмечен этим проходом). Таблица захвата не достижима ни из чего, кроме записи. Свидетели:
  `lmx_gc_selftest` — через `lmx_gc_collect` (таблица в своём чанке, значение живо в графе: после сборки запись
  найдена и слот читается) и `lmx_implements_table_selftest` (проход напрямую, с проверкой, что таблица не делит чанк
  со значением).

- Обход модели: корень пути — захват (`path[0] = 7`), `AT(узел, слот захвата)`; `OF` / `PUT_OF` первого поля несут

## 6. Срез 2 — отказы захвата на месте, запись через захват (Opus, 2026-09-28)

По пробелу §5 и учёту REVIEW 2032ca0 (п. 1–3). Замеры «до» — транслятор `2032ca0` на тех же фикстурах.

- **Причина модели в отказе хозяина.** Модель callable-merge пробуется для обхода тихо (`l2_rw_quiet`), и её
  первый отказ `l2_error` держал только для заметки `--walk-methods`: хозяин говорил общее «a callable merge needs a
  walkable body» у своего заголовка. Теперь `l2_rw_methods_count` хранит первый отказ каждого метода с местом
  (`l2_m_why`, строка и столбец), а для метода, которого обход не пробует, — `l2_rw_may_why` у его заголовка;
  хозяин (`l2_mad_unwalkable`; нативный хозяин и конструктор обхода) говорит «a callable merge needs a walkable
  body: <причина>» там, где причина стоит. Это общее для любой модели callable-merge, не только для захвата.
- **Корень головы кадра.** Голова кадра — один текст, `l2_scan_ident` атома `m` не встречал, и модель, которая
  пользуется захватом только в записи (`m\count: x`), захвата не записывала: проверка отказывала «unknown field path
  root» (до: `_write_root` — 18:9). `l2_scan_path_root` разрешает корень, как разрешился бы атом: формал или своё поле
  хозяина этого написания, через `l2_scan_ident` с его именем — свои имена модели затеняют его и здесь.
- **Путь через захват в аргументе и в голове вызова.** `l2_actual_path` знал корнем только формал или своё поле
  именованного типа: `probe(loc\box)` отказывался «unresolved name» у `loc` (до: 21:23). Теперь поле через захват
  проверяет захват (`l2_cap_add`); поле-значение — не эта форма (`twice(loc\value)` идёт обычным путём,
  `_call_arg`). Голова вызова `loc\nope(x)` — то же через `l2_cap_text` в `l2_check_primary` (до: «unknown field
  path root»).
- **Только значения** (учёт 3). `l2_cap_add` отказывал лишь поле-Structure и ссылку (виды 2, 3, 10); массив,
  вызываемое, указатель на значение проходили, ядро возвращало 0, и хозяин падал при возврате (до: `loc\buf[0]` —
  «lmx: invariant: a Structure capture could not be copied», exit 3 — abort был путём, не стражем). Теперь
  переносится только число или char (виды 0, 1, 7, 8, 9), остальное — отказ при трансляции; abort хозяина — страж
  (и нехватка памяти), так и названо у `l2_mad_cap_emit` и у `lmx_walk_capture`.
- **Слова обхода.** Поле, которого у типа захвата нет, обход отказывает словами проверки захвата («names no field
  of its type»), а не общим «a field path».
- **`l2_capf`** (учёт 1): объявляется только у хозяина и конструктора модели, захватывающей Structure
  (`l2_mad_struct_caps`); у callable-merge без такого захвата мёртвого объявления нет.

  (`loc\nope`, 19:17), `_nofield_write_refused` (`m\nope: x`, 15:9), `_field_struct_refused` (`probe(loc\box)`, 21:27 —
  у `box`), `_field_array_refused` (`loc\buf[0]`, 13:21), `_call_head_refused` (`loc\nope(x)`, 13:17),
  `_whole_refused` (`probe(loc)` — допуск в тип Structure может бросить, бросающая модель не обходится: причина у
