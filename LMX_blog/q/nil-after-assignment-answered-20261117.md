# Что отвечает сравнение с `nil` после присваивания в место, объявленное без значения

Дата: 2026-11-17. Задаёт исполнитель (сессия fable_pc). Статус: **закрыт ответом автора 2026-11-17 — 5; тип записи
при присваивании меняется**.

Две записи нормы расходились в одном наблюдаемом месте.

- Решение 2026-11-08 ([журнал](../2026-11-08.md#uninit-pointer-preserved)): «Сделайте тип "int без инициализации"
  указателем  на ту самую ячейку …, при этом даже отпадает необходимость менять тип при первом пирсваивании».
- Решение 2026-11-17 ([журнал](../2026-11-17.md#typed-nil)): `nil` — «но это значение»; «мы можем переменную
  сравнить с nil».

## Минимальная программа

```lmx
fn: f (int: a) int
    if: a = nil
        a := 5
    if: a = nil
        return: 1
    return: a
```

`f(7)` в обоих вариантах возвращает 7. Различался `f()`: вариант А — 5 (присваивание заменяет `nil` значением),
вариант Б — 1 (тип места при присваивании не меняется).

## Ответ автора

> --1)  Во первых где ты там увидел required если не написал его в примере? 2) на f() ответ очевидно 5 3) граф в твоём примере не меняется, data тоже не публикуется. Прямого присваивания data\a нет у тебя. Правило "место присваивания не меняется" отмени и убери отовсюду. У нас есть type value и если type другое то data\a := 5 его поменяет

## Редакторское пояснение (исполнитель, не слова автора)

`f()` возвращает 5. В этой программе `a := 5` пишет в место вызова: граф не меняется, данные не публикуются — в
вопросе исполнитель ошибочно приписал этой программе изменение вывода графа и упомянул `required`, которого в
примере нет. Граф меняет прямое присваивание по пути, `data\a := 5`: запись значения — тип и значение, и если тип
записи другой («T без инициализации»), присваивание его меняет. Правило 2026-11-08 «тип места при первом
присваивании не меняется» отменено и снято из [книги](../../docs/LMX_semantics.ru.md#construction),
[L2 §3](../../docs/L2_spec_ru.md#value-record), [спецификации ядра §3.2](../../docs/kernel-implementation.ru.md#primitive-storage)
и [плана](../../next_core_tasks_v3.md#typed-nil-plan).
