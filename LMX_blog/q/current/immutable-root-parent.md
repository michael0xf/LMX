# Корень значения `immutable:` без `independent:` и его лексический родитель

Статус: ОТКРЫТ, 2026-10-10. Вопрос задаёт `fable_pc` при проектировании среза RR2c-2b
([дизайн](../../steps/qualifier-receivers-20261010.md); тикет
[critical_qualifier_receivers_bug](../../steps/tickets/critical_qualifier_receivers_bug.md)); передан
автору через Codex почтальоном `lmx_uds`.

## Контекст

По книге ([квалификация](../../docs/LMX_semantics.ru.md#qualification)) `immutable` защищает само
значение — выбранное дерево: корень и те вложенные Structure, чей обычный `parent` указывает на
проверяемого родителя; внешняя ссылка, *уже хранящаяся как значение данных*, допустима только на уже
неизменяемый объект и остаётся терминалом; примитивы и методы — листья. `independent` — отдельный
ресивер: он освобождает корень от лексического родителя (`parent = 0`). По правилу автора 2026-10-10
([LMX_blog/2026-10-10.md](../../2026-10-10.md#qualifier-receivers-20261010)) три квалификатора — обычные
ресиверы, принимающие любую Structure, и каждый допустим отдельно.

Физически результат `merge` — копия используемой части дерева, `parent` переписаны внутри копии
(ответ автора 2026-10-05, [parent копии merge](../merge-lexical-copy-and-root-placement.md)): у корня
результата есть родитель — копия лексической цепочки, обычная, неквалифицированная Structure. Проверка
ядра перед квалификацией (`lmx_qualify_tree_preflight`) сегодня требует для корня с ненулевым
`parent`, чтобы этот родитель сам лежал в ранее запечатанном, уже неизменяемом профиле, — то есть
читает `parent` корня как внешнюю ссылку-значение. Поэтому `b: immutable: merge(A C)` без
`independent` транслятор пока отказывает («a merge qualified immutable without independent is not
built yet»), а полная цепочка `independent: const: immutable:` построена.

## Вопрос

Является ли `parent` корня неизменяемого значения «внешней ссылкой, хранящейся как значение данных», —
то есть должен ли лексический родитель значения `immutable:` без `independent:` сам быть
неизменяемым, — или `parent` корня есть структурная связь вне защищаемого дерева, и `immutable:` без
`independent:` строит неизменяемое значение под обычным, изменяемым лексическим родителем?

## Предлагаемое чтение, если автор не укажет иначе

`parent` корня — структурная связь, а не хранимое значение данных: дерево квалификации родителя не
включает, и `independent` — единственный ресивер, который его касается. Тогда `immutable:` без
`independent:` строит и запечатывает дерево результата под обычным родителем — копией лексической
цепочки, — ничего в родителе не замораживая; проверка ядра принимает у корня `parent` 0 или любой
корректный заголовок Structure, и требование «родитель уже неизменяем» снимается и для
`RuntimeImmutable` над существующим деревом: у существующего дерева родитель тоже обычный.
