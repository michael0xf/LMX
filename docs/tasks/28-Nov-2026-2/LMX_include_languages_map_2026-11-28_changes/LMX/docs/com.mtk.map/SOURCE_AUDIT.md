## 2. Три разных отношения в данных

При переносе сохранены разные отношения, которые нельзя сводить к одному «ровному дереву»:

1. **Дерево размещения** — `MapNodeModel.parent/slots`. Его ветви имеют разную глубину и разные ёмкости страниц. Пустой структурный слот `MapNil` не становится байтом исходника.
2. **Документ/bunch** — отдельная последовательность `first → next`, со своими концом, длиной и ревизией. Несколько документов могут использовать одно дерево размещения и один scope.
3. **Tag-интервалы и синтаксис P0** — ссылки на диапазоны документа. Интервалы могут пересекаться; они не обязаны образовывать XML-дерево. P0 хранит своё настоящее синтаксическое дерево и ссылки на Cursor, а не второе имитирующее parser дерево.

[storage.lmx](src/storage.lmx) содержит реальные тела создания узлов, вставки структурных детей с переносом переполнения вверх, разделения страницы, вставки/удаления источника, переноса якорей и разреза bunch. [cursor.lmx](src/cursor.lmx) содержит проход по цепочке, прямое клонирование позиции, диапазоны и представление вложенного документа.

## 3. Координация LMX через Message

Весь изменяемый scope — дерево размещения, документы/bunches, Cursor, Tag и индексы — принадлежит **одному обычному Message owner**. Внутренние вызовы `MapTree`, `MapCursor`, `MapTag` выполняются на его полосе. Внешний агент отправляет Message владельцу; он не изменяет чужой live graph по полученной ссылке.

Java `synchronized` описан выше только как факт об оригинале. LMX-перенос использует предусмотренную модель Message, без L3 monitor, mutex, lock ordering и второго scheduler. Низкоуровневая синхронизация внешнего C/L2 провайдера остаётся его внутренней реализацией. Основание — актуальные [Actor Model](../spec/patterns/06_async_and_messages/060_actor_model_comparision.md), [Monitor Object](../spec/patterns/07_state_coordination/070_monitor_object_comparision.md) и [Read-Write Lock](../spec/patterns/07_state_coordination/065_read_write_lock_comparision.md): mutable state читается и меняется владельцем, наружу уходят предназначенные для передачи результаты.

У таблиц, индексов, байтов и самого дерева общие операции — обычные LMX CODE-ссылки. Отдельные операции имеют собственные параметры и возвращаемый тип. Это соответствует передаче исполняемой ссылки в [Dependency Injection](../spec/patterns/08_objects_and_composition/072_dependency_injection_comparision.md). Именованная структура со ссылкой на метод не меняет lexical owner этого метода; расширения связываются явными ссылками, как в [Extension Object](../spec/patterns/08_objects_and_composition/081_extension_object_comparision.md).

Java-наследование `Branch → LiveVector → Array` раскрыто в данные и общие тела: размещение обслуживает `MapStorage`, обычные коллекции — `MapVector`, явное членство с пересчётом индекса — `MapLive`. Отдельный пустой L2 port на каждый бывший Java-метод не введён.

## 4. Cursor, изменения и вложенный MIX

Cursor представлен **якорем нулевой ширины** в позиции между исходными значениями. В Java сам Cursor занимал слот; эта деталь несовместима с прямыми byte offsets P0 и заменена явным реестром `leaf.anchors`. Стабильны ссылка и `id`; текущая позиция меняется после редактирования. `bias=0` оставляет якорь слева от вставки, `bias=1` — справа. `cloneAt` копирует непосредственную пару leaf/slot и не ищет заново весь префикс документа.

`MapSpan` — самостоятельный вложенный MIX document с отдельным ID и собственными `p0Root`, `checkpoints`, `ownerBinding`, `parsedRevision`; его source bytes остаются в родительском документе. Границы хранятся двумя стабильными Cursor. `createAt` принимает захваченные при проходе границы. Вызывающий уже доказал их порядок при последовательном чтении; `bounds` отдельно проверяет вычисляемые координаты. Оба граничных якоря и span сначала создаются локально, вместимость реестров резервируется, затем оба якоря публикуются. Отказ предварительного выделения не оставляет первый бесхозный зарегистрированный якорь.

Изменения имеют три origin: **1 — исходный ввод**, **2 — производные отметки parser**, **3 — семантические атрибуты**. Origin 2 не меняет source revision и не посылает входное изменение обратно P0. Изменение source payload внутри такого turn запрещено. Создание/перемещение Cursor само по себе также не является source edit.

В `MapChange.edits` сохранена **последовательность** правок. Координаты каждой правки относятся к состоянию непосредственно перед ней. Координаты разных шагов нельзя объединять простым `min/max`. Удобные поля `begin/oldEnd/newEnd` действуют только при `hasSingleRange=1`. Очередь `takeChanges` читается без удаления; `acknowledge(revision)` удаляет подтверждённый префикс. Очередь удерживается в памяти owner, а не объявляется журналом, переживающим перезапуск процесса.

`begin/commit` группирует события и ревизию; это **не реализация rollback при произвольном исключении**. Специальная `setAt`/`Cursor.replace` для одной существующей позиции сначала собирает запись изменения и новую очередь, затем меняет значение и ревизию. Она сохраняет все Cursor и всегда возвращает один `MapChange`. Общие структурные вставки/удаления остаются черновиком; обработку отказов allocator и восстановление владельца необходимо принять вместе с реальным runtime.

## 5. Копирование и производительность

Модели в [contracts.lmx](src/contracts.lmx) копируются до привязки живых ссылок. Sentinel `MapNil` имеет const-привязку и `independent` + `immutable` target. По правилам копирования в §20/§23 [семантики](../spec/LMX_semantics.en.md) такой target сохраняет адрес; обычная изменяемая Structure при `copy` была бы другой сущностью и сломала бы проверки отсутствия. Owner, CODE, document и соседние live records присваиваются после создания экземпляра; готовое живое дерево целиком не копируется.

Снимок вектора копирует массив ссылок, не произвольный mutable граф значений. Для передачи между Message-аренами используется явный снимок верхнего слоя. Generic MIX сохраняет value-ссылки по owner-протоколу. Для документа с `p0Source=1` общие `MapStorage.admitValue/admitValues` до первой мутации проверяют scalar int в диапазоне 0…255 и создают отдельные records: изменение входного массива или исходного scalar после вызова не меняет source. Проверку используют `insert`, `setAt`, `replace` и общий Message-вход; весь bulk payload проверяется до удаления прежнего диапазона. Сам live граф остаётся закрытым состоянием owner, а не внешним обходным API для прямой записи полей.

Для этой версии **не заявлено O(log n) для произвольной абсолютной позиции**. `locate` и вычисление Cursor.position могут пройти предыдущие страницы. Вставка в конец имеет прямой путь через `document.last`. Последовательный reader использует `read/next`, а token-start/token-end захватывают `cloneAt`: нет поиска абсолютного префикса на каждом байте. Разделение страницы переносит её локальные anchors; собственный weighted extent index может стать отдельным улучшением после измерений на runtime.

## 6. Числа и кодировки: осознанные исправления

[bytes.lmx](src/bytes.lmx) хранит октеты 0…255 и использует проверяемые полуоткрытые диапазоны. Java имел смешанные inclusive/exclusive границы и мог обращаться на один байт за содержимое. Числа `int`/`i64` хранятся отдельными значениями; отсутствие — `MapNil`, поэтому допустимое число `-1` не теряется как старый NIL.

Флаг `Bytes.utf16` в оригинале означает последовательности `0, high, low`, записываемые `appendChar` (строки 189–197), а не стандартный UTF-16LE. Этот совместимый кодек назван legacy escaped16; суррогатные пары проверяются. Для текста есть строгий UTF-8 decoder/encoder, не допускающий overlong, суррогатных кодов и значений вне Unicode scalar range. `MapTextAbi.charSigned` — явный профиль admitted C99 ABI, который необходимо установить под целевой `char`; это не скрытая смена настройки ОС.

`parseInt` исправляет Java-условие цифры `<=58`, допускавшее `':'`, и проверяет переполнение с поддержкой INT_MIN. `divideAt` сохраняет назначение оригинала: receiver оставляет префикс, возвращается суффикс. Вводящее в заблуждение `removeLastWord` отображено на фактически выполняемое удаление первого префикса. `htmlFind` имеет ясный новый договор: сначала нормализуется выбранный диапазон сущностей, затем ищется символ; старые частичные изменения и padding не обещаются. Полные отличия записаны по методам в [coverage_storage.json](validation/coverage_storage.json).

## 7. Что действительно проверено

- **Java baseline PASS:** реальная компиляция исходного core и 15 проверок probe, с сохранёнными командами и SHA-256.
- **LMX structural/static checks:** разрешение имён и первых шагов путей, ограниченная проверка отступов/скобок, целостность оригиналов. Это не parser и не TYPE admission.
