# Редакция 2026-11-22 (2): три места, где пакет не говорит, что значит запись

Записано 2026-11-23 исполнителем fable_pc при переносе пакета в документацию. Перенос и план от ответов не
зависят: по каждому месту названо, как исполнитель действует до ответа. Опись и поиск по пакету, книге и журналу
сделаны помощниками и перепроверены.

## В1. `@: q int` — тип вторым аргументом универсальной ссылки

Пакет: требование ссылки стоит в голове (`int@: q`), `@: p Model` — универсальная ссылка на саму Model, запись с
тремя аргументами снята. Не сказано, что значит запись с двумя аргументами, когда второй — слово примитивного типа.

```lmx
int: n 5
@: q int
int: before \q
q := @n
int: after \q
```

Сегодня ядро читает `@: q int` как ссылку на `int` без значения: строка `before` отказывает, `after` равно 5. По
редакции это чтение снято. Что наблюдается после редакции:

- (а) `q` — ссылка на сам ресивер `int`, как `@: p Model` ссылается на Model: `before` получает ресивер, отказа нет;
- (б) слово `int` в роли значения даёт свой код типа, как `int: numbersType int[]` даёт код массива: `q` ссылается
  на значение-код;
- (в) тип в позиции инициализатора отказывает ошибкой типа: требование пишется только в голове.

От ответа зависит одно: забытая прежняя строка после перевода отказывает (в) или молча меняет смысл (а, б). В
исходниках ядра на L2 таких записей около двенадцати тысяч. В программах проверки запись с двумя аргументами и
словом типа стоит в 15 строках; ещё около 60 строк пишут три аргумента и переводятся механически.

До ответа: перевод записей идёт с проверкой равенства порождённого текста до и после, прежнее чтение не снимается.
Запись с тремя аргументами `@: p int @x` после перевода считается отказом по числу аргументов.

## В2. Массив заданной длины

Пакет: место без значения `int[]: values`, пустой массив `int[]: values []`, массив с элементами
`int[]: values [1 2 3]`, место от готового значения `T[]: destination Source`; длина — свойство значения. Записи
«массив из N элементов без перечисления» нет.

```lmx
[]: int cells 2
cells[1] := 7
```

Так сегодня пишут тридцать строк проверок прежнего пути: число после имени — длина. Тем же способом порождаемый
код L1 объявляет массивы C постоянной длины (`[]: size_t name N`). По редакции `int[]: cells 2` — инициализация
готовым значением 2, которое не массив.

- (а) элементы перечисляются: `int[]: cells [0 0]`;
- (б) длина задаётся операцией после объявления: `int[]: cells []`, затем изменение размера;
- (в) отдельная запись длины.

Сюда же: исполнитель читает `T[]` на уровне L2 так же, как на L3, — массив с дескриптором `parent/length/storage`,
а указатель C пишется `T@` (аргументы запуска `char@@: mainArgs`). Если на уровне L2 `T[]` должен оставаться
массивом C, это меняет перевод исходников ядра.

До ответа: тридцать строк остаются в прежней записи; порождаемый L1 пишет массивы C как сейчас.

## В3. `[]` как имя типа

Пакет: `@[]` — тип массива ссылок, где левый `@` — универсальная ссылка; `[]: pending` — место, принимающее любой
массив. Не сказано, является ли `[]` сам по себе именем типа «любой массив», которое можно продолжать постфиксом.

```lmx
[]@: p
[][]: rows
int: code []@
```

- (а) да: `[]@` — ссылка на любой массив, `[][]` — массив любых массивов, оба с кодами типа;
- (б) нет: `[]` — только голова объявления, эти три записи отказывают.

До ответа: разбор хранит такие головы как записаны, ядро на них отказывает.

## Ответ автора, 2026-11-23

Дословно, с выводами — в [журнале](../2026-11-23.md#typed-head-first-argument). Автор указал, что правило для
первого места уже стоит в документах, и добавил общее: формы типизированной головы различает первый аргумент,
безымянных переменных нет, значением ссылки может быть адрес.

## Что отвечают документы, по местам

Найдено исполнителем после ответа в документе
[о типах](../../docs/spec/CORE_SEQUENCES_REGEX.ru.md#types-details); это чтение исполнителя, не слова автора.

- **В1.** Снятые чтения, среди них `@: int` как тип указателя на `int`, читает общий разрешитель по их обычному
  смыслу; в новые головы они не преобразуются. Значит, `@: q int` — универсальная ссылка `q` с инициализатором,
  которым стоит слово `int` в роли значения: ни прежнего смысла, ни особого отказа. Забытая прежняя строка
  молча меняет смысл, поэтому перевод исходников обязан не оставлять таких строк; он сделан командой по узлам
  разбора, и счёт по тексту это подтверждает.
- **В2.** Отдельной записи длины нет. Формы массива — место без значения, место со значением и построенное
  значение без имени; согласованный размер меняет `sys\resize`. Тридцать строк проверок прежнего пути и восемь
  массивов исходников переписываются на эти формы в шаге, который снимает прежнюю запись. `T[]` на уровне L2 —
  массив LMX с дескриптором, а указатель C пишется `T@`.
- **В3.** Самостоятельное `[]` без левой формы сохраняет обычную роль литерала или символа ресивера и не
  является постфиксным конструктором при отсутствующем аргументе; группа слева от постфикса типа даёт полное
  требование, которое из неё получает общий нормализатор. Значит, `[]@` и `[][]` читаются общим механизмом как
  постфикс при пустой группе: требование пустой модели, а не отдельное имя типа «любой массив»; особого отказа
  нет. Ответил fable по документам; автор этого места отдельно не называл.

Сверку этих мест с пакетами документов делает помощник; если в пакетах найдётся предложение, не перенесённое в
рабочие документы, оно вносится с записью в журнале правок документации.
