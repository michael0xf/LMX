# Ответы о присваивании и индексе

Вопросы закрыты. Ответы сверены с действующей документацией 2026-11-15.
Ниже сохранены действующие правила; вопросы об отменённых формах удалены.

## Групповое присваивание

Окончательная [реплика автора](../2026-11-10.md#no-structure-head):

> акутальность поддержки head в виде структуры получается исчезла -- мы присваиваем (a, b, c):=myFn() # правильно я понял?

Текущий контракт — [групповое присваивание](../../docs/LMX_semantics.ru.md#group-assign):
все правые значения вычисляются до первой записи, поля результата сопоставляются по позиции,
а левая часть состоит из доступных мест с учётом последовательной видимости переменных и const.
Форму результата-Structure объявляет fn.

## Написание составных присваиваний

Действуют `+=`, `-=`, `*=`, `/=`,
`%=`, `<<=`, `>>=`, `&=`, `^=`, `|=`, `**=` и обычное `:=`;
[операторы](../../docs/LMX_grammar.ru.md#operators).

## Индекс и тип адресованного значения

Последующие решения автора — [сырой индекс L2 и указатель L3](../2026-11-15-explicit-compilation.md#arrays-native-proposal).
Structure и `Array<@>` взаимозаменяемы. L2 вычисляет смещение без проверок длины,
знака индекса или прежнего требования поля; допустим и отрицательный индекс.
L3 проверяет только итоговый индекс относительно length. Именованные пути
проверяются по общему контракту допуска; сырая запись `S[n] := p` этого допуска не выполняет.
Вспомогательный ресивер типа теперь называется `sys\typeof`,
[контракт](../../docs/LMX_semantics.ru.md#get-type).
