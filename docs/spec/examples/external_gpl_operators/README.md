# Два пользовательских оператора с разнородными аргументами

В выражении `(margin mipMax usage stock "IIC" 2500)` после имени оператора стоят четыре самостоятельных аргумента. Матрица задаёт ограничения задачи, вектор задаёт запасы, строка выбирает допустимые типы переменных, целое задаёт лимит времени. Одна пользовательская операция получает их все при обычной группировке Expression. [Примеры в книге LMX](../../LMX_semantics.ru.md#heterogeneous-user-operands) · [Подготовка аргументов](../../LMX_semantics.ru.md#prepared-operands).

## План производства через GNU GLPK

Цех выпускает два изделия целыми партиями. Неизрасходованное сырьё можно продать на вес. Сколько партий выпустить и сколько сырья продать, чтобы получить наибольший доход?

```lmx
[3]double: margin [12 9 2]
[2][3]double: usage [4 3 1; 2 3 0]
[2]double: stock [10.5 6]
@: plan (margin mipMax usage stock "IIC" 2500)
```

Каждая колонка соответствует решению: партия первого изделия, партия второго, продажа единицы сырья. Строки матрицы задают расход сырья и труда. Запасы составляют 10,5 единицы сырья и 6 часов труда. Например, партия первого изделия расходует 4 единицы сырья и 2 часа, приносит 12. Продажа единицы сырья приносит 2 и не требует труда.

| Вход | Что получает метод |
| --- | --- |
| `left` | Вектор доходов на единицу каждого продукта |
| `right[0]` | Матрицу расхода ресурсов, по одной строке на ресурс |
| `right[1]` | Вектор доступных ресурсов в порядке строк |
| `right[2]` | Строку с одним символом на колонку. `I` задаёт целое количество, `C` допускает дробь, `B` допускает 0 и 1 |
| `right[3]` | Целый лимит времени решения в миллисекундах |

GLPK нашла оптимум **29** при количествах `[2 0 2.5]`. Две партии приносят 24, продажа 2,5 единицы оставшегося сырья приносит ещё 5. Замена `"IIC"` на `"III"` требует продавать сырьё целыми единицами. Новый оптимум **28** при количествах `[2 0 2]`. Обёртка задаёт тип каждой колонки через `glp_set_col_kind`, передаёт лимит в `glp_iocp.tm_lim` и вызывает `glp_intopt`. Результат содержит статус решения. [GNU GLPK](https://www.gnu.org/software/glpk/) · [Пакет и лицензия GPL-3.0-or-later](https://packages.msys2.org/packages/mingw-w64-x86_64-glpk).

## Минимальный разрез сети через igraph

Через какие линии проходит самое узкое место на пути из порта на завод? Слева оператор получает структуру направленной сети. Справа идут номер исходной вершины, имя конечной вершины и вектор пропускных способностей в порядке рёбер.

```lmx
[5]double: capacity [5 4 2 3 1]
@: cut (network cutBetween 0 "завод" capacity)
```

Вершины сети пронумерованы от нуля в порядке «порт», «север», «юг», «завод».

| Номер ребра | Направление | Пропускная способность |
| --- | --- | ---: |
| 0 | порт → север | 5 |
| 1 | порт → юг | 4 |
| 2 | север → завод | 2 |
| 3 | юг → завод | 3 |
| 4 | север → юг | 1 |

Результат содержит ёмкость **5**, номера рёбер **2 и 3** и вершины со стороны источника — порт, север и юг. Эти две линии отделяют завод от порта. Можно доставить 2 единицы через север и 3 через юг, так что разрез меньшей ёмкости невозможен. Расширение допускает имя или номер для *каждой* вершины. Выражение `(network cutBetween "порт" 3 capacity)` возвращает тот же результат. Строка здесь служит ключом вершины. [API igraph для минимального разреза](https://python.igraph.org/en/0.11.9/api/igraph.Graph.html#st_mincut) · [Код потока и лицензия GPL-2.0-or-later](https://github.com/igraph/igraph/blob/0.10.16/src/flow/flow.c).

## Как подключены операции

Оба оператора могут разделять один DATA-контракт. Так выглядит сторона LMX, если пользовательское расширение экспортирует методы `Solvers\maximize` и `Solvers\minCut`, принимающие левое значение и массив правых ссылок:

```lmx
ExternalOps:
    @: left
    int: depth
    []@: right
    const: int: PASS_ARGS_AS_IS 0
    const: int: PRIORITY 70
    required: left right
    return: @
    mipMax:
        return: Solvers\maximize(\left; right)
    cutBetween:
        return: Solvers\minCut(\left; right)
```

В методе вызывающего `import: ExternalOps` вводит оба имени из примеров. Приоритет 70 выбран для этих двух операций. В показанных вызовах depth опущен. Каждый элемент `right` сохраняет собственный тип, поэтому матрица занимает одну позицию, как и строка. [Контракт операнда и пример объявления](../../LMX_semantics.ru.md#prepared-operands).

В исполняемом примере разрешённые ссылки на `mipMax` и `cutBetween` связаны с двумя функциями расширения. Обе проходят через эталонный группировщик Expression и один адаптер `UserOperand.invoke`. Адаптер принимает левое значение и правые аргументы в порядке записи. Математическая работа выполняется в нативных библиотеках через swiglpk и python-igraph. [Исполняемый пример](run.py) · [Группировщик](../../tools/expression_grouping_reference.py) · [Каталог стандартных матричных операций LMX](../../TENSOR_EXPRESSIONS.md#matrix-contracts).

### Воспроизведение

Из корня LMX в PowerShell с Python 3.11:

```powershell
py -3.11 -m venv "$env:TEMP\lmx-gpl-examples"
& "$env:TEMP\lmx-gpl-examples\Scripts\python.exe" -m pip install --only-binary=:all: "swiglpk==5.0.13" "igraph==0.11.9"
& "$env:TEMP\lmx-gpl-examples\Scripts\python.exe" -B "docs/spec/examples/external_gpl_operators/run.py"
```

Проверены группировка на готовых значениях, оба решения GLPK 5.0 и разрез igraph 0.10.16 для обоих способов адресации. Показанные фрагменты исходника LMX иллюстрируют вызов. Разбор их текста промышленным P0 и нативная сборка LMX в эту проверку не входили.
