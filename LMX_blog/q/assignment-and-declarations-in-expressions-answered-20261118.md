## Что есть сегодня

Пробы исполнителя на принятом инструменте чистого графа, режим интерпретации; дерево разбора — команда `p0`.
Наблюдение — запись в `shared\Observed\seen`.

| запись | дерево разбора сегодня | ответ инструмента |
|---|---|---|
| `r := (1 + v := 2 + 2) * (v + 1)` | `1 + (v := 2 + 2)`: правая часть `:=` идёт до конца группы | отказ |
| `int: n (1 + int(v 2) + 2) * (v + 1)` в data | как написано; `int(v 2)` — запись внутри выражения | отказ |
| `f(1 + int: v 2; + 2)` | одно выражение из пяти полей; `;` закрывает только `int:` | отказ |
| `n := 1 + int(2) + 2` | — | 5, работает |
| `f(a := 1 b := 2 c e := 3)`; то же с запятыми | у обеих одно дерево: `a := (1  b := (2  c  e := 3))`, один аргумент | отказ |
| `f(a := 1; b := 2; c := 7; e := 3)` | четыре аргумента | 1273 |

Ответы на «можно ли»:

- Пункты 2–4 — можно без правки разбора: дерево разбора уже держит такие записи внутри выражения, не хватает
  исполнения.
- Пункт 1 требует правки разбора: где кончается правая часть `:=`, сегодня решает разбор, а норма этого не
  определяет — грамматика, §21: «приоритет и ассоциативность `:=` этим решением не определены».
- Пункт 5: сегодняшний разбор ломает и форму без запятых, и форму с запятыми; работает только `;`. Все
  поддерживаемые тесты пишут `;`.

Масштаб: в поддерживаемых исходниках и тестах 40 344 записи с `:=`; ни в одной правая часть не содержит второго
поля; около 7 500 записей имеют справа выражение с оператором (`x := a + b`).

## Вопросы

### 1. Счёт в примере пункта 1

`(1 + v := 2 + 2) * (v + 1)`. При `v := 2` слева 1 + 2 + 2 = 5, справа 2 + 1 = 3; произведение 15. Число 8
получается при `+` между группами. Верно 15?

### 2. Где кончается правая часть `:=`

В `1 + v := 2 + 2` у автора правая часть — `2`. В `n := (…) * (v + 1)` и `n := 1 + int(2) + 2` — всё выражение.
Варианты:

1. До конца записи, как сегодня. Тогда `1 + v := 2 + 2` даёт v = 4, а `f(a := 1 b := 2)` — один аргумент.
2. Ровно один операнд. Тогда `n := 1 + 2` даёт n = 1; это меняет около 7 500 записей исходников.
3. Предложение исполнителя. Правая часть продолжается, пока следующий оператор связывает сильнее оператора, стоящего
   перед присваиванием. Если перед присваиванием оператора нет, она идёт до конца выражения. На следующем поле она
   кончается всегда. Тогда `n := 1 + 2 * 3` даёт 7; `1 + v := 2 + 2` даёт v = 2;
   `f(a := 1 b := 2 c e := 3)` — четыре аргумента.

Различающая запись: `(1 + v := 2 * 3)`. По третьему правилу v = 6. По второму v = 2.

### 3. Групповое присваивание

Грамматика, §2 (решение автора 2026-11-10, [журнал](../2026-11-10.md#no-structure-head)): `(a b c) := c, a, b` —
правая часть из трёх полей. При любом правиле, где `f(a := 1, b := 2)` — два аргумента, эта запись читается как
`((a b c) := c), a, b`. Предложение исполнителя: писать `(a b c) := (c, a, b)`. В разборе эта форма ещё не
реализована (ошибка разбора), в исходниках не встречается. Согласны?

### 4. Позиционный аргумент после именованного

Исходная спецификация: «Positional fields are assigned first in order. Once a named argument field is encountered,
all following actual fields in that call must be named». Книга,
[запись в известное место](../../docs/spec/LMX_semantics.ru.md#assign-known):
«Позиционные фактические аргументы предшествуют именованным». В примерах автора `f(a := 1, b := 2, c, e := 3)` и
`(v := 2, 5)` позиционный стоит после именованного. Сегодня это отказ.

```lmx
fn: g (int: a; int: b) int
    return: a * 10 + b
g(b := 2, 5)
```

Ответ 52 — позиционный занимает первый формал, не поданный по имени, — или ошибка: 5 — второй аргумент, а формал
`b` уже подан?

### 5. Присваивание внутри аргумента

`f(1 + v := 2 + 2)`. Это `f(v := 2, 5)`, и переменная `v` вызывающего не меняется? Или пишется `v` вызывающего, а
`f` получает одно значение 5? По правилу пункта 3 «на том же уровне что и само выражение» исполнитель читает первое.

### 6. Объявление, стоящее аргументом целиком

Книга, [запись в известное место](../../docs/spec/LMX_semantics.ru.md#assign-known)
(решение 2026-11-11): «объявления в
аргументах быть не может»; запись-вызов в аргументах даёт позиционный аргумент. Сегодня при `fn: g (int: a; int: b)`
запись `g(int: b 2; 5)` отвечает 25: значение объявления подано первым по позиции. По пункту 3 автора это
`g(b := 2, 5)`, то есть 52. Подтвердите 52.

### 7. Уровень выражения у ресивера

В `int: n (1 + int(v 2) + 2) * (v + 1)` выражение — аргумент ресивера `int`, а ресивер повторяет поведение `fn` и
`sub`. Буквально по правилу «на уровне выражения» `v` объявилась бы среди аргументов `int`, их стало бы три, и
запись отказала бы. Автор пишет, что объявляются две переменные.

```lmx
fn: h () int
    if: (1 + int(v 2)) > 2
        return: v
    return: 0
```

`h()` даёт 2, если объявление попадает туда, где исполняется запись, — в активацию. `h()` даёт ошибку «`v`
неизвестна», если объявление остаётся среди аргументов `if`. Исполнитель читает первое. Тогда в data у вызова стоят
`int: v 2` и за ней `int: n 15`. Верно?

### 8. `int` с именем внутри выражения

`n := 1 + int(k) + 2` при k = 4 сегодня отвечает 3: форма `int(k)` с известным именем возвращает ноль. Исполнитель
читает так: она возвращает значение `k` после проверки типа, то есть ответ 7. Верно?

## Что исполнитель прочитает сам, если автор не поправит

- Вычисление идёт слева направо, как записано: `(v + 1) * (1 + v := 2)` читает прежнее `v`.
- В графе ничего не исполняется: путь `S\n` даёт запись как написана, поля `S\v` в графе нет.
- В data внутри значения объявляющего ресивера `:=` исполняется: его аргументы в роли `code`.
- C не задаёт порядок вычисления операндов, поэтому транслятор печатает такие выражения по частям, в записанном
  порядке.

## Что из ответа следует

Редакторское пояснение исполнителя, не слова автора.

1. Счёт: `(1 + v := 2 * 3)` — 7; `(1 + v := 2 + 2) * (v + 1)` — 25. Уточнено автором позже в тот же день
   ([журнал](../2026-11-18.md#chain-is-not-grouped)): второй пример даёт 15, и `v` в обоих равно 2 — цепочка
   аргументов присваивания не сгруппирована невидимыми скобками. Исходный пример автор писал без скобок по
   забывчивости; `(1 + (v := 2) + 2) * (v + 1)` — 15.
2. Знаки присваивания — `:=`, `+=` и остальные — читаются по правилам головы Structure: правая часть идёт до
   конца записи. Это первый вариант вопроса 2, так разбор отвечает и сегодня.
3. Групповое присваивание пишется `(a b c) := (c, a, b)`.
4. Именованный аргумент, стоящий на своей позиции, считается позиционным, и разбор идёт дальше как
   позиционный. `g(b := 2, 5)` при `fn: g (int: a; int: b)` — отказ; при `fn: g (int: b; int: a)` — принят.
5. `f(1 + (v := 2) + 2)` — это `f(v := 2, 5)`; переменная `v` вызывающего не меняется.
6. Объявление в аргументах — повторное объявление формала: оно присваивает формалу. `g(int: b 2; 5)` при
   `fn: g (int: a; int: b)` — отказ; `g(int: b 2)` принят. Ответ инструмента 25 — старый баг.
7. Объявление внутри выражения-аргумента остаётся на уровне аргументов ресивера; наружу ничего не попадает.
   `h()` из вопроса 7 даёт ошибку: в теле `if` имя `v` неизвестно.
8. `int(k)` в выражении возвращает значение `k` после проверки типа.
