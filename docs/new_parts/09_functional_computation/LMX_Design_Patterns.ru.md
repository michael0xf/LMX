# LMX: Функциональные вычисления

Haskell даёт естественный контроль для Maybe/Monad и каррирования. Scala сочетает функциональные приёмы с JVM, явным батутом и обычным управлением ресурсами. Эти языки выбраны за подходящие механизмы, а не для универсального рейтинга краткости.

Четыре исходных пункта 82–85 сохранены отдельно. Код сравнивает конкретные наблюдения: отсутствие результата, передачу следующего шага, освобождение ресурса и сохранение частично применённого значения. LMX использует обычные структуры и методы; в контрольных языках допускаются их стандартные функциональные библиотеки.

## Каталог

### 082. [Monad](082_monad_comparision.md)

Контекстное связывание вычислений на конкретном примере Maybe: отсутствие результата пропускает следующие шаги.

**Сценарий:** Дважды поделить целое число пополам. Каждый шаг допускает только чётное число. Прогнать 8 и 6; во втором случае второй шаг должен вернуть отсутствие, а продолжение после отсутствия не вызывается.

**Наблюдение:** Для 8: present=1, value=2 (Just 2 / Some(2)). Для 6: present=0 (Nothing / None). Bind не читает value отсутствующего результата. Законы unit/bind рассматриваются по наблюдаемому значению, без сравнения адресов контейнеров.

Haskell использует стандартный Maybe и >>=, Scala — Option.flatMap. Их краткость здесь отражает уже существующую библиотечную абстракцию. В LMX показана её реализация для int; универсальный полиморфный интерфейс Monad и доказательство законов для произвольных эффектов этим листингом не создаются.

### 083. [Trampoline](083_trampoline_comparision.md)

Исполнитель последовательно получает следующий шаг вычисления вместо роста цепочки вложенных вызовов.

**Сценарий:** Взаимные even/odd шаги определяют чётность неотрицательного n. Проверить 0, 1 и 100001. Каждый шаг возвращает управление драйверу; в LMX нет рекурсивного вызова второго шага.

**Наблюдение:** 0 → true/1, 1 → false/0, 100001 → false/0. Выполняется n+1 шагов с проверкой базы. LMX-драйвер хранит один текущий next, а не историю из n кадров.

В Scala использован готовый TailCalls; в Haskell явно показан тип Bounce и хвостовой драйвер. В LMX шаг представлен обычной ссылкой на метод, состояние остаётся в живом драйвере. Это один специализированный алгоритм; универсальная CPS-библиотека и асинхронное планирование не предполагаются.

### 084. [Execute Around](084_execute_around_comparision.md)

Приобретение и освобождение ресурса окружают переданное пользовательское действие.

**Сценарий:** Передать три операции: acquire создаёт ресурс, action возвращает 42 либо выбрасывает ошибку, release фиксирует освобождение. Проверить обычный результат, ошибку тела и ошибку acquire.

**Наблюдение:** Успех: acquire → action → release, результат 42. Ошибка action: тот же порядок с обязательным release и распространением ошибки. Ошибка acquire: release не вызывается, потому что ресурс не получен.

LMX использует finally, Haskell — bracket, Scala — try/finally. У Haskell bracket также учитывает асинхронные исключения; наш общий сценарий ограничен обычным выходом и ошибкой тела. Сравниваются одинаковые supplied acquire/release/action, поэтому размер реализации файловой системы не приписывается одному языку.

### 085. [Currying](085_currying_comparision.md)

Преобразование бинарного сложения в последовательность получения функции и её вызова с оставшимся аргументом.

**Сценарий:** Построить add5 и add100, завершить обе фабричные активации, затем вызвать add5(1), add100(1), add5(1). Одноимённая локальная saved у вызывающего не должна менять захваченное значение.

**Наблюдение:** Последовательность 6, 101, 6; общий demo возвращает 6101006. Исходный прототип остаётся с saved=0. У каждой возвращённой функции один явный вход x.

В Haskell функции естественно каррированы; Scala показывает Function2.curried. LMX реализует ту же наблюдаемую двухступенчатую операцию через возвращаемый метод и явное сохраняемое окружение. Это существенно длиннее встроенной функции двух функциональных языков; заменять это изменением default неверно, потому что default оставил бы дополнительный вход и возможность переопределения.
