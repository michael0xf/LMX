# Прямые обращения к Python из LMX

В L2 и L3 `py.` открывает доступ к пространству имён выбранной сессии Python. Как и у `c.*` в L2, для очередного имени не требуется объявлять одноимённый ресивер или добавлять строку в таблицу LMX. Имена встроенных функций, модулей и объектов, которые приложение определило после трансляции, подчиняются одному правилу. [Грамматика](../../docs/spec/LMX_grammar.ru.md#foreign).

| Обращение из LMX | Что делает Python в выбранной сессии |
| --- | --- |
| `py.abs(-7)` | Вызывает доступный `abs` с одним аргументом. При обычном встроенном `abs` результат равен 7. |
| `py.math.factorial(6)` | Если имя `math` уже связано с модулем в этой сессии, получает его атрибут `factorial` и вызывает с аргументом 6. Результат равен 720. |
| `py.score(21)` | Вызывает `score`, определённую приложением в Python. Создавать `score` в LMX для этого не требуется. |
| `py.open(path)` | Обращается к Python-имени `open`. По умолчанию это встроенная функция открытия файла. |

Общий P0 сохраняет слитную цель и обычные аргументы LMX. При исполнении переход получает готовую сессию из обычного связывания у владельца. Если открыто несколько сессий, обращение использует сессию данного места вызова. Сам префикс не открывает сессию и не задаёт общей на процесс. Имена и атрибуты разрешаются в ней по правилам Python. Аргументы LMX вычисляются по одному разу и передаются Python как позиционные и именованные аргументы. Контекст моста и сессия относятся к самому переходу. Параметр Python с именем `session` или `context` получает значение только тогда, когда вызывающий передал его самой функции. Отсутствие имени, отсутствующий атрибут и исключение вызываемого объекта передаются как ошибки соответствующего обращения. Поиск имени не устанавливает пакеты.

## Установка и управление сессией

| Обычный ресивер LMX | Входы | Результат |
| --- | --- | --- |
| `installPython` | `context`, `plan` | `PythonInstallation` с принятым поколением установки |
| `openPython` | `context`, `request` | Готовая `PythonSession` после открытия или подключения |
| `closePython` | `context`, `session` | Освобождение сессии после проверки её ресурсов |

Эти имена разрешаются в графе LMX обычным способом. Публичные имена ссылаются на тела с собственным DATA. `PythonGateContext` содержит порты `native` и `installer`. [Имена ресиверов](../src/lifecycle.lmx) · [Тела и договоры входов](../src/gates.lmx).

## Объекты, аргументы и результаты

Адаптеры импорта, чтения и записи атрибутов и элементов, вызова удерживаемого объекта, копирования значений, управления ссылками и буферами служат реализации перехода. Например, `py.getattr(obj; "x.y")` вызывает Python `getattr` с одним именем атрибута `x.y`. У выражения `py.a.b` точки написанной цели задают последовательность обращений к объектам.

У прямого обращения результатом служит удерживаемый Python-объект. Для вызова ранее полученного callable адаптер принимает `args` как упорядоченный Array handles одной сессии и `kwargs` как Array пар `PythonKeyword(name,value)`. Пустые наборы допустимы. Мост проверяет принадлежность handles сессии и повторы имён до вызова Python. Для CPython это подготовленные tuple/dict и `PyObject_Call`. Вариант с vectorcall сохраняет порядок, владение и исключения. [Протокол вызова CPython](https://docs.python.org/3/c-api/call.html) · [Примеры с освобождением ресурсов](../examples/README.md).

| Действие адаптера | Владение результатом |
| --- | --- |
| Импорт модуля, чтение атрибута или элемента, вызов объекта | Одна удерживаемая ссылка. Успешная запись атрибута или элемента возвращает удерживаемый `None`. |
| `retain`, `release` | Создание и освобождение одной отдельной ссылки владельца. |
| `fromValue`, `toValue` | Из значения LMX получается удерживаемый объект Python. Обратное копирование даёт `PythonValue` с явными пределами глубины и числа элементов. |
| `buffer`, `releaseBuffer` | Получение и освобождение отдельной аренды буфера с указанным режимом записи. |

Аргументы каждого адаптера определены его DATA. [Договоры адаптеров](../src/gates.lmx) · [Модель владения](ARCHITECTURE.md).

## Открытие и установка

`PythonOpenRequest.mode`: `1` — app-private runtime из `installation`, `2` — явно выбранный внешний Python через `external`. Неактивное поле не читается. `openPython` инициализирует `slots`, identity, generation и owner; возвращать готовую session до успешного handshake запрещено.

`installPython` возвращает новую опубликованную filesystem generation. Живая session удерживает своё поколение; install не подменяет под ней `libpython`, modules или native extensions. System mode использует имеющиеся packages выбранного Python и не устанавливает ничего в его global site-packages. Для добавления packages создаётся отдельное app-owned окружение/worker; его изменение является отдельной установкой.

Установка failure не является Python call failure: причина отражается в `PythonProblem.reason` (`digest`, `target`, `python-abi`, `no-compatible-wheel-tag`, `probe`, `publication-conflict`). Загрузка/вызов передают реальную структурированную ошибку. Все recoverable границы имеют объявленный `PythonBridgeFailure`.

## External wire contract

Wire передаёт обычные ограниченные DATA и opaque `(sessionId,generation,objectId,lease)`; адреса не пересылаются. Header содержит protocol `1`, sequence и hash принятых bytes. `PythonExternalTurn` проверяет generation, последовательность и повтор уже завершённого запроса. Повтор с другим payload даёт conflict. Пропавший результат не делает side effect безопасным для повторного выполнения.

В начальном worker-профиле есть import/getattr/call/getitem/setitem/setattr/retain/release/toValue/fromValue. Open/close обслуживаются lifecycle channel, install — локальным installer выбранного владельца. Shared buffers и callbacks в handshake равны нулю. Живой proxy, coroutine и generator не превращаются в завершённое значение: их тип/lifetime сохраняется; отдельный await/stream API потребует будущего расширения capabilities.
