## Автор: правила объявлений, присваивания и указателей на методы

Техническая выдержка из сообщения автора:

```text
У нас теперь такие правила автоматически вытекают:
Model: ptr  при неизвестном Model это в любом случае ошибка так как var -- атом
Model: () при неизвестном Model это объявление структуры
Model: ptr  при известном Model и неизвестном ptr  это объявление указателя ptr на реальную Model
@: ptr Model #синоним предыдущего
Model: ptr  при известном Model и известном ptr это попытка присвоить Model значение ptr
@:  ptr Model 0 # null указатель на Model
ptr: Model  # при известном ptr попытка присвоить ему значение Model
@:  ptr Model Other # объявление указателья типа Model и присвоение ему Other через implements
Все формы node\[i]field удаляем полностью и кода кроме массивов arr[i]\[j]
В случае fn fm sub catch те же конструкции без "@" делают вызовы, с "@" -- это уже указатели на методы и они так же синонимы самим методам, как было со структурами.
@: fn_ptr myFn
fn_ptr: args #в отличие от C99 это не вызов а попытка присвоения указателя
\fn_ptr: args #это вызов функции по адресу
```
