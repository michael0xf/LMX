## Проект (черновик до ответа Codex на FABLE-308-IDS-TRANSLATOR-DESIGN-QUESTIONS-20261108T1406Z-01)

1. Сервис `lmx_ids` входит в сборку l2trans как часть (`bld_machine_module(… "lmx_ids", ids_names, 6, 0)` в `bld_p0_l2_selected`,

   нормализует их при своей загрузке (`l2_ids_load`); коды транслятора в выпуск не попадают.
2. `LmP0Text` получает поле `code` (decl 39). Граница текста — конструирование: P0 даёт код в `lm_p0_new_text` и в прямых записях
   атомов/голов через `lm_p0_text_code`; frontend — через один помощник конструирования (`lm_compiler_text_init`/`text_code`) на всех
   ~100 местах, включая синтезированные имена и срезы путей; `lm_compiler_text_clone` переносит код.
3. Сравнения: `lm_compiler_text_same` — равенство кодов; идентификатор без кода в точке сравнения — инвариант транслятора (отказ
   с внутренним сообщением, измеримо реестром и bootstrap), не байтовое сравнение. Литералы: `lm_compiler_text_word(текст, w)` /
   `lm_compiler_frame_word(узел, w)` с индексом слова таблицы транслятора `l2_words` (первые 20 — слова ядра `LMX_ID_*` в порядке
   засева, дальше — собственные написания транслятора; таблица заполняется один раз при старте через name→code, в проходах —
   только числа). Пунктуация — по решению Codex (вопрос 1).
4. Интерн сигнатур (`lm_compiler_intern_match/store`), `lm_compiler_throw_key` (неявные броски 1..7 = `LMX_ID_*` 1..7), таблицы
   предефов по смещениям (`pd + off`) — коды вместо срезов байтов; сравнения кодов типов через `prim_code_name` — сравнением кодов.
5. Остаются текстом: исходный буфер, координаты диагностики, тексты пользовательских строк, пути файлов, CLI, вывод.

## Устройство (кандидат a15)

1. **Сервис кодов в трансляторе.** `lmx_ids` — часть сборки l2trans и l1trans (`bld_machine_module(… "lmx_ids", p0_ids_names, 6, 0)` в
   `bld_p0_l2_selected`; заголовок и state-юнит пишутся decl 57/58; корни `decl_l2_frontend_root` и `decl_l1_backend_root` предефят
   `l2src/lmx_ids.h.lm1` и импортируют `l2src/lmx_ids.lm1`): свой экземпляр пары таблиц на процесс транслятора. Выпущенная единица
   по-прежнему несёт написания и нормализует их при загрузке; коды транслятора в выпуск не попадают.
2. **Граница текста.** `LmP0Text` = {`data`, `length`, `code`} (decl 39). Единственное место, где байты становятся кодом, —
   `lm_p0_text_code(data, n)` (p0_text): всякому написанию, которое может именовать или быть словом языка, — код из `lmx_ids_code`;
   не кодируются число (цифра первой), строка в кавычках, пустой текст (`lm_p0_text_codable`); точный идентификатор в обратных кавычках
   (n ≥ 3, `` `…` ``) получает код своего значения — содержимого между кавычками ([грамматика, exact identifiers](../../../docs/LMX_grammar.ru.md):
   «обе записи обозначают одно имя»; ядро регистрирует имена обходчика так же, срез 303). Сервис, не давший кода кодируемому написанию, —
   инвариант (сообщение, exit 3). P0 даёт код в `lm_p0_new_text` и в семи прямых записях атомов/голов (parser 1664, 2394, 2545, 2580,
   2644, 2692, 3478), `lm_p0_identifier_payload` и `lm_p0_text_view_new_cstr`; frontend — на ~100 местах конструирования (срезы путей,
   синтезированные имена `sprintf`, литералы собственных написаний `"Lmx"`, `"LmxArray"`, `" receiveMessage"`, …) и в `l2_machine_types`
   (`"ptrdiff_t"`). **Копия текста несёт код источника**, а не вычисляет его заново: `lm_compiler_text_clone` (a12 — см. причину отказов
   ниже), `lm_compiler_cnt_keep`, `lm_compiler_exact_ident` (код точного идентификатора — код его значения), голова источника в
   `lm_compiler_written_form_split`.
3. **Сравнения.** `lm_compiler_text_same(a, b)` — равенство кодов; кодируемое написание с кодом 0 на сравнении — инвариант транслятора
   (`lm_compiler_text_invariant`: «l2trans: invariant: an identifier without a code (left|right|word|implicit name|intern …): <написание>
   (code, length, text, ids)» на stderr, `exit(3)`; ответ Codex 3: без байтового запасного пути и без «0 = 0»); байты сравниваются лишь
   когда оба текста некодируемы (числа, строки). Литералы: `lm_compiler_text_word(t, w)` / `lm_compiler_frame_word(узел, w)` — код
   текста против кода слова `w` таблицы транслятора `l2_words` (`c.LM_W_*`, 129 слов: первые 20 — слова ядра `LMX_ID_*` в порядке засева,
   их коды проверяются равными константам; далее собственные написания транслятора, пунктуация `[]`, `@`, `+`, `\`, …, имена таблиц
   `primitive.convert`/`primitive.description` и их столбцов; заполняется один раз при старте `lm_compiler_words_init` через name→code,
   ни одно слово без кода). Неявные броски — `lm_compiler_text_implicit(t, g)`: код имени = номер обходчика g (1..7). `lm_compiler_text_eq`
   остаётся только для литералов-не-написаний (`"0"`); кодируемый литерал в нём — инвариант. `lm_compiler_payload_same` — обёртка над
   text_same (обратные кавычки снимает граница текста); `lm_compiler_payload_eq`, `lm_compiler_text_is_bytes` удалены.
4. **Сегменты пути.** Текст пути (`L2Path\text`, «a\b\c», склеенный адаптером из атомов) режется в резолвере (`lm_compiler_seg_at`/`seg_split`:
   off/len); сегмент читается как текст со своим кодом в точке разреза — `lm_compiler_seg_text(pd, off, len, @out)` спрашивает код у той же
   единственной таблицы; сравнения — `lm_compiler_seg_same(имя, pd, off, len)` (= text_same) и `lm_compiler_seg_word(pd, off, len, w)`
   (= text_word): resolve 2283 (`node`), 2359, 2402, 2517, 3096; coords 1154; context 2122; lower 596 (имя перед `[`), 3795/3805 (plain_base),
   14652–14666 (корень `node`/формал/own хоста); values 1301–1307 (части метода `args`/`return`/`var`/`body` — слова); types 185 (имя за
   префиксом `c.`); `lm_compiler_name_is_seg` — обёртка над seg_same. Шаги L2Path с переносимыми кодами атомов — альтернатива глубже
   (вопрос 1 Codex, FABLE-308-IDS-TRANSLATOR-PASS2-QUESTIONS-20261108T1630Z-01).
5. **Типовые слова и таблицы.** Коды примитивов сравниваются как коды: `lm_compiler_prim_same(a, b)` (оба с типовым словом и равны) вместо
   `strcmp(prim_code_name(a), prim_code_name(b))` (core 3521, emit 5195, lower 1364, 1454, 1507, 1648, 9594, 9698); таблицы спрашиваются
   кодом слова типа — `lm_compiler_prim_code(ft)` = `l2_words[prim_word(ft)]`, `lm_compiler_own_ty_code(ty)`. Таблицы `primitive.description`
   и `primitive.convert`: имя таблицы и столбцов — слова (`lm_compiler_table_find(w)`, `lm_compiler_table_col(t, w)`,
   `lm_compiler_convert_colword`/`prim_colword`; `*_colname` остаются для текста диагностик); ячейка-имя — код её атома, перенесённый
   парсером (`lm_compiler_tbx_code(at)`, 0 для ячейки не-имени); `lm_compiler_convert_hit(from_code, to_code)` и `lm_compiler_prim_row(name,
   code)` ищут строку по кодам; `None`/`forbidden`/`void` — слова; ячейка `1` — число (строка `"1"`, не написание); `cv_recv_code` —
   код ячейки receiver (перенесён, не вычислен). `lm_compiler_primitive_leaf_implements` сравнивает cand/req кодами.
6. **Интерн сигнатур.** Контракт хранит коды имён формалов (`l2_it_nc`) и скрытых входов (`l2_it_hc`) и их типы; массивы указателей на

8. **Остаются текстом (по роли; классификация Codex):** CLI; пути и суффиксы файлов; снимки состояния эмиттера (emit 2030/2035/16589);
