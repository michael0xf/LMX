# Результат-Structure структурного вызова: хвост `return`, 2026-11-25

Принят компонент 21.7 K3n, часть 2 (хвост). Хвост `return: 7 9` в теле, чей запуск несёт описание результата
блоком мест ([часть 1](../graph-structure-result-20261124/notes.md): поле кадра `result_description`), строит
результат: один новый Structure с местами, объявленными как поля блока; значения — элементы хвоста по порядку (книга
`#structure-result`: хвост `return: 1 2 3` поставляет описанные поля результата по порядку). До среза такой вызов
отвечал 5: хвост не был результатом.

## Решение дизайна

Проект codex (`CODER-K3N-TAIL-DESIGN-20261124-01-ANSWER`): ветка берётся только при живом `result_description`
запуска; хвост разбирается в общем возврате runtime; число значений равно числу полей блока, иначе 5 до вычисления
любого элемента; несовместимое значение — 4, как в любом принимающем месте; каждый элемент вычисляется один раз,
слева направо, в области видимости тела, и принимается в НОВОЕ место, объявленное как его поле; блок описания не
подаётся в `merge_literal_open/put`; значение-элемент — обыкновенное выражение, эмиттер не меняется.

Уточнение codex от 2026-11-25 (`CODER-K3N-TAIL-VALUE-ROOT-20261125-01-ANSWER`): корень для временного Value
остаётся. Мутант N3 (ниже) показывает только, что в наблюдаемой точке полей под корнем `made` уже достаточно; окно
между возвратом `eval_record` и переносом в новое место идёт через скалярный ABI (`result_receive_as` →
`scalar_snapshot`, `materialize` → `foreign_capture` с `abi.init` и `abi.copy`) и отдельной гарантии
нереентерабельности не имеет. Две роли разделены в комментарии функции: Structure держит уже сделанные места, пока
позже идущий элемент может собрать мусор; Value держит вычисленный операнд до переноса в новое место. Один слот в
существующей записи корней, без нового выделения.

невозможен, поэтому программа с циклом таких вызовов прежде отвечала 5. Устранение — срез K5a по решению Astra (через

подходящим ответом; отдельные массивы слотов сохраняются. Рост ширины чанка отложен (D-67;
`l2src/lmx_pool_selftest.lm1:260–276`), `copy_metadata` — отдельный срез; затем одна широкая проверка G1/G2.

## Границы

- Поле описания, объявленное ссылкой (`@: b Box`): и одно значение `return: node\Pair`, и хвост `return: 7 node\Box`
  отвечают 4 — общая сверка интерфейса (`lmx_graph_source_interface`) не принимает поле-ссылку. Это граница K3
  целиком, не хвоста; строк не добавлялось (проба, не свидетельство).
- Приём элемента по типу поля сделан для скалярных мест (профиль пула и собственное место `int`); прочие поля
  проходит общая сверка результата с описанием. Значение элемента для поля иного скалярного типа принимается, только
  если оно уже имеет этот тип — как у скалярного результата: литерал `5` под `size_t: a` — 4, место size_t — принято.
- Мутант N3 живёт: корень Value не различается исполнением (см. решение дизайна).
- Полный набор, G1/G2 и fixedpoint на этом срезе не запускались: одна широкая проверка — на границе связанного
  изменения (вместе со срезом K5).
