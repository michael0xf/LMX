# Приказ автора: интерпретатор исполняет и L2 — с проверками; модуль проверок и типы L3

Дата записи: 2026-11-18. Источник: сообщение автора в диалоге с исполнителем (сессия fable_pc). Цитата дословная, с
авторским написанием; заголовок и пояснения стоят вне цитаты. Действующая норма — в
[семантике](../docs/LMX_semantics.ru.md#scope).

<a id="interpreter-runs-l2"></a>
## 1. Правило «интерпретатор поддерживает только L3» убирается; L2 интерпретируется с проверками, нативный L2 — без них

В отчёте о приёмке среза, где файл `.lm2` строится записью `L2:`, исполнитель написал по действовавшей норме: явный
`L2:` интерпретатор не исполняет, следующий шаг — нативный метод записи. Сообщение автора:

> Внесите в план и в код изменения:
> 1) Убери из документации правило что интерпретатор поддерживает только L3
> 2) сделайте модуль проверок и типы L3
> 3) интерпретацию L2 делайте с теми же проверками что и при интерпретации L3, если какой то адресной операции на L3 вообще нет , сделайте её с проверками для интерпретатора L2
> 4) нативный код L2 компилите без этих проверок для интерпретатора

Этим приказом снята часть «только L3» записей [2026-11-17, §24](2026-11-17.md#interpreter-is-l3) и
[уточнения к ней](2026-11-17.md#l3-compiles-too). Остальное в них действует: граф один, L2 — не другой язык и не
другой граф, L3 тоже компилируется в нативный код. Типы L3, о которых говорит пункт 2, перечислены автором в записи
[2026-11-17, §25](2026-11-17.md#l3-own-types).

## 2. `private` и `required` с несколькими аргументами; «корневой уровень» при чтении `data` не буквальный

Сообщение автора исполнителю в ходе работы над шагами приказа из §1:

> вставь в документы и план кода поддержку многоаргументных версий ресиверов private и required -- так как действие требует одного аргумента то это возможно, чтобы не приходилось писать десять раз. И проверь чтобы  "корневой уровень" при чтении data не означало буквально корневой игнорируя ресиверы типа private и required

Норма: [ресивер private:](../docs/LMX_semantics.ru.md#private-binding),
[ресивер required:](../docs/LMX_semantics.ru.md#required-receiver),
[прямой проход по данным](../docs/LMX_semantics.ru.md#data-root-declaration-execution). Что показала проверка
реализации — [ответы исполнителя, Р52](q/fable-self-answers-20261110.md).

## 3. Ресиверы `private`, `required`, `const`, `immutable`, `independent` исполняются; их переменные — корневые

Исполнитель записал §2 словами «корневой уровень не буквальный» и только для `private` и `required`. Следующее
сообщение автора:

> буквально-не буквально, просто ресиверы private required const immutable independent (и может какие-то еще) очевидно выполняются и переменные которые им передаются считаются "корневыми", также нужны многоаргументные формы и для всех перечисленных (и поищи еще для каких могут быть нужны)

Норма: [прямой проход по данным](../docs/LMX_semantics.ru.md#data-root-declaration-execution),
[const, immutable и independent](../docs/LMX_semantics.ru.md#qualification). Что нашёл поиск других ресиверов и что
делает реализация сегодня — [ответы исполнителя, Р53](q/fable-self-answers-20261110.md).

<a id="one-unnamed-structure-for-receivers"></a>
## 4. Одна Structure в аргументах, которые считаются `code`, — вся структура аргументов; и для ресиверов тоже

Исполнитель написал в отчёте: «группу с несколькими объявлениями в одних скобках,
`private: (int: x 20; int: y 3)`, я не вводил — только несколько отдельных аргументов». Ответ автора после цитаты
этой фразы:

> -- посмотри в жокументах и в коде, именно одна безымянная структура при передаче аргументов раскрывается (это касается только передачи аргументов, не парсера вообще)

Следующие сообщения автора, подряд:

> то есть это должно происходить автоматически и для ресиверов тоже

> парсера это не касается,

> это только правило вызова и везде где передаваемое ведет себя как code -- это надо делать

> в документах оно бесконечно упоминается, только не путать с выдуманным правилом про парсер - -в парсере ничего не раскрывается

И уточнение общего случая:

> общий случай -- мы подготовили структуру и передали ссылку на нее. Ссылку не присваивали какому-то имени, это даже не "безымянная" структура а более общий случай -- одна структура в аргументах которые считаются code

И пример автора:

> то есть
> Struct: arg0 arg1 arg2
> f: Struct
> f(arg0 arg1 arg2)
> f: arg0 arg1 arg2
> последние три ведут себя одинаково и с парсером это не связано -- это только общий с ресиверами механизм передачи аргументов в роли code

<a id="five-identical-calls"></a>
Позже автор прислал пример полностью; точки в начале трёх последних строк стоят у автора на месте отступа:

> Struct: arg0 arg1 arg2
> f: Struct
> f: (arg0 arg1 arg2)
> f(arg0 arg1 arg2)
> f: arg0 arg1 arg2
> f:
> . arg0
> . arg1
> . arg2

>  это 5 одинковых вызовов и повторяю что это не поведение парсера а общий с ресиверами способ вызова при передаче аргументов в роди code

Норма: [вся структура аргументов](../docs/LMX_semantics.ru.md#whole-arguments). Проверка реализации и исправление
прочтения исполнителя — [ответы исполнителя, Р54 и Р55](q/fable-self-answers-20261110.md).
