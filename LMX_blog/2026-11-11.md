## Повтор объявления — внеочередная проверка типа с присваиванием; в `data` повтор лишает имя голого пути

Источник: два сообщения автора подряд в сессии 2026-11-11 (чат «opus2»), в ответ на рабочую заметку исполнителя о
том, что он читает, «как исполняется повтор `int: i 6` в теле метода и в корне». Приведены целиком, дословно, с
исходными опечатками; первая строка первого сообщения — цитата заметки исполнителя, как её привёл автор.

Первое сообщение:

```text
"как повтор int: i 6 работает в теле метода и в корне." -- он никак не работает, это просто внеочередная проверка типа с присваиванием. Так как var в методах автозаполняется при построении графа. Повтор объявление в data (var) убирает возможнось обращаться к indexпеременной без индекса var\[n]variable
```

Второе сообщение:

```text
в выполняемых структурах то же самое только автозаполнения нет, если структура считает себя data то она все равно сначала инициализирует перменные своего корнеого уровня
```

Чтение исполнителя (не слова автора). У повтора объявления нет своего механизма: `int: i 6` при известном `i` — та же
проверка типа, что у объявления, исполненная ещё раз, и запись значения. Места метода существуют до исполнения тела:
его `var` заполняется при построении графа, поэтому объявление в теле ничего не создаёт и при первом исполнении. В
исполняемой Structure повтор — то же самое, но места сами не заводятся: их даёт выбранная `data`; Structure, которая
сама себе `data`, сначала инициализирует переменные своего корневого уровня. В `data` два вхождения одной корневой
головы лишают имя голого пути: нужен индекс вхождения, `var\[n]variable`. Новой нормы сообщения не вводят — они
называют действующую: [книга, имена и пути](../docs/LMX_semantics.ru.md#fields) («при двух и более … требуется
индекс», «автоматически выбирать первое исходное вхождение нельзя») и
[структурные формы](../docs/LMX_semantics.ru.md#forms-declare-or-call) («повторные объявления … после обычного допуска
записывает в существующее место»). Рабочий frontend исполняет её для Structure со среза 276; оба транслятора измерены
по этим сообщениям в [срезе 352](../steps/witnesses/receiver-check-20261111/notes.md) (раздел «Повтор объявления»),
найденные расхождения реализации записаны шагом 5 [раздела M9 плана](../next_core_tasks_v3.md#m9). Как исполнитель
читает «сначала инициализирует» для литерального и для вычисляемого начального значения — в
[ответах исполнителя](q/fable-self-answers-20261110.md), пункт М8.

## Ресиверы `call` и `fncall`: открытый общий механизм запуска кода над данными

Источник: пять сообщений автора подряд в сессии 2026-11-11 (чат «opus2»), после заметок исполнителя о проверке
повтора объявления и о том, что Structure, вызванная над собой, не читает своё поле раньше строки его объявления.
Каждое приведено целиком, дословно, с исходными опечатками; сообщения не склеены. Первая фраза четвёртого сообщения
— заметка исполнителя, как её привёл автор.

Первое сообщение:

```text
таким образом вопрос "видимость переменных вперед или назад" не имеет смысла в данном случае так как используется схема call(code, data) , просто data это автодозаполняемый var для fn sub catch. И data читается целиком. Методы могут быть внутри code, но они видимы в обе стороны.
Сделай, пожалуйста, ещё сужающие изменения в документации и в коде:
Ресиверов "call" надо много разных, и сделать чтобы через них интерпретатор запускал fn sub catch:
response:=call(args var return code) #fn
response:=call(var return code) #fn без аргументов
response:=call(return code) #fn без data
response:=call(args var code) #sub
response:=call(var code) #sub без аргументов
response:=call(code) # запуск структуры с самой собой как data
отсюда следствия:
1)fn sub catch отличаются тем что при построении графа дозаполняют свои var
2) если call при вызове структур получил какой-то левый data в котором нет используемых переменных -- выдавать ошибку
3) если в коде несколько корневых объявлений одной переменной и используется call(code) то выдавать ошибку при попытке обращения из кода к такой переменной без индекса
```

Второе сообщение (поправка к списку форм):

```text
их назвать по-разному , поправлюсь:

response:=fncall(args var return code) #fn
response:=fncall(var return code) #fn без аргументов
response:=fncall(return code) #fn без data
call(args var code) #sub
call(var code) #sub без аргументов
call(code) # запуск структуры с самой собой как data
```

Третье сообщение:

```text
то есть цель -- максимально открытый максимально общий механизм, а не скрытая кухня. Зачем -- чистый граф и новые L3Thread будут писаться прямо runtime в итоге
```

Четвёртое сообщение (первая фраза в кавычках — заметка исполнителя):

```text
"вызовы в fn теперь через fncall(...), в sub и при запуске Structure через call(...)." -- этот вызов это не обявление и не стандартный вызов, ты понял? Это дополнение к существующим механизмам
```

Пятое сообщение:

```text
fn вызываетс как раньше но мы должны быть способны как минимум в интепретаторе вызвать любую композицию структур
```

Чтение исполнителя (не слова автора). Код исполняется над данными: у `fn`, `sub` и `catch` данные — их `var`,
дозаполняемый при построении графа; этим они и отличаются от обычной Structure. Данные читаются целиком, поэтому у
переменных нет видимости «вперёд» или «назад»; методы внутри кода видимы в обе стороны. `fncall` и `call` — ресиверы,
которые получают части запуска явно: аргументы, данные, описание результата, код. Это дополнение: объявления `fn`,
`sub`, `catch` и обычный вызов `f(x)` остаются как были; интерпретатор исполняет обычный вызов тем же механизмом, что
открыт этими ресиверами, и ресивером можно запустить любую композицию структур. Три следствия — правила допуска
вызова: дозаполнение `var` есть только у `fn`, `sub`, `catch`; данные без используемой переменной — ошибка; при
`call(code)` имя с несколькими корневыми объявлениями в коде без индекса — ошибка. Что эти сообщения меняют в прежних
правилах `call` и что исполнитель прочитал сам — в [книге](../docs/LMX_semantics.ru.md#call-receivers),
[плане](../next_core_tasks_v3.md#m10) и [ответах исполнителя](q/fable-self-answers-20261110.md) (часть Н); порядок
аргументов прежней записи `call: code data` против `call(var code)` вынесен автору —
[П6](q/current/colon-declares-contradictions-20261110.md).
