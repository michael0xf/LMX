## Нормативная сверка

- Публичный `fn` заменён на обычный expression-операнд `Name :: DATA`; именованный DATA перенесён полностью. Конструктор по типам — `signatureTypes`, извлечение сигнатуры — `signature`.
- `::` не открывает особый Frame и не получает цель `end: Name`. Один правый шаблон и несколько правых аргументов различаются. Чтение полей DATA-шаблона не является раскрытием аргументов.
- При трёх совместных условиях снимается только внешний контейнер в `right`; `left` остаётся целым. P0 ничего не снимает, правило не применяется рекурсивно, результат функции автоматически не раскрывается. [Точная норма](../LMX_semantics.en.md#operand-right-only-opening).
- Ресивер LMX `implements` переименован в `satisfies`. Ключевые слова контрольных языков не менялись.
- Все операции входят в одно ядро; клиентские версии библиотек и обязательный `import: fun` не используются.
- `width` присутствует во всех восьми Flyweight. Сохранены значимые поля, copy/identity/effects и динамическая модель LMX; многопоточность остаётся на Message и описанном HTTP-транспорте.

[Аудит раскрытия](validation/operand_right_unwrap_review.json) и [интеграция в ядро](../kernel-implementation.en.md#receiver-kernel-integration) содержат подробные условия.

## Имена и общие типы

Применены **15 окончательно согласованных переименований** по [решениям об именах](../NAMING_2026-11-22.md) и [точной карте](api_revision_20261122.json); добавлены `splice`, `hasPrefix`, `hasSuffix`. `replaceRange` меняет диапазон и возвращает target; `splice` возвращает удалённые элементы; текстовый `replace` возвращает новый текст. Иностранные API сохраняют настоящий регистр и договор. Повторный запуск мигратора безопасно завершается без повторного переименования нового splice.

Составные типы записываются постфиксно: `T[]`, `T@`, `T@@`. Неинициализированная запись имеет нулевой payload и отличается от null и пустого массива. Успешный допуск не меняет фактический stride плотного массива. Корневые ТЗ объединены в [CORE_SEQUENCES_REGEX.en.md](../CORE_SEQUENCES_REGEX.en.md) и применены к связанным основным документам.

В предыдущей правке API были выполнены проверки Python-моделей; их результат сохранён, повторный запуск в правке throws не заявляется: **2640 случаев replaceRange и 2640 случаев splice**, включая ссылочные элементы и самоналожение. Это проверка перестановки и снимка модельного алгоритма, а не LMX-парсера, типовой системы, указателей или ядра. Предыдущие проверки арифметики range отделены в [SEQUENCES_SOURCE_REPORT](LMX_Fn_Receivers/tests/SEQUENCES_SOURCE_REPORT.json).

## Исполнение и оставшаяся интеграция

**Новые LMX-программы, интерпретатор и нативные переходы здесь не запускались.** Проверки относятся к публикации; `runtime_executed: false` сохранено. Новые Haskell/Scala-листинги также не выдаются за исполненные.

В [KERNEL_REQUIREMENTS](LMX_Fn_Receivers/KERNEL_REQUIREMENTS.md) перечислены **17 интерфейсов**: восемь исходных reflection/execution-входов, четыре Array-входа и пять фаз обычного вызова. Алгоритмы адаптеров, последовательностей и Pattern уже представлены LMX-исходниками; их подключение к этим интерфейсам и проверка на ядре остаются обязательными.

Для адаптеров исходники предусматривают отложенные реальные слоты, defaults/autofill, различие пропуска и явного значения, required/private, фактически достигнутые промежуточные сигнатуры и конечный callable как значение. Это конкретная попытка реализации [приоритетного ТЗ](../LMX_semantics.en.md#adapter-behavior), а не только перечень пожеланий. Источники связаны с [текущей нормой](../LMX_semantics.en.md#adapter-behavior).

Для динамических Pattern/callback-исходов остаётся интеграция с общей метаинформацией объявленных выходов ядра. Имя и payload ошибки должны проходить наружу без преобразования в отсутствие совпадения. Высокоуровневый matcher не закрывает этот интеграционный пункт.

После интеграции нужно выполнить подготовленные сценарии на интерпретаторе, при нативной компиляции и смешанных переходах, включая lifetime, объявленные отказы и связи owner → DATA → CODE. Эти проверки не объявляются завершёнными.
