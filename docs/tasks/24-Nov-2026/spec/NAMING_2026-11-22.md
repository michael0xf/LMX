# Canonical operation names and migration history

The current core uses one canonical name per operation and two applicable forms:
receiver and operand. New word names use lowerCamelCase, preferably an established
meaningful name of the corresponding operation. Symbolic names keep their spelling
and are available through ordinary exact identifiers in backticks. A name does not
import another language's evaluation, indexing, mutation or failure policy.

The [current catalog](patterns/LMX_Fn_Receivers/CATALOG.md),
[operation forms](OPERATION_FORMS.md),
[generic-operation contract](GENERIC_OPERATIONS.md), and
[equality contract](GENERIC_EQUALITY.md) specify the live API. Previous spellings
below are migration history only: no compatibility aliases, deprecated exports
or forwarding methods keep them callable.

## Current canonical migration

| Previous spelling or meaning | Current name | Contract |
| --- | --- | --- |
| `bindResult`, `flatMap` | `bind` | Result and sequence families share the same name as Maybe; receiving family and exact result remain explicit |
| Pattern `sequence` | `then` | Ordinary 0/1/N parts and established operand arity share one composition algorithm |
| `signatureTypes` | `->` | Ordered input TYPE tokens, then the result; reorder former result-first calls |
| `to` | `->` | Preserve input/result order; receiver `` `->`(A; B) `` and qualified segment `` FxToTokens\`->` `` use the exact identifier; no executable old alias |
| Predicate-example `both` | `allOf` | General signature and ordered short-circuit; empty set needs an explicit contract |
| Function-building `pipe(first; second)` | `compose(outer := second; inner := first)` | `pipe` now means immediate application of stages to a value |
| `intercalate` | `join` | One generic sequence-joining algorithm |
| `repeatText` | `cycle` | Select `rejectNegative := 1` when preserving the former negative-count refusal |
| `compareText` | `compare` | General lexicographic order; the text profile retains unsigned-octet order |
| `formatInt`, `parseInt` | `format`, `parse` | Explicit profiles; exact integer encoding/decoding remains one profile |
| `charRange` | `within` | Pattern of an inclusive ordered-value range; distinct from sequence `range` |
| `anyChar` | `anyElement` | One complete unit of the selected source |
| `textStart`, `textEnd` | `start`, `end` | Bounds of the selected source; structural role determines use of a marker |
| `matchedText` | `matchedValue` | Materialize a fragment in its source profile |
| `captureText`, `captureTexts` | `captureValue`, `captureValues` | One capture or its history in the source profile |

`type(x)` / `x type` queries a captured value's physical type; it is distinct
from `types`, `signature`, `Name :: DATA` and `return`. `arrayView` and `element`
provide explicit whole-value Pattern entry points. `++var` / `var++` and
`--var` / `var--` are names of one-PLACE variants; `var` is an argument slot,
not a wildcard in identifier lookup.

## Earlier canonical migrations

| Previous name in the preceding edition | Current name | Meaning retained by this rename |
| --- | --- | --- |
| `splice` | `replaceRange` | Replace a half-open sequence interval and return the same target. The new removed-result `splice` is added separately. |
| `deleteat` | `deleteAt` | Remove an explicit half-open interval and return the same target. |
| `flatmap` | `bind` | Sequence continuation with one-level concatenation; the intermediate spelling was also retired. |
| `groupby` | `groupBy` | Stable equal-key groups; optional projection and comparison use the documented shared defaults. |
| `oneof` | `oneOf` | Match one complete source unit from a set. |
| `noneof` | `noneOf` | Match one complete source unit outside a set. |
| `backref` | `sameAs` | Match the source-unit range of the preceding named capture. |
| `lookahead` | `ahead` | Positive lookahead under the existing capture/cursor contract. |
| `negative_lookahead` | `notAhead` | Negative lookahead; matching errors remain errors. |
| `lookbehind` | `behind` | Positive lookbehind under the existing text-context contract. |
| `negative_lookbehind` | `notBehind` | Negative lookbehind; matching errors remain errors. |
| `fullmatch` | `wholeMatch` | Return Maybe of a Match covering the entire source. |
| `eachmatch` | `eachMatch` | Iterate selected matches with the existing zero-progress rules. |
| `greedy` | `extendFirst` | Try repetition extension before accepting a shorter candidate. |
| `reluctant` | `stopFirst` | Try stopping repetition before extending it. |

The three added names are `splice`, `hasPrefix`, and `hasSuffix`. In particular, the rename is applied to the old target-returning `splice` before the new removed-result operation is introduced. They are distinct contracts, not two versions selected implicitly.

## 1. Sequences and mutation

| Operation | Mutation and result |
| --- | --- |
| `replaceRange(target; begin; end; values)` | Replace `[begin,end)` with the immediate insertion values; return the **same target descriptor**. |
| `splice(target; begin; end; values)` | Perform the same replacement; return a **fresh outer container of the removed pre-write elements**. |
| `append(target; values)` | Insert at the original end; return the same target. |
| `insert(target; position; values)` | Insert a sequence at one position; return the same target. |
| `deleteAt(target; begin; end)` | Remove the explicit half-open interval; return the same target. |

All five entrances share one mutation algorithm. Bounds, final size, and dense-target element admission are checked before mutation. Overlapping insertion values and any removed-result snapshot are stabilized before a write or resize can change them. Commit invokes no user converter or callback. Actual-evaluation effects and resource failures retain the existing failure rules; no general transactional rollback is added.

The new `splice` result preserves the target's actual element requirement and storage profile: dense T[] yields fresh dense T[], while Structure/@[] yields fresh @[] containing the original record references. It is a shallow snapshot: reference identities and actual lexical parents remain unchanged. Replacing a result slot does not replace a target slot; mutations of a shared referenced object remain shared. An empty removed interval yields an initialized empty container of that same profile. `replaceRange` need not allocate an unused removed-result container.

The exact word `replaceRange` occurs in [Kotlin's text API](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.text/replace-range.html); those String/CharSequence functions return replacement text. Swift's related mutating array operation is named [**replaceSubrange(_:with:)**](https://developer.apple.com/documentation/swift/array/replacesubrange%28_%3Awith%3A%29), and returns Void. Neither is claimed to have LMX's same-target return contract. Julia's range form of [splice!](https://docs.julialang.org/en/v1/base/collections/#Base.splice!) provides a familiar removed-elements result; [Perl splice](https://perldoc.perl.org/functions/splice) returns removed elements in list context and has a different scalar-context result. LMX always returns the specified removed container and uses its own half-open interval.

Other established contracts remain visible. `insert` accepts a sequence, not just one item; `deleteAt` takes an interval, not an arbitrary index set. `compress` requires equal source/mask lengths. `index(items; accepts)` returns Maybe of the first accepted physical index, including index 0, rather than a negative sentinel. The names `any`, `all`, `index`, `count`, `append`, `insert`, `reverse`, and `compress` are unchanged in this revision.

## 2. Patterns and source profiles

`oneOf`, `noneOf`, and the unchanged `satisfy` have direct spelling analogues in [Haskell Parsec](https://hackage-content.haskell.org/package/parsec-3.1.18.0/docs/Text-Parsec-Char.html). The other approved pattern spellings state their LMX operation directly. This table does not claim that `sameAs`, `extendFirst`, or `stopFirst` are literal names of Perl regex functions. Foreign examples retain real APIs such as Python `re.fullmatch` and Julia `eachmatch`.

Boundary predicates accept a Pattern or an explicitly admitted literal-source role. Text literals remain text and are not parsed as regex syntax. Array sources expose whole typed elements under their explicit profile.

| Receiver | Result and acceptance condition |
| --- | --- |
| `hasPrefix(source; pattern)` | int 1 iff a candidate starts at source position 0; consuming the whole source is not required. Otherwise 0. |
| `hasSuffix(source; pattern)` | int 1 iff a candidate at some valid start ends at the source end. Otherwise 0. |
| `wholeMatch(source; pattern)` | Existing Maybe of a Match beginning at 0 and ending at the source end. |
| `matches(source; pattern)` | int 1/0 for the same whole-source condition. |
| `contains(source; pattern)` | Existing int 1/0 for a match anywhere. |

For `hasSuffix`, all relevant candidates and overlapping starts remain eligible. On `ab`, `literal("a") | "ab"` has a suffix match even though the first candidate at start 0 ends early. On `ababa`, literal `aba` has a suffix match starting at 2, even if a nonoverlapping iterator selects the earlier match at 0. A final `find`/`eachMatch` result is therefore not the definition of suffix testing. Empty-pattern matches at the appropriate boundary count; empty source follows the same rules. The matcher retains the full source context for anchors and lookaround, and matching errors remain errors rather than 0.

`replace(source; pattern; replacement)` produces a **new source-profile value**; it does not mutate source. Text keeps its encoding, and Array output keeps the specified element/result requirement. `replaceFirst` retains its explicit one-match limit. Sequence interval mutation has the separate names `replaceRange` and `splice`. Pattern construction and calls continue through ordinary methods and the established Expression operand protocol, with no new parser or callable ABI.

## 3. Functional families and shared comparison

The canonical binding operation is `bind` for Maybe, Result and sequences.
Scala's `flatMap` and Java's [Stream.flatMap](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/stream/Stream.html#flatMap(java.util.function.Function))
are foreign APIs, not retained LMX aliases. Sequence binding remains eager and
flattens one level. Maybe and Result preserve their terminal containers, exact
result types and callback failure contracts.

`groupBy(items; keyOf := 0; sameKey := 0)` groups by the whole current element
by default. A supplied projection runs once per element; a supplied equality
consumes whole keys. Groups and members retain first-occurrence order.
`groupAdjacent` remains the distinct consecutive-run contract; neither operation
silently takes another language's ordering policy.

`unique` and `equalFields` accept optional `same=0`. The shared default compares
actual scalars and recursively compares finite acyclic sequences. The sole
paired range traversal also serves search, Pattern literals and backreferences.
No separate text-equality loop, hidden case folding or identity shortcut changes
the selected relation.

## 4. Mixed-case names retained after review

| Names | Reason to retain them |
| --- | --- |
| `zipWith` | Recognizable Haskell name; no unrelated spelling change is introduced. |
| `->` | Constructs a signature with result last; `signature` and `types` retain reflection roles. |
| `bindFields` | DATA-field binding; container binding has the unified name `bind`. |
| `runUntil`, `retryCall`, `retryPost` | Keep repetition policy, declared-failure retry and Message retry distinct. |
| `composeData` | DATA-overlay operation; `compose` constructs callables and `pipe` applies stages. |
| `within`, `boundaryOf`, `utf8Text`, `byteText`, `matchAt` | Keep order, boundary, encoding and position contracts explicit. |
| `matchedSpan`, `matchedValue`, `captureSpans`, `lastCapture`, `captureValue`, `captureValues` | Distinguish source-backed spans from materialized values, one capture from history. |
| `replaceFirst`, `atLeast`, `atMost` | Preserve the explicit limit or count bound. |
| Ready `ascii*` and `line*` Pattern values | These are explicit text profiles, not limits imposed on the shared engine. |

Models and failures such as `Pattern`, `RxPreparedSource`, `ArrayView`, `TextView`, `Match`, `Span` and `PatternEncoding` are separate from callable names. Internal helper and kernel-bridge names are outside this public rename table. No additional automatic lowercasing is authorized by it.

## 5. Application and verification

The live inventory is the common catalog. Symbolic and word operations share ordinary canonical-name lookup and role-aware lowering; ready values and declared failures are listed separately.

Apply the approved map once to current LMX declarations, references, exports, catalogs, normative documentation, examples and alternatives, fixture descriptions, and publication inputs. Keep actual foreign-language API spellings. Any preserved historical source is explicitly identified as historical; current main examples use canonical LMX names. Current source forms use `T[]: array` and `Struct@: ptr` where the type requirement belongs in the declaration head; a universal `@: ptr Model` refers to Model itself and does not supply a hidden type annotation.

Statistics are regenerated from current main listings after selecting the shortest eligible complete variant. A rename cannot make a different task eligible for comparison. PDF, XLSX, CSV, JSON, and Markdown totals are rebuilt from that selection. Source, link, and publication checks do not assert LMX kernel execution; runtime acceptance remains explicitly separate.
