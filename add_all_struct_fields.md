## 1. Один заголовок и общие массивы

Плоская L2-запись:

```lmx
struct: Lmx
    @: parent Lmx
    size_t: length
    @: storage void
```

Убрать вложенный VoidArray и native из заголовка. Capacity тоже не добавлять: резерв в элементах
хранится в таблице арены «адрес дескриптора → capacity». Адрес Lmx-дескриптора сохраняется при
изменении размера, storage может перемещаться.

Structure и Array<@> полностью взаимозаменяемы при одинаковом содержимом: индексирование,
именованные пути, length, implements, копирование/merge, исполнение, typeof, descriptor.
Оба хранят void *; числовой Array<T> хранит непосредственно элементы T. Parent у массивов остаётся.
Никакого отказа только из-за метки STRUCT/ARRAY.

Все массивы имеют переменную длину. Общий allocator/resize обслуживает Structure, Array<@>,
типизированные и служебные массивы. Отдельный List/DynamicArray с собственным capacity не нужен.
Стабильные отдельные ячейки примитивов и канонические строки сохраняют свои адреса; не создавать
Array-дескриптор на каждую такую ячейку. Это общий механизм выделения, не требование перемещать всё.

В L2 [], [][], [][][] любого конечного ранга — вычисление offset. Array[-1] допустим.
Чтение, запись и адрес используют общий расчёт без length/sign/arena/бывших-полевых проверок.
В L3 соседние индексы сводятся к одному линейному индексу, затем одна проверка 0 <= index < length.
Переход a[i]\[j] между отдельными массивами — другой случай; не создавать скрытые строки-дескрипторы.

У L3 собственные указательные типы. Ссылка на элемент массива хранит ссылку на сам Array-дескриптор
и index, не storage; после resize storage читается из того же дескриптора.
Указатель на примитив — свой тип L3 на общей типизированной основе, с использованием имеющегося
задела uninit:T там, где он подходит. Не смешивать отсутствие значения с видом указателя.
Обычные сырые указатели L2 после перемещения storage автоматически не исправляются.

## 2. Ресиверы и descriptor

| Ресивер | Результат/эффект |
| --- | --- |
| parent(S) | Значение parent из заголовка |
| length(S) | Значение length из заголовка |
| sys\storage(S) | Значение storage из заголовка |
| sys\native(S) | Обычная Structure native-дескриптора с вариантами из таблиц call либо 0 |
| sys\capacity(S) | Резерв из таблицы арены |
| sys\descriptor(S) | Structure с тремя адресами настоящих полей заголовка |
| sys\resize(S,n) | Меняет length, обеспечивает нужное хранилище общим allocator |
| sys\reserve(S,n) | Меняет резерв, не length |

У первых шести форм без аргумента выбирается текущая data, включая вложенные тела управления.
Для code нужен явный аргумент. Простое чтение не строит descriptor; capacity не ищется на каждом
индексном доступе. Ресиверы выполняются в code, одноимённая запись в data остаётся обычными данными.
data/code остаются аргументами-Structure call, node не меняется.

Результат sys\descriptor — обычная Structure с указателями:

```lmx
(
    @@: parent Lmx
    @: length size_t
    @@: storage void
)
```

Машинные типы: Lmx **, size_t *, void **. Если d — результат, \(d\length) := n меняет S.length,
а d\length := p меняет указатель в самом d. Запись в length сама не выделяет storage;
для согласованного изменения размера служит sys\resize. Native/capacity в результате descriptor нет.
Никаких прокси, отражающих lvalue, скрытых setter, копии заголовка или обратной синхронизации.

Явные struct\field и типизированные разыменования не ограничиваются запретом присваивать по голому
имени Structure/callable. Они используют общий типизированный путь. S[n] := p — сырая запись void *;
S\[n]field — именованный путь с контрактом поля. Повторы имён сохраняются.
sys\indexof(field parent) требует единственного вхождения ссылки; sys\indexof(field index parent)
выбирает указанное с нуля вхождение и возвращает физическую позицию. Отсутствие/неоднозначность —
ошибка явного поиска. Обратной индексной таблицы не нужно.

## 3. Native-дескрипторы и прямые вызовы

Основное хранилище native-дескрипторов всех компилируемых Structure — таблицы ресивера call
в арене Thread. Дескриптор — обычная Structure: реальные сигнатуры/варианты, модуль и имя машинного
входа, пути к исходникам L1 и C. Одна Structure не ограничена единственным native-адресом.

При трансляции fn/sub/catch отсутствующее обычное поле native добавляется в чистый граф
со ссылкой на тот же дескриптор из таблиц call. Другим Structure поле автоматически не добавляется.
Общий выпуск методов и обычных Structure не требует data=code. Реальные вызовы определяют
C-сигнатуры; заголовок без code описывает вызов.

Известный native вызывает известный native прямо в C: обычные параметры и необходимые скрытые
аргументы связывания. Не строить графовый кадр, универсальные Value-обёртки и поиск/trampoline
только ради такого вызова. Явно написанные обращения программы к data/code сохраняются.
Динамический call ищет вариант по цели и реальной сигнатуре.

## 4. Явная компиляция и sys\endturn

sys\compile(S) — построение и проверка чистого графа без исполнения программы, трансляция в L1,
затем C, машинная компиляция/связывание и регистрация успешных результатов в таблицах call.
Вернуть диагностики, ошибочный результат не устанавливать. sys\translate(S) остаётся переводом
в текст L1 с errors; L1 не является LMX.

Записи в граф ничего не аннулируют автоматически. Удалить отслеживание правок полностью:
проверки, обратные связи, code_uses, reset-only таблицы/переносы, ветви генератора и устаревшие
тестовые ожидания. Проверить lmx_graph_invalidate_prepare/finish/invalidate и reset-only части
lmx_code_* / reset_gen. Общие ссылки/GC/типизированное хранение сохранять по их собственной задаче.
Не заменять это журналом, версиями, проверкой хешей на endturn или автоматическим восстановлением.

Если скомпилированная A прямо вызывает B, сборка только B не меняет вызов внутри A.
Явно компилировать общую единицу с нужными вызывающими/вызываемыми. Не вводить отдельную систему
автоматического отслеживания обратных зависимостей. Произвольная порча графа не требует ремонта.

sys\endturn() — системный выход из вложенных вызовов через зарегистрированные finally в обратном
порядке к обычной границе такта. Catch не перехватывает; возврата к месту вызова/продолжения стека нет.
Сам ресивер не меняет running/success и не завершает Message; следующий назначенный такт — обычный вход.
Использовать общий cleanup/exit механизм, не изображать endturn аварийной остановкой.

До границы момент применения правки исполняемого графа не гарантируется. Обязательное копирование
code при входе отменяется полностью, включая прежнюю копию лишь кода C-функции.
Независимость выбранных локальных значений/описаний сохраняется. После успешной явной компиляции
и endturn следующий вход использует подготовленное обновление. Один endturn не обнаруживает правок,
не проверяет/не компилирует граф и не публикует локалы. Старые native-кадры/finally завершаются
до освобождения их машинного кода.

## 5. Сохранение Thread и восстановление

sys\toLmx(S) сохраняет выбранную структуру. Если S — L3 Thread, сохраняются также все таблицы его
арены, включая call/native. Таблицы принадлежат арене, а не полям R0; R0 — только частный Thread.
Внешние таблицы не добавляются скрыто к любой произвольной S.

Codec сохраняет порядок полей, нулевые слоты, sharing/циклы, имена, типизированные значения и
связи с native-дескрипторами. После перезапуска на той же платформе восстановить чистый граф
с готовыми ABI-совместимыми бинарниками без трансляции заново. Сохраняются модуль/символ/пути,
а не числовые адреса прошлого процесса. Резерв capacity можно восстановить как length;
если резерв не записан, это не меняет содержимого массива.

## 7. Порядок кодинга и документация

1. Общая физическая основа parent/length/storage + arena capacity; перенос потребителей, allocator/resize,
   взаимозаменяемость Structure/Array<@>. Затем общий сырой L2 offset и L3 reference/check.
2. Таблицы call в арене, обычные native-дескрипторы/поля fn/sub/catch, реальный прямой native→native.
3. Явная компиляция, удаление всей reset-инфраструктуры, sys\endturn через существующий cleanup.
4. Codec выбранного Thread с таблицами арены и повторным подключением готовых бинарников.
5. Согласовать источник provenance/semantics-book.md и штатно пересоздать RU/EN; L1/L2, kernel,
   руководство, CORE, to_sol и основной v3/checklist должны описывать одну модель.

Проверки и построение чистого графа сначала реализовывать в сборщике под реальные задачи.
В runtime переносить только нужный работающий общий код, когда есть конкретный потребитель;
не создавать заранее второй builder, универсальные обёртки и дополнительные состояния.
Оптимизацию ядра выполнять сразу там, где общий механизм очевиден.

Приёмка соразмерна: короткие языковые случаи на сырой отрицательный L2-index, единую L3-проверку,
resize и descriptor-reference, прямой C-вызов, отсутствие скрытого reset, явную компиляцию/endturn
с finally и сохранение/загрузку Thread с готовым бинарником. По мере переноса самосборки использовать
языковой test. Старые PASS не объявлять доказательством новых контрактов; не строить отдельную
инфраструктуру тестов и проверок «на будущее».
