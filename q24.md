# Q24. Повторное типизированное объявление одного имени в одном теле

Состояние: 2026-09-25, **закрыт автором: A** («на этот механизм уже вся next_core_tasks.md переписана, мы только недавно поменяли на lastIndex по умолчанию (было 0)») (Sonnet -164: правило «неуточнённое имя = последнее вхождение» проведено по 22 местам транслятора, но программа-пример не транслируется).

## Измерено (`c2831dc` + Sonnet -164)

`l2_own_add` отказывает «duplicate declaration» на второе `int: arg` в одном теле (правило 4 из S2 -112, Opus: «Duplicate typed declaration in one scope is refused universally» — принято координатором без автора). Повторное вхождение own-поля сегодня возникает ТОЛЬКО по правилу одноимённой привязки аргумента (формал, переприсвоенный по имени — `test\[N]arg`, -146). Книга (§fields): «Повторные исходные имена сохраняются… `[1]name` — второе вхождение»; автор (Q19.2): объявления — операторы на своём месте, заново инициализируют ячейки при каждом исполнении; Q22.2 = A: неуточнённое имя = последнее — общее правило.

## Минимальная программа

```text
fn: test () int
    int: arg 1
    int: arg 2
    return: 0
end: test

test()
7
return
```

- **A (книга):** второе `int: arg 2` — второе вхождение того же имени: `test\[0]arg` = 1, `test\[1]arg` = 2, `test\arg` = 2 (последнее). Правило 4 S2 отменяется; отказ «duplicate declaration» уходит.
- **B (код сегодня):** повторное типизированное объявление в одном теле — отказ «duplicate declaration»; вхождения множатся только правилом привязки аргумента (`fn: test (int: arg)` + `arg: 2` → `[1]arg`). Тогда книгу надо сузить: «повторные имена возникают из переприсваивания формала по имени».

Рекомендация: **A** (книга и Q19.2 уже так читаются; отказ — самодельное правило S2).

## Уточнение автора (2026-09-25)

«главное чтобы так можно было сделать и `(int: x 1; char: x (x + 2))` читался правильно». Семантика: повторное объявление допустимо и с другим типом — новое вхождение своего типа; внутри тела голое имя в выражении — последнее вхождение, объявленное до текущего оператора (инициализатор второго `x` читает первое: 1 + 2 = 3, и лишь затем возникает `[1]x`); снаружи `test\x` — последнее вхождение. Программа-свидетель для D-48: `int: x 1` / `char: x (x + 2)` → `test\[0]x` = 1, `test\[1]x` = 3, `test\x` = 3.

## Уточнение автора 2 (2026-09-25)

«главное разрулить это в трансляции так как в Си такое невозможно прямо …»: транслятор даёт каждому вхождению свою C-ячейку (как сегодня `l2_qN`/own-слоты); значение другого типа идёт через абсолютную конвертацию с валидацией (порт §7 «implements + конвертеры» из `lingvamyxa_prev`, спека §2.2.3/§2.2.4), в интерпретаторе — тем же конвертером-приёмником; C-каст не используется. До посадки порта конвертеров разнотипный инициализатор — локализованный отказ «conversion int→char: converters not ported yet (§7)», однотипные повторы — полностью.
