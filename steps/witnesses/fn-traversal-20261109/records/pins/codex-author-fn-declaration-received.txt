«"структура с безымянным словом int  " -- что за "безымянное слово int" ? int это ресивер который называется "int". fn это ресивер fn. Причем тут int? Вы захардкодили int туда? РАЗБОР CODEX (не новая цитата):

Ошибка: Мы смешали исходное объявление ресивера fn с созданным значением функции. Исходное дерево должно сохранять именованную структуру fn и полный контракт: name, args, return, var, body; аргументы допускают обычное именование.

При обходе ресивер применяется и в namespace создаётся name с args/return/var/body общим правилом, как int создаёт i.

int и fn — именованные ресиверы, не требующие специального merge. Не выводи язык из int-подмножества.

КОНКРЕТНЫЕ ОШИБКИ:
1. lm_graph_build_method: убирает аргумент name и добавляет fn как поле0 — ОШИБКА
2. lmx_graph_method: распознаёт жёсткое пять-полейное представление — ОШИБКА
3. kernel RU/EN §3.4 документирует эту ошибку прямо
4. lmx_graph_call_shape требует result с w_int и отказывает другому — жёсткая граница реализации, не норма

Новая модель: no hidden prepared representation между обходами. Namespace временный, каждый обход чист, исходный граф достаточен обоим потребителям. Создаваемые значения — обычные сущности Lmx по общим правилам.
