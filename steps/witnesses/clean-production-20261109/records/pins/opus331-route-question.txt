Измерение первой границы существующей командой `G50 0 entry 0 -- run S/<unit> 1` (CWD P/runs/opus331, логи P/pins/opus331-probe-*.log) на staged production-входах:

- lmx_schedule, tools/docs_check, tools/text, tools/winargs: `graph: build answered 2`. Минимальные ручные источники изолируют границу построителя: указательный формал `@: s T` в сигнатуре (`@: s c.LmxSchedule`, `@: s char`) — lm_graph_build_method требует у формала-Frame ровно [тип, имя] (l2_graph_tool.lm2, цикл после lm_graph_build_fields); `ulong:`/`size_t:` формалы, fn без `end:`, `---` и комментарии в теле принимаются.

Наблюдение: эти входы нашего pipeline — машинные модули, которые build-runtime переводит старым фронтендом F (bld_kernel_l2 → bld_machine_module → l2trans --library --machine, L2 §20). Их тела — код C-двери: c.GetTickCount64(), c.stdout, запись полей C-struct через указатель (`slot\owner: owner`), константы c.LMX_SCHEDULE_*. Интерпретатор чистого графа такие тела исполнить не может, а эмиттер чистого графа выпускает графовую программу (вход LmxEntry, int-результаты по ячейкам), не машинные функции C ABI. Образец цели — F-выпуск S/src/l2src/lmx_schedule.lm1 (prototype-блок, сигнатуры `@: LmxSchedule l2_p0_0_slot; ... ulong: ...`, `l2_p0_0_slot\owner: l2_p0_2_owner`, `return: c.LMX_SCHEDULE_OK`).

Предлагаемый маршрут для «source → Lmx → emission» реального входа (kernel §7, §11 п.3; S8.4):
1. построитель: указательный формал `@: name T` как место-ссылка формала; корневые `include:`/`predef:` — объявления C-двери, которые стоят в интерпретаторе и переносятся в выпуск;
2. режим машинной эмиссии над чистым графом (graph_trans, тот же контракт имён экспорта/заголовка, что у bld_machine_module), первым — lmx_schedule; проверка: выпуск из чистого графа против F-выпуска того же модуля, его C-компиляция и сборка rt с этим модулем от чистого пути (рецепт берёт производителя модуля по поколению: G предыдущего поколения, как tool строит tool);
3. дальше модуль за модулем по kernel-списку bld_kernel_l2 от малых (lmx_clock, lmx_manager_running_lane, lmx_chars_owned …), с удалением F-маршрута для перенесённого модуля.
Альтернатива — корень программы tools/lmxtool.lm2/graph_trans.lm2 (include, Array массивов char, корень Message с receiveMessage/sendMessage, C-дверь): блокеров заметно больше (почта, Array, char, C-дверь в интерпретаторе).
