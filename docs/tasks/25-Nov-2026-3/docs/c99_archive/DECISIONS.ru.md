# Решения о составе архива

Дата снимка: 2026-11-25. Точный состав, версии, URL и пути к лицензиям
зафиксированы в [SOURCES.json](../../third_party/lmx_c99_compact/SOURCES.json).
Таблицы ниже объясняют отбор; [каталог](CATALOG.ru.md) описывает каждый
компонент, а [матрица форматов](FORMAT_MATRIX.json) — конкретные направления
чтения и записи.

## Принятые пополнения

| Группа | Библиотеки | Полученная возможность |
|---|---|---|
| Носители и компактные данные | littlefs, FatFs, SPIFFS, FlashDB, heatshrink, QCBOR, TinyCBOR | Файловые и секторные форматы, потоковое сжатие, два независимых CBOR API |
| Управление и локальная связь | Fusion, libfixkalman, PID, libcanard, nanoMODBUS, coreMQTT, lwIP | Обработка IMU, фильтрация и регулятор; Cyphal/CAN, Modbus, MQTT и IP stack |
| Специализированные алгоритмы и форматы | PCRE2, libLBFGS, libdmtx, libtiff, libxls, matio | Регулярные выражения, оптимизация, Data Matrix, TIFF/BigTIFF, старый XLS, MAT4/5 |
| Научные вычисления | liblsoda, ERFA | Жёсткие и нежёсткие системы ОДУ; астрономические координаты, время и преобразования |
| Документы | PDFio | Чтение/запись PDF objects и streams, metadata и копирование страниц |

Повторяющиеся возможности сохраняются намеренно. Например, CBOR API и flash
filesystems предлагают разные требования к памяти, модель работы и точки
интеграции. Замена одного другим требует проверки представления и поведения,
а не только совпадения имени операции.

## Размер: строго меньше миллиона байт

Для новых библиотек действует предел **1 000 000 байт**, не 1 MiB.
Это верхняя граница, а не желательный бюджет: подходящий по формальным
признакам код включается только тогда, когда его возможности оправдывают
размер. Для узкого или малополезного этому снимку формата допустимый расход
может быть существенно меньше.
В [SIZES.json](SIZES.json) отделены исходники, статические архивы объектов
и размер полного собранного библиотечного профиля. Для всех 23 принятых
добавлений уже полный `.a` выбранного профиля меньше предела. Маленькая
демонстрационная программа сама по себе не доказывает размер всей библиотеки.

Числа относятся к конкретной проверенной конфигурации GCC/Linux x86_64.
Размер на другой ISA и с другими возможностями нужно измерять заново.
Зависимости и общие компоненты перечислены отдельно. Сумма `.a` не является
измерением размера финального ядра LMX или его оперативной памяти.

**HDF5 исключён по подтверждённому пользователем пределу размера.** Проверен
C99-профиль HDF5 1.14.6: serial C, без C++/Fortran, утилит, parallel/threadsafe
и полного high-level слоя. Даже проверочная программа чтения/записи после
LTO и удаления символов занимала 2 087 336 байт. Исходники HDF5 и отдельный
добавочный архив в поставку не включены. Поэтому нет netCDF-4/HDF5 и
MAT7.3/HDF5. MAT4/5 поддерживаются отдельным профилем matio.
Источник проверки: <https://github.com/HDFGroup/hdf5/tree/hdf5_1.14.6>.

**netCDF classic также исключён по решению пользователя.** Проверенный профиль
netCDF-C 4.10.1 для CDF-1/2/5 укладывался в формальный предел: полный shared
library после удаления символов — 848 352 байта, без удаления невызванных API
и без LTO при линковке. Очищенное дерево исходников занимало 8 216 588 байт.
Для задач этого снимка пользователь не считает classic-возможности
оправдывающими такой расход; вариант порядка 50 КБ имел бы иной вес при
отборе. Это решение о составе и полезности, а не утверждение, что эти форматы
вообще нигде не используются. Исходники, target и зависимости netCDF
в поставку не включены. Источник проверки:
<https://github.com/Unidata/netcdf-c/tree/v4.10.1>.

Исходные 132 компонента сохранены как предыдущая проверенная подборка;
их прежние профили не выдаются за заново прошедшие новый порог размера.
Например, некоторые их статические архивы больше миллиона байт. Фактические
размеры этих профилей также присутствуют в общем отчёте.

## Граница назначения

- Lua, Wren, Duktape, Perl и другие самостоятельные общие языковые среды
  не добавляются. LMX остаётся языком программирования и моделью данных.
- SLJIT, PCRE2 и другие специализированные механизмы допустимы независимо
  от того, какие языки или приложения используют их upstream.
- llhttp нужен как HTTP parser. CivetWeb и аналогичный готовый сервисный
  lifecycle не подменяют механизмы, управляемые из LMX.
- JSON и другие внешние форматы нужны для совместимости. YAML/TOML/INI
  не предлагаются как способ расширять или определять сам LMX.
- Сохранённые примеры с `main()` служат обучению API. Они не становятся
  обязательными демонами или сервисами будущей системы.

| Компонент | Изменение | Основание и проверка |
|---|---|---|
| PID | Исправлен один знак feedback в производной через отдельное представление исходника для сборки | Регрессионный ramp test воспроизводит неверное установившееся значение исходной реализации; ramp/step проходят после исправления. [Подробности](../../third_party/lmx_c99_compact/extensions/control_extra/PID_FIX.md) |
| matio | Внутренний `Add` получил имя `lmx_matio_Add` | Устраняет конфликт с NNoM, не меняет публичный `Mat_*` API |
| Zstd | Внутренние `divsufsort`/`divbwt` получили префикс `lmx_zstd_` | Сохраняет встроенную и отдельную реализации с разными сигнатурами; совместный [пример](../../third_party/lmx_c99_compact/examples/archive/suffix_zstd.c) проверяет обе |
| liblsoda | C99-форма диагностических macros и исправленная граница выделения памяти в printf helper | Hash guards исходных фрагментов; decay/stiff Robertson/printf tests |
| Другие новые адаптеры | C99-совместимые объявления/конвертеры, выбор производственных translation units и платформенных headers | Изменения описаны в README/VERIFICATION соответствующей группы; upstream vendor inputs сохраняются отдельно от генерируемого представления для сборки |

Подробные результаты отдельных групп находятся рядом с их CMake-файлами.
Механическое прохождение компилятора не считается доказательством
семантической правильности: где найден реальный риск, добавлен пример,
который воспроизводит исходную ошибку или проверяет нужную цепочку API.

## Известные ограничения и отсрочки

**PDFio:** обычные metadata, страницы, Flate, копирование страниц и ограниченный
AES-128 roundtrip прошли проверки. У зашифрованного PDF чтение CreationDate
возвращает `0` вместо записанного `1700000000`. Сохранён отдельный воспроизводящий
тест, явно помеченный `KNOWN_FAIL`; он не превращён в успешный тест и не включён
в число прошедших проверок. См. [ограничения PDFio](../../third_party/lmx_c99_compact/extensions/pdf_extra/KNOWN_LIMITATIONS.md).

**UDUNITS-2:** подходящий по назначению и размеру код пока не включён.
Эксперимент с byacc вместо Bison менял error recovery: некорректное выражение
вызывало повторное освобождение памяти. Контрольный Bison-вариант эту проверку
проходит; общего дефекта UDUNITS этим не установлено.
[Запись решения](UDUNITS_DEFERRED.md) сохраняет конкретное условие следующей
попытки, без непроверенного target в рабочей сборке.

**Лицензии:** новые добавления имеют сохранённые permissive notices.
В унаследованной подборке два прежних исключения — `tensors:mint` и
`micro_mlp:afan_neural_network` — остаются `NOASSERTION`: отсутствие найденной
лицензии нельзя переименовывать в MIT или public domain. Эти записи выделены
в каталоге. Лицензия интеграционных файлов не заменяет лицензии vendor-кода.

**Переносимость и оборудование:** проверенная платформа — Linux x86_64.
Платформенные ветви сохранены, но Windows/macOS, конкретные MCU, реальные
flash power-loss сценарии и быстродействие на процессоре 100–200 MHz
в этой работе не измерялись. RAM-модели и loopback проверяют программные
пути, а не физическую надёжность устройства.
