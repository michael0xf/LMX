# The idiom `@: shared data[0]` of R0 is translated (slice M1 of step 21.7)

Written 2026-11-23 by Fable, the coordinator and the single writer of main. Slice M1 of step 21.7 of the plan
section `next_core_tasks_v3.md#docs-20261121`. The rule, the scripts and the census are by the peer session opus;
Fable decided that the programs are translated before the kernel slice (the executor's answers Р145 and Р147 in
`LMX_blog/q/fable-self-answers-20261110.md`), found that the first form of the rule does not hold on the accepted
set, applied the second, compared the files with the helper's hashes and ran the whole list of witness rows.

## The norm

- The special meaning of the name `data` is withdrawn; a former path `data\x` is replaced with an explicit path
  to the intended Structure ([what is withdrawn](../../../docs/spec/LMX_semantics.en.md#removed-builtins)).
- R0 has no DATA and nothing compensates for it ([R0](../../../docs/spec/LMX_semantics.en.md#root-entry)).
- `node` starts in the lexical space above the selected method. Above R0 there is none, so `node` has no target
  in the code of R0; in a method declared at the root it starts at the root.

## The rule

- The line of R0 `@: shared data[0]` is removed.
- Every vertical body of a root-level `fn` or `sub` that uses `shared` gets `@: shared node[0]` as its first
  line (after the closing parenthesis of a header continued on the following lines).
- The expected dump changes the same way: the root line `@: shared (data [] 0)` is removed and the bodies get
  `@: shared (node [] 0)`.
- The rule applies where `data` at R0 occurs only in the idiom, `shared` is used only in vertical bodies or
  nowhere, and no callable whose body uses `shared` is run through `X\code`.

A first form of the rule replaced `data` by `node` in the records of R0 itself. On the accepted set
`@: shared node[0]` in the code of R0 answers 3; that is what the norm gives, and the kernel is not changed to
make `node` name the root at R0.
