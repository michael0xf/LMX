# Именованные фактические обычного вызова (книга §10, :1060)

Строка плана — `next_core_tasks.md`, «Именованные фактические обычного вызова». Норма — книга :1060: «Positional actual
arguments precede named ones. After the first named argument, subsequent arguments must also be named. An unknown name,
duplicate assignment to one argument, missing required argument or ordering violation is an error. A named argument's
body is supplied as a structural value when that is the receiving expression's specified mode; it does not become an
arbitrary sequence of immediate calls.»

## 1. Замер (Opus, 2026-09-28, на `d4196be`)

- **Как читается вызов.** Обычный вызов привязывает фактические по позиции: проверка (`l2_check_call`), подготовка и
  эмиссия (`l2_prep`, `l2_emit_call`), обход (`l2_rw_call`) и скан свободных имён (`l2_scan_node`) — все идут по полям
  тела вызова и делят их на фактические через `l2_expr_span`. Именованное фактическое понимается только в виде
  `Name: ()` (D-23, `l2_named_empty_actual` — семь мест). Любое другое `f(a: 8; b: 1)` отказывает: «unknown method»,
  frame=a. Кадр `a: 8` читается как вызов `a`.
- **Как это выглядит в P0** (printTree). `f(a: 8; b: 1)` — кадр `f`, тело `[кадр a (8), кадр b (1)]`. `g(x)` и `g: x` —
  одно дерево: кадр `g` с телом `[x]`. `f(x + 1, -1)` — плоско: `[x, +, 1, -1]`, где `-1` — один атом. А `f(x, - 1)` —
  `[x, -, 1]`, одно фактическое `x - 1`.
- **Общие ворота привязки уже есть.** Это `l2_bind_actuals`, которым привязывает свои фактические ресивер `table`
  (`steps/table-receiver.md` §5). Слова отказов — книги: аргумент дважды, имя не формала, позиционное после
  именованного, больше позиционных, чем формалов, формал без фактического.
- **Как читается вызываемый.** `l2_call_head_method` (D-106): сначала callable-формал вызывающего метода (контракт —
  его формалы), затем метод по имени или по пути (`A\M` — метод поля-ссылки).

## 2. Механизм

Один проход до всех остальных — `l2_bind_calls`, первым шагом `l2_parse_unit` и `l2_parse_library`. Он читает тело
каждого метода (E и процедуры именованных Structure включительно) и `return`-trailer, а тела вложенных методов — как
их собственные. У каждого кадра, чей заголовок `l2_call_head_method` читает как вызываемого, фактические привязываются
`l2_bind_actuals` к формалам вызываемого. Порядок формалов:

- все фактические позиционные и по порядку — вызов остаётся как написан (дерево не трогается);
- есть именованное — тело вызова переписывается в порядке формалов: у позиционного — его поля как написаны, у
  именованного — тело его кадра;
- `name: ()` — P0 сплющивает единственную `()`, у кадра нет полей — даёт пустую Structure (узел Structure без полей).

**Тело именованного аргумента — одно значение** (книга). Переписанный вызов читается назад по `l2_expr_span`, и каждое
фактическое обязано быть одним фактическим своих полей. Тело, которое при позиционном чтении стало бы несколькими
(`p: 1 2`) или склеилось бы с соседом (`b: - 1` после `a: x` даёт `x - 1`), хранится целым — одной Structure.

Так все проходы видят позиционный вызов. Отдельной ветки для именованных у проверки, эмиссии, обхода и скана нет.

**Следствия.**
- *Заголовок-формал.* Кадр среди фактических, заголовок которого называет формал вызываемого, — аргумент этого формала,
  что бы ещё ни называло это имя: P0 не различает `g(2)` и `g: 2` (свидетель `unit_named_actual_formal_name`).
- *Слова арности.* Число фактических у вызова метода проверяют ворота. Прежние «incompatible entry signature» за
  лишние или недостающие фактические становятся словами книги («more arguments than f has formals», «f has no
  argument b»).
- *D-23 обобщён.* `l2_named_empty_actual` (кадр `x:` без полей среди фактических) стал `l2_empty_actual` — пустая
  Structure позиционно для формала Structure-типа. Особой формы именованного больше нет: `take(x: ())` после привязки —
  та же пустая Structure на месте `x`.

## 3. Итог (Opus, 2026-09-28)

**Строки харнесса** (новые; все — в обоих режимах, кроме строки callable-формала — он вне обходимого подмножества,
как `unit_callable_anon`):
- `unit_named_actuals` и обходимый двойник: `f(a: 8; b: 1)`, `f(b: 1; a: 8)`, `f(8; b: 1)`, `f(a: x; b: 0 + 1)`,
  тот же вызов из метода и вызов, привязанный внутри аргумента, `f(b: 1; a: f(b: 1; a: 9))` — все 7;
- пять отказов ворот словами книги: аргумент дважды, `c` — не аргумент, позиционное после именованного, `f has no
  argument b`, «given by position and again by name»;
- `unit_named_actual_formal` — `op(x: value)` по формалу контракта;
- `unit_named_actual_path` — `A\M(v: 4U)`;
- `unit_named_actual_formal_name` — `f(g(2))`, где `g` и метод, и формал `f`: `g` получает 2 (12, не 40);
- `unit_named_actual_whole` — `f(a: 8; b: - 1)` = 9: тело `b` хранится целым (по позиции `f(8, - 1)` — это `f(8 - 1)`).

**Иглы, сменившие слова** — отказы арности говорят ворота, у лишнего фактического или у вызова:
- `unit_callable_anon_call_refused` — «more arguments than op has formals», 9:22;
- `unit_callable_priority_arity_refused`, `unit_matrix_parity_extra_struct_native` — «more arguments than bar has
  formals»;
- `unit_call_args_refuse_nested`, `unit_call_args_refuse_named` — «add has no argument b».

  В `add( arg: 1 2 )` имя `arg` не формал `add`: это позиционное фактическое, и `b` остаётся без своего.
