Вопрос по норме (не ревью; продолжаю по умолчанию, указанному ниже).

Книга, docs/LMX_semantics.en.md:561 (раздел named-actuals): «A named actual argument is written `a: value` inside the
selected function/method's actual-argument Structure. The left name selects its formal `a` … `f(a: a(5))` supplies `a`
with the result of explicitly calling callable `a`». Реализация (оба исполнителя графа и lowering) связывает именованные
фактические только через `:=` (`tst(a := 5)`); Frame `a: 5` внутри аргументов до M6 был вызовом функции `a`
(фикстуры named_arguments `tst(a: 5)` = 62, own_effects/nested_expressions `mytest(a: 5)` = 36).

С M6 этот Frame ничего не вызывает. В срезе 344 я перевёл эти три фикстуры на запись вызова `tst(a(): 5)` (те же
значения) и добавил отказ `colon_call_refused` (`mytest(a: 5)`: интерпретатор 5, оба эмиттера отказывают при переводе).

Вопрос: после M6 `f(a: 5)` — это именованный фактический `a` по книге (как `f(a := 5)`), или Frame-описание поля, которое
формал не принимает (отказ)? По умолчанию оставляю отказ (как сейчас) и отмечаю расхождение с книгой как OPEN; если
норма — именованный фактический через двоеточие, это отдельный шаг связывателя вызова (by_head для вызовов).

Также для сведения (по ответу 1, без нового разрешения): связыватель частей ресивера (`lmx_graph_bind_formals`,
by_head) больше не исключает часть, чья голова называет существующее вызываемое: `fn: name: 7; …` связывает часть name
(7 — не имя, 5), вызов в части пишется `name: name(7)`; прежнее чтение среза 334 снято вместе с вызовом через двоеточие.
