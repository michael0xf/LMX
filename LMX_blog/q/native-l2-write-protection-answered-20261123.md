# Проверки по уровням: защита записи в `const` и `immutable` в нативном коде L2

Записано 2026-11-23 исполнителем fable_pc при описи проверок (план, шаг 21.25).

**Закрыт ответом автора в тот же день: (а).** Ответ дословно ([журнал](../2026-11-23.md#checks-by-level)):

> " const под L2: без проверки при нативном исполнении" -- да, если транслятор по каким-то причнам пропустил и
> не выдал ошибку то селяви, все подходит в том числе запить в случайную область памяти (после ядра подключим
> libsoidum)

Защита записи из нативного кода L2 снимается; запись, которую транслятор видит, он отклоняет при трансляции.

## Что сошлось не до конца

Правило автора от 2026-11-23 ([журнал](../2026-11-23.md#checks-by-level)): «нативный L2 -- никаких проверок».
Книга, [квалификация](../../docs/spec/LMX_semantics.ru.md#qualification), говорит о записи в защищённое место:
общий механизм времени исполнения отказывает до изменения этого места, и это относится и к собственному
сохранённому телу, и к внешнему коду. Спецификация L2,
[адреса, загрузка и запись](../../docs/spec/L2_spec_ru.md#lowlevel-address), говорит, что адресная операция не
снимает `const` и `immutable`.

Отказ записи в защищённое место — это проверка при исполнении, и она стоит на каждой записи. Из документов не
видно, считается ли она проверкой в смысле правила (тогда в нативном L2 её нет) или частью смысла записи во всех
исполнителях (тогда она есть и в нативном L2).

## Программа

```lmx
(
    Observed:
        int: seen 0
)
sub: main () (
    int: k 0
)
    @: shared node[0]
    const: int: b 1
    L2:
        b := 2
    shared\Observed\seen := b
main()
```

Без записи `L2:` та же запись `b := 2` — код L3: отказ, ответ 4, в интерпретаторе и нативно. Это закреплено строкой
`marks_const_write_code` и вопроса не вызывает.

С записью `L2:` в интерпретаторе сегодня отказ, ответ 4, `seen` остаётся 0 — интерпретатор проверяет и код L2,
это по правилу.

Вопрос — что наблюдается, когда эта программа исполняется нативно:

- (а) запись проходит без проверки: `seen` равно 2, отказа нет. Защита записи — проверка обёртки L3; нативный код
  L2 порождает саму запись;
- (б) отказ, ответ 4, `seen` остаётся 0, как в интерпретаторе: защита `const` и `immutable` — часть смысла записи
  в любом исполнителе, под правило о проверках не подпадает.

## Что от ответа зависит

Транслятор L2 вписывает защиту записи в код методов, написанных в файлах `.lm2`, — шесть мест порождения, два
шаблона. В машинные функции (ядро, транслятор) этот текст не попадает: там записи идут прямым сохранением. При (а)
шесть мест снимаются, защита остаётся в общей обёртке записи, которой пользуются интерпретатор и нативный код
L3. При (б) они остаются и сводятся к одному вызову той же обёртки.

Сведение двух шаблонов к одной обёртке записи делается в любом случае; по ответу (а) из кода методов `.lm2` вызов
защиты уходит.
