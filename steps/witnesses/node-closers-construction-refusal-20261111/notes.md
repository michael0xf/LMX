## Что изменено

Подробно, по файлам и процедурам, — [итог помощника](../../handoff/m11-step5b2-result-20261111.md) (раздел 1). Коротко:

1. **Слово `node`** (`lmx_graph_node_space`, `lmx_graph_resolve`, `lmx_graph_language_word`). `node` — пространство
   над кодом, который исполняет запуск; оно лексическое по коду, а не по поданным данным. У кода обычной Structure
   это её родитель; у вызываемого — блок, где стоит его объявление, сквозь тела ресиверов управления; если этот
   блок — часть объявления другого вызываемого, ответ — часть `data` того вызываемого (внутренний метод меняет
   данные объемлющего путём `node\имя`). У корня единицы пространства нет — имя не отвечает (ответ 3). `node`
   читается раньше цепочки активаций, местом или входом метода оно не бывает. Чтение и запись `node\имя` идут общим
   шагом пути и общей записью; правок эмиттера для `node` нет — выпущенный код зовёт ту же функцию ядра.
2. **Связать `node` нельзя** (`lm_graph_frame_admitted` в построителе). Запись с головой `node`, объявление `int:`
   или `@:` с именем `node` (и формал), `fn`, `sub`, `fm` с таким именем — отказ построения, ответ 2; в написании
   с обратными кавычками тоже. Путь `node\x := v` разрешён.
3. **Сверка закрытий по правилам рабочего frontend** (та же `lm_graph_frame_admitted`; дефект
   `GRAPH-END-TARGET-UNCHECKED`). Цель `end:` — ровно один атом, допустимый для закрываемой записи: у `fn`, `sub`,
   `fm` — имя или слово ресивера, у `(): имя` — имя, у всякой иной записи — её голова. Запись с головой `end` или
   `until`, которую парсер не сделал трейлером, — «лишний трейлер», отказ построения. Закрытие нескольких уровней
   одним трейлером принимается.
4. **Запись `data()` в коде вызываемого** (`lmx_graph_block`, `lmx_graph_callable_code`; в эмиттере —
   `lm_graph_emit_data_launch`). Запись с головой `data` запускает данные живого запуска: `data()` — над ними же,
   `data(D)` — над `D`; два позиционных аргумента — ответ 5. Вне кода вызываемого запись пропускается, как прежде
   (у обычной Structure поле `data` остаётся моделью мест до кодовой части подшага 5в).
5. **Исход строки `graph-check` «отказ построения»** (`bld_graph_check`, разбор строки в `lmxtool_methods.lm2`).
   Поле 11 принимает `2`: во всех трёх режимах инструмент графа отвечает числом поля 13 и печатает строку
   `graph: build answered N`; программа не выпускается, не транслируется и не запускается. Строки с полем 11,
   равным 0 или 1, читаются как прежде.
6. **Файл перехвата драйвера** (`driver_root_launch`). После чтения перехваченного вывода хоста файл
   `l2_driver_launch.err` удаляется — в рабочем каталоге программы ничего не остаётся (слово автора 2026-11-11:
   файл ему не нужен). В проверке документов снята оговорка о «защищённом» имени (`ce_readable_name`); защищённым
   остаётся только корневой каталог `build`.

## Пределы

- Запись `data(...)` запускается только в коде вызываемых; в корне, в Structure над собой и над поданными данными
  она пропускается — кодовая часть подшага 5в.
- Метод, объявленный в теле `if`, чистым графом не создаётся (вызов — ответ 3); правило `node` для такого метода в
  коде есть (`lmx_graph_node_passes`), фикстуры у него нет.
- `return: inner()` с вызовом метода, объявленного в коде объемлющего, отвечает 5; обход — `int: r inner()`.
- Сверка закрытий шире рабочего frontend в двух местах: у безымянного `fn` или `sub` принимается `end: fn`
  (`end: sub`) по грамматике §17, рабочий frontend отказывает в любом трейлере безымянного; у объявлений и вызовов
  цель-голова (`int: x 4` и `end: int`) принимается, рабочий frontend отказывает формой. Отказа там, где рабочий
  frontend принимает, пробы не нашли.
- Голое `node` значением (`f(node)`, `@: p node`) не определено этим подшагом и не тронуто.
- Мутант m20 выжил: слово языка и ветка `node` в `lmx_graph_resolve` держат одно положение вдвоём (m21).
- Копии драйвера вне `selfbuild` — `dev/l2src_sandbox/l2_driver.lm2` и `l2src/harness/l2_eternal_driver.lm1` — файл
  перехвата по-прежнему создают и не удаляют.
- `close_stray_end` закрепляет нынешнее чтение парсера (внутри круглых скобок `end: имя` — запись, а не трейлер);
  пакет правок парсера меняет ожидание этой фикстуры.
