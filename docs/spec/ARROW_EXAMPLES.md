# `->`: примеры сигнатур LMX

`->` строит описание сигнатуры из последовательности полных TYPE: сначала идут входы, **последний TYPE задаёт результат**. `::` объявляет имя этого описания. Ни один из этих шагов не создаёт тело функции и не выполняет описанные формалы. Все примеры ниже используют уже принятую норму; новых правил приоритета или раскрытия TYPE здесь нет.

В `int -> int int` всего три TYPE: два входа `int` и результат `int`. Правый поток может иметь любую допустимую конечную длину. Для нульарного случая используется обычная форма `` `->`(R) ``. В `@Struct: var` объявлено место типа «адрес Struct». В `f :: @Struct -> @Struct` слева от `::` записано имя `f`, а `->` описывает вход и результат одного типа «адрес Struct». Обе позиции TYPE содержат TypeRef этого типа. [Договор TypeRef](TYPE_REFERENCES.md#type-reference).

Источник правил: [семантика сигнатур](LMX_semantics.en.md#fn-signature), [приоритет и DATA-контракт](LMX_semantics.en.md#signature-description-consumption), [границы групп](LMX_semantics.en.md#signature-grouping), [одно тело конструктора](patterns/LMX_Fn_Receivers/src/fn_operand.lmx).

## 1. От простых типов к составным

Это независимые объявления. В примерах с `Model` предполагается доступная модель:

```lmx
Model:
    int: key
    int: value
```

| Объявление | Входы по порядку | Результат | Смысл |
| --- | --- | --- | --- |
| `` readValue :: `->`(int) `` | Нет | `int` | Нет входов; результат int. |
| `` readValues :: `->`([]int) `` | Нет | `[]int` | Нет входов; результат — один массив. |
| `` reset :: `->`(void) `` | Нет | `void` | Процедура без входов и без возвращаемого значения. |
| `doubleValue :: int -> int` | `int` | `int` | Один int на входе и int на выходе. |
| `positive :: int -> int` | `int` | `int` | Тип предиката: флаг кодируется int; тело предиката здесь не задаётся. |
| `scale :: double -> double` | `double` | `double` | Один double; конструктор не специализируется на int. |
| `add :: int -> int int` | `int`, `int` | `int` | Два аргумента; последний из трёх TYPE — результат. |
| `add3 :: int -> int int int` | `int`, `int`, `int` | `int` | Три аргумента; длина правой последовательности не фиксирована. |
| `blend :: int -> double double double` | `int`, `double`, `double` | `double` | Разные типы входов, порядок сохраняется. |
| `textSize :: []char -> int` | `[]char` | `int` | Текстовый массив — один аргумент, а не поток символов. |
| `joinText :: []char -> []char []char` | `[]char`, `[]char` | `[]char` | Два массива на входе, один на выходе. |
| `total :: []int -> int` | `[]int` | `int` | Редукция массива описывается одной входной позицией. |
| `combine :: []int -> []int []int` | `[]int`, `[]int` | `[]int` | Оба массива целые; элементы не становятся формалами. |
| `scaled :: []int -> int []int` | `[]int`, `int` | `[]int` | Массив, коэффициент, массив результата. |
| `inspect :: @Model -> int` | `@Model` | `int` | Ссылка с полным требованием Model. |
| `change :: @Model -> int void` | `@Model`, `int` | `void` | Ссылка и новое значение; процедура не возвращает фиктивный 0. |
| `find :: []Model -> int @Model` | `[]Model`, `int` | `@Model` | Массив моделей и ключ; результат — ссылка с требованием Model. |
| `writeCell :: @int -> int void` | `@int`, `int` | `void` | Типизированная ссылка на int плюс значение для записи. |
| `readCell :: @int -> int` | `@int` | `int` | Ссылка — один TYPE, уровень @ сохранён. |

Имена вроде `total`, `find` и `change` показывают назначение будущей операции. Одна строка сигнатуры ещё ничего не суммирует, не ищет и не изменяет. `void` задаёт отсутствие результата; это не нулевая ссылка, пустой массив или числовой ноль. Конкретные правила допустимости отсутствующей ссылки и доменных ошибок принадлежат будущему методу, а не этой записи TYPE.

## 2. Функции как входы и результаты

Внутренняя стрелка строит **один полный callable TYPE**. Его нельзя раскрывать как дополнительные внешние входы. Для вложенных сигнатур явно показываем границы:

```lmx
makeAdder :: int -> (int -> int)
```

Результат — одна полная сигнатура функции. Внешних входов: 1.

```lmx
invoke :: (int -> int) -> int int
```

Callable и число на входе; число на выходе. Внешних входов: 2.

```lmx
compose :: (int -> int) -> (int -> int) (int -> int)
```

Два callable на входе, callable на выходе. Внешних входов: 2.

```lmx
transform :: (int -> int) -> []int []int
```

Callable и один массив; описания callable не раскрываются. Внешних входов: 2.

```lmx
thunkFactory :: int -> (`->`(int))
```

Один аргумент; результат — функция без аргументов, возвращающая int. Внешних входов: 1.

```lmx
acceptThunk :: (`->`(int)) -> int
```

Функция без аргументов — один входной callable TYPE. Внешних входов: 1.

```lmx
curried3 :: int -> (int -> (int -> int))
```

Три явно вложенных одноаргументных уровня; это описание, не автоматическое каррирование тела. Внешних входов: 1.

У `add :: int -> int int` два входа одного вызова. У `makeAdder :: int -> (int -> int)` один вход, а результатом является callable с ещё одним входом. Это разные профили. Получить второй из реализации первого можно существующим `curry`; наличие стрелки само не каррирует тело.

## 3. Равнозначные записи и приоритет `::`

Следующие три строки — альтернативы одного описания:

```lmx
f :: int -> int int
```

```lmx
f :: (int -> int int)
```

```lmx
f :: `->`(int; int; int)
```

У `::` приоритет `sys\priority(":=")`, у `->` — `sys\priority("+")`. Поэтому общая подготовка Expression связывает весь конструктор справа от `::`. Метод `::` по-прежнему принимает DATA; отдельного вычислителя правой части внутри него нет. P0 сохраняет написанную структуру, а одинаковое подготовленное описание не требует тождества исходных графов.

Можно явно сохранить готовое описание:

```lmx
@: description (int -> int int)
f :: description
```

Или переиспользовать уже названную сигнатуру:

```lmx
Binary :: int -> int int
AnotherBinary :: Binary
```

Эти формы сохраняют позиционный профиль. Отражать физические служебные поля объекта описания в новые формальные аргументы нельзя.

## 4. Где границы действительно меняют смысл

| Форма | Что получает конструктор | Следствие |
| --- | --- | --- |
| `int -> int int` | Три последовательных TYPE | Два входа и один результат. |
| `(int -> int int)` | Один завершённый конструктор во внешней группе | То же описание при обычной подготовке этого Expression. |
| `int -> (int int)` | `int` и одна целая группа справа | Не эквивалент двум правым TYPE; допустимость группы как полного TYPE проверяется отдельно. |
| `int -> (int -> int)` | `int` и один callable TYPE справа | Один вход и callable-результат. |
| `int -> ()` | `int` и присутствующая пустая Structure | Не сокращение функции без аргументов. |
| `` `->`(int) `` | Один TYPE | Нет входов, результат int. |
| `f :: int int int` | Несколько отдельных правых вхождений для `::` | Такая голая запись списка TYPE не вводилась. |

Группировщик работает с чистым графом и не видит исходные скобки. Его нормализация выражений не даёт права разбирать внутреннее устройство целого TYPE, модели или DATA-описания. Запись скобками в таблице только показывает структурные границы читателю. Не требуется отдельный проход, раскрывающий `(int int)` по имени операнда `->`.

Две стрелки без явного указания вложенной сигнатуры не следует читать по привычке как неявное каррирование Haskell. LMX сохраняет общий механизм Expression и последовательность входных TYPE; для callable-результата используйте ясно выделенное `int -> (int -> int)`.

## 5. От сигнатуры к настоящему вызову

Ниже тело написано отдельно, а типизированная ссылка допускает его по сигнатуре. Позиционным именам `first` и `second` не приходится совпадать с несуществующими метками короткого TYPE-профиля.

```lmx
Binary :: int -> int int

Addition:
    int: first
    int: second
    return: int
    apply:
        return: first + second

Demo:
    return: int
    run:
        @Binary: add Addition\apply
        return: add(2; 3)
```

Ожидаемый результат `Demo\run()` — `5`, когда исходник принят и операция явно вызвана по обычному профилю примеров. Имя `Demo` не является автоматической точкой входа. Корень запускается по общему правилу R0; `::` не создаёт `Main` и не выбирает метод реализации.

Когда нужны публичные имена параметров, defaults или другие декларации, остаётся полная DATA-форма:

```lmx
NamedBinary :: (int: first; int: second; return: int)
```

Она сохраняет метки формалов, чего краткий безымянный вектор TYPE сам по себе не добавляет. Ошибки и контракты узла также не исчезают из определения настоящего метода при коротком объявлении сигнатуры.
