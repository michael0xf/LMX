# Общие операции для новых алгоритмических примеров

В единое ядро добавлены `fill`, `lowerBound` и `last`. У каждой операции одно LMX-тело и две публичные формы; они включены в `operation_definitions.json`, `catalog.json`, проекции обычных вызовов и операндов и общую сборку `LMX_Receivers.lmx`. Статус настоящего парсера и runtime: **NOT_RUN**.

## fill: заполнить существующий массив

Обычная форма — `fill(target; valueRecord)`, операндная — `target fill valueRecord`. [Общее тело `FxArrayFill\fill`](src/fill.lmx) использует существующий `FxSeqStore\write`, который выполняет обычный допуск значения и запись. Ссылка на отсутствующее поле `FxKernel\arrayWrite\throws` не вводится: ошибки копируются из реально объявленных методов `FxSeqInfo\get` и `FxSeqStore\write`.

`target` допускает существующие профили Array, включая плотные `[]T` и ссылочные массивы. `valueRecord` — подготовленная запись одного значения, а не обязательный `int`. Меняются элементы массива, его длина и дескриптор сохраняются. Если значение является ссылкой, все записи сохраняют ту же цель; глубокое копирование объектов не обещается. Пустой массив возвращается без допуска к несуществующему элементу и без записи. На поздний ресурсный отказ общего отката нет. `fill` не увеличивает массив и не предполагает нулевого содержимого после `sys\resize`.

Обе формы приводят к одному методу:

```lmx
fill(values; (0 record))
values fill (0 record)
```

Это две альтернативные записи операции, а не последовательность, которую следует исполнять дважды. Значение `0` иллюстрирует заполнение числового массива; тело функции не специализировано по нему.

Набор заявленных отказов: `FxKernelFailure`, `FxTypeToken`, `ReceiverIndex`, `SequenceElement`. Это раскрытие скопированных деклараций, а не самостоятельный анализ всех возможных неявных системных отказов.

Сложность: линейное число записей по длине массива, постоянное дополнительное место, не считая работы существующего допуска и системных средств.

## lowerBound: найти границу разбиения

Обычная форма — `lowerBound(items; needleRecord; less)`, операндная — `items lowerBound needleRecord less`. [Общее тело `FxLowerBound\lowerBound`](src/lowerBound.lmx) выполняет двоичный поиск и возвращает индекс первого элемента, для которого `less(element, needle)` ложно; если таких элементов нет, возвращает длину.

Вход должен быть разбит на префикс истинных и суффикс ложных результатов этого предиката. Полностью отсортированный массив достаточен, но сортировка целиком не навязывается как более сильное требование. Проверка разбиения линейным проходом не выполняется. Предикат обязан сохранять это разбиение и не изменять вход во время поиска. Пустой вход даёт индекс 0 и не вызывает предикат. Равенство элементов не проверяется.

Элементы и искомое значение сохраняют свои фактические типы. Например, предикат может сравнивать поле ключа записи с отдельным искомым ключом; эти два аргумента не обязаны иметь один тип. `FxSeqRead` получает готовую запись элемента, а общий `FxApply` применяет реальный переданный callable. Именованный отказ предиката передаётся по существующему договору `FxApply`/`FxCallFailure`, а не превращается в «не найдено».

```lmx
lowerBound(items; (key record); Compare\less)
items lowerBound (key record) Compare\less
```

В этих альтернативных формах предполагаются доступные `items`, `key` и совместимый `Compare\less`. Полный двоичный поиск, обе LMX-формы его использования/реализации и контрольные алгоритмы находятся в [сравнении 100](../10_algorithms/100_lower_bound_comparision.md).

Набор заявленных отказов: `FxCallFailure`, `FxKernelFailure`, `FxPredicate`, `FxTypeToken`, `ReceiverIndex`. Для массива с произвольным доступом требуется `O(log(n + 1))` обращений к элементам и предикату и `O(1)` дополнительного места; стоимость пользовательского предиката учитывается отдельно.

## last: полезный хвост последовательности

`last(items; count)` / `items last count` возвращает новый внешний массив из последних `min(count, length(items))` элементов с сохранением порядка, физического профиля и ссылок на их цели. `count = 0` даёт пустой массив; `count` больше длины — копию всего внешнего массива; отрицательное значение даёт `SequenceSize`. Вход не изменяется. Одно [тело FxSeqLast\last](src/last.lmx) переиспользует существующий `drop` и копирует его полный список ошибок.

Название взято непосредственно из Julia. Общий LMX-договор относится к элементам Array; он не выдаётся за неявное декодирование Unicode или поиск графем. В J22 после отбора ASCII-цифр и массивный LMX, и строковый Julia `last` сохраняют одни и те же последние четыре цифры. Для текстового профиля с многобайтовой кодировкой границы символов задаёт существующий явный профиль, а не голый срез байтов.

Первичный источник: [Julia Base.last](https://docs.julialang.org/en/v1/base/collections/#Base.last) и [строковая форма](https://docs.julialang.org/en/v1/base/strings/#Base.last).

## Публикация и граница сравнения

Операндная форма строится существующим `asOperand` с обычным приоритетом библиотечных операций `sys\priority("+")`. Она не создаёт вторую реализацию алгоритма. Обычные и операндные формы сохраняют свой порядок фактических аргументов, результат и конечные ошибки. Новых механизмов диспетчеризации, синтаксиса или provider hooks не требуется.

В сравнении **реализации** двоичного поиска показаны полные тела всех сторон. Короткий вызов готовой LMX-функции не сопоставляется по размеру с полной чужой реализацией. Переиспользуемые зависимости учитываются один раз в каждой полной границе, а все текущие размеры пересчитаны после добавления примеров. Сводные Markdown, CSV, PDF и XLSX строятся из этих же полных границ исходников.

## Первичные источники

- [C++ Working Draft: fill](https://eel.is/c++draft/alg.fill) — присваивание одного значения элементам диапазона. Имя `fill` сохранено.
- [C++ Working Draft: lower_bound](https://eel.is/c++draft/lower.bound) — граница разбиения по предикату. Имя приведено к принятому `lowerCamelCase`: `lowerBound`.
- [Python: bisect_left](https://docs.python.org/3/library/bisect.html#bisect.bisect_left) — точка вставки перед равными элементами; поиск не требует проверки равенства.

Источники поясняют выбор операции и названия; конкретные правила профилей Array, ошибок и публикации определяет текущая спецификация LMX.
