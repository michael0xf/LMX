# Мост Claude Code для LMX

Мост: [tools/claude_bridge.py](../tools/claude_bridge.py). Прямой вызов CLI через stdin/stdout, без файловой почты и вотчеров. Ответ возвращается вызывающему процессу в JSON. Следующий запрос продолжает тот же разговор по явно сохранённому ID.

## Изоляция

- Рабочая директория всегда LMX. Собственные настройки, история и ID находятся в игнорируемой Git директории `.claude-bridge/`.
- `CLAUDE_CONFIG_DIR` задаётся только окружению дочернего процесса. Настройки пользователя и проекта L1 не изменяются. Автообновление общего CLI отключено для этого процесса.
- Не используются `--continue`, поиск чужих сессий, остановка или перезапуск существующих агентов.
- Начальный режим — рецензент с инструментами Read/Glob/Grep, без команд оболочки и записи. `--restricted` ограничивает файловые инструменты рабочей директорией; hooks отключены, внешние MCP не подключаются. Это пока не агент для редактирования кода.
- Локальная блокировка запрещает одновременную отправку в один разговор. При неясном результате доставки повтор автоматически не выполняется. После аварии сначала исследовать локальную историю и `session.json`; не снимать `pending` и не удалять `busy.lock` вслепую.
- `exchanges.jsonl` — локальный журнал завершённых обменов, не транспорт сообщений. Может содержать содержимое запросов и ответов; не коммитить его или настройки авторизации.

## Команды из корня LMX

```powershell
python tools/claude_bridge.py status
python tools/claude_bridge.py login
python tools/claude_bridge.py ask "Прочитай READ.ME и кратко объясни назначение L1_spec."
python tools/claude_bridge.py ask "Какой вопрос я задал в предыдущем сообщении?"
```

`login` предназначен для интерактивной авторизации в отдельном профиле моста. Для провайдера с API-совместимым endpoint запускать мост с его настройками окружения; способ подключения должен соответствовать используемому провайдеру. Секреты не передавать в аргументах, репозитории или сообщениях чата. Путь CLI при необходимости задаётся переменной `LMX_CLAUDE_EXE`.

Многострочный запрос можно передать в stdin без позиционного аргумента. Лимит ожидания задаётся `--timeout` (секунды, по умолчанию 180). Это мост по запросу: он не запускает бесконечный самостоятельный разговор моделей.

## Проверено 2026-09-19

- Найден Windows CLI Claude Code 2.1.278 в пользовательском `.local/bin`.
- Пять автоматических проверок прошли: новая сессия/продолжение, конкурирующий запрос, неопределённая доставка, чужой ID и отдельное окружение.
- Реальный `auth status` подтверждает каталог настроек и истории внутри LMX, но возвращает `loggedIn: false`.
- Полноценный обмен с моделью и сохранение контекста ещё не проверены: ожидается информация о способе подключения провайдера. Нельзя считать мост полностью настроенным до двух успешных связанных запросов.
- Два существовавших процесса Claude Code остались запущены; управляющие команды к ним не отправлялись.

Автор отложил настройку авторизации до отдельного указания; сейчас он уточняет возможность подключения у Grok и grok_bot.

После подключения выполнить две команды `ask` выше и проверить одинаковый `session_id` и содержательный ответ на второй запрос. Обновить этот раздел по фактическому результату.

Проверки кода: `python -m unittest discover -s tests -p test_claude_bridge.py -v`.

Основание: [программный интерфейс Claude Code](https://code.claude.com/docs/en/headless), [отдельный каталог настроек](https://code.claude.com/docs/en/settings), справка установленного CLI.
