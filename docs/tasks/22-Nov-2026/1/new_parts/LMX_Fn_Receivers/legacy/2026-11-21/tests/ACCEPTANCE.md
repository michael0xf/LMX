# Историческая приёмка 2026-11-21 — не текущий API

# Матрица приёмки

Это план проверки реализацией LMX. Отчёт о выполненных здесь статических проверках находится в `STATIC_REPORT.json`. Таблица ниже не является отчётом о выполнении ядром.

## Порядок запуска

Подключить библиотеку в роли DATA принятым в ядре способом. Выбрать либо `LMX_Receivers.lmx`, либо перечисленные в README отдельные модули и примеры; одновременно загружать оба набора не нужно. Реализовать поставщик `FxKernel` по ТЗ. Сначала запускать `FxFnAndAssignmentExamples\run()`, затем `FxGenericExamples\run()`, затем `RxAllExamples\run()` для прежних семейств. Каждый набор возвращает 1 после прохождения своих `sys\assert`; старый `RxFunctionExamples\run()` процедурный и вызывается общим набором без ожидания результата.

Полный подготовленный набор — `FxAllExamples\run()`. Ни один из этих вызовов не включён в файл как автоматическое действие при подключении.

## Основные сценарии

| ID | Проверка | Ожидается |
|---|---|---|
| FN01 | Старый `Name :: Data` рядом с новым API | Сигнатура создаётся по прежнему DATA-контракту |
| FN02 | Готовые int-коды от `sys\typeof`: int, double, @ | Читаются значения кодов, сохраняется порядок трёх входов |
| FN03 | Указатели на `uninit:int`, `uninit:double`, `uninit:@` | Тип извлекается без payload; теги исходных записей не меняются |
| FN04 | Пустой `right`, реальный void-result из сигнатуры процедуры | Ноль входов, `hasResult=0`, отсутствие выдуманного return |
| FN05 | Результат слева, три элемента справа | Все три — входы, последний не изымается |
| FN06 | Канонический операнд `signatureTypes` после подключения | Тот же результат, что у квалифицированного `FxSignatureOperand\make` |
| FN07 | Неверный код, отсутствующий left, незнакомое требование | Объявленный отказ без опубликованной частичной сигнатуры |
| FN08 | Два разных полных требования при одном физическом коде @ | Ограничения не теряются при нормализации и fn-match |
| FN09 | Пустая структура как настоящий результат | Отличается от процедуры без результата |
| ARG01 | `(a b c) := (b c a)` | Циклическая перестановка старых значений |
| ARG02 | `(a b c) := (copy(s))` | Позиционная передача трёх значений, источник сохранён |
| ARG03 | Разное число мест и значений | Отказ до первой записи |
| ARG04 | Написанная безымянная Structure слева; справа ровно одна написанная безымянная Structure с вложенным структурным полем | Снят только внешний правый уровень; left и вложенный правый контейнер сохранены |
| ARG07 | Обычный левый type-токен и единственная правая Structure | Right сохраняет один контейнер; именованный/возвращённый контейнер тоже не открывается |
| ARG05 | Сериализация и повторный разбор групп | P0 не удаляет анонимные контейнеры |
| ARG06 | Raw-операнд с непотреблённым вызовом внутри группы | Нет преждевременного эффекта; `sys\eval` управляет выполнением |
| GEN01 | Lambda для int, double, строки; результат double | Три ступени, точные типы, правильное число |
| GEN02 | Два продолжения одного префикса | Независимые накопленные последовательности |
| GEN03 | Partial с K=0 и K=N | Полный интерфейс либо отложенный nullary; фабрика не вызывает target |
| GEN04 | Lambda/partial/uncurry для N=0 | Корректный nullary callable; вызов только по явному запуску |
| GEN05 | Процедура без return | Завершение без чтения несуществующего результата |
| GEN06 | Конечный результат — callable | Возвращается без дополнительного вызова |
| GEN07 | Flip при трёх разных типах | Меняются первые два типа и подстановки; третий сохраняется |
| GEN08 | Uncurry для трёх разных типов | Каждая ступень имеет отдельную типизированную ссылку; прежний тип локала не переиспользуется |
| GEN09 | Partial получает примитив, затем источник изменяется | Сохранённое числовое значение не меняется |
| GEN10 | Partial получает ссылку, затем её цель изменяется | Последующий вызов наблюдает ту же общую цель |
| GEN11 | Захват переживает возврат создавшей активации | Нет обращения к завершившемуся native stack-local |
| GEN12 | Структурный результат с несколькими полями | Сохраняются описание и обычный приём результата |
| GEN13 | Массив/структура как единственный формал | Одна ступень, именованный actual передаёт значение целиком |
| GEN14 | Defaults/optional у target | Не завершают цепочку раньше; остаточные формалы адаптера required |
| GEN15 | Target с именованным throws | Финальная обёртка сохраняет разрешённый исход |
| GEN16 | Ошибка построителя промежуточной ступени | Соответствует её отдельному throws-контракту |
| GEN17 | Совпадающие служебные имена у пользователя | private-состояние и формалы не становятся его динамическими входами |
| GEN18 | Повторяющиеся исходные имена формалов | Публичные p0, p1, … адресуют позиции через обычный fn-map |
| GEN19 | Изменение target/графа и явная компиляция | Сохраняются действующие правила актуализации, без скрытого compile |
| REF01 | Имена физических записей | Сохраняются порядок, повторы, различие отсутствия и пустого имени |
| REF02 | Rename | Одна карта copy, правка выбранных канонических имён; не текстовая подстановка |

## Исполнители

Для FN02–FN05 и GEN01–GEN18 выполнить интерпретируемый путь, нативный путь после явной компиляции и оба направления перехода между ними. Особенно проверить адресуемые временные значения, запись ссылочного значения, исходную цель ссылки и возвращаемые примитивы: это четыре разных наблюдаемых аспекта.

Сравнивать результаты, объявленные исходы, число вызовов target и видимые эффекты. Не требовать одинаковых внутренних адресов новых экземпляров. Прямые нативные вызовы, которым не нужна упаковка, должны оставаться допустимыми в обычном ABI.

## Стоимость

Измерять отдельно создание сигнатуры, создание адаптера, создание очередной lambda-ступени и многократный вызов готовой последней функции. Не приписывать времени вызова стоимость предварительного `sys\fromLmx`, если она произошла раньше, и не исключать её из стоимости фабрики. Фиксировать число аллокаций/копирований и объём удержанного графа. До этих измерений конкретных коэффициентов относительно прямого вызова не заявлять.
