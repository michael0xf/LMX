## Норма и границы

- Одно пространство имён в непосредственно объемлющей Structure для примитивных полей, обычных Structure, ссылок, методов и `catch`. Первое объявление поля заводит место; повторная объявляющая форма того же поля на этом уровне выбирает существующее место и является **присваиванием**, проходящим обычную проверку совместимости. Это общее правило для полей, в том числе `int: i 5; int: i 6`, `@` и обычной именованной Structure; оно не создаёт второго физического поля. `catch` остаётся точкой управления с отдельным контрактом обработчиков: этот срез не превращает второе одноимённое `catch` в присваивание. Вложенная Structure может затенить имя. Каждый написанный оператор сохраняется отдельно в исходном графе.
- Неизвестная голова `Model` с одиночным атомом в `Model: ptr` — ошибка трансляции независимо от известности `ptr`; `Model: ()` с новой головой объявляет пустую Structure. Повторная форма `Model: ()` на том же уровне обращается к существующему месту и проверяется как присваивание пустой Structure, а не отбрасывается как дубль.
- Известная обычная Structure `Model` с неизвестным `ptr`: `Model: ptr` = `@: ptr Model` — новое поле-ссылка с адресом именно этого экземпляра. `@: ptr Model 0` даёт null; `@: ptr Model Other` записывает адрес `Other` только после `implements(Model, Other)`.
- При уже существующем `ptr` форма `Model: ptr` повторно выбирает место `ptr`: это присваивание значения `Model` в `ptr` после проверки совместимости, а не запись в `Model` и не новое физическое поле. `ptr: Model` для обычного ссылочного `ptr` также адресует `ptr`; для указателя на метод тот же синтаксис является вызовом по его роли. Повторный `@`-ресивер для существующего места выбирает присваивание. Отказ допуска не меняет цель.
- Первое `@: ptr` или `@: ptr 0` объявляет указатель без требования к референту (`void`), во втором случае с нулевым адресом. Позднейшая запись адреса в это место не создаёт задним числом модель и не запускает `implements` для неё. Явное `@: ptr Model 0` сразу объявляет ограничение Model; `@: ptr myFunc` — указатель на метод с его контрактом. Имя метода `myFunc()` вызывает его прямо. Для хранимого указателя на метод `ptr_f()` и `(\ptr_f)()` оба вызывают текущее вхождение; `ptr_f: args` — тот же вызов с аргументами. По общему приоритету `\ptr_f()` разыменовывает **результат вызова** `ptr_f()`, а не служит специальным синтаксисом вызова указателя. Перепривязка указателя записывается повторной формой `@: ptr_f newMethod` (или другим обычным адресным присваиванием), не `ptr_f: newMethod`. `catch` сохраняет свой контракт; иностранный C99 `fnptr:` не переинтерпретировать.
- Удалить *именованные* селекторы `node\[N]field`, `s\[N]name` и корневой `[N]name` из языка и транслятора. Оставить безымянный индексный шаг Array: `arr[i]\[j]\[k]` следует ссылкам на отдельные Array, а `arr[i][j][k]` индексирует один прямоугольный Array.
- Карта `implements` по-прежнему переводит физические позиции требуемых полей в позиции кандидата. Две прежние половины ordinal/LAST после запрета дублей избыточны. Не удалять карту целиком, не возвращаться к предположению одинаковых слотов и не вводить runtime-имена. На переходе допустимо заполнить обе половины одинаково, затем согласованно сократить producer, native, walker, copy и `exec_map` до одной карты.

## Минимальные свидетели

```text
Model: ()
Model: ptr             # новое ptr: адрес Model
@: null_ptr Model 0
Other: ()
@: other_ptr Model Other  # только после допуска
ptr: Other             # попытка записать Other в ptr
Model: ptr             # повторная объявляющая форма: записать Model в ptr
```

Отрицательные: неизвестное `Model: ptr` с атомом справа; несовместимое повторное присваивание существующему месту (включая столкновение видов); именованный `node\[0]field`, отказ `implements` для типизированной ссылки и ошибочный фактический аргумент метода. Положительные: `int: x 1; int: x 2`, повторная структурная форма как присваивание, затенение во вложенной Structure, void-указатель из `@: ptr` и `@: ptr 0` с последующей записью адреса без Model-`implements`, сохранение исходного дерева, оба вызова `ptr_f()` / `(\ptr_f)()`, оба вида многомерной индексации и перестановка полей кандидата.
