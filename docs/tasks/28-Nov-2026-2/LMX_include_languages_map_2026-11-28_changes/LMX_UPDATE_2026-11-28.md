# Обновление LMX: платформы, Python, MIX/P0 и Message patterns

**28 ноября 2026. База — `LMX-28-Nov-2026.tar.gz`.**

Работа завершена как редакция документации и конкретных LMX-черновиков.
Подключение новых native-портов к production-ядру остаётся явно выделенным
следующим этапом; успешный запуск LMX не заявлен.

## Какой архив использовать

- **`LMX_include_languages_map_2026-11-28_full.tar.gz`** — полный обновлённый
  проект. Распаковывайте в **новую пустую директорию**: в нём уже нет старого
  содержимого `include_languages`.
- **`LMX_include_languages_map_2026-11-28_changes.tar.gz`** — только **188 новых
  и 37 изменённых файлов проекта**, без 6804 неизменённых файлов. Список
  **103 удалённых старых путей** находится в
  [LMX_CHANGESET_2026-11-28.json](LMX_CHANGESET_2026-11-28.json).

Это два способа получить одну редакцию; применять оба не нужно.
Простое извлечение поверх существующей папки переписывает файлы, но не
удаляет старые пути. Поэтому для наложения используйте helper ниже
либо явно выполните удаления по манифесту.

### Применение небольшого архива

Нужен Python 3.9 или новее. Распакуйте `changes` в отдельную папку. Рядом с частичным `LMX/` лежит
`apply_lmx_update_20261128.py`.

```sh
python apply_lmx_update_20261128.py --target /путь/к/вашему/LMX
python apply_lmx_update_20261128.py --target /путь/к/вашему/LMX --apply
```

Первый вызов только проверяет. Второй проверяет хеши всех затрагиваемых
файлов, сохраняет прежние версии в соседней резервной папке, переносит новые
и изменённые файлы и удаляет только перечисленные прежние пути.
Если локальная версия затрагиваемого файла отличается и от базы, и от
результата, обновление отказывается её перезаписывать.

Уже применённые файлы распознаются по результату; повторный запуск допустим.
Незатронутые локальные файлы не удаляются. Во время применения другой процесс
не должен редактировать те же файлы. Запись атомарна для отдельного файла;
резервная папка нужна и на случай прерывания всего обновления.

## Что находится внутри

### 1. Платформы и Python

В [include_languages](LMX/include_languages/README.md) восемь каталогов:
Windows, Linux/Ubuntu, macOS, Android NDK, MIR, WASM linear, RISC-V и
остальные C99-compatible hosts. В каждом отдельно `README.md` и `PYTHON.md`.
MIR/WASM/RISC-V сохраняют оговорённые section и L1/L2 номера.

Подключаемый язык — Python через 15 фиксированных `py.*` ворот;
`c.*` относится к L2. Есть 10 source-файлов LMX и 6 примеров,
частная установка runtime, существующий Python endpoint, обработка ошибок,
владение references/buffers и проверяемые native/installer contracts.

### 2. com.mtk.map и исходный Java

[LMX-черновик](LMX/docs/com.mtk.map/README.md) содержит 26 LMX-файлов вместе
с P0 orchestration и примерами. Рядом сохранена исходная библиотека:

`LMX/docs/com.mtk.map/java_original/`

Все 67 исходных файлов, включая 56 `.java`, побайтно совпадают с базой.
Методная карта охватывает **1323 AST объявления**: 591 storage и 732 upper,
без пересечений и пропусков. Исходные TODO и отсутствующие внешние зависимости
отмечены отдельно.

В присланном Java действительно есть внутренняя синхронизация и неодинаковая
глубина ветвей. В LMX используются Message owner и общий код композиции.
Высокоуровневый `synchronized` не добавлен.

### 3. P0 ↔ Cursor ↔ MIX

[Договор интеграции](LMX/docs/com.mtk.map/p0/README.md) и LMX-тела описывают
одновременное заполнение MIX и построение P0, живые Cursor в source bindings,
журнал ревизий, локальное продолжение существующего parser и переиспользование
неизменённых узлов. Сохраняется один parser с подпарсером `[]`, который
вызывает основной, и один механизм группировки.

Исправлены перенос dirty-координат, устаревший numeric reader offset,
идентичности пустых/схлопнувшихся spans, владение byte records, общий барьер
подтверждений подписчиков, mixed metadata invalidation и повтор cleanup
до ACK. Незакрытый batch не считается готовым состоянием.

### 4. Документы в якорях

Каждый ограниченный LMX mark имеет отдельный child MIX document, собственный
локальный P0 root/checkpoints и живые границы общего источника.
Отдельный MIX scanner связывает Var в Tag, допускает пересечение интервалов
и сохраняет identities исходных Var. Исходные byte offsets и `atom_char`
разделены. Portable snapshot сохраняет текст/семантические метки/child scopes
и исключает native P0 graph.

### 5. Четыре Message patterns

В [группу асинхронных шаблонов](LMX/docs/spec/patterns/06_async_and_messages/README.md)
добавлены:

| ID | Шаблон |
| --- | --- |
| 109 | Request–Response / Ask |
| 110 | Become / Selective Stash |
| 111 | Phased Message Lifecycle |
| 112 | External Blocking Adapter |

Для каждого есть полные LMX/Go/Erlang листинги, принятый comparison-документ,
RU/EN руководство, сценарии, источники и метрики. Каталог, CSV/XLSX/PDF
публикации и общая статистика согласованы.

Message сам не вводит deadlock. Эти примеры сохраняют состояние ожидаемой
работы, обрабатывают ответы/служебные события и относят физическое
блокирование внешних API к L2/native adapter.

## Задание для следующего агента

Начать с [основного task и плана интеграции](LMX/docs/tasks/INCLUDE_LANGUAGES_MAP_2026-11-28.md),
[source audit](LMX/docs/com.mtk.map/SOURCE_AUDIT.md) и
[проверок](LMX/docs/com.mtk.map/validation/README.md).

Опирайтесь на актуальные `docs/spec/examples` и `docs/spec/patterns`;
selfbuild — проверяемая справка о текущем ядре. Не подменяйте отсутствующие
native hooks успешными заглушками и не создавайте второй parser/grouping.
Сначала подключите обычные LMX-модули к полному production runtime,
потом запускайте отмеченные NOT_RUN cases и меняйте статус только по
фактическому результату.

Исходный Java сохраняется неизменным для сравнений. Для будущих изменений
снова ведите точный diff; пути удаления должны быть явными.
