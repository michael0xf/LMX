# K03 — definition, application and assignment everywhere (next_core_tasks_v2.md, §3)

Status 2026-10-01: K03a (`7f54dfb`), K03b (`e5186f2`) and K03c (this slice) done; the remaining

## K03a — the resolved-Structure arity refusal, not "not built yet"

**Reproduction (reading, not a new failure).** The plan's own words: "The current diagnostic
«a call of a named Structure with an argument is not built yet» records a real refusal but gives
the wrong reason after Q59. Replace it through the common resolved-call contract check, not a new
syntax-specific ban and not implementation of invented arguments."

Two sites carried the placeholder in `l2trans.lm1` (`l2_colon_check_assignment`'s typed-binding
guard and the plain `T: value` path), and THIRTEEN harness rows pinned its text, several of them
with the comment that it is "the implementation's status, not a rule of the language".

**Repair.** One helper, `l2_struct_arity_error(path, at, name)`, prints the SAME message the
argument matcher already gives a callable with too few formals — "more arguments than NAME has
formals" — with the resolved head's name; both sites call it. The reason is now the resolved
value's contract (Q59: an ordinary named Structure has no arguments), not an unimplemented
construct, and no new ban was introduced: it is the common check applied to the same value.

**Witnesses.** The thirteen rows, with their needles moved to the new message; twelve pass in the
focused run `build/l2_harness/k03a_focus_20261001_01`. The thirteenth,
`unit_value_formal_call_refused`, was one of the retained baseline failures and stayed red — it
became K03b below, not a regression (checked against `baseline_comparison.json`'s retained list).

## K03b — one reference transport for both formal spellings (the fixture was wrong)

**Reproduction.** `unit_value_formal_call_refused` (retained baseline failure since 2026-09-30):
`fn: m (Model: v) int` with a local `Model: w` and the frame `v: w`, pinned as an arity refusal
at 12:5 on the theory (ef80eb3, ticket 16 step 3) that `(Model: v)` makes v a callable VALUE and
`v: w` its call, told from `(@: Model v)` by the declaration node. The translator ACCEPTS it. Two
focused attempts to make it refuse (`k03b_focus_20261001_02`, `_03`) guarded on
`l2_declaration_model(l2_formal_decl(...), 0|1)`; neither could fire for `Model: v` — signature 0
accepts depth 1 only and signature 1 accepts depths 0 and 1, so the helper is not a
value/reference discriminator — and the first refused the `@:` sibling instead.

**The rule, already recorded.** The fixture's premise is the obsolete distinction, withdrawn
before this slice in three places: the semantics ("A signature is not executed": for nonprimitive
A, formals `(A: b)` and `(@: A b)` describe the same reference transport with candidate admission
to A), `next_core_tasks_v2.md` K03 ("Existing primitive or explicit reference binding → assignment
after conversion/admission; a reference binding does not auto-call its referent"),
`steps/generated-diagnostic-migration-20260930.md` D4 ("The old call-refusal expectation is
invalid. A repaired witness must compare both signature spellings under the same
assignment/admission operation, not assert a difference between them") and
`steps/native-selfbuild-20260930.md` ("Remove the old callable-versus-reference distinction in
`unit_value_formal_call_refused`"). No author question was needed: the general rule decides.

**What the HEAD translator already does** (probes `build/fable_k03b/src/p1..p5`, the
`k03a_full_20261001_01` translator, `l2trans.lm1` bytes = HEAD): both spellings accept `v: w`
and `v: @w`, both are called with `mo` or `@mo`, and both emit the SAME lines — the admission
`lmx_runtime_implements(..., l2_q1, Model, Model)` throwing `implements` (status 2) on failure,
then the formal's store `l2_p0_0: l2_q1` (p1.lm1:116/136 = p2.lm1:116/136). The behaviour was
right; the fixture, its row and three comments were wrong.

## K03c — definition everywhere: the nested case, the retained call, ten unmasked rows (fable)

**Reproduction.** deepseek's probe (`p_def3.lm2`), confirmed on `7f54dfb` and `4b2035c`
(`build/fable_k02c/src/q_a.lm2`, `q_c.lm2`, `q_f.lm2`): a nested head inside a definition —
`C: makeA()`, the block `C:` / `makeA()` / `end: C`, a nested block `D:` inside `C:` — gives
`internal: an own declaration has no physical field` (`frame=makeA` / `D`). Root `newthing()`, root
`Known()`, `C: makeA()` with makeA KNOWN (`q_d`) and `C:` holding `int: x 1` (`q_e`) all translate.
Cause: `l2_ns_body_stmt` knew only the declaration shapes of `l2_ns_decl_first` as fields; a nested
unknown head fell to "a statement of the body", C got a procedure, and the own-collector made
`makeA()` an own row of that procedure (the empty-Structure rule) with no slot in C's layout
(`l2_own_mslot` -1 at `l2_layout_owns`). Defect record:
[UNKNOWN-NESTED-HEAD-DEFINITION-INTERNAL](defects.md#unknown-nested-head-definition-internal).

Q58's `Batch: (put: 7)` with put a method was `3:1: unresolved name` (`r_q58.lm2`):
`l2_tail_is_structure` read a tail of one call frame of a method as the head's VALUE
(callable-first), so absent Batch was an unresolved call — while the author's answer is that Batch
holds the one Structure `(put: 7)`.

**Repair.**
- `l2_ns_nested_def(node, me)` (new): a frame whose head is an identifier that is no field of `me`
  declared above and is ABSENT at the unit level above me's own item (`l2_head_absent` with
  `l2_ns_at[top]`, read from the source's order), with a Structure tail (`l2_tail_is_structure`: the
  empty one too). `l2_ns_body_stmt` asks it before the declaration-shape test (a field, not a
  statement); `l2_take_ns_body` declares it as the SAME kind-2 field the `(): name` spelling does —
  `l2_fn_close` on the head, `l2_nsf_push(2)`, recurse with `me` as the parent, patch `l2_nsf_ref`.
  No new field kind, no spelling flag; construction is the existing nested-child path
  (`lmx_struct_new_owned(l2_nsp[parent], …)`).
- `l2_tail_is_structure`: a tail of one call frame of a METHOD is a statement of the body, hence a
  Structure (Q58); a receiver's call (`merge: A B`) and the C door stay the head's value. The
  atom-first spelling (`addN: makeAdder 5`) is unchanged — a different P0 shape (two atoms), the
  callable-merge route of the make_adder rows.
- The ten section-C rows of `generated-diagnostic-migration-20260930.md` (`unit_universal_absent_*`,
  `unit_s2_vis_structure_below_refused`, `unit_next_message_word_refused`, `entry_ret_tr_bad`,
  `unit_decl_unknown_type_refused`, `unit_colon_undeclared_refused`, `unit_matrix_absent_*_refused`):
  their intended refusals ("unresolved name" at the written position) were MASKED by a root
  `return: 0` / `return: m()` that the unit refuses first. Probed without the mask, every one gives
  exactly the row's needle: a literal or one-value tail never declares (the book §9 :563), so an
  absent head with such a tail is an unresolved call — consistent with Q57, which defines only
  where the tail is a Structure. Re-authored: the masking line replaced by the standard ending
  (`int: r m()` where the refused statement is in a method, then `sendMessage: exit(...)` /
  `return`); needles and line numbers unchanged.
