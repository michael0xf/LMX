# Удаление избыточных закрытий LMX

`normalize_lmx_closers.py` сокращает исходники по действующим правилам
[уровней и закрытия](../spec/LMX_grammar.ru.md#levels). Это ограниченный
лексический и структурный редактор, а не P0-парсер и не проверка исполнения.

Обычный переход на один уровень вверх закрывает предшествующее тело сам.
Пустая физическая строка вне защищённого текста закрывает блок до корня;
конец файла также закрывает допускающие это формы. В этих местах отдельные
закрывающие строки могут оказаться лишними. Физические строки разделяются LF, CRLF или CR.
Пустая строка может содержать только пробелы и табуляции. При других пробельных символах
вне литерала или комментария редактор сохраняет весь блок для проверки P0.

В частности, `---` на уровне 0 перед **одной** пустой физической строкой
удаляется: эта строка уже закрывает открытые уровни 1 и глубже и сбрасывает
текущий уровень в 0. Следующий обычный код начинается с нулевого уровня.
Комментарии между маркером и пустой строкой сохраняются; комментарий без
пустой строки не заменяет требуемое многоуровневое закрытие.

Многоуровневое снижение без другой границы по-прежнему требует разрешённого
закрытия. Маркер перед более глубокими строками может открывать анонимную
структуру; такие маркеры остаются. Терминальные действия `return` и `until`
не удаляются. Именованное закрытие удаляется только при найденном явном
совпадающем заголовке, а не по произвольной похожести имени.

Редактор не вставляет пустые строки в продолжающееся тело. Комментарий после
удалённого закрытия сохраняется отдельной комментирующей строкой. Строковые
литералы, точные идентификаторы, сырой текст и сырые комментарии защищены.
Сложные формы Mix, неподдержанный отступ и незакрытые формы остаются без
изменений для проверки настоящим парсером. Файлы, специально описывающие
грамматику и отрицательные синтаксические случаи, не нормализуются.
Слитный токен с начальной точкой в колонке 0 (`.(1)+`, `.:`, `.5`) также
консервативно сохраняет весь блок: отличие от канонической зоны точечных
уровней должен подтвердить полный лексер. Обычная запись `a .(1)+ b` этому
ограничению не подвержена.

## Запуск из каталога, содержащего docs

```sh
python docs/tools/normalize_lmx_closers.py docs --markdown --check
python docs/tools/normalize_lmx_closers.py docs --markdown --write --relative-to docs --report closer-normalization.json
python docs/tools/test_normalize_lmx_closers.py
```

Без `--write` выполняется только предварительный просмотр. `--markdown`
разрешает обработку блоков, явно помеченных `lmx`, `lm1`, `lm2` или `lm3`;
разделительные линии самого Markdown и код других языков не изменяются.
`--check` возвращает ненулевой статус, если ещё найдены доказанно лишние
закрытия. Неподдержанные формы перечисляются в отчёте, а не объявляются
проверенными парсером.

Для каждого изменения сохраняются исходная строка, причина и SHA-256 до/после.
Проекция сохранённых полей и физических структурных границ должна совпасть.
Она проверяет именно область этого редактора, а не равенство графов полного P0.
Регрессионные проверки включают необходимое многоуровневое закрытие, открытие
анонимной группы, строковые данные, комментарии, CRLF, EOF и идемпотентность.

Строковые зеркала LMX внутри текущих JSON-каталогов обновляет отдельный
[синхронизатор метаданных](SYNC_LMX_METADATA.md). После изменения полных
листингов необходимо заново рассчитать обычную полную метрику публикации.
