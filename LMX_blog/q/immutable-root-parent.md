# Корень значения `immutable:` без `independent:` и его лексический родитель

Статус: РЕШЁН 2026-10-10 — ответ Codex по утверждённой книге (REPLY
FABLE-Q-IMMUTABLE-ROOT-PARENT-20261010 через почтальона `lmx_uds`); нового вопроса автору не
потребовалось. Вопрос задал `fable_pc` при проектировании среза RR2c-2b
([дизайн](../../steps/qualifier-receivers-20261010.md); тикет
[critical_qualifier_receivers_bug](../../steps/tickets/critical_qualifier_receivers_bug.md)).

## Контекст

По книге ([квалификация](../../docs/LMX_semantics.ru.md#qualification)) `immutable` защищает само
значение — выбранное дерево: корень и те вложенные Structure, чей обычный `parent` указывает на
проверяемого родителя; внешняя ссылка, *уже хранящаяся как значение данных*, допустима только на уже
неизменяемый объект и остаётся терминалом; примитивы и методы — листья. `independent` — отдельный
ресивер: он освобождает корень от лексического родителя (`parent = 0`). По правилу автора 2026-10-10
([LMX_blog/2026-10-10.md](../2026-10-10.md#qualifier-receivers-20261010)) три квалификатора — обычные
ресиверы, принимающие любую Structure, и каждый допустим отдельно.

Физически результат `merge` — копия используемой части дерева, `parent` переписаны внутри копии
(ответ автора 2026-10-05, [parent копии merge](merge-lexical-copy-and-root-placement.md)): у корня
результата есть родитель — копия лексической цепочки, обычная, неквалифицированная Structure. Проверка
ядра перед квалификацией (`lmx_qualify_tree_preflight`) на день вопроса требовала для корня с
ненулевым `parent`, чтобы этот родитель сам лежал в ранее запечатанном, уже неизменяемом профиле, —
то есть читала `parent` корня как внешнюю ссылку-значение. Поэтому `b: immutable: merge(A C)` без
`independent` транслятор отказывал («a merge qualified immutable without independent is not built
yet»), а полная цепочка `independent: const: immutable:` была построена.

## Вопрос

Является ли `parent` корня неизменяемого значения «внешней ссылкой, хранящейся как значение данных», —
то есть должен ли лексический родитель значения `immutable:` без `independent:` сам быть
неизменяемым, — или `parent` корня есть структурная связь вне защищаемого дерева, и `immutable:` без
`independent:` строит неизменяемое значение под обычным, изменяемым лексическим родителем?

## Решение (Codex, 2026-10-10, по утверждённой книге)

Книга решает вопрос сама. [§10, квалификация](../../docs/LMX_semantics.ru.md#qualification):
проверяется выбранное дерево; вложенная Structure принадлежит ему, когда её `parent` указывает на
проверяемого родителя; только внешняя ссылка, *уже хранящаяся как значение данных*, обязана указывать
на уже неизменяемый объект. Собственный `parent` корня — структурная лексическая связь с узлом вне
выбранного дерева, а не такая хранимая ссылка-значение. Тот же раздел: `independent` сам по себе даёт
корню `parent = 0`; `const`, `immutable` и `independent` — независимые принимающие выражения,
применимые раздельно. Значит, `immutable:` без `independent:` может запечатать выбранное значение под
обычным изменяемым лексическим родителем; оно не должно ни замораживать этого родителя, ни требовать
его неизменяемости. `RuntimeImmutable` над существующим выбранным деревом следует той же границе и не
переподвешивает его. Ненулевой `parent` корня проверяется как обычная корректная структурная связь
(время жизни — по общим правилам графа), без требования лежать в ранее запечатанном неизменяемом
профиле. Настоящие внешние ссылки на данные, хранящиеся внутри выбранного дерева, по-прежнему
проходят установленную предпроверку — эта проверка не ослабляется. Книга,
[§2, граф](../../docs/LMX_semantics.ru.md#graph): лексический родитель и владение памятью независимы;
решение автора 2026-10-05 ([parent копии merge](merge-lexical-copy-and-root-placement.md)): merge
переписывает `parent` внутри копии, а не принимает место вызова.

Реализация — срез RR2c-2b: правило корня в `lmx_qualify_tree_preflight` (ядро), `immutable:` без
`independent:` над merge (транслятор), свидетели native и walker и отрицательный свидетель внешней
ссылки на данные внутри дерева — в [плане](../../steps/qualifier-receivers-20261010.md), не здесь.
